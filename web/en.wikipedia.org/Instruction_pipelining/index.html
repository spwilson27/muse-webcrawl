Instruction pipelining

In computer engineering, instruction pipelining is a technique for implementing instruction-level parallelism within a single processor. Pipelining attempts to keep every part of the processor busy with some instruction by dividing incoming instructions into a series of sequential steps (the pipeline) performed by different processor units, with different instructions processed in different steps at the same time.

Concept

A classical pipeline divides instruction execution into five stages: instruction fetch, instruction decode, execute, memory access, and write back. While one instruction is being executed, the next is being decoded and a third is being fetched, so in the ideal case one instruction completes every clock cycle.

Hazards

Pipelines can stall because of hazards: structural hazards (hardware contention), data hazards (an instruction depends on a result not yet written), and control hazards (branches whose outcome is unknown). Techniques such as forwarding, branch prediction and speculative execution mitigate these stalls in modern processors.

History

Pipelining was pioneered in machines such as the IBM 7030 Stretch and CDC 6600 and became a defining feature of RISC architectures in the 1980s.
