2–3 tree

In computer science, a 2–3 tree is a tree data structure, where every node with children (internal node) has either two children (2-node) and one data element or three children (3-node) and two data elements. A 2–3 tree is a B-tree of order 3. Nodes on the outside of the tree (leaf nodes) have no children and one or two data elements.

Properties

2–3 trees are required to be balanced: all leaf nodes are at the same depth. Each internal node either contains one data item and has two children, or contains two data items and has three children. The data items are kept in sorted order, guiding searches through the tree.

Operations

Searching a 2–3 tree proceeds like searching a binary search tree, comparing the key against the one or two keys in each node. Insertion maintains balance by splitting a temporary 4-node that may arise when a leaf overflows, propagating the split upward if necessary. Deletion similarly merges nodes to restore the invariant. All operations take logarithmic time.

History

The structure was invented by computer scientist John Hopcroft in 1970. 2–3 trees are closely related to red–black trees: every 2–3 tree can be represented as a red–black tree and vice versa.
