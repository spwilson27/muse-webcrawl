In computer science, binary search, also known as half-interval search, logarithmic search, or binary chop, is a search algorithm that finds the position of a target value within a sorted array. Binary search compares the target value to the middle element of the array. If they are not equal, the half in which the target cannot lie is eliminated and the search continues on the remaining half, again taking the middle element to compare to the target value, and repeating this until the target value is found. If the search ends with the remaining half being empty, the target is not in the array.

Procedure

Given a sorted array of n elements and a target value T, the algorithm maintains low and high bounds on the interval that may contain T. At each step it examines the middle element: if it equals T, its index is returned; if it is less than T, the search continues in the upper half; otherwise it continues in the lower half. The interval halves with each step, giving a running time proportional to the logarithm of the array size.

Complexity

Binary search runs in worst-case logarithmic time, making O(log n) comparisons, where n is the number of elements. It requires the array to be sorted and to support random access; for data structures without O(1) random access, such as linked lists, it offers no advantage over linear search.

History and pitfalls

Although the idea is simple, correct implementations are notoriously error-prone: details such as computing the midpoint without integer overflow and handling boundary conditions have caused bugs in widely used library implementations. The first published description of binary search appeared in 1946, and the first bug-free implementation was not published until 1962.

Applications

Beyond searching sorted arrays, the binary-search pattern underlies binary search trees, bisection methods for root finding, and software library routines such as C's bsearch and Java's Arrays.binarySearch.
