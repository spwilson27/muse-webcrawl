Border Gateway Protocol

From Wikipedia, the free encyclopedia

Border Gateway Protocol (BGP) is a standardized exterior gateway protocol designed to exchange routing and reachability information among autonomous systems (AS) on the Internet. BGP is classified as a path-vector routing protocol, and it makes routing decisions based on paths, network policies, or rule-sets configured by a network administrator.

BGP used for routing within an autonomous system is called Interior Border Gateway Protocol (iBGP). In contrast, the Internet application of the protocol is called Exterior Border Gateway Protocol (eBGP).

Operation

BGP neighbors, called peers, are established by manual configuration between routers to create a TCP session on port 179. Peers exchange the prefixes (IP address ranges) they can reach, along with a list of the autonomous systems a route has traversed — the AS path. Each router applies local policy to select the best path to each destination, considering attributes such as local preference, AS path length, and multi-exit discriminator (MED). The global BGP routing table carries on the order of a million IPv4 and IPv6 prefixes.

History

BGP was first described in 1989 in RFC 1105, jokingly sketched on two napkins — the famous "two-napkin protocol." The current version, BGP-4, was standardized in 1994 (RFC 1654, later RFC 4271) and introduced Classless Inter-Domain Routing (CIDR), which greatly slowed the growth of routing tables.

Security

BGP was designed without built-in authentication of route announcements, which has allowed incidents of prefix hijacking and route leaks — for example, the 2008 incident in which Pakistan Telecom inadvertently made YouTube unreachable worldwide. The Resource Public Key Infrastructure (RPKI) and Route Origin Validation are being deployed to sign and verify route origins.
