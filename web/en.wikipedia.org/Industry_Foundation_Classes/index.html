Industry Foundation Classes

The Industry Foundation Classes (IFC) is a standardized, digital description of the built environment, including buildings and civil infrastructure. It is an open, international standard (ISO 16739), intended to be vendor-neutral, and usable across a wide range of hardware devices, software platforms, and interfaces for many different use cases.

Overview

The IFC specification describes a relational information structure for the exchange of data between different software applications in the architecture, engineering and construction (AEC) industry. The main purpose of IFC is to enable interoperability between different building information modeling (BIM) software tools, so that architects, engineers, contractors and owners can share a common model of a facility throughout its life cycle, from design and construction to operation and demolition.

IFC is developed and maintained by buildingSMART International, a non-profit organization formerly known as the International Alliance for Interoperability (IAI), which was founded in 1994. The IFC schema defines thousands of entity types covering geometry, materials, spatial structure, building elements such as walls, doors and windows, building services such as pipes and ducts, structural analysis, and cost and schedule information.

Versions

Major releases of the schema include IFC1.0 (1997), IFC2x (2000), IFC2x3 (2006), and IFC4 (2013), which was published as ISO 16739:2013. IFC4 introduced improved geometry, enhanced material definitions, and better support for building services and infrastructure. IFC4.3, published as ISO 16739-1:2024, extended the schema to infrastructure assets such as roads, railways, bridges and tunnels.

File formats

IFC data can be encoded in several forms. The most common is the STEP physical file format (.ifc), a text-based format defined by ISO 10303-21. An XML representation (.ifcXML) and compressed archives (.ifcZIP, using ZIP compression, typically reducing file size by 60–80%) are also supported. The schema itself is defined using the EXPRESS modelling language, and more recently via the ifcOWL ontology for linked-data applications.

Model View Definitions

Because the full IFC schema is very large, exchanges are usually governed by Model View Definitions (MVDs), which specify the subset of the schema required for a particular workflow, such as coordinating architectural and structural models or handing over data for facility management.
