Signal (computing)

In computing, a signal is an asynchronous notification sent to a process or to a specific thread within the same process to notify it of an event that occurred. Signals originated in 1970s Bell Labs Unix and were later specified in the POSIX standard.

When a signal is sent, the operating system interrupts the target process's normal flow of execution to deliver the signal. Execution can be interrupted during any non-atomic instruction. If the process has previously registered a signal handler, that routine is executed. Otherwise, the default signal handler is executed.

Common signals

  • SIGHUP (1) — hangup detected on the controlling terminal or death of the controlling process.
  • SIGINT (2) — interrupt from the keyboard (typically Ctrl+C).
  • SIGKILL (9) — kill signal; cannot be caught, blocked, or ignored.
  • SIGSEGV (11) — invalid memory reference (segmentation fault).
  • SIGTERM (15) — termination signal, the default sent by the kill command.
  • SIGSTOP (19) — stop the process; cannot be caught or ignored.

Sending signals

Signals can be sent from the shell with the kill utility, from a keyboard shortcut, or by the kernel when a process performs an illegal operation such as dividing by zero or accessing invalid memory. A process can send a signal to itself or another process with the kill system call, subject to permission checks.

$ kill -TERM 1234   # ask process 1234 to terminate
$ kill -9 1234      # force process 1234 to terminate
