Subset sum problem

Subset sum problem
FieldComputer science, complexity theory, cryptography
ProblemGiven integers and a target, does a subset sum exactly to the target?
ComplexityNP-complete
AlgorithmsDynamic programming O(n·sum); meet-in-the-middle O(2^(n/2))
RelatedKnapsack problem, partition problem, Merkle–Hellman cryptosystem

The subset sum problem (SSP) is a classic decision problem in computer science: given a set (or multiset) of integers and a target sum, determine whether some subset of the integers adds up exactly to the target. For example, the set {−7, −3, −2, 5, 8} has a subset {−3, −2, 5} summing to 0. Subset sum is one of Karp's 21 NP-complete problems and is a special case of the knapsack problem.

Algorithms

Despite its NP-completeness, subset sum admits efficient algorithms for many instances. A dynamic programming algorithm runs in pseudo-polynomial time: it tabulates all achievable sums, in time proportional to the number of elements times the total sum of the set — fast when the numbers are small, but exponential in the bit-length of large inputs. The Horowitz–Sahni meet-in-the-middle algorithm splits the set in half, enumerates all subset sums of each half (2^(n/2) of them), sorts one list, and searches for complementary pairs, improving the naive 2^n enumeration; Schroeppel–Shamir reduces its memory usage.

Special cases and applications

The equal-subset-sum and partition problems are close relatives. Subset sum underpinned the Merkle–Hellman knapsack cryptosystem, one of the first public-key cryptosystems; it was broken in the 1980s by Shamir and others exploiting the disguised superincreasing structure of its private key — a cautionary lesson that NP-completeness alone does not guarantee cryptographic security. Approximation versions of subset sum are tractable: an FPTAS can find a subset whose sum is within any desired factor of optimal.
