Buffer over-read

In computer security and programming, a buffer over-read or out-of-bounds read is an anomaly where a program, while reading data from a buffer, accesses memory past the end of the buffer. It is the read-side counterpart of the better-known buffer overflow, which involves writing past a buffer's end.

Causes

Buffer over-reads typically result from incorrect assumptions about the size or termination of incoming data — for example, trusting a length field in a network packet without validating it against the amount of data actually received, or reading past the end of a string that lacks a terminating null byte.

Consequences

An over-read can cause a program to crash if it reaches unmapped memory, or it can leak sensitive information stored adjacent to the buffer back to an attacker. The most famous example is the Heartbleed bug (CVE-2014-0160), disclosed in 2014, in which a missing bounds check in the OpenSSL implementation of the TLS heartbeat extension allowed attackers to read up to 64 kilobytes of server memory per request, potentially exposing private keys and passwords.

Prevention

Over-reads are mitigated by careful bounds checking, use of memory-safe languages, fuzz testing, and analysis tools such as AddressSanitizer, which detect out-of-bounds accesses at runtime.
