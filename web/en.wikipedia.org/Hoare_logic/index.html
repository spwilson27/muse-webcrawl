Hoare logic


A Hoare triple: if P holds before command C, then Q holds after

Hoare logic (also known as Floyd–Hoare logic) is a formal system of axioms and inference rules for reasoning rigorously about the correctness of computer programs. It was introduced by Tony Hoare in his 1969 paper "An Axiomatic Basis for Computer Programming", building on Robert Floyd's 1967 method of assigning assertions to flowchart nodes. Hoare logic underpins much of formal verification and influenced programming language design, including Hoare's own work on CSP.

Hoare triples

The central notion is the Hoare triple {P} C {Q}, where C is a command (program fragment), and P and Q are assertions — the precondition and postcondition. The triple asserts partial correctness: if P holds before executing C, and C terminates, then Q holds afterwards. For example, {x = n} x := x + 1 {x = n + 1}. Total correctness additionally requires a proof of termination.

Principal rules

The system includes an axiom for assignment — {P[E/x]} x := E {P}, substituting backwards — and rules of composition (sequencing), consequence (weakening/strengthening assertions), conditional (if-then-else) and iteration (while loops). The loop rule uses a loop invariant P: if {P ∧ B} C {P} for guard B, then {P} while B do C {P ∧ ¬B}. Finding good invariants is the creative core of program verification.

Extensions and legacy

Extensions handle arrays, pointers, procedures, concurrency and object-orientation. Notable descendants include Dijkstra's weakest-precondition calculus (1975), dynamic logic, and separation logic (Reynolds, O'Hearn, 2000s), which reasons locally about heap memory and supports tools such as Infer. Automated and interactive verification systems — Dafny, Frama-C, Coq-based verifiers and the seL4 microkernel proof — trace their foundations to Hoare logic, which remains a standard topic in computer science education.
