Graphics Device Interface

Graphics Device Interface (GDI)
DeveloperMicrosoft
First release1985 (Windows 1.0)
TypeGraphics API / system component
SuccessorDirect2D / Windows Imaging Component

The Graphics Device Interface (GDI) is a legacy Microsoft Windows application programming interface and core operating system component responsible for representing graphical objects and transmitting them to output devices such as monitors and printers. Introduced with Windows 1.0 in 1985, GDI allowed applications to draw in a device-independent way: the same drawing calls could target a screen, a printer or a memory bitmap, with device drivers translating the abstract operations to specific hardware.

Architecture

Applications draw through a device context (DC), an object that encapsulates a drawing surface and a set of selected tools — pens, brushes, fonts, bitmaps and regions. GDI primitives include lines, curves, rectangles, polygons, text output and bit-block transfers (BitBlt). The interface is implemented principally in the file Gdi32.dll, with a kernel-mode counterpart historically located in Win32k.sys. GDI+, released with Windows XP, added anti-aliasing, gradient fills and improved image handling on top of the classic API.

Limitations and legacy

GDI is a largely CPU-bound, immediate-mode 2D API without direct access to modern GPU acceleration. Microsoft introduced Direct2D and DirectWrite as hardware-accelerated successors, but GDI remains deeply embedded in Windows: the classic desktop window manager rendered through GDI for decades, and countless applications still depend on it, so it continues to be supported in current Windows versions. GDI objects are a limited resource, and leaks of handles are a classic source of application instability.
