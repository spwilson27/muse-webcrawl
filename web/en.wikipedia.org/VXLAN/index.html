VXLAN

Full nameVirtual Extensible LAN
StandardRFC 7348
PublishedAugust 2014
TransportUDP (destination port 4789)
Segment ID24-bit VNI (up to ~16 million segments)

Virtual Extensible LAN (VXLAN) is a network virtualization technology that uses encapsulation to run an overlay layer-2 network over an existing layer-3 infrastructure. It is specified in RFC 7348, published in 2014, and was developed by VMware, Cisco Systems, and other vendors to address the scalability limits of VLANs in large cloud computing and data center deployments.

Overview

VXLAN encapsulates an original Ethernet frame inside a UDP packet, adding a VXLAN header that contains a 24-bit VXLAN Network Identifier (VNI). Whereas a conventional VLAN identifier is only 12 bits — limiting a network to 4,094 segments — the VNI permits roughly 16 million isolated logical networks to coexist on the same physical infrastructure. Endpoints that perform the encapsulation and decapsulation are called VXLAN Tunnel Endpoints (VTEPs).

Operation

When a virtual machine sends a frame on a VXLAN segment, its local VTEP wraps the frame in a VXLAN header, an outer UDP header, and an outer IP header, then forwards it across the routed network to the destination VTEP, which strips the headers and delivers the original frame. Broadcast, unknown-unicast, and multicast traffic within a segment can be handled with IP multicast groups or by head-end replication in the control plane. Extensions such as BGP EVPN provide a standards-based control plane for learning MAC and IP addresses, reducing reliance on flood-and-learn behaviour.

Comparison with other technologies

VXLAN is similar in purpose to NVGRE and to Geneve, which later sought to unify overlay encapsulation formats. Compared with IEEE 802.1ad (Q-in-Q) or spanning-tree-based designs, VXLAN allows layer-2 segments to span routed layer-3 networks and makes full use of equal-cost multipath routing.
