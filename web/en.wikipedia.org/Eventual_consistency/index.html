Eventual consistency

From Wikipedia, the free encyclopedia

Eventual consistency is a consistency model used in distributed computing to achieve high availability. It guarantees that, if no new updates are made to a given data item, eventually all accesses to that item will return the last updated value — that is, all replicas will converge to the same state. Between an update and convergence, different replicas may return different (stale) values.

Context

Eventual consistency is a weak consistency model contrasted with strong consistency, in which every read returns the most recent write. The trade-off is described by the CAP theorem: under a network partition, a distributed system must choose between consistency and availability, and eventually consistent systems choose availability. Such systems are sometimes described by the acronym BASE — Basically Available, Soft state, Eventually consistent — as opposed to the ACID guarantees of traditional databases.

Mechanisms

Systems achieve convergence through techniques such as anti-entropy protocols and gossip protocols for spreading updates, vector clocks and version vectors for detecting concurrent writes, and conflict-resolution strategies including last-writer-wins timestamps, application-level merge functions, and conflict-free replicated data types (CRDTs). Amazon's Dynamo and its descendants (Cassandra, Riak, DynamoDB in its default mode) popularised the model for web-scale storage; the Domain Name System is an older example of an eventually consistent system.

Variants

Stronger models built on eventual consistency include causal consistency, read-your-writes consistency, monotonic reads, and session consistency, which repair specific anomalies users find surprising while keeping most operations available during partitions. Werner Vogels's 2008 article "Eventually Consistent" is a widely cited exposition of the concept.
