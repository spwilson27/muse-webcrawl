The travelling salesman problem (TSP) is one of the most famous problems in computer science and operations research. It asks: given a list of cities and the distances between each pair, what is the shortest possible route that visits each city exactly once and returns to the origin city? The problem is NP-hard — no known algorithm solves all instances efficiently — which makes it a central test case for optimisation methods and complexity theory.

Formulation

The TSP is naturally modelled on a complete weighted graph: vertices are cities, edge weights are distances, and the goal is a minimum-weight Hamiltonian cycle. The symmetric variant (undirected distances) is the classic case; the asymmetric variant models one-way costs such as flight fares. The number of possible tours grows factorially — (n−1)!/2 for symmetric TSP — so brute force is infeasible beyond tiny instances.

History

The problem was formalised in the 1930s (with early forms appearing in 19th-century German handbooks for salesmen) and named by the RAND Corporation in the 1950s. Dantzig, Fulkerson and Johnson solved a 49-city instance in 1954 with cutting-plane methods, founding modern integer programming approaches. The Held–Karp dynamic programming algorithm (1962) gives an exact O(n²·2ⁿ) solution. Concorde TSP Solver has solved instances with tens of thousands of cities to provable optimality, including a tour of 85,900 cities.

Approximations and applications

For metric TSP, Christofides's 1976 algorithm guarantees a tour within 1.5 times optimal; longstanding improvements have only recently appeared. Heuristics — nearest neighbour, Lin–Kernighan, simulated annealing, genetic algorithms — dominate practical use. Applications range from delivery routing and circuit-board drilling to DNA sequencing, where fragments must be assembled in an optimal order.
