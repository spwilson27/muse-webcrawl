HTTP compression

HTTP compression is a capability built into web servers and web clients to improve transfer speed and bandwidth utilisation by reducing the size of HTTP responses. A client advertises the compression schemes it accepts with the Accept-Encoding request header, and the server selects one — indicating it in the Content-Encoding response header — or declines to compress.

Schemes

The most widely used content codings are gzip (based on DEFLATE, supported since the late 1990s) and Brotli (br), released by Google in 2015, which usually achieves better ratios for text. The older deflate and compress codings are less common, and Zstandard (zstd) support has been added to browsers more recently.

Considerations

Compression is applied mainly to text formats such as HTML, CSS, JavaScript, JSON and XML, since media formats are typically already compressed. Compressing responses to requests containing secrets can enable compression side-channel attacks such as BREACH, so some applications disable compression for sensitive dynamic content.
