Static type checking

Static type checking is the process of verifying the type safety of a program based on analysis of its text (source code), performed before the program is run. It contrasts with dynamic type checking, in which type checks occur during execution. A programming language is said to be statically typed if type checking is performed at compile time rather than at run time.

Advantages

Static type checking catches a class of errors early: misapplied operations, wrong argument counts, and mismatched assignments are reported by the compiler before deployment. Types also serve as machine-checked documentation and enable optimisations, since the compiler can lay out data and dispatch calls without runtime checks.

Statically typed languages

Examples include Java, C#, Haskell, ML, Rust, and Go. Many of these use type inference — notably the Hindley–Milner algorithm — so annotations are needed only at boundaries.

Trade-offs

Static checking rejects some programs that would have run correctly, because it must be conservative. Dynamic languages such as Python and JavaScript allow greater flexibility; gradual typing systems such as TypeScript and Python's optional type hints let programmers add static checks incrementally.

Type soundness

A type system is sound if well-typed programs cannot produce type errors at run time — summarised by Robin Milner's slogan "well-typed programs cannot go wrong." In practice, most mainstream languages include escape hatches (casts, reflection, unsafe blocks) that weaken this guarantee.
