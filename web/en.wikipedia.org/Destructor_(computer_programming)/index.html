Destructor (computer programming)

A destructor runs automatically when an object's lifetime ends, releasing resources the object holds.

In object-oriented programming, a destructor is a method which is invoked mechanically just before the memory of an object is released. It can happen when the object's lifecycle is bound to a scope and the execution leaves the scope, when the object is embedded in another object whose lifetime ends, or when the object is explicitly released by calling delete or free. Its main purpose is to free the resources (memory allocations, open files and database connections, network connections, and so on) which were acquired by the object along its lifecycle and/or to delegate the release of resources to other objects.

By language

C++ gives destructors a central role: a destructor, written ~ClassName(), is invoked deterministically when an object goes out of scope or is deleted, and underpins the RAII (Resource Acquisition Is Initialization) idiom. Virtual destructors are needed when deleting polymorphically through a base-class pointer. In garbage-collected languages, cleanup is less deterministic: Java's Object.finalize() (deprecated since Java 9) and C#'s finalizers run at the garbage collector's discretion, so these languages instead emphasize explicit disposal patterns (AutoCloseable/try-with-resources in Java, IDisposable/using in C#). Python calls __del__ when an object is destroyed, Rust drops values deterministically via the Drop trait, and D and Objective-C provide their own destructor or dealloc conventions.

Critical aspects

Because destructors often run during stack unwinding or at program exit, throwing an exception from a destructor is dangerous — in C++ it leads to std::terminate if it escapes during unwinding, so destructors are implicitly noexcept since C++11. Destructors must also handle partial construction: a destructor runs for fully constructed subobjects even if a constructor threw.
