Heartbleed is a security bug in some outdated versions of the OpenSSL cryptography library, which is a widely used implementation of the Transport Layer Security (TLS) protocol. It was introduced into the software in 2012 and publicly disclosed in April 2014. Heartbleed could be exploited regardless of whether the vulnerable OpenSSL instance was running as a TLS server or client. It resulted from improper input validation in the implementation of the TLS heartbeat extension, hence the name.

Behaviour

The heartbeat extension allows a computer at one end of a connection to test whether the other end is still available by sending a known string of data and requiring a matching response. The flaw — a missing bounds check in OpenSSL's handling of heartbeat requests — allowed an attacker to request up to 64 kilobytes of the server's memory in a single query, potentially repeatedly, exposing passwords, session cookies and even the server's private encryption keys.

Impact and response

At the time of disclosure, roughly 17 percent of the Internet's secure web servers were believed vulnerable. Cloudflare famously challenged the security community to steal its private key via Heartbleed, and the challenge was quickly met, proving that private keys could indeed be extracted. Major websites forced password resets, and system administrators worldwide patched servers, revoked certificates and reissued keys. The bug also spurred new funding for open-source security projects and helped motivate the creation of forks and hardening efforts such as LibreSSL.
