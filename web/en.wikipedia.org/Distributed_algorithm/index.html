Distributed algorithm

Field: Distributed computing

Executes on: Multiple interconnected processors or nodes

Classic problems: Leader election, consensus, mutual exclusion, spanning tree

A distributed algorithm is an algorithm designed to run on computer hardware constructed from interconnected processors. Distributed algorithms are used in fields such as telecommunications, scientific computing, distributed information processing, and real-time process control. Each processor runs the algorithm concurrently and communicates with others, typically by message passing, since the processors do not share memory or a global clock.

Characteristics

Standard problems addressed by distributed algorithms include leader election, consensus, distributed search, spanning tree generation, mutual exclusion, and resource allocation. A central challenge is that the system lacks a single point of control and complete knowledge of the global state, and components may fail independently. The Byzantine generals problem formalizes the difficulty of reaching agreement when some components behave arbitrarily or maliciously.

Models

Distributed algorithms are analysed in models that specify how nodes communicate (message passing versus shared memory), whether execution is synchronous or asynchronous, and what kinds of failures can occur. Correctness and performance are measured by properties such as safety and liveness, and by message and time complexity.

Applications

Distributed algorithms underpin routing protocols in computer networks, distributed databases, peer-to-peer systems, sensor networks, and consensus mechanisms such as Paxos and Raft used to keep replicated services consistent. Leslie Lamport's work on logical clocks and Byzantine agreement, and Edsger Dijkstra's earlier self-stabilizing algorithms, laid much of the field's foundation.
