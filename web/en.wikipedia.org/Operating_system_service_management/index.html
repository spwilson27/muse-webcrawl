Operating system service management

Operating system service management refers to the mechanisms by which an operating system starts, stops, supervises and configures long-running background programs — called services on Windows and daemons on Unix-like systems. A service manager (or init system) typically acts as the first user-space process at boot, launches services in dependency order, restarts them on failure, and provides administrators with tools to query and control them.

Service managers supervise background programs throughout a system's uptime.

Unix and Linux

Traditional Unix systems used the System V init program, which ran shell scripts from runlevel directories. Modern successors include systemd (used by most major Linux distributions), which manages "units" and offers parallel startup, socket activation, journald logging and the systemctl tool; Upstart, formerly used by Ubuntu; OpenRC; runit; and the minimal s6. BSD systems use rc scripts, while macOS uses launchd, which inspired several Linux designs.

Windows

On Microsoft Windows, the Service Control Manager (services.exe) starts and supervises services configured in the registry. Administrators manage them with the Services console, the sc.exe command, or PowerShell cmdlets. Services can be set to start automatically, manually, or be disabled, and can be configured with recovery actions on failure.

Common features

  • Dependency-based or parallel startup
  • Automatic restart and watchdog supervision
  • Logging of service output
  • Resource limits and sandboxing (cgroups, privileges)
  • Status reporting and runtime control
