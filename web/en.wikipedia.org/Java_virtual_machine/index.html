Java virtual machine

A Java virtual machine (JVM) is a virtual machine that enables a computer to run Java programs as well as programs written in other languages that are also compiled to Java bytecode. The JVM is detailed by a specification that formally describes what is required in a JVM implementation. Having a specification ensures interoperability of Java programs across different implementations so that program authors using the Java Development Kit (JDK) need not worry about idiosyncrasies of the underlying hardware platform.

Design

The JVM operates on Java bytecode, an intermediate instruction set stored in .class files, typically generated from Java source code but also produced by compilers for other JVM languages such as Kotlin, Scala, Groovy, and Clojure. At runtime, the JVM loads class files, verifies their correctness, and executes them — by interpretation, by just-in-time (JIT) compilation to native machine code, or both. Oracle's HotSpot, the reference implementation's engine, adaptively optimizes frequently executed ("hot") code paths.

Key features

  • Platform independence — "write once, run anywhere": the same bytecode runs on any device with a JVM.
  • Automatic memory management — a garbage collector reclaims unreachable objects, with collectors ranging from the low-pause G1 to ZGC and Shenandoah.
  • Safety and security — bytecode verification, strong typing, and bounds checking.
  • Managed runtime services — multithreading, reflection, and dynamic class loading.

Implementations

The JVM reference implementation is developed under the OpenJDK project, with builds distributed by Oracle, Eclipse Adoptium (Temurin), Amazon (Corretto), Microsoft, and others. Alternative implementations include GraalVM, which supports ahead-of-time native compilation and polyglot execution, and the Android Runtime (ART), which executes DEX bytecode rather than standard JVM bytecode.
