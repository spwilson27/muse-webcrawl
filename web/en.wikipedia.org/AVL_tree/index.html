AVL tree

An AVL tree (named after its inventors, Georgy Adelson-Velsky and Evgenii Landis) is a self-balancing binary search tree. It was the first such data structure to be invented, published by Adelson-Velsky and Landis in a 1962 paper. In an AVL tree, the heights of the two child subtrees of any node differ by at most one; if they differ by more than one after an insertion or deletion, the tree is rebalanced using rotations.

Properties

Each node stores a balance factor — the height of its right subtree minus the height of its left subtree (or vice versa) — which in a valid AVL tree is −1, 0, or +1. The height of an AVL tree with n nodes is O(log n), specifically bounded by about 1.44 log2(n + 2) − 0.33, so search, insertion, and deletion all take O(log n) time in the worst case. The tight balance condition makes AVL trees more rigidly balanced than red–black trees, giving slightly faster lookups at the cost of potentially more rotations on updates.

Rebalancing

After modification, the algorithm retraces the path from the changed node to the root, updating balance factors. If a node becomes unbalanced, one of four cases applies: left-left and right-right imbalances are fixed by a single rotation, while left-right and right-left imbalances require a double rotation (a rotation of the child followed by a rotation of the node). Insertion needs at most one single or double rotation; deletion may require rotations at several levels, though still O(log n) overall.

Comparison and applications

AVL trees are preferred where lookups dominate, such as in-memory databases, ordered maps, and sets, while red–black trees are common in language libraries (for example, the Linux kernel and Java's TreeMap) because they need fewer rotations on insertions and deletions. AVL trees are also used in geometric and interval data structures and in functional data structures where strict balancing bounds are valuable.
