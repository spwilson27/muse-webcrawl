Adapter pattern

In software engineering, the adapter pattern is a software design pattern that allows the interface of an existing class to be used as another interface. It is often used to make existing classes work with others without modifying their source code. The pattern was described in the influential 1994 book Design Patterns by the "Gang of Four". An adapter is also sometimes called a wrapper.

Structure

An adapter has three main participants: the target interface the client expects; the adaptee, an existing class with an incompatible interface; and the adapter, which translates calls on the target interface into calls on the adaptee. In the object adapter variant the adapter holds a reference to the adaptee and delegates to it; in the class adapter variant (possible only with multiple inheritance) the adapter inherits from both the target and the adaptee.

Uses

Adapters are used to integrate legacy code or third-party libraries whose interfaces cannot be changed, to provide a uniform interface over several different classes, and in unit testing to wrap external dependencies. A everyday analogy is a power-plug travel adapter, which lets an appliance work with a foreign socket without modifying either.

Related patterns

The adapter pattern is related to, but distinct from, the bridge pattern (which separates abstraction from implementation up front), the decorator pattern (which adds behaviour while keeping the same interface), and the facade pattern (which presents a simplified interface to a whole subsystem).
