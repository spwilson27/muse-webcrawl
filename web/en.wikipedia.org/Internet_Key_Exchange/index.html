In computing, Internet Key Exchange (IKE, sometimes IKEv1 or IKEv2) is the protocol used to set up a security association (SA) in the IPsec protocol suite. IKE builds upon the Oakley protocol and ISAKMP, and uses a Diffie–Hellman key exchange to set up a shared session secret, from which cryptographic keys are derived.

IKEv1

IKE version 1, defined in RFC 2409 (1998), operates in two phases. In phase 1, two peers authenticate each other (using pre-shared keys, digital signatures, or public-key encryption) and establish a secure management channel. In phase 2, they negotiate the IPsec security associations that protect the actual data traffic. Phase 1 can run in main mode or the shorter aggressive mode.

IKEv2

IKE version 2, originally specified in RFC 4306 (2005) and clarified in RFC 7296, simplified the protocol: a typical initial exchange requires only four messages, it integrates NAT traversal, supports EAP authentication (common for remote-access VPNs), includes built-in liveness checks, and supports MOBIKE for handling address changes on mobile devices. Public key certificates with digital signatures remain the usual authentication method.

Implementations

IKE is implemented in most IPsec-based VPN products, including the open-source strongSwan and Libreswan projects and the built-in VPN stacks of major operating systems.
