Relocation (computing)

Relocation is the process of assigning load addresses for position-dependent code and data of a program and adjusting the code and data to reflect the assigned addresses. A linker usually performs relocation in combination with symbol resolution, binding symbolic references to actual addresses. Relocation information in an object file tells the linker or loader which locations in the code must be patched and how.

Overview

Compilers and assemblers generate object modules in which many addresses are relative to a notional base of zero. When modules are combined into an executable and placed in memory at some base address, references — such as jump targets and addresses of global data — must be adjusted by the difference between the assumed and actual base. Each patch site is described by a relocation entry giving its offset, the symbol it refers to, and the relocation type (for example absolute, or PC-relative).

Static and dynamic relocation

Static relocation is done once by the linker when the executable is created. Dynamic relocation is done by the loader or dynamic linker when the program is loaded, which is essential for shared libraries that may be mapped at different addresses in different processes. Techniques such as position-independent code (PIC) minimise the number of relocations a shared library needs, improving shareability and load time, though some — notably entries in the Global Offset Table and Procedure Linkage Table — typically remain.

Hardware relocation

On systems with virtual memory, a memory management unit translates virtual to physical addresses, largely removing the need for software relocation of whole programs. Historically, base-and-limit registers and relocation registers on machines such as the IBM System/360 performed a simpler form of hardware relocation.
