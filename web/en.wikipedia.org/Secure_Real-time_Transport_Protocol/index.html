Secure Real-time Transport Protocol

SRTP encrypts the RTP payload and appends an authentication tag, protecting voice and video streams in transit.

The Secure Real-time Transport Protocol (SRTP) is a profile of the Real-time Transport Protocol (RTP) intended to provide encryption, message authentication and integrity, and replay protection for RTP traffic in both unicast and multicast applications. It was published by the IETF in March 2004 as RFC 3711. A companion protocol, Secure RTCP (SRTCP), applies the same protections to the RTP Control Protocol.

Features

SRTP provides confidentiality by encrypting the RTP payload, historically with the Advanced Encryption Standard in counter mode or Segmented Integer Counter Mode, and in later profiles with AES in Galois/Counter Mode, which combines encryption and authentication. Integrity and authentication are provided by an HMAC-SHA1 authentication tag when a non-AEAD cipher is used. Replay protection uses a sliding window over packet sequence numbers. Only the payload is encrypted; the RTP header remains readable so that header compression and network monitoring can still function.

Key management

SRTP itself does not define how session keys are exchanged. Common key-management schemes include SDES (Security Descriptions, carried in SDP), DTLS-SRTP, in which keys are negotiated by a DTLS handshake, and ZRTP, developed by Phil Zimmermann, which negotiates keys in the media path itself. DTLS-SRTP is the mandatory approach in WebRTC, where SRTP support is required in all implementations.

Applications

SRTP is widely used to secure Voice over IP calls, videoconferencing systems, and browser-based real-time communication. Because it adds only a small per-packet overhead, typically a few bytes for the authentication tag, it is well suited to latency-sensitive media.
