Refactoring

In computer programming and software design, refactoring is the process of restructuring existing source code — changing the factoring — without changing its external behaviour. Refactoring is intended to improve the design, structure, and implementation of the software (its non-functional attributes), while preserving its functionality. Potential advantages include improved code readability and reduced complexity, which can improve maintainability and make it easier to add new features.

Techniques

The term was popularised by Martin Fowler's 1999 book Refactoring: Improving the Design of Existing Code, which catalogued small, behaviour-preserving transformations such as Extract Method, Rename Variable, Move Method, Replace Conditional with Polymorphism, and Introduce Parameter Object. Refactorings are typically applied as a series of tiny steps, with automated unit tests run frequently to catch regressions — a practice central to extreme programming and test-driven development, where refactoring forms one part of the red–green–refactor cycle.

Motivations and risks

Common motivations include removing code smells and duplication, clarifying intent, and preparing code for a new feature ("make the change easy, then make the easy change"). Modern integrated development environments automate many refactorings (renaming, moving, extracting) with guaranteed semantics in statically typed languages. Risks include introducing defects in untested code, conflicts with parallel development, and time spent on restructuring with no visible short-term payoff; hence refactoring is best done continuously in small increments rather than in large rewrites.
