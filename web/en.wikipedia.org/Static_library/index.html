Static library

Filename extensions: .a (Unix), .lib (Windows)
Created by: Archiver (ar)
Related: Dynamic library

In computer science, a static library or statically linked library is a set of routines, external functions and variables which are resolved in a caller at compile-time and copied into a target application by a compiler, linker, or binder, producing an object file and a stand-alone executable.

Overview

A static library is an archive of object files. On Unix-like systems it is created with the ar archiver and conventionally carries the .a extension; on Microsoft Windows the extension is .lib. When a program is linked against a static library, the linker copies only the object modules actually referenced by the program into the final executable.

Advantages and disadvantages

Static linking produces a self-contained executable that does not depend on the presence of the library at run time, simplifying deployment and avoiding version conflicts sometimes called "DLL hell". The disadvantages include larger executable files, duplication of library code across processes, and the need to recompile and redistribute the program to benefit from library bug fixes — in contrast to a dynamic library, which is loaded at run time and can be updated independently.
