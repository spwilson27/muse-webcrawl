Backward compatibility

Backward compatibility (also called downward compatibility) is a property of a system, product or technology that permits it to be used with interfaces, data or accessories created for an earlier version. A new product is backward compatible if it works with the inputs and accessories of its predecessors; the reverse property — old products working with new ones — is forward compatibility.

Examples

Famous cases include the Intel x86 processor family, which still runs software written for the 8086 of 1978; game consoles such as the PlayStation 2, which played PlayStation discs; and software file formats, such as newer versions of office suites opening documents saved decades earlier. In telecommunications, standards bodies have often required new generations to interwork with old — while the shift to digital television and mobile networks shows compatibility sometimes being deliberately abandoned.

Trade-offs

Maintaining backward compatibility protects customers' investments and eases migration, but it imposes cost and complexity: legacy quirks accumulate, security flaws may be preserved, and design is constrained by old decisions. Developers sometimes joke that every bug becomes a feature once users depend on it. Breaking compatibility, conversely, risks fragmenting the user base and stranding old data and equipment.
