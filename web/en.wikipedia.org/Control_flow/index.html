Control flow

In computer science, control flow (or flow of control) is the order in which individual statements, instructions or function calls of an imperative program are executed or evaluated. Emphasis on explicit control flow distinguishes imperative and declarative programming languages. Within an imperative program, a control flow statement is a statement that results in a choice being made as to which of two or more paths to follow.

Control structures

The basic control structures are sequence (statements executed in order), selection (conditionals such as if–then–else and switch/case), and iteration (loops such as for, while and do–while). The structured program theorem shows that these three suffice to express any computable function, and structured programming advocates restricting programs to them rather than unrestricted jumps. Most languages also provide loop exits (break, continue), procedure and function calls with returns, and mechanisms for exceptional conditions.

Unconditional branches and exceptions

Unconditional jumps (such as goto) were common in early languages but were famously criticized by Edsger Dijkstra in 1968. Exception handling provides a structured way to transfer control when errors or unusual conditions occur, using try/catch/finally constructs. Continuations, coroutines, generators and asynchronous constructs (async/await) generalize control flow further, enabling suspension and resumption of computations.
