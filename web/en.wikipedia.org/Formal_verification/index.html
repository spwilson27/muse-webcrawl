Formal verification

Formal verification proves a system model satisfies a formal specification.

In the context of hardware and software systems, formal verification is the act of proving or disproving the correctness of a system with respect to a certain formal specification or property, using formal methods of mathematics. Formal verification is a key incentive for formal specification of systems, and is at the core of building reliable, safety-critical systems, as it can find errors in system design that simulation and testing may miss.

Approaches

  • Model checking — an algorithm exhaustively explores the states of a finite-state model against a property expressed in temporal logic, producing a counterexample when the property fails. Tools include SPIN, NuSMV and TLA+, whose creator Leslie Lamport promoted specification before implementation.
  • Theorem proving — properties are expressed in a logic and proved with interactive proof assistants such as Coq, Isabelle and Lean, or automatically with SMT solvers such as Z3. Theorem proving can handle infinite state spaces but requires human guidance.
  • Equivalence checking and property checking — widely used in chip design to confirm that a circuit implementation matches its register-transfer-level description.

Applications

The 1994 Pentium FDIV bug, which cost Intel roughly $475 million, greatly increased industry interest in formal methods. Landmark verified systems include the seL4 microkernel, whose functional correctness was proved in Isabelle/HOL; the CompCert optimizing C compiler, verified in Coq; and the protocols and algorithms formally specified at Amazon Web Services using TLA+. Formal verification is also used in avionics (under DO-178C's formal methods supplement), railway signalling, and increasingly for smart contracts.

Limitations

Verification proves that a system meets its specification — not that the specification captures what users actually want. State explosion limits model checking, proofs are costly to develop and maintain, and verified models may still diverge from physical hardware or deployed binaries.
