Structural type system

A structural type system (or property-based type system) is a major class of type system in which type compatibility and equivalence are determined by the type's actual structure and not by other characteristics such as its name or place of declaration. Structural systems are used to determine if types are equivalent and whether a type is a subtype of another.

Comparison with nominal typing

In a nominal type system, two types are compatible only if they share the same name or an explicitly declared inheritance relationship — as in Java or C#. In a structural system, by contrast, a value of one type can be used wherever another type is expected provided it has all the required members with compatible types. This is closely related to the informal notion of duck typing, except that compatibility is checked statically by the compiler.

Languages

TypeScript is a prominent structurally typed language: object types are compatible if their members match, regardless of declared names. Go uses structural typing for interfaces — a type satisfies an interface simply by implementing its methods, without any explicit declaration. OCaml uses structural typing for object types and polymorphic variants, while Haskell is principally nominal but offers structural features in some extensions.

Advantages and disadvantages

Structural typing supports flexible, decoupled code: independently developed libraries can interoperate without sharing declarations. Its disadvantages include the possibility of accidental compatibility — two types with the same shape but different meanings (such as a type for metres and a type for feet) are treated as interchangeable — and sometimes less informative error messages and less complete documentation of intent.
