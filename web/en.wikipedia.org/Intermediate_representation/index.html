Intermediate representation

From Wikipedia, the free encyclopedia

An intermediate representation (IR) is the data structure or code used internally by a compiler or virtual machine to represent source code. An IR is designed to be conducive to further processing, such as optimization and translation. A "good" IR must be able to represent the source code without loss of information and to be independent of any particular source or target language.

The central phases of a typical compiler—analysis, optimization, and synthesis—are often separated by one or more intermediate representations. The front end parses source code and produces an IR; machine-independent optimizations are applied to the IR; the back end then generates target machine code from the IR. This retargetable structure lets one compiler support many source languages and many target architectures by combining front ends and back ends around a shared IR.

Forms

Intermediate representations take several forms:

  • Graph-based representations, such as abstract syntax trees, directed acyclic graphs and control-flow graphs.
  • Linear representations, resembling instructions for an abstract machine, such as three-address code.
  • Static single assignment (SSA) form, in which each variable is assigned exactly once, simplifying many optimizations; used by LLVM and GCC's GIMPLE.

Examples

Well-known examples include LLVM IR, the Java bytecode of the Java Virtual Machine, the Common Intermediate Language of the .NET framework, GCC's GENERIC and GIMPLE, and the register transfer language (RTL) used in GCC's later stages.
