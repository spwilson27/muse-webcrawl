Candidate key

A candidate key, or simply a key, of a relational database is any set of columns that have a unique combination of values in each row, with the additional constraint that removing any column could produce duplicate combinations of column values. Put formally, a candidate key is a minimal superkey: a set of attributes that uniquely identifies each tuple (row) of a relation and contains no redundant attributes.

Definitions

A superkey is any set of attributes whose values uniquely identify rows. A candidate key is a superkey that is irreducible — none of its proper subsets is also a superkey. A relation may have several candidate keys; one is usually chosen as the primary key, the remainder becoming alternate keys. A candidate key consisting of more than one attribute is called a composite key. Attributes that belong to any candidate key are called prime attributes.

Example

In an employee table, the set {employee ID} may be a candidate key if IDs are unique, and {national insurance number} may be another; the designer might select employee ID as the primary key. By contrast, {employee ID, department} is a superkey but not a candidate key, because the department attribute is unnecessary for uniqueness.

Practical use

Database designers identify candidate keys from functional dependencies in the data, and enforce them with unique constraints or unique indexes so the database management system rejects duplicate key values. Surrogate keys — arbitrary system-generated identifiers — are often chosen as primary keys when no stable natural candidate key exists.
