Inter-process communication

In computer science, inter-process communication (IPC), also spelled interprocess communication, are the mechanisms provided by an operating system for processes to manage shared data. Typically, applications can use IPC, categorized as clients and servers, where the client requests data and the server responds to client requests.

Approaches

Principal IPC mechanisms include:

  • Files — one process writes data that another reads.
  • Signals — simple system messages notifying a process of an event.
  • Sockets — data streams over an interface, local or across a network.
  • Message queues — ordered streams of messages stored by the kernel.
  • Pipes — including anonymous and named pipes, connecting process output to input.
  • Shared memory — a memory region mapped into multiple processes, usually requiring semaphores or other synchronization to avoid race conditions.

Synchronous and asynchronous communication

Message-passing may be blocking (synchronous), where a sender waits until the message is delivered, or non-blocking (asynchronous), where the sender continues immediately, requiring buffering. IPC between machines is generally handled with network mechanisms such as sockets, remote procedure calls, and message brokers.
