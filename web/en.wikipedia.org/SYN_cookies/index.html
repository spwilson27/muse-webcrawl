SYN cookies

SYN cookies are a technique used to resist SYN flood denial-of-service attacks against TCP servers. Invented by Daniel J. Bernstein in 1996, the method avoids allocating connection state when a SYN packet arrives, instead encoding the necessary connection information into the sequence number of the SYN-ACK response — the "cookie".

Operation

When a client sends a SYN, the server computes a cryptographic hash of the source and destination addresses and ports plus a secret value and a timestamp, and uses part of it as the initial sequence number. No memory is allocated. If the client completes the handshake by returning the cookie incremented by one in its ACK, the server validates it and only then creates the connection state, reconstructing the limited options that could be encoded.

Trade-offs

Because only a few bits are available, some TCP options cannot be preserved when cookies are in use. Implementations such as the Linux kernel therefore enable SYN cookies only when the connection queue overflows, using them as a fallback under attack rather than for every connection.
