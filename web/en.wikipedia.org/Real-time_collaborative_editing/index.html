Real-time collaborative editing

Real-time collaborative editing is a type of collaborative editing in which multiple users edit the same document simultaneously over a network, with each user's changes visible to the others nearly instantaneously. It contrasts with non-real-time modes, such as editing based on merging or locking whole documents. Well-known examples include Google Docs, Microsoft 365's web applications, Etherpad, and collaborative code editors.

History

Early research systems of the 1980s and 1990s, such as GROVE and the Jupiter system, established the core algorithms. The technology reached mass use in the 2000s with web-based office suites; Google Docs grew out of Writely, acquired by Google in 2006. Shared cursors, presence indicators and coloured carets showing each participant became standard features.

Technical challenges

The central problem is concurrency control: users may edit the same characters at the same time from different locations, and the system must keep all replicas consistent while preserving each user's intention. Two families of algorithms dominate: operational transformation (OT), which transforms concurrent operations against one another, and conflict-free replicated data types (CRDTs), which design data structures so that concurrent updates commute and replicas converge automatically. Other challenges include undo in a shared document, offline editing and synchronisation, access control, and scalability to many simultaneous editors.

Benefits and drawbacks

Real-time collaboration removes merge conflicts and version confusion, supports immediate feedback and co-authoring, but can create distractions, social pressure and difficulties with attribution and accountability compared with asynchronous editing.
