Forward secrecy

Ephemeral key exchange ensures each session uses fresh keys that are discarded afterwards.

In cryptography, forward secrecy (FS), also known as perfect forward secrecy (PFS), is a property of secure communication protocols in which compromise of long-term keys does not compromise past session keys. It protects past sessions against future compromises of keys or passwords: an attacker who records encrypted traffic and later obtains the server's private key cannot decrypt the recorded sessions.

How it works

Forward secrecy is typically achieved by generating a fresh, ephemeral key pair for each session using the Diffie–Hellman key exchange, and deleting the ephemeral private key when the session ends. Because the session key is never stored and cannot be recomputed from the long-term key alone, stealing the long-term key yields nothing about past sessions. The term was coined by Whitfield Diffie, Paul van Oorschot, and Michael Wiener in 1992.

Deployment

Early versions of TLS often used RSA key transport, in which the session key is encrypted under the server's long-term key and therefore lacks forward secrecy. Modern practice uses ephemeral Diffie–Hellman (DHE) or elliptic-curve ephemeral Diffie–Hellman (ECDHE) cipher suites. TLS 1.3, published in 2018, made forward secrecy mandatory by removing non-ephemeral key exchange. Forward secrecy is also central to secure messaging protocols such as the Signal Protocol, whose "double ratchet" additionally provides post-compromise security by continually updating keys during a session.

Limitations

Forward secrecy protects only past communications; it does not protect future sessions after a compromise, nor data stored at the endpoints. It also cannot help if an adversary compromises a device during a live session. Its main cost is modest additional computation and the loss of some passive network-inspection techniques used by enterprises.
