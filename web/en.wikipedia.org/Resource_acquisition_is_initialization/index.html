Resource acquisition is initialization

Resource acquisition is initialization (RAII) is a programming idiom used in several object-oriented, statically typed programming languages, most notably C++, to describe a particular language behaviour. In RAII, holding a resource is a class invariant, and is tied to object lifetime: resource allocation (or acquisition) is done during object creation (specifically initialization), by the constructor, while resource deallocation (release) is done during object destruction, by the destructor.

Motivation

Resources such as heap memory, file handles, network sockets, mutexes, and database connections must be released once no longer needed. Manual management is error-prone, especially when exceptions can interrupt control flow. By binding a resource to the lifetime of an object, RAII guarantees that the resource is released whenever the object goes out of scope, including during stack unwinding after an exception.

Examples

In C++, the standard library's smart pointers, such as std::unique_ptr and std::shared_ptr, apply RAII to dynamic memory, and std::lock_guard applies it to mutexes. Class templates such as file streams acquire the file on construction and close it on destruction. The idiom is central to exception-safe C++ design, as described by Bjarne Stroustrup and in the C++ Core Guidelines.

Other languages

Related deterministic-cleanup mechanisms exist in other languages, such as Rust's ownership and Drop trait, Ada's controlled types, and scoped guards in D. Languages relying on garbage collection, such as Java and C#, typically use constructs like try-with-resources or using blocks to approximate RAII for non-memory resources.
