Exception handling

Exception handling — the process of responding to anomalous or exceptional conditions during program execution.

Exception handling is the process of responding to the occurrence of exceptions — anomalous or exceptional conditions requiring special processing — during the execution of a program. In general, an exception breaks the normal flow of execution and executes a pre-registered exception handler; the details of how this is done depend on whether it is a hardware or software exception.

Exception handling, if provided, is facilitated by specialized programming language constructs, hardware mechanisms like interrupts, or operating system inter-process communication facilities such as signals. Some exceptions, especially hardware ones, may be handled so gracefully that execution can resume where it was interrupted.

Definition

An exception is a problem that arises during the execution of a program. A programming language mechanism for exception handling is generally expected to support raising an exception, which transfers control to a handler, and to allow the handler to inspect information about the exceptional condition, typically carried in an exception object.

Language mechanisms

Many modern languages provide try, catch (or except) and finally constructs derived from work in languages such as CLU and Ada:

try {
    riskyOperation();
} catch (IOException e) {
    log(e);
} finally {
    cleanup();
}

In languages such as C++, Java, C#, Python and Ruby, exceptions are thrown with a throw or raise statement and caught by syntactically enclosing handlers.

Checked and unchecked exceptions

Java introduced the notion of checked exceptions, which must be declared in a method's signature and handled by callers. Most other languages chose unchecked exceptions only, and the merits of checked exceptions remain debated.

Exception safety

In C++, exception safety describes guarantees a component provides about program state when an exception is thrown, commonly classified as no-throw, strong, basic and no guarantees.

Alternatives

Other error-handling styles include returning error codes, option/maybe types, result types, and condition systems (as in Common Lisp) that allow restarting computation from the point of failure.
