Use after free

A pointer remains after its object is freed; the memory may be reallocated

Use after free
TypeMemory safety bug (temporal)
CWECWE-416
RelatedDangling pointer, double free, null pointer dereference
Common inC, C++ and other manually memory-managed languages

Use after free is a class of software bug in which a program continues to use a pointer to memory after that memory has been freed (deallocated). Because the allocator may reuse the freed region for another object, the stale pointer can read or write data belonging to a different object, causing crashes, data corruption, or — in security contexts — privilege escalation and arbitrary code execution.

Causes

Typical causes include error paths that free an object while other code still holds pointers to it, complex ownership relationships without a clear discipline, premature deallocation callbacks, and the related double free error, in which memory is freed twice. Use-after-free vulnerabilities have featured prominently among serious browser, kernel and operating-system exploits, and are regularly assigned CVE identifiers.

Detection and prevention

Mitigations and defences include setting pointers to null after freeing (which converts some errors into more detectable null dereferences), smart pointers and ownership systems such as C++'s unique_ptr and the borrow checker of Rust, garbage collection, sanitizers such as AddressSanitizer, hardened allocators that quarantine freed memory, and type-safe designs such as generational handles. Static analysis and fuzzing are widely used to find use-after-free bugs before release.
