Extensibility

Extensibility is a software engineering and systems design principle that applies to the design of software, hardware, protocols, and formats in which the implementation takes future growth into consideration. An extensible system can be extended — new functionality can be added without modifying the existing structure, or with minimal modification — making the design easier to change and reducing the risk that future requirements will force a complete rewrite.

Mechanisms

Extensibility is achieved through mechanisms such as plug-in architectures, application programming interfaces (APIs), configuration files, scripting hooks, inheritance and polymorphism in object-oriented design, and self-describing formats with reserved fields for later use. Markup languages such as XML were designed explicitly for extensibility, allowing new elements without breaking existing documents. Formats like HTML historically relied on graceful degradation, in which browsers ignore unknown elements, permitting forward-compatible evolution.

Trade-offs

Extensibility is not free: designing for unknown future requirements adds complexity and can be misused, producing over-engineered systems burdened by speculative features (the "inner-platform effect" and violations of the YAGNI principle). Successful extensible designs balance flexibility against simplicity, and openness against security — extension points such as macros and plug-ins can introduce vulnerabilities, as with malicious browser extensions or macro viruses. Extensibility is closely related to, but distinct from, scalability (the ability to handle increased load) and interoperability (the ability to work with external systems).
