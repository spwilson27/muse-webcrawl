Denormalization

In database theory, denormalization is a strategy used on a previously normalized database to increase performance. In computing, denormalization is the process of trying to improve the read performance of a database, at the expense of losing some write performance, by adding redundant copies of data or by grouping data.

Denormalization trades redundancy for faster reads

Motivation

A normalized design minimizes redundancy and update anomalies, but queries spanning many tables require joins, which can be expensive on large data volumes. Where read load dominates — reporting systems, data warehouses, and high-traffic web applications — deliberately duplicating data can eliminate joins and precompute aggregates.

Techniques

Common techniques include storing derived values (such as totals) alongside their components, keeping redundant copies of a column in multiple tables, maintaining summary or materialized tables refreshed periodically, and flattening hierarchies into a single table. In NoSQL systems such as document databases, embedding related data in one document is a form of denormalization built into the data model.

Trade-offs

Redundant data can become inconsistent if updates fail to propagate, so denormalized designs need discipline: application-level maintenance, triggers, or scheduled reconciliation. Denormalization increases storage use and slows writes, and is normally applied selectively, after measurement shows a normalized design cannot meet performance goals.
