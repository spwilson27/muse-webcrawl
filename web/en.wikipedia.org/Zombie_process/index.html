Zombie process

From Wikipedia, the free encyclopedia

On Unix and Unix-like computer operating systems, a zombie process or defunct process is a process that has completed execution (via the exit system call) but still has an entry in the process table. This is a process in the terminated state. This occurs for the child processes, where the entry is still needed to allow the parent process to read its child's exit status: once the exit status is read via the wait system call, the zombie's entry is removed from the process table and it is said to be "reaped".

Overview

When a process ends via exit, all of the memory and resources associated with it are deallocated so they can be used by other processes. However, the process's entry in the process table remains. The parent can read the child's exit status by executing the wait system call, whereupon the zombie is removed. The wait call may be executed in sequential code, but it is commonly executed in a handler for the SIGCHLD signal, which the parent receives whenever a child has died.

Consequences

A child process always first becomes a zombie before being removed from the process table. In most cases, zombies are very brief, but if a parent program fails to reap its children — because of a bug or because it was written carelessly — the zombies accumulate. A zombie itself consumes almost no resources besides a process ID and a process-table entry, but a large number of zombies can exhaust the available process IDs and prevent new processes from starting. Zombies cannot be killed with the kill command, because they are already dead; the remedy is to fix or terminate the parent process, after which the zombies are adopted by init (PID 1) and reaped automatically.
