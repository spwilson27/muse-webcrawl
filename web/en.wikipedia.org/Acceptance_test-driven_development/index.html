Acceptance test-driven development
Related to: Test-driven development, behavior-driven development
Practice: Acceptance criteria defined before coding

Acceptance test-driven development (ATDD) is a development methodology based on communication between the business customers, the developers, and the testers. ATDD encompasses many of the same practices as specification by example, behavior-driven development (BDD), and example-driven development.

Process

In ATDD, the team collaboratively defines acceptance tests that express the desired behavior of a feature before implementation begins. Developers then write code to make the tests pass, often automating them so they run continuously as regression tests.

Benefits

ATDD helps align software with business requirements, provides living documentation, and reduces defects discovered late in development. It extends the unit-level cycle of test-driven development to the feature level.
