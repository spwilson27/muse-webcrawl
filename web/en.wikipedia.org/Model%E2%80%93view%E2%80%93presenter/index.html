Model–view–presenter

Model–view–presenter (MVP) is a software architectural pattern derived from model–view–controller (MVC), used mainly for building user interfaces. MVP separates an application into three components: the model, which manages data and business logic; the view, which displays data and routes user commands; and the presenter, which acts on the model and the view, retrieving data, formatting it for display, and deciding how the view responds to input.

History

The pattern was developed at Taligent in the 1990s by Mike Potel and described in a 1996 paper, as a refinement of MVC tailored to modern GUI frameworks. It later became popular in Microsoft .NET development, including the Web Client Software Factory for ASP.NET, and in Google Web Toolkit and Android application design.

Variations

Two main variants are distinguished. In passive view, the view contains almost no logic and is updated entirely by the presenter, which maximises testability. In supervising controller, the view handles simple data binding directly while the presenter manages more complex interactions. In both, the presenter interacts with the view through an interface, allowing the view to be replaced by a mock object in unit tests — a principal motivation for MVP over classic MVC in environments where controllers are hard to isolate.

Comparison with related patterns

MVP is closely related to model–view–viewmodel (MVVM), which replaces the presenter with a viewmodel exposed through data binding, and to presentation–abstraction–control. The choice among them depends on the data-binding capabilities of the platform.
