RC4

In cryptography, RC4 (Rivest Cipher 4, also known as ARC4 or ARCFOUR) is a stream cipher. While it is remarkable for its simplicity and speed in software, multiple vulnerabilities have been discovered in RC4, rendering it insecure. It is especially vulnerable when the beginning of the output keystream is not discarded, when nonrandom or related keys are used, or when the same key is reused. RC4 was widely used in protocols such as Transport Layer Security (TLS) and WEP, but its use in TLS was prohibited by RFC 7465 in 2015.

History

RC4 was designed by Ron Rivest of RSA Security in 1987. It was initially a trade secret, but in September 1994 a description of it was anonymously posted to the Cypherpunks mailing list and then to the sci.crypt newsgroup, from where it spread widely. Because RSA Security had never officially released the algorithm, the leaked version was dubbed "ARCFOUR" to avoid trademark issues.

Algorithm

RC4 generates a pseudorandom stream of bits (a keystream) from a key of 1 to 256 bytes using two phases: a key-scheduling algorithm (KSA) that permutes a 256-byte state array S based on the key, and a pseudo-random generation algorithm (PRGA) that repeatedly swaps elements of S and outputs bytes. Encryption XORs the keystream with plaintext.

Security

Biases in the early keystream bytes (Fluhrer–Mantin–Shamir analysis, 2001) enabled the practical cracking of WEP Wi-Fi encryption. Later, increasingly strong statistical attacks against RC4 in TLS led the IETF to prohibit its use in TLS in 2015, and browsers and Microsoft removed support. RC4 survives in legacy systems and some malware, but it should not be used in new designs.
