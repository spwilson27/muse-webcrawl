Multiple dispatch

Multiple dispatch or multimethods is a feature of some programming languages in which a function or method can be dynamically dispatched based on the run-time type of more than one of its arguments. This is a generalization of single dispatch — the polymorphism found in most object-oriented languages, where a method call is dispatched only on the type of the object through which it is invoked (the implicit this or self argument). With multiple dispatch, a function such as collide(a, b) can select an implementation specialised for the pair of types (Asteroid, Spaceship), (Spaceship, Asteroid), and so on, without nested conditional logic or the visitor pattern.

Languages

Multiple dispatch is central to the Common Lisp Object System (CLOS), where generic functions dispatch on all required arguments, and to Dylan, Julia, and Fortress. In Julia, multiple dispatch is the core design paradigm: nearly all built-in functions are generic functions with many methods specialized on argument types. Languages without native support emulate multimethods with libraries — for example, C++ through the visitor pattern or double dispatch, Python through the multimethod and singledispatch (single-argument only) modules, and C# through the dynamic keyword, which performs run-time overload resolution.

Semantics

When several methods are applicable, the implementation typically selects the most specific one according to a precedence order over the argument types; ambiguous ties may be resolved by argument order (as in CLOS) or signalled as errors. Method combination rules, as in CLOS's standard method combination with :before, :after, and :around methods, can further structure dispatch.

Advantages and criticism

Supporters argue that multiple dispatch yields open, extensible code: new types and new operations can be added independently, addressing the "expression problem", and binary operations such as arithmetic between mixed numeric types become natural. Critics note potential performance costs, ambiguity errors, and reduced encapsulation compared with class-based single dispatch.
