Pipeline (Unix)

In Unix-like computer operating systems, a pipeline is a mechanism for inter-process communication using message passing: a chain of processes arranged so that the output of each element (its standard output) feeds directly as input to the next (its standard input). The concept was introduced by Douglas McIlroy and implemented in Unix shells, where pipelines are written with the vertical bar character: command1 | command2 | command3.

Concept

Each process in the pipeline runs concurrently, connected by operating-system pipes — anonymous buffers through which data streams. A process blocks when it writes to a full pipe or reads from an empty one, which synchronizes the chain automatically. Pipelines embody the Unix philosophy of composing simple, single-purpose tools: for example, ls | grep ".txt" | wc -l lists files, filters those whose names contain ".txt", and counts them.

History

McIlroy had proposed "coupling programs like a garden hose" as early as 1964 and pressed for the idea for years; pipelines were implemented in Unix in 1973. The notation influenced later shells and operating systems, including DOS, Windows PowerShell (which passes objects rather than text), and dataflow programming environments.

Named pipes and variants

A related mechanism is the named pipe or FIFO, a pipe that exists as a file in the filesystem and lets unrelated processes communicate. Shells also support process substitution and "pipelines" that capture exit statuses (such as bash's PIPESTATUS), while anonymous pipes remain one of the basic primitives created by the pipe() system call.
