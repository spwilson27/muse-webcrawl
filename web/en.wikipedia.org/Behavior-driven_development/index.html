Behavior-driven development

In software engineering, behavior-driven development (BDD) is a software development process that encourages collaboration among developers, quality assurance experts, and customer representatives in a software project. It encourages teams to use conversation and concrete examples to formalize a shared understanding of how the application should behave. It emerged from test-driven development (TDD).

Principles

Behavior-driven development specifies that tests of any unit of software should be specified in terms of the desired behavior of the unit. Borrowing from the terminology of domain-driven design, the "desired behavior" in this case consists of the requirements set by the business — that is, the desired behavior that has business value for whatever entity commissioned the software unit.

Behavioral specifications

BDD uses the Given-When-Then format to describe examples of expected behavior in a structured natural language that can be partially automated:

Given some initial context,
When an event occurs,
Then ensure some outcomes.

Tools such as Cucumber, Behave and SpecFlow parse these specifications, written in a language such as Gherkin, into executable tests.

History

Dan North developed BDD in the mid-2000s as a response to the difficulties of teaching and applying test-driven development, replacing the word "test" with "behavior" to focus attention on specification rather than verification.
