Three-phase commit protocol

In computer networking and databases, the three-phase commit protocol (3PC) is a distributed algorithm which lets all nodes in a distributed system agree to commit a transaction. It is an extension of the two-phase commit protocol (2PC) designed to reduce the risk that a failure of the coordinator blocks the transaction indefinitely.

Phases

Like 2PC, 3PC begins with a voting phase in which the coordinator asks all cohorts whether they can commit. It then inserts a second phase — the pre-commit (or "prepared to commit") phase — in which the coordinator informs cohorts that all have voted yes. Only after cohorts acknowledge the pre-commit does the coordinator issue the final commit decision.

Advantages and limitations

The extra phase means that if the coordinator fails after sending pre-commit messages, a recovery coordinator can determine that the transaction was proceeding to commit and safely complete it, avoiding the blocking problem of 2PC. However, 3PC is vulnerable to network partitions, in which different subsets of nodes may reach different decisions, and for that reason it is less widely deployed in practice than 2PC.
