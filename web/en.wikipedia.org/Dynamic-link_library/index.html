Dynamic-link library

Diagram of a program loading a DLL at run time (placeholder image)

A dynamic-link library (DLL) is Microsoft's implementation of the shared library concept in the Microsoft Windows and OS/2 operating systems. DLL files have the .dll extension (or .ocx for libraries containing ActiveX controls) and contain code, data and resources that multiple programs can use simultaneously.

Characteristics

Unlike static libraries, which are linked into an executable at compile time, a DLL is loaded at run time. A program can load a DLL implicitly when it starts, or explicitly during execution using functions such as LoadLibrary and GetProcAddress. DLLs export functions and variables listed in an export table, and executables record their DLL dependencies in an import table. Because the library code is shared in memory, updates to a DLL can benefit all programs using it, and total memory use is reduced.

Versioning and "DLL hell"

The sharing of DLLs historically produced "DLL hell": installations that overwrote shared libraries with incompatible versions, breaking other applications. Later mitigations included version resources, side-by-side assemblies and the Windows File Protection system.

Uses

Windows itself is largely implemented through DLLs such as kernel32.dll, user32.dll and gdi32.dll. DLLs are also used for device drivers, COM components, application plug-ins, and localization resource files.
