Application server

An application server is a server that hosts applications or software that delivers a business application through a communication protocol. For a typical web application, the application server sits behind the web servers (or included in them) and performs tasks requested by clients, often connecting to database servers. Examples include Jakarta EE application servers such as WildFly, GlassFish, WebLogic, and WebSphere, as well as Microsoft's .NET platform and numerous language-specific frameworks.

Three-tier architecture: web, application, and database servers

History

The term originally referred to servers in client–server systems that ran the bulk of business logic, distinct from file servers and database servers. It came to prominence in the 1990s with the rise of three-tier architectures and early web applications, and expanded during the Java EE era, when vendors offered standardized containers providing transactions, security, persistence, messaging, and connection pooling.

Services

Application servers typically provide middleware services including: transaction management, security and authentication, database connection pooling, load balancing and clustering for high availability, messaging (such as JMS), web services support (SOAP/REST), and dependency injection or component models (e.g., Enterprise JavaBeans, Servlets). Modern lightweight frameworks and microservice platforms (Spring, Node.js runtimes, Django, Rails) are often considered application servers in a broader sense, even though they dispense with the heavyweight container model.

Distinction from web servers

A web server primarily handles HTTP requests and serves static content or delegates dynamic requests, while an application server executes application logic and may serve content through multiple protocols. In practice the two roles are often combined in a single product or deployed behind a reverse proxy.
