Confused deputy problem

The confused deputy problem is a type of computer security vulnerability. In this example, a program that is innocently granted access is tricked into misusing its authority, supplying a means for other software programs to gain otherwise unauthorized access.

The term was coined by Norm Hardy in a 1988 paper, "The Confused Deputy (or why capabilities might have been invented)". Hardy's example involved a compiler service running on a timesharing system: a user could direct the compiler to write billing information into a file. By naming an arbitrary file as the billing file, a user could cause the compiler — which held privileges the user lacked — to overwrite files the user could not modify directly. The compiler was the "confused deputy": it held authority on behalf of others but could be tricked into applying that authority to the wrong objects.

Capability-based security

In a capability-based system, the designator of a resource and the authority to access it are combined, so a deputy cannot be confused: when a client asks a service to act on an object, the client must supply the capability for that very object. This makes it impossible for a caller to trick a deputy into using the deputy's own, broader authority against an object named by the caller.

Related concepts

The confused deputy problem is related to privilege escalation and to cross-site request forgery on the web, in which a browser (the deputy) is tricked into issuing requests using a victim's credentials.
