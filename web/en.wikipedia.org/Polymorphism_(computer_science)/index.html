In programming language theory and type theory, polymorphism is the use of a single symbol to represent multiple different types, or the provision of a single interface to entities of different types. A polymorphic type is a type whose operations can also be applied to values of some other type, or types.

Forms of polymorphism

  • Ad hoc polymorphism: a function behaves differently depending on the type of its arguments — as with operator overloading and function overloading.
  • Parametric polymorphism: code is written generically so it works identically for any type, as with generic functions and containers (e.g. a list of any element type).
  • Subtyping (inclusion polymorphism): a name denoting instances of many different classes related by a common superclass; the mechanism behind much of object-oriented polymorphism, where a subclass object can be used wherever its superclass is expected.

History

The concept was systematised by Christopher Strachey in 1967, distinguishing parametric from ad hoc polymorphism. Luca Cardelli and Peter Wegner's 1985 paper "On Understanding Types, Data Abstraction, and Polymorphism" remains a standard classification. Polymorphism is a core feature of object-oriented languages such as Java and C++, and of functional languages in the ML and Haskell families.

Implementation

Compile-time polymorphism may be resolved statically (overloading, templates/generics), while subtyping polymorphism is usually implemented with dynamic dispatch through virtual method tables, selecting the actual implementation at run time.
