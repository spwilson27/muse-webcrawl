Class diagram

Class diagram
Diagram type: Static structure diagram
Standard: Unified Modeling Language (UML)
Shows: Classes, attributes, operations, relationships

In software engineering, a class diagram in the Unified Modeling Language (UML) is a type of static structure diagram that describes the structure of a system by showing the system's classes, their attributes, operations (or methods), and the relationships among objects. The class diagram is the main building block of object-oriented modeling and is used both for conceptual modeling of an application domain and for detailed design modeling that can be translated into code.

Elements

A class is drawn as a rectangle with three compartments: the class name, its attributes, and its operations. Each member can be annotated with a visibility marker: + for public, − for private, # for protected, and ~ for package. Classes are connected by several kinds of relationships: association (a structural link, often with multiplicities such as 1..*), inheritance/generalization (shown with a hollow triangular arrowhead pointing to the superclass), aggregation (hollow diamond, a part–whole relationship), composition (filled diamond, a stronger part–whole relationship where parts depend on the whole), dependency (dashed arrow), and realization of an interface.

Use

Class diagrams are widely used in model-driven engineering and can be forward-engineered into code skeletons in object-oriented languages or reverse-engineered from existing code. Related diagram types include the object diagram, which shows instances at a particular moment, and package diagrams that organize classes into namespaces.
