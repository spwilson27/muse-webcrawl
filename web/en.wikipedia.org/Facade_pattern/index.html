Facade pattern

TypeStructural design pattern
SourceDesign Patterns (Gang of Four, 1994)
IntentProvide a unified, higher-level interface to a set of interfaces in a subsystem
Related patternsAdapter, Mediator, Abstract factory

The facade pattern (also spelled façade) is a software design pattern commonly used in object-oriented programming. Analogous to a building's façade in architecture, a facade is an object that serves as a front-facing interface masking more complex underlying or structural code. It improves readability and usability of a library by masking interaction with complex components behind a single, simplified application programming interface (API), and reduces dependencies of outside code on the inner workings of a library.

Intent and structure

In Design Patterns: Elements of Reusable Object-Oriented Software (1994), the Gang of Four define the facade's intent: "Provide a unified interface to a set of interfaces in a subsystem. Facade defines a higher-level interface that makes the subsystem easier to use." The facade class delegates client requests to the appropriate subsystem classes but does not hide them entirely — clients may still access subsystem classes directly when fine-grained control is needed.

Usage

Facades are commonly used to wrap poorly designed or legacy APIs, to present a simple interface over a complex class library (for example, a "compile" method that drives a compiler's scanner, parser, and code generator), to structure a system into layers, and to decouple clients from subsystem components so the subsystem can evolve independently. A facade differs from the adapter pattern, which converts one interface into another expected by the client, and from the mediator pattern, which centralizes communication between colleague objects.

Example

A home-theatre facade might expose a single watchMovie() operation that dims the lights, lowers the screen, powers the projector, amplifier, and streaming player, and sets the correct inputs — replacing a dozen manual steps the client would otherwise perform on each subsystem class directly.
