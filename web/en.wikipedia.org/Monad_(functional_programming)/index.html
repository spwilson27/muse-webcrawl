Monad (functional programming)


Operations: return (unit) and bind (>>=)
Origin: Category theory
Key languages: Haskell, Scala, F#

In functional programming, a monad is a structure that combines program fragments (functions) and wraps their return values in a type with additional computation. It is defined by a type constructor, a return (or unit) function that wraps a value, and a bind operation that chains monadic functions together, subject to three laws (left identity, right identity, and associativity).

Motivation

Monads allow programmers to sequence operations that involve extra structure or effects — possible failure, optionality, lists of results, state, input/output, or asynchronous values — while keeping the sequencing logic uniform and composable. The idea entered programming through Eugenio Moggi's work on the semantics of computation and was popularized by Philip Wadler; Haskell adopted monads as the standard way to structure I/O in a purely functional language.

Common monads

Examples include Maybe/Option (computation that may fail), Either/Result (failure with an error value), List (non-deterministic computation), IO, State, Reader, Writer, and continuations. In Haskell, do notation provides syntactic sugar over bind and return; similar constructs include Scala's for-comprehensions and F#'s computation expressions.

Criticism and culture

Monads are notorious for the difficulty beginners have in grasping them, and for the proliferation of tutorials attempting new analogies — a phenomenon sometimes called the "monad tutorial fallacy". Nonetheless, the pattern is now standard in functional programming and has influenced mainstream languages through constructs for optional and asynchronous values.
