Time complexity

In computational complexity theory, the time complexity of an algorithm quantifies the amount of time it takes to run as a function of the length of the input. Time complexity is commonly estimated by counting elementary operations and is expressed using big O notation, which suppresses constant factors and lower-order terms: an algorithm whose running time grows quadratically with input size n is said to run in O(n²) time.

Common classes

Frequently encountered time complexities include constant time O(1), logarithmic O(log n) (as in binary search), linear O(n), linearithmic O(n log n) (optimal comparison sorting), quadratic O(n²), and exponential O(2n). Algorithms whose running time is bounded by a polynomial in the input size are considered tractable in the theory of computational complexity; the class P consists of decision problems solvable in polynomial time by a deterministic Turing machine. Average-case and worst-case complexity may differ considerably, as with quicksort, and amortised analysis accounts for the cost of sequences of operations.

Model dependence and analysis

Time complexity is defined relative to a model of computation, such as the Turing machine or the random-access machine used in algorithm analysis. Formally, for a deterministic Turing machine the time complexity is the maximum number of steps over all inputs of a given length. Because constant factors depend on implementation and hardware, big O analysis focuses on asymptotic growth, though in practice constants and memory access patterns can matter greatly. Space complexity is analysed in parallel fashion.
