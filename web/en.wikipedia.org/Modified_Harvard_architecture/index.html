Modified Harvard architecture

The modified Harvard architecture is a variation of the Harvard computer architecture that, unlike the pure Harvard architecture, allows the contents of the instruction memory to be accessed as data, or permits data memory to be read as instructions, under defined circumstances. Most modern computers that are documented as Harvard architecture are, in fact, modified Harvard architecture.

Background

In a pure Harvard architecture, separate storage and signal pathways are used for instructions and data, so code cannot be treated as data. This prevents techniques such as self-modifying code, runtime code generation (just-in-time compilation), and loading programs from data storage without special provisions. The von Neumann architecture, by contrast, uses a single memory and bus for both.

Common modifications

  • Split-cache architecture — separate instruction and data caches (as in most modern CPUs such as x86 and ARM processors) backed by a unified main memory; from the programmer's perspective the machine behaves like a von Neumann machine, while gaining parallel cache access.
  • Instruction memory as data — microcontrollers (e.g., many PIC, AVR, and ARM Cortex-M devices) allow reading program flash memory as data, so constant tables can be stored in code space.
  • Data memory as instructions — some systems allow executing code from RAM, enabling loaders and overlays.

Examples

Digital signal processors and microcontrollers frequently use modified Harvard designs: the Texas Instruments TMS320 DSPs provide pathways to move data between program and data spaces, and AVR microcontrollers use the LPM instruction to read program memory. Desktop and server CPUs with separate L1 instruction and data caches over unified memory are often described as modified Harvard machines.
