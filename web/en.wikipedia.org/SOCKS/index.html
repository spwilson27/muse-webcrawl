SOCKS

SOCKS protocol
DeveloperDavid Koblas, MIPS Computer Systems
StandardRFC 1928 (SOCKS5)
Default port1080
OSI layerSession layer (Layer 5)

SOCKS is an Internet protocol that exchanges network packets between a client and server through a proxy server. SOCKS5, the current version, additionally provides authentication so only authorized users may access the proxy. Practically, a SOCKS server proxies TCP connections to an arbitrary IP address, and provides a means for UDP packets to be forwarded. SOCKS operates at a lower level than HTTP proxying: it is agnostic to the application-layer protocol being tunnelled, which makes it suitable for arbitrary traffic, not just web browsing.

A SOCKS proxy relays arbitrary TCP and UDP traffic between client and server.

History

The protocol was originally developed by David Koblas, a system administrator of MIPS Computer Systems, and was publicly described in a 1992 Usenix security symposium paper by Koblas and Michelle R. Koblas. SOCKS version 4 extended the protocol to support TCP-based client-server applications. SOCKS5, published as RFC 1928 in 1996 by Marcus Leech of NEC, added support for UDP, authentication, and address resolution by hostname within the proxy, superseding earlier versions.

Comparison with HTTP proxies

An HTTP proxy understands and may interpret the HTTP traffic passing through it, and is generally limited to HTTP applications. A SOCKS proxy simply forwards raw packets without interpreting the application protocol, so it can carry any TCP or UDP traffic, including email, peer-to-peer and SSH connections. SSH clients commonly use SOCKS via the dynamic port forwarding feature of the OpenSSH client, and the Tor network exposes a SOCKS interface for applications.
