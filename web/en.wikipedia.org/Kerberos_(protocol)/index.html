Kerberos is a computer-network authentication protocol that works on the basis of tickets to allow nodes communicating over a non-secure network to prove their identity to one another in a secure manner. It is named after Cerberus, the three-headed dog of Greek mythology, reflecting its three parties: the client, the server, and the trusted Key Distribution Center (KDC).

How it works

A user authenticates to an Authentication Server and receives a Ticket Granting Ticket (TGT). When the user wants to access a service, the Ticket Granting Service issues a service ticket for that specific server. The client presents the ticket to the service, which can verify it using its own secret key shared with the KDC. Passwords are never sent over the network, and sessions are protected with symmetric-key cryptography.

History and use

Kerberos was developed at the Massachusetts Institute of Technology as part of Project Athena in the 1980s. Version 5, described in RFC 4120 (superseding RFC 1510), is the dominant standard. Microsoft adopted Kerberos as the default authentication protocol for Windows domains and Active Directory, and it is widely used in Unix environments through implementations such as MIT Kerberos and Heimdal.

Limitations

Kerberos requires a continuously available and trusted KDC, loose clock synchronization between participants, and is vulnerable if a user's credentials or a service key are stolen — attacks such as "Kerberoasting" and pass-the-ticket exploit weaknesses in deployments.
