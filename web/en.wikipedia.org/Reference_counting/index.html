Reference counting

In computer science, reference counting is a technique for automatic memory management in which each object keeps a count of the number of references (pointers) to it held by other objects or variables. When the count reaches zero, the object is no longer reachable and can be deallocated. It is one of the principal forms of garbage collection, alongside tracing collectors.

Each object tracks how many references point to it.

Operation

Creating a reference increments the target's count; destroying or reassigning a reference decrements it. When a count falls to zero, the object's resources are released and the counts of any objects it referenced are decremented in turn, which may cascade. Deallocation is incremental and predictable — objects are freed as soon as they become unreachable — which makes reference counting attractive for managing non-memory resources such as file handles (as in COM and many C++ idioms).

Advantages and disadvantages

Advantages include prompt reclamation, locality of overhead, and deterministic destruction. The central disadvantage is the inability to collect reference cycles: structures that reference each other (directly or in a loop) keep each other's counts above zero even when unreachable from the program. Remedies include weak references (which do not increment the count), cycle detectors run alongside, or programmer discipline. Multithreaded programs must update counts atomically, adding overhead; Swift, CPython, Objective-C, Rust's Rc/Arc, and C++ shared_ptr all rely on reference counting in some form.

History

Reference counting was described by George E. Collins in 1960 for LISP, and refined for distributed systems in the following decades. CPython, the reference implementation of Python, uses reference counting as its primary mechanism, supplemented by a generational cycle collector.
