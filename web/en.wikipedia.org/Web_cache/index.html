Web cache

From Wikipedia, the free encyclopedia

A web cache (or HTTP cache) is a system for optimising the World Wide Web. It is implemented both client-side and server-side. The caching of multimedia and other files can result in less overall delay in displaying a web page. A cache stores copies of documents passing through it; subsequent requests may be satisfied from the cache if certain conditions are met, reducing latency and bandwidth consumption.

Types of caches

Browser caches are private caches held by a user's web browser on their own device. Proxy caches serve many users through an intermediary, commonly run by an ISP. Gateway caches, also called reverse proxy caches or surrogate caches, sit in front of origin servers and are operated by the site itself; content delivery networks (CDNs) distribute such caches geographically to bring content closer to users.

How caching works

HTTP responses carry headers that control caching. Cache-Control directives such as max-age state how long a response is fresh; during freshness, the cache may reuse it without contacting the origin. Once stale, the cache may validate the stored response using an ETag or the Last-Modified time, receiving a lightweight "304 Not Modified" reply if the content is unchanged. Some responses, such as those marked no-store or containing personalised data, must not be cached.

Benefits and trade-offs

Effective caching reduces server load, network congestion and user-perceived delay, and can keep content available during brief outages. The trade-offs are staleness — users may see outdated content — and the complexity of cache invalidation when origin content changes.
