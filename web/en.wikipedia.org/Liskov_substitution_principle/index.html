Liskov substitution principle

The Liskov substitution principle (LSP) is a principle of object-oriented programming concerning subtyping: objects of a superclass should be replaceable by objects of any of its subclasses without altering the correctness of the program. It was introduced by computer scientist Barbara Liskov in a 1987 conference keynote, and formulated with Jeannette Wing in a 1994 paper, "A behavioral notion of subtyping". Liskov's own informal statement was:

"What is wanted here is something like the following substitution property: If for each object o1 of type S there is an object o2 of type T such that for all programs P defined in terms of T, the behavior of P is unchanged when o1 is substituted for o2, then S is a subtype of T."

Requirements

The formalised principle imposes behavioural conditions on a subtype: it must not strengthen preconditions or weaken postconditions of inherited methods (the contravariance/covariance rules for arguments and results), it must preserve the supertype's invariants, and it must satisfy the history constraint — a subtype may not permit state changes that the supertype forbids. Signatures must also be compatible: method argument types contravariant, return types covariant, and no new exceptions beyond those the base method allows.

Examples and violations

The classic violation is the square–rectangle problem: a Square class derived from Rectangle whose setters keep the sides equal breaks client code that assumes width and height can be changed independently. Other canonical examples include mutable points derived from immutable ones, and penguin subclasses of a Bird class with a fly method that must fail. Such violations indicate modelling errors: substitutability, not mere inheritance of code, is what makes a subtype.

SOLID

LSP forms the "L" of Robert C. Martin's SOLID mnemonic for five design principles, and underlies design-by-contract approaches. Violations can often be detected by type-checking tests that run a supertype's contract tests against all subclasses.
