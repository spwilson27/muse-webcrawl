Canvas fingerprinting

How small rendering differences produce a device fingerprint (placeholder)

Canvas fingerprinting is one of a number of browser fingerprinting techniques used by websites to track visitors. It works by exploiting the HTML5 canvas element: a website instructs the visitor's browser to draw a hidden image and text, and because the exact pixel output depends on the browser, operating system, graphics hardware, drivers, and installed fonts, the result renders slightly differently on different systems. Reading back the pixels yields a largely unique identifier for the device, which can be hashed and used for tracking without cookies.

Technique

The script typically draws text with a specified font and background, sometimes combined with WebGL rendering. The canvas data is extracted (for example via toDataURL) and hashed. Variations in anti-aliasing, sub-pixel rendering, and graphics processing units make the output stable for a given machine yet different across machines, providing enough entropy to distinguish a large fraction of users.

History

The technique was described in a 2012 paper by Keaton Mowery and Hovav Shacham of the University of California, San Diego. It gained wide public attention in 2014 after researchers at Princeton University and KU Leuven published a large-scale study ("The Web never forgets") finding canvas fingerprinting scripts on thousands of popular websites, including those of major companies and government sites.

Countermeasures

Because fingerprinting is difficult for users to detect, browser vendors and privacy tools have introduced defences: the Tor Browser asks permission before allowing canvas readout and returns blank data by default; Firefox includes fingerprinting resistance options; Brave randomises canvas output; and extensions such as CanvasBlocker can spoof or block readouts. Randomising the output per session undermines the stability the technique depends on.
