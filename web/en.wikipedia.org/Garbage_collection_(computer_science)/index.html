Garbage collection (computer science)

In computer science, garbage collection (GC) is a form of automatic memory management. The garbage collector attempts to reclaim memory occupied by objects that are no longer in use by the program, freeing the programmer from manually allocating and deallocating memory and preventing many memory leaks and dangling-pointer bugs.

History

Garbage collection was invented around 1959 by John McCarthy for the Lisp programming language. It became widespread with object-oriented and managed languages such as Smalltalk, Java, C# and Go, while languages like C and C++ traditionally rely on manual management, sometimes supplemented by reference counting.

Strategies

The most common approach is tracing garbage collection, exemplified by mark-and-sweep: starting from roots (globals, stack references), the collector marks all reachable objects and sweeps away the rest. Copying collectors move live objects to a new region, compacting memory. Reference counting frees objects when their count of references falls to zero but cannot collect reference cycles on its own.

Generational collection

Because most objects die young, many collectors divide the heap into generations and collect the young generation most often, promoting survivors to older generations — a key optimisation in the Java HotSpot and .NET runtimes. Modern collectors such as G1, ZGC and Shenandoah aim for short, concurrent pauses on very large heaps.

Trade-offs

Automatic collection costs CPU time and memory headroom and can introduce pause times; it also does not manage non-memory resources such as file handles, which still need explicit handling or finalisation.
