End-to-end encryption

AbbreviationE2EE
FieldCryptography, computer security
Key ideaOnly communicating endpoints can read messages
ExamplesSignal Protocol, PGP, OMEMO

End-to-end encryption (E2EE) is a private communication system in which only the communicating users can participate and read the messages. It is intended to prevent potential eavesdroppers — including telecom providers, Internet providers, malicious actors, and even the provider of the communication service — from being able to access the cryptographic keys needed to decrypt the conversation.

In an E2EE system, messages are encrypted on the sender's device and only decrypted on the recipient's device. The service relaying the messages handles only ciphertext. This contrasts with encryption in transit alone, where the service provider itself can read the content.

How it works

Modern E2EE systems typically combine an initial key agreement protocol — often based on Diffie–Hellman key exchange — with a ratcheting mechanism that continually derives fresh keys, providing forward secrecy (past messages stay safe if a key is later compromised) and post-compromise security. The Signal Protocol, used by applications such as Signal and WhatsApp, popularised the Double Ratchet algorithm combined with extended triple Diffie–Hellman (X3DH) key agreement.

Challenges and debate

E2EE protects confidentiality but complicates content moderation, spam and abuse detection, and lawful access by authorities, which has made it a recurring subject of policy debate. It also does not by itself protect metadata — information about who communicated with whom and when — and security depends on endpoint integrity and on users verifying keys where the application supports it.

History

The concept builds on public-key cryptography introduced in the 1970s. Phil Zimmermann's PGP (1991) brought end-to-end encryption to email, while Off-the-Record messaging (2004) added deniability and forward secrecy for instant messaging.
