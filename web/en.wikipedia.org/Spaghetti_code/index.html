Spaghetti code

Spaghetti code is a pejorative phrase for unstructured, difficult-to-maintain source code. It refers to code whose control flow is tangled like a bowl of spaghetti, typically because of heavy use of unconditional jumps such as GOTO statements, exceptions, threads or other unstructured branching that makes the programme's logic hard to follow.

History

The phrase was in use by the late 1970s. The problem it names was a central motivation for the structured programming movement: Edsger Dijkstra's famous 1968 letter "Go To Statement Considered Harmful" argued that unrestricted jumps degraded the quality of programmers' thinking, and structured constructs — sequences, selections and iterations — were shown to be sufficient to express any computable flow of control (the Böhm–Jacopini theorem). Spaghetti code often arises when inexperienced programmers build on code they do not fully understand, or when large projects evolve for years without refactoring under schedule pressure.

Related terms

Similar food-based metaphors include lasagna code, with too many indiscriminate layers of abstraction; ravioli code, composed of many small, loosely related objects; and spaghetti with meatballs, where object-oriented code is still tied together by procedural spaghetti. Causes commonly identified include lack of a coherent architecture, violation of the single-responsibility principle, excessive global state, and long functions with nested conditionals. The standard remedies are disciplined design, code review and refactoring.
