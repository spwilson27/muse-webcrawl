In object-oriented programming, the visitor pattern is a behavioral software design pattern that separates an algorithm from the object structure on which it operates. A visitor class defines an operation to be performed on the elements of an object structure, letting new operations be added to existing object structures without modifying those structures. It is one of the twenty-three canonical patterns described by the "Gang of Four" in Design Patterns (1994).

Structure

The pattern involves two kinds of types: elements (nodes of the structure), each with an accept(visitor) method, and visitors with a visit method overloaded for each concrete element type. When accept is called, the element calls back the matching visit method passing itself — a technique called double dispatch, which combines the runtime type of the element with the runtime type of the visitor.

Uses

Classic applications include compilers, where separate visitors type-check, optimize, and generate code over an abstract syntax tree without entangling those operations in the node classes; and document or scene-graph processors performing export, statistics, or rendering passes.

Advantages and drawbacks

Visitor makes it easy to add new operations but hard to add new element classes, since every existing visitor must then gain a new method — a trade-off sometimes called the expression problem. It also breaks some encapsulation, since visitors often need access to elements' internal state. Alternatives include pattern matching in functional languages, the acyclic visitor variant, and reflection-based walkers.
