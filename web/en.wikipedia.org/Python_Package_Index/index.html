Python Package Index

The Python Package Index, abbreviated as PyPI and also known as the Cheese Shop, is the official third-party software repository for the Python programming language. It is analogous to the CPAN repository for Perl and to the CRAN repository for R. PyPI is run by the Python Software Foundation, a charity. Some package managers, including pip, use PyPI as the default source for packages and their dependencies.

As of 2024, more than 500,000 Python packages can be accessed through PyPI. PyPI primarily hosts Python packages in the form of source archives, called "sdists", or pre-built "wheels". PyPI as an index allows users to search for packages by keywords or by filters against their metadata, such as free software license or compatibility with POSIX. A single entry on PyPI is able to store, aside from just a package and its metadata, previous releases of the package, precompiled wheels (e.g. containing DLLs on Windows), as well as different forms for different operating systems and Python versions.

History

The Python Distribution Utilities (Distutils) Python module was first added to the Python standard library in the 1.6.1 release, in September 2000, and in the 2.0 release in October 2000, nine years after the first Python release in February 1991, with the goal of simplifying the process of installing third-party Python packages. However, Distutils only provided the tools for packaging Python code, and not a package manager. It was able to generate metadata for packages, but it did not include metadata for dependencies.

PyPI itself was deployed in 2003 by Richard Jones, initially as a flat index of package metadata submitted by developers. In 2018, the legacy codebase was replaced by a new platform codenamed Warehouse, developed with sponsorship from Mozilla's Open Source Support program. In April 2018, PyPI moved from pypi.python.org to the new domain pypi.org, with the old domain shut down in January 2019.

Security incidents

PyPI has periodically been the target of typosquatting attacks, in which malicious packages are uploaded under names resembling popular libraries. In response, PyPI introduced measures including two-factor authentication requirements for maintainers of critical projects in 2022, trusted publishing via OpenID Connect, and proactive malware scanning and removal by the PyPI safety and security team.
