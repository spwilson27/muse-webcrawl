Finalizer

In computer programming, a finalizer or finalize method is a special method that is invoked by a garbage collector before an object is destroyed and its memory reclaimed. Finalizers allow an object to perform cleanup tasks, such as releasing non-memory resources, as a last resort before disposal.

Behaviour

Finalizers are found in garbage-collected languages including Java (the Object.finalize() method), C# and other .NET languages (where the syntax resembles a destructor), and Python (__del__). Unlike destructors in languages such as C++, which run deterministically when an object leaves scope, finalizers run at a time chosen by the garbage collector; there is no guarantee when — or, in some circumstances, whether — a finalizer will execute.

Criticism and alternatives

Because of their unpredictability and performance costs, finalizers are widely discouraged for managing resources. Java deprecated Object.finalize() in Java 9 and has moved toward removing it, recommending instead explicit resource management such as try-with-resources, and Cleaner mechanisms based on phantom references for the rare cases where a safety net is needed. In .NET, the recommended pattern is to implement IDisposable and reserve the finalizer as a fallback for unmanaged resources only.

Object resurrection

A notorious subtlety of finalizers is object resurrection: a finalizer can store a reference to the object being finalized, making it reachable again after the collector had decided to reclaim it. Languages handle this differently, but resurrection is generally considered an anti-pattern that can cause inconsistent program state.
