Tar (computing)

In computing, tar (from tape archive) is a file format and the name of a utility used to collect many files into a single archive file, often called a tarball, for distribution or backup, while preserving file metadata such as permissions, ownership, and timestamps. Tar itself does not compress the archive; it is usually combined with a compression program such as gzip (.tar.gz, .tgz), bzip2 (.tar.bz2), or xz (.tar.xz).

Format

A tar archive consists of a series of 512-byte records. Each file is preceded by a header block containing its name (100 bytes), mode, owner and group IDs, size, modification time, a checksum, and a type flag; the file's data follows, padded to a multiple of 512 bytes. The archive ends with at least two zero-filled blocks. The POSIX "ustar" extension added fields for longer paths (via a prefix field) and user/group names, and the later "pax" format added extended headers capable of storing arbitrary metadata and unlimited file sizes and name lengths.

Usage

Typical commands include:

tar -cf archive.tar files/    # create
tar -xzf archive.tar.gz        # extract a gzipped archive
tar -tvf archive.tar           # list contents verbosely

Tar remains ubiquitous in Unix-like systems: source-code releases, package formats (Debian .deb, Slackware packages, Docker image layers), and backup workflows all build on it. Because it was designed for sequential tape media, tar has no central index — listing or extracting a file near the end requires reading through preceding data — and files are typically accessed as a stream.

History

Tar first appeared in Version 7 Unix in 1979. Successive format variants (notably GNU tar's) added features and incompatibilities that the POSIX ustar (1988) and pax (2001) standards sought to reconcile. The phrase "tarball" is now generic for distributed archive bundles, and the idiom "tar and feathers" jokes aside, the command's terse flags (-cvf, -xvf) are among the most memorised in Unix culture.
