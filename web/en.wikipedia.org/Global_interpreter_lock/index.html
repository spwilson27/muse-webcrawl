Global interpreter lock

A global interpreter lock (GIL) is a mechanism used in computer-language interpreters to synchronize the execution of threads so that only one native thread (per process) can execute at a time. An interpreter that uses a GIL will always allow exactly one thread to execute at a time, even if run on a multi-core processor. Some popular interpreters that have a GIL are CPython, the most widely used implementation of the Python programming language, and Ruby MRI, the reference implementation of the Ruby programming language.

Rationale

Interpreter implementations that use a GIL typically do so to simplify their internal memory management. In CPython, for example, object reference counts are manipulated by many internal operations, and a single global lock makes it unnecessary to add fine-grained locking around every object. The GIL also makes it easier to integrate extension libraries written in C that are not themselves thread-safe.

Effect on multi-threaded programs

Because the GIL prevents multiple threads from executing Python bytecode simultaneously, CPU-bound multi-threaded programs in CPython do not gain speed from additional processor cores, and may even run slightly slower than a single-threaded equivalent. Programs that spend much of their time waiting on input/output can still benefit from threads, since the GIL is released while a thread blocks on I/O. For CPU-bound parallelism, programmers commonly use multiple processes, via libraries such as multiprocessing, or move hot code into C extensions that release the GIL.

Alternatives and removal efforts

Other Python implementations, such as Jython and IronPython, do not have a GIL because they rely on the underlying Java or .NET runtimes. Over the years there have been repeated proposals to remove the GIL from CPython; experiments historically showed unacceptable slowdowns for single-threaded code. In 2023, PEP 703 proposed making the GIL optional in CPython through a separate "free-threaded" build, and the Python Steering Council accepted the proposal, with an experimental free-threaded build first shipped in Python 3.13.
