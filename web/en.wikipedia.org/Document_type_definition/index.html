Document type definition

From Wikipedia, the free encyclopedia

A document type definition (DTD) is a specification file that formally defines the structure and the legal elements and attributes of an XML document. Besides its application to XML, DTDs have also been used for SGML documents. A DTD can be declared inside an XML document (an "internal subset") or in an external file (an "external subset") referenced by a document type declaration.

Declarations

A DTD consists of markup declarations that define element types, attribute lists, entities, and notations. For example:

<!ELEMENT note (to, from, heading, body)> <!ELEMENT to (#PCDATA)> <!ATTLIST note date CDATA #IMPLIED>

Element declarations specify which child elements or character data an element may contain; attribute-list declarations specify allowed attributes, their types, and default values; entity declarations define replacement text or external resources.

Validation

An XML parser can use a DTD to check that a document conforms to its declared structure; such documents are called valid, as opposed to merely well-formed. DTDs are limited: they use a non-XML syntax, provide weak datatype support, and do not support namespaces. These limitations motivated later schema languages such as XML Schema and RELAX NG.

Use in HTML

Historical versions of HTML were defined as applications of SGML, and HTML documents conventionally began with a <!DOCTYPE> declaration referencing public DTDs for HTML 2.0, 3.2, or 4.01. HTML5 simplified this to the minimal <!DOCTYPE html>, which no longer references a DTD.

Security considerations

External entities declared in DTDs are the basis of XML external entity (XXE) attacks and entity-expansion ("billion laughs") denial-of-service attacks, so many modern parsers restrict or disable external DTD processing by default.
