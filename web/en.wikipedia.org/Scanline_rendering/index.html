Scanline rendering

Scanline rendering is an algorithm for visible surface determination in 3D computer graphics in which the rows (scanlines) of pixels of an image are processed sequentially, rather than the polygons of the scene one by one or each pixel individually. The geometry intersecting a given scanline is sorted and rendered as the scanline sweeps down the image.

Technique

In a typical implementation, polygons are projected and their edges inserted into an edge table bucketed by scanline. For each scanline, an active edge list maintains the polygon edges currently crossed by the line, sorted by depth or x-coordinate. Spans between edge intersections are filled, applying shading, texture mapping, and hidden-surface removal. Variants incorporate z-buffering or painter's-algorithm depth sorting within each scanline.

History and use

Scanline algorithms were foundational in early computer graphics because they required little memory at a time when storing a full framebuffer depth buffer was expensive. They underpinned production renderers such as Pixar's RenderMan (in its REYES architecture, which dices geometry into micropolygons processed largely scanline by scanline), and they remain relevant in embedded and real-time rasterisation where memory bandwidth is constrained.

Relation to other methods

Scanline rendering contrasts with ray tracing, which traces a ray per pixel, and with pure z-buffer rasterisation, which processes primitives in arbitrary order. Modern GPUs combine tiling and scanline-order traversal with per-pixel depth tests.
