Strong and weak typing

In computer programming, programming languages are often classified colloquially as strongly typed or weakly typed (loosely typed). These terms have no universally agreed technical definition. Generally, a strongly typed language is more likely to generate an error when data is used in a way its type does not intend, and tends to forbid implicit conversions between unrelated types, while a weakly typed language permits more implicit type conversion (coercion).

Interpretations

Because the term is ambiguous, writers have used it to mean several different things: whether the language enforces type safety and memory safety; whether implicit conversions occur (JavaScript's "1" + 2 producing "12" is often cited as weak typing); whether type checking is static or dynamic; or how easily a language lets programmers subvert the type system, as C does with casts and pointer arithmetic.

Discussion

Luca Cardelli described type systems as strong or weak in terms of whether they permit "untrapped errors". Many practitioners prefer more precise terms — type safe, statically checked, dynamically checked, implicit conversion — over the strong/weak label.
