HTTP ETag

An ETag (entity tag) is part of HTTP, the protocol for the World Wide Web. It is one of several mechanisms HTTP provides for web cache validation, allowing a client to make conditional requests and a server to avoid resending content that has not changed. An ETag is an opaque identifier assigned by a web server to a specific version of a resource found at a URL. If the resource content ever changes, a new and different ETag must be generated.

Operation

The server includes the tag in the ETag response header:

ETag: "686897696a7c876b7e"

On a subsequent request the client sends it back in If-None-Match. If the current version matches, the server replies 304 Not Modified with an empty body, saving bandwidth. ETags prefixed with W/ are "weak" validators, indicating only semantic equivalence; unprefixed tags are "strong" and assert byte-for-byte identity. Related headers include If-Match, If-Range and the date-based Last-Modified validator.

Generation and issues

Servers commonly derive ETags from a hash of the content, or from the file's modification time and size (as in Apache's default scheme, which caused problems in load-balanced farms where inode numbers differ). Because ETags persist across sessions and are resent even where cookies are blocked, they have also been abused as a persistent tracking mechanism — so-called "zombie cookies" — prompting browsers to limit such uses.
