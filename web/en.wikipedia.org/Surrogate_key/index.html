Surrogate key

A table using a system-generated integer as surrogate key alongside its natural attributes.

A surrogate key (or synthetic key, pseudokey, entity identifier, factless key, or technical key) in a database is a unique identifier for either an entity in the modelled world or an object in the database. Unlike a natural key, which is derived from application data (such as a person's tax-file number), a surrogate key is not derived from the data: it is generated by the system, typically as a sequential integer or a UUID, and has no business meaning.

Advantages

  • Stability: surrogate keys never change, even if the natural attributes of an entity are corrected or re-keyed.
  • Simplicity of joins: a single narrow column replaces potentially wide or composite natural keys in foreign-key relationships.
  • Uniformity: every table follows the same key pattern, simplifying application code and ORM mapping.
  • Insulation: the database design is decoupled from changes in business identifiers.

Disadvantages

Surrogate keys add an extra index and may require additional lookups: queries based on business attributes must join or search by the natural key anyway, which should therefore still be constrained unique to prevent duplicate entities. In data-warehouse dimension tables, surrogate keys are standard practice because source systems change over time and slowly changing dimensions need stable identifiers.

Generation

Common generation methods include auto-incrementing identity columns, database sequences, and globally unique identifiers (GUIDs/UUIDs). Sequential integers are compact and index-friendly, while UUIDs ease merging data across distributed systems at the cost of larger, randomly ordered index keys.
