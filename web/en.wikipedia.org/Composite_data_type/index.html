Composite data type

ConceptProgramming language data type
Built fromPrimitive data types and other composite types
Common formsRecord/struct, array, union, class, tuple, list
Contrasts withPrimitive (scalar) data types

In computer science, a composite data type (or compound data type) is any data type that can be constructed from primitive data types and other composite types. Composite types let programmers group related values into a single unit that can be manipulated as a whole, and they are the building blocks of data structures and abstract data types.

A record composed of fields of primitive types

Common composite types

  • Records / structures — fixed collections of named fields of possibly different types, e.g. C's struct and Pascal's record.
  • Arrays — indexed collections of elements of a single type, found in nearly every language.
  • Unions — types that store one of several alternative types in the same memory; tagged unions (sum types) record which alternative is present.
  • Tuples — ordered, fixed-length sequences of values of specified types.
  • Classes and objects — composites that bundle data with the operations (methods) that act on it, the foundation of object-oriented programming.
  • Strings, lists, sets, and maps — often implemented as composites of characters or key–value pairs.

Theory

In type theory, the principal ways of combining types are product types (tuples, records — a value contains all components) and sum types (tagged unions — a value contains one of several alternatives); together these form algebraic data types, central to functional languages such as Haskell and ML. Type systems vary in whether composite types are compared by structure (structural typing) or by declared name (nominal typing).
