Paging

In computer operating systems, paging is a memory management scheme by which a computer stores and retrieves data from secondary storage for use in main memory. In this scheme, the operating system retrieves data from secondary storage in same-size blocks called pages. Paging is an important part of virtual memory implementations in modern operating systems, using secondary storage to let programs exceed the size of available physical memory.

Overview

A process's virtual address space is divided into fixed-size pages (commonly 4 KiB), and physical memory is divided into frames of the same size. The memory management unit (MMU) translates virtual addresses to physical addresses using a page table maintained by the operating system. Pages not currently in physical memory are held in a page file or swap partition on disk; when a program accesses such a page, a page fault occurs and the operating system loads the page, possibly evicting another page using a page replacement algorithm such as least recently used (LRU).

Advantages

Paging eliminates external fragmentation, allows memory to be allocated non-contiguously, enables sharing of pages between processes (for example shared libraries), and underpins protection: each page can carry read, write and execute permission bits. Techniques built on paging include demand paging, copy-on-write, and memory-mapped files. Multi-level page tables and translation lookaside buffers (TLBs) make address translation efficient on large address spaces.

History

Paging was first implemented on the Atlas computer at the University of Manchester, operational in 1962, and became a standard feature of operating systems with systems such as Multics and later Unix and Windows.
