Training, validation, and test data sets

A common workflow splits available data into training, validation, and test subsets.

In machine learning, a common task is the study and construction of algorithms that can learn from and make predictions on data. Such algorithms learn by optimising a mathematical model from example data, known as training data. In order to measure how well a model generalises to new data, the available data are commonly split into three subsets: a training set, a validation set, and a test set.

Training data set

A training data set is the sample of data used to fit the model: the model's parameters (for example, the weights of a neural network) are adjusted according to performance on this set. The training set is the largest of the three subsets, often comprising 60–80% of the available examples.

Validation data set

A validation data set is used to evaluate a model fitted on the training set while tuning the model's hyperparameters—settings that are not learned directly, such as learning rate, network architecture, or regularisation strength. Validation performance guides model selection and techniques such as early stopping. Because information from the validation set indirectly influences the model, a separate test set is still needed for an unbiased final estimate.

Test data set

A test data set is a set of examples used only to assess the performance of a fully specified model. It should be independent of the training and validation data and should ideally be used only once, at the end of the modelling process, to estimate how the model will perform on genuinely unseen data. Repeated evaluation on a test set can lead to overfitting to that set.

Cross-validation

When data are scarce, cross-validation is used instead of a single fixed split: the data are partitioned into k folds, and each fold in turn serves as the validation set while the remainder are used for training. This produces a more reliable estimate of model performance at higher computational cost.

Terminology and pitfalls

The terms "validation" and "test" are sometimes used interchangeably in industry, which can cause confusion. A common pitfall is data leakage, in which information from the validation or test data contaminates training—for example through preprocessing fitted on the whole data set—leading to overly optimistic performance estimates.
