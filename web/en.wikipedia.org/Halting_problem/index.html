Halting problem

Halting problem

In computability theory, the halting problem is the problem of determining, from a description of an arbitrary computer program and its input, whether the program will finish running (halt) or continue to run forever. Alan Turing proved in 1936 that a general algorithm to solve the halting problem for all possible program–input pairs cannot exist, publishing the result in his landmark paper "On Computable Numbers, with an Application to the Entscheidungsproblem".

Statement

Formally: there is no Turing machine H which, given the description of any Turing machine M and input w, always halts and answers "yes" if M halts on w and "no" otherwise. The halting problem is the canonical example of an undecidable problem: computable functions can decide it for many particular programs, but no single algorithm decides it in general.

Proof sketch

Turing's proof proceeds by contradiction, using a diagonal argument. Suppose such a decider H existed. One could then build a machine D that takes the description of a machine as input, uses H to ask whether that machine halts when given its own description, and then does the opposite: D loops forever if the answer is "halts" and halts if the answer is "loops". Running D on its own description yields a paradox — D halts if and only if it does not halt — so H cannot exist. The argument parallels Cantor's diagonal argument and, in later folklore, the barber paradox.

Significance

Together with Alonzo Church's work on the lambda calculus, Turing's result settled the Entscheidungsproblem posed by David Hilbert: there can be no fully mechanical procedure for deciding the truth of arbitrary mathematical statements. In practical computing, undecidability implies that no program verifier, compiler or static analyser can perfectly predict all behaviour of arbitrary programs — for example, perfect virus detection and general loop detection are impossible. Rice's theorem generalises the result to all non-trivial semantic properties of programs.

Related concepts

The halting problem nevertheless has structure studied by computability theorists: it is computably enumerable (a machine can confirm halting by simply running the program) but not decidable, and it is complete for its level of the arithmetical hierarchy. Bounded versions of the problem — whether a program halts within a given number of steps — are decidable but computationally intractable, as illustrated by the busy beaver function, whose values grow faster than any computable function.
