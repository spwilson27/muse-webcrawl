Superscalar processor

Diagram of a superscalar pipeline issuing multiple instructions per clock cycle to parallel execution units.

A superscalar processor is a CPU design that implements a form of parallelism called instruction-level parallelism within a single processor, allowing it to execute more than one instruction per clock cycle. The processor fetches, decodes, and dispatches several instructions at once to multiple redundant functional units — such as several arithmetic logic units, load-store units, and floating-point units — provided the instructions are independent and do not contend for the same resources.

History

The CDC 6600 (1964), designed by Seymour Cray, is often cited as an early superscalar-like design because it could issue one instruction per cycle to multiple functional units. The term "superscalar" entered common use in the late 1980s. Early commercial superscalar machines included the IBM RS/6000 (1990) and the Intel Pentium (1993), which had dual integer pipelines. Superscalar design, combined with deep pipelining, became the dominant approach to high-performance general-purpose computing in the 1990s.

Design considerations

To sustain multiple instruction issues per cycle, a superscalar processor must check for data dependencies (hazards) between instructions in the issue window, predict branches, fetch instructions across predicted paths, and often rename registers to remove false dependencies. Many designs execute instructions out of order, buffering them in reservation stations or reorder buffers so that independent instructions can proceed while others wait on memory or long-latency operations. The width of the machine — the maximum number of instructions issued per cycle — is limited by dependency checking complexity, power consumption, and the amount of parallelism available in typical programs.

Limitations

Superscalar execution is bounded by the instruction-level parallelism inherent in code: control dependencies, memory dependencies, and long-latency cache misses reduce achievable throughput. Increasing issue width yields diminishing returns, which led the industry toward multicore designs in the mid-2000s once power and complexity walls were reached.
