Duck typing

“If it walks like a duck and quacks like a duck, it must be a duck”

In computer programming, duck typing is a style of dynamic typing in which an object's suitability for a given purpose is determined by the presence of certain methods and properties, rather than by the type of the object itself. The concept derives from the duck test: “If it looks like a duck, swims like a duck, and quacks like a duck, then it probably is a duck.”

Concept

With duck typing, a programmer does not check an object's class or declared interface; instead, code simply calls the methods it needs, and a runtime error occurs if the object does not support them. The style is common in dynamically typed languages such as Python, Ruby, and JavaScript, and contrasts with nominative typing, where compatibility is based on explicit declarations.

Example

In Python, a function that iterates over its argument works with any iterable object—lists, tuples, generators, or custom classes implementing __iter__—without requiring a common base class. The related Pythonic philosophy of “easier to ask forgiveness than permission” encourages attempting operations and handling exceptions.

Comparison

Duck typing offers flexibility and concise code but sacrifices compile-time safety; errors surface only when code paths execute. Structural typing in languages such as Go, TypeScript, and OCaml provides a statically checked analogue based on method sets (interfaces) rather than declared inheritance.
