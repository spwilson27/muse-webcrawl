Trivial File Transfer Protocol

A TFTP read transfer, block by block

AbbreviationTFTP
PurposeSimple file transfer
Port69/UDP
RFC(s)RFC 1350

The Trivial File Transfer Protocol (TFTP) is a simple lockstep file transfer protocol for transferring files between a client and a server over a network. It provides little functionality beyond basic file transfers and is much simpler to implement than the File Transfer Protocol (FTP) — a design goal that made it attractive for small embedded systems and bootstrapping.

Overview

TFTP runs over UDP port 69 and uses a lockstep acknowledgement scheme: a file is transferred in fixed blocks of 512 bytes (by default), and each block must be acknowledged before the next is sent; a data packet shorter than 512 bytes marks the end of the transfer. There is no authentication, no directory listing, and no encryption, so TFTP is normally restricted to trusted local networks.

The protocol was first defined in 1980 (IEN 133) and is currently specified in RFC 1350 (1992). Later RFCs added options such as a larger block size (RFC 2348) and a transfer-size option (RFC 2349), allowing faster transfers and early failure on insufficient storage.

Uses

TFTP's tiny memory footprint made it a standard component of Preboot Execution Environment (PXE) network booting, where a diskless machine downloads its boot files from a server. It is also widely used to upload firmware and configuration files to routers, switches, IP phones, and other embedded devices, and by network administrators to back up device configurations.

Security

Because TFTP lacks authentication and access controls, misconfigured servers exposed to the internet have historically been abused — for example, for unauthorised file access and as reflectors in UDP amplification denial-of-service attacks. Best practice is to confine TFTP to isolated management networks.
