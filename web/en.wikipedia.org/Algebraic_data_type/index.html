Algebraic data type

ParadigmFunctional programming
KindsProduct types, sum types
LanguagesHaskell, ML, OCaml, Rust, Scala, Swift

In computer programming, especially functional programming and type theory, an algebraic data type (ADT) is a kind of composite type—a type formed by combining other types. Two common classes of algebraic types are product types (such as tuples and records) and sum types (also called tagged or disjoint unions, or variant types).

The values of an algebraic data type are typically analyzed with pattern matching, which allows the program to inspect which constructor was used to build a value and to extract the data it contains. Algebraic data types were introduced in the Hope programming language in the 1970s and are a central feature of languages in the ML family and of Haskell.

Product types

A product type combines several values into one; the number of possible values is the product of the numbers of values of the components. Records and tuples are product types. In Haskell, a declaration such as data Point = Point Double Double defines a product type with a single constructor taking two arguments.

Sum types

A sum type is a type whose values can be constructed by one of several constructors, each possibly carrying different data. A classic example is a binary tree:

data Tree a = Empty | Leaf a | Node (Tree a) (Tree a)

Here Empty, Leaf, and Node are the constructors of the type Tree. Enumerated types are the special case of sum types in which every constructor has no arguments.

Pattern matching

Algebraic data types are commonly used with pattern matching, which checks a value against a sequence of patterns and binds variables to its components. Compilers for languages like OCaml and Haskell check pattern matches for exhaustiveness, warning when cases are missing.

Generalized algebraic data types

Generalized algebraic data types (GADTs) extend ordinary algebraic data types by allowing constructors to specify more precise type instances of the result type. They are supported in Haskell (via GHC extensions), OCaml, and other languages, and enable encoding invariants in types, such as well-typed interpreters for embedded languages.
