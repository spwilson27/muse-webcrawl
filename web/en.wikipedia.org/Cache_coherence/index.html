Cache coherence

In computer architecture, cache coherence is the uniformity of shared resource data that ends up stored in multiple local caches. In a multiprocessor system, each processor has its own cache of main memory; when one processor modifies data, other copies must be invalidated or updated so that every processor sees a consistent view. Maintaining coherence is one of the central problems of shared-memory multiprocessor design.

Coherence requirements

A system is coherent if a read of a location returns the most recent write to that location (from any processor), writes to the same location are serialized in the same order for all processors, and causality is preserved. Coherence is distinct from the broader memory consistency model, which governs the ordering of accesses to different locations.

Mechanisms

Two main strategies are used. Snooping protocols suit bus-based systems: each cache controller monitors ("snoops") a shared bus for transactions affecting lines it holds, updating their state. Directory-based protocols scale to larger systems by keeping, in a central or distributed directory, a record of which caches hold each block and its state, so updates and invalidations can be sent point-to-point.

Protocols track each cache line in states such as those of the widely used MESI protocol — Modified (dirty, exclusive), Exclusive (clean, exclusive), Shared (clean, possibly replicated) and Invalid — and its extensions (MOESI, MESIF) add states to reduce traffic. Invalidation-based protocols discard other copies on write; update protocols instead broadcast new values, which generally wastes bandwidth and is less common.
