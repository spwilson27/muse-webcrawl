SQL injection


Image placeholder: SQL injection

SQL injection is a code injection technique used to attack data-driven applications, in which malicious SQL statements are inserted into an entry field for execution (for example, to dump the database contents to the attacker). SQL injection must exploit a security vulnerability in an application's software, such as when user input is either incorrectly filtered for string literal escape characters embedded in SQL statements or user input is not strongly typed and unexpectedly executed. SQL injection is mostly known as an attack vector for websites, but it can be used to attack any type of SQL database.

History

The technique was first widely documented in 1998 by Jeff Forristal (writing as "rain.forest.puppy") in Phrack magazine and in articles on the early web security mailing lists. The 2007–2008 series of attacks against Microsoft SQL Server installations, and high-profile breaches such as the 2011 Sony Pictures attack and the 2015 TalkTalk data breach, brought the vulnerability to broad public attention. SQL injection has consistently ranked among the OWASP Top 10 web application security risks.

Technical description

SQL injection occurs when an application constructs a database query by concatenating untrusted user input into a query string. An attacker can supply input that alters the structure of the intended query — for example, entering ' OR '1'='1 into a login form so that the resulting WHERE clause always evaluates to true. Variants include union-based injection (using UNION SELECT to append attacker-chosen results), error-based injection (extracting data from database error messages), boolean-based blind injection (inferring data one bit at a time from application behavior), and time-based blind injection (using conditional delays such as SLEEP to encode answers).

Prevention

The standard defense is the use of parameterized queries (prepared statements), which keep code and data separate so that input can never be interpreted as SQL syntax. Additional measures include input validation, least-privilege database accounts, stored procedures used carefully, and web application firewalls as a compensating control.
