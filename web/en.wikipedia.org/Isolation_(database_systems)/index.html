Isolation (database systems)

Isolation determines when changes made by one transaction become visible to others.

In database systems, isolation is one of the ACID properties (alongside atomicity, consistency and durability). It determines how transaction integrity is visible to other users and systems: a transaction in process and yet not committed must remain isolated from other transactions, so that concurrent executions produce the same result as if the transactions ran serially.

Isolation levels

The ANSI/ISO SQL standard defines four isolation levels in increasing order of strictness: Read Uncommitted, Read Committed, Repeatable Read, and Serializable. Weaker levels permit concurrency anomalies: dirty reads (reading uncommitted data), non-repeatable reads, and phantom reads, in exchange for higher throughput.

Implementation

Isolation is typically enforced with locking (two-phase locking) or multiversion concurrency control (MVCC), in which readers access a snapshot of committed data while writers create new versions. Snapshot isolation, a popular MVCC variant, prevents most read anomalies but does not guarantee full serializability.
