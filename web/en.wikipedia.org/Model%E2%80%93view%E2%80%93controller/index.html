Model–view–controller

Model–view–controller (MVC) is a software design pattern commonly used for developing user interfaces that divides the related program logic into three interconnected elements: the model, the view, and the controller. This is done to separate internal representations of information from the ways information is presented to and accepted from the user.

Components

  • Model — the central component; the application's dynamic data structure, independent of the user interface. It directly manages the data, logic and rules of the application, and notifies associated views and controllers when its state changes.
  • View — any representation of information, such as a chart, diagram, or screen layout. Multiple views of the same information are possible.
  • Controller — accepts input (mouse clicks, keystrokes, HTTP requests) and converts it to commands for the model or view.

History

MVC was first described in 1979 by Trygve Reenskaug, then working on Smalltalk at Xerox PARC. It became a foundational concept in Smalltalk-80 and influenced later frameworks. With the growth of the web, MVC was adapted in server-side frameworks such as Ruby on Rails, Django (which calls its variant "model–template–view"), ASP.NET MVC, Laravel, and Spring MVC, as well as in desktop and mobile GUI frameworks.

Variations

Many derivative patterns exist, including model–view–presenter (MVP), model–view–viewmodel (MVVM), hierarchical MVC, and presentation–abstraction–control. Implementations differ in the direction of dependencies and in how actively the view observes the model (passive vs. active model).

Advantages and criticism

Advantages commonly cited include separation of concerns, parallel development, testability, and multiple views over the same data. Critics note added complexity for simple applications, tight coupling that can creep between view and controller, and frequent deviations from the original pattern in popular frameworks.
