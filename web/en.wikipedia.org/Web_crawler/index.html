Web crawler

The architecture of a typical web crawler: a frontier of URLs feeds fetching, parsing, and indexing modules.

A Web crawler, sometimes called a spider or spiderbot, is an Internet bot that systematically browses the World Wide Web, typically operated by search engines for the purpose of Web indexing (web spidering).

Web search engines and some other websites use Web crawling or spidering software to update their web content or indices of other sites' web content. Web crawlers copy pages for processing by a search engine, which indexes the downloaded pages so that users can search more efficiently.

Overview

A crawler starts with a list of URLs to visit, called the seed or frontier. As it visits each page it identifies the hyperlinks in the page and adds them to the frontier, while storing the page content for indexing or archival. Crawlers must implement politeness policies (respecting robots.txt and limiting request rates), revisit policies (deciding how often to re-check pages for changes), and normalization of URLs to avoid fetching the same resource repeatedly.

History

Among the earliest crawlers were Matthew Gray's World Wide Web Wanderer (1993) and the programs behind WebCrawler, Lycos, and AltaVista in 1994–95. Google's crawler, Googlebot, underpins the largest web index. Other notable crawlers include Bingbot, Baiduspider, Yandex.Bot, and the Internet Archive's Heritrix, used for web archiving.

Challenges

Crawlers face a web of tens of billions of pages: duplicate content, spider traps (such as infinite calendar pages), dynamically generated content requiring JavaScript rendering, and content hidden behind forms or logins (the "deep web"). Modern architectures distribute crawling across large clusters and prioritize pages by importance and freshness.
