Calling convention

In computer science, a calling convention is an implementation-level (low-level) scheme for how subroutines or functions receive parameters from their caller and how they return a result. Calling conventions are usually part of a platform's application binary interface (ABI) and differ among architectures, operating systems, and compilers. When some code calls a function, the convention specifies, among other things, where parameters are placed (in registers, on the call stack, or both), in what order, how return values are delivered, which registers the called function must preserve, and who is responsible for cleaning up the stack — the caller or the callee.

Examples

On 32-bit x86, numerous conventions coexisted: cdecl (arguments pushed right-to-left on the stack, caller cleans up), stdcall (callee cleans up, used by the Windows API), fastcall (first arguments in registers), and Microsoft's thiscall for C++ member functions. On x86-64 the field consolidated: the System V AMD64 ABI (used by Linux and most Unix-like systems) passes the first six integer or pointer arguments in registers RDI, RSI, RDX, RCX, R8, and R9, while Microsoft's x64 convention uses RCX, RDX, R8, and R9 with a mandatory 32-byte "shadow space" on the stack. ARM's AAPCS similarly assigns the first arguments to registers R0–R3 (or X0–X7 in AArch64).

Importance

Calling conventions matter whenever separately compiled code must interoperate — for example, when linking libraries, writing assembly routines called from C, making operating-system calls, or implementing foreign function interfaces. A mismatch between what a caller expects and what a callee does typically corrupts the stack and crashes the program, so adherence to the platform ABI is a strict requirement rather than a stylistic choice. Compilers may use private, optimised conventions for internal functions whose callers they control.
