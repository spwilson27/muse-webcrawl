Knapsack problem

Combinatorial optimization problem; NP-hard in general; solvable in pseudo-polynomial time by dynamic programming.

The knapsack problem is a classic problem in combinatorial optimization: given a set of items, each with a weight and a value, determine which items to include in a collection so that the total weight does not exceed a given capacity and the total value is as large as possible. It takes its name from the scenario of a traveller filling a knapsack of fixed capacity with the most useful items.

Definition

Maximise Σ vixi subject to Σ wixi ≤ W, with xi ∈ {0, 1}.

where each item i has value vi and weight wi, the knapsack capacity is W, and the decision variable xi indicates whether the item is taken.

Variants

  • 0-1 knapsack: each item may be taken at most once.
  • Bounded knapsack: each item type has a limited number of copies.
  • Unbounded knapsack: unlimited copies of each item type.
  • Multiple knapsack: several knapsacks with different capacities.
  • Multi-dimensional knapsack: several capacity constraints (e.g. weight and volume).

Computational complexity and algorithms

The decision version of the 0-1 knapsack problem is NP-complete, and the optimization problem is NP-hard. Nevertheless, it admits a well-known dynamic programming algorithm running in O(nW) time, which is pseudo-polynomial because it is polynomial in the numeric value of the capacity rather than in the input size. Fully polynomial-time approximation schemes (FPTAS) exist, and meet-in-the-middle and branch-and-bound methods handle moderate instances exactly. The greedy heuristic of sorting by value-to-weight ratio is optimal for the fractional knapsack problem, in which items may be divided.

Applications

Knapsack models arise in resource allocation, capital budgeting, cargo loading, cutting problems, and project selection. A knapsack-type trapdoor also underlay the Merkle–Hellman knapsack cryptosystem, one of the earliest public-key cryptosystems, later broken.
