at (command)

In Unix-like computer operating systems, at is a command that is used to schedule commands to be executed once, at a particular time in the future. The related commands batch, atq and atrm respectively schedule commands to run when system load permits, list pending jobs, and remove pending jobs. Jobs are executed by the atd daemon, which reads them from a spool directory (traditionally /var/spool/at or /var/spool/cron/atjobs). Unlike cron, which schedules recurring tasks, at is designed for one-off execution.

Usage

The user supplies a time specification and then types the commands to run, ending the input with Ctrl+D (or redirecting commands from a file with -f). Time formats are flexible; examples include at 22:00, at midnight, at teatime (16:00), at now + 30 minutes and at 14:30 31.12.2030. For example:

$ echo "shut down database" | at 02:00 tomorrow
$ atq
$ atrm 3

Access to at can be controlled through the files /etc/at.allow and /etc/at.deny. When a job runs, its standard output and error are normally mailed to the user with the local mail system, unless redirected. The environment (working directory, variables, umask) captured at submission time is reproduced when the job executes.

Other platforms

Microsoft Windows historically included an AT command for scheduling tasks, which was deprecated in favour of schtasks; the Services snap-in and Task Scheduler provide the equivalent functionality. Variants of at are standard on Linux (where it is provided by the at package, originally by Thomas Koenig), the BSDs, macOS (where atrun is disabled by default in favour of launchd) and other Unix systems, and the command is specified by POSIX.
