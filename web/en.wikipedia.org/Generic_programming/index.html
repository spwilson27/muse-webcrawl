Generic programming

From Wikipedia, the free encyclopedia

Generic programming is a style of computer programming in which algorithms are written in terms of types to be specified later that are then instantiated when needed for specific types provided as parameters. This approach, pioneered by the ML programming language in 1973, permits writing common functions or types that differ only in the set of types on which they operate when used, thus reducing duplication. Such software entities are known as generics in Ada, C#, Delphi, Eiffel, F#, Java and Swift; parametric polymorphism in ML, Scala and Haskell; and templates in C++ and D.

History

The concepts of generic programming were developed to their modern depth by David Musser and Alexander Stepanov in the 1980s, culminating in the C++ Standard Template Library (STL), which organised algorithms around iterators and abstract requirements on types called concepts. Generic programming in statically typed languages aims to give the abstraction benefits of dynamic languages without sacrificing type safety or runtime performance, by specialising generic code at compile time.

Facilities in languages

C++ templates support compile-time polymorphism and template metaprogramming and are Turing-complete. Java generics (since Java 5) use type erasure. C# generics are reified and checked at runtime. Haskell's type classes express ad-hoc polymorphism similarly to concepts. Rust's traits and generics, and Swift's protocols, continue the same design lineage. Languages differ in whether generic parameters can be constrained, and in the diagnostics produced when constraints are violated.

Advantages and costs

Generic code promotes reuse (a single sorting routine for all comparable types), catches type errors early, and often compiles to code as fast as hand-specialised versions. Costs include longer compile times, code bloat from multiple instantiations, and, in some systems, notoriously long error messages when templates are misused.
