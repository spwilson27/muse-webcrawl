Ambiguous grammar

In formal language theory, a context-free grammar is ambiguous if there exists a string that can be generated by the grammar in more than one way — that is, the string has two different parse trees, or equivalently two different leftmost derivations. Ambiguity is a property of the grammar, not of the language as such: some languages, called inherently ambiguous languages, are ambiguous under every grammar that generates them.

Example

The classic example is a simple expression grammar E → E + E | E × E | id. The string id + id × id has two parse trees, corresponding to different groupings of the operators. Programming-language grammars are usually rewritten to be unambiguous by encoding operator precedence and associativity. Another famous case is the dangling else problem: a grammar for if-then-else statements can attach an "else" to either of two "if"s, which real language specifications resolve by convention.

Decidability

It is undecidable in general whether an arbitrary context-free grammar is ambiguous, and whether a context-free language is inherently ambiguous. An example of an inherently ambiguous language is { aibjck : i = j or j = k }. In compiler design, parser classes such as LR and LALR require unambiguous grammars, and practical parser generators report conflicts indicating potential ambiguity.
