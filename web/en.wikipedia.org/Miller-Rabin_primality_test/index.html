Miller–Rabin primality test

The Miller–Rabin primality test is a probabilistic algorithm for determining whether a given number is prime. It was developed from Gary Miller's deterministic test (1976), which relied on the unproven generalised Riemann hypothesis, by Michael O. Rabin (1980), who turned it into an unconditional Monte Carlo algorithm. Like the Fermat and Solovay–Strassen tests, it works by finding "witnesses" to compositeness; unlike them, it never misidentifies primes and has a provably small error probability, making it the standard practical primality test used in cryptography.

Each round of the test either proves compositeness or boosts confidence in primality.

Algorithm

To test an odd integer n > 2, write n − 1 = 2s·d with d odd. Choose a base a in [2, n − 2]. Compute x = ad mod n. If x = 1 or x = n − 1, the round is inconclusive. Otherwise square x up to s − 1 times; if it never reaches n − 1, then n is certainly composite and a is a witness. If n is composite, at least three quarters of all bases are witnesses, so k independent rounds bound the error probability by 4−k.

Deterministic variants

For numbers of bounded size, testing a small fixed set of bases is sufficient and exact. For example, testing bases {2, 3, 5, 7, 11, 13} decides primality for all n < 3.3 × 1014, and seven particular bases (2, 325, 9375, 28178, 450775, 9780504, 1795265022) give an exact test for all 64-bit integers. Under the generalised Riemann hypothesis, testing all bases up to 2(ln n)2 is deterministic and polynomial-time.

Applications

Miller–Rabin is the workhorse of key generation in RSA, Diffie–Hellman and elliptic-curve systems, where random primes of hundreds or thousands of bits must be found quickly; implementations in OpenSSL, Java's BigInteger.isProbablePrime and Python's sympy rely on it, often combined with trial division by small primes first. Although the AKS test (2002) proved primality testing is possible in deterministic polynomial time, it remains far slower in practice.
