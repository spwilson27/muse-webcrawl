Representational state transfer

Representational state transfer (REST) is a software architectural style that was created to describe the design and guide the development of the architecture for the World Wide Web. REST defines a set of constraints for how the architecture of a distributed, Internet-scale hypermedia system, such as the Web, should behave. REST APIs that faithfully implement these constraints are often called "RESTful."

REST clients manipulate resources through representations exchanged over a uniform interface.

History

The term was introduced by Roy Fielding in his 2000 PhD dissertation at the University of California, Irvine, "Architectural Styles and the Design of Network-based Software Architectures." Fielding, a co-author of HTTP and a co-founder of the Apache HTTP Server project, articulated REST to explain the architecture that made the early Web scalable, in contrast to ad hoc styles of network-based application design.

Architectural constraints

REST is defined by six guiding constraints: client–server separation; statelessness (each request contains all information needed to understand it); cacheability of responses; a layered system; code on demand (optional); and a uniform interface, itself comprising resource identification, manipulation of resources through representations, self-descriptive messages, and hypermedia as the engine of application state (HATEOAS). In practice, most web APIs described as RESTful use HTTP methods (GET, POST, PUT, DELETE) on resource URLs with JSON representations, though full hypermedia-driven REST is comparatively rare.
