FASTQ format

FASTQ format is a text-based format for storing both a biological sequence (usually nucleotide sequence) and its corresponding quality scores. Both the sequence letter and quality score are encoded with a single ASCII character for brevity. The format was originally developed at the Wellcome Trust Sanger Institute to bundle a FASTA-formatted sequence and its quality data, and has become the de facto standard for storing the output of high-throughput sequencing instruments such as the Illumina Genome Analyzer.

Format

A FASTQ file normally uses four lines per sequence:

@SEQ_ID
GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCCATTTGTTCAACTCACAGTTT
+
!''*((((***+))%%%++)(%%%%).1***-+*''))**55CCF>>>>>CCCCCCC65

Line 1 begins with '@' and is followed by a sequence identifier and optional description. Line 2 is the raw sequence. Line 3 begins with '+' and is optionally followed by the same identifier. Line 4 encodes the quality values for the sequence in line 2, with the same number of symbols.

Quality encoding

Quality scores represent the probability that the corresponding base call is incorrect, conventionally on the Phred scale, Q = −10 log10 P. Different platforms and eras have used different ASCII offsets and ranges: the original Sanger (Phred+33) encoding, Illumina's earlier Phred+64 pipelines, and Solexa scores — a source of historic incompatibility. Modern data overwhelmingly uses Phred+33, standardized in part through the Sequence Read Archive. A formal description of the format and its variants was published by Cock et al. in 2010, "The Sanger FASTQ file format for sequences with quality scores."

Usage

FASTQ files are the input to read alignment, variant calling, and transcriptomics pipelines (often compressed with gzip), and are archived by the major sequence repositories. Paired-end data is stored in two files of matching reads, conventionally suffixed _1 and _2.
