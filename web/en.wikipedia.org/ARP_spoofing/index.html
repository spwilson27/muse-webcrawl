ARP spoofing

ARP spoofing, also called ARP cache poisoning or ARP poison routing, is a technique by which an attacker sends falsified Address Resolution Protocol (ARP) messages onto a local area network. The aim is to associate the attacker's MAC address with the IP address of another host, such as the default gateway, causing traffic meant for that IP address to be sent to the attacker instead.

Background

ARP resolves IPv4 addresses to link-layer MAC addresses on a local network. It is stateless and unauthenticated: hosts accept ARP replies even when they have not sent a request ("gratuitous" ARP), and they update their ARP caches with the most recent information received. These design properties, acceptable in ARP's original trusted-network context, make the protocol vulnerable to spoofing on any network where an attacker can send frames.

Attack uses

Once a victim's ARP cache is poisoned, the attacker can perform a man-in-the-middle attack by forwarding the intercepted traffic to its real destination so the connection continues to work while being observed or modified. Variants include denial-of-service attacks, in which a target IP is mapped to a nonexistent MAC address; session hijacking; and redirection of traffic to credential-harvesting pages. Tools such as arpspoof (part of dsniff), Ettercap, Bettercap, and Cain and Abel have long automated the technique. ARP spoofing works only within the local broadcast domain and cannot directly cross routers.

Defenses

Defenses include static ARP entries for critical hosts, Dynamic ARP Inspection on managed switches (which validates ARP packets against a DHCP-snooping binding table), port security, network segmentation, and monitoring tools such as arpwatch and XArp that flag changing IP-to-MAC mappings. Encrypting application traffic with TLS or using VPNs does not stop the redirection but sharply limits what an interceptor can read or alter. The long-term architectural answer, IPv6 with Secure Neighbor Discovery, has seen little deployment.

Legitimate uses

The same gratuitous-ARP mechanisms are used legitimately for high-availability failover, in which a standby device announces that it has taken over an IP address, and by some network-management and redirection systems such as hotel and hotspot portals.
