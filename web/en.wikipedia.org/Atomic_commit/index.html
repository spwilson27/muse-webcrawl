Atomic commit
Field: Distributed computing, databases
Problem: All participants agree to commit or abort a transaction
Protocols: Two-phase commit, three-phase commit, Paxos commit

In distributed computing and databases, an atomic commit is an operation that applies a set of changes as a single indivisible unit across multiple participants: either all participants commit the transaction or all of them abort it, even in the presence of failures. It is the "A" (atomicity) of the ACID properties extended across a distributed system.

Protocols

The classic solution is the two-phase commit protocol, in which a coordinator first asks all participants to vote (the prepare phase) and then broadcasts the decision to commit if all voted yes, or to abort otherwise. Its weakness is blocking: if the coordinator fails after participants have voted, they may be unable to resolve the transaction until it recovers. Three-phase commit reduces blocking under some failure assumptions, while consensus-based approaches such as Paxos commit replicate the decision so that coordinator failure can be tolerated.

Atomic commit problem

The atomic commit problem is closely related to consensus; it can be shown that no protocol guarantees termination in a fully asynchronous system with even one faulty process (the FLP impossibility result), so practical systems rely on timeouts, failure detectors, and consensus algorithms.
