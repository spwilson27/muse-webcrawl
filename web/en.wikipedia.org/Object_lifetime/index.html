Object lifetime

In object-oriented programming, the object lifetime (or life cycle) of an object is the time between an object's creation and its destruction. Object lifetime is a central concern in languages with manual memory management, where it is the programmer's responsibility to destroy objects that are no longer needed; in languages with garbage collection, objects are destroyed automatically when they become unreachable.

Creation

Objects are created by allocating memory and then initialising it, typically via a constructor. The details of allocation and initialisation order differ between languages; in some, such as C++, creation can partly fail, raising questions about the state of a partially constructed object.

Destruction

Destruction generally involves finalisation — in C++, a destructor; in languages such as Java and C#, a finalizer — followed by deallocation of the memory. Deterministic destruction, as in C++, allows the RAII (Resource Acquisition Is Initialization) idiom, in which an object's destructor releases resources such as files or locks. Garbage-collected environments typically provide non-deterministic finalisation, so explicit resource management (for example, try-with-resources or using blocks) is used instead.

Lifetime problems

Errors in lifetime management include memory leaks, use-after-free, double free, and dangling references. Static program analysis, smart pointers, ownership systems (as in Rust), and conservative garbage collection are all techniques used to mitigate such errors.
