Binary search tree

A binary search tree (BST), also called an ordered or sorted binary tree, is a rooted binary tree data structure whose internal nodes store keys in sorted order: for every node, all keys in its left subtree are smaller than the node's key, and all keys in its right subtree are larger. This property allows lookup, insertion, and deletion to be performed by a form of binary search, skipping about half of the tree at each step on average.

Operations

Searching

To search for a key, the algorithm compares it with the root: if equal, the search succeeds; if smaller, it continues in the left subtree; if larger, in the right subtree. Because each comparison discards one subtree, the running time is proportional to the height of the tree.

Insertion and deletion

Insertion proceeds like an unsuccessful search, attaching the new key as a leaf where the search ends. Deletion has three cases: removing a leaf is trivial; removing a node with one child replaces it with that child; removing a node with two children replaces its key with that of its in-order successor (the smallest key in its right subtree) or predecessor, and then deletes that node instead.

Traversal

An in-order traversal of a BST visits the keys in sorted order. Pre-order and post-order traversals are used for copying and deleting whole trees and for representing expressions.

Performance

The worst case arises when keys are inserted in sorted order, degenerating the tree into a linked list. This motivated self-balancing binary search trees — such as AVL trees, red–black trees, splay trees, and treaps — which use rotations or randomised priorities to keep the height logarithmic. Randomised insertion order also gives expected logarithmic height without explicit balancing.

Applications

BSTs underlie implementations of sets, maps, and priority queues in standard libraries (often as red–black trees), support range queries and order statistics, and appear in databases and file systems in generalised forms such as the B-tree.
