Subroutine

In computer programming, a subroutine (also called a procedure, function, routine, or method, depending on the language) is a sequence of program instructions that performs a specific task, packaged as a unit that can be called from other parts of a program. When the subroutine finishes, control returns to the instruction following the call. Subroutines are a fundamental tool for decomposing programs, avoiding duplication, and building libraries of reusable code.

History

The concept dates to the earliest stored-program computers: David Wheeler is credited with inventing the subroutine call on the EDSAC in 1949, and the 1952 textbook by Wheeler, Maurice Wilkes, and Stanley Gill described subroutine libraries. Early assembly languages and Fortran provided SUBROUTINE facilities; later languages generalized the idea with parameters, local variables, and return values.

Mechanics

Calls are normally implemented with a call stack: the return address, saved registers, arguments, and local variables are pushed as a stack frame for each invocation, which permits recursion — a subroutine calling itself. Calling conventions specify how arguments are passed (by value or by reference) and how results are returned.

Advantages

Subroutines support modularity, abstraction, and code reuse; they reduce program size, localize changes, and can improve performance through caching or optimized library implementations. Related concepts include mathematical functions, coroutines, and methods in object-oriented programming.
