RTP Control Protocol

RTCP packets flow between participants alongside the RTP media stream, carrying reception statistics and source descriptions.

The RTP Control Protocol (RTCP) is a binary-encoded out-of-band signaling protocol that functions alongside the Real-time Transport Protocol (RTP). Its basic functionality and packet structure is defined in RFC 3550. RTCP provides statistics and control information for an RTP session, but does not itself transport any media data.

The primary function of RTCP is to provide feedback on the quality of service (QoS) in media distribution, by periodically sending statistics information such as transmitted octet and packet counts, packet loss, packet delay variation, and round-trip delay time to participants in a streaming multimedia session. An application may use this information to control quality of service parameters, perhaps by limiting flow, or using a different codec.

Functions

RTCP performs several functions: it carries reception quality feedback from receivers (Receiver Reports) and transmission information from senders (Sender Reports); it assigns each source a persistent canonical name (CNAME) so participants can be tracked across streams; it conveys minimal session control information in Source Description (SDES) packets; and it signals when a participant leaves a session with a BYE packet. Typically RTCP traffic is limited to 5% of the session bandwidth, so that control traffic does not overwhelm the media itself.

Packet types

RTCP defines several packet types: Sender Report (SR, type 200), Receiver Report (RR, type 201), Source Description (SDES, type 202), Goodbye (BYE, type 203) and Application-defined (APP, type 204). Extensions defined later include Extended Reports (RTCP XR, RFC 3611), which add detailed metrics such as burst loss, jitter buffers and voice quality scores, and feedback messages used by WebRTC for congestion control and rapid key-frame requests.
