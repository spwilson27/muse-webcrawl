In computer science, merge sort (also commonly spelled mergesort) is an efficient, general-purpose, comparison-based sorting algorithm. Most implementations produce a stable sort, meaning that the order of equal elements is preserved. Merge sort is a divide-and-conquer algorithm invented by John von Neumann in 1945; a detailed description appeared in a report by Herman Goldstine and von Neumann in 1947.

Algorithm

Conceptually, merge sort works as follows: divide the unsorted list into n sublists, each containing one element (a list of one element is considered sorted); then repeatedly merge sublists to produce new sorted sublists until only one remains. In the more common top-down implementation, the list is recursively split in half until sublists of size one are reached, and the merge step combines two sorted halves by repeatedly taking the smaller of their front elements.

function merge_sort(list):
    if length(list) <= 1: return list
    mid = length(list) / 2
    left  = merge_sort(list[0 .. mid])
    right = merge_sort(list[mid .. end])
    return merge(left, right)

Analysis

Merge sort performs Θ(n log n) comparisons in the worst, average, and best cases for arrays of random data, because the recursion tree always has log n levels and each level processes all n elements once. Its principal drawback for arrays is the Θ(n) auxiliary storage used during merging. For linked lists, merge sort can be implemented with only O(1) extra space (plus recursion stack) by relinking nodes, and it is a standard choice where sequential access dominates.

Variants and use

Variants include bottom-up (iterative) merge sort, natural merge sort, which exploits existing runs in the data, and in-place merging schemes. Merge sort is the basis of Timsort, the hybrid algorithm used in Python and Java's object sorting, and of external sorting methods for data too large to fit in memory, where its sequential access pattern is ideal. Because the two halves can be sorted independently, merge sort parallelizes readily, achieving O(n) time with enough processors on a CREW PRAM model.
