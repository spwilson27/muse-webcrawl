Middleware

Middleware
TypeSoftware layer
Sits betweenOperating system / network and applications
ExamplesMessage brokers, ORBs, application servers, API gateways

Middleware is computer software that provides services to software applications beyond those available from the operating system. It is often described as "software glue": it makes it easier for developers to implement communication, input/output and data management so that they can focus on the specific purpose of their application. The term dates to a 1968 NATO software engineering report and came into wide use in the 1980s with networked computing.

Types

Major categories include message-oriented middleware and message brokers (such as IBM MQ, Apache Kafka and RabbitMQ), which pass messages between systems; transaction-processing monitors; object request brokers based on CORBA; remote procedure call frameworks; database middleware; web and application servers (such as Jakarta EE servers); and enterprise service buses used in service-oriented architectures. In web frameworks such as Express and Django, "middleware" also denotes functions that process a request between the server and the application logic — for example authentication, logging and compression.

Role in distributed systems

Middleware hides the heterogeneity of networks, hardware and operating systems behind uniform programming interfaces, supplying services such as naming, transactions, security, persistence and failover. By standardising these services, middleware underlies enterprise application integration and much of modern cloud and microservices infrastructure.

Criticism

Middleware can add complexity, cost and vendor lock-in, and over-layered middleware stacks have sometimes been blamed for brittle enterprise systems; lighter-weight APIs and microservices patterns partly emerged in reaction to it.
