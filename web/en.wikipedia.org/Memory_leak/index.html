Memory leak

In computer science, a memory leak is a type of resource leak that occurs when a computer program incorrectly manages memory allocations, so that memory which is no longer needed is not released. A memory leak reduces the performance of the computer by reducing the amount of available memory, and in the worst case can cause the program — or the whole system — to crash or be terminated by the operating system.

Causes

Leaks are most common in languages with manual memory management, such as C and C++, where a program allocates heap memory with functions like malloc but never calls free. They can also occur in garbage-collected languages when a program keeps unintended references to objects — for example by storing them in a long-lived cache or failing to deregister event listeners — preventing the garbage collector from reclaiming them.

Consequences

A slow leak may be unnoticeable in a short-lived process, because the operating system reclaims all of a process's memory when it exits. In long-running systems such as servers, daemons and operating system kernels, even a small leak per operation accumulates: the process's memory footprint grows until the system begins swapping or the out-of-memory manager kills the process.

Detection and prevention

Tools such as Valgrind, AddressSanitizer and various heap profilers help detect leaks. Preventive techniques include disciplined ownership conventions, reference counting, smart pointers and RAII in C++, and automatic garbage collection in languages such as Java, C# and Go. Related resource leaks include file-handle leaks and connection leaks.
