ZPP

In computational complexity theory, ZPP (zero-error probabilistic polynomial time) is the complexity class of problems for which a probabilistic Turing machine exists with these properties:

  • It always outputs the correct YES or NO answer.
  • Its expected running time is polynomial in the size of the input (though it may on occasion run longer).

Equivalently, ZPP is the class of problems that can be solved by a Las Vegas algorithm — a randomized algorithm that never errs but whose running time is guaranteed only in expectation. The machine may also be allowed to output "don't know" with bounded probability on any given run, provided the expected number of repetitions needed to get a definite answer is polynomial.

Definition and relations

ZPP equals the intersection of the classes RP and co-RP: a problem is in ZPP if and only if it has both a one-sided-error randomized polynomial-time algorithm that never falsely accepts and one that never falsely rejects. Consequently ZPP is contained in both RP and BPP, and in turn contains P, since deterministic polynomial-time algorithms are a special case of Las Vegas algorithms. Whether ZPP equals P or is strictly larger is an open question, connected with the broader problem of derandomization.

Witness viewpoint

An alternative characterization uses a polynomial-time probabilistic "witness" algorithm: the problem is in ZPP if the algorithm outputs YES, NO, or "unknown," is correct whenever it commits to an answer, and answers "unknown" with probability at most one half, so that a constant expected number of independent repetitions yields an answer with high probability.

History

The class was introduced by John Gill in his 1977 work on probabilistic Turing machines, which also introduced RP, co-RP, and BPP. ZPP's name derives from "zero-error probabilistic polynomial time".
