Dynamic dispatch

A virtual method table (vtable) resolves calls at run time

In computer science, dynamic dispatch is the process of selecting which implementation of a polymorphic operation (method or function) to call at run time, based on the actual type of the object (or arguments) involved, rather than on the static type known at compile time. It is a core mechanism of object-oriented and other polymorphic programming languages, in contrast to static dispatch, in which the implementation is chosen at compile time.

Single and multiple dispatch

In single dispatch, the selection depends on one argument — in most object-oriented languages, the receiver object of a method call (this/self). Languages such as Common Lisp (CLOS), Julia and Dylan support multiple dispatch, in which generic functions select a method based on the types of all their arguments. Double dispatch is a work-around pattern for emulating two-argument dispatch in single-dispatch languages, often used with the visitor pattern.

Implementation

The most common implementation is the virtual method table (vtable): each class has a table of pointers to its method implementations, and each object carries a pointer to its class's table, so a virtual call costs an indirection. Alternatives include message-passing lookup in languages derived from Smalltalk and Objective-C, method caches and inline caches in JIT-compiled environments, type classes in Haskell, and trait objects in Rust, the latter allowing the programmer to choose between static and dynamic dispatch explicitly.

Performance

Dynamic dispatch historically carried a reputation for overhead because it inhibits inlining and forces indirect branches, which stress branch predictors. Modern JIT compilers mitigate this with speculative devirtualization, and CPUs have become adept at predicting repeated indirect targets, so the cost is often small relative to the design benefits.
