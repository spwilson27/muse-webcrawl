Heapsort

Class: Sorting algorithm
Data structure: Array (binary heap)
Worst-case performance: O(n log n)
Space complexity: O(1) auxiliary

Heapsort is a comparison-based sorting algorithm which can be thought of as an improved selection sort. Like selection sort, heapsort divides its input into a sorted and an unsorted region, and it iteratively shrinks the unsorted region by extracting the largest element from it and inserting it into the sorted region. Unlike selection sort, heapsort does not waste time with a linear-time scan of the unsorted region; rather, it maintains the unsorted region in a heap data structure to more quickly find the largest element in each step.

Algorithm

The algorithm, invented by J. W. J. Williams in 1964, first rearranges the array into a max-heap in linear time (the "heapify" phase, improved by Robert W. Floyd). It then repeatedly swaps the root (the maximum) with the last element of the heap, reduces the heap size by one, and restores the heap property by sifting the new root down. After n−1 such steps the array is sorted.

Performance

Heapsort runs in O(n log n) time in the worst, average, and best cases and uses only constant extra memory, a combination unmatched by quicksort (which has a quadratic worst case) or merge sort (which needs linear extra space). In practice it is usually slower than a well-implemented quicksort because of poorer cache locality. Heapsort is not a stable sort.

Variants

Variants include Floyd's bottom-up heap construction, the smoothsort algorithm of Edsger Dijkstra, which adapts to nearly sorted inputs, and weak heapsort. The introsort algorithm used in many standard libraries begins with quicksort and switches to heapsort when recursion depth suggests degenerate behaviour.
