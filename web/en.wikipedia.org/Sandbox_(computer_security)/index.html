Sandbox (computer security)

From Wikipedia, the free encyclopedia

In computer security, a sandbox is a security mechanism for separating running programs, usually in an effort to mitigate system failures and/or software vulnerabilities from spreading. It is often used to execute untested or untrusted programs or code, possibly from unverified or untrusted third parties, suppliers, users or websites, without risking harm to the host machine or operating system. A sandbox typically provides a tightly controlled set of resources for guest programs to run in, such as storage and memory, while network access and the ability to inspect the host system or read from input devices are usually disallowed or heavily restricted.

Implementations

Sandboxes are implemented in many layers of a computing system. Web browsers run web content in sandboxed processes so that a compromised renderer cannot access the rest of the system. The Java virtual machine and .NET runtime historically provided sandbox models for applets and downloaded code. Operating systems offer sandboxing through mechanisms such as chroot, Linux namespaces and seccomp filters, FreeBSD jails, and macOS App Sandbox; dedicated tools such as Sandboxie intercept the system activity of programs on Windows. Virtual machines and containers can also serve as sandboxes, providing stronger isolation at greater cost.

Uses

Beyond isolating untrusted code, sandboxes are used by security analysts to observe the behaviour of malware in a controlled environment, by software testers to run automated tests without side effects, and by application stores and mobile platforms to restrict what installed applications may access. Sandboxing is a form of defence in depth: it assumes the contained program may be malicious or exploited, and limits the damage it can do.

Limitations

Sandboxes add complexity and overhead, and their isolation is only as strong as their implementation; sandbox escapes are a prized class of software vulnerability. A sandbox also cannot judge whether permitted operations are being used maliciously, so it is normally combined with other controls such as code signing, least-privilege design, and monitoring.
