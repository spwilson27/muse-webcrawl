Linearizability

Linearizability is a consistency model for concurrent programming and distributed systems, introduced by Maurice Herlihy and Jeannette Wing in 1990. A system is linearizable if every operation appears to take effect instantaneously at some point — its "linearization point" — between the operation's invocation and its response, so that the concurrent execution is equivalent to some sequential execution respecting real-time order.

Definition and properties

Linearizability is a safety property: it constrains what results concurrent operations may return, but says nothing about liveness. It is composable ("local"), meaning a system built from linearizable objects is itself linearizable, a property not shared by some weaker models. Unlike sequential consistency, linearizability respects the real-time ordering of non-overlapping operations: once a write completes, subsequent reads must observe it.

Use in distributed systems

In distributed systems, linearizability provides "strong consistency": the system behaves as if there were a single copy of the data. Consensus-based systems such as those using Paxos or Raft (e.g. etcd, ZooKeeper) provide linearizable operations, usually at the cost of higher latency or reduced availability during network partitions — a tension formalised by the CAP theorem.
