Cucumber is a software tool that supports behaviour-driven development (BDD). It allows software behaviours to be described in a simple, human-readable domain-specific language called Gherkin, using plain-text "feature" files written in the language of the business — and now available in many spoken languages — so that non-programmers can read and write specifications that are also executable tests.

How it works

A scenario in Gherkin is structured with the keywords Given, When and Then:

Feature: Shopping basket
  Scenario: Adding an item
    Given an empty basket
    When the customer adds a cucumber
    Then the basket contains 1 item

Each step is bound to code ("step definitions") that drives the application, so the feature files act as living documentation and an automated acceptance test suite at once. Cucumber began as a Ruby tool written by Aslak Hellesøy in 2008, growing out of the RSpec story runner; implementations now exist for Java, JavaScript, Python and many other platforms, and the project is maintained under the Cucumber open-source organisation.
