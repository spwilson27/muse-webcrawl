Dynamic linker

In computing, a dynamic linker is the part of an operating system that loads and links the shared libraries needed by an executable when it is started (at "run time" or "load time") or, on request, while it is running. Dynamic linking defers much of the linking process until a program starts, in contrast to static linking, in which the linker copies all library routines into the executable at build time. On Unix-like systems the dynamic linker is itself a small program — for example ld-linux.so for the glibc loader on Linux — whose pathname is recorded in the executable's PT_INTERP segment; on Windows the linking is performed by the system loader with DLLs.

The dynamic linker maps shared libraries into a process and resolves its symbols at load time.

How it works

When a dynamically linked program is executed, the kernel loads the dynamic linker, which reads the program's dynamic section to find its needed libraries, searches the standard paths (and configuration files such as /etc/ld.so.cache on Linux, plus environment settings like LD_LIBRARY_PATH), maps each library into memory, and applies relocations so that references to functions and variables point to the correct addresses. Position-independent code and the procedure linkage table (PLT) and global offset table (GOT) allow code pages to be shared between processes while each process keeps its own data pointers. Many systems resolve function addresses lazily, binding a symbol the first time it is actually called, which speeds program startup.

Programs can also load libraries explicitly at run time using dlopen and look up symbols with dlsym on POSIX systems (or LoadLibrary/GetProcAddress on Windows), enabling plugins, drivers, and optional features.

Advantages and disadvantages

Dynamic linking saves disk space and memory because one copy of a library serves many programs; library bug fixes and security patches take effect for all programs at once; and programs can be extended with modules loaded on demand. The costs include startup overhead, fragility when libraries change incompatibly ("DLL hell"), security risks if library search paths are subverted, and more complex deployment. Static linking remains common for system-critical tools and self-contained distribution, and is the default in some languages' toolchains such as Go's.

Implementations

On ELF-based systems the dynamic linker is provided by the C library: glibc's ld.so on most Linux distributions, musl's loader, the linkers in the BSD systems, and macOS's dyld for Mach-O binaries. The Windows loader (ntdll.dll) performs analogous work for DLLs, applying import address tables and side-by-side assemblies in later versions to mitigate versioning conflicts.
