Chroot

chroot is an operation on Unix and Unix-like operating systems that changes the apparent root directory for a running process and its children. A program that is run in such a modified environment cannot name (and therefore normally cannot access) files outside the designated directory tree. The modified environment is commonly called a chroot jail.

History

The chroot system call was introduced in Version 7 Unix in 1979 and was added to BSD by Bill Joy in 1982 as part of the work on installing and testing software safely. The command-line utility of the same name invokes the call to launch a program inside the new root.

Uses

Chroot environments are used to isolate and sandbox untrusted or potentially vulnerable services — for example, running a DNS or mail server so that, if it is compromised, the attacker is confined to a minimal filesystem. Other uses include software installation, building packages in a clean environment, testing, system recovery from a live medium, and running legacy programs that expect particular library versions.

Limitations

chroot was not originally designed as a complete security boundary: processes running as root inside a chroot may be able to escape, and the mechanism provides no isolation of network, process or device namespaces. Modern systems therefore supplement or replace it with jails, zones, and containers that build on namespace isolation.
