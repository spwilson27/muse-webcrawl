SYN flood

TypeDenial-of-service attack
ExploitsTCP three-way handshake
First documented1996 (Phrack magazine; CERT advisory)
MitigationsSYN cookies, SYN cache, rate limiting, filtering

A SYN flood is a form of denial-of-service attack in which an attacker rapidly initiates many connections to a server without completing them. The server is left holding large numbers of half-open connections, consuming the resources reserved for connection state until it can no longer accept legitimate traffic.

Background: the TCP handshake

A normal TCP connection begins with a three-way handshake: the client sends a SYN (synchronise) packet, the server replies with SYN-ACK and reserves state for the connection in a backlog queue, and the client completes the handshake with an ACK. Until the final ACK arrives, the connection is "half-open" and the server's reserved state is held until it times out.

The attack

In a SYN flood, the attacker sends a rapid succession of SYN requests, typically using spoofed source addresses belonging to unreachable or uninvolved hosts. The server dutifully replies with SYN-ACK packets and allocates backlog entries, but the final ACKs never arrive — the spoofed hosts either do not exist or discard the unsolicited replies. The backlog fills, and new connection attempts, including those from real users, are refused or dropped. Perpetrated from many machines at once, the attack becomes a distributed denial of service (DDoS).

The attack was described publicly in 1996, notably in issue 48 of the hacker magazine Phrack and in a subsequent CERT advisory; it was used that year against the New York ISP Panix, one of the earliest widely reported denial-of-service incidents.

Countermeasures

Defences include increasing the size of the backlog queue and shortening the half-open timeout, though both merely raise the threshold. More robust techniques include:

  • SYN cookies — the server encodes the connection state into the sequence number of its SYN-ACK and allocates nothing until the client returns a valid ACK, making spoofed floods harmless to memory.
  • SYN cache — a compact global hash of pending connections that stores far less state per entry.
  • Filtering and rate limiting — upstream routers and scrubbing services discard or throttle suspicious SYN traffic.
  • Firewalls and proxies that complete handshakes on the server's behalf and pass on only established connections.
