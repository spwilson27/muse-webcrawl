Elliptic-curve Diffie–Hellman (ECDH) is a key agreement protocol that allows two parties, each having an elliptic-curve public–private key pair, to establish a shared secret over an insecure channel. It is a variant of the Diffie–Hellman key exchange that uses the mathematics of elliptic curves rather than modular exponentiation in a finite field.

Key establishment process

Before the protocol can be run, the two parties must agree on the parameters of the elliptic curve: the finite field over which the curve is defined, the curve equation, and a generator point G of prime order. Each party then generates a private key d, a randomly selected integer, and computes a public key Q = dG, where the multiplication is the scalar multiplication of the generator point.

Alice computes K = dA QB using her own private key and Bob's public key, while Bob computes K = dB QA. Because scalar multiplication is associative in the relevant sense, both arrive at the same point: dA dB G. The shared secret is typically the x-coordinate of this point, which is then passed through a key derivation function to produce symmetric encryption keys.

Security

The security of ECDH rests on the difficulty of the elliptic-curve discrete logarithm problem: given G and Q = dG, it is computationally infeasible to recover d for well-chosen curves. ECDH provides much shorter key sizes than classical Diffie–Hellman for equivalent security; a 256-bit elliptic-curve key offers security comparable to a 3072-bit finite-field key.

ECDH by itself does not authenticate either party and is therefore vulnerable to man-in-the-middle attacks if used alone. In practice it is combined with digital signatures, as in the TLS handshake, or with pre-shared identity keys, as in the Signal protocol's X3DH handshake. Implementations must also validate that received public keys are points on the correct curve to prevent invalid-curve attacks.

Usage

Ephemeral ECDH (ECDHE) is the standard key exchange in modern TLS connections, providing forward secrecy. Curve25519, designed by Daniel J. Bernstein, is widely used through the X25519 function and appears in SSH, WireGuard, and many messaging applications. NIST curves such as P-256 and P-384 remain common in enterprise and government systems.
