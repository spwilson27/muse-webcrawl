Hungarian notation

Summary

Field: Computer programming

Inventor: Charles Simonyi

Variants: Systems Hungarian, Apps Hungarian

Hungarian notation is a convention in computer programming in which the name of a variable or function indicates its type or intended use. It was developed by Charles Simonyi, a Hungarian-born programmer at Xerox PARC and later Microsoft, and it became widely known through its use in the Windows API, where prefixes such as lp (long pointer), sz (null-terminated string), and h (handle) appear in names like hWnd and szName.

Systems and Apps Hungarian

In Systems Hungarian, the prefix encodes the low-level data type (for example, i for integer, f for float, b for boolean). In Simonyi's original Apps Hungarian, the prefix instead encodes the semantic "kind" of the value — such as rw for row and col for column — so that assigning a value of the wrong kind looks visibly incorrect, catching errors that a type checker cannot.

Criticism and decline

Critics argue that encoding data types in names duplicates information the compiler already checks, makes code harder to read, and becomes misleading when a variable's type changes. Modern integrated development environments show type information on demand, and strongly typed languages reduce the need for the convention, so Hungarian notation is far less common in new code than it was in the 1980s and 1990s. The semantic Apps variant, however, still has defenders.
