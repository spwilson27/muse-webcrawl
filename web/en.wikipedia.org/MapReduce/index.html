MapReduce

MapReduce is a programming model and an associated implementation for processing and generating big data sets with a parallel, distributed algorithm on a cluster. A MapReduce program is composed of a map procedure, which performs filtering and sorting, and a reduce procedure, which performs a summary operation.

Overview

The model was popularised by a 2004 paper by Jeffrey Dean and Sanjay Ghemawat of Google, drawing inspiration from the map and reduce functions common in functional programming. The framework takes care of scheduling tasks, data distribution and handling machine failures, allowing programmers without experience of distributed systems to use large clusters.

Dataflow

The computation takes a set of input key/value pairs and produces a set of output key/value pairs. The user expresses the computation as two functions:

Map: takes an input pair and produces a set of intermediate key/value pairs. The library groups together all intermediate values associated with the same intermediate key and passes them to the reduce function.

Reduce: accepts an intermediate key and a set of values for that key. It merges these values together to form a possibly smaller set of values.

Between the two phases, a shuffle step redistributes the intermediate data across the nodes of the cluster based on the keys. A canonical example is counting word frequencies: mappers emit (word, 1) pairs, and reducers sum the counts for each word.

Implementations and successors

The best-known open-source implementation is Apache Hadoop MapReduce. MapReduce proved highly influential for large-scale batch processing, but its disk-heavy, batch-oriented design led to successors such as Apache Spark, which keeps intermediate results in memory and supports a richer set of operations. Google itself moved to newer systems for many workloads, while the model remains widely used and taught.
