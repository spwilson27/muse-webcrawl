Weak reference

In computer programming, a weak reference is a reference to an object that does not prevent the object from being reclaimed by a garbage collector, unlike a strong reference, which keeps its referent alive as long as the reference exists. Weak references are used to build data structures such as caches and observer registries that must not extend the lifetime of the objects they point to.

Uses

A common use is the weak hash map, in which entries disappear automatically when their keys are no longer referenced elsewhere; Java's java.util.WeakHashMap is a standard example. Weak references also implement canonicalizing mappings, where a program keeps one shared instance of an object per value: if a weak reference has been cleared, the object can be recreated. Event listener and callback registries use weak references so that registering an observer does not itself keep the observer alive, avoiding a common source of memory leaks.

Language support

Java provides three strengths of non-strong reference through the java.lang.ref package: weak references, soft references (cleared only under memory pressure), and phantom references. The .NET Framework offers WeakReference and WeakReference<T>; Python's weakref module provides proxies and weak-key dictionaries for most user-defined classes. In C++, std::weak_ptr pairs with std::shared_ptr to break reference cycles.

Semantics

Accessing a weak reference is a two-step operation: the program must check whether the referent still exists and obtain a strong reference to it before use. In Java, a cleared weak reference returns null from get(); a C++ weak_ptr must be lock()ed into a shared_ptr. If an object has only weak references, the collector may reclaim it at the next collection cycle, and the weak references are cleared.
