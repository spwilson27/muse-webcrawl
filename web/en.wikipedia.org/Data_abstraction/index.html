Data abstraction

In software engineering and computer science, abstraction is the process of generalizing concrete details, such as attributes, away from the study of objects and systems to focus attention on details of greater importance. Data abstraction specifically enforces a clear separation between the abstract properties of a data type and the concrete details of its implementation.

The abstract properties are those that clients of the data type can observe — its interface — while the concrete implementation is kept hidden, a principle known as information hiding. This allows the implementation to change without affecting code that uses the abstraction.

Abstract data types

An abstract data type (ADT) is a mathematical model for a data type defined by its behavior from the point of view of a user: the possible values, the possible operations on data of this type, and the behavior of these operations. Stacks, queues, lists, and maps are classic examples. Object-oriented programming languages support ADTs through classes and encapsulation, while functional languages may use algebraic data types and modules.

Levels of abstraction

In database systems, data abstraction is commonly described at three levels: the physical level (how data is stored), the logical level (what data is stored and its relationships), and the view level (tailored presentations for particular users). This layering, formalized in the ANSI/SPARC architecture, insulates applications from changes in storage structures.
