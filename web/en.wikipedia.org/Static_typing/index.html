Static typing

In computer science, static typing is a property of a programming language's type system in which type checking is performed during compile-time as opposed to run-time. In a statically typed language, variable types are known at compile time, so many errors — such as applying a function to an argument of the wrong type — can be caught before the program executes. The opposite approach is dynamic typing, used by languages such as Python, Ruby, and JavaScript, in which type checking occurs at run time.

Characteristics

Statically typed languages include C, C++, Java, C#, Rust, Go, Haskell, and ML. In some, types must be declared explicitly (manifest typing); in others, the compiler can infer types automatically, as in Haskell, OCaml, and much of Rust and modern C++ code using auto. Static typing is often associated with better tooling support: code completion, refactoring tools, and documentation generated from type signatures.

Advantages and disadvantages

Advocates point to earlier error detection, potential performance benefits (the compiler can optimize based on known types), and improved maintainability of large codebases. Critics argue that static type declarations add verbosity and reduce flexibility, and that extensive unit testing can provide some of the same guarantees dynamically. Gradual typing — as in TypeScript's approach to JavaScript, or Python's optional type hints — attempts to combine the two approaches.

Related concepts

Static typing is distinct from, though often correlated with, strong typing (the degree to which type conversions are restricted) and type safety. A language's type system may also be sound or unsound, nominal or structural, and may support features such as generics, algebraic data types, and type inference.
