Segment routing

In segment routing, the source encodes the path as an ordered list of segments carried in the packet header.

Segment routing is a form of source routing for computer networks, standardized by the IETF, in which the ingress node steers a packet through a network by encoding its path as an ordered list of instructions called segments, each identified by a Segment Identifier (SID). Intermediate nodes forward the packet according to the active segment without holding per-flow state, which simplifies the network core compared with older traffic-engineering approaches.

Architecture

A segment can represent a topological instruction (go to a particular node or along a particular link), a global prefix (reach this destination by the shortest path), or a service function. Interior gateway protocols such as OSPF and IS-IS are extended to advertise segment identifiers, so every node learns the label or address associated with each segment. Segment routing operates over two data planes: SR-MPLS, which carries segments as an MPLS label stack, and SRv6, which uses IPv6 addresses as SIDs and carries the segment list in a Segment Routing Header defined in RFC 8754.

Advantages

Segment routing supports traffic engineering and fast reroute — sub-50-millisecond protection against link and node failures — without the signalling overhead of RSVP-TE and without maintaining per-flow state in intermediate routers. A central controller using the Path Computation Element Protocol (PCEP) or BGP can compute and impose paths for software-defined networking. The technology is widely deployed by telecommunications carriers in 5G transport and IP backbone networks.

History

The architecture was described in RFC 8402 (2018), developed largely within the IETF SPRING working group, with major contributions from engineers at Cisco. It has become a principal successor technology to LDP and RSVP-TE in service-provider networks.
