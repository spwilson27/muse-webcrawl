Extreme programming

Extreme programming (XP) is an agile software development methodology that aims to produce higher-quality software and improve the quality of life of the development team. It takes widely accepted good practices — such as code review, testing and frequent releases — to "extreme" levels, on the theory that if a little is good, doing it continuously is better.

Origins

XP was developed by Kent Beck during the Chrysler Comprehensive Compensation System project, which began in 1996, and was set out in his 1999 book Extreme Programming Explained. Ward Cunningham and Ron Jeffries were also influential in its formulation. XP became one of the most prominent of the agile methods that fed into the Agile Manifesto of 2001.

Practices

The methodology's core practices include pair programming, in which two programmers work at one workstation; test-driven development, writing automated unit tests before the code they test; continuous integration, merging work many times a day; refactoring to improve design without changing behaviour; simple design; small, frequent releases planned with the customer using user stories; an on-site customer available to answer questions; common coding standards; collective code ownership; and a sustainable pace, avoiding chronic overtime. Beck organised the method around the values of communication, simplicity, feedback, courage and (in the second edition) respect.

Reception

XP strongly influenced subsequent agile practice: test-driven development, continuous integration and refactoring are now mainstream. Some XP practices, such as the on-site customer, proved harder to sustain and were adapted in methods like Scrum, which is often combined with XP's engineering practices.
