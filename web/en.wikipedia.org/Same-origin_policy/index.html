Same-origin policy


Image placeholder: Same-origin policy

In computing, the same-origin policy (SOP) is a fundamental security mechanism of the World Wide Web that restricts how a document or script loaded from one origin can interact with resources from another origin. An origin is defined by the combination of protocol (scheme), host and port of a URL. The policy was introduced by Netscape Navigator in the mid-1990s alongside JavaScript and is now implemented by all web browsers.

Mechanism

Under the policy, a script running in a page from one origin may access properties of another document only if both share the same origin. This prevents a malicious site from, for example, reading the contents of a user's webmail in another tab via the Document Object Model. The policy applies asymmetrically: embedding cross-origin resources (images, stylesheets, and scripts via <script> tags) is generally allowed, while reading them is restricted. XMLHttpRequest and the Fetch API are blocked from reading cross-origin responses unless the server grants permission.

Relaxation mechanisms

Cross-Origin Resource Sharing (CORS) allows servers to declare, via HTTP headers such as Access-Control-Allow-Origin, which origins may read their responses. Other historic workarounds include JSONP and setting document.domain to share access between subdomains. PostMessage provides a controlled channel for cross-origin communication between frames.
