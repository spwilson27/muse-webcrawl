Branching (version control)

Branching, in version control and software configuration management, is the duplication of an object under version control (such as a source code file or directory tree) so that modifications can occur in parallel along multiple branches.

The originating branch is sometimes called the parent branch, the upstream branch (or simply upstream if the branches are hierarchically related), or the backing stream. The child branches are called branches off the parent. A branch not referred to by a parent branch is called a trunk, mainline, or main branch.

In some distributed revision control systems, such as Mercurial and Git, there is a principal repository and many additional repositories, each of which can be considered a branch of the parent repository.

Motivation

Branches allow parts of software to be developed in parallel. Large and complex projects require multiple teams to develop different features and to fix bugs in the same code base concurrently. Branches support this by allowing developers to work in isolation without destabilising the main line of development. Branches are typically eventually merged back into a parent branch, frequently the main line, once the work on them is complete and accepted.

Common branching strategies

  • Feature branches — a new branch is created for each feature, then merged and deleted when the feature is finished.
  • Release branches — maintained to stabilise and patch a specific release while development continues on the trunk.
  • Trunk-based development — developers work on a single branch with very short-lived side branches, if any.
  • GitFlow — a widely used model with long-lived development and master branches plus supporting feature, release, and hotfix branches.

Merging

Merging reconciles the changes made on a branch with those on another. If the same lines of code were changed divergently, the version control system reports a merge conflict that a developer must resolve manually. Systems differ in how they represent and perform merges: distributed systems such as Git track a directed acyclic graph of commits, which records branch and merge history explicitly.
