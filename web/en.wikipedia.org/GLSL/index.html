OpenGL Shading Language

GLSL programs control the programmable stages of the OpenGL pipeline

The OpenGL Shading Language (GLSL) is a high-level shading language with a syntax based on the C programming language. It was created by the OpenGL ARB (OpenGL Architecture Review Board) to give developers more direct control of the graphics pipeline without having to use ARB assembly language or hardware-specific languages.

Features

GLSL shaders are small programs that run on the GPU. A typical program set includes a vertex shader, which processes each vertex and outputs its clip-space position, and a fragment shader, which computes the colour of each fragment (pixel candidate). Later versions added geometry, tessellation control and evaluation, and compute shaders. GLSL provides built-in vector and matrix types (vec2, vec3, vec4, mat4, and so on), swizzling, texture sampling functions, and qualifiers for inputs, outputs, and uniforms. It deliberately omits pointers, recursion, and dynamic memory allocation, fitting the massively parallel GPU execution model.

#version 330 core
layout(location = 0) in vec3 aPos;
uniform mat4 model;
uniform mat4 view;
uniform mat4 projection;
void main()
{
    gl_Position = projection * view * model * vec4(aPos, 1.0);
}

Versions and related languages

GLSL was introduced as an extension to OpenGL 1.4 and became core in OpenGL 2.0 (2004); its versions are numbered to track OpenGL versions (for example GLSL 4.60 accompanies OpenGL 4.6). GLSL ES is the variant used with OpenGL ES and WebGL on mobile and web platforms. With the arrival of Vulkan, shaders for that API are usually written in GLSL or HLSL and compiled offline to SPIR-V intermediate representation using tools such as glslangValidator.

See also: GDScript, another domain-specific language used in game development.
