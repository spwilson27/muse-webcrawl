Defensive programming

Defensive programming is a form of defensive design intended to ensure the continuing function of a piece of software under unforeseen circumstances. Defensive programming practices are often used where high availability, safety, or security is needed.

Defensive programming is an approach to improve software and source code, in terms of:

  • General quality — reducing the number of software bugs and problems
  • Making the source code comprehensible — the source code should be readable and understandable, so it is approved in a code audit
  • Making the software behave in a predictable manner despite unexpected inputs or user actions

Techniques

Common defensive programming techniques include validating all input data, checking preconditions and postconditions, using assertions, handling errors explicitly rather than ignoring them, and designing code so that it fails gracefully. Input validation is considered essential: data from external sources is never trusted, and is checked against criteria such as type, length, format, and range before use.

Defensive programming vs. normal practices

Overly defensive programming, however, can introduce its own problems: excessive checks can obscure the logic of a program, make code harder to maintain, and in some cases mask genuine bugs by silently substituting default values. Critics compare it to "defensive driving" taken to an extreme — constant checking of conditions that a well-designed system should be able to guarantee. A balanced approach validates data at system boundaries while trusting internal invariants that are enforced by design and verified by testing.

Secure programming

Defensive programming overlaps substantially with secure programming, the practice of writing software that resists malicious input. Many security vulnerabilities, such as buffer overflows and SQL injection, result from programs trusting input that an attacker controls. Techniques such as bounds checking, parameterized queries, and least-privilege design are hallmarks of both disciplines.
