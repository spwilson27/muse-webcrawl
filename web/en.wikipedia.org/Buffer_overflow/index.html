Buffer overflow

In computer security and programming, a buffer overflow, or buffer overrun, occurs when a program writes data to a buffer beyond the buffer's allocated boundary, overwriting adjacent memory locations. Buffers are areas of memory set aside to hold data; because languages such as C and C++ perform no automatic bounds checking, buggy code that copies input without verifying its length can corrupt data, crash the program, or be exploited to execute arbitrary code.

Exploitation

A classic stack-based buffer overflow overwrites the saved return address of a function with an address chosen by the attacker, redirecting execution to injected machine code (shellcode) stored in the buffer itself. The 1988 Morris worm used a buffer overflow in the Unix finger daemon as one of its propagation methods, and Elias Levy's 1996 article "Smashing the Stack for Fun and Profit" in Phrack popularized the technique. Heap-based overflows, format string vulnerabilities, and integer overflows are related classes of attack.

Protective countermeasures

Defenses include writing software in memory-safe languages or with bounds-checked libraries; compiler-inserted stack canaries that detect return-address corruption; marking memory non-executable (DEP/NX bit); address space layout randomization (ASLR); and control-flow integrity mechanisms. Operating systems and compilers such as GCC and Microsoft Visual C++ enable several of these by default, and return-oriented programming was developed in response to non-executable memory.
