Atomicity (database systems)

Atomicity
Field: Database systems
Part of: ACID (atomicity, consistency, isolation, durability)
Implementation: Write-ahead logging, shadow paging, rollback

In database systems, atomicity is one of the ACID transaction properties. An atomic transaction is an indivisible and irreducible series of database operations such that either all occur, or none occur. A guarantee of atomicity prevents updates to the database from occurring only partially, which can cause greater problems than rejecting the whole series outright.

Example

The canonical example is a bank transfer: money must be debited from one account and credited to another. If the system fails after the debit but before the credit, the money would vanish. Atomicity ensures the transfer either completes in full or is rolled back as if it never began.

Implementation

Database systems typically implement atomicity with a transaction log: changes are recorded in a write-ahead log before being applied, and on recovery after a crash, incomplete transactions are undone using the log. An alternative technique is shadow paging, in which modified pages are written to new locations and the database pointer is switched atomically when the transaction commits. In distributed databases, atomicity across nodes is provided by the atomic commit protocols, such as two-phase commit.
