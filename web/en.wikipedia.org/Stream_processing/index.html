Stream processing

Stream processing is a programming paradigm and a style of data processing in which data is treated as a continuous, potentially unbounded flow of records ("streams") that is processed incrementally as it arrives, rather than as finite batches stored before computation. Systems for event stream processing — such as Apache Kafka Streams, Apache Flink, Apache Spark Streaming and Amazon Kinesis — allow applications to analyse, transform, filter, aggregate and react to data in near real time, with low latency.

Concepts

A stream processing application is often modelled as a directed graph of operators that consume and produce streams of events. Because streams are unbounded, aggregations are typically computed over windows — for example tumbling, sliding or session windows based on event time or processing time. Handling late and out-of-order events, and providing fault tolerance through checkpointing and state snapshots, are central technical challenges. Semantics are commonly described as at-most-once, at-least-once or exactly-once processing.

Applications

Stream processing is used for real-time analytics and dashboards, fraud detection, monitoring and alerting, recommendation systems, data-pipeline (ETL) transformation, and processing of sensor and Internet-of-Things data. It contrasts with batch processing systems such as classic MapReduce, although modern architectures (for example the lambda and kappa architectures) combine or unify the two models.
