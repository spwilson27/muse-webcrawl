Code review

Code review (or peer code review) is a software quality assurance activity in which one or more programmers examine the source code written by another programmer, in order to find defects, improve code quality, share knowledge, and enforce coding standards. It is a form of static analysis performed by humans rather than automated tools.

Methods

Reviews take several forms. Formal inspection processes, pioneered by Michael Fagan at IBM in the 1970s, use defined roles and checklists. Modern lightweight review is usually tool-assisted: an author submits a change (often as a pull request or patch) and reviewers comment line by line, requesting changes before the code is merged. Other approaches include pair programming, in which review is continuous, walkthroughs, and over-the-shoulder review.

Benefits and evidence

Studies of inspection have found it to be among the most effective means of detecting defects, catching errors earlier and more cheaply than testing alone. Beyond defect detection, reviews spread knowledge of the codebase across a team, mentor junior developers, and produce code that is more consistent and maintainable. Effective review practice favours small changes, prompt turnaround, and a collegial tone.
