Metaprogramming

Metaprogramming is a programming technique in which computer programs have the ability to treat other programs as their data. It means that a program can be designed to read, generate, analyse or transform other programs, and even modify itself, while running.

Approaches

Metaprogramming is commonly divided into code generation at compile time (macros, template metaprogramming in C++, generics), runtime manipulation through reflection (inspecting and modifying objects, classes and methods dynamically, as in Ruby or Python), and external generation by separate programs such as parser generators and code generators. Lisp's hygienic and unhygienic macros are a classic example; Lisp code and data share the same representation (homoiconicity), making macro metaprogramming especially natural.

Advantages and drawbacks

Metaprogramming reduces boilerplate, enables domain-specific languages, and allows frameworks such as object-relational mappers and test libraries to adapt to user code. Its costs are complexity: heavily metaprogrammed code can be hard to read, debug and optimise, and runtime reflection can impose performance penalties.

Examples

Well-known uses include Ruby on Rails' dynamic finders and ActiveRecord associations, C++ template metaprogramming (which is Turing-complete), Java annotations processed at compile time, and the eval constructs of scripting languages.
