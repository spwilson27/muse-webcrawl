Count-distinct problem

FieldComputer science, streaming algorithms
Also known asCardinality estimation, F0 estimation
Key algorithmsFlajolet–Martin, HyperLogLog, MinCount

In computer science, the count-distinct problem is the problem of finding the number of distinct elements in a data stream that may contain repeated elements. It is also called cardinality estimation or F0 estimation (the zeroth frequency moment). Exact solutions require memory proportional to the number of distinct elements, so practical interest lies in randomised algorithms that give an approximate answer using very little memory.

Algorithms

Early work by Flajolet and Martin (1985) hashed each element and recorded the maximum number of trailing (or leading) zeros seen, estimating the cardinality as roughly 2 raised to that value, averaged over multiple hash functions. The LogLog and HyperLogLog algorithms refined this idea using harmonic means of many registers, achieving errors of a few percent with kilobytes of memory. Other approaches include MinCount (KMV), which keeps the k smallest hash values, and adaptive sampling.

Optimality

Theory shows that approximating the number of distinct elements within a factor (1 ± ε) requires space on the order of ε−2 plus logarithmic terms; refined bounds were established by Kane, Nelson, and Woodruff, whose algorithm is essentially optimal. A deterministic exact algorithm needs space linear in the stream's distinct count.

Applications

Cardinality estimation is used in database query optimisers, network monitoring (counting distinct flows or visitors), and large-scale web analytics, where systems such as Redis implement HyperLogLog natively.
