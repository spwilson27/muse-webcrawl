Software regression

From Wikipedia, the free encyclopedia


Regression testing aims to catch reintroduced defects

In software development, a software regression is a type of software bug where a feature that has worked before stops working. This may happen after changes are applied to the software's source code, including the addition of new features and bug fixes. Regressions often occur when a change breaks assumptions made by other parts of the system, or when a previously fixed bug reappears due to merging or refactoring errors.

Causes

Regressions can result from changes in the code itself, changes in configuration or data, upgrades to libraries, compilers, or operating environments, or unintended side effects of unrelated modifications. Because modern codebases are large and interconnected, a seemingly local change can affect behaviour far from the edited code.

Prevention and detection

Regression testing — re-running previously developed test cases after a change — is the principal defence. Automated unit, integration, and end-to-end tests run in continuous integration pipelines help detect regressions quickly. Techniques include test selection and prioritisation, bisection to locate the change that introduced the defect, and maintaining a regression test suite that grows as bugs are fixed.
