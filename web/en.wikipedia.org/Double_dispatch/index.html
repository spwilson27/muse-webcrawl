Double dispatch

Two polymorphic calls select behaviour based on two objects' types.

Double dispatch is a technique in object-oriented programming in which a method call is dispatched — its implementation selected at runtime — based on the runtime types of two objects rather than one. Most object-oriented languages provide single dispatch (the familiar virtual method call, chosen by the receiver's type). Operations whose behaviour depends on a pair of objects, such as computing the interaction between two shapes or two game entities, require double dispatch.

Implementation

The standard implementation uses the visitor pattern. The first object accepts a visitor and, from within its own method, calls back ("dispatches again") on the visitor with a method whose name encodes the first object's type; the visitor, itself chosen by type, then executes the correct pair-specific behaviour. In pseudo-code: shape.intersect(other) calls other.intersectWith(shape-as-typed).

Uses

Double dispatch appears in collision handling in games and simulations, arithmetic on mixed numeric types, stream and document formatting where behaviour depends on both element and output device, and adaptive interfaces. Languages with generic functions or multimethods, such as Common Lisp's CLOS, Julia, and Dylan, provide multiple dispatch directly, generalising double dispatch to any number of arguments.

Trade-offs

The visitor-based encoding introduces boilerplate and makes adding new types invasive, since every visitor must handle them — a form of the expression problem. Alternatives include lookup tables keyed on type pairs, reflection, and chained conditional tests.
