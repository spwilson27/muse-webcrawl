Deflate (stylised as DEFLATE) is a lossless data compression file format and algorithm that uses a combination of LZ77 and Huffman coding. It was designed by Phil Katz to replace the LZW compression used in his PKZIP archiving tool, in part to avoid the patent encumbrance on LZW, and it was later specified formally in RFC 1951 (May 1996).

Algorithm

DEFLATE first applies LZ77-style matching: sequences of bytes already seen within a sliding window of up to 32 KiB are replaced by references giving a length (3–258 bytes) and a backward distance. The resulting stream of literals and match references is then encoded with Huffman coding, using one of three block modes: stored (uncompressed), fixed Huffman codes defined by the specification, or dynamic Huffman codes transmitted with the block. Compressed data is processed as a series of blocks, each independently selectable by the encoder to balance speed and compression ratio.

Formats and implementations

The raw DEFLATE stream is wrapped by several widely used formats: the zlib format (RFC 1950), which adds a short header and an Adler-32 checksum, and the gzip format (RFC 1952), which adds file metadata and a CRC-32 checksum. DEFLATE is the compression method of ZIP archives, the PNG image format (via zlib), and HTTP content encoding, among many others. The reference implementation is the zlib library by Jean-loup Gailly and Mark Adler; decompress-only implementations are small enough to be embedded in boot loaders and firmware. Adler also maintains the single-file puff decoder, intended as an intelligible specification of the format.

Compression performance

DEFLATE compressors such as gzip and zopfli trade speed against ratio by adjusting match-search effort and block splitting. Although newer algorithms — including LZMA, bzip2's Burrows–Wheeler method, Brotli, and Zstandard — often achieve higher ratios, DEFLATE's universality, patent-free status, and speed keep it the default interchange format for compressed data on the web and in archives.
