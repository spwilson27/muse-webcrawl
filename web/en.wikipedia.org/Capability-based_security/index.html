Capability-based security

A capability as an unforgeable token designating an object and access rights (placeholder)

Capability-based security is a concept in the design of secure computing systems, based on the idea of a capability: an unforgeable token of authority that designates an object together with a set of access rights to it. A user program on a capability-based operating system must use a capability to access an object; possessing the capability is both necessary and sufficient proof of permission. This unifies designation (naming) with authorisation, in contrast to systems based on access control lists, where any program running with a user's ambient authority can access anything that user can.

Principles

Key properties of capability systems include:

  • Unforgeability — capabilities cannot be fabricated; they can only be created, copied, or restricted by those who already hold them (or by the kernel on their behalf).
  • Least authority — programs can be given exactly the capabilities they need and no more, following the principle of least privilege.
  • No ambient authority — a program cannot access resources merely because of who is running it; it must be handed the relevant capability.

Advocates argue that capabilities naturally solve the "confused deputy" problem, in which a privileged program is tricked into misusing its authority on behalf of an attacker.

History and implementations

The capability model dates to work by Dennis and Van Horn in 1966. Notable capability-based systems include the Cambridge CAP computer, Carnegie Mellon's Hydra, KeyKOS, EROS and its successors Coyotos and CapROS, and the seL4-based Genode framework. The Capsicum framework brought capabilities to FreeBSD. In programming languages, object-capability ("ocap") security appears in E, Joe-E, and parts of JavaScript (SES) and is central to the design of the Fuchsia operating system's component model and the WebAssembly component ecosystem.
