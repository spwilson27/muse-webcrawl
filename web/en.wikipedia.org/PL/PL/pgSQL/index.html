PL/pgSQL

PL/pgSQL (Procedural Language/PostgreSQL Structured Query Language) is a procedural programming language supported by the PostgreSQL relational database management system. It closely resembles Oracle's PL/SQL language. PL/pgSQL was designed by Jan Wieck and first appeared in PostgreSQL 6.4, released on October 30, 1998.

PL/pgSQL is the default procedural language for PostgreSQL and is installed by default in modern versions. It allows SQL queries and commands to be combined with procedural constructs — variables, conditional statements, loops, and exception handling — inside functions, procedures, triggers and DO blocks executed on the database server.

Design goals

  • Create functions and trigger procedures that perform complex computations and enforce business logic in the database
  • Bring computation closer to the data, reducing round trips between client and server
  • Reuse the server's SQL parser: individual SQL statements in a PL/pgSQL function are planned much like prepared statements

Structure

A PL/pgSQL function body is a block with an optional DECLARE section, a BEGIN ... END body, and an optional EXCEPTION section. SQL statements can be embedded directly; dynamic SQL is available through EXECUTE. Control structures include IF, CASE, LOOP, WHILE, FOR (over ranges or query results), RETURN and RETURN NEXT/QUERY for set-returning functions. Errors and notices are raised with RAISE, and GET DIAGNOSTICS exposes stack and status information.

Comparison

Compared with plain SQL functions, PL/pgSQL trades the optimiser's ability to inline function bodies for full procedural control. Other PostgreSQL procedural languages include PL/Perl, PL/Python and PL/Tcl; PL/pgSQL remains the most commonly used because it needs no external runtime and handles SQL natively.
