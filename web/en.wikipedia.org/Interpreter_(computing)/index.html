Interpreter (computing)

In computer science, an interpreter is a computer program that directly executes instructions written in a programming or scripting language, without previously compiling them into a machine language program. An interpreter generally uses one of the following strategies: parse the source code and perform its behaviour directly; translate source code into an efficient intermediate representation such as bytecode and execute that; or execute a precompiled stored representation.

Interpreters versus compilers

A compiler translates an entire program into machine code ahead of time, generally producing faster execution but requiring a separate build step. Interpreters start executing immediately and can evaluate code interactively (a "REPL"), which aids debugging and learning, but usually run more slowly because translation happens repeatedly at run time. Many modern language implementations blend the two approaches: for example, Java compiles to bytecode that is interpreted and then just-in-time (JIT) compiled, and CPython compiles source to bytecode before interpreting it.

History

Interpreted languages date back to early systems such as Lisp (1958), which pioneered interactive development. BASIC interpreters were central to home computing in the 1970s and 1980s, being built into the ROM of machines from vendors such as Commodore, Apple and Sinclair. Shell interpreters, and later languages such as Perl, Python, Ruby and JavaScript, made interpretation ubiquitous in system administration and web development.

Advantages and disadvantages

Interpreters offer platform independence of source code, rapid edit-run cycles, dynamic typing and reflection facilities, and easier debugging. Their drawbacks include slower execution, the need for the interpreter to be present on the target machine, and less up-front error checking than ahead-of-time compilation provides.
