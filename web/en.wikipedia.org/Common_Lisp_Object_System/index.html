Common Lisp Object System

ParadigmObject-oriented, multi-paradigm
Part ofANSI Common Lisp (standardized 1994)
InfluencesFlavors, LOOPS, Smalltalk
Key conceptsGeneric functions, multiple dispatch, metaobject protocol

The Common Lisp Object System (CLOS) is the object-oriented programming facility of the Common Lisp programming language. Standardized as part of ANSI Common Lisp in 1994, CLOS is notable for being built around generic functions and multiple dispatch rather than message passing, and for its powerful metaobject protocol (MOP), which allows programmers to customize the behavior of the object system itself.

A CLOS class hierarchy with multiple inheritance

Design

Classes are defined with defclass, specifying slots (instance variables) and superclasses; multiple inheritance is supported, with a class precedence list resolving conflicts. Behavior is defined not inside classes but in generic functions declared with defgeneric and specialized via defmethod. Unlike most object systems, methods can specialize on any or all of their required arguments — multiple dispatch — and method combination allows :before, :after, and :around methods to wrap a primary method.

Metaobject protocol

CLOS classes, generic functions, and methods are themselves objects (metaobjects), and the MOP — described in the book The Art of the Metaobject Protocol (1991) — specifies protocols by which programmers can redefine fundamental operations such as class instantiation, inheritance computation, and slot access. This makes CLOS one of the most extensible object systems ever standardized.

History and influence

CLOS synthesized earlier Lisp object systems, principally New Flavors and Xerox PARC's LOOPS. Its generic-function model influenced later languages and libraries, including Dylan, Julia's multiple dispatch, and aspects of R's S4 system and Python frameworks. Critics have noted that its power and flexibility can also produce programs that are difficult to reason about.
