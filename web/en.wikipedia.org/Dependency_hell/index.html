Dependency hell

Dependency hell is a colloquial term for the frustration of some software users who have installed software packages which have dependencies on specific versions of other software packages. The term describes a situation in which it is difficult or impossible to install, remove, or upgrade components because their version requirements conflict with one another.

Problems

Dependency hell can take several forms:

Long chains of dependencies: a package depends on another package, which depends on another, and so on, so installing one application pulls in a large tree of libraries. Conflicting dependencies: two packages require different, incompatible versions of the same shared library, so they cannot be installed together. Circular dependencies: packages indirectly depend on themselves. Diamond dependency: two components depend on different versions of a common library, and both versions cannot coexist at runtime.

Solutions

Operating systems and language ecosystems address dependency hell with package managers that perform automated dependency resolution, often using SAT solvers to find a compatible set of versions. Other approaches include bundling or vendoring dependencies with each application, containerization, static linking, versioning schemes such as semantic versioning, and allowing multiple versions of a library to be installed side by side.

Historically, the term was closely associated with "DLL hell" on Microsoft Windows, where conflicting shared dynamic-link libraries could break applications, and with "JAR hell" in Java environments.
