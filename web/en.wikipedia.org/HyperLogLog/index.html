HyperLogLog is an algorithm for the count-distinct problem, approximating the number of distinct elements in a multiset. It was published in 2007 by Philippe Flajolet and co-authors, refining the earlier LogLog algorithm of Marianne Durand and Flajolet (2003). Like other cardinality estimators, HyperLogLog trades exactness for a dramatic reduction in memory: it can estimate cardinalities well beyond 109 with a typical standard error of about 2% using only around 1.5 kilobytes of memory.

Principle

The algorithm hashes each item and observes the maximum number of leading zeros seen in hash values routed to a set of substreams (stochastic averaging). Rare patterns — a hash with many leading zeros — are evidence of a large number of distinct items. HyperLogLog improves on LogLog by using the harmonic mean of the substream maxima, which suppresses the influence of large outliers, and by applying bias corrections for small and large cardinalities.

Operations

HyperLogLog sketches are mergeable: the union of two sets is estimated by taking the register-wise maximum of their sketches, which makes the structure well suited to distributed systems and streaming databases. Implementations are built into systems such as Redis (the PFADD/PFCOUNT commands), PostgreSQL extensions, Apache Spark, and Google BigQuery's approximate count distinct functions. Extensions such as HyperLogLog++ (used by Google) refine the bias correction for small cardinalities.
