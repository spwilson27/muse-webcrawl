HATEOAS

HATEOAS: clients discover available actions by following hypermedia links in responses.

HATEOAS (Hypermedia as the Engine of Application State) is a constraint of the REST application architecture. It specifies that a client interacts with a network application largely through hypermedia provided dynamically by the server: the client needs no prior knowledge of the API beyond an initial entry point and an understanding of the media types, because each response contains links describing the actions currently available.

Concept

The idea, set out in Roy Fielding's 2000 doctoral dissertation that defined REST, is analogous to the human web: a user starts at a home page and follows links that the server presents in context, rather than constructing addresses from out-of-band documentation. In an API, a response representing, for example, a bank account may include links to deposit, withdraw, or transfer operations only when those operations are valid for the account's current state — so application state transitions are driven by the hypermedia itself.

Implementation

HATEOAS is realised through media types that support links and forms, such as HAL, JSON-LD with Hydra, Siren, and Collection+JSON; HTML itself is a hypermedia format. Advocates argue the approach decouples clients from server URL structures and workflows, making APIs more evolvable. Critics note that many real-world "REST" APIs omit hypermedia entirely, that link-following clients can be harder to build, and that adoption in commercial APIs has remained limited compared with fixed, documented endpoint designs.
