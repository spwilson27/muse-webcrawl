Version control

Version control (also known as revision control, source control, or source code management) is the management of changes to documents, computer programs, large web sites, and other collections of information. A system that implements version control is a version control system (VCS). Changes are usually identified by a number or letter code, termed a "revision", and each revision is associated with a timestamp and the person making the change. Revisions can be compared, restored, branched and merged — capabilities fundamental to modern collaborative software development.

History

Early tools such as SCCS (1972) and RCS (1982) managed individual files on a single machine. CVS (released 1990) popularised networked, repository-wide versioning, and Apache Subversion (2000) improved on it with atomic commits and versioned directories. In 2005, dissatisfied with existing tools for maintaining the Linux kernel, Linus Torvalds created Git, a distributed version control system in which every checkout contains the full history. Git, along with Mercurial (also 2005), became the dominant model, further popularised by hosting platforms such as GitHub, GitLab and Bitbucket.

Models

In a centralised system, a single server holds the definitive repository and users check out working copies. In a distributed system, each user's repository is a complete peer: commits are made locally and synchronised by pushing and pulling changesets. Distributed systems make branching and merging cheap and routine, enabling workflows such as feature branches and pull requests.

Terminology

Core concepts include the repository (the database of revisions), the working copy, a commit (a recorded snapshot with a message), a branch (a parallel line of development), a merge (combining branches, sometimes producing a conflict a human must resolve), and a tag (a named revision, often a release). Version control is also widely used outside programming, for documents, configuration, infrastructure-as-code and data.
