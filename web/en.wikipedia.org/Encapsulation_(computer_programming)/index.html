In object-oriented programming (OOP), encapsulation refers to the bundling of data with the methods that operate on that data, and the restriction of direct access to some of an object's components. Encapsulation is used to hide the internal representation, or state, of an object from the outside, a practice often called information hiding. It is one of the fundamental principles of OOP, alongside inheritance, polymorphism and abstraction.

Definition and rationale

Encapsulation allows a class's implementation to be changed without breaking code that depends on its public interface. By exposing only selected operations, the class can enforce invariants on its internal state: for example, a BankAccount class that keeps its balance in a private field and exposes deposit and withdraw methods can guarantee that the balance never becomes negative in an invalid way. This reduces coupling between components and improves maintainability of large systems.

// Java-like example
public class BankAccount {
    private double balance;          // hidden state
    public void deposit(double amt) { if (amt > 0) balance += amt; }
    public double getBalance()      { return balance; }
}

Access control

Most object-oriented languages provide access modifiers. Java and C# offer public, protected, package-private (or internal) and private levels; C++ adds friend declarations; Python relies on naming conventions (a leading underscore, and name mangling for double underscores) rather than enforced restrictions; Smalltalk makes all instance variables private by default. Properties, getters and setters are commonly used to mediate access while preserving encapsulation.

Encapsulation beyond OOP

The term is also used more generally in computing: in networking, encapsulation describes wrapping data in protocol headers as it passes down a protocol stack (as in the OSI model); in functional programming, closures and abstract data types achieve similar information hiding without classes.
