REST

REST (Representational State Transfer)
Field: Software architecture
Introduced: 2000, by Roy Fielding
Common use: Web APIs over HTTP

REST (Representational State Transfer) is an architectural style for distributed hypermedia systems, defined by Roy Fielding in his 2000 doctoral dissertation. A system conforming to the REST constraints is described as RESTful. REST principles underpin the design of most modern web APIs.

Constraints

Fielding's style is defined by six constraints: client–server separation, statelessness (each request contains all information needed to process it), cacheability, a uniform interface, a layered system, and — optionally — code on demand. The uniform interface centres on resources identified by URIs and manipulated through representations, typically JSON exchanged with standard HTTP methods: GET, POST, PUT, PATCH and DELETE.

RESTful APIs

In practice, "REST API" usually denotes a web service that exposes resources over HTTP with these conventions, as opposed to RPC-style or SOAP services. Maturity of such APIs is sometimes assessed with the Richardson Maturity Model, whose highest level adds hypermedia controls (HATEOAS). Alternatives and complements to REST include GraphQL and gRPC.
