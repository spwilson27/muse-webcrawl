Row (database)


One highlighted row of an employee table

In a relational database, a row — formally a tuple — is a single, implicitly structured data item in a table. A row represents one instance of the entity the table describes (for example, one employee or one order), and consists of a value for each of the table's columns.

In the relational model

In the formal relational model, a table corresponds to a relation, mathematically a set of tuples. Because a set has no duplicate members and no intrinsic ordering, a relation strictly cannot contain two identical rows, and rows have no meaningful sequence — although real SQL databases permit duplicate rows in tables without keys and impose order only when a query specifies it with an ORDER BY clause.

Working with rows

In SQL, rows are retrieved with SELECT, added with INSERT, changed with UPDATE and removed with DELETE. A primary key uniquely identifies each row, allowing other tables to reference it through foreign keys, and allowing individual records to be updated or joined unambiguously. Systems may also attach internal identifiers, such as Oracle's ROWID or PostgreSQL's ctid, to physical rows.

Storage

Most traditional database engines store data row-by-row: all values of one row are kept together on disk, which suits transactional workloads that read or write whole records. In contrast, column-oriented databases store each column separately and reconstruct rows at query time, favouring analytical queries that scan few columns over many rows.
