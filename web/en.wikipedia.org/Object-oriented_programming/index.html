Object-oriented programming

Object-oriented programming (OOP) is a programming paradigm based on the concept of objects, which bundle together data (in the form of fields or attributes) and code (in the form of procedures, or methods) that operates on that data. A distinguishing feature of OOP is that an object's own methods can access and modify its internal state. Programs are designed by making objects interact with one another, exchanging messages.

History

OOP was pioneered by Simula 67, developed in the 1960s by Ole-Johan Dahl and Kristen Nygaard in Norway for simulations; it introduced classes, objects, and inheritance. Alan Kay coined the term "object-oriented programming" in connection with Smalltalk, developed at Xerox PARC in the 1970s, which also popularised the graphical user interface. Bjarne Stroustrup's C++ (from 1979, released 1985) brought OOP to mainstream systems programming, and Java (1995), C#, and many other languages followed. By the 1990s OOP had become the dominant paradigm in commercial software development.

Core principles

  • Encapsulation — bundling data with the methods that operate on it and hiding internal representation behind a public interface.
  • Abstraction — modelling only the essential features of an object, suppressing irrelevant detail.
  • Inheritance — forming new classes (subclasses) from existing ones, inheriting attributes and behaviour and adding or overriding specifics.
  • Polymorphism — the ability for objects of different types to be used through a common interface, typically via subtype polymorphism and dynamic dispatch (virtual methods).

Classes and objects

In class-based languages, a class is a blueprint defining the state and behaviour shared by its instances; an object is an instance created from the class, usually via a constructor. Other languages, such as JavaScript and Self, use prototype-based inheritance, in which objects inherit directly from other objects. Associated modelling tools include UML class diagrams, and associated design knowledge is codified in design patterns (such as those catalogued by the "Gang of Four" in 1994: factory method, observer, singleton, and so on).

Criticism and alternatives

OOP has been criticised for emphasising data over algorithms, for fragile inheritance hierarchies and the "banana/gorilla/jungle problem" (getting more code than intended through reuse), and for modelling difficulties with cross-cutting concerns. Critics such as Joe Armstrong (creator of Erlang) and Richard Stallman voiced reservations; modern practice often mixes OOP with functional programming — immutability, higher-order functions, and composition over inheritance — and languages such as Scala, Kotlin, and Rust deliberately blend paradigms.
