The Elliptic Curve Digital Signature Algorithm (ECDSA) is a variant of the Digital Signature Algorithm (DSA) which uses elliptic-curve cryptography. It offers equivalent security to other signature schemes with significantly smaller key sizes, which makes it attractive for constrained environments and high-volume systems.

Key and signature generation

A signer's private key is a random integer d in the range of the curve group's order, and the public key is the point Q = dG. To sign a message, the signer hashes the message, selects a fresh random nonce k, computes the point kG, and derives the signature pair (r, s) from the point's x-coordinate and the hash. Verification uses the public key to check that a recomputed point matches the value implied by r.

Security considerations

The nonce k must be unique and unpredictable for every signature. Reusing k for two different messages reveals the private key by simple algebra — a failure famously exploited in the 2010 PlayStation 3 compromise, where Sony used a constant value. This risk motivated deterministic nonce generation (RFC 6979), which derives k from the private key and message hash.

ECDSA signatures are also malleable: if (r, s) is valid, so is (r, n − s). Bitcoin addressed this in transaction validation rules, and later systems such as BIP-62 and SegWit reduced its impact.

Applications

ECDSA is used to authorize transactions in Bitcoin and many other cryptocurrencies, typically over the secp256k1 curve. It is widely deployed in X.509 certificates for TLS, in SSH host and user keys, in smart cards, and in software code signing. Certicom's Scott Vanstone proposed the algorithm in 1992, and it was standardized by ANSI in 1999 and by NIST in FIPS 186.
