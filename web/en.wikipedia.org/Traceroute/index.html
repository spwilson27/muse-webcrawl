Traceroute

Traceroute is a computer network diagnostic command for displaying possible routes (paths) and measuring transit delays of packets across an Internet Protocol (IP) network. The history of the route is recorded as the round-trip times of the packets received from each successive host (remote node) in the route (path); the sum of the mean times in each hop is a measure of the total time taken to establish the connection.

Implementation

Traceroute works by sending packets with incrementally increasing time-to-live (TTL) values. Each router along the path decrements the TTL; when it reaches zero, the router returns an ICMP Time Exceed message, revealing its identity. On Unix-like systems the command is traceroute, typically using UDP datagrams; on Windows it is tracert, using ICMP echo requests. Modern variants include MTR, which combines traceroute with ping statistics, and Paris traceroute, which keeps a constant flow identifier to avoid load-balancer artifacts.

History

The traceroute program was written by Van Jacobson in 1987, prompted by suggestions from Steve Deering and implemented with help from C. Philip Wood, Tim Seaver, and Ken Adelman. It quickly became a standard tool for network operators diagnosing routing problems.

Usage

Network administrators use traceroute to identify where traffic is delayed or dropped, to detect routing loops, and to map the path packets take between two points on the Internet.
