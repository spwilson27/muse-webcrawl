Decompiler

A decompiler is a computer program that converts an executable or low-level program (such as machine code, assembly language, or bytecode) back into a higher-level programming language representation. It performs roughly the reverse operation of a compiler, though the output is rarely identical to the original source code, because compilation discards information such as comments, variable names, and program structure.

Process

Decompilation typically proceeds through several phases:

  1. Loading and disassembly — interpreting the binary format and translating machine code to assembly.
  2. Data-flow analysis — recovering expressions and variable usage from registers and stack operations.
  3. Control-flow structuring — rebuilding loops, conditionals, and other high-level constructs from jumps and branches.
  4. Type recovery and code generation — emitting readable source in a language such as C or Java.

Uses

Decompilers are used in software maintenance (recovering lost source code), interoperability, malware analysis and security research, and program understanding. Bytecode languages such as Java and .NET CIL decompile particularly well because their class files retain substantial metadata; well-known tools include JD and Fernflower for Java, ILSpy and dotPeek for .NET, and the multi-architecture platforms Ghidra and Hex-Rays (IDA Pro's decompiler) for native code.

Limitations and legality

Perfect decompilation is generally impossible: optimising compilers transform code in ways that cannot be uniquely inverted, and obfuscation deliberately frustrates analysis. The legality of decompilation varies by jurisdiction; it may be restricted by copyright law and licence terms, with exceptions in some places for interoperability (for example under the EU Software Directive).
