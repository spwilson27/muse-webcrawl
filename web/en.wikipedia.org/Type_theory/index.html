In mathematics, logic, and computer science, a type theory (also known as a type system) is a formal system in which every term has a "type". Type theory has origins in Bertrand Russell's response to the paradoxes of naive set theory, especially Russell's paradox, and was developed through works such as Russell's theory of types in Principia Mathematica (1910–1913) and Alonzo Church's simply typed lambda calculus (1940).

History

Russell's ramified theory of types stratified expressions into a hierarchy to block self-referential paradoxes. Church simplified and formalized the theory using lambda calculus. In the 1970s, Per Martin-Löf developed intuitionistic (dependent) type theory as a foundation for constructive mathematics, and Jean-Yves Girard and John Reynolds independently discovered System F (the polymorphic lambda calculus).

Core concepts

A type theory is presented by judgments, most basically the typing judgment Γ ⊢ t : T ("in context Γ, term t has type T"). Dependent type theories allow types to depend on terms, unifying propositions and types via the Curry–Howard correspondence, under which proofs are terms and propositions are types. In such systems, type checking can guarantee the correctness of proofs, which underlies proof assistants such as Coq, Lean, and Agda.

Relation to set theory and category theory

Type theory serves as an alternative foundation of mathematics to set theory; many type theories have categorical semantics, for example in locally cartesian closed categories. Homotopy type theory, developed in the 2000s by Vladimir Voevodsky and others, adds the univalence axiom and interprets types as homotopy types (spaces), opening connections between logic, topology, and computer science.

Applications in programming

Type systems in programming languages — from ML and Haskell to Java and Rust — are applied descendants of these theories. Features such as parametric polymorphism, algebraic data types, and type inference trace back to formal type-theoretic research.
