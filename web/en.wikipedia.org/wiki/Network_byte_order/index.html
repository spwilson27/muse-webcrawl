Network byte order

The term network byte order refers to the convention in the Internet protocol suite that multi-byte numeric values in protocol headers are transmitted most significant byte first — that is, in big-endian order. Because computer architectures store numbers in memory in different orders (little-endian on x86, big-endian on some other architectures), a single agreed convention is needed so that any two hosts can interpret data the same way.

In network byte order, the most significant byte is sent first.

Conversion functions

On Unix-like systems and Windows, the socket API provides the functions htons and htonl to convert 16-bit and 32-bit values from host byte order to network byte order, and ntohs and ntohl for the reverse direction. On machines that are already big-endian, these functions are no-ops. Header fields of IP, TCP, and UDP packets, along with many other Internet protocols, use network byte order.

History

The convention dates to the earliest ARPANET protocol specifications in the 1970s and was formalized in RFC 1700, "Assigned Numbers". The choice plausibly followed the convention used by IBM mainframes and the Xerox Networking Systems protocols. Danny Cohen's 1980 paper "On Holy Wars and a Plea for Peace" discusses the endian debate from which the terms big-endian and little-endian derive.
