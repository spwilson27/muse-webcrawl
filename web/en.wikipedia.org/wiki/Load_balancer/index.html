Load balancer

A load balancer is a device or software component that distributes network traffic or application requests across a group of servers (a server farm or pool) in order to improve responsiveness, reliability and capacity. By spreading work evenly, load balancing prevents any single server from becoming a bottleneck or a single point of failure, and allows systems to scale horizontally by adding more servers.

How it works

Clients connect to a single virtual address or hostname exposed by the load balancer. The balancer inspects each incoming request and forwards it to one of the available back-end servers according to a scheduling algorithm. Common algorithms include:

  • Round robin — requests are distributed in simple rotation.
  • Weighted round robin — servers receive traffic in proportion to assigned weights reflecting their capacity.
  • Least connections — the request goes to the server currently handling the fewest active sessions.
  • Least response time — combines connection count and observed latency.
  • IP hash / consistent hashing — a hash of the client address or request key selects the server, giving session affinity.

Load balancers perform health checks on back-end servers, automatically removing failed instances from the pool until they recover. Many also provide session persistence ("sticky sessions"), SSL/TLS termination, connection multiplexing, content caching and request rewriting.

Layer 4 and layer 7

Load balancers are often classified by the OSI layer at which they operate. Layer 4 (transport-layer) balancers route packets based on IP addresses and TCP/UDP ports without inspecting application content, and are fast and simple. Layer 7 (application-layer) balancers understand protocols such as HTTP and can route based on URLs, headers, cookies or message content, enabling features such as content-based routing and web application firewall integration.

Implementations

Load balancing is delivered in several forms: dedicated hardware appliances (historically dominated by vendors such as F5 Networks), software balancers such as HAProxy, nginx and Envoy, and cloud services such as AWS Elastic Load Balancing, Azure Load Balancer and Google Cloud Load Balancing. DNS-based distribution — publishing several IP addresses for one hostname — is a simpler, coarser form of load balancing.

Related concepts

Load balancing is closely related to reverse proxies, content delivery networks (CDNs) and global server load balancing (GSLB), which distributes traffic between geographically dispersed data centres. In distributed systems, similar algorithms appear in client-side balancing within microservice architectures, where a service registry supplies the list of healthy instances.
