Rule of three (computer programming)

The rule of three is a rule of thumb in C++ (prior to C++11 it was known in similar form as the Law of The Big Three) that claims that if a class defines any of the following, it should probably explicitly define all three:

  • destructor
  • copy constructor
  • copy assignment operator

These three functions are special member functions automatically generated by the compiler if not declared by the programmer. If one of these had to be defined by the programmer, it usually means the class manages a resource (such as dynamically allocated memory or a file handle), and the compiler-generated versions — which perform shallow copies — will be inappropriate for the others.

Rule of five

With the introduction of move semantics in C++11, the rule of three has been extended to the rule of five, adding the move constructor and move assignment operator. If a class declares any of the five special member functions, the others should be considered as well.

Rule of zero

The rule of zero recommends designing classes so that they need none of the five special member functions, delegating resource management to dedicated RAII classes (such as smart pointers and containers), so that the compiler-generated versions are correct by construction.
