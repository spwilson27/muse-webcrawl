Command-line interface

A command-line interface (CLI) is a means of interacting with software via commands in the form of successive lines of text (command lines). Command-line interfaces emerged in the mid-1960s, on computer terminals, as an interactive and more user-friendly alternative to the non-interactive interface available with punched cards. Today most users interact through graphical user interfaces (GUIs), but CLIs remain standard for system administration, software development, and automation.

How it works

A CLI is driven by a program called a command-line interpreter or shell, which displays a prompt, reads a line of typed input, parses it into a program name plus arguments and options (flags), executes it, and prints the output. Unix shells include the Bourne shell, Bash, and zsh; Windows provides Command Prompt and PowerShell. CLIs offer features such as piping (chaining programs via |), redirection of input/output, wildcards (globbing), variables, and scripting, allowing complex tasks to be automated as shell scripts.

Advantages and disadvantages

  • Advantages: precision, scriptability and reproducibility, low resource use, remote administration over SSH, and composability of small tools (the Unix philosophy).
  • Disadvantages: steep learning curve, need to memorise commands and syntax, and poor discoverability compared with menus.

History

Teleprinters connected to early time-sharing systems (CTSS, Multics, then Unix) established the text-command model. MS-DOS popularised the CLI on personal computers in the 1980s; GUIs displaced it for general users in the 1990s, but developer culture revived CLI tools in the 2000s–2010s (package managers, version control via Git, cloud CLIs, containers), and terminal interfaces remain ubiquitous in professional computing.
