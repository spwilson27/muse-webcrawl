Memory-mapped I/O

Memory-mapped I/O
Same address bus used for memory and I/O devices.

Memory-mapped I/O (MMIO) is a method of performing input/output between the central processing unit and peripheral devices in a computer. It uses the same address bus to address both memory and I/O devices: the memory and registers of the I/O devices are mapped to (associated with) address values in the processor's address space, so ordinary memory load and store instructions can read and write device registers.

Overview

When a device is mapped, a range of physical addresses is decoded by the system's interconnect as belonging to the device rather than to RAM. Writing to a mapped control register might start a DMA transfer or send a byte out of a serial port; reading a mapped status register reports the device's state. Because devices are accessed with normal instructions, any addressing mode usable for memory is available for I/O, simplifying code compared with architectures that provide special I/O instructions.

Comparison with port-mapped I/O

The alternative, port-mapped I/O (PMIO), used extensively on the x86 architecture, places devices in a separate I/O address space reachable only through dedicated IN and OUT instructions. MMIO consumes part of the memory map — historically creating constraints such as the "640 KB barrier" and the PCI hole below 4 GB — but avoids a second address space and is used almost exclusively in RISC and embedded architectures such as ARM and RISC-V.

Practical concerns

Device accesses must not be cached, reordered, or optimized away by the compiler or CPU, so operating systems map MMIO regions as uncacheable and device drivers use volatile accesses, accessor functions (such as readl/writel in Linux), and memory barriers. With virtual memory, the kernel maps device physical addresses into its own address space, and user programs may access devices through facilities such as /dev/mem or UIO.
