Interrupt

In digital computers, an interrupt (sometimes referred to as a trap) is a request for the processor to interrupt currently executing code (when permitted), so that the event can be processed in a timely manner. If the request is accepted, the processor will suspend its current activities, save its state, and execute a function called an interrupt handler (or an interrupt service routine, ISR) to deal with the event.

Types

Hardware interrupts are signalled by peripheral devices — keyboards, timers, disk controllers and network cards — to indicate that they need attention, for example when a key has been pressed or a DMA transfer has completed. Software interrupts are caused by executing a special instruction and are used to request operating system services (system calls). Exceptions are generated by the processor itself in response to conditions such as division by zero, page faults or invalid opcodes.

Handling

When an interrupt occurs, the processor typically saves the program counter and registers on the stack, looks up the handler address in an interrupt vector table, and transfers control. Handlers are kept short because interrupts may be disabled or lower-priority interrupts masked while they run; operating systems often split handling into a minimal "top half" that acknowledges the device and a deferred "bottom half" that does the remaining work. Interrupt controllers such as the APIC prioritise, route and mask interrupt lines, and support message-signalled interrupts (MSI) in modern PCIe systems.

Uses

Interrupts free the processor from polling devices, enabling responsive multitasking: timer interrupts drive process scheduling, keyboard and mouse interrupts deliver input, and network interrupts signal packet arrival. In embedded and real-time systems, predictable interrupt latency is a key design requirement.
