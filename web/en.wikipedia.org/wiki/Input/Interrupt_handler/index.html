Interrupt handler
Also called an interrupt service routine (ISR).

In computer systems programming, an interrupt handler, also known as an interrupt service routine (ISR), is a special block of code associated with a specific interrupt condition. Interrupt handlers are initiated by hardware interrupts, software interrupt instructions, or software exceptions, and are used for dealing with high-priority, low-latency events such as input from peripheral devices.

Operation

When a device requires attention it asserts an interrupt request. The processor suspends the currently executing program, saves enough of its state (typically the program counter and status registers) to resume it later, and transfers control to the handler registered for that interrupt vector. The handler performs the urgent work — for example, reading a character from a keyboard controller or acknowledging a timer tick — then issues an end-of-interrupt signal and returns, allowing the interrupted program to continue. Interrupt handlers are usually kept short, deferring longer processing to ordinary threads or "bottom half" mechanisms such as softirqs and tasklets in Linux or deferred procedure calls in Windows.

Interrupt context

Code running in interrupt context faces restrictions: it generally cannot sleep or block, may not access user-space memory directly, and must be careful about locking, since it can preempt almost any other code. Nested interrupts and interrupt priorities allow more urgent events to preempt less urgent handlers. Reentrancy and race conditions with the interrupted code are central design concerns.

First-level and second-level handlers

Many systems split handling into a fast first-level interrupt handler (FLIH), which does the minimal time-critical work, and second-level handlers that perform the bulk of the processing later, at lower priority. This division bounds interrupt latency while keeping total throughput high.
