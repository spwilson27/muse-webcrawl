Kernel (operating system)

From Wikipedia, the free encyclopedia


The kernel connects application software to the computer hardware.

A kernel is a computer program at the core of a computer's operating system that always has complete control of the system. It is the portion of the operating-system code that is always resident in memory and facilitates interactions between hardware and software components. The kernel manages the system's resources, performs process scheduling and memory management, and provides controlled access to devices through device drivers and system calls.

Functions

The kernel's principal duties are process management (creating, scheduling, and terminating processes and threads), memory management (virtual memory, paging, and protection between address spaces), device management (through drivers and interrupt handling), and system call handling, which gives user programs a safe interface to request services. Many kernels also incorporate file systems, networking stacks, and inter-process communication facilities.

Design approaches

Monolithic kernels

In a monolithic design, all operating-system services run together in kernel space, sharing one address space. This gives high performance but means a fault in any component can crash the whole system. Unix and Linux are prominent examples; Linux mitigates rigidity with loadable kernel modules.

Microkernels

A microkernel provides only minimal mechanisms — address spaces, threads, and inter-process communication — in privileged mode, running services such as drivers and file systems as user-space servers. This improves modularity and fault isolation at some cost in communication overhead. Examples include Mach, the L4 family, MINIX 3, and QNX.

Hybrid kernels

Hybrid designs, such as the Windows NT kernel and Apple's XNU (which combines Mach with BSD components), place some traditionally user-space services in the kernel for performance while retaining a modular structure.

Protection

Kernels execute in the processor's most privileged mode (kernel mode, ring 0 on x86), separated from user mode by hardware enforcement. A crash or "panic" in kernel space is unrecoverable without reboot, which is why kernels are written conservatively and subjected to heavy review. Modern systems add mitigations — address-space layout randomisation, stack canaries, and control-flow integrity — to harden this critical layer.

History

Early systems had resident monitors; the concept matured with multiprogramming systems of the 1960s such as OS/360 and Multics, and Brinch Hansen's RC 4000 nucleus (1969) is an early statement of the microkernel idea. The Tanenbaum–Torvalds debate of 1992 famously aired the monolithic-versus-microkernel argument as Linux was beginning.
