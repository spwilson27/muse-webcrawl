Input validation

Input validation is the process of checking data provided to a program or system — by users, other programs, files, or networks — to ensure it conforms to expected type, length, format, and range before it is processed. Proper validation is both a correctness measure and a fundamental security defence: many common attacks, including SQL injection, cross-site scripting, and buffer overflows, exploit applications that trust unvalidated input.

Approaches

Validation may be syntactic (does the value have the right form — e.g., a date, a number, an allowed length?) or semantic (is it meaningful in context — e.g., a delivery date not in the past?). Two strategies are allowlisting, which accepts only input matching known-good patterns and is generally preferred, and blocklisting, which rejects known-bad patterns and is prone to bypasses. Validation should generally be performed on the server side even when client-side checks exist for usability, because attackers can bypass the client.

Related techniques

Where data must be accepted in flexible form, related defences include parameterised queries, output encoding, and sanitisation. Robust systems also enforce constraints as close to the data's entry point as possible and fail safely when validation fails, rejecting the input rather than attempting to repair it silently.
