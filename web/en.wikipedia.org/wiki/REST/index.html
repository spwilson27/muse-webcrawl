REST

Representational state transfer (REST) is a software architectural style that was created to guide the design and development of the architecture for the World Wide Web. REST defines a set of constraints for how the architecture of a distributed, Internet-scale hypermedia system, such as the Web, should behave. Systems that honour these constraints are often described as RESTful.

The style was introduced by Roy Fielding in his 2000 doctoral dissertation at the University of California, Irvine, where he described the architecture underlying HTTP. REST has since become the dominant design model for web APIs.

Constraints

  • Client–server — separation of concerns between the user interface and data storage.
  • Stateless — each request contains all the information needed to understand it; the server stores no client session state.
  • Cacheable — responses may be labelled cacheable to improve performance.
  • Uniform interface — resources are identified in requests (typically by URIs), manipulated through representations, with self-descriptive messages and hypermedia as the engine of application state (HATEOAS).
  • Layered system — intermediaries such as proxies and load balancers may sit between client and server.
  • Code on demand (optional) — servers may extend client functionality by transferring executable code.

RESTful APIs

In practice, most "REST APIs" use HTTP methods (GET, POST, PUT, PATCH, DELETE) against resource URIs, exchanging representations in JSON or XML. Richardson's maturity model grades APIs from plain HTTP tunnelling (level 0) through resources (level 1) and HTTP verbs (level 2) to hypermedia controls (level 3).
