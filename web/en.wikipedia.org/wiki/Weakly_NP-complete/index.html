Weakly NP-complete

In computational complexity theory, an NP-complete problem is called weakly NP-complete if it can be solved in pseudo-polynomial time: that is, by an algorithm whose running time is polynomial in the numeric values of the input, though possibly exponential in the number of bits used to represent those values. By contrast, a strongly NP-complete problem remains NP-complete even when its numbers are bounded by a polynomial in the input size.

Examples

The classic example of a weakly NP-complete problem is the knapsack problem: although no algorithm polynomial in the input length is known, dynamic programming solves it in time proportional to the number of items multiplied by the knapsack capacity, which is polynomial in the numeric value of the capacity. Other weakly NP-complete problems include the subset sum problem, the partition problem, bin packing, and scheduling problems such as minimizing makespan on identical machines.

Relationship to strong NP-completeness

If a problem is strongly NP-complete, then (unless P = NP) it admits neither a pseudo-polynomial time algorithm nor a fully polynomial-time approximation scheme. Weakly NP-complete problems, on the other hand, often do admit fully polynomial-time approximation schemes, precisely because their pseudo-polynomial algorithms can be combined with scaling and rounding techniques. The traveling salesman problem and the Hamiltonian path problem are examples of strongly NP-complete problems.
