Dynamic dispatch

Dynamic dispatch selects the method implementation based on the object's runtime type.

Dynamic dispatch is the process in computer programming of selecting which implementation of a polymorphic operation (method or function) to call at run time, based on the actual type of the object on which it is invoked. It is the mechanism that allows a single call site to trigger different behaviour for different subclasses, and it is central to object-oriented programming.

Single and multiple dispatch

Single dispatch, used by most object-oriented languages, chooses the method according to the type of one special argument—the receiver (often this or self). Multiple dispatch, found in languages such as Julia, Common Lisp (CLOS) and Dylan, considers the types of several arguments, so a generic function can have methods specialised on combinations of argument types.

Implementation

In languages like C++ and Java, single dispatch is typically implemented with a virtual method table (vtable): each object carries a pointer to a table of function pointers for its class, and a virtual call indexes into the table—an overhead of a few instructions over a direct call. Dynamically typed languages such as Smalltalk, Objective-C and Ruby instead perform a method lookup in the receiver's class (and its superclasses) at call time, usually cached for speed. Static dispatch, by contrast, resolves the call entirely at compile time, as with non-virtual functions or generic templates.
