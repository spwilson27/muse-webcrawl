SIGBUS

SIGBUS is a signal in computer programming, sent by an operating system to a process when it causes a bus error. On POSIX systems, SIGBUS is typically generated when a process attempts a memory access that the hardware cannot complete — for example, accessing a memory-mapped file beyond its end, or performing an unaligned memory access on an architecture that requires alignment.

The symbolic constant for SIGBUS is defined in the header file signal.h. Its signal number varies across platforms; on Linux on x86-64 it is 7. The name is an abbreviation of "bus error".

Causes

Common causes of a bus error include:

  • Accessing beyond the end of a memory-mapped file — for example, using mmap on a file and reading or writing past the region backed by the file's size.
  • Unaligned access — attempting to read or write a multi-byte value at an address not aligned to its size, on architectures (such as SPARC and some ARM configurations) that require natural alignment.
  • Accessing a hole in a truncated file or device mapping that has been shrunk after mapping.

Comparison with SIGSEGV

SIGBUS is often confused with SIGSEGV (segmentation fault). Generally, SIGSEGV is raised when a process accesses a virtual address that has no valid mapping at all, whereas SIGBUS is raised when the address is mapped but the access cannot be physically completed or violates architectural constraints such as alignment.

Handling

Like other signals, SIGBUS can be caught with a handler installed via sigaction, although recovery is often impractical. By default, the process is terminated and a core dump is produced, allowing the failure to be debugged post-mortem.
