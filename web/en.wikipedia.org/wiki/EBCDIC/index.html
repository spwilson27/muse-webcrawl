EBCDIC

From Wikipedia, the free encyclopedia

EBCDIC descends from the codes used on punched cards.

Extended Binary Coded Decimal Interchange Code (EBCDIC) is an eight-bit character encoding used mainly on IBM mainframe and midrange computer systems. IBM introduced it in 1963–1964 with the System/360 line, deriving it from the six-bit binary-coded decimal (BCD) codes used on earlier IBM machines and punched-card equipment.

Characteristics

Unlike ASCII, which was standardised in the same period, EBCDIC places the letters of the alphabet non-contiguously: the code values for A–I, J–R and S–Z occupy three separate blocks, a legacy of its punched-card origins. Digits 0–9 are encoded as F0–F9 in hexadecimal, the high nibble F reflecting the "zone" punches of card code. There is no single EBCDIC: IBM defined many code pages (such as CCSID 037 for US/Canada and CCSID 500 for international use) differing in their placement of punctuation and national characters, which historically made data exchange between EBCDIC systems — let alone with ASCII systems — error-prone.

Use and legacy

EBCDIC remains in use on IBM Z mainframes running z/OS and on IBM i systems, where enormous quantities of legacy business data and COBOL and RPG applications depend on it. Conversion tables between EBCDIC code pages and ASCII/Unicode are built into operating systems, file-transfer tools and terminal emulators. Programmers from the ASCII world often regard EBCDIC quirks — non-contiguous letters breaking simple range checks, and dozens of incompatible code pages — as a notorious legacy burden; a well-known joke expansion is "Even Bad Codes Do Instruct Computers".
