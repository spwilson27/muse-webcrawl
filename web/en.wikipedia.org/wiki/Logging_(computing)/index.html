In computing, logging is the act of keeping a log: a record of events that occur in a computer system, such as problems, errors or information about current operations. These events may occur in the operating system, in software, or over a communications network. A log message commonly consists of a timestamp, a severity level, a component identifier and a description of the event. Logs are typically written to files, a system journal, or transmitted to a remote logging server for aggregation and analysis.

Purposes

  • Debugging and problem diagnosis — reconstructing the state of a program before a failure
  • Security — recording authentication attempts, access and administrative actions for intrusion detection and forensics
  • Auditing and compliance — demonstrating who did what, when, in regulated industries
  • Operations — health monitoring, alerting, and capacity planning
  • Analytics — web server access logs underpin traffic measurement

Severity levels and facilities

The syslog standard (RFC 5424) defines eight severity levels, from Emergency (system unusable) down to Debug. Application frameworks such as Log4j, java.util.logging, Python's logging module and Microsoft's Event Tracing use comparable scales (FATAL, ERROR, WARN, INFO, DEBUG, TRACE) and let developers route messages by level and logger name to appenders (files, consoles, sockets, databases). Log rotation utilities such as logrotate archive and discard old files so logs do not exhaust disk space.

Analysis and aggregation

In distributed systems, logs from many machines are shipped to central platforms (for example the ELK/Elasticsearch–Logstash–Kibana stack, Splunk, or cloud logging services) where they are indexed and queried. Structured logging — emitting entries as JSON with consistent fields rather than free text — makes automated parsing and correlation across services far more reliable. Log management overlaps with metrics and tracing in the discipline of observability, and with security information and event management (SIEM) in security operations.

Challenges

Excessive logging can degrade performance and bury important events in noise; insufficient logging hampers incident response. Logs may contain sensitive data (credentials, personal information), making retention, access control and redaction important governance concerns.
