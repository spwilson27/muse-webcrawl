Rolling hash


Type: Hash function
Key property: O(1) update when the window slides
Applications: Pattern matching, data deduplication, rsync

A rolling hash (also known as a recursive hashing or rolling checksum) is a hash function where the input is hashed in a window that moves through the input. A few sequences of output values are easy to compute — in particular, the hash of the next window can be computed from the hash of the previous window in constant time, by removing the contribution of the character that leaves the window and adding the contribution of the character that enters it.

Polynomial rolling hash

The Rabin–Karp string search algorithm uses a polynomial hash: a window of length k over an alphabet is treated as a number in some base B, usually reduced modulo a large prime. Dropping the leading character requires subtracting its weighted value and multiplying the remainder by B before adding the new trailing character — all constant-time operations. When window hashes match the pattern hash, the algorithm verifies the candidate match character by character to rule out collisions.

Content-defined chunking

Rolling hashes are central to data deduplication. In the rsync algorithm, a weak rolling checksum (based on Adler-32) quickly identifies blocks of a file that match blocks of an older version, so only differences need to be transferred. In backup and storage systems, a rolling hash such as Buzhash or the Rabin fingerprint is used for content-defined chunking: a chunk boundary is declared whenever the hash of a sliding window satisfies a condition (for example, its low bits are all zero), so chunk boundaries follow the content and resist shifting when bytes are inserted or deleted.

Examples

  • Rabin–Karp — polynomial rolling hash for substring search.
  • Buzhash — based on a table of random values XORed and rotated as the window slides.
  • Adler-32 — used as the rolling checksum in rsync.
  • Gear hash — a fast rolling hash used in modern chunking research.
