WebSocket

StandardRFC 6455
Developed byIETF
Introduced2011

WebSocket is a computer communications protocol, providing simultaneous two-way communication channels over a single TCP connection. The WebSocket protocol was standardized by the IETF as RFC 6455 in 2011. The HTTP-compatible handshake is designed to allow web servers to use the standard HTTP ports 80 and 443 and to support existing HTTP proxies and intermediaries.

WebSocket is distinct from HTTP in that, after the initial upgrade handshake, the connection stays open and both client and server can send messages at any time, enabling low-latency, real-time applications such as chat, live feeds, and multiplayer games without repeated polling.

Protocol

Handshake

The client initiates the connection with an HTTP GET request carrying an Upgrade: websocket header, a Sec-WebSocket-Key, and a requested protocol version. The server replies with status 101 Switching Protocols and a Sec-WebSocket-Accept value derived from the key and a fixed GUID.

Data frames

Messages are exchanged as frames with a small header indicating whether the frame is text (UTF-8) or binary, whether it is the final fragment, and a payload length. Client-to-server frames must be masked. Control frames handle ping, pong, and connection close.

WebSocket API

The WHATWG WebSocket API, implemented in all major browsers, exposes a WebSocket object in JavaScript with methods such as send() and close() and events including open, message, error, and close.

Security

Encrypted connections use the wss:// scheme over TLS. Because the protocol allows arbitrary cross-origin connections, servers should validate the Origin header and use tickets or tokens rather than ambient cookies to defend against cross-site WebSocket hijacking.
