The Cathedral and the Bazaar: Musings on Linux and Open Source by an Accidental Revolutionary is an essay, and later a book, by Eric S. Raymond on software engineering methods, based on his observations of the Linux kernel development process and his experiences managing the open-source project fetchmail. First presented at the Linux Kongress in 1997 and published as a book in 1999, it contrasts two models of free software development.

The two models

In the Cathedral model, source code is available with each release, but code developed between releases is restricted to an exclusive group of developers, as with the GNU Emacs and GCC projects of the time. In the Bazaar model, which Raymond attributes to Linus Torvalds, code is developed over the Internet in view of the public: release early, release often, delegate everything you can, and treat users as co-developers.

Lessons and Linus's Law

The essay draws nineteen lessons from the fetchmail experience. Its best-known formulation is Linus's Law: "Given enough eyeballs, all bugs are shallow." Raymond argues that treating users as co-developers is the most effective route to rapid code improvement and effective debugging, and that the bazaar style — often assumed to be chaotic — can be more productive than cathedral-style planning.

Influence

The essay is widely credited with persuading Netscape Communications to release the source code of Netscape Communicator in 1998, which led to the Mozilla project. It became a foundational text of the open-source movement and a standard reference in discussions of collaborative development, sometimes discussed alongside philosophical works on distributed cognition such as The Extended Mind. The book collects related essays including "A Brief History of Hackerdom", "The Magic Cauldron", and "Revenge of the Hackers".
