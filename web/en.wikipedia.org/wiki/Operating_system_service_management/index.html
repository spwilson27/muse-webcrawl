Operating system service management

OS service management

Examplessystemd, launchd, Windows Service Control Manager, init
FunctionsStarting, stopping, supervision, logging

In computing, operating system service management is the administration of long-running background processes — services or daemons — by the operating system. A service manager starts services at boot, stops them at shutdown, restarts them if they fail, and provides tools to inspect and control them.

Implementations

Traditional Unix systems used System V init scripts and runlevels; modern Linux distributions largely use systemd, which manages "units" with dependency ordering, socket activation, and integrated logging (journald). macOS uses launchd, which starts daemons on demand from property-list definitions. On Windows, the Service Control Manager maintains the registry of services, their start types (automatic, manual, disabled), and recovery actions.

Common tasks

Administrators enable or disable services, inspect status and logs, and define restart policies and resource limits. Good service management is central to reliability: it determines boot order, failure handling, and how a machine recovers from crashes.
