Serverless functions run on demand, triggered by events, with infrastructure managed by the provider.

Serverless computing is a cloud computing execution model in which the cloud provider dynamically manages the allocation and provisioning of servers. Despite the name, servers still exist; developers simply do not provision, scale, patch, or administer them, and pricing is based on the actual amount of resources consumed by an application rather than on pre-purchased capacity.

Models

The term covers two related approaches. In function as a service (FaaS), developers deploy discrete functions that run in stateless, event-driven containers, spun up on demand and scaled automatically; the paradigm was popularised by AWS Lambda, launched in 2014. Backend as a service (BaaS) refers to applications built substantially on third-party managed services—authentication, databases, storage, and messaging—that handle server-side logic and state.

Advantages and drawbacks

Advantages include the elimination of server administration, automatic scaling from zero to large loads, and cost efficiency for spiky or low-volume workloads, since idle time is not billed. Drawbacks include cold start latency when a function is invoked after inactivity, execution time limits, constrained local state and storage (functions are ephemeral and stateless), reduced observability and debugging challenges, potential vendor lock-in, and unpredictability of cost at very high sustained volumes, where conventional servers can be cheaper.

Use cases

Common applications include web APIs and microservices, stream and file processing (e.g. image transformation when a file is uploaded), scheduled jobs, chatbots, IoT back ends, and glue logic between other cloud services. Frameworks such as the Serverless Framework, AWS SAM, and Knative (for Kubernetes) support building and portable deployment of serverless applications.
