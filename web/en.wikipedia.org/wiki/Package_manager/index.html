A package manager or package-management system is a collection of software tools that automates the process of installing, upgrading, configuring, and removing computer programs for a computer in a consistent manner. It typically maintains a database of software dependencies and version information to prevent software mismatches and missing prerequisites, and works with software archives or "repositories" from which packages can be downloaded and installed.

Functions

Packages contain the software itself plus metadata: a description, version number, checksums and signatures for verification, and a list of dependencies on other packages or libraries. When a user asks to install a program, the package manager solves the dependency graph — selecting compatible versions of everything required — downloads and verifies the packages, runs installation scripts, and records the result so the whole system can later be upgraded or audited in one operation. Advanced package managers use SAT solvers or similar algorithms for optimal dependency resolution; package managers are distinguished from simple installers by this system-wide, dependency-aware operation.

Kinds of package managers

Operating-system package managers manage the whole software stack of a machine: Debian's dpkg/APT (.deb), Red Hat's RPM/DNF (.rpm), Arch's pacman, FreeBSD's ports and pkg, macOS's third-party Homebrew, and Windows tools such as winget and Chocolatey. Language-ecosystem package managers handle libraries and tools for a programming language, generally at project level: npm and Yarn for JavaScript, pip and Poetry for Python, Cargo for Rust, Maven and Gradle for Java, NuGet for .NET and RubyGems for Ruby. Application-level stores (mobile app stores, Steam, Flatpak, Snap) apply the same ideas with sandboxing and curated catalogs.

History

The concept developed with Unix software distribution and became central to Linux distributions in the mid-1990s, when Red Hat's RPM (1995) and Debian's APT (1998) first made dependency-aware, one-command system installation and upgrading routine. The model proved so successful that it was adopted for programming libraries (CPAN for Perl predates most) and eventually became the dominant way software is distributed on nearly every platform.
