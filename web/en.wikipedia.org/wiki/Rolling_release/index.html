Rolling release


Model: Continuous delivery of updates
Contrasts with: Point release
Examples: Arch Linux, Gentoo, openSUSE Tumbleweed, Void Linux

Rolling release, also known as rolling update or continuous delivery, is a concept in software development of frequently delivering updates to applications. This differs from a standard, or point release, development model which uses software versions that must be reinstalled over the previous version. Rolling release distributions of Linux, for example, are installed once and then receive continual updates, so there is no discrete "version" of the system as a whole.

Models

Rolling releases range from fully rolling distributions, in which every package is updated as soon as upstream releases it (Arch Linux, Gentoo), to semi- or partially rolling models, in which a stable core is paired with rolling application software. Some distributions offer both: openSUSE maintains the point-release Leap and the rolling Tumbleweed; Manjaro holds Arch packages back for additional testing before releasing them in waves.

Advantages and disadvantages

Advantages include immediate access to new features and fixes, no disruptive version upgrades, and a system that is always current. Disadvantages include a higher risk of breakage from an individual bad update, greater bandwidth use, and difficulty in reproducing a specific past state of the system. Snapshotting tools (such as Btrfs snapshots with Snapper) and atomic-update mechanisms are often used to mitigate the risk.

Beyond operating systems

The rolling model has spread widely: web browsers such as Chrome and Firefox moved to rapid release cycles, "evergreen" web applications deploy continuously, and Windows 10 was marketed as "Windows as a service" with rolling feature updates. In game development and SaaS products, continuous delivery is now the dominant release strategy.
