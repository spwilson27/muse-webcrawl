Model–view–presenter

Model–view–presenter (MVP) is a software architectural pattern derived from model–view–controller (MVC), used mostly for building user interfaces. In MVP the presenter assumes the role of the "middle-man": all presentation logic is pushed into the presenter, and the view is made as passive as possible.

Components

  • The model is an interface defining the data to be displayed or otherwise acted upon in the user interface.
  • The view is a passive interface that displays data (from the model) and routes user commands to the presenter to act upon it. The view usually implements an interface with properties and events that the presenter can use.
  • The presenter acts upon the model and the view: it retrieves data from repositories (the model), formats it for display, responds to user input forwarded by the view, and updates the view accordingly.

History

MVP emerged in the 1990s, notably at Taligent, and was described by Mike Potel in 1996. It was later popularised in the .NET community through patterns such as Martin Fowler's "Supervising Controller" and "Passive View" variants, which differ in how much logic resides in the view.

Advantages

Because the view is passive and the presenter has no dependency on concrete UI controls, presentation logic can be unit-tested without a graphical environment. The pattern has been widely used in Windows Forms, ASP.NET Web Forms, and Android development, though model–view–viewmodel (MVVM) became preferred where data binding is available.
