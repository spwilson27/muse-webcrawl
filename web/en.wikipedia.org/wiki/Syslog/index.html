Syslog

In computing, syslog is a standard for message logging. It allows separation of the software that generates messages, the system that stores them, and the software that reports and analyses them. Each message is labelled with a facility code, indicating the type of system that generated it, and assigned a severity level. Computer system designers may use syslog for system management and security auditing as well as general informational, analysis, and debugging messages.

History

Syslog was developed in the 1980s by Eric Allman as part of the Sendmail project, and became the de facto standard logging facility on Unix and Unix-like systems. The network protocol was documented informally in RFC 3164 (2001), and a standardised version was published as RFC 5424 in 2009, with transport mappings including TLS-protected transmission in RFC 5425. On Linux systems, traditional implementations such as sysklogd have largely been supplemented or replaced by rsyslog, syslog-ng and the systemd journal.

Severity levels

ValueSeverityMeaning
0EmergencySystem is unusable
1AlertAction must be taken immediately
2CriticalCritical conditions
3ErrorError conditions
4WarningWarning conditions
5NoticeNormal but significant condition
6InformationalInformational messages
7DebugDebug-level messages

Facilities include auth, authpriv, cron, daemon, kern, mail, user and eight local0–local7 codes for custom use.

Protocol

Syslog messages are traditionally sent over UDP port 514, or over TCP for reliability. A classic message contains a priority value (facility times eight plus severity, in angle brackets), a header with timestamp and hostname, and the message body beginning with a tag identifying the program. RFC 5424 adds structured data elements and a more rigorous timestamp format.
