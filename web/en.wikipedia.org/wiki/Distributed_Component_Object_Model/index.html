The Distributed Component Object Model (DCOM) is a Microsoft technology for communication between software components on networked computers. It extends the Component Object Model (COM) so that objects can be activated and invoked across machine boundaries, using DCE/RPC as its underlying remote procedure call mechanism. DCOM shipped with Windows NT 4.0 in 1996.

Overview

DCOM lets a client program instantiate a COM object on a remote server, identified by its CLSID, and call its interfaces as if it were local. The Service Control Manager on the server machine launches the object, and proxies and stubs marshal interface pointers and parameters using the Network Data Representation of DCE/RPC. COM's IUnknown and reference counting are extended over the wire with a pinging protocol to detect dead clients.

Security and configuration

DCOM permissions — activation, launch and access rights — are configured with the DCOMCNFG tool and stored in the registry. Its reliance on port 135 (the RPC endpoint mapper) plus dynamically allocated ports made DCOM difficult to use through firewalls and across the Internet, limiting its adoption there. Vulnerabilities in the DCOM RPC interface were exploited by the Blaster worm in 2003, prompting Microsoft to harden RPC/DCOM in later Windows service packs. Industrial automation's OPC Classic standards were built on DCOM and inherited these configuration challenges, motivating the later OPC Unified Architecture.
