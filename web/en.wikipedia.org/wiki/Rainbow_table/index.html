Rainbow table

A rainbow table is a precomputed table for reversing cryptographic hash functions, mainly for cracking password hashes. Tables are used to recover a plaintext password (or the key space of potential passwords) up to a certain length composed of a limited set of characters.

Rainbow tables are a practical implementation of a space–time tradeoff, using less computer processing time and more storage than a brute-force attack, but more processing time and less storage than a full lookup table of all possible passwords.

Background

The technique was developed by Philippe Oechslin and published in 2003, extending the 1980 time–memory tradeoff of Martin Hellman. Rainbow tables improve on Hellman's chains by using multiple reduction functions so that collisions from different starting points can be detected and merged chains avoided, making the tables more effective.

Operation

A rainbow table is generated by building long chains of hashes: starting from a plaintext, apply the hash function, then a reduction function that maps the hash back to a possible plaintext, and repeat. Only the starting and ending values of each chain are stored. To crack a target hash, the lookup process applies the reduction and hash functions repeatedly, working backwards through the chain positions until the stored endpoint matches, at which point the chain is regenerated to recover the plaintext.

Each reduction function differs per column of the chain; hence the name "rainbow", from the colour-coding of the successive reduction functions in diagrams of the method.

Defenses

Rainbow tables are defeated by salting password hashes — adding a random per-user salt before hashing — because the table would have to be computed for every possible salt. Slow, memory-hard hash functions such as bcrypt, scrypt and Argon2 also raise the cost of precomputation dramatically. The term "salt" derives from the practice described by Ken Thompson and Robert Morris in early Unix systems.

Common applications

Rainbow tables have been published for common hash schemes such as MD5, SHA-1 and the Windows LM hash, and are used by password-recovery tools. A Windows password stored with the LM hash could be cracked in minutes with freely available tables.
