Reactive programming

Reactive programming is a declarative programming paradigm concerned with data streams and the propagation of change. In a reactive program, values are defined in terms of other values, and when a source value changes, dependent values update automatically — much as a formula in a spreadsheet recalculates when one of its input cells changes.

Concepts

Reactive systems are typically built from streams (sequences of values over time) and operators that transform, combine, filter and merge them. Implementations must handle issues such as glitches (transient inconsistent states during propagation), evaluation order, and the management of dynamic dependency graphs. Functional reactive programming (FRP), introduced by Conal Elliott and Paul Hudak in the 1990s, treats time-varying values ("behaviours") and events as first-class abstractions with precise denotational semantics.

Implementations

Reactive techniques underpin modern user-interface frameworks and asynchronous programming libraries. Microsoft's Reactive Extensions (Rx), and its ports such as RxJava and RxJS, model asynchronous data as observable streams. Web frameworks including React popularised a related reactive view layer, in which the interface is a function of application state. The Reactive Manifesto (2013) separately promoted the properties of responsive, resilient, elastic and message-driven systems under the broader label "reactive systems".
