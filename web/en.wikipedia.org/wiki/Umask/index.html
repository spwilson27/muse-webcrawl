umask

In computing, umask is a Unix command and system call that sets and determines the file mode creation mask: a per-process mask of permission bits that are turned off when a new file or directory is created. When a program creates a file requesting mode 0666, or a directory requesting 0777, the kernel clears any bits set in the process's umask, so the actual permissions are the requested mode ANDed with the bitwise complement of the umask.

How it works

For example, with the common umask 022, a new file created with mode 666 becomes 644 (rw-r--r--) and a new directory created with mode 777 becomes 755 (rwxr-xr-x). A umask of 027 yields files of 640 and directories of 750, typical for stricter shared systems; a umask of 077 yields 600/700, private to the owner. Executable files are only created executable if the creating program explicitly requests it; the umask can never add permission bits, only remove them.

Usage

The shell builtin umask displays or changes the current mask, e.g. umask 022. It is normally set in login scripts or by pam_umask. Programmatically, the POSIX umask() system call sets the mask and returns the previous value. Because the mask is inherited across fork and exec, parent processes and system services (via systemd's UMask= setting) can control the default permissions of everything they create. Choosing an overly permissive umask (such as 000) is a common security concern on multi-user systems.
