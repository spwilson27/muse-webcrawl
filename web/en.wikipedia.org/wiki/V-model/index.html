V-model

The V-model is a software development process model that represents a development process as a sequence of phases arranged in a V shape. It is an extension of the waterfall model, in which each development phase is paired with a corresponding testing phase planned in parallel.

Structure

The descending left arm of the V contains the specification and design stages: business requirements, system design, architectural (high-level) design and module (low-level) design, followed by coding at the bottom. The ascending right arm contains the corresponding verification and validation stages: unit testing (against module design), integration testing (against architectural design), system testing (against system design) and acceptance testing (against the requirements). The model emphasises that test plans should be developed alongside — not after — the corresponding design documents.

History and use

The model emerged in the late 1980s in German and American defence and systems-engineering projects; a version was codified in the German federal V-Modell standard for public-sector IT projects (later V-Modell XT). It remains common in regulated industries such as medical devices, automotive and aerospace, where traceability between requirements and tests is mandated.

Criticism

Critics argue that the V-model shares the waterfall model's rigidity: it assumes requirements are known and stable up front, handles change poorly, and provides no working software until late in the project. Iterative and agile methodologies were developed partly in reaction to these limitations.
