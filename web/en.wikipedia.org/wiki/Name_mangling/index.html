Name mangling

In compiler construction, name mangling (also called name decoration) is a technique used to solve various problems caused by the need to resolve unique names for programming entities in many modern programming languages. It provides a way of encoding additional information in the name of a function, structure, class, or another data type in order to pass more semantic information from the compiler to the linker.

Why mangling is needed

Languages such as C++ allow function overloading: several functions may share one name provided their parameter types differ. Traditional linkers, designed for C, expect every symbol to be unique. Mangling solves the conflict by folding the signature — namespace, class, and parameter types — into the symbol itself. The C++ function void f(int) might become _Z1fi under the Itanium ABI scheme, while f(double) becomes a different symbol.

Schemes and compatibility

There is no single standard for C++ name mangling. Microsoft Visual C++ uses a scheme beginning with ?, while GCC and Clang on most platforms follow the Itanium C++ ABI, whose mangled names begin with _Z. Because schemes differ, object files produced by different compilers are often not link-compatible even on the same operating system. Tools such as c++filt demangle symbol names for debugging and profiling.

Other languages

Mangling also occurs elsewhere. Fortran compilers historically appended underscores to symbol names. Rust encodes crate and version information in its symbols. The Java Native Interface and C linkage declarations such as extern "C" deliberately suppress mangling so that symbols can be found across language boundaries.
