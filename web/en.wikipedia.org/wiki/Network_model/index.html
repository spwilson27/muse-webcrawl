Network model

The network model is a database model conceived as a flexible way of representing objects and their relationships. Its distinguishing feature is that the schema, viewed as a graph in which object types are nodes and relationship types are arcs, is not restricted to being a hierarchy or lattice.

The network model was adopted by the CODASYL Data Base Task Group in 1969 and underwent a major update in 1971. It is sometimes known as the CODASYL model after the consortium that developed it, or the DBTG model after the Database Task Group that authored it.

History

The original inventor of the network model was Charles Bachman, who developed it while working at General Electric on the Integrated Data Store (IDS), one of the first database management systems, in the early 1960s. Bachman's work strongly influenced the CODASYL Data Base Task Group, whose 1969 specification became the basis for commercial network database systems from vendors such as Computer Sciences Corporation, Honeywell, and Cullinet (with its IDMS product).

The network model was a contemporary and competitor of the relational model proposed by Edgar F. Codd in 1970. A famous 1974 debate between Bachman and Codd contrasted the navigational style of network databases with the declarative style of relational databases. Bachman received the Turing Award in 1973 for his work on database technology.

Overview

In a network database, data is organised into records, which are grouped into record types. Relationships between records are expressed by set types: a named directed relationship between an owner record type and a member record type. Unlike the hierarchical model, a member record may participate in several sets and may have more than one owner, which allows many-to-many relationships to be modelled directly.

A network database is navigated procedurally: a program maintains currency indicators pointing at records it has most recently accessed and follows set occurrences from owner to member records. Charles Bachman called this style "the programmer as navigator."

Basic concepts

  • Record type — a named collection of data items, analogous to a table but without relational constraints.
  • Set type — a named owner–member relationship between two record types.
  • Set occurrence — one instance of a set type: one owner record together with its member records.
  • Currency — the notion of "current" record for the run unit, each set type, and each record type.

Comparison with other models

The network model generalises the earlier hierarchical model by removing the restriction that each record has only one parent. Compared with the relational model, it offered predictable performance and direct pointer-based access in exchange for queries that are harder to write and a schema that is costly to change. Most new database designs from the 1980s onward adopted the relational model, though network-style graph structures have returned to prominence with modern graph databases.
