CPU cache

A CPU cache is a hardware cache used by the central processing unit (CPU) of a computer to reduce the average cost (time or energy) to access data from the main memory. A cache is a smaller, faster memory, located closer to a processor core, which stores copies of the data from frequently used main memory locations. Most CPUs have a hierarchy of multiple cache levels (L1, L2, often L3, and rarely even L4), with different instruction-specific and data-specific caches.

Typical L1 size32–64 KB per core (split I/D)
Typical L2 size256 KB – a few MB per core
Typical L3 sizeSeveral MB to >100 MB, shared
Line sizeCommonly 64 bytes
TechnologySRAM

Operation

When the processor requests data, the cache is checked first. A cache hit means the data was found (fast); a cache miss forces a fetch from a slower level or main memory, after which a block of data — a cache line, typically 64 bytes — is copied into the cache, exploiting spatial locality. Caches work because programs exhibit temporal locality (recently used data is likely to be reused) and spatial locality (nearby data is likely to be used).

Organization

Caches are described by their associativity: direct-mapped (each memory block maps to exactly one line), fully associative (any block can go anywhere), or set-associative (a compromise, e.g. 8-way or 16-way). Replacement policies include LRU (least recently used) and pseudo-LRU. Write policies are write-through or write-back; in multiprocessors, coherence protocols such as MESI keep the caches consistent. Instructions and data are kept in separate L1 caches (a modified Harvard architecture), while L2 and L3 are usually unified.

History

The concept of "slave memory" was described by Maurice Wilkes in 1965. Early implementations appeared in the IBM System/360 Model 85 (1968). Microprocessors integrated on-chip caches from the late 1980s (Intel 80486, 1989, with 8 KB on die); separate L2 caches moved on-package and then on-die in the 1990s, and shared L3 caches became standard in the multicore era. AMD's 3D V-Cache (2022) stacks an additional L3 die vertically. Cache timing side channels underlie the Spectre vulnerabilities disclosed in 2018.
