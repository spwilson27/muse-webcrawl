Refinement type

In computer science, a refinement type is a type endowed with a predicate which is assumed to hold for any element of the refined type. Refinement types can express preconditions and postconditions for functions, and invariants for data; when combined with automatic theorem proving, they support static program verification beyond what ordinary type systems can guarantee.

A refinement type {x : τ | p(x)} restricts a base type τ by a predicate p. [Image placeholder]

Form

A refinement type is typically written {x : τ | p}, where τ is a base type (such as the integers) and p is a logical formula over x. For example, the type of natural numbers can be expressed as a refinement of the integers:

{x : int | 0 ≤ x}

A function's specification can then require a positive divisor, e.g. a division function with the type int → {y : int | y ≠ 0} → int, so that a type checker can statically rule out division by zero.

Checking

Refinement type checking reduces subtyping questions to logical validity, discharged by SMT solvers such as Z3. Systems implementing refinement types include Liquid Haskell, Liquid types for OCaml, F* (which generalises the idea with dependent types), Stainless for Scala, and the Dafny language, whose types are paired with verification conditions.

History

The concept traces to work on indexed and dependent types in the late 1980s and 1990s, including Freeman and Pfenning's "Refinement types for ML" (1991), and was popularised for practical verification by the Liquid Types line of research from UC San Diego in the 2000s.
