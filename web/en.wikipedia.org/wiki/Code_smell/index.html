Code smell

A code smell hints at a deeper design problem

Coined by: Kent Beck (popularised by Martin Fowler, Refactoring, 1999)

Related: Anti-pattern, technical debt

In computer programming, a code smell is any characteristic in the source code of a program that possibly indicates a deeper problem. The term was coined by Kent Beck and popularised by Martin Fowler in the 1999 book Refactoring. A smell is not necessarily a bug — the code may work correctly — but a surface symptom that usually corresponds to a weakness in design that can slow development, increase the risk of future bugs, and make the code harder to understand and change. Determining what counts as a smell is subjective and varies by language, project and reviewer.

Common code smells

Fowler's catalogue, expanded in the book's second edition (2018), includes:

Bloaters — code that has grown too large to work with comfortably: Long Method, Large Class, Long Parameter List, and Primitive Obsession (using primitive types where a small class would do).

Change preventers — structures that make a change in one place require many changes elsewhere: Divergent Change and Shotgun Surgery.

Dispensables — things that can be removed without harm: Duplicated Code, Dead Code, Lazy Class, Speculative Generality, and excessive Comments used to deodorise confusing code.

Couplers — excessive coupling between classes: Feature Envy, Inappropriate Intimacy, Message Chains, and Middle Man.

Object-orientation abusers — Switch Statements used in place of polymorphism, Refused Bequest (a subclass that does not use inherited behaviour), and Temporary Fields.

Treatment

The standard remedy for smells is refactoring — small, behaviour-preserving transformations such as Extract Method for a long function or replacing duplicated logic with a shared abstraction. Automated static-analysis tools can detect some smells (duplicate blocks, excessive complexity, overly long methods) and are often wired into code review pipelines, though many smells remain matters of engineering judgement.
