Superkey

In the relational model of databases, a superkey (or super-key) is a set of attributes that uniquely identifies each tuple (row) in a relation (table): no two distinct tuples can have identical values across all of the superkey's attributes. A superkey may contain additional attributes beyond those strictly necessary for uniqueness.

Definitions

A superkey that contains no proper subset which is itself a superkey — that is, a minimal superkey — is called a candidate key. From the candidate keys, one is typically chosen as the primary key of the relation. Any superset of a superkey is itself a superkey, so the set of all attributes of a relation always forms a (trivial) superkey.

Example

In an employee table with attributes (EmployeeID, NationalInsuranceNumber, Name, Department), the sets {EmployeeID}, {NationalInsuranceNumber}, and {EmployeeID, Name} are all superkeys, but only the first two are candidate keys, since {EmployeeID, Name} contains the smaller superkey {EmployeeID}.

Use

Superkeys matter in database design and normalization because functional dependencies are stated in terms of them: an attribute set X is a superkey of a relation exactly when X functionally determines every attribute of the relation. Determining all superkeys is part of computing candidate keys from a set of functional dependencies.
