Java bytecode is the instruction set of the Java virtual machine (JVM), the intermediate representation produced by compiling Java source code and other JVM languages. Bytecode is stored in .class files, each of which contains the compiled form of a single class or interface. Because the JVM is available on many platforms, Java programs are often described as "write once, run anywhere": the same bytecode can execute on any system with a compatible JVM implementation.

Relation to Java

A Java programmer does not usually need to know Java bytecode directly, but understanding it helps in analyzing program behavior, performance, and security. Compilers for the Java language translate source code into bytecode, and the JVM then executes it — historically by interpretation, and in modern implementations primarily through just-in-time (JIT) compilation to native machine code. Other languages, including Kotlin, Scala, Groovy, and Clojure, also compile to Java bytecode.

Instruction set

The JVM instruction set consists of 256 possible one-byte opcodes, of which around 200 were in use in early versions. Instructions operate on an operand stack rather than on general-purpose registers, making the JVM a stack machine. Each method has its own operand stack and array of local variables. Instructions include:

  • Load and store instructions (e.g. iload, astore)
  • Arithmetic instructions (e.g. iadd, fsub, dmul)
  • Type conversion instructions (e.g. i2l, f2d)
  • Object creation and manipulation (e.g. new, getfield, putfield)
  • Operand stack management (e.g. pop, dup, swap)
  • Control transfer instructions (e.g. ifeq, goto, tableswitch)
  • Method invocation and return (e.g. invokevirtual, invokestatic, ireturn)

Class file format

Every class file begins with the four-byte magic number 0xCAFEBABE, followed by the minor and major version numbers of the class file format, a constant pool, access flags, references to this class and its superclass, interfaces, fields, methods, and attributes. The constant pool holds symbolic references — class names, method names and descriptors, strings, and numeric constants — that the JVM resolves at run time. Before execution, a bytecode verifier checks the code for type safety and structural validity, a key part of Java's security model.

Example

A simple method such as:

int add(int a, int b) { return a + b; }

compiles to bytecode equivalent to:

iload_0
iload_1
iadd
ireturn
