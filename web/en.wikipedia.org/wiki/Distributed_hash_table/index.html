Distributed hash table

From Wikipedia, the free encyclopedia

A distributed hash table (DHT) is a distributed system that provides a lookup service similar to a hash table. Key-value pairs are stored in a DHT, and any participating node can efficiently retrieve the value associated with a given key. Keys are unique identifiers which map to particular values, which in turn can be anything, from addresses, to documents, to arbitrary data. Responsibility for maintaining the mapping from keys to values is distributed among the nodes, in such a way that a change in the set of participants causes a minimal amount of disruption.

Properties

  • Decentralisation: the nodes collectively form the system without any central coordination.
  • Scalability: lookups typically cost O(log n) messages, so systems function with thousands or millions of nodes.
  • Fault tolerance: the system remains reliable even as nodes join, leave or fail continuously ("churn").

History and designs

DHT research began in 2001 with four influential designs — CAN, Chord, Pastry and Tapestry — following the rise of peer-to-peer file-sharing systems such as Napster and Gnutella, which were either centralised or inefficient at lookup. Kademlia (2002), with its XOR-based distance metric, became especially influential; variants of it are used in BitTorrent's trackerless "Mainline DHT", in the Kad network, and in IPFS and Ethereum node discovery.

Structure

Most DHTs build an abstract overlay network on a large identifier space (for example, 160-bit identifiers). Each node is assigned an identifier, each key is mapped into the same space, and a routing rule directs queries towards the node responsible for a key. Keys are usually replicated on several neighbouring nodes so that data survives departures. Security is a persistent challenge: open DHTs are vulnerable to Sybil and eclipse attacks in which malicious nodes distort routing or storage.
