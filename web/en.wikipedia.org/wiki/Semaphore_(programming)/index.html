Semaphore (programming)

From Wikipedia, the free encyclopedia

Semaphore — a synchronization primitive used to control access to a common resource by multiple processes in a concurrent system.

In computer programming, a semaphore is a variable or abstract data type used to control access to a common resource by multiple processes and to avoid critical section problems in a concurrent system such as a multitasking operating system. Semaphores are a type of synchronization primitive and were introduced by the Dutch computer scientist Edsger W. Dijkstra in the mid-1960s.

A semaphore is a record of how many units of a particular resource are available, coupled with operations to safely adjust that record as units are acquired or released, and, if necessary, to wait until a unit becomes available.

History

Dijkstra developed the semaphore concept while working on an early multiprogramming system at the Mathematisch Centrum in Amsterdam. He introduced the operations P and V, named after the Dutch words proberen ("to test") and verhogen ("to raise, increment"), in his 1965 paper describing the THE multiprogramming system. Semaphores became one of the foundational tools of concurrent programming and remain built into most modern operating systems and threading libraries.

Semantics and operations

The classic semaphore supports two atomic operations:

  • wait (P): decrements the value of the semaphore. If the value would become negative, the calling process is blocked and placed in a queue until the semaphore can be decremented.
  • signal (V): increments the value of the semaphore. If any processes are waiting, one of them is unblocked and allowed to proceed.

Because the test-and-decrement must be indivisible, semaphore operations are implemented with the help of the operating system kernel or hardware atomic instructions, so that no race condition can occur between checking the value and changing it.

Types of semaphores

A binary semaphore can take only the values 0 and 1 and behaves much like a lock or mutex, although the two are not identical: a mutex typically has an owner that must release it, whereas a semaphore may be signalled by a different thread than the one that waited on it. A counting semaphore can take any non-negative integer value and is used to manage a pool of identical resources, such as a fixed number of database connections.

Uses

Semaphores are commonly used to solve the producer–consumer problem, to implement bounded buffers, to limit the number of threads simultaneously executing a section of code, and to signal events between cooperating threads. Misuse can lead to deadlock, priority inversion, and other concurrency bugs, so higher-level constructs such as monitors and condition variables are often preferred in application code.
