A smart contract is a computer program or transaction protocol intended to automatically execute, control or document events and actions according to the terms of a contract or agreement. Stored on a blockchain, smart contracts run exactly as programmed without a central intermediary, producing outcomes that are transparent, traceable and effectively irreversible.

History

Computer scientist and cryptographer Nick Szabo proposed the concept in the mid-1990s, comparing a contract embedded in code to a vending machine: hardware and software enforce the bargain mechanically. Szabo's designs (including "bit gold") anticipated elements of Bitcoin. The idea became practical with Ethereum, proposed by Vitalik Buterin in 2013 and launched in 2015, which provided a general-purpose, Turing-complete virtual machine (the EVM) for on-chain programs, written mainly in Solidity.

How they work

Developers deploy contract bytecode to the blockchain; users interact by sending transactions that call contract functions, paying computation fees ("gas" on Ethereum). Because contracts cannot access off-chain data directly, they rely on oracles (e.g., Chainlink) to feed in prices and other facts. Standard interfaces such as ERC-20 (fungible tokens) and ERC-721 (non-fungible tokens, NFTs) made contracts composable, powering decentralised finance (DeFi) protocols for lending, exchanges and stablecoins, as well as decentralised autonomous organisations (DAOs).

Security and legal issues

Immutability cuts both ways: bugs cannot easily be patched. The 2016 hack of The DAO, in which a re-entrancy vulnerability drained about 3.6 million ether (then ~$50–60 million), led to a controversial hard fork of Ethereum. Billions more have been lost to exploits of DeFi contracts. Legally, smart contracts raise questions about enforceability, jurisdiction and the status of "code is law"; some jurisdictions (e.g., several U.S. states, the UK Law Commission's 2021 advice) recognise that smart legal contracts can be valid under existing law.
