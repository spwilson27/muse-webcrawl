Interrupt handler


Also called: Interrupt service routine (ISR)
Field: Operating systems, embedded systems

In computer systems programming, an interrupt handler, also known as an interrupt service routine (ISR), is a special block of code associated with a specific interrupt condition. Interrupt handlers are initiated by hardware interrupts, software interrupt instructions, or software exceptions, and are used for implementing device drivers and transitions between protected modes of operation, such as system calls.

Operation

When an interrupt occurs, the processor suspends its current activity, saves its state, and transfers control to the handler registered for that interrupt vector. The handler performs the urgent work — for example reading data from a device or acknowledging a timer tick — and then returns, restoring the saved state so the interrupted program resumes. Because handlers run with some interrupts disabled and must not block, they are typically kept short; longer processing is deferred to a lower-priority routine, a pattern known in the Linux kernel as "top half" and "bottom half" (softirqs, tasklets, and workqueues).

Types

Handlers may service hardware interrupts from devices, software interrupts invoked deliberately by an instruction, and exceptions caused by faults such as division by zero or page faults. In many operating systems, device drivers register a handler along with the interrupt request line (IRQ) the device uses.

Design constraints

Interrupt handlers generally cannot sleep, allocate memory that might block, or call most ordinary kernel services. Shared interrupts, interrupt latency, and re-entrancy must all be handled carefully to avoid lost interrupts and race conditions.
