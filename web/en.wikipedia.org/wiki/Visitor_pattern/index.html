Visitor pattern

In object-oriented programming, the visitor pattern is a behavioural design pattern that separates an algorithm from the object structure on which it operates. It allows new operations to be added to an existing structure without modifying the classes of the elements, by encoding each operation in a separate "visitor" object.

Mechanism

Each element class provides an accept method that takes a visitor; the method calls back the visitor's visit method specific to that element type — a technique known as double dispatch. The pattern is one of the classic patterns described by the "Gang of Four" in Design Patterns (1994).

Uses and trade-offs

Visitor is widely used in compilers, where passes such as type checking, optimisation and code generation operate over an abstract syntax tree. Its weakness is that adding a new element type requires changing all existing visitors, making it best suited to stable element hierarchies with evolving operations. Functional languages often achieve the same effect with pattern matching.
