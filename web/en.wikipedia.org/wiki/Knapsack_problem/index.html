Knapsack problem

The knapsack problem is a problem in combinatorial optimization: given a set of items, each with a weight and a value, determine which items to include in a collection so that the total weight is less than or equal to a given limit and the total value is as large as possible. It derives its name from the problem faced by someone who is constrained by a fixed-size knapsack and must fill it with the most valuable items.

Choosing the most valuable combination of items that fits in a knapsack of limited capacity.

Definition

The most common problem being solved is the 0–1 knapsack problem, which restricts the number of copies of each kind of item to zero or one. Given a set of n items, each with weight wi and value vi, and a maximum capacity W, the goal is:

maximize Σ vi xi   subject to   Σ wi xi ≤ W,   xi ∈ {0, 1}

Variants include the bounded knapsack problem (each item type available in limited quantity), the unbounded knapsack problem (unlimited copies), and the multiple knapsack problem (several knapsacks). The problem is one of Richard Karp's 21 NP-complete problems, described in his 1972 paper, and appears on the list of Millennium-adjacent classics of theoretical computer science.

Computational complexity

The 0–1 knapsack problem is NP-hard, and its decision version is NP-complete. Nevertheless, it admits a pseudo-polynomial time algorithm based on dynamic programming whose running time is proportional to the number of items times the capacity W. Because W is a numerical value rather than a function of the input length, this does not contradict NP-hardness: the problem is described as weakly NP-hard. Knapsack also admits a fully polynomial-time approximation scheme (FPTAS), making it one of the best-behaved NP-hard optimization problems in practice.

Solution methods

Dynamic programming

The classical algorithm computes, for each item and each capacity, the maximum value obtainable. Building the table requires O(nW) time and space, which is practical when the capacity is moderate. Space can be reduced by processing items in reverse order of capacity within a single one-dimensional array.

Greedy and approximation algorithms

A simple greedy strategy sorts items by value density (value per unit weight) and packs them in that order; although this can be arbitrarily bad for the 0–1 problem, combining it with a best-single-item check yields a 2-approximation. The FPTAS scales item values to reduce state space while losing only a small, controlled fraction of optimality.

Branch and bound

Exact solvers often use branch and bound, computing upper bounds from the linear (fractional) relaxation of the problem, in which fractions of items are allowed. The fractional problem is solvable greedily by value density, and its optimum bounds any integral solution.

Applications

Knapsack models arise in resource allocation, budgeting, cargo loading, cutting stock problems, and project selection. The problem also played a role in early public-key cryptography: the Merkle–Hellman knapsack cryptosystem (1978) based its security on the subset-sum special case, although it was later broken by Adi Shamir and others.
