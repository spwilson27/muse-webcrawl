Readers–writer lock

In computer science, a readers–writer lock (also called a shared–exclusive lock, multi-reader lock, or push lock) is a synchronization primitive that allows concurrent access for read-only operations while requiring exclusive access for write operations. Because reading shared data does not modify it, many threads may hold the lock simultaneously in read (shared) mode, improving performance over a simple mutex when reads greatly outnumber writes.

Policies and fairness

Implementations differ in scheduling policy. A reader-preferring lock lets new readers in even while a writer waits, maximizing concurrency but risking writer starvation. A writer-preferring lock blocks new readers once a writer is queued, guaranteeing the writer access but potentially delaying readers. Fair or phase-fair variants alternate between reader batches and writers. The classic readers–writers problem, one of the canonical synchronization problems, studies these trade-offs.

Implementations

Readers–writer locks are widely provided: POSIX threads offer pthread_rwlock, C++17 provides std::shared_mutex, Java offers ReentrantReadWriteLock, and Windows has Slim Reader/Writer (SRW) locks. Writers typically may not upgrade a read lock to a write lock atomically, so designs must take care to avoid deadlock when an upgrade is needed. Downgrading a write lock to a read lock is often supported and useful for publishing updates atomically.
