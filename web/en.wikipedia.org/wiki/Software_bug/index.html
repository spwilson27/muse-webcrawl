Software bug

A software bug is a defect, error, or fault in a computer program that causes it to produce an incorrect or unexpected result, or to behave in unintended ways. The process of finding and fixing bugs is called debugging. Bugs arise from mistakes in a program's source code or design, from incorrect requirements, or from interactions between components.

Etymology

The term "bug" for an engineering defect long predates computing; Thomas Edison used it in the 1870s. A famous computing anecdote involves a moth found in a relay of the Harvard Mark II computer in 1947, taped into the logbook by operators including Grace Hopper — often cited, though incorrectly, as the origin of the term.

Types of bugs

  • Logic errors — the program runs but computes the wrong result.
  • Syntax errors — caught at compile time when code violates language rules.
  • Runtime errors and crashes — such as null-pointer dereferences, division by zero, and memory-access violations.
  • Race conditions — timing-dependent faults in concurrent programs.
  • Security vulnerabilities — bugs, such as buffer overflows, that attackers can exploit.
  • Off-by-one and boundary errors — mistakes at the edges of loops and ranges.

Consequences

Some bugs have had catastrophic effects: the Ariane 5 rocket explosion (1996) was caused by a numeric conversion overflow; the Therac-25 radiation-therapy accidents in the 1980s were linked to a race condition; and the 2012 Knight Capital glitch lost the firm about US$440 million in under an hour. The Year 2000 problem ("Y2K bug") prompted a worldwide remediation effort over two-digit year storage.

Management

Bugs are tracked in issue-tracking systems, prioritised by severity and priority, and addressed through testing techniques including unit tests, integration tests, fuzzing, static analysis, and code review. The related term glitch usually denotes a brief, transient malfunction.
