B-tree

A B-tree of order 4. Each node holds several sorted keys and points to child subtrees.

In computer science, a B-tree is a self-balancing tree data structure that maintains sorted data and allows searches, sequential access, insertions and deletions in logarithmic time. The B-tree generalises the binary search tree, allowing nodes to have more than two children. Unlike other self-balancing binary search trees, the B-tree is well suited for storage systems that read and write relatively large blocks of data, such as databases and file systems.

History and definition

B-trees were invented by Rudolf Bayer and Edward M. McCreight while working at Boeing Research Labs and described in their 1970 paper "Organization and Maintenance of Large Ordered Indices". The name's origin was never fully explained by its inventors; suggestions include "balanced", "broad", "bushy" and "Boeing".

A B-tree of order m is a tree in which every node has at most m children, every internal node except the root has at least ⌈m/2⌉ children, all leaves appear at the same depth, and keys within a node are kept in sorted order, partitioning the key ranges stored in the subtrees between them. When a node overflows on insertion it splits; when it underflows on deletion it merges or redistributes keys with a sibling. Because nodes are sized to match disk blocks (often holding hundreds of keys), a B-tree storing millions of entries is only a few levels deep, so only a handful of disk accesses are needed per operation.

Variants and uses

The most common variant is the B+ tree, which stores all records (or pointers to them) in the leaves and links the leaves together for fast sequential scans; internal nodes hold keys only as routing guides. B-trees and B+ trees underpin the indexes of virtually all relational database systems, and B-tree-like structures are used in file systems including NTFS, HFS+ and ext4 (via extent trees) as well as in key-value stores. Related structures include the B* tree, which keeps nodes at least two-thirds full, and log-structured merge trees used in some modern storage engines as an alternative write-optimised design.
