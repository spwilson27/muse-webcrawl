Semantic versioning

Semantic versioning (often abbreviated SemVer) is a scheme for assigning version numbers to software releases in a way that conveys the nature of the changes made. Under semantic versioning, a version number takes the form MAJOR.MINOR.PATCH (for example, 2.1.3), where each component is incremented according to rules tied to the public API of the software.

Rules

The MAJOR version is incremented when incompatible API changes are made; the MINOR version when functionality is added in a backward-compatible manner; and the PATCH version when backward-compatible bug fixes are made. Pre-release versions may be denoted by a hyphen and identifiers (e.g. 1.0.0-alpha), and build metadata may be appended with a plus sign. A version of 0.y.z denotes initial development, in which anything may change at any time.

History and use

The specification (semver.org) was authored by Tom Preston-Werner, co-founder of GitHub. Semantic versioning is widely used in package ecosystems such as npm, Cargo, and many others, where dependency resolvers rely on version ranges to select compatible releases automatically.
