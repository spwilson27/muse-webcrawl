Certificateless cryptography

Certificateless cryptography is a variant of identity-based cryptography intended to avoid the key escrow problem of identity-based systems while also avoiding the need for digital certificates used in conventional public-key infrastructure. It was introduced by Sattam Al-Riyami and Kenneth Paterson in 2003.

Motivation

In a traditional public-key infrastructure, a certificate authority binds a public key to an identity with a signed certificate, which must be stored, distributed, and checked for revocation. In identity-based cryptography, the public key is simply the user's identity, but a trusted Key Generation Center (KGC) computes the user's full private key and therefore can decrypt or sign on behalf of any user — the key escrow problem. Certificateless cryptography splits key generation between the KGC and the user.

How it works

The KGC generates system parameters and, for a given identity, computes a partial private key from the KGC's master secret. The user independently chooses a secret value and combines it with the partial private key to form the full private key, and likewise computes a public key from the secret value and the system parameters. Because the KGC never learns the user's secret value, it cannot compute the full private key, eliminating escrow; because the public key is derived in part from the KGC-issued partial key, no certificate is needed to bind it to the identity.

Security model and applications

Security analyses of certificateless schemes typically consider two adversary types: an outsider who may replace users' public keys but does not know the master secret, and a malicious-but-passive KGC that knows the master secret but cannot replace public keys. Certificateless encryption, signatures, key agreement, and signcryption schemes have been proposed, and the approach has attracted interest for resource-constrained environments such as wireless sensor networks, vehicular networks, and cloud computing, where certificate management is burdensome.
