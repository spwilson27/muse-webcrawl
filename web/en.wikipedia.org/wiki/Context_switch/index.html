Context switch

In computing, a context switch is the process of storing the state of a process or thread, so that it can be restored and resume execution at a later point, and restoring the state of a different, previously saved, process or thread. This allows multiple processes to share a single central processing unit (CPU), and is an essential feature of a multitasking operating system.

Mechanism

The state saved for a process typically includes the program counter, processor registers, stack pointer, memory-management information and open-file state, stored in a data structure such as the process control block. Context switches are usually triggered by an interrupt, a system call, or the scheduler's time quantum expiring. Switching between threads of the same process is generally cheaper than switching between processes, because threads share an address space and no memory-management context must change.

Cost

A context switch is pure overhead: while it occurs, the system does no useful work for any user process. Its cost includes saving and restoring state, scheduler execution, and indirect effects such as flushing or cold-starting CPU caches and translation lookaside buffers. Typical direct costs on modern hardware are on the order of microseconds, but cache effects can make the effective cost much larger.

Hardware support

Some processor architectures provide hardware support for context switching; for example, the x86 architecture historically supported task switching via task state segments, though most operating systems implement switching in software for portability and speed.
