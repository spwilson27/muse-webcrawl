Stack-oriented programming

Stack-oriented programming is a programming paradigm that relies on a stack machine model for passing parameters. In a stack-oriented language, nearly all operations work by manipulating values on an implicit operand stack: arguments are pushed onto the stack, operators consume values from the top of the stack, and results are left on the stack for subsequent operations.

Characteristics

Stack-oriented languages characteristically use postfix (reverse Polish) notation, so that an expression such as 3 4 + pushes 3 and 4 and then applies the addition operator, leaving 7 on the stack. Because the data flow is implicit, programs tend to be extremely concatenative: the output stack of one word (subroutine) becomes the input stack of the next, and words can be composed without explicit variable declarations or argument lists.

Defining a new word typically consists of giving a name to a sequence of existing words. The programmer must keep track of the "stack effect" of each word — how many items it consumes and produces — which is often documented in a stack-effect comment such as ( a b -- sum ).

Examples

The best-known stack-oriented language is Forth, designed by Charles H. Moore in the 1970s and long used in embedded systems, astronomy, and control applications. Other examples include PostScript, the page-description language whose stack model also underlies much of PDF rendering; Factor, a modern concatenative language; Joy; and early HP calculators' RPL. The Java Virtual Machine and the .NET Common Language Runtime are also stack machines at the bytecode level, though their source languages are not usually written in stack-oriented style.

Advantages and disadvantages

Advocates point to conceptual simplicity: there is a single uniform mechanism for data flow, interpreters are tiny, and interactive testing is natural because any word can be exercised directly from the stack. Critics note that tracking stack contents mentally becomes difficult in large programs, that deep stack manipulation can obscure intent compared with named variables, and that errors in stack depth may only surface at run time.
