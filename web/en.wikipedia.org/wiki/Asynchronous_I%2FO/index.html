Asynchronous I/O

Asynchronous I/O lets a process continue while transfers complete in the background

In computer science, asynchronous I/O (also non-blocking I/O) is a form of input/output processing that permits other work to proceed before a transfer finishes, with completion signalled later. It contrasts with synchronous (blocking) I/O, in which a thread waits until each operation completes.

Forms and mechanisms

Approaches include readiness-based event notification (select, poll, epoll on Linux, kqueue on BSD, IOCP on Windows), completion-based interfaces (POSIX AIO, Linux io_uring, Windows overlapped I/O), and language-level constructs such as futures, promises, and async/await. Event-driven designs use these mechanisms to build servers that handle many connections per thread, avoiding the limits of the thread-per-connection model highlighted by the C10k problem.

Trade-offs

Asynchronous designs improve scalability and resource use but add complexity: control flow is fragmented into callbacks or state machines, error handling is harder, and for fast NVMe storage the distinction between blocking and non-blocking calls narrows.
