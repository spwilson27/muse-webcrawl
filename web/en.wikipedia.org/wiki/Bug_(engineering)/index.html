Bug (engineering)

Bug
Domain: Engineering, computing
Related terms: Defect, fault, glitch, debugging

In engineering, a bug is a design defect or error in a system that causes it to behave in unintended ways. In computing, a software bug is an error, flaw, or fault in a program that produces an incorrect or unexpected result. Fixing such defects is called debugging.

Etymology

The term "bug" for a technical defect predates computing: Thomas Edison used it in the 1870s for faults in his inventions. A famous computing anecdote dates to September 9, 1947, when operators of the Harvard Mark II found a moth trapped in a relay; the insect was taped into the logbook, popularizing the story — though the term was already established among engineers, and the logbook entry was a joke about literally "debugging" the machine.

Types

Software bugs include syntax errors, logic errors, runtime errors, race conditions, buffer overflows, and security vulnerabilities. Particularly elusive defects have earned names such as "heisenbugs," which change behaviour when observed, and "schrödinbugs," which appear only when someone examines the code.

Management

Bugs are tracked in issue-tracking systems, classified by severity and priority, and addressed through testing, code review, formal verification, and maintenance releases known as patches. The cost of fixing a bug generally rises the later it is found in the development process.
