Event sourcing

Event sourcing is a software design pattern in which the state of an application is determined by a sequence of events, each of which is recorded in an append-only event store. Instead of storing only the current state of an entity in a database, the system persists every change as an immutable event — for example, "item added to cart" or "payment received" — and derives the current state by replaying the events.

Characteristics

Because the event log is complete, the system can reconstruct the state of an entity at any point in its history, providing a built-in audit trail and simplifying debugging. Projections can be built from the same events to serve different read models, an approach often combined with the CQRS pattern (command query responsibility segregation). Events can also be published to other services, making the pattern popular in microservice architectures.

Challenges

Replaying long event streams can be slow, so systems often store periodic snapshots of state. Events are never deleted, which raises storage costs and complicates compliance with privacy rules requiring erasure of personal data; common mitigations include encrypting personal data per subject so it can be "crypto-shredded". Versioning event schemas over time is another persistent difficulty.
