Sum type

A sum type combines values from several types, each tagged with its origin

In type theory and programming languages, a sum type (also called a tagged union, variant type or discriminated union) is a data type whose values can be one of several fixed variants, each carrying data of possibly different types. A value of a sum type can only be used safely by checking which variant it holds, typically through pattern matching.

Definition

Formally, given types A and B, their sum type A + B contains all values of A and all values of B, kept distinct even if the underlying representations coincide. Each value carries a tag indicating which side of the sum it came from. Sum types are dual to product types: the number of possible values of a sum is the sum of the numbers of values of its components, whereas for products it is the product.

Examples

Sum types are central in functional languages such as Haskell, ML and Rust. In Haskell:

data Shape = Circle Float | Rectangle Float Float

Here Circle and Rectangle are constructors; a Shape is either a circle with a radius or a rectangle with two side lengths. In Rust, the same idea appears as enums, and in TypeScript as discriminated unions of object types.

The option type (Option<T> / Maybe T) and the result type (Result<T, E>) are ubiquitous sum types used to represent optional and fallible computations without null references or exceptions.

Relation to untagged unions

Unlike the untagged union of C, a sum type always knows which variant is active, making it type-safe: reading the wrong variant is a compile-time error rather than undefined behaviour. Languages without native sum types often simulate them with class hierarchies (the visitor pattern) or with a tag field plus casts, at the cost of safety or ergonomics.
