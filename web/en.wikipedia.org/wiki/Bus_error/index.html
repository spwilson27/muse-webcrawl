Bus error

In computing, a bus error is a fault raised by hardware, notifying an operating system that a process is trying to access memory that the CPU cannot physically address — an invalid address for the address bus — or memory whose access violates alignment restrictions. On POSIX systems, a bus error normally causes the operating system to deliver the signal SIGBUS to the offending process, usually terminating it with a core dump.

Causes

Non-existent address

Software instructing the CPU to read or write a specific physical address that does not correspond to installed memory or a memory-mapped device can produce a bus error. This use of "bus" refers to the address bus of the system.

Unaligned access

Many CPU architectures require multi-byte data to be placed at addresses that are multiples of the data size (natural alignment). Reading a four-byte integer from an address not divisible by four raises a bus error on architectures such as SPARC and older ARM and 68000 processors; x86 generally tolerates unaligned access in user programs, though it may be slower.

Paging errors

Accessing a memory-mapped file beyond a page boundary, or mapping a file and then truncating it, can cause accesses to fail with SIGBUS where a segmentation fault might be expected: the virtual address is validly mapped, but the underlying storage no longer backs it.

Bus error vs. segmentation fault

A segmentation fault (SIGSEGV) indicates an access to a virtual address with no valid mapping or insufficient permissions, whereas a bus error indicates a problem at a lower level: an address that exists in the address space but cannot be physically satisfied or is improperly aligned.
