Network File System

Network File System (NFS) is a distributed file system protocol originally developed by Sun Microsystems (Sun) in 1984. It allows a user on a client computer to access files over a computer network much like local storage is accessed. NFS, like many other protocols, builds on the Open Network Computing Remote Procedure Call (ONC RPC) system.

Versions

  • NFSv2 (RFC 1094, 1989) operated over UDP, was stateless, and limited files to 2 GB owing to 32-bit offsets.
  • NFSv3 (RFC 1813, 1995) added support for 64-bit file sizes, asynchronous writes, and improved error reporting, and could run over TCP.
  • NFSv4 (RFC 3010, 2000; revised by RFC 7530) introduced statefulness, stronger security including Kerberos, file locking integrated into the protocol, and a single-port design suited to firewalls. NFSv4.1 (RFC 5661) added parallel NFS (pNFS), separating metadata from data paths; NFSv4.2 (RFC 7862) added features such as server-side copy and sparse files.

Design

NFS uses a client–server model in which a server exports directories that clients mount, integrating them into their local file-system namespace. Earlier versions relied on auxiliary protocols — the Mount protocol and the Network Lock Manager — whereas NFSv4 folds these functions into the main protocol. Because the server in versions 2 and 3 was stateless, crash recovery was simple, though file locking required side protocols.

Usage

NFS became ubiquitous on Unix and Linux systems for home-directory sharing, diskless workstations, and data-centre storage, and implementations exist for virtually all operating systems, including Microsoft Windows. Typical deployment challenges include security on untrusted networks, performance over high-latency links, and consistency semantics, leading to complementary or alternative systems such as SMB, AFS, and modern cloud-based file services.
