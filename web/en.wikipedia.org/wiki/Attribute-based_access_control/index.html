Attribute-based access control

Attribute-based access control (ABAC), also known as policy-based access control, defines an access control paradigm whereby a subject's authorization to perform a set of operations is determined by evaluating attributes associated with the subject, the resource, the environment, and the action, against a set of policies, rules, or relationships that describe the allowable operations for the given set of attributes.

Concept

Unlike role-based access control (RBAC), where permissions are tied to roles, ABAC can express complex, fine-grained policies using attributes such as a user's department, clearance level, device, location, and time of access, together with properties of the resource (for example, classification or owner). Policies are typically boolean combinations of attribute conditions: a request is permitted only if the policy evaluation returns "permit". The XACML standard provides a widely used language and architecture for ABAC, with logical components such as the Policy Enforcement Point (PEP) and Policy Decision Point (PDP).

Advantages

ABAC can model RBAC policies as a special case while also supporting contextual and relationship-based rules without enumerating every permission in advance. This makes it well suited to large, dynamic enterprises and cloud environments, and it underpins "zero trust" architectures. ABAC was standardized conceptually by NIST in Special Publication 800-162 (2014), Guide to Attribute Based Access Control (ABAC) Definition and Considerations.

Drawbacks

ABAC systems can be complex to design, audit, and debug, because effective permissions are computed dynamically rather than being directly inspectable as lists; ensuring correct attribute governance across an organization is also a significant operational challenge.
