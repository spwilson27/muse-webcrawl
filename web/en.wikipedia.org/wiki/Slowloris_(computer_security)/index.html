Slowloris (computer security)

Slowloris is a type of denial of service attack tool which allows a single machine to take down another machine's web server with minimal bandwidth and side effects on unrelated services and ports.

Slowloris tries to keep many connections to the target web server open and hold them open as long as possible. It accomplishes this by opening connections to the target web server and sending a partial request. Periodically, it will send subsequent HTTP headers, adding to — but never completing — the request. Affected servers will keep these connections open, filling their maximum concurrent connection pool, eventually denying additional connection attempts from clients.

History

The program and the attack technique were created by Robert "RSnake" Hansen, who first discussed it in 2009. The name "Slowloris" is a pun on the slow loris, a primate known for its slow movement and large eyes. The attack gained wider notice when tools using the same technique, such as those built into later frameworks, were used in real attacks against large websites.

How it works

Traditional denial-of-service attacks flood a server with traffic. Slowloris instead exploits the behaviour of threaded web servers: many servers allocate a connection thread to each HTTP request and hold it until a complete request has been received or a timeout expires. By sending a syntactically valid but incomplete HTTP request — for example, a request line and a few headers, but never the blank line that terminates the headers — the attacker causes the server to wait. By periodically sending one more header line, the attacker keeps each connection alive indefinitely while consuming almost no bandwidth.

Hundreds of such connections exhaust the server's connection pool. Legitimate users are then unable to connect, even though the server is otherwise idle and network bandwidth is unconsumed. Because the attack uses valid HTTP traffic at very low rates, it can be difficult to detect with conventional rate-based intrusion detection.

Affected servers

Threaded servers that wait for complete requests, such as older configurations of the Apache HTTP Server, were notably vulnerable. Servers using event-driven architectures, or those which time out incomplete requests aggressively, are much less affected. The similar "Slow POST" variant sends a complete header with a declared body length, then transmits the body extremely slowly.

Mitigation

  • Configure minimum data rates and short timeouts for incomplete requests and headers.
  • Limit the number of connections per IP address.
  • Place the web server behind a reverse proxy or load balancer that absorbs incomplete requests.
  • Use modules such as Apache's mod_reqtimeout or mod_qos.
  • Prefer event-based server architectures (e.g. nginx) for public-facing endpoints.
