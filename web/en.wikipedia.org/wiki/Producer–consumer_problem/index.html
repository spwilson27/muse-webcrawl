Producer–consumer problem

In computing, the producer–consumer problem (also known as the bounded-buffer problem) is a classic example of a multi-process synchronization problem, first described by Edsger W. Dijkstra. The problem describes two processes, the producer and the consumer, who share a common, fixed-size buffer used as a queue. The producer's job is to generate data, put it into the buffer, and start again. At the same time, the consumer is consuming the data (i.e., removing it from the buffer), one piece at a time.


A bounded buffer mediates between producer and consumer.

The problem

The solution must ensure that the producer will not try to add data into the buffer if it is full, and that the consumer will not try to remove data from an empty buffer. It must also prevent race conditions in which both processes manipulate the buffer's state simultaneously, corrupting it.

Solutions

Dijkstra's solution uses semaphores: one counting semaphore tracks empty slots, another tracks filled slots, and a mutex protects the buffer itself. The producer waits on the "empty" semaphore before adding an item and signals "full" afterwards; the consumer does the reverse. Equivalent solutions can be built with monitors or message passing. Careless semaphore ordering can lead to deadlock, making the problem a standard teaching example in operating systems courses.
