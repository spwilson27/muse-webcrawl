Materialized view

In computing, a materialized view is a database object that contains the results of a query. It is a form of cache: unlike an ordinary view, which is a virtual table computed on demand each time it is accessed, a materialized view stores the query result physically as actual data, much like the contents of a table.

Purpose

Materialized views are used to speed up expensive or frequently run queries, particularly aggregations over large tables in data warehouses, and to replicate data to remote sites in distributed databases. By pre-computing and storing the result, the database avoids repeating costly joins and aggregations at query time. Query optimizers in systems such as Oracle Database can automatically rewrite queries to use a suitable materialized view.

Maintenance

Because the stored result becomes stale when the underlying data changes, materialized views must be refreshed. Refresh strategies include complete refresh (recomputing the whole result) and incremental or "fast" refresh (applying only the changes recorded in materialized view logs). Refreshes may occur on a schedule, on demand, or immediately on commit of a transaction, trading freshness against update cost. Materialized views are supported by many systems, including Oracle, PostgreSQL (without built-in incremental refresh), Microsoft SQL Server (as indexed views), and various data-warehouse and streaming platforms.
