Static program analysis

Static program analysis (also simply referred to as static analysis, although that term is shared by other disciplines) is the analysis of computer programs performed without executing them, in contrast with dynamic program analysis, which is performed on programs during their execution.

The term is usually used in contrast with dynamic analysis, in which the analysis is performed on a program as it runs, and it is possible to use information from the environment the program is running in. In most cases the analysis is performed on some version of a program's source code, and in other cases on some form of its object code. The sophistication of the analysis performed by tools varies from those that only consider the behaviour of individual statements and declarations, to those that include the complete source code of a program in their analysis.

Uses

Uses of the information obtained from static analysis include:

  • Type checking — a form of static analysis in which the program is checked to ensure that operations are applied to values of appropriate types.
  • Style and programming errors — detecting code that does not conform to a style guide or that contains suspicious constructs, such as unused variables.
  • Program understanding — helping developers understand large code bases by extracting documentation and relationships.
  • Security review — searching for vulnerabilities such as buffer overflows and injection flaws before deployment.

Data-flow analysis

Data-flow analysis is a technique for gathering information about the possible set of values calculated at various points in a computer program. A program's control-flow graph (CFG) is used to determine those parts of a program to which a particular value assigned to a variable might propagate. The information gathered is often used by compilers when optimizing a program. A canonical example of a data-flow analysis is reaching definitions.

Abstract interpretation

A well-known approach to formal static analysis is abstract interpretation, developed in the late 1970s by Patrick Cousot and Radhia Cousot. It is based on the idea of executing the program over an abstract domain that safely over-approximates the concrete semantics, so that properties proven about the abstraction hold for the real program. Tools built on abstract interpretation, such as Astrée, have been used to prove the absence of run-time errors in safety-critical avionics software.

Limitations

By Rice's theorem, it is impossible for any static analyser to always correctly decide non-trivial semantic properties of arbitrary programs, such as whether a program terminates. Practical tools therefore trade off soundness (no false negatives) against completeness (no false positives), and analyses are typically either conservative approximations or bug-finding heuristics that may miss defects.

Tools

Well-known static analysis tools include Lint (one of the earliest, for C, originating at Bell Labs in 1978), Coverity, Klocwork, PVS-Studio, SonarQube, FindBugs/SpotBugs for Java, ESLint for JavaScript, and the analyzers built into compilers such as Clang and GCC.
