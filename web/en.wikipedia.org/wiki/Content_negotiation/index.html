Content negotiation

In computing, content negotiation refers to mechanisms defined as part of HTTP that make it possible to serve different versions of a document (or representations of a resource) at the same URI, so that user agents can specify which version fits their capabilities best. The best-known example is choosing the natural language of a web page, but negotiation also covers media type, character encoding and content encoding such as compression.

Mechanisms

In server-driven negotiation, the client sends request headers — Accept, Accept-Language, Accept-Charset and Accept-Encoding — possibly with quality values (q-values), and the server selects a representation, responding with Vary to inform caches. In agent-driven negotiation, the server responds with a list of alternatives (for example with status 300 Multiple Choices) and the client makes the choice. A third approach, transparent content negotiation, combines the two.

Use in APIs

Web APIs commonly use the Accept header to choose between JSON, XML and other serializations of the same resource, a practice central to REST-style design. If no offered representation is acceptable, a server may return 406 Not Acceptable.
