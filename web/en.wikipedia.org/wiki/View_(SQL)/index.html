View (SQL)

In a database, a view is the result set of a stored query. A view is a virtual table that is defined by a query and can be referenced like a normal table in subsequent queries. Unlike ordinary tables, a view does not store data itself (in most database systems); instead, the data is computed each time the view is queried. Views can join and simplify multiple tables into a single virtual table, and can act as aggregated tables, where the database engine aggregates data (sums, averages, and so on) and presents the calculated results as part of the data.

A view presents the result of a stored query as a virtual table

Creation

A view is created with the CREATE VIEW statement:

CREATE VIEW employee_details AS
SELECT e.id, e.name, d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.id;

Once created, the view can be queried as though it were a table: SELECT * FROM employee_details;

Advantages

Views simplify complex queries by encapsulating joins and calculations; provide a layer of abstraction and security by restricting access to specific columns or rows; ensure a consistent, unchanged view of the structure of the database even if underlying tables are split or restructured; and can present data in a different format or with calculated values to applications.

Read-only and updatable views

Not all views are updatable. Views based on a single table without aggregates or distinct clauses can often accept INSERT, UPDATE and DELETE operations, whereas views involving joins, groupings or set operations are generally read-only. A materialized view, by contrast, physically stores the result set and is refreshed periodically.
