Copy elision

In C++ computer programming, copy elision is a compiler optimization technique that eliminates unnecessary copying of objects. The best-known form is the return value optimization (RVO), in which a function returning an object by value constructs the result directly in the caller's storage rather than creating a temporary and copying or moving it.

Forms

In unnamed RVO, a function returns a temporary object, and the compiler constructs it in place. In the named return value optimization (NRVO), the returned object is a local variable; most compilers perform this optimization as well, though it historically was not guaranteed. Copy elision may also apply when a temporary is passed by value or thrown as an exception.

Language rules

Copy elision is unusual among optimizations because it can change observable behaviour: the skipped copy or move constructor and destructor may have side effects that then do not occur. For that reason the standard explicitly permits it even when the constructor has side effects. Since C++17, elision is guaranteed in certain cases — returning a prvalue of the same type — through revised value-category rules, and no copy or move constructor need even be accessible in those cases.

Interaction with move semantics

Where elision is not performed, move semantics (introduced in C++11) reduce the cost of the remaining transfers by moving resources out of temporaries instead of copying them.
