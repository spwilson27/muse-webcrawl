Isolation (database systems)

In database systems, isolation is one of the four ACID properties of transactions. It determines how and when changes made by one transaction become visible to concurrent transactions, ensuring that concurrently executing transactions do not interfere with each other and that the database remains consistent.

Isolation controls the visibility of concurrent transactions.

Isolation levels

The SQL standard defines four isolation levels, in increasing order of strictness: read uncommitted, read committed, repeatable read and serializable. Weaker levels allow phenomena such as dirty reads, non-repeatable reads and phantom reads, but offer better concurrency and performance; serializable isolation guarantees that concurrent transactions produce the same result as some serial execution.

Implementation

Isolation is typically implemented with locking (two-phase locking) or with multiversion concurrency control (MVCC), in which readers access snapshots of the data. Many modern systems default to read committed or snapshot isolation.
