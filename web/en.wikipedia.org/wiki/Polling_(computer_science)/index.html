Polling (computer science)

Type: Synchronisation / control scheme

Alternative: Interrupt-driven I/O

Polling, or a polled operation, in computer science is the process by which a program or device repeatedly checks the status of an external device or resource until it is ready or until a condition is met. A processor engaged in polling samples the state of a peripheral at regular intervals — for example, testing a status flag to see whether a keyboard has a key press waiting or whether a network interface has received a packet.

Comparison with interrupts

The main alternative to polling is interrupt-driven processing, in which the external device signals the processor only when it needs attention. Polling is simple to implement and gives predictable timing, which suits simple embedded systems and hard real-time loops. Its disadvantages are wasted processor cycles spent checking devices that are not ready (sometimes called a "busy wait") and higher latency in responding, bounded by the polling interval. Interrupts are generally more efficient but introduce complexity: asynchronous handling, re-entrancy concerns and interrupt latency of their own.

Polling in networks and software

In client–server systems, clients often poll a server for updates — for example, an email client periodically asking for new mail, or a web application repeatedly requesting the state of a long-running job. Polling over networks trades freshness against load: frequent polls waste bandwidth and server capacity, a problem mitigated by techniques such as long polling, in which the server holds a request open until data is available, and by push mechanisms such as WebSockets.

Roll call polling

In multi-drop communication networks, roll call polling is a scheme in which a central controller invites each terminal in turn to transmit, ensuring orderly access to a shared medium.
