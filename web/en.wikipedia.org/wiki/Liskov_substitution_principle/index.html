Liskov substitution principle

The Liskov substitution principle (LSP) is a particular definition of a subtyping relation, called (strong) behavioural subtyping, that was initially introduced by Barbara Liskov in a 1987 conference keynote address titled Data abstraction and hierarchy. It was later formalised by Liskov and Jeannette Wing in a 1994 paper. The principle states that objects of a superclass should be replaceable with objects of any of its subclasses without breaking the correctness of the program.

Formulation

Liskov and Wing's formal statement reads: "Let φ(x) be a property provable about objects x of type T. Then φ(y) should be true for objects y of type S where S is a subtype of T." In practical terms, a subtype must preserve the observable behaviour of the supertype: it must not strengthen preconditions of inherited methods, must not weaken their postconditions, must preserve invariants of the supertype, and must not throw new exceptions not allowed by the base methods.

Example and violations

The classic illustration is the circle–ellipse (or square–rectangle) problem: although a circle is mathematically a special ellipse, a mutable Circle class cannot safely substitute for a mutable Ellipse class whose width and height can be set independently, because setting the ellipse's width alone would break the circle's invariant that its axes are equal. Similarly, a class modelling ducks that throws an exception when asked to fly, if flightless, violates the principle if clients of the base class expect flight always to succeed.

Relation to SOLID

LSP is the "L" of Robert C. Martin's SOLID mnemonic for object-oriented design principles, alongside the single-responsibility, open–closed, interface-segregation, and dependency-inversion principles. Violations are often detected by code smells such as type-checking and downcasting in client code, empty or exception-throwing overrides, and overridden methods that return null where the base contract does not allow it.
