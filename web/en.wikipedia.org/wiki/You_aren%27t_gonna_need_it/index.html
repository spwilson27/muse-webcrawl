You aren't gonna need it

AcronymYAGNI
FieldSoftware engineering
OriginExtreme Programming (XP) community, late 1990s
Related principlesKISS, DRY, minimal viable product

"You aren't gonna need it" (YAGNI) is a principle of software development originating in Extreme Programming: a programmer should not add functionality until it is actually necessary. It counters speculative generality — building features, abstractions, or configurability in anticipation of future requirements that may never arrive.

Rationale

Unneeded code carries costs: it takes time to build, test, document and maintain, adds complexity that makes the needed parts harder to change, and is frequently built on wrong assumptions about the future. Delaying implementation until a real requirement exists keeps options open and designs simpler.

Scope and limits

YAGNI applies to speculative features, not to good design habits or cheap structural choices made while implementing a present need. It complements refactoring: because code can be changed later, there is less need to guess the future up front.
