Denormalization

Denormalization is a strategy used on a previously-normalized database to increase performance. In computing, denormalization is the process of trying to improve the read performance of a database, at the expense of losing some write performance, by adding redundant copies of data or by grouping data.

Motivation

A normalized design often requires joins between many tables to answer a query. When queries are frequent and joins expensive, database designers may deliberately reintroduce redundancy — for example, storing a customer's name on each order record — so that common read operations avoid joins. Denormalization is typically applied after database normalization has produced a clean logical design, and only where performance measurements justify it.

Techniques

  • Adding redundant columns duplicated from another table
  • Storing derived or precomputed values, such as totals
  • Joining tables together into a single wide table
  • Maintaining summary tables and materialized views

Trade-offs

Denormalized databases can suffer from update anomalies: if a copied value changes, every copy must be updated consistently. Write operations become slower and the design is harder to modify. Denormalization is therefore a deliberate trade-off of data integrity risk and write cost for read speed, and is common in data warehousing, reporting systems, and NoSQL designs.
