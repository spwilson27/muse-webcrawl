Transactional Synchronization Extensions

Transactional Synchronization Extensions (TSX) is an extension to the x86 instruction set architecture that adds hardware transactional memory support, speeding up the execution of multi-threaded software through lock elision. It was introduced by Intel in 2013 with the Haswell microarchitecture.

Instruction sets

TSX provides two software interfaces. Hardware Lock Elision (HLE) adds instruction prefixes (XACQUIRE and XRELEASE) that can be applied to existing locked instructions, allowing the processor to elide the lock when no conflict occurs while retaining compatibility with processors that lack the feature. Restricted Transactional Memory (RTM) adds new instructions — XBEGIN, XEND and XABORT — with which programmers can directly define transactional regions of code.

Operation

When a transaction executes, the processor tracks the memory it reads and writes. If another processor accesses conflicting data, one of the transactions is aborted and its changes discarded, and execution falls back to a conventional lock path. This allows programs written around coarse-grained locks to run with much finer effective concurrency.

History and issues

Shortly after launch, a bug in the Haswell implementation led Intel to disable TSX on affected processors via microcode update in 2014; it was re-enabled in later generations. In 2021 further microcode updates disabled TSX on many Skylake-generation processors, partly in response to security issues such as the TAA (TSX Asynchronous Abort) side-channel vulnerability.
