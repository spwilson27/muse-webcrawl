Point-free programming

Illustration of functions composed as a pipeline without named arguments

Point-free programming, also called tacit programming, is a programming paradigm in which function definitions do not identify the arguments (or "points") on which they operate. Instead, programs are constructed by combining other functions through operations such as function composition and combinators.

Examples

In Haskell, the function that sums a list might be written pointfully as sum xs = foldr (+) 0 xs, but point-free as sum = foldr (+) 0. Similarly, f x = g (h x) becomes f = g . h. The style is natural in concatenative languages such as Forth and Joy, and in array languages such as APL and J, and can be used in many functional languages.

Discussion

Advocates argue that point-free definitions can be concise and can make equational reasoning about programs easier, since they emphasise the algebra of functions themselves. Critics note that heavily point-free code can be difficult to read, sometimes jokingly calling it "pointless" style. The term derives from topology, where a "point-free" treatment of spaces avoids reference to individual points.
