Object composition

In computer science, object composition is a way to combine simple objects or data types into more complex ones. A composite object has one or more component objects, references them, and typically delegates work to them, in contrast to inheritance, in which a class is a subtype of another class.

Kinds of composition

Two broad forms are usually distinguished. In aggregation, the component objects can exist independently of the whole (a department has professors, but the professors exist whether or not the department does). In composition in the strict sense, the parts are created and destroyed with the whole and cannot be shared (a house has rooms that cease to exist if the house is demolished). Unified Modeling Language diagrams mark the strict form with a filled diamond on the whole's end of the relationship line.

Composition over inheritance

The design principle "favor composition over inheritance", popularized by the 1994 book Design Patterns, holds that reusing behavior by composing objects is usually preferable to inheriting it. Inheritance couples a subclass tightly to its parent and can force it to inherit unwanted behavior (the fragile base class problem), whereas composition keeps components black-box and interchangeable: a class can swap one component for another with the same interface at runtime.

Composition is the mechanism behind several common design patterns, including Strategy, Decorator, and Adapter, and it underlies entity–component architectures in game development, where entities are assembled from mix-and-match components rather than placed in deep class hierarchies.
