Container (virtualization)

In computing, a container is a standard unit of software created by OS-level virtualization that packages code and all its dependencies so an application runs quickly and reliably from one computing environment to another. Unlike a virtual machine, which virtualises hardware and runs a full guest operating system under a hypervisor, containers share the host operating system's kernel and isolate processes from one another, making them much lighter in resource use and faster to start.

Technology

On Linux, container isolation is built principally from two kernel features: namespaces, which limit what a process can see (process IDs, network interfaces, mount points, users, and so on), and control groups (cgroups), which limit, account for and isolate resource usage such as CPU, memory and I/O. A container image is a file system snapshot containing the application and its runtime, libraries and settings; images are layered and shared between containers.

History

The concept developed through Unix chroot (1979), FreeBSD jails (2000), Solaris Containers/Zones (2004), OpenVZ, and Linux efforts including LXC (2008). Google's internal systems (Borg) shaped modern orchestration. Docker, released as open source in 2013, popularised containers by providing a developer-friendly image format, tooling and registry ecosystem. The Open Container Initiative (OCI), founded in 2015, standardised image and runtime specifications. Kubernetes, open-sourced by Google in 2014, became the dominant container orchestration platform for scheduling, scaling and self-healing containerised workloads.

Comparison with virtual machines

  • Overhead: containers share the kernel and need no guest OS, so they start in seconds and use less memory.
  • Isolation: hypervisors provide a stronger hardware-level boundary; containers rely on kernel namespaces and are generally considered a weaker security boundary.
  • Portability: container images run on any host with a compatible kernel and runtime, while VMs package an entire machine image.

Use

Containers underpin microservices architectures, continuous integration and deployment pipelines, and much cloud-native computing. Popular tools include Docker Engine, containerd, Podman, and orchestration systems such as Kubernetes and Docker Swarm.
