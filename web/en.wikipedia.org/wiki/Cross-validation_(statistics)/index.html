Cross-validation, sometimes called rotation estimation or out-of-sample testing, is any of various similar model validation techniques for assessing how the results of a statistical analysis will generalize to an independent data set. Cross-validation is a resampling method that uses different portions of the data to test and train a model on different iterations. It is mainly used in settings where the goal is prediction, and one wants to estimate how accurately a predictive model will perform in practice.

In a prediction problem, a model is usually given a dataset of known data on which training is run (training dataset), and a dataset of unknown data (or first seen data) against which the model is tested (called the validation dataset or testing set). The goal of cross-validation is to test the model's ability to predict new data that was not used in estimating it, in order to flag problems like overfitting or selection bias and give insight on how the model will generalize to an independent dataset.

Motivation

When a model is fitted to data, maximizing a fit criterion such as likelihood tends to overfit: the model may describe random noise rather than the underlying relationship. Cross-validation addresses this by evaluating the model on data it did not see during fitting. A single holdout estimate depends heavily on which observations happen to land in the test set, so averaging over many splits gives a more stable estimate of out-of-sample performance.

Common types

Holdout method

The simplest approach partitions the data once into a training set and a test set. It is fast but its estimate has high variance and wastes data.

K-fold cross-validation

The original sample is randomly partitioned into k equal-sized subsamples (folds). Of the k subsamples, a single subsample is retained as the validation data for testing the model, and the remaining k − 1 subsamples are used as training data. The process is repeated k times, with each of the k subsamples used exactly once as the validation data. The k results are then averaged. Ten-fold cross-validation is a common choice, and stratified variants preserve class proportions in classification problems.

Leave-one-out and leave-p-out

Leave-one-out cross-validation (LOOCV) is the limiting case where each single observation forms the validation set in turn. It has low bias but can have high variance and is computationally demanding for models that are expensive to refit; for many parametric models closed-form shortcuts exist.

Nested cross-validation

When cross-validation is used both to tune hyperparameters and to estimate generalization error, the two uses must be separated: an outer loop estimates performance while an inner loop selects hyperparameters. Using one loop for both tasks produces optimistically biased estimates.

Time-series variants

For temporal data, random folds leak future information into training; rolling-origin (forward-chaining) splits, in which training always precedes testing in time, are used instead.

Statistical analysis

Cross-validation estimates the expected out-of-sample error of a fitting procedure. Its variability is a subject of active study; naive variance estimates that ignore the overlap between training sets understate uncertainty. Cross-validation is used to choose model complexity — for example the number of neighbors in k-nearest-neighbors or the penalty parameter in regularized regression — and forms the basis of model-selection criteria implemented in most machine-learning libraries.

Misuse and leakage

Common errors include performing feature selection or data cleaning on the whole dataset before splitting (target leakage), applying cross-validation after tuning on the same folds and reporting the tuned score as the generalization estimate, and using ordinary folds for clustered or time-ordered data. Correct practice places every data-dependent step inside the resampling loop.
