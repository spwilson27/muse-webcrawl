Magnet URI scheme

TypeURI scheme / de facto standard
Introduced2002
IdentifiesContent by cryptographic hash rather than location
Primary useBitTorrent and other peer-to-peer networks

The magnet URI scheme defines a format for links that identify a resource — typically a file available through a peer-to-peer network — by its content, using a cryptographic hash value, rather than by its location on a server. Clicking a magnet link (beginning magnet:?xt=urn:btih:…) tells a client application what content to look for; the client then discovers sources for that content through mechanisms such as distributed hash tables and peer exchange.

Format

A magnet link is a query string of parameters. The essential one is xt ("exact topic"), whose value is a URN containing the content hash — for BitTorrent, the SHA-1 hash of the torrent's info dictionary (urn:btih:), encoded in hexadecimal or base32, with newer v2 torrents using SHA-256 (urn:btihm:). Optional parameters add a display name (dn), file length (xl), tracker addresses (tr) and keyword or source hints.

History and significance

The scheme was developed from work by Bram Cohen and others in 2002, drawing on earlier hash-based linking proposals in the Gnutella community. Magnet links rose to prominence as torrent index sites moved away from hosting .torrent files: in 2012 The Pirate Bay replaced most hosted torrents with magnet links, dramatically shrinking the site's data footprint and making indexes harder to suppress, since a magnet link contains no copyrighted data itself and the actual metadata is fetched from the swarm via protocols such as µTP and the metadata exchange extension (BEP 9). Magnet links are supported by all major BitTorrent clients and also underpin "trackerless" operation through the Mainline DHT.
