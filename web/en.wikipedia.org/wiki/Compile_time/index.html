Compile time

From Wikipedia, the free encyclopedia

In computer programming, compile time is the period during which a compiler processes source code and translates it into a lower-level form (such as object code, bytecode or machine code), or, by extension, the set of properties and operations that are determined during that process. It contrasts with run time, when the resulting program is actually executed.

Compile-time concepts

Many programming-language features operate at compile time. Compile-time type checking in statically typed languages verifies that expressions are used consistently with their declared types before the program ever runs, catching a class of errors early. Compile-time constants and constant expressions can be evaluated by the compiler and folded into the generated code. Some languages provide deliberate facilities for compile-time computation, such as C++ templates and constexpr, Rust's const fn, D's compile-time function execution, and Lisp-family macros, which generate code during compilation.

Errors and optimisation

Problems detected during compilation — syntax errors, type errors, undeclared identifiers — are called compile-time errors and prevent the program from being built, in contrast to runtime errors, which occur while the program executes. Compilers also perform optimisations at compile time, trading longer build times for faster or smaller programs; techniques such as just-in-time (JIT) compilation blur the distinction by postponing some compilation until run time.

Practical considerations

Long compile times slow development, so large projects use incremental compilation, caching (for example ccache), distributed builds and modular design to reduce them. In embedded and safety-critical development, predictable compile-time behaviour and compile-time checking are valued for the errors they eliminate before deployment.
