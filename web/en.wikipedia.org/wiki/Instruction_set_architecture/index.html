Instruction set architecture

From Wikipedia, the free encyclopedia


The ISA is the interface between software and hardware.

An instruction set architecture (ISA) is an abstract model of a computer, also referred to as computer architecture in this sense. A realisation of an ISA is called an implementation. The ISA serves as the boundary between software and hardware: it defines the machine language that compilers target and that processors execute, including the instruction set, registers, addressing modes, data types, memory model, and interrupt and exception handling visible to the programmer.

Components

An ISA specification typically defines: the set of opcodes and instruction formats; the general-purpose and special registers; the sizes and representations of data types (integers, floating point, vectors); addressing modes for computing operand addresses; the memory consistency model; input/output mechanisms; and the privileged architecture (system instructions, interrupt behaviour) used by operating systems.

Classification

ISAs are classified by complexity into CISC (complex instruction set computer) designs, with many specialised, variable-length instructions, and RISC (reduced instruction set computer) designs, with small, regular, load–store instruction sets favouring pipelining. Other classes include VLIW (very long instruction word), EPIC, and vector architectures. They are also classified by operand model (accumulator, stack, register–memory, register–register), word size (8, 16, 32, 64 bits), and endianness.

Implementations and compatibility

One ISA may have many implementations differing in performance and cost: IBM System/360 (1964) pioneered the idea of a compatible family spanning price points, with microcode hiding implementation details. Modern examples include x86-64 (implemented by Intel and AMD, internally translating to micro-operations), ARM (licensed to many manufacturers), the open RISC-V ISA, MIPS, Power, and SPARC. Binary compatibility with an established ISA is a powerful commercial lock-in, which emulation and dynamic binary translation seek to break.

Extensions

ISAs evolve through extensions: x86 added MMX, SSE, and AVX vector extensions; ARM added NEON and SVE; RISC-V is explicitly modular, with a base ISA plus standard and custom extensions. Extensions must preserve backward compatibility, so successful ISAs accrete features for decades.
