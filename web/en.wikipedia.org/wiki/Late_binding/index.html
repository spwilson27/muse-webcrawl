Late binding

In computer programming, late binding — also called dynamic binding or dynamic linkage — is a mechanism in which the method, function, or property being called on an object is looked up by name at run time rather than being fixed at compile time. Late binding is closely associated with dynamic typing, polymorphism, and object-oriented programming, where the same message sent to objects of different classes can invoke different implementations. By contrast, in early binding (or static binding) the association between a name and its implementation is determined when the code is compiled or linked.

With late binding, the implementation invoked is selected when the program runs.

Uses

Late binding enables behaviour such as:

  • Polymorphism: a variable declared with a base type can hold objects of any subclass, and calls to an overridden (virtual) method dispatch to the subclass implementation at run time, typically via a virtual method table.
  • Duck typing: in dynamically typed languages such as Python, Ruby, and JavaScript, any object with the right method can be used, regardless of its class.
  • Reflection and plug-ins: programs can load classes or components unknown at compile time and invoke their members by name, as in COM Automation, where IDispatch calls are resolved at run time.
  • Dynamic libraries: functions in shared libraries may be linked when the program starts or even when first called (lazy binding), rather than at compile time.

Trade-offs

Late binding offers flexibility and extensibility, and supports features such as hot-swapping components and scripting, but it generally carries a run-time cost: method lookups add overhead, and the compiler cannot perform some optimisations or type checks, so errors that early binding would catch at compile time may surface only when the program runs. In practice, many languages and platforms mix both strategies — for example, C++ uses early binding by default and late binding for virtual functions, while Java binds instance methods dynamically by default and resolves overloaded methods at compile time.

History

The term "late binding" gained currency with the rise of object-oriented languages such as Smalltalk in the 1970s, in which all message sends are dynamically dispatched. It was widely popularised in the 1990s through Microsoft's Component Object Model (COM) and Visual Basic documentation, where late binding described creating and calling objects (for example, through CreateObject and IDispatch) without a compile-time reference to their type libraries.
