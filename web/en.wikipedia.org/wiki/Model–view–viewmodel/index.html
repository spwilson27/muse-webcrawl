Model–view–viewmodel

Model–view–viewmodel (MVVM) is a software architectural pattern that facilitates the separation of the development of a graphical user interface (the view) from the development of the business logic or back-end logic (the model). The intermediate component, the viewmodel, exposes the data and commands of the model in a form the view can bind to.

Components

  • Model — the data and business logic of the application, as in MVC.
  • View — the visual elements and layout; it observes the viewmodel and renders its state.
  • Viewmodel — an abstraction of the view that exposes public properties and commands; a binder (data-binding engine) synchronises the view with the viewmodel, typically in both directions.

History

MVVM was invented by Microsoft architects Ken Cooper and Ted Peters specifically to target the data-binding capabilities of Windows Presentation Foundation (WPF) and Silverlight, and was publicly described by John Gossman in 2005. It is a variant of Martin Fowler's Presentation Model pattern.

Use

The pattern is standard in WPF, UWP, .NET MAUI and Xamarin applications, and closely related ideas appear in JavaScript frameworks such as Knockout, Angular and Vue, and in Android's architecture components. By removing nearly all GUI code from the viewmodel, it enables designers and developers to work in parallel and makes presentation logic readily testable.

Criticism

Critics note that for simple interfaces MVVM can add considerable boilerplate, and that heavy reliance on data binding can make behaviour harder to trace and debug.
