Saved game

Save points are a common way of creating saved games.

A saved game (also called a game save, savegame, save file, save point, or simply save) is a piece of digitally stored information about the progress of a player in a video game. From the earliest games, storing progress allowed players to resume long games across multiple sessions; as games grew longer and more complex, saving became a standard and expected feature.

A saved game is usually stored on the player's device — originally in battery-backed memory within a game cartridge, later on memory cards, hard drives, and solid-state storage — or, in modern systems, synchronised to cloud storage so that progress follows the player between machines.

History

Early arcade games held no persistent state, and early home computer games relied on passwords: strings of characters encoding the player's progress, which the player wrote down and re-entered. Battery-backed RAM in cartridges such as The Legend of Zelda (1986) allowed genuine save files on console. Home computer games on floppy disks allowed players to save freely to disk. The PlayStation's removable memory cards (1994) made save files portable between consoles. Modern platforms provide automatic cloud saves through services such as Steam Cloud, PlayStation Plus, and Xbox network saves.

Mechanisms

Save points and checkpoints

Some games restrict saving to designated locations (save points) or moments (checkpoints, often reached automatically). This design preserves tension and prevents the player from saving immediately before every risky action. Survival horror games such as Resident Evil famously combined save points with a limited supply of ink ribbons, making each save a resource decision.

Quicksave and autosave

Many PC games allow quicksaving: creating a save at any moment with a single keystroke, conventionally F5, with F9 for quickloading. Autosave stores progress automatically at intervals or milestones without player action. The ability to save anywhere has been debated by designers: it removes frustration but can allow "save scumming" — repeatedly reloading until a random or difficult action succeeds.

Permadeath

In contrast, roguelike games and "ironman" or "hardcore" modes delete or invalidate the save file when the player character dies, making every decision permanent. Permadeath is a defining feature of the roguelike genre, descending from Rogue (1980).

Save files and sharing

Save files vary from a few kilobytes to hundreds of megabytes. Players share save files to skip difficult sections, unlock content, or distribute scenarios and editor creations. Because save data is player-controlled, it is also a vector for cheating and exploits, such as save editing and duplication glitches; competitive and online games therefore validate saves server-side. Save files may become incompatible across game patches, and corrupted saves are a recurring source of player data loss, mitigated by rotating multiple autosave slots.

Design considerations

Save systems shape how a game is played: generous saving encourages experimentation, while restricted saving builds suspense and weight. Designers also use saves to structure sessions, marking natural stopping points. Accessibility discussions have increasingly favoured flexible save options, since restrictive systems can exclude players who cannot play for long uninterrupted periods.
