OAuth

OAuth (short for "Open Authorization") is an open standard for access delegation, commonly used to grant websites or applications access to a user's information on another service without sharing the user's password. Instead of credentials, the user authorises the third party to act with limited scope, and the service issues access tokens. OAuth underlies the familiar "Sign in with Google" and "Log in with Facebook" buttons, though identity itself is layered on top by protocols such as OpenID Connect.

History

OAuth began in 2006–2007, when developers from Twitter, Ma.gnolia, and Google sought a common way to let third-party clients access APIs on a user's behalf. OAuth 1.0 was published as RFC 5849 in 2010 and relied on cryptographic request signing. OAuth 2.0, published in October 2012 as RFC 6749, replaced the signing scheme with bearer tokens sent over HTTPS and defined several "grant types" (flows) for different client situations, becoming far more widely adopted — and frequently criticised as more of a framework than a strict protocol.

How it works

Four roles take part: the resource owner (the user), the client (the third-party application), the authorization server (which issues tokens after user consent), and the resource server (the API hosting the data). In the most common flow, the authorization code grant, the client redirects the user to the authorization server; after the user consents, the server returns a short-lived code which the client exchanges — authenticated with its own client secret — for an access token. Later extensions such as PKCE (Proof Key for Code Exchange) secure the flow for mobile and browser-based applications, and OAuth 2.1 consolidates these best practices.
