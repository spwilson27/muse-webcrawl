Distributed tracing

A trace visualised as a set of timed spans across multiple services.

Distributed tracing, also called distributed request tracing, is a method used to profile and monitor applications built using a microservices architecture. It helps pinpoint where failures occur and what causes poor performance by following a request as it propagates through the services that make up an application.

Concepts

A trace represents the end-to-end journey of a single request or transaction. Each trace is composed of spans, which are timed units of work performed by a service; spans can be nested to show parent–child relationships. A unique trace identifier is propagated between services, usually in HTTP headers, so that spans emitted by different processes can be assembled into a single trace. This propagation is standardised by the W3C Trace Context specification.

History and tooling

The approach was popularised by Google's Dapper system, described in a 2010 paper, which inspired open-source implementations such as Zipkin and Jaeger. The OpenTracing and OpenCensus projects later merged into OpenTelemetry, a vendor-neutral observability framework providing APIs and SDKs for generating and exporting trace data.

Use

Distributed tracing is one of the "three pillars" of observability, alongside metrics and logging. It is used to measure latency across service boundaries, diagnose bottlenecks, and understand dependencies between services in complex systems.
