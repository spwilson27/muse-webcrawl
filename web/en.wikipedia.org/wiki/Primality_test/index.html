Primality test

A primality test is an algorithm for determining whether an input number is prime. Among other fields of number theory, it is used for cryptography. Unlike integer factorization, primality tests do not generally give prime factors, only stating whether the input number is prime or not. Factorization is thought to be a computationally difficult problem, whereas primality testing is comparatively easy (its running time is polynomial in the size of the input). Some primality tests prove that a number is prime, while others, like Miller–Rabin, prove that a number is composite and are therefore called probabilistic tests.

Simple methods

The simplest primality test is trial division: given an input number n, check whether it is evenly divisible by any prime number between 2 and √n (i.e., that the division leaves no remainder). If so, then n is composite. Otherwise, it is prime. For example, to test whether 211 is prime, one divides it by 2, 3, 5, 7, 11 and 13; none divides it evenly, and since 17² = 289 > 211 testing can stop, so 211 is prime.

Trial division can be improved with a wheel, for instance testing only numbers coprime to the first few primes. Nevertheless, trial division is exponential in the number of digits of n and is impractical for numbers with hundreds of digits.

Probabilistic tests

Probabilistic tests are based on properties that primes satisfy but composites usually do not. The Fermat primality test uses Fermat's little theorem: if p is prime and a is not divisible by p, then

ap−1 ≡ 1 (mod p).

Composites that pass for a given base are called Fermat pseudoprimes; Carmichael numbers pass for every base coprime to them. The Miller–Rabin test strengthens this idea by writing p − 1 = 2s·d and examining the sequence of square roots of 1 modulo p; it has no Carmichael-like counterexamples and, repeated k times, errs with probability at most 4−k. In practice Miller–Rabin (often combined with small trial division) is the standard method used by computer algebra systems and cryptographic libraries.

Other probabilistic tests include the Solovay–Strassen test, based on the Euler criterion, and the Lucas and Frobenius pseudoprime tests; the Baillie–PSW test combines a Miller–Rabin test with a Lucas test and has no known counterexamples.

Fast deterministic tests

For numbers below fixed bounds, deterministic variants of Miller–Rabin with a small fixed set of bases are exact; for example, testing seven specific bases is correct for all 64-bit integers. The AKS primality test, published in 2002 by Agrawal, Kayal and Saxena ("PRIMES is in P"), was the first unconditional deterministic polynomial-time test, though its running time makes it slower than probabilistic tests in practice.

Tests based on elliptic curves (Elliptic Curve Primality Proving, ECPP) and the Adleman–Pomerance–Rumely test provide primality certificates and are used to prove primality of numbers with thousands of digits.

Complexity

In computational complexity theory, the formal language corresponding to primality testing is denoted PRIMES. It was long known to lie in NP ∩ coNP; the AKS algorithm showed it belongs to P. Generating a random prime of cryptographic size (e.g. for RSA) proceeds by choosing random odd numbers and testing them until a prime is found, which by the prime number theorem takes only a few hundred trials for 1024-bit candidates.
