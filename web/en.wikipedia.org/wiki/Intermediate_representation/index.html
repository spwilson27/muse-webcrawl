An intermediate representation (IR) is the data structure or code used internally by a compiler or virtual machine to represent source code. An IR is designed to be conducive to further processing, such as optimization and translation. A "good" IR must be able to represent the source code without loss of information and be independent of any particular source or target language.

The use of an IR decouples the front end of a compiler (which parses a particular source language) from the back end (which generates code for a particular machine), so that M front ends and N back ends require only M + N components rather than M × N. Most modern compilers use several IRs at different levels of abstraction, lowering progressively toward machine code.

Classification

  • Graphical IRs — abstract syntax trees, control-flow graphs, and data-flow graphs; suited to structural analysis.
  • Linear IRs — sequences of simple instructions such as three-address code; close to assembly language but machine-independent, using virtual registers.
  • Hybrid forms — notably static single assignment (SSA) form, which combines a control-flow graph with the rule that each variable is assigned exactly once, making many optimizations straightforward.

Well-known IRs

LLVM IR is an SSA-based, typed assembly-like language at the heart of the LLVM project and the Clang compiler, designed for lifetime-long program analysis and transformation. Java bytecode and the Common Intermediate Language (CIL) of the .NET platform are stack-based IRs verified and executed by virtual machines. WebAssembly extends the idea to a portable compilation target for the web. GCC internally uses GENERIC and GIMPLE trees, while CPython compiles source to bytecode for its interpreter loop.

Uses beyond compilation

IRs are also central to static program analysis, binary translation, decompilation, and hardware synthesis, where register-transfer level descriptions serve as an intermediate step between behavioral specifications and logic gates.
