Batch processing

Batch processing is a method of running software tasks, known as jobs, on a computer system without manual intervention. Jobs are collected into batches, set up in advance with their input data and control instructions, and then executed automatically — often sequentially and frequently outside peak hours — with results delivered when the batch completes.

Jobs are accumulated and run as a batch rather than interactively.

History

Batch processing dates to the earliest days of computing. In the punched-card era, operators grouped decks of cards into batches and loaded them onto machines such as the IBM 1401 and later mainframes running systems like OS/360, where the Job Control Language (JCL) described each job. Because early computers could serve only one user at a time, batching maximised expensive machine utilisation. The rise of interactive time-sharing in the 1960s and 1970s reduced reliance on batch work for program development, but batch processing remained dominant for high-volume business tasks.

Modern uses

Contemporary batch workloads include payroll runs, bank statement generation, end-of-day settlement in finance, bulk data loading and transformation in data warehouses, report generation, and large-scale scientific computations. Modern schedulers such as cron, Control-M, Apache Airflow and cloud services coordinate batch jobs, handling dependencies, retries and prioritisation. Batch processing contrasts with stream processing and interactive computing, where requests are handled immediately as they arrive.

Advantages and disadvantages

Batch processing is efficient for large volumes of similar transactions, can be scheduled for off-peak periods, and separates job preparation from execution. Its main disadvantage is latency: errors may not be discovered until a batch finishes, and users cannot interact with a job while it runs.
