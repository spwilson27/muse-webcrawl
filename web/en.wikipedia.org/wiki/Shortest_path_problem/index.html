Shortest path problem

In graph theory, the shortest path problem is the problem of finding a path between two vertices in a graph such that the sum of the weights of its constituent edges is minimised. It models countless practical tasks, from road-network routing to network packet forwarding.

Variants and algorithms

The single-source problem (shortest paths from one source to all other vertices) is solved for non-negative weights by Dijkstra's algorithm (1956), and for graphs with negative edges (but no negative cycles) by the Bellman–Ford algorithm. The single-pair problem is efficiently addressed in practice by A* search with an admissible heuristic. All-pairs shortest paths are computed by the Floyd–Warshall algorithm or by Johnson's algorithm. If edges are unweighted, breadth-first search suffices.

Applications

Internet routing protocols such as OSPF use shortest-path computations; mapping and navigation services apply accelerated variants (contraction hierarchies, hub labelling) to continental road graphs; and variants of the problem underlie logistics, VLSI design and robot motion planning. Related formulations — such as the travelling salesman problem — are NP-hard, in contrast to the polynomial-time shortest path problem.
