Virtual function

ParadigmObject-oriented programming
MechanismDynamic dispatch, typically via a virtual method table (vtable)
LanguagesC++, C#, D, Delphi, Java (implicit), Rust (via trait objects)

In object-oriented programming, a virtual function, virtual method, virtual procedure or virtual subroutine is a function or method whose behaviour can be overridden within an inheriting class by a function with the same signature (name and parameters). This concept is an important part of the (runtime) polymorphism portion of object-oriented programming (OOP). That is, a variable of a base class type can reference an object of a derived class, and a call to a virtual function through that variable will invoke the derived class's version.

Example (C++)

In C++, a member function is declared virtual in the base class with the keyword virtual:

class Animal {
public:
    virtual ~Animal() = default;
    virtual void speak() const { /* generic */ }
};

class Dog : public Animal {
public:
    void speak() const override { /* bark */ }
};

void makeItSpeak(const Animal& a) {
    a.speak();   // calls Dog::speak if a refers to a Dog
}

A pure virtual function, declared with = 0, has no implementation in the base class and makes the class abstract; derived classes must override it to be instantiated. Virtual destructors ensure that destroying a derived object through a base pointer calls the correct destructor chain.

Implementation

Most compilers implement virtual dispatch using a virtual method table (vtable): a per-class array of function pointers. Each object of a polymorphic class contains a hidden pointer (vptr) to its class's vtable, and a virtual call indexes into the table at a fixed offset. This adds a small runtime cost (an indirection and inhibited inlining) compared with non-virtual calls, which is why some languages (Java, C#) make methods virtual by default while C++ requires the explicit keyword, and why performance-critical code sometimes uses templates (static polymorphism) instead.

Variations in other languages

In Java, all non-static, non-final instance methods are virtual by default. In C#, methods must be marked virtual and overrides declared with override. In Rust, dynamic dispatch is achieved through trait objects (dyn Trait), and in some languages (such as Python and Smalltalk) all method calls are dynamically dispatched, making the notion implicit.
