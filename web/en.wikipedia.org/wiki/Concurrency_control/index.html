Concurrency control

In information technology and computer science, especially in database systems and transactional processing, concurrency control ensures that concurrent operations are performed correctly while preserving data integrity. When multiple transactions execute simultaneously and access the same data, concurrency control mechanisms coordinate them so that the final result is equivalent to some serial execution — a property known as serializability.

Concurrency control coordinates simultaneous transactions so shared data remains consistent.

Techniques

The main categories of concurrency control are pessimistic and optimistic. Pessimistic methods, above all locking, prevent conflicts before they occur: two-phase locking (2PL) and its strict variant guarantee serializability by requiring transactions to acquire all locks before releasing any. Timestamp ordering assigns each transaction a timestamp and enforces access in timestamp order. Multiversion concurrency control (MVCC) maintains multiple versions of data items so readers need not block writers, and is used by systems such as PostgreSQL and Oracle. Optimistic concurrency control assumes conflicts are rare, lets transactions proceed without locking, and validates at commit time, aborting if a conflict is detected.

Problems addressed

Without control, concurrent transactions can produce lost updates, dirty reads, non-repeatable reads and phantom reads. Database systems expose isolation levels — from read uncommitted to serializable — that trade consistency for performance. Deadlocks, in which transactions wait indefinitely for one another's locks, must be detected or prevented by the system.
