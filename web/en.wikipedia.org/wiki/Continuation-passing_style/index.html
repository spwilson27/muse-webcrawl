Continuation-passing style

In functional programming, continuation-passing style (CPS) is a style of programming in which control is passed explicitly in the form of a continuation. This is contrasted with direct style, which is the usual style of programming. A function written in continuation-passing style takes an extra argument: an explicit "continuation", i.e. a function of one argument. When the CPS function has computed its result value, it "returns" it by calling the continuation function with this value as the argument.

Example

In direct style, a simple function such as the identity or a factorial might be written straightforwardly. In CPS, every function receives an additional continuation parameter k, and instead of returning a value it calls k with the value:

(define (fact n k)
  (if (= n 0)
      (k 1)
      (fact (- n 1)
            (lambda (v) (k (* n v))))))

Every call in CPS is a tail call, because functions never return to their caller; instead the continuation captures "what to do next".

Uses

CPS is used as an intermediate representation in compilers for functional languages, notably in the tradition of Guy L. Steele's work on the Rabbit compiler for Scheme and Andrew Appel's Compiling with Continuations. Because control flow is explicit, CPS makes it easy to implement features such as first-class continuations (call/cc), exceptions, coroutines and backtracking. CPS transformation is closely related to the A-normal form used in other compilers.

Relation to other concepts

Continuation-passing style corresponds, via the Curry–Howard correspondence, to double-negation translations in logic. In web programming, asynchronous APIs that use callback functions are an informal analogue of CPS, sometimes leading to deeply nested callbacks known colloquially as "callback hell".
