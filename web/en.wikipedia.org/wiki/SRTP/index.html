Secure Real-time Transport Protocol

The Secure Real-time Transport Protocol (SRTP) is a profile of the Real-time Transport Protocol (RTP) intended to provide encryption, message authentication, and replay protection to RTP traffic. It was published by the IETF in March 2004 as RFC 3711.

SRTP was developed by a team including Mats Näslund and Karl Norrman of Ericsson, David McGrew of Cisco, and Mark Baugher. It is widely used in Voice over IP (VoIP) telephony, videoconferencing, and WebRTC, where it is mandatory: WebRTC encrypts all media with DTLS-SRTP.

StandardRFC 3711 (2004)
PurposeEncryption and authentication of RTP streams
Default cipherAES in Counter Mode (AES-CM)
AuthenticationHMAC-SHA1
Companion protocolSRTCP (for RTCP traffic)

Operation

SRTP encrypts only the RTP payload, leaving the header readable so that header compression and network processing remain possible, and appends an authentication tag that protects the header and payload against forgery. A rollover counter and sequence number form the packet index used to derive per-packet keys from a master key via a key derivation function, and a replay window rejects retransmitted packets.

Key management

SRTP itself does not manage keys. Keying is negotiated by external protocols: ZRTP, MIKEY, SDES (key exchange in SDP, RFC 4568), or DTLS-SRTP (RFC 5764), in which a DTLS handshake provides the keying material.

Implementations

The widely used open-source library libsrtp, originally from Cisco, implements SRTP in many VoIP stacks; SRTP support is built into SIP phones, softphones, and media servers such as Asterisk and FreeSWITCH.
