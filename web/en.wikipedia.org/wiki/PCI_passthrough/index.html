PCI passthrough


Requires: IOMMU (Intel VT-d / AMD-Vi). Used by: KVM, Xen, VMware ESXi, Hyper-V.

PCI passthrough is a virtualization technique that allows a virtual machine to have direct, exclusive access to a physical PCI or PCI Express device, such as a graphics card, network adapter, or storage controller, rather than sharing an emulated or paravirtual device provided by the hypervisor.

How it works

Passthrough relies on an IOMMU — Intel VT-d or AMD-Vi — which remaps the device's DMA accesses into the guest's address space and isolates the device so it cannot read or write host memory outside the guest. On Linux the device is typically bound to a stub or VFIO driver on the host, then assigned to a guest under KVM/QEMU; Xen and VMware ESXi (DirectPath I/O) provide equivalent facilities.

Uses

The most common consumer use is GPU passthrough, giving a guest near-native graphics performance for gaming or GPU computing while the host runs another operating system. In data centres, passthrough of network interfaces and NVMe controllers reduces virtualization overhead for latency-sensitive workloads. Related technology, SR-IOV, lets a single device present multiple virtual functions that can each be passed through to different guests.

Limitations

A passed-through device is unavailable to the host and cannot easily be shared or live-migrated with the guest. Faulty or malicious devices historically posed isolation risks, mitigated by IOMMU grouping and Access Control Services (ACS) on PCIe switches.
