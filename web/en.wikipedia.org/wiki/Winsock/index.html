Winsock

In computing, Winsock (Windows Sockets API, WSA) is a technical specification that defines how Windows network software should access network services, especially TCP/IP. It defines a standard interface between a Windows TCP/IP client application (such as an FTP client or a web browser) and the underlying TCP/IP protocol stack.

The specification is based on the Berkeley sockets API model used in BSD UNIX for communications between programs. Winsock functions are exported from the ws2_32.dll library in modern versions of Windows.

Winsock architecture with layered service providers

History

In the early 1990s, several vendors shipped incompatible proprietary TCP/IP stacks for Windows, forcing application developers to write different code for each stack. The Windows Sockets specification, first released as Winsock 1.1 in 1993, was the result of a vendor collaboration begun at CompuServe forums and led by figures including Martin Hall of JSB Software. Winsock 2, released in 1994 and shipped with Windows 95 and Windows NT 4.0, added support for multiple protocol stacks, quality of service, and a layered service provider (LSP) architecture.

Technology

Winsock 2 introduced the ability to layer service providers between applications and the base TCP/IP provider, which was used for features such as encryption and parental controls but also became a vector for malware, leading Microsoft to deprecate the LSP mechanism in later Windows versions. The API supports blocking and non-blocking sockets, overlapped I/O, and I/O completion ports for high-performance servers.
