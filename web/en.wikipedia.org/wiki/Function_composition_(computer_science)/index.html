Function composition (computer science)

In computer science, function composition is an act or mechanism to combine simple functions to build more complicated ones. Like the usual composition of functions in mathematics, the result of each function is passed as the argument of the next, and the result of the whole composition is the result of the last one.

Overview

Function composition is a fundamental building block of functional programming. Programs are constructed by composing functions that operate on data, with the composition operator usually written in one of the following ways:

-- Haskell: (f . g) x = f (g x)
compose f g = \x -> f (g x)
// JavaScript
const compose = (f, g) => x => f(g(x));

Many languages provide built-in composition operations. Unix pipelines are a shell-level form of composition, in which the standard output of each program becomes the standard input of the next. In object-oriented and concurrent programming, related patterns include function chaining, pipelines and the use of higher-order functions such as map, filter and fold, which can themselves be composed to build data transformations.

Composition operators

Two styles of composition appear in practice. Point-free (or tacit) composition defines a function directly as a composition of others without naming its argument, as in Haskell's (.) operator. Piping operators — such as F#'s |> or Elixir's |> — apply functions left-to-right in the order data flows, which many programmers find more readable for long transformation chains.

Related concepts

Function composition is closely related to currying and partial application, which make it easier to build specialised functions for use in compositions, and to the monadic bind operation, which generalises composition to functions returning values wrapped in a context. In category-theoretic terms, composition in most programming languages is modelled on composition of morphisms in the category of types and functions.
