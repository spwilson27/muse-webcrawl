Observer pattern

The observer pattern: a subject maintains a list of observers and notifies them of state changes.

The observer pattern is a software design pattern in which an object, named the subject, maintains a list of its dependents, called observers, and notifies them automatically of any state changes, usually by calling one of their methods. It is one of the behavioral design patterns identified by the "Gang of Four" in their 1994 book Design Patterns.

The pattern is mainly used for implementing distributed event handling systems, in "event driven" software. In such systems, the pattern is usually implemented using callbacks, publish/subscribe mechanisms, or signals and slots. Most modern programming libraries and frameworks for graphical user interfaces support some form of the observer pattern, since GUIs are naturally event-driven: a button click, for instance, is an event to which registered handler functions subscribe.

Structure

The main components of the pattern are the Subject (or Observable), which provides an interface for attaching and detaching observers and for notifying them, and the Observer, which defines an updating interface for objects that should be notified of changes in a subject. Concrete subjects store state of interest and send notifications when that state changes; concrete observers keep a reference to a concrete subject and implement the update interface so their state stays consistent with the subject's.

Advantages and disadvantages

The observer pattern promotes loose coupling: the subject knows only that observers implement a certain interface, and observers can be added or removed at runtime without modifying the subject. However, the pattern can lead to unexpected update cascades, memory leaks when observers are not properly deregistered (the "lapsed listener problem"), and difficulty in determining what changed, since notifications may carry no information about the specific change.
