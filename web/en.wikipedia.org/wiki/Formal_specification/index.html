Formal specification

In computer science, formal specifications are mathematically based techniques whose purpose is to help with the implementation of systems and software. They are used to describe a system, to analyze its behavior, and to aid in its design by verifying key properties of interest through rigorous and effective reasoning tools. These specifications are formal in the sense that they have a syntax, their semantics fall within one domain, and they are able to be used to infer useful information.

Motivation

Ambiguity in natural-language requirements is a major source of software defects. A formal specification states precisely what a system should do, without describing how it should do it, providing a basis for proving correctness, generating tests, and checking that an implementation satisfies its requirements.

Specification languages

Several families of specification languages exist. Model-based languages such as Z, VDM, and B describe a system by building an abstract model of its state and operations. Algebraic (axiomatic) languages such as OBJ and Larch describe behavior through equations and logical axioms. Process algebras such as CSP and CCS specify concurrent systems, while interface description languages and contracts (preconditions and postconditions, as in Eiffel) specify components in isolation.

Use in development

Formal specifications support formal verification, refinement from specification to code, automated test-case generation, and unambiguous communication among developers and clients. Although full formal specification is costly and is most common in safety- and security-critical domains, lightweight formal methods are widely applied in industry.
