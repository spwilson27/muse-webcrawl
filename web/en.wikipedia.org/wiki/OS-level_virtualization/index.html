OS-level virtualization

From Wikipedia, the free encyclopedia
Containers share the host kernel, unlike hypervisor-based virtual machines.

OS-level virtualization is an operating system virtualization technique in which the kernel allows the existence of multiple isolated user-space instances, commonly called containers. All containers share the same host operating system kernel, but each has its own file system, process tree, network namespace and resource limits, so that from inside, a container appears much like a standalone operating system. The technique contrasts with hardware virtualization, in which a hypervisor runs complete guest operating systems, each with its own kernel, on virtual hardware.

History

The idea descends from the Unix chroot mechanism (1979), which isolates a process's view of the file system. FreeBSD jails (2000) extended the idea to processes, networking and users; Solaris Containers/Zones (2004) and OpenVZ (2005) developed it further. On Linux, the combination of namespaces (for isolation of processes, mounts, networking, users and more) and cgroups (for resource accounting and limits) provided the kernel primitives from which LXC (2008) and then Docker (2013) built practical container systems. Docker's image format and tooling popularised containers for application packaging and deployment, and orchestration systems such as Kubernetes made them a standard unit of cloud infrastructure.

Advantages and limitations

Because containers share the host kernel and contain no guest OS, they are lightweight: images are smaller, instances start in milliseconds to seconds, and many more can run on a host than full virtual machines. The trade-off is a weaker isolation boundary — a kernel vulnerability can compromise all containers — and the requirement that containers run the host's operating system family: a Linux host runs Linux containers natively, and other systems must be emulated or run in a lightweight VM. Security-conscious deployments therefore combine containers with sandboxing technologies such as gVisor or microVMs (e.g. Firecracker), or run containers inside virtual machines.

Implementations

  • Linux: Docker, Podman, LXC/LXD, containerd, CRI-O
  • FreeBSD: jails
  • Solaris/illumos: Zones
  • Windows: Windows Containers (process and Hyper-V isolation modes)
