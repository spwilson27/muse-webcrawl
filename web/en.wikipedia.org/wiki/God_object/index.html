God object

In object-oriented programming, a god object (also known as a god class) is an object that references a large number of distinct types, has too many unrelated or uncategorized methods, or some combination of both. The god object is an example of an anti-pattern and a code smell.

A common programming technique is to separate a large problem into several smaller, more manageable parts (divide and conquer) and create solutions for each of them. Once the smaller problems are solved, the big problem as a whole has been solved. Therefore, a given object for a small problem need only know about itself. However, a god object knows or does an excessive amount, centralising functionality that ought to be distributed among many smaller objects.

Characteristics

God objects exhibit high coupling and low cohesion: they interact with many other parts of the system, and their responsibilities are numerous and unrelated. Because a god object centralises so much behaviour, changes to it risk breaking many parts of the system at once, and it becomes difficult to test, reuse, or maintain. Systems centred on a god object also tend to have many other objects that are mere data holders, passing information to the central object for processing.

Remedies

The standard remedy is refactoring: applying the single-responsibility principle by splitting the god object's responsibilities among several cohesive classes, delegating behaviour to the objects that own the relevant data. Related anti-patterns include the "blob" in procedural design and overly large utility classes.
