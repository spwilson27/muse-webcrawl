Consistent hashing

[Hero image placeholder: hash ring with nodes and keys distributed around a circle]

Consistent hashing is a special kind of hashing technique such that when a hash table is resized, only n/m keys need to be remapped on average, where n is the number of keys and m is the number of slots. In contrast, in most traditional hash tables, a change in the number of array slots causes nearly all keys to be remapped because the mapping between the keys and slots is defined by a modular operation.

Consistent hashing was introduced by David Karger and colleagues at MIT in 1997, originally for use in distributed caching on the World Wide Web.

Technique

Consistent hashing is based on mapping each object and each cache node to a point on a circle (the hash ring). Both nodes and keys are hashed onto the same identifier space, typically using a function such as SHA-1. A key is assigned to the first node encountered walking clockwise around the ring from the key's position. When a node is added or removed, only the keys in the arc between that node and its predecessor change assignment; all other keys keep their nodes.

Virtual nodes

To balance load more evenly, each physical node is represented by many "virtual nodes" (replicas) scattered around the ring. This smooths out the statistical variance in key distribution and lets nodes take on load proportional to their capacity.

Uses

Consistent hashing is used in Amazon's Dynamo and its open-source derivatives Apache Cassandra and Voldemort, in distributed cache systems such as memcached (via the Ketama algorithm), in content delivery networks originating with Akamai, and in load balancers and peer-to-peer systems. A related technique, rendezvous hashing (highest random weight), achieves similar goals.
