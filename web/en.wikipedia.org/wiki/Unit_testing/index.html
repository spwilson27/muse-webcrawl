Unit testing

From Wikipedia, the free encyclopedia

Unit testing is a software testing method in which individual units of source code — the smallest testable components, such as functions, methods, or classes — are tested in isolation to verify that each behaves as intended. A unit test typically arranges inputs and preconditions, invokes the unit, and asserts properties of the result. Because units are tested apart from the whole system, failures localise defects precisely and tests run in milliseconds, enabling them to be executed on every build.

Practice

Unit testing is usually automated with a framework — the xUnit family (JUnit for Java, NUnit for .NET, PyUnit/unittest for Python, and their many descendants, modelled on Kent Beck's SUnit for Smalltalk) provides fixtures, assertions, and runners. Dependencies of the unit under test are commonly replaced with test doubles: stubs, mocks, fakes, and spies. In test-driven development (TDD), tests are written before the code they test, in a "red–green–refactor" cycle. Proponents argue unit tests document behaviour, enable safe refactoring, and lower the cost of change; critics note that heavy mocking can couple tests to implementation details, making them brittle, and that unit tests cannot catch integration or specification errors. Unit testing sits at the base of the "test pyramid," with integration tests and end-to-end tests above it, and modern continuous integration pipelines run the suite on every commit, gating merges on a green build.
