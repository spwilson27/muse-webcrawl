Secure Boot

Secure Boot is a security feature of the Unified Extensible Firmware Interface (UEFI) specification designed to ensure that a device boots only software trusted by the manufacturer. When the computer starts, the firmware verifies the digital signature of each piece of boot software — including firmware drivers, EFI applications, and the operating system bootloader — against a database of authorised keys stored in firmware. If a component's signature is not recognised or has been revoked, the boot process stops.

How it works

Secure Boot relies on a hierarchy of keys. A Platform Key (PK), controlled by the device manufacturer, anchors trust. Key Exchange Keys (KEK) authorise updates to the signature databases: the allowed-signature database (db) and the forbidden-signature database (dbx), which records compromised or revoked bootloaders. Each stage of boot verifies the next before executing it, forming a chain of trust from firmware to operating system kernel. Revocations via dbx updates are how known-vulnerable bootloaders (for example during the BootHole and BlackLotus vulnerabilities) are blocked.

Adoption and controversy

Secure Boot shipped with UEFI 2.2 and was widely deployed with Windows 8 PCs from 2012, when Microsoft required it enabled by default on certified x86 machines while requiring that users be able to disable it; on ARM Windows devices it initially could not be disabled, drawing criticism from free-software advocates concerned about vendor lock-in. Linux distributions typically boot under Secure Boot using a small signed "shim" bootloader verified against Microsoft's signing service, which in turn loads their own kernels and modules. The feature defends against bootkits and rootkits that load before the operating system, though it does not protect against attacks after a trusted system is running.
