HATEOAS

HATEOAS (Hypermedia as the Engine of Application State) is a constraint of the REST application architecture that distinguishes it from other network application architectures. With HATEOAS, a client interacts with a network application entirely through hypermedia provided dynamically by application servers. A REST client needs little prior knowledge about how to interact with an application beyond a generic understanding of hypermedia.

Principle

The principle is analogous to browsing the World Wide Web: a user enters a website at a home page and navigates by following links, rather than constructing addresses from a manual. In a HATEOAS-driven API, the response to a request includes links describing the actions currently available on the returned resource, so the client discovers possible state transitions from the representation itself. Roy Fielding, who introduced the concept in his 2000 doctoral dissertation defining REST, has argued that most APIs described as "RESTful" do not satisfy this constraint.

Example

A request for a bank account might return a representation including links to deposit, withdraw and transfer actions only when the account state permits them:

{
  "accountNumber": 12345,
  "balance": 250.00,
  "links": [
    { "rel": "deposit", "href": "/accounts/12345/deposit" },
    { "rel": "transfer", "href": "/accounts/12345/transfer" }
  ]
}

Formats

Several hypermedia formats have been designed to carry such links, including HAL, JSON:API, Siren, and Collection+JSON. Adoption in public APIs has been limited compared with plain JSON APIs documented out-of-band, but HATEOAS remains influential in discussions of API design and evolvability.
