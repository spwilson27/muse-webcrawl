Abstract type

In programming language theory, an abstract type is a type in a nominative type system that cannot be instantiated directly, but only through a concrete subtype or implementation. The term overlaps with abstract data type (ADT): a specification of values and operations defined by behaviour rather than by representation.

Abstract classes and interfaces

In object-oriented languages such as Java and C#, an abstract class may declare abstract methods without bodies, obliging subclasses to implement them; it cannot itself be instantiated. Interfaces carry this further by declaring only signatures (and, in modern Java, default methods). In C++, a class with at least one pure virtual function is abstract. These constructs enforce a contract while deferring implementation.

Purpose

Abstract types support polymorphism and information hiding: client code depends on the abstract specification, so implementations can be exchanged without changing callers. Classic examples are an abstract Shape type with concrete Circle and Rectangle subtypes, and the collections frameworks of many languages, where interfaces such as List or Map hide whether the underlying structure is an array, a linked list, or a hash table.

Abstract versus concrete

A concrete type supplies all implementations and can be instantiated. Type theorists model abstract types with existential types, an approach formalised by John Mitchell and Gordon Plotkin ("Abstract types have existential type", 1988), and they underlie the module systems of languages in the ML family.
