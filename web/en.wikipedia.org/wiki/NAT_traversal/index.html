NAT traversal

Network address translation traversal is a computer networking technique of establishing and maintaining Internet Protocol connections across gateways that implement network address translation (NAT). NAT breaks the end-to-end connectivity principle on which the Internet was originally designed, making it difficult for hosts behind NAT devices — such as home routers — to accept incoming connections. NAT traversal techniques allow peer-to-peer applications, voice over IP, online gaming, and remote access to work despite NAT.

A rendezvous server helps two NATted hosts discover each other's public endpoints so they can communicate directly.

The problem

A NAT device rewrites the source address and port of outgoing packets, creating a temporary mapping that lets replies return. An external host, however, cannot initiate a connection to a private address it cannot even route to, and the NAT will normally drop unsolicited inbound packets. Symmetric NATs, which use a different external port for each destination, make prediction especially difficult.

Techniques

  • Port forwarding — manual or automatic (via UPnP IGD or NAT-PMP/PCP) static configuration of the NAT to forward specific ports to an internal host.
  • STUN (Session Traversal Utilities for NAT) — a protocol letting a host discover its public (server-reflexive) address and port mapping from a server on the open Internet.
  • UDP hole punching — both peers send packets to each other's discovered public endpoints, creating NAT mappings that admit the peer's traffic, enabling direct connection.
  • TURN (Traversal Using Relays around NAT) — when direct connection fails, traffic is relayed through a public server.
  • ICE (Interactive Connectivity Establishment) — a framework, standardised by the IETF, that combines STUN and TURN, gathering candidate addresses and testing connectivity pairs; it is used by WebRTC, SIP, and other real-time protocols.
  • Application-level gateways and tunnelling — proxies such as SOCKS, and techniques like NAT64 or Teredo that encapsulate IPv6 within IPv4 UDP.

Applications

NAT traversal underpins VoIP (SIP and H.323 historically struggled badly with NAT), WebRTC video calls, peer-to-peer file sharing, multiplayer gaming, and remote-desktop tools. Its importance persists because IPv4 address exhaustion keeps NAT — including carrier-grade NAT — ubiquitous, though widespread IPv6 deployment would largely remove the problem.
