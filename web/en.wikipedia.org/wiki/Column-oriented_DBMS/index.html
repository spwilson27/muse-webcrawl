Column-oriented DBMS

A column-oriented DBMS (or columnar database management system) is a database management system (DBMS) that stores data tables by column rather than by row. In a column store, the values of each column are stored contiguously on disk, whereas in a conventional row store the values of each row are stored together.

Benefits

Columnar storage is well suited to analytical (OLAP) workloads such as data warehouses, where queries typically read a few columns of many rows and compute aggregates. Because only the referenced columns need to be read, I/O is reduced. Values within a column are of the same type and often highly similar, enabling very effective compression — run-length encoding, dictionary encoding and delta encoding can shrink storage substantially. These properties also allow efficient vectorized query execution.

Drawbacks

The layout is poorly suited to transactional (OLTP) workloads involving frequent inserts, updates and single-row retrieval, since writing one logical row requires accessing many separate column segments. Column stores therefore often use staging areas, batch loading and specialized structures such as write-optimized stores merged into read-optimized main stores.

History and examples

One of the earliest columnar products was Sybase IQ in the 1990s. Research systems such as MonetDB and C-Store (commercialized as Vertica) popularized the architecture in the 2000s. Widely used modern columnar systems and formats include Apache Cassandra (a wide-column store), Google BigQuery, Amazon Redshift, ClickHouse, Apache Parquet and Apache ORC, and columnar features in MariaDB (ColumnStore) and PostgreSQL extensions.
