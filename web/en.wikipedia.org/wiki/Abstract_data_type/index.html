Abstract data type

In computer science, an abstract data type (ADT) is a mathematical model for a type of data structure defined by its behaviour — the operations that can be performed on it and the properties those operations must satisfy — rather than by its implementation. Users interact with an ADT only through its published interface, a principle known as information hiding or encapsulation. Classic examples include the stack, queue, list, set, map (dictionary) and priority queue.

Definition

An ADT specifies a set of values and a set of operations on them, together with axioms the operations must obey. For a stack, for instance, the axioms state that pushing an element then popping returns that element, and that a newly created stack is empty. Nothing is said about whether the stack is stored in an array or a linked list; any implementation satisfying the axioms is acceptable, and the choice can change without affecting client code.

History

The concept crystallised in the 1970s through the work of David Parnas on modular design, C. A. R. Hoare's proofs of data representation, and Barbara Liskov's CLU language, which provided direct support for data abstraction. Liskov and Stephen Zilles's 1974 paper "Programming with Abstract Data Types" is a founding text. Algebraic specification languages such as OBJ developed formal methods for defining ADTs by equations.

Implementation and use

Modern programming languages realise ADTs through classes, modules, interfaces and generics: Java's List interface with ArrayList and LinkedList implementations, or the container types of the C++ Standard Template Library, are canonical examples. Standard libraries and data-structure courses are organised around the distinction between the ADT (what it does) and the concrete data structure (how it does it), with efficiency analysed in terms of the time and space complexity of each operation.
