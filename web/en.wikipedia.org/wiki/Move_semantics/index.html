Move semantics

Move semantics is a feature of some programming languages, most prominently C++ (introduced in C++11), that allows the resources of a temporary or expiring object to be transferred ("moved") to another object instead of being copied. When a class manages a resource such as heap-allocated memory, a file handle or a socket, copying requires duplicating the resource, whereas moving simply reassigns ownership — typically by copying a pointer and nulling out the source.

In C++, move semantics are implemented through rvalue references (declared with &&) and move constructors and move assignment operators, which are selected when the argument is an rvalue — for example a temporary, or an object cast with std::move. The moved-from object is left in a valid but unspecified state, safe to destroy or reassign.

The mechanism avoids expensive deep copies when returning large objects from functions, inserting elements into containers, or transferring unique ownership, complementing copy elision and return-value optimisation. Related designs appear in other languages: Rust's default move semantics transfer ownership on assignment for non-Copy types, enforced at compile time by the borrow checker.
