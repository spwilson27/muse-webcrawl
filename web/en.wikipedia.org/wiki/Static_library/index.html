Static library

A static library (or archive) is a collection of object files that a linker copies, in whole or in needed part, directly into the executable being built — a process called static linking. The resulting program is self-contained with respect to that library's routines: it does not need the library file to be present at run time. Static libraries contrast with shared (dynamic) libraries, whose code is loaded and linked when the program runs.

Formats and tools

On Unix-like systems, static libraries conventionally have the .a extension and are created with the ar archiver, which bundles relocatable object files (plus a symbol index, generated with ranlib) into one file; the linker ld then searches archives given with the -l option and extracts only the members that resolve undefined symbols. On Windows, static libraries use the .lib extension and the COFF format, created by the LIB tool. If the linker is given an import library (also .lib) for a DLL, that is a different mechanism despite the shared extension.

Advantages and disadvantages

Statically linked programs avoid the "dependency hell" of matching shared library versions at run time, start without library search costs, and can see small performance benefits because calls need no indirection through a procedure linkage table; link-time optimization across the whole program is also easier. The disadvantages are larger executables (each program carries its own copy of the code), higher memory use when many programs run simultaneously, and poor maintainability: a security fix in a library requires relinking and redistributing every application that uses it, whereas a shared library can be updated once. Modern "fat" or "thin" archives and linker options that keep whole archives (--whole-archive) address some edge cases, such as registering statically linked plug-ins.

Usage

Static libraries remain common for small utilities, embedded systems, system-critical binaries that must run before shared libraries are available, and languages such as Go and Rust, which favor static linking by default. Operating-system distributions generally prefer dynamic linking for the reasons above.
