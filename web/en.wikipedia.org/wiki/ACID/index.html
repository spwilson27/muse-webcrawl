ACID

From Wikipedia, the free encyclopedia

[Image placeholder: Diagram of a database transaction committing atomically]

In computer science, ACID (atomicity, consistency, isolation, durability) is a set of properties of database transactions intended to guarantee data validity despite errors, power failures, and other mishaps. A database transaction that satisfies these properties is said to be an ACID transaction, and database systems that support such transactions are often called ACID-compliant. The concept was articulated in work by Theo Härder and Andreas Reuter in 1983, building on transaction concepts developed by Jim Gray in the late 1970s.

Properties

Atomicity

Atomicity guarantees that each transaction is treated as a single unit: either all of its operations succeed, or none of them do. If part of a transaction fails, the whole transaction is aborted and the database is left unchanged — as in a bank transfer, where a debit and its matching credit must never be separated.

Consistency

Consistency ensures that a transaction can only bring the database from one valid state to another, maintaining all defined rules and constraints, such as unique keys, referential integrity, and application invariants (for example, that the total money across accounts is preserved by a transfer).

Isolation

Isolation ensures that concurrently executing transactions do not interfere with one another: the result is the same as if the transactions had run sequentially. Systems implement isolation through locking or multiversion concurrency control, and offer graded isolation levels (such as read committed and serializable) that trade concurrency for strictness.

Durability

Durability guarantees that once a transaction has been committed, it remains committed even in the event of a system crash or power loss. Committed data is recorded in non-volatile storage, typically via a write-ahead log, before the commit is acknowledged.

ACID versus BASE

Large distributed systems often relax ACID guarantees in favour of availability and partition tolerance, following instead the BASE model (Basically Available, Soft state, Eventual consistency), as described by the CAP theorem. Systems such as many NoSQL databases adopt eventual consistency, while modern distributed SQL systems attempt to provide ACID semantics at scale.
