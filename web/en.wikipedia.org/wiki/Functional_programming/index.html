Functional programming

From Wikipedia, the free encyclopedia
[Image: A diagram of pure functions mapping inputs to outputs, with no side effects]

In computer science, functional programming is a programming paradigm where programs are constructed by applying and composing functions, treating computation as the evaluation of mathematical functions and avoiding changing-state and mutable data.

Its roots lie in Alonzo Church's lambda calculus (1930s), the theoretical twin of Turing's machines. Lisp (1958) was the first functional language; the family includes ML, Haskell (1990, purely functional), Erlang, Clojure, and F#, and functional features (first-class functions, lambdas, map/filter/reduce) now pervade mainstream languages.

Concepts

Pure functions (same input, same output, no side effects), immutability, higher-order functions, recursion instead of loops, lazy evaluation (Haskell), and strong static type systems with type inference (ML family) characterise the style. Declarative style emphasises what to compute rather than step-by-step how.

Functional techniques simplify parallel programming (no shared mutable state to race on) and reasoning about correctness; monads structure effects in pure languages. Costs can include unfamiliarity, and performance surprises from immutability and laziness.

Influence

Even resolutely imperative languages have absorbed functional ideas — JavaScript's array methods, Python's comprehensions, Java's streams and lambdas, C++'s library — while big-data frameworks (MapReduce, Spark) apply functional map/reduce at scale.
