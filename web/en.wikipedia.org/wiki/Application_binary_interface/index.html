Application binary interface
Abbreviation: ABI
Level: Machine code / binary
Covers: Calling conventions, data layout, object file formats

An application binary interface (ABI) is an interface between two binary program modules. It defines low-level details such as how functions are called, how data types are laid out in memory, how system calls are made, and the format of executable files. Unlike an application programming interface (API), which is defined at source-code level, an ABI operates at the level of compiled machine code.

Components

An ABI typically specifies the sizes, layouts, and alignments of data types; the calling convention controlling how arguments are passed in registers or on the stack and how return values are delivered; the manner of making system calls to the kernel; and the binary format for object files, libraries, and executables, such as ELF on Unix-like systems.

Importance

Programs compiled for one ABI generally cannot run on a system using another without recompilation or an emulation layer. Stable ABIs allow operating system vendors and library authors to release binary software that keeps working across versions; breaks in ABI compatibility are a common source of breakage when upgrading system libraries. Examples include the System V AMD64 ABI used on Linux and the ABIs defined for the ARM architecture.
