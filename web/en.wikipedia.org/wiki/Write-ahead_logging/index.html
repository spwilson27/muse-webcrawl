In computer science, write-ahead logging (WAL) is a family of techniques for providing atomicity and durability in database systems and journaling file systems. The principle is that a log record describing a change must be written to stable storage before the change itself is applied to the database, so that the database can be recovered to a consistent state after a crash by replaying (redo) or rolling back (undo) the logged operations.

How it works

Transactions append records to a sequential log. Before a modified data page can be written back to disk, all log records up to the page's latest modification must first be flushed — this ordering guarantee is what gives the technique its name. A checkpoint periodically establishes a point from which recovery can begin, limiting the amount of log that must be processed after a failure.

Implementations

Write-ahead logging underlies the recovery mechanisms of systems including PostgreSQL (whose WAL also supports replication and point-in-time recovery), SQLite (in WAL mode), Oracle's redo logs and many others. The ARIES algorithm is an influential formalisation of write-ahead logging with physiological logging, steal/no-force buffer policies and repeated history during redo.
