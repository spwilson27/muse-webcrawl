Replay attack

A replay attack (also known as a playback attack) is a form of network attack in which valid data transmission is maliciously or fraudulently repeated or delayed. It is carried out either by the originator or by an adversary who intercepts the data and re-transmits it, possibly as part of a spoofing attack by Internet Protocol (IP) packet substitution.

Example

Suppose a user authenticates to a server by sending a hash of their password. An attacker who eavesdrops on the exchange cannot recover the password from the hash, but can simply replay the same hash in a new connection and the server will accept it — unless the protocol adds freshness. This is why static credentials alone cannot prevent replay.

Countermeasures

Common defences include:

  • Nonces — one-time random values included in each exchange, so a replayed message is recognised as already used.
  • Timestamps and session tokens — messages are valid only within a short window or a single session.
  • Sequence numbers — each message carries a monotonically increasing number, as in the Kerberos authentication protocol, which combines timestamps with authenticators.
  • Challenge–response authentication — the verifier issues a fresh random challenge that the prover must incorporate into its response.

Related attacks

Replay attacks are related to man-in-the-middle attacks, reflection attacks and session hijacking. Protocols such as TLS provide replay protection within a connection by sequencing records, though application-level tokens (for example, anti-CSRF tokens in web forms) are still needed to prevent resubmission of valid requests.
