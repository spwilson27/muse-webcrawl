Traversal Using Relays around NAT

Traversal Using Relays around NAT (TURN) is a protocol that assists in the traversal of network address translators (NAT) or firewalls for multimedia applications. It may be used with the Transmission Control Protocol (TCP) and User Datagram Protocol (UDP). It is most useful for clients on networks masqueraded by symmetric NAT devices. TURN does not aid in the traversal of symmetric NATs or in NAT traversal in general, but rather provides a relay fallback when direct peer-to-peer connectivity cannot be established.

Overview

TURN is defined in RFC 8656 (which obsoleted RFC 5766). A client behind a NAT asks a TURN server on the public Internet for an allocation: a relayed transport address at which other peers can send data that the server will forward to the client. The client authenticates using a long-term credential mechanism, obtains permissions for the peers it wishes to communicate with, and can then exchange data either through Send/Data indications or through channels that reduce overhead.

Relationship to STUN and ICE

TURN is an extension of STUN (Session Traversal Utilities for NAT) and is most commonly deployed as part of ICE (Interactive Connectivity Establishment), the framework used by WebRTC and many VoIP systems. ICE first attempts direct and STUN-assisted connections; TURN relaying is used only as a last resort, because relaying consumes server bandwidth and adds latency. Widely used implementations of TURN servers include coturn.
