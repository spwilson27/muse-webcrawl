A dynamic-link library (DLL) is a type of shared library in the Microsoft Windows and OS/2 operating systems. A DLL file contains code, data and resources that multiple programs can use simultaneously, and it is loaded into a process's address space at run time rather than being linked into an executable at compile time.

Characteristics

DLLs use the same Portable Executable file format as Windows executables and export functions that programs import by name or ordinal. They enable modular software design: common functionality such as the Windows API itself is provided in system DLLs (such as kernel32.dll and user32.dll), updates to a DLL can benefit all programs using it, and a single in-memory copy of a DLL's code pages can be shared between processes, saving RAM and disk space.

Versioning problems

Because programs share DLLs, replacing a DLL with an incompatible version can break applications that depend on it — a notorious problem of 1990s Windows known as "DLL hell". Microsoft addressed it with mechanisms including Windows File Protection, side-by-side assemblies and manifests, private DLL copies shipped with applications, and later the component-based servicing model.

Comparison

Unix-like systems provide analogous functionality through shared objects (.so files) and dynamic libraries (.dylib on macOS). DLLs additionally support features such as delayed loading, explicit run-time linking via LoadLibrary and GetProcAddress, and the hosting of ActiveX controls and other COM components.
