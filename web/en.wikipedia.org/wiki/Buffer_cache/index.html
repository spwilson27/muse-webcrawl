Buffer cache

In computing, a buffer cache is a region of main memory used by an operating system kernel to cache blocks read from, or written to, block devices such as hard disks and solid-state drives. By keeping copies of recently used disk blocks in RAM, the kernel can satisfy subsequent reads without accessing the comparatively slow device, and can batch and reorder writes.

Operation

When a process requests data from a file, the kernel first searches the buffer cache. On a hit, the data is copied directly from memory; on a miss, a free buffer is allocated (evicting the least recently used buffer if necessary), the block is read from the device, and the data is both delivered to the caller and retained in the cache. Writes may be handled write-through, appearing on the device immediately, or write-back (delayed), in which modified ("dirty") buffers are flushed to the device later by a daemon or on demand, for example through the sync system call or at unmount.

History

The buffer cache was a central structure of early Unix kernels, which maintained a fixed pool of buffer headers organised in hash queues and a free list, protected by sleep/wakeup synchronisation. Classic Unix used the update daemon to flush dirty buffers every 30 seconds. Later systems integrated the buffer cache with the virtual memory system into a unified page cache, as in SunOS, SVR4 and modern Linux, so that file data and memory-mapped pages share the same cache pages. Monitoring tools such as free and top report memory held in buffers and cache separately from memory used by applications, since cache memory can be reclaimed under pressure.
