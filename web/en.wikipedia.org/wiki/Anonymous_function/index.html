Anonymous function

Also calledLambda function, lambda expression, function literal, closure
OriginLambda calculus (Alonzo Church, 1930s)
First in a languageLisp (1958)

In computer programming, an anonymous function (function literal, lambda abstraction, lambda function, lambda expression or block) is a function definition that is not bound to an identifier. Anonymous functions are often arguments passed to higher-order functions or results of them, and are a central feature of functional programming languages.

History

The concept derives from Alonzo Church's lambda calculus of the 1930s, in which all functions are anonymous, written with the Greek letter lambda (λ). Lisp, designed in 1958, adopted the lambda keyword, and anonymous functions spread to languages such as Scheme, ML, Haskell and Erlang, and later to mainstream languages: Python (lambda), JavaScript, Ruby, C# (lambda expressions and delegates), C++ (C++11 lambdas) and Java (Java 8 lambda expressions).

Uses

Anonymous functions are used for short callbacks and event handlers, for sorting with custom comparators, in map/filter/reduce operations, and to create closures that capture variables from the enclosing scope. In Python, for example, lambda x: x * x defines a one-expression function squaring its argument; JavaScript's arrow functions, x => x * x, serve the same purpose.

Criticism and limitations

Some argue anonymous functions can harm readability when overused or made overly long, and some languages restrict them (Python limits lambda bodies to a single expression). Debugging can be harder because stack traces may lack meaningful function names.
