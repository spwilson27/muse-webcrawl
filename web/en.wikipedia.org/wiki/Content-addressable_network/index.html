Content-addressable network

The content-addressable network (CAN) is a distributed, decentralised peer-to-peer infrastructure that provides hash table functionality on an Internet-like scale. CAN was one of the four original distributed hash table (DHT) proposals, introduced concurrently with Chord, Pastry and Tapestry, in a paper by Sylvia Ratnasamy, Paul Francis, Mark Handley, Richard Karp and Scott Shenker presented in 2001.

Design

CAN maps keys onto points in a virtual d-dimensional Cartesian coordinate space. The space is partitioned into zones, each owned by a participating node; a node stores the key–value pairs whose keys hash to points within its zone and keeps track of its immediate neighbours in the coordinate space. To retrieve a value, the requester hashes the key to a point and the query is routed greedily through neighbouring zones toward the destination point. Routing between arbitrary points takes on the order of d·n1/d hops, and each node maintains only 2d neighbours, independent of the total number of nodes n.

Joins and departures

A new node joins by finding the zone containing a random point and splitting that zone with its current owner. When a node leaves, a neighbour takes over its zone or two zones are merged. Periodic background communication lets neighbours detect failures and trigger repairs.

Enhancements and influence

The original design described several refinements: multiple independent coordinate spaces ("realities"), multiple nodes per zone for redundancy, overloading zones, and more expressive routing metrics reflecting network latency. Like other DHTs, CAN influenced the design of scalable peer-to-peer storage and lookup systems, though systems such as Kademlia and Chord saw wider deployment in practice.
