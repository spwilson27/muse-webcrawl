PL/I

PL/I (Programming Language One, pronounced "P-L-one") is a procedural, imperative computer programming language designed by IBM in the 1960s for scientific, engineering, business and systems programming. Intended to be a single language replacing the separate worlds of FORTRAN (scientific), COBOL (business) and assembly language (systems), PL/I was one of the most ambitious languages of its era: it combined array processing, string handling, record-structured files, exception handling, pointers, recursion, multitasking and compile-time macro preprocessing in one large design. Though it never displaced its rivals, PL/I was heavily used — especially on IBM mainframes — and influenced many later languages. Substantial PL/I code remains in production in banking, insurance and government systems.

History

PL/I grew out of a 1963–64 joint committee of IBM and its user group SHARE, formed to design a successor language for the new System/360 family. Originally to be called NPL (New Programming Language) — a name changed because it clashed with Britain's National Physical Laboratory — the language was renamed PL/I. The first manual appeared in 1964 and the first compilers (the "F" compiler, then the optimising compiler) followed from 1966. IBM's insistence that one language could serve all purposes made PL/I very large: George Radin, one of its architects, and the committee produced a design in which most features had defaults, so beginners could write simple programs while experts could exploit the full feature set. An ANSI standard was published in 1976 (with a "General Purpose Subset", Subset G, intended for minicomputers).

Features and character

PL/I programs are built from procedures, which may be internal or external, recursive or re-entrant. The language offers:

  • Rich data types: fixed- and floating-point decimal and binary arithmetic with user-specified precision, character and bit strings, arrays, structures (records), pointers and offsets, and controlled (heap) storage.
  • Powerful I/O: stream I/O (GET/PUT) for formatted data and record I/O for files, including indexed (VSAM) datasets.
  • Exception handling via ON-units — an early form of structured error handling covering conditions such as OVERFLOW, ZERODIVIDE, ENDFILE and user-defined conditions.
  • String handling and editing facilities rivalling COBOL's, plus list processing and multitasking support.
  • A compile-time preprocessor influenced by, and influencing, macro languages.
HELLO: PROCEDURE OPTIONS (MAIN);
   DECLARE MSG CHARACTER (20) VARYING INITIAL ('Hello, world!');
   PUT LIST (MSG);
END HELLO;

The same flexibility made the language notorious for complexity: because PL/I performs automatic type conversions and requires no declarations, the (apocryphal but famous) statement fragment "IF IF = THEN THEN THEN = ELSE;" could be valid in dialects where keywords are not reserved. Compilers were large and slow by 1960s standards, and the language's size contributed to disputes between IBM and academic critics — Edsger Dijkstra was scathing — while practitioners valued its productivity.

Notable uses

PL/I was used to write much of the Multics operating system — the first major operating system written in a high-level language — using the EPL subset and later full PL/I. Intel commissioned Gary Kildall's PL/M dialect for microprocessors, and the language saw heavy mainframe use for decades: IBM continues to sell and develop its Enterprise PL/I compilers for z/OS. The language's ambition — one tool for every job — anticipated later "kitchen-sink" designs, and its exception handling, string types and generics-like defaults foreshadowed features that became mainstream decades later.
