Byte order mark

The byte order mark (BOM) is a particular Unicode character, U+FEFF ZERO WIDTH NO-BREAK SPACE, whose appearance at the very beginning of a text stream indicates to a reader the byte order (endianness) of the following encoded text, and in some contexts which Unicode encoding is in use. The BOM is deprecated as a zero-width space character in most circumstances; its role in encoding detection remains its principal function.

Usage

For UTF-16, where code units are two bytes, a BOM of FE FF signals big-endian text and FF FE signals little-endian text; the Unicode standard requires consumers to assume big-endian in the absence of a BOM. For UTF-8, endianness is irrelevant, but a BOM (EF BB BF) is often used simply as a signature identifying the file as UTF-8 — historically common in Windows applications such as Notepad. The Unicode standard does not require or recommend a BOM for UTF-8.

Practical issues

A UTF-8 BOM can break software that does not expect it: it may appear as stray characters ("ï»¿") when a file is decoded as Latin-1, cause compilers and interpreters to error — for instance preventing a Unix shell script or PHP file from working correctly — or leak into web output before headers are sent. Consequently, many coding standards require UTF-8 files to be saved without a BOM. In Unicode terminology, U+FEFF occurring in the middle of a file is treated as a zero-width no-break space (or, since Unicode 3.2, preferably the word joiner U+2060 serves that function).
