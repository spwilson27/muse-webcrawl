In computing, multitasking is the concurrent execution of multiple tasks (also known as processes) over a certain period of time. New tasks can interrupt already-started ones before they finish, instead of waiting for them to end. As a result, a computer executes segments of multiple tasks in an interleaved manner, while the tasks share common processing resources such as central processing units (CPUs) and main memory. Interleaving provides flexibility (multiple tasks can be executed in parallel) and power (the system can respond to multiple users at once).

Preemptive and cooperative multitasking

In preemptive multitasking, the operating system kernel interrupts a running task at intervals (typically driven by a timer interrupt) and gives the CPU to another task, a process called a context switch. This prevents any single program from monopolising the processor. Unix, Linux, and modern Windows use preemptive multitasking.

In cooperative multitasking, each program must voluntarily yield control, either explicitly or by waiting for input. Early Macintosh System software and 16-bit Windows used this approach; a misbehaving application could freeze the whole system.

History

Multitasking was first developed in the 1960s to improve utilisation of expensive mainframe computers, whose fast CPUs sat idle while jobs waited on slow input/output devices. Systems such as IBM's OS/360 with multiprogramming, and time-sharing systems like CTSS, Multics, and Unix, extended the idea to interactive use by many terminal users. Personal computers gained multitasking in the 1980s, initially cooperatively, then preemptively with systems such as AmigaOS, Windows NT, and Mac OS X.

Multithreading and multiprocessing

Multitasking within a single process is provided by threads, which share the process's memory while running independently. On multiprocessor and multicore machines, tasks genuinely execute simultaneously, one per core, and the scheduler must balance load across cores.
