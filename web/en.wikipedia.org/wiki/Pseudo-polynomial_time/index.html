Pseudo-polynomial time

In computational complexity theory, a numeric algorithm runs in pseudo-polynomial time if its running time is a polynomial in the numeric value of the input — the largest number in the input — rather than a polynomial in the length of the input (the number of bits required to represent it). Because the length of the input is logarithmic in its largest value, a pseudo-polynomial algorithm is exponential in the size of the input in the worst case.

Example

Consider testing whether a number n is prime by trial division up to √n. The number of operations is polynomial in n itself, but n can be written in only log2 n bits, so the algorithm is exponential in terms of input length. (Efficient polynomial-time primality tests, such as the AKS test, do exist.)

Weakly NP-complete problems

Pseudo-polynomial algorithms are especially significant for NP-complete problems whose instances involve numerical parameters. The classic dynamic-programming algorithm for the knapsack problem runs in time proportional to the number of items times the capacity, and a similar algorithm exists for subset sum; these problems are therefore called weakly NP-complete, in contrast to strongly NP-complete problems, which remain NP-complete even when all numbers in the input are polynomially bounded in the input length and hence admit no pseudo-polynomial algorithm unless P = NP.
