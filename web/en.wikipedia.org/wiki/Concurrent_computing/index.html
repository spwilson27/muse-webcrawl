Concurrent computing

Interleaving of instructions from two concurrent processes

Concurrent computing is a form of computing in which several computations are executed concurrently — during overlapping time periods — instead of sequentially, with one completing before the next starts. It is a property of a system in which processes may overlap in time but need not run simultaneously on separate processors. Concurrency is distinct from parallelism, in which computations are literally executed at the same instant, for example on multiple cores of a multicore processor. A concurrent system may execute on a single processor through interleaved scheduling, whereas a parallel system requires multiple processing units.

History

Concurrency arose with early multitasking and time-sharing operating systems of the 1960s, which interleaved several programs on one machine. Edsger W. Dijkstra's work on cooperating sequential processes introduced the semaphore in 1965, and C. A. R. Hoare developed monitors and later Communicating Sequential Processes (CSP, 1978). Per Brinch Hansen contributed concurrent programming concepts to operating system design, and the actor model was formulated by Carl Hewitt in 1973. With the spread of multicore processors in the 2000s, concurrency became essential to mainstream software performance.

Concepts

Concurrent programs are built from processes or threads that communicate through shared memory or message passing. Because interleavings are nondeterministic, concurrent programming introduces hazards absent from sequential code: race conditions, in which a result depends on the timing of unsynchronised accesses; deadlock, in which processes wait indefinitely for one another; livelock and starvation. Synchronisation mechanisms include locks, mutexes, semaphores, monitors, condition variables, barriers, atomic operations and lock-free algorithms. Properties of concurrent systems are often described in terms of safety ("nothing bad happens") and liveness ("something good eventually happens").

Models and languages

Formal models of concurrency include CSP, the π-calculus and Petri nets. Programming languages support concurrency in varied ways: Java provides threads and the java.util.concurrent library; C++ has a standard thread library since C++11; Go offers lightweight goroutines and channels following CSP; Erlang and Elixir use the actor model with immutable messages, suiting telecom and fault-tolerant systems; Rust enforces data-race freedom through its ownership type system.

Applications

Concurrency underpins operating systems, web servers handling many simultaneous requests, graphical user interfaces that must remain responsive, databases managing concurrent transactions, distributed systems, and real-time and embedded systems.
