Address space layout randomization

Address space layout randomization (ASLR) is a computer security technique involved in preventing exploitation of memory corruption vulnerabilities. In order to prevent an attacker from reliably jumping to, for example, a particular exploited function in memory, ASLR randomly arranges the address space positions of key data areas of a process, including the base of the executable and the positions of the stack, heap and libraries.

History

The PaX project first proposed and implemented ASLR for the Linux kernel in 2001. Address space randomisation subsequently entered mainstream operating systems: OpenBSD enabled it by default in 2003, the Linux kernel merged a basic form in 2005, Windows Vista added ASLR in 2007, and Mac OS X introduced partial library randomisation in Leopard with fuller randomisation in Lion. Mobile systems adopted it as well; iOS implemented ASLR from version 4.3, and Android from version 4.0 (with full support for position-independent executables in 5.0).

Effectiveness and limitations

ASLR works best on 64-bit systems, where the address space is large enough to provide substantial entropy. On 32-bit systems the number of bits available for randomisation is small, and researchers have shown that brute-force or partial-pointer-overwrite attacks can defeat it. Information leaks that disclose a single runtime address can also undermine ASLR, because libraries are often loaded at a consistent offset from a known base; this motivates complementary defences such as position-independent executables (PIE), which randomise the main executable's base, and fine-grained randomisation schemes proposed in the research literature.

Related techniques

ASLR is normally deployed together with a non-executable stack and heap (NX bit / DEP), stack canaries, and control-flow integrity measures as part of a defence-in-depth strategy against buffer overflow and return-oriented programming attacks.
