Algebraic data type

In computer programming, especially functional programming and type theory, an algebraic data type (ADT) is a kind of composite data type, i.e., a data type formed by combining other types. Two common classes of algebraic types are product types (such as tuples and records) and sum types (also called tagged or disjoint unions, or variant types).

The values of a product type typically contain several values, called fields. All values of that type have the same combination of field types. The set of all possible values of a product type is the Cartesian product of the sets of all possible values of its field types. The values of a sum type are typically grouped into several classes, called variants. A value of a variant type is usually created with a quasi-functional entity called a constructor. Each variant has its own constructor, which takes a specified number of arguments with specified types. The set of all possible values of a sum type is the disjoint union of the sets of all possible values of its variants.

Examples

One of the most common examples of an algebraic data type is the singly linked list. In Haskell:

data List a = Nil | Cons a (List a)

Here Nil and Cons are constructors of the List type. Algebraic data types are used with pattern matching, which allows programs to deconstruct values in a type-safe way:

sum :: List Int -> Int
sum Nil = 0
sum (Cons x xs) = x + sum xs

History and usage

Algebraic data types were introduced in the Hope programming language in the 1970s and became a hallmark of the ML family of languages and Haskell. Variants of the idea appear in many modern languages: enums with associated values in Rust and Swift, sealed classes in Scala and Kotlin, and discriminated unions in F# and TypeScript.

A generalised algebraic data type (GADT) relaxes the requirement that all constructors return the same type, allowing type parameters to vary by constructor and giving the type system additional expressive power.
