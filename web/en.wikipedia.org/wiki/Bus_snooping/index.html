Bus snooping

Placeholder image: caches snooping a shared system bus.

Bus snooping, also called bus sniffing, is a technique used in distributed shared memory and multiprocessor systems in which each cache monitors (snoops) the shared bus for memory accesses that could affect the validity of its own cached data. It is the mechanism underpinning snoopy cache-coherence protocols such as MESI.

How it works

Every cache controller watches all transactions on the bus. When a processor issues a read or write to an address, the snooping hardware in each other cache checks whether it holds a copy of that cache block. Depending on the protocol, the cache may invalidate its copy, update it, or supply the data itself. When a processor writes to a block that other caches hold, a bus transaction broadcasts the invalidation or update so that no processor reads stale data.

Snoop filters

To reduce the bandwidth and power cost of checking every transaction against every tag, many designs add snoop filters: coarse-grained directories that track which caches may hold a block and direct snoops only to those caches. This approximates a directory-based protocol while retaining bus broadcast semantics.

Limitations

Because the bus is a shared medium, snooping does not scale to large numbers of processors: every coherence event consumes bus bandwidth visible to all nodes. Large multiprocessors therefore generally use directory-based coherence instead, while bus snooping remains common in small multicore chips and symmetric multiprocessing systems.
