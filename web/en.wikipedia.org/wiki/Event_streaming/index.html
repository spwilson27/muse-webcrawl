Event streaming

Event streaming
FieldDistributed systems, data engineering
Key technologiesApache Kafka, Apache Flink, Apache Spark Streaming, ksqlDB
Related conceptsPublish–subscribe, event sourcing, stream processing

Event streaming is the practice of capturing data in real time from event sources — such as databases, sensors, mobile devices, and applications — in the form of streams of events, storing those streams durably for later retrieval, and processing and reacting to them as they occur. An event is a record of something that happened, typically containing a key, a value, and a timestamp. Event streaming platforms combine messaging, storage, and stream processing in a single system, in contrast to traditional message queues, which deliver messages to consumers and then discard them.

Architecture

In an event streaming architecture, producers publish events to named streams (called topics in Apache Kafka), which are stored as ordered, immutable, append-only logs, partitioned for scalability. Consumers read events at their own pace and can replay them from any point in the log. Stream processing frameworks allow continuous computation over the streams — filtering, aggregation, joins, and windowing — to produce derived streams and materialised views.

Use cases

Common use cases include real-time analytics and monitoring, fraud detection, log aggregation, change data capture from databases, decoupling microservices through event-driven communication, and feeding data pipelines and machine-learning systems with fresh data.

History

The approach was popularised by Apache Kafka, developed at LinkedIn and open-sourced in 2011, which reframed the commit log as a unifying abstraction for data integration. The associated design philosophy — sometimes called "the log" or streaming-first architecture — influenced a generation of tools, and the related pattern of event sourcing stores the state of a system as a sequence of events.
