Concurrent Versions System

The Concurrent Versions System (CVS, also known as the Concurrent Versioning System) is a free and open-source client–server version control system originally developed in the 1980s. CVS keeps track of all changes in a set of files, typically the source code of a software project, and allows multiple developers to collaborate on it concurrently.

History

CVS grew out of a set of shell scripts written by Dick Grune in 1984–85 to coordinate work with a colleague, building on the single-file Revision Control System (RCS). Brian Berliner rewrote it in C in 1989, and it became the dominant version control system for open-source projects in the 1990s, hosted by services such as SourceForge. CVS stores file histories as RCS files in a central repository and uses a copy-modify-merge workflow rather than locking.

Features and limitations

CVS supports branching and tagging, anonymous read-only access for public projects, and network-transparent operation. Its weaknesses include non-atomic commits, poor handling of file renames and directories (which are not versioned), and limited support for binary files. These limitations motivated successors such as Subversion, designed explicitly as "CVS done right", and later distributed systems such as Git and Mercurial, which largely displaced CVS.
