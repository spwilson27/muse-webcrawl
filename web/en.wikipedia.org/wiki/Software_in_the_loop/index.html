Software in the loop

SIL testing runs the actual production code against a simulated environment.

Software in the loop (SIL) is a method of testing and validating embedded and control software in which the compiled production code — the same code that will run on the target device — is executed on a host computer (or an emulator of the target processor) connected to a simulation of the physical system and environment it will control. SIL is a standard stage in the model-based design workflow common in the automotive, aerospace, and industrial-control industries.

Place in the V-model workflow

In model-based development, a controller is first designed as a block-diagram model and tested in model in the loop (MIL) simulation, where both controller and plant are models. Code is then generated (or handwritten) from the model and re-verified: in SIL, the generated or written code runs against the plant model, checking numerical equivalence with the model and exposing implementation errors, overflow, and timing-independent logic faults. Subsequent stages are processor in the loop (PIL), which runs the code on the actual target processor, and hardware in the loop (HIL), which connects the real controller hardware to a real-time simulation of the plant.

Advantages and limits

SIL allows testing early, cheaply, and repeatably, without physical prototypes, and permits dangerous or rare scenarios to be exercised safely. Its limits are that the host environment differs from the target in timing, word length, and hardware interfaces; discrepancies between the simulated plant and reality can also mask defects. For these reasons SIL complements rather than replaces later PIL and HIL verification and physical testing, and safety standards such as ISO 26262 (automotive) prescribe back-to-back testing across these stages.
