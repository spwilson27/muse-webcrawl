POSIX

POSIX (the Portable Operating System Interface) is a family of standards specified by the IEEE Computer Society for maintaining compatibility between operating systems. POSIX defines application programming interfaces (APIs) for system services — including process control, file and directory operations, signals, threads and networking — together with a command-line shell and a set of standard utilities. Software written to the POSIX interfaces can be ported between compliant systems with little or no modification.

History

POSIX grew out of efforts in the mid-1980s to end the fragmentation of Unix systems, when vendors were shipping incompatible variants. The IEEE 1003 working group published the first standard in 1988, covering a core C-language API modelled largely on Unix System V and BSD practice. The name "POSIX" was suggested by Richard Stallman, who noted it could be pronounced "pah-zicks" and was more memorable than "IEEEIX".

Through the 1990s the family grew to include real-time extensions, threads (pthreads) and additional utilities. In 2001 the POSIX specifications were merged with the Single UNIX Specification under the Austin Group, producing a single jointly maintained document; subsequent revisions appeared in 2008, 2017 and 2024.

Contents

The standard is organised into volumes covering base definitions, system interfaces, the shell and utilities, and rationale. It specifies, among other things, the semantics of fork/exec, file descriptors, pipes, environment variables, regular expressions, and more than a hundred standard utility programs such as ls, grep, awk and make.

Compliance

Most Unix-like systems — Linux distributions, the BSDs and macOS — implement most of POSIX, though formal certification is rare: macOS is a certified UNIX, while Linux is generally described as "mostly POSIX-compliant". Microsoft Windows historically offered POSIX subsystems and later the Windows Subsystem for Linux.
