Public key infrastructure

A public key infrastructure (PKI) is the set of roles, policies, hardware and software needed to create, distribute, use and revoke digital certificates that bind public keys to identities in public-key cryptography. The most widely deployed example is the X.509 infrastructure securing TLS on the web; others include national e-ID systems, code signing, and secure email.

Components

A certificate authority (CA) verifies identity and issues certificates; a registration authority handles enrolment. Hierarchies begin at a self-signed root CA, whose key is embedded in browsers and operating systems as a trust anchor. Certificates contain the subject name, public key, issuer, serial number and validity period. Revocation is published via certificate revocation lists (CRLs) or checked in real time with OCSP. End entities — servers, users, devices — hold private keys, ideally in hardware security modules or smart cards.

Trust and its failures

In the web PKI, any of several hundred trusted CAs can issue for any domain, a weakness addressed by Certificate Transparency logs, which make mis-issuance public, and by CAA DNS records restricting which CAs may issue. The 2011 compromise of the Dutch CA DigiNotar, which led to fraudulent certificates for major sites and the company's collapse, is the canonical failure case. Alternative trust models include the PGP web of trust, DANE, and SPKI.

Uses

Beyond HTTPS, PKI underpins document and code signing, smart-card logon, passport chips (ICAO PKI), payment systems and device identity in industrial and automotive networks. Standards come from the IETF (RFC 5280), the CA/Browser Forum baseline requirements, and ETSI.
