Instruction cache

An instruction cache, commonly called an I-cache, is a hardware cache used by a CPU to speed up access to instructions stored in slower main memory. It holds copies of recently or frequently fetched instructions so that the fetch stage of the processor pipeline can proceed without waiting for memory.

Design

Instruction caches exploit the locality of reference of program code: loops and frequently called routines tend to be executed repeatedly, so their instructions remain in the cache. Modern processors use a split L1 cache design, with separate instruction and data caches (a modified Harvard architecture), which allows simultaneous instruction fetch and data access. Larger, unified caches at the L2 and L3 levels back the L1 I-cache.

Operation

When the processor fetches an instruction at a given virtual or physical address, it first checks the I-cache. On a hit, the instruction is delivered immediately; on a miss, a cache line (typically 32–128 bytes) is loaded from a lower level of the memory hierarchy. Prefetching and branch prediction work with the I-cache to keep the pipeline supplied, fetching instructions along predicted execution paths.

Coherence issues

Because instruction caches may hold copies of code that is modified in memory—by a loader writing a new program, a just-in-time compiler, or self-modifying code—architectures must ensure coherence between the data and instruction caches, sometimes requiring explicit cache-flush or "fence" instructions.
