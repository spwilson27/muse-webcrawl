Security information and event management

Security information and event management (SIEM) is a field within computer security combining security information management (SIM) and security event management (SEM). SIEM systems provide real-time analysis of security alerts generated by applications and network hardware: they collect, normalize, aggregate, and correlate log and event data from many sources so that security teams can detect incidents, investigate them, and satisfy compliance reporting requirements.

A SIEM console correlates events from across an organization's systems to highlight genuine incidents.

Capabilities

  • Log collection and management: gathering logs from operating systems, applications, firewalls, intrusion detection systems, antivirus tools, and cloud services, and retaining them for forensic and compliance purposes.
  • Normalization and correlation: converting events into a common format and applying rules to link related events into incidents — for example, many failed logins followed by a successful one from an unusual location.
  • Alerting and dashboards: notifying analysts and presenting real-time views of security posture.
  • User and entity behavior analytics (UEBA): baselining normal behavior and flagging anomalies, increasingly with machine learning.

History

The term SIEM was coined by Gartner analysts Mark Nicolett and Amrit Williams in 2005. Early products grew out of separate log-management (SIM) and real-time event-correlation (SEM) tools. Modern SIEM platforms are frequently integrated with security orchestration, automation, and response (SOAR) features and with extended detection and response (XDR).

Deployment

SIEM systems are deployed in security operations centers (SOCs) of larger organizations, as on-premises appliances or software, and increasingly as cloud services. Their effectiveness depends heavily on tuning: badly configured correlation rules produce alert fatigue or miss genuine attacks.
