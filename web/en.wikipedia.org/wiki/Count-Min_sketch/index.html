Count–min sketch

A count–min sketch: each item increments one counter in every row; the estimate is the minimum.

The count–min sketch is a probabilistic data structure that serves as a frequency table of events in a stream of data. It was invented in 2003 by Graham Cormode and S. Muthu Muthukrishnan. Instead of storing an exact count for every item, it uses a fixed-size two-dimensional array of counters together with several different hash functions, trading a small, one-sided error for greatly reduced memory.

Structure and operations

The sketch is a table of width w and depth d. To update an item, the item is hashed by each of the d hash functions, and the counter at the hashed position in each row is incremented. To estimate the frequency of an item, the values of its d counters are read and the minimum is returned. Because collisions can only add counts, the estimate never under-counts; with w = ⌈e/ε⌉ and d = ⌈ln(1/δ)⌉, the estimate is within an additive ε of the true count with probability at least 1 − δ.

Applications

Count–min sketches are used for finding frequent items ("heavy hitters") in data streams, network traffic measurement, natural language processing, and approximate query processing in databases and streaming systems. Variants include the count sketch and conservative-update sketches, and the structure underlies approximate frequency tracking in systems such as Redis and Apache Spark.
