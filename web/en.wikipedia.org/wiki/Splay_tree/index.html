Splay tree

A splay tree is a self-adjusting binary search tree with the additional property that recently accessed elements are quick to access again. It performs basic operations such as insertion, look-up, and removal in O(log n) amortized time. For many sequences of non-uniformly distributed accesses, the splay tree can outperform other search trees, even after all accesses are counted, because it adapts its shape to the access pattern — an instance of the general principle of exploiting locality of reference.

Splaying

All normal operations on a splay tree are combined with a restructuring move called splaying: after accessing a node, a sequence of tree rotations moves it to the root. The rotations are organised in three cases applied bottom-up: zig (node is a child of the root — a single rotation), zig-zig (node and parent are both left children or both right children — rotate the grandparent, then the parent), and zig-zag (node and parent are opposite-side children — rotate the parent, then the grandparent). The zig-zig rule, in particular, is what distinguishes splaying from naively rotating the accessed node to the root, and is essential to the amortized bound.

Properties

Splay trees were introduced by Daniel Sleator and Robert Tarjan in 1985. They need no explicit bookkeeping of heights or balance colours, so each node stores no metadata beyond its pointers. Their performance is described by several celebrated results, including the static optimality theorem (they are as efficient as any fixed optimal search tree for a given access distribution, up to a constant factor) and the working set property (recently accessed items are fast to reach). Individual operations can, however, cost O(n) in the worst case, and splaying on every access makes the tree unsuitable where predictable latency or concurrent read access matters. A randomised alternative with similar aims is the treap.
