Transaction processing

Transaction processing is a style of computing in which individual, indivisible operations called transactions are executed completely or not at all. It is widely used in information systems that must maintain data integrity in multi-user environments, such as airline reservation systems, banking systems and online retail.

Properties

A transaction is conventionally required to satisfy the ACID properties: atomicity (all changes take effect or none do), consistency (the database moves from one valid state to another), isolation (concurrent transactions do not interfere with one another's intermediate results), and durability (once committed, a transaction's effects survive system failures). If any part of a transaction fails, the whole transaction is rolled back.

Systems

Transaction processing is typically managed by a transaction processing monitor or by the transaction facilities of a database management system. Online transaction processing (OLTP) systems handle many short transactions in real time, in contrast to batch processing and online analytical processing (OLAP). Distributed transactions spanning multiple databases can be coordinated with protocols such as two-phase commit.

History

Early transaction processing systems emerged in the 1960s with airline reservation systems such as SABRE and IBM's CICS. Research by Jim Gray and others formalised the concepts of transactions, locking and recovery that underpin modern systems.
