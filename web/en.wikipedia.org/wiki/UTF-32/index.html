UTF-32

UTF-32
TypeUnicode transformation format
Code unit size32 bits (fixed)
VariantsUTF-32BE, UTF-32LE

UTF-32 (32-bit Unicode Transformation Format), sometimes called UCS-4, is a fixed-length encoding used to encode Unicode code points, in which each code point is represented by exactly one 32-bit code unit. The code unit value is simply the code point itself, zero-extended. Because Unicode defines codespace up to U+10FFFF, the high-order bits are always zero.

Advantages

The principal advantage of UTF-32 is simplicity: the nth character of a string is found at a fixed offset, so indexing is O(1), and individual code points can be inserted, deleted, or accessed without scanning. This makes it convenient as an internal in-memory representation in some software, particularly in older Unix systems and libraries that used fixed-width wide characters.

Disadvantages

UTF-32 is space-inefficient: it uses four bytes for every character, even plain ASCII text, which costs four times the storage of UTF-8. No common file format or network protocol uses UTF-32 as its primary encoding, and the Unicode Consortium notes that "the use of UTF-32 as an encoding form for the interchange of text is discouraged". Its fixed width also no longer buys grapheme-level indexing, since user-perceived characters may consist of multiple code points, just as with UTF-8 and UTF-16.

Variants

UTF-32 comes in big-endian (UTF-32BE) and little-endian (UTF-32LE) forms. Unlabelled "UTF-32" in Unicode data streams uses big-endian byte order by default unless a byte order mark (U+FEFF) indicates otherwise. Programming languages such as Python used UTF-32 internally for strings in some configurations before adopting a flexible representation.
