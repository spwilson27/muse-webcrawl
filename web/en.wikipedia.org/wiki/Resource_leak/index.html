Resource leak

A resource leak is a type of resource consumption by a computer program in which the program fails to release resources it has acquired. Typically arising from a bug, a resource leak gradually depletes the available supply of a resource — such as memory, file handles, sockets or database connections — until the program or system degrades or crashes. Recovering the resources usually requires restarting the affected process, since most operating systems reclaim a process's resources only when it terminates.

Types

  • Memory leak — the best-known type, in which allocated memory is no longer referenced but never freed.
  • Handle/descriptor leaks — files, sockets or database connections opened but never closed, eventually exhausting system limits.
  • Other resources — leaks of locks, GPU memory, temporary files, or entries in finite system tables.

Causes and prevention

Leaks commonly occur when cleanup code is skipped on error paths, when ownership of a resource is ambiguous, or when data structures grow without bound. Prevention strategies include clear ownership conventions, idioms such as RAII in C++, try-with-resources and using blocks, garbage collection (which addresses memory but not other resources), and detection tools such as Valgrind, sanitizers and static analysers. In long-running servers even a small leak is serious, because resource consumption grows without limit over the process's lifetime.
