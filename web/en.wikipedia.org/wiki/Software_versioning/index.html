Software versioning

Software versioning is the process of assigning either unique version names or unique version numbers to unique states of computer software. Within a given version number category (major, minor), these numbers are generally assigned in increasing order and correspond to new developments in the software.

Schemes

Many schemes exist. A common sequence-based scheme uses dot-separated integers such as 1.0, 1.1, 2.0, where the first number signals a major release and later numbers mark minor changes and bug-fix (patch) releases. Semantic versioning (SemVer) formalises this as MAJOR.MINOR.PATCH: MAJOR increments for incompatible API changes, MINOR for backward-compatible features, and PATCH for backward-compatible fixes.

Other schemes are date-based (calendar versioning, as in Ubuntu's 22.04 for April 2022), use code names (Android dessert names, Debian release names from Toy Story characters), or employ marketing-driven numbering. Development stages are often labelled with suffixes: alpha, beta, release candidate (RC), and general availability (GA).

Internal versioning and ranges

Programs frequently carry separate internal version numbers (such as an operating system kernel version) alongside public product names. Package managers must interpret version ranges and ordering rules — including pre-release qualifiers and epochs — to resolve dependencies correctly.
