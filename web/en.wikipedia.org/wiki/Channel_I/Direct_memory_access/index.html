Direct memory access in channel I/O

Direct memory access (DMA) is the defining capability of the channel I/O architecture used by IBM mainframe computers: once an I/O operation has been started, a specialized processor called a channel transfers data directly between an input/output device and main storage (memory), without the central processing unit (CPU) having to move each byte or word itself. The CPU is interrupted only when the operation completes or an error occurs.

A channel moves data between a device and main storage independently of the CPU

Operation

An I/O operation begins when the CPU executes a START I/O instruction naming a subchannel. The channel subsystem then fetches a chain of channel command words (CCWs) — the channel program — from memory. Each CCW specifies a command (read, write, control, sense), a main-storage address, a byte count, and flags for chaining. The channel executes the program autonomously: it arbitrates for storage accesses, moves data in bursts, assembles and disassembles records, and posts status in the subchannel when finished.

Because the channel fetches its commands from memory and scatters or gathers data using CCW data chaining, a single START I/O can fill an arbitrary set of buffers. Address translation and protection are applied by the channel subsystem so that a channel program operating on behalf of one program cannot access another program's storage.

Comparison with programmed I/O

On smaller computers, DMA is usually provided by a simple DMA controller that moves a contiguous block between a device and memory. Mainframe channel DMA is more general: the channel is itself a programmable processor executing command chains, handling device-specific control operations, retry, and error recovery in parallel with normal CPU work. This offload was essential to the throughput of systems such as the System/360, whose selector and multiplexor channels sustained many simultaneous device transfers while the CPU continued executing application programs.
