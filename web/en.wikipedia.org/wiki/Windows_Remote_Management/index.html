Windows Remote Management

DeveloperMicrosoft
TypeRemote administration service
ProtocolWS-Management (SOAP over HTTP/HTTPS)
Ports5985 (HTTP), 5986 (HTTPS)
Included inWindows Vista / Server 2008 and later

Windows Remote Management (WinRM) is Microsoft's implementation of the WS-Management protocol, a standard SOAP-based protocol that allows hardware and operating systems to interoperate for remote administration. WinRM is the server component used by Windows PowerShell remoting and by the command-line tools winrm and winrs.

Components

  • WinRM service — listens for WS-Management requests, by default on TCP port 5985 for HTTP and 5986 for HTTPS.
  • winrm.exe — the command-line tool used to configure listeners, certificates, authentication settings and the service itself (for example winrm quickconfig).
  • winrs.exe — Windows Remote Shell, which runs a command on a remote machine through WinRM.
  • PowerShell Remoting — Enter-PSSession and Invoke-Command run over WinRM, making it the default remoting transport for Windows administration.
  • WMI plug-in — allows remote WMI access through WS-Management rather than DCOM.

Security

WinRM supports Kerberos, NTLM (including Negotiate), CredSSP, Digest and certificate-based authentication. Within a domain, Kerberos is typical; for workgroup machines, HTTPS listeners with certificates or explicitly configured TrustedHosts lists are commonly used. Traffic over HTTP is authenticated and the payload is encrypted by the authentication layer in domain scenarios, but HTTPS is recommended for stronger guarantees.

History

WinRM 1.1 shipped with Windows Vista and Server 2008; version 2.0, bundled with Windows 7 and PowerShell 2.0, added the PowerShell remoting architecture. Later versions shipped in the Windows Management Framework packages.
