Single-responsibility principle

The single-responsibility principle (SRP) is a computer programming principle stating that a module, class or function should have responsibility over a single part of a program's functionality, and should encapsulate it. Popularly phrased by Robert C. Martin as: a class should have only one reason to change.

Context

SRP is the "S" in the SOLID principles of object-oriented design articulated by Martin. Separating responsibilities makes software easier to understand, test and maintain, and reduces coupling between unrelated concerns. Critics note that "one reason to change" is subjective and that excessive decomposition can fragment a design.
