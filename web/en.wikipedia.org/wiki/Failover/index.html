Failover

Failover is the process of automatically switching to a redundant or standby computer server, system, hardware component, or network when the previously active application, server, system, hardware component, or network fails or is terminated abnormally. Failover and switchover are closely related: switchover typically describes a planned/manual switch, while failover happens automatically in response to a failure.

Systems designers usually provide failover capability in servers, systems, or networks requiring continuous availability and a high degree of reliability. At the server level, failover automation usually uses a "heartbeat" cable that connects two servers; as long as a regular "pulse" or "heartbeat" continues between the main server and the secondary server, the secondary will not initiate its systems. There may also be a third "spare parts" server that runs standby components for fault tolerance.

Design

The first server acts as primary and the second as standby. If the primary server becomes unavailable, the system fails over services to the standby. A variation is to use a secondary system in normal operation: this is called a multi-master approach, in contrast to the active–passive (primary–standby) approach. In active–active configurations, both systems process requests and load is balanced between them, so the failure of one simply shifts its load to the other.

Failback

Failback is the process of restoring a system, component, or service previously in a state of failure back to its original, working state, and having the standby system go from performing a function to being back in standby mode. In databases, failover often involves promoting a replica to become the new primary; returning writes to the original primary requires resynchronisation to avoid data divergence.

Applications

Failover is used in database clusters, web hosting, telecommunications, and cloud computing, where virtual IP addresses and DNS changes can redirect traffic to healthy instances. It is also used in non-computing contexts: vehicle systems such as dual-circuit brakes, essential aircraft flight controls, and electrical grids all employ analogous automatic switching. In computing systems subject to intermittent failure, clustering with automated failover is a standard element of high availability architecture, often measured against service-level objectives such as 99.9% ("three nines") uptime.

Limitations

Failover mechanisms can themselves fail: split-brain scenarios occur when network partitions cause both nodes to believe they are primary. Techniques such as quorum, fencing, and STONITH ("shoot the other node in the head") are used to prevent data corruption in such cases. Failover also adds cost and complexity, and the standby resources may sit idle most of the time.
