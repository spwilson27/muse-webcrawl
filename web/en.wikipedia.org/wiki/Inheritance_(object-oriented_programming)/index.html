Inheritance (object-oriented programming)

Inheritance is a mechanism in object-oriented programming (OOP) in which one class, called a subclass or derived class, acquires the properties (fields) and behaviours (methods) of another class, called a superclass, base class, or parent class. Inheritance models an "is-a" relationship — for example, a Car is a Vehicle — and supports code reuse, hierarchical classification, and polymorphism, since a subclass can override inherited methods to specialize behaviour while remaining usable wherever the superclass is expected.

History

Inheritance was introduced by Simula 67, the first object-oriented language, and popularized by Smalltalk and later by C++, Java, and C#. In class-based languages the subclass inherits the interface and implementation of its parent; in prototype-based languages such as JavaScript, objects inherit directly from other objects.

Types of inheritance

In single inheritance, a subclass has exactly one direct superclass, as in Java and C#. In multiple inheritance, supported by C++ and Python, a class may inherit from several parents, which can cause the "diamond problem" when two parents share a common ancestor. Languages that avoid multiple inheritance of implementation often provide interfaces or traits as a partial substitute. Multilevel inheritance forms chains of classes, and hierarchical inheritance describes one parent with many children.

Substitutability

For inheritance to be sound, a subclass should be usable in place of its superclass without breaking expectations, a guideline formalized as the Liskov substitution principle. Violations — such as a Square class inheriting from Rectangle but breaking its independent width and height setters — are classic teaching examples.

Criticism and alternatives

Deep inheritance hierarchies can become fragile: a change to a base class can break subclasses (the fragile base class problem), and inheritance creates tight coupling between classes. A common design maxim is "favour composition over inheritance," building behaviour by combining objects rather than by extending classes. Patterns such as delegation, mixins, and interfaces address some of these concerns.
