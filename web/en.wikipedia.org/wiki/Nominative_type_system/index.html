Nominative type system

A nominative type system (also called a nominal type system) is a major class of type system in programming languages, in which compatibility and equivalence of data types is determined by explicit declarations and by type names, rather than by the internal structure of the types. It contrasts with structural type systems, where types are compatible if their structures match.

Characteristics

In a nominative system, two types with identical structure but different names are distinct and incompatible unless a relationship between them has been explicitly declared. Subtyping likewise holds only where declared — typically through class inheritance or interface implementation. For example, in Java or C#, a class Point with fields x and y is not interchangeable with an unrelated class Coordinate having the same fields; one must be declared to extend or implement the other, or both must share a common declared supertype.

Advantages and trade-offs

Nominative typing lets names carry semantic intent: a UserId and an OrderId may both wrap an integer yet be kept deliberately incompatible, catching mix-ups at compile time. It also supports encapsulation and abstraction boundaries and simplifies some compiler error messages. The cost is reduced flexibility: structurally identical types cannot be substituted for one another without intermediate declarations, which structural systems (as in OCaml, Go interfaces, or TypeScript) permit. Many languages mix the two approaches — nominal classes with structural interfaces, for instance.

Languages

Predominantly nominative languages include Java, C#, C++, and Scala. Rust's trait system is largely nominative for types though trait bounds are checked structurally. The debate between nominal and structural typing is a recurring theme in programming-language design.
