Eventual consistency is a consistency model used in distributed computing to achieve high availability. It guarantees that, if no new updates are made to a given data item, eventually all accesses to that item will return the last updated value. In contrast to strong consistency, reads may temporarily return stale values while updates propagate between replicas. Eventual consistency is a specific form of weak consistency and is one of the axes of the BASE philosophy (Basically Available, Soft state, Eventual consistency) popularized by large-scale web systems.

Motivation

Under the constraints formalized by the CAP theorem, a distributed system facing network partitions must trade off consistency against availability. Systems favouring availability — such as Amazon's Dynamo and its descendants Apache Cassandra and Riak — allow writes on any replica and reconcile them later, enabling them to keep operating and scale across data centres. Mechanisms for propagation and reconciliation include read repair, anti-entropy gossip, hinted handoff, version vectors, last-write-wins timestamps, and conflict-free replicated data types (CRDTs), which guarantee convergence by construction.

Variations

Stronger guarantees built on eventually consistent storage include read-your-writes, monotonic reads, and causal consistency. Many modern databases offer tunable consistency, letting each operation choose between eventual and stronger (quorum-based) levels. The Domain Name System is a long-standing example of an eventually consistent system, in which updates propagate through caches over hours.

Criticism

Eventual consistency complicates application development: programmers must handle stale reads and write conflicts that strong consistency would prevent. It is therefore considered unsuitable, in its pure form, for workloads such as financial transactions that require invariant preservation.
