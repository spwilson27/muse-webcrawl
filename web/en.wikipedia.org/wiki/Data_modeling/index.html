Data modeling

Data modeling (American English) or data modelling (British English) is the process of creating a data model for the data to be stored in a database. A data model defines how data elements relate to one another and to the properties of real-world entities, providing a structured framework for the design of information systems.

[ Hero image: An entity–relationship diagram for a simple order-processing system ]

Levels of model

  • Conceptual data model — identifies the highest-level entities and relationships of an organisation, independent of technology.
  • Logical data model — describes the structure of the data in detail: entities, attributes, keys, and relationships, still independent of a specific database product.
  • Physical data model — describes how the model is implemented in a particular database system, including tables, column types, indexes, and constraints.

Approaches

Entity–relationship modelling, introduced by Peter Chen in 1976, represents the world as entities connected by relationships. Object-oriented modelling uses classes and inheritance, closely aligned with UML class diagrams. For relational databases, normalisation organises attributes to eliminate redundancy. Dimensional modelling — star and snowflake schemas — optimises structures for analytical queries in data warehouses, while newer approaches such as Data Vault address auditability and change over time.

Purpose

A data model acts as a communication tool between business stakeholders and developers, documents an organisation's understanding of its information, and serves as the blueprint from which database schemas and application interfaces are generated.
