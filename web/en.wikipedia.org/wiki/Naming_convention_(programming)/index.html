Naming convention (programming)

A naming convention is a set of rules for choosing the character sequence used for identifiers in source code and documentation. Consistent naming improves readability, makes code easier to maintain, and can convey information about an identifier's type, scope, or purpose. Conventions are usually adopted per language community or per project and are often enforced by linters and style guides.

Language conventions

Python's PEP 8 prescribes snake_case for functions and variables, PascalCase for classes, and underscores to mark private names. Java conventionally uses camelCase for methods and variables and PascalCase for classes. In C, macros are usually written in upper case, while POSIX reserves certain prefixes for the implementation. JavaScript communities commonly follow camelCase, with PascalCase reserved for constructors and components.

Considerations

Good identifiers are descriptive but not excessively long, avoid ambiguous abbreviations, and are consistent within a codebase. Research on program comprehension suggests carefully chosen names measurably reduce maintenance effort. Critics of type-encoding schemes such as Hungarian notation note that modern editors and type checkers make such prefixes redundant, although "Apps Hungarian" — encoding semantic meaning rather than type — remains defended.
