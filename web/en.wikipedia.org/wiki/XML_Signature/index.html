XML Signature (also called XMLDSig, XML-DSig and XML-Sig) defines rules for digitally signing XML documents and, by reference, arbitrary data. It is a joint standard of the World Wide Web Consortium and the Internet Engineering Task Force. Unlike binary signature formats, an XML Signature is itself XML, so signatures can be embedded in, attached to, or used to envelop the data they sign.

Structure

A signature is contained in a <Signature> element with three parts:

  • SignedInfo — identifies the canonicalisation method, the signature algorithm (such as RSA-SHA256), and one or more <Reference> elements, each identifying data by URI, applying transforms, and recording a digest value.
  • SignatureValue — the base64-encoded digital signature computed over the canonicalised SignedInfo.
  • KeyInfo — optional information identifying the verification key, such as an X.509 certificate.

Signature types

Three forms are distinguished: an enveloped signature is embedded within the document it signs; an enveloping signature contains the signed data within itself; and a detached signature stands apart from the data, referencing it externally. Because XML can be serialised in many equivalent ways, canonical XML (C14N) normalises a document's representation before digesting, so that superficial changes (attribute order, whitespace in tags) do not invalidate signatures.

Applications and security

XML Signature underpins WS-Security for SOAP web services, SAML assertions in single sign-on, signed Office Open XML and OpenDocument files, and many e-government and e-invoicing systems. Its flexibility has also led to serious vulnerabilities when implemented carelessly — notably XML signature wrapping attacks against identity systems — which has motivated restrictive processing profiles in modern deployments.
