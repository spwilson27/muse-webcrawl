MQTT (originally an initialism of MQ Telemetry Transport) is a lightweight, publish-subscribe network protocol that transports messages between devices. The protocol usually runs over TCP/IP and is designed for connections with remote locations that have resource constraints or limited network bandwidth, making it a de facto standard for the Internet of things (IoT).

History

Andy Stanford-Clark of IBM and Arlen Nipper of Arcom Control Systems (now Eurotech) authored the first version of the protocol in 1999 for monitoring an oil pipeline over a satellite link. It was used by IBM internally and in products such as WebSphere MQ. In 2013 IBM submitted MQTT to the OASIS standards body; version 3.1.1 became an ISO standard (ISO/IEC 20922:2016), and MQTT 5.0 was released by OASIS in 2019.

Design

MQTT clients connect to a central broker and exchange messages addressed by hierarchical topic strings, using publish/subscribe decoupling in space and time. Messages are small (a minimum header of two bytes). Three quality-of-service levels are defined: QoS 0 (at most once), QoS 1 (at least once), and QoS 2 (exactly once). Additional features include retained messages, last-will messages, persistent sessions (in 3.1.1) and, in version 5, reason codes, message expiry, and shared subscriptions.

Applications

MQTT is used in home automation, industrial telemetry, connected vehicles, and mobile messaging infrastructures; Facebook Messenger historically used MQTT for chat delivery. Popular brokers include Eclipse Mosquitto, HiveMQ, and EMQX, and the Eclipse Paho project provides client libraries in many languages.
