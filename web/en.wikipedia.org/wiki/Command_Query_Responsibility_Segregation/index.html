Command Query Responsibility Segregation

Command Query Responsibility Segregation (CQRS) is a software architecture pattern that separates the model used to update information (commands) from the model used to read information (queries). The pattern was described and popularised by Greg Young, building on Bertrand Meyer's earlier command–query separation principle from object-oriented design. CQRS is frequently combined with event sourcing, in which state changes are stored as a sequence of events.

CQRS: writes (left) and reads (right) use different models, synchronised by events.

Principles

In a traditional CRUD architecture, a single data model both reads and modifies state. CQRS splits these responsibilities: the command side handles writes using a rich domain model that enforces business rules, while the query side uses a separate, often denormalised read model optimised for display and reporting. Because the two models are independent, each can be scaled, optimised, and even stored in different technologies. Updates to the read model are usually propagated asynchronously, making the system eventually consistent rather than immediately consistent.

Relation to event sourcing

CQRS is often paired with event sourcing: instead of storing current state, the command side stores a stream of domain events. Read models are then projections built by replaying or subscribing to those events. This combination yields a complete audit log and enables rebuilding read models in new shapes, at the cost of greater architectural complexity.

Benefits and drawbacks

Benefits include independent scaling of read and write workloads, read models tailored to specific queries, and a natural fit with domain-driven design's collaborative, task-based user interfaces. Drawbacks include substantially increased complexity, eventual consistency that developers and users must understand, and duplicated modelling effort. Critics, including some of the pattern's early advocates in particular contexts, note that CQRS is usually appropriate only for the bounded contexts of a system with genuinely divergent read/write requirements, rather than as a whole-system default.
