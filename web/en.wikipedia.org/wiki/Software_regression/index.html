Software regression

A regression test suite re-run after a code change

A software regression is a type of software bug in which a feature that previously worked correctly stops working, typically after changes are made to the software — a bug fix, a new feature, a refactoring, or a change in the environment. The term comes from "regressing" to an earlier, worse state.

Types

Regressions are often classified as local (a change directly breaks nearby functionality), remote (a change in one part of the code breaks functionality elsewhere), and unmasked (a pre-existing latent bug becomes visible after a change). "Regression" can also refer to performance regressions, in which code changes make the software slower or more resource-hungry without breaking correctness.

Prevention and detection

The standard countermeasure is regression testing: maintaining a suite of automated tests covering existing behavior and re-running it whenever the code changes, so failures introduced by a change are caught immediately. In continuous integration, the suite runs on every commit. When a regression is found, developers often use bisecting (for example, git bisect) to identify the exact change that introduced it. A regression test is usually added for any fixed bug to prevent its recurrence.
