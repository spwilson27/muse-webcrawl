Swapping

[Image placeholder: memory swapping]

In computer systems, swapping is a memory management scheme in which a process can be temporarily moved out of main memory (RAM) to a backing store — commonly a hard disk or SSD — and later brought back into memory for continued execution. Swapping allows the combined memory requirements of all running processes to exceed the amount of physical memory installed.

Overview

A process that has been swapped out occupies a region of the backing store known as the swap space or swap area. When the scheduler decides to run the process again, it is swapped back in, possibly to a different location in memory. Swapping is performed by a part of the operating system kernel sometimes called the swapper or, in systems with paging, in coordination with the pager.

Swapping and paging

Swapping originally operated on whole processes. Modern virtual memory systems instead use paging, in which individual pages of a process are moved between memory and disk on demand. The terminology overlaps: on many systems, "swapping" informally refers to page-level transfers to the swap area, and Linux, for example, uses a swap partition or swap file for anonymous pages evicted from RAM.

Performance

Because disk access is far slower than RAM access, excessive swapping causes severe slowdowns, a condition known as thrashing. The time taken to swap a process depends on the amount of memory transferred and the speed of the backing store; solid-state drives have greatly reduced swap latency compared with rotating disks.

History

Swapping was one of the earliest memory management techniques, used in time-sharing systems of the 1960s such as CTSS, where only one user program could reside in memory at a time. It remains a fallback mechanism in modern operating systems when physical memory is exhausted.
