Hazard (computer architecture)

In the domain of central processing unit design, hazards are problems with the instruction pipeline in CPU microarchitectures when the next instruction cannot execute in the following clock cycle, potentially reducing performance. Hazards arise because pipelining overlaps the execution of multiple instructions whose interactions are not always compatible with simple sequential semantics.

Types

Data hazards occur when instructions depend on the results of prior instructions, divided into read-after-write (true dependency), write-after-read, and write-after-write hazards. Structural hazards occur when hardware cannot support a combination of instructions simultaneously, such as two instructions needing the same functional unit. Control hazards stem from branches and other instructions that change the program counter.

Handling

Techniques for dealing with hazards include pipeline stalls ("bubbles"), operand forwarding (bypassing), register renaming, out-of-order execution, and branch prediction. Compilers can also schedule instructions to avoid stalls.
