Software configuration management

SCM tracks and controls changes to software artifacts throughout the development life cycle.

Software configuration management (SCM or S/W CM) is the discipline of identifying, organizing, and controlling changes to software artifacts — source code, documentation, configuration files, and build outputs — throughout the software development life cycle. It answers the questions of what changed, when, why, and by whom, and it ensures that a given version of a system can be reliably reconstructed. SCM is one of the supporting process areas of maturity frameworks such as CMMI and of standards such as ISO 10007.

Core activities

Standard formulations describe four main activities. Configuration identification selects the artifacts ("configuration items") to be controlled and establishes baselines — formally agreed versions that serve as references for further development. Configuration change control evaluates, approves, and tracks change requests, often through a change control board. Configuration status accounting records and reports the state of configuration items and baselines. Configuration audits verify that a delivered product matches its documentation and requirements.

Version control and tooling

The best-known component of SCM is version control. Early tools such as SCCS (1972) and RCS managed individual files; CVS and later Subversion centralized versioning of whole projects; and distributed systems such as Git and Mercurial, in which every developer holds a full repository history, became dominant in the 2000s and 2010s. Modern practice extends SCM into build automation, continuous integration, release management, and infrastructure as code. Related concepts include branching and merging strategies, software bills of materials, and configuration management of deployed systems, which overlaps with IT configuration management databases (CMDBs).
