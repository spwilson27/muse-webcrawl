Object-oriented design

Object-oriented design (OOD) is the process of planning a system of interacting objects for the purpose of solving a software problem. It is one approach to software design, and it forms the design stage of the object-oriented software development life cycle, following object-oriented analysis and preceding implementation in an object-oriented programming language.

Overview

In object-oriented design, the designer identifies the objects (and classes of objects) that make up the system, the attributes and operations of each, and the relationships among them — including inheritance, composition, and association. An object is understood to have identity, state, and behavior, and to communicate with other objects by sending messages. The goal is a design that is modular, extensible, and maintainable, with each object encapsulating its data and exposing a well-defined interface.

Key concepts

  • Encapsulation — bundling data with the operations that act on it and hiding internal detail.
  • Abstraction — modeling only the essential characteristics of a thing relevant to the problem.
  • Inheritance — deriving new classes from existing ones, reusing and extending their behavior.
  • Polymorphism — allowing objects of different classes to respond to the same message in their own ways.
  • Coupling and cohesion — design aims for loose coupling between objects and high cohesion within them.

Methods and notation

Early methodologies included Grady Booch's object-oriented design method, James Rumbaugh's Object Modeling Technique (OMT), and Ivar Jacobson's use-case-driven approach; these converged in the Unified Modeling Language (UML), standardized in the 1990s, which provides class diagrams, sequence diagrams, and other views of an object-oriented design. Responsibility-driven design, popularized by Rebecca Wirfs-Brock, emphasizes identifying object roles and responsibilities, often using CRC (Class-Responsibility-Collaborator) cards. Design patterns, catalogued by the "Gang of Four" in 1994, capture reusable solutions to common design problems, and principles such as SOLID summarize widely taught heuristics for class design.
