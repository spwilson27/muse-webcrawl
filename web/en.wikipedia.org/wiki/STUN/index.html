STUN

STUN
Full nameSession Traversal Utilities for NAT
StandardRFC 8489 (obsoletes RFC 5389)
Port3478 (UDP/TCP); 5349 (TLS)
PurposeNAT traversal; discovering public IP address and port

STUN (Session Traversal Utilities for NAT) is a standardised set of methods and a network protocol that allows an end host to discover its public IP address and port as allocated by a network address translator (NAT), and to determine restrictions on how that mapping can be used. It is defined by the IETF in RFC 8489.

Operation

A client behind a NAT sends a Binding request to a STUN server on the public Internet. The server replies with the client's "server-reflexive" address — the address and port as seen from the public side. By comparing this with its local address, the client can tell whether it is behind NAT and can advertise the reflexive address to peers so that media or data can flow directly between them. STUN also provides keep-alive and connectivity-check mechanisms.

Role in ICE and WebRTC

STUN is a core component of the ICE framework used by WebRTC, SIP telephony and online games to establish peer-to-peer connections. Where direct connectivity fails — for example behind symmetric NATs — ICE falls back on TURN servers, which relay traffic and use STUN's message format and authentication mechanisms.

History

The original protocol, "Simple Traversal of UDP through NATs", was published as RFC 3489 in 2003. Experience showed that classifying NAT types was unreliable, so RFC 5389 (2008) redefined STUN as a toolbox of traversal utilities and backronymed the name to its present form; RFC 8489 (2020) is the current revision.
