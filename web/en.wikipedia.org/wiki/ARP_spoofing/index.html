ARP spoofing

ARP spoofing, ARP cache poisoning, or ARP poison routing, is a technique by which an attacker sends (spoofed) Address Resolution Protocol (ARP) messages onto a local area network. The aim is to associate the attacker's MAC address with the IP address of another host, such as the default gateway, causing any traffic meant for that IP address to be sent to the attacker instead.

Mechanism

ARP was designed without any authentication mechanism: a host accepts ARP replies even if it never sent a request, and updates its ARP cache accordingly. An attacker exploits this by sending forged ARP replies claiming that the attacker's MAC address corresponds to the gateway's IP address. Victims then send their traffic to the attacker, who may simply forward it (a man-in-the-middle attack), modify it, or drop it (a denial-of-service attack).

Uses

ARP spoofing can be used to intercept, modify, or stop data in transit on a switched network, enabling session hijacking, eavesdropping on unencrypted traffic, and credential theft. It is also used legitimately in some network administration, virtualisation and high-availability setups, and is a feature of tools such as arpspoof, Ettercap and Cain and Abel.

Defences

Defences include static ARP entries for critical hosts, Dynamic ARP Inspection on managed switches (which validates ARP packets against a DHCP snooping database), ARP monitoring tools such as Arpwatch, and the use of encrypted protocols (such as TLS and SSH) so that intercepted traffic cannot be read or usefully modified.
