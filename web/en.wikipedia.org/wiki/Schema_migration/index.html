Schema migration

In software engineering, schema migration (also database migration, or database change management) refers to the management of version-controlled, incremental and reversible changes to a relational database schema. A schema migration is performed on a database whenever it is necessary to update or revert that database's schema to some newer or older version.

Migrations are generally performed programmatically by means of a migration tool, or manually by executing the required SQL statements. Each migration is recorded so that a database can be automatically brought to any target version, which allows application code and schema to evolve together and keeps development, staging, and production databases consistent.

Purpose

Schema migrations let teams track schema changes in version control alongside application code, automate deployments, and roll changes back when problems occur. Frameworks such as Ruby on Rails, Django, Laravel, and Alembic provide migration systems, while standalone tools include Flyway and Liquibase.

Risks

Migrations can be risky on large production databases: a change that is trivial on a small development database may lock tables or take hours on a large one, and data-transforming migrations can be difficult to reverse. Expand-and-contract (parallel change) patterns are often used to migrate without downtime.
