Pastry (DHT)

From Wikipedia, the free encyclopedia

Pastry is an overlay network and routing substrate for the implementation of a distributed hash table (DHT) similar to Chord. The key–value pairs are stored in the peer machine that owns a specified key, and each machine is responsible for responding to requests for a pair of keys that it owns. Pastry was developed by researchers at Microsoft Research and Rice University, principally Antony Rowstron and Peter Druschel, and published in 2001.

Design

Each node in a Pastry network is assigned a randomly chosen 128-bit node identifier (nodeId) from a circular identifier space. NodeIds are uniformly distributed, so nodes with adjacent identifiers are spread across the network. Keys are likewise 128-bit values; a key is assigned to the live node whose nodeId is numerically closest to the key.

Routing

Each node maintains a routing table organised by the length of shared prefix, in digits, between its own nodeId and other nodes' identifiers, for a chosen base 2b (typically b = 4). Messages are routed in O(log2b N) hops: at each hop the message is forwarded to a node sharing a longer prefix with the key than the current node. A leaf set of numerically nearest neighbours is also maintained, giving fault tolerance when nodes fail.

Locality

Pastry routes take account of network locality: in principle, depending on the selection of nodes within a routing-table cell, routing can be made to prefer physically near nodes, reducing delay. Pastry has been used as the routing layer for systems such as the SCRIBE multicast system and the PAST distributed file store.
