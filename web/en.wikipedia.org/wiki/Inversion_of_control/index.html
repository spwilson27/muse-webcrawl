Inversion of control

Inversion of control (IoC) is a programming principle in which a program's custom-written code receives the flow of control from a generic framework, rather than the custom code controlling the flow itself. In traditional procedural programming, the main program calls into reusable libraries; with inversion of control, the reusable framework calls the specialised code, a shift summarised by the "Hollywood principle": "Don't call us, we'll call you."

Forms

Event-driven programming and graphical user-interface frameworks exemplify IoC: the framework runs an event loop and invokes the programmer's handlers in response to user actions. Callbacks, the observer pattern, and template methods are common mechanisms. In object-oriented design, IoC is often achieved through dependency injection, in which an object's dependencies are supplied to it rather than created by it, making components easier to test and substitute.

Benefits and criticism

Inversion of control promotes loose coupling, modularity, and reuse of framework behaviour. Critics note that it can make control flow harder to follow, since the sequence of execution is determined by the framework rather than by explicit code.
