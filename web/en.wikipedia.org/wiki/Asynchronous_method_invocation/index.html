Asynchronous method invocation

In multithreaded computer programming, asynchronous method invocation (AMI), also known as asynchronous method calls or the asynchronous pattern, is a design pattern in which the call site is not blocked while waiting for the called code to finish. Instead, the calling thread is notified when the reply arrives. Polling for a reply is an undesired option.

Background

Most method calls are synchronous, meaning that when the method is invoked the calling method waits (blocks) until the callee returns control. Long-running operations, such as reading a large file, querying a remote service, or performing a lengthy computation, can therefore stall the caller — in a graphical user interface this makes the application appear frozen. Asynchronous invocation lets the caller continue with other work while the operation proceeds.

Implementations

Common mechanisms for asynchronous invocation include:

  • Futures and promises — the call returns a placeholder object immediately; the caller can later block on, poll, or chain continuations to the placeholder.
  • Callbacks — the caller supplies a function to be invoked when the operation completes, as in event-driven JavaScript and Node.js.
  • async/await — language-level syntax (e.g. in C#, Python, JavaScript, Rust) that lets asynchronous code be written in a sequential style.
  • Message passing and actor systems — requests are sent as messages and replies delivered as further messages.

Middleware frameworks such as CORBA, the Internet Communications Engine (Ice), and .NET Remoting/WCF provide AMI facilities, often generating proxy code that hides the threading and marshalling details from the caller.
