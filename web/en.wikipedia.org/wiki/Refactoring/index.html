Refactoring

Image placeholder: code being restructured without behaviour change.

Code refactoring is the process of restructuring existing source code — changing its internal structure — without changing its external behaviour. The goal is to improve non-functional attributes of the software, such as readability, maintainability and extensibility, and to reduce complexity and technical debt.

Techniques

Common refactorings include renaming variables and methods, extracting methods, moving code between classes, inlining, and replacing conditional logic with polymorphism. Martin Fowler's 1999 book Refactoring: Improving the Design of Existing Code catalogued dozens of named refactorings and popularised the term. Modern development environments automate many of them, and automated regression tests give the safety net that makes frequent small refactorings practical.

Motivation

Software tends to accumulate design degradation as features are added under time pressure. Regular refactoring counteracts this "code rot", making future changes cheaper and safer. In agile methods such as extreme programming, refactoring is a continuous activity interleaved with test-driven development rather than a separate phase.
