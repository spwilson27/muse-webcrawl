Application performance management

In the fields of information technology and systems management, application performance management (APM) is the monitoring and management of the performance and availability of software applications. APM strives to detect and diagnose complex application performance problems to maintain an expected level of service, and it is often described as the translation of IT metrics into business meaning.

Dimensions

Industry analysts commonly distinguish several dimensions of APM:

  • End-user experience monitoring — measuring the response times and quality experienced by real users, or by synthetic ("robot") transactions.
  • Runtime application architecture discovery and modelling — mapping the components an application traverses in production.
  • User-defined transaction profiling — tracing individual business transactions across components.
  • Component deep-dive monitoring — detailed instrumentation of application servers, middleware and databases.
  • Analytics — correlating large volumes of performance data to detect patterns and root causes.

Approaches

APM tools collect metrics such as response time, throughput, error rates and resource consumption (CPU, memory, disk and network). Two broad data collection methods are common: agent-based instrumentation of application code (for example, bytecode instrumentation in Java or .NET environments), and network-based approaches that infer application behaviour from traffic inspection. Modern APM increasingly overlaps with observability practices built on metrics, logs and distributed traces.

Business context

Because slow or unavailable applications directly affect revenue and user satisfaction, APM is used to enforce service-level objectives and to prioritise engineering work. Common use cases include incident detection, capacity planning, release validation and digital experience monitoring for web and mobile applications.
