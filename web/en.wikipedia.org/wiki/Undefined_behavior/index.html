Undefined behavior

In computer programming, particularly in the C and C++ languages, undefined behavior (UB) is the result of executing a program whose behavior is not specified by the language standard—for example, accessing a deallocated memory location, dereferencing a null pointer, or causing signed integer overflow. The standard imposes no requirements on a program once undefined behavior occurs: the implementation may ignore the situation, behave predictably, or, in the jocular phrasing of programmers, cause "demons to fly out of your nose".

Rationale

Leaving behavior undefined allows compilers to omit run-time checks and to make aggressive optimizations by assuming that undefined situations never arise. This has led to famous surprises, such as compilers deleting null-pointer checks that appeared after a dereference, because the earlier dereference would already have been undefined behavior if the pointer were null. The C standard lists hundreds of instances of undefined behavior in an informative annex.

Related notions

Undefined behavior is distinguished from unspecified behavior, where the standard offers several possibilities and the implementation need not document which, and from implementation-defined behavior, which must be documented. Modern tooling—sanitizers such as UBSan and AddressSanitizer—helps detect undefined behavior at run time, and newer languages such as Rust aim to make such behavior impossible in safe code.
