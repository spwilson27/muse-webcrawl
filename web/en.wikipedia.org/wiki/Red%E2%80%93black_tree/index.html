Red–black tree

From Wikipedia, the free encyclopedia

In computer science, a red–black tree is a binary search tree data structure, a type of self-balancing binary search tree. Each node stores a color attribute, either red or black, and the tree maintains balance through a set of coloring rules enforced during insertion and deletion. Red–black trees guarantee that search, insertion, and deletion operations take O(log n) time in the worst case, where n is the number of nodes.

History

Red–black trees were invented in 1972 by Rudolf Bayer, who called them "symmetric binary B-trees". The modern name and the red–black coloring scheme derive from a 1978 paper by Leonidas J. Guibas and Robert Sedgewick, who used red and black pens in their analysis; the colors are also often said to have been chosen because red and black were the best-looking colors produced by the laser printer at Xerox PARC, or because they were the colors of pens available. Chris Okasaki popularized a purely functional formulation in 1999.

Properties

In addition to the requirements imposed on a binary search tree, a red–black tree satisfies the following properties:

  1. Every node is either red or black.
  2. All null leaves (NIL nodes) are considered black.
  3. A red node does not have a red child (no two red nodes are adjacent).
  4. Every path from a given node to any of its descendant NIL nodes contains the same number of black nodes (the black height).
  5. (In some conventions) The root is black.

These constraints ensure that the longest possible path from the root to a leaf is no more than twice as long as the shortest possible path, meaning the tree remains approximately balanced. The height of a red–black tree with n internal nodes is at most 2 log2(n + 1).

Operations

Search in a red–black tree proceeds exactly as in an ordinary binary search tree. Insertion and deletion, however, may violate the red–black properties; balance is restored by recoloring nodes and performing tree rotations (left and right). At most two rotations are required after an insertion, and at most three after a deletion, so the restructuring is cheap compared to the O(log n) descent.

Applications

Red–black trees are widely used in practice. They underlie the implementation of associative containers in several standard libraries: std::map and std::set in C++, TreeMap and TreeSet in Java, and the Completely Fair Scheduler in the Linux kernel historically used a red–black tree to organize runnable tasks. They are closely related to B-trees: a red–black tree is equivalent to a B-tree of order 4.
