Dependency injection

Dependency injection (DI) is a software design pattern in which an object or function receives other objects or functions (dependencies) that it requires, rather than creating them internally. It is a form of inversion of control and is used to increase modularity and testability.

Overview

A client that needs a service does not create the service itself; instead, an external entity — often called an injector, assembler, or container — supplies it. Dependencies can be supplied through constructor injection, setter injection, or interface injection.

Advantages and disadvantages

Dependency injection simplifies unit testing because dependencies can be replaced with mock objects, and it decouples classes from the concrete implementations they use. Critics argue that it can obscure where dependencies come from and add framework complexity.
