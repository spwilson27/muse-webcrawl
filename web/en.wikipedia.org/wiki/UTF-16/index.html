UTF-16 (16-bit Unicode Transformation Format) is a character encoding capable of encoding all 1,112,064 valid code points of Unicode. The encoding is variable-length, as code points are encoded with one or two 16-bit code units. UTF-16 arose from the earlier fixed-width 16-bit encoding UCS-2, once it became clear that more than 216 code points were needed.

UTF-16 encodes Basic Multilingual Plane characters in a single 16-bit unit and supplementary characters as surrogate pairs.

Encoding

Code points from the Basic Multilingual Plane (BMP, U+0000 through U+FFFF), excluding the surrogate range U+D800–U+DFFF, are encoded in a single 16-bit code unit equal to the code point value. Code points in the supplementary planes (U+10000 through U+10FFFF) are encoded as a pair of code units called a surrogate pair: the code point is reduced by 0x10000, split into two 10-bit halves, and each half is offset into the high-surrogate range (U+D800–U+DBFF) and low-surrogate range (U+DC00–U+DFFF) respectively.

Byte order

UTF-16 data can be serialized in big-endian or little-endian order. A leading byte order mark (BOM)—the code point U+FEFF encoded in the stream—indicates which order is used; in its absence, external metadata must specify the order, and the Unicode standard defaults to big-endian for the label "UTF-16". The explicit labels UTF-16BE and UTF-16LE forbid the ambiguity. By contrast, UTF-8 has a single unambiguous byte order.

Usage

UTF-16 is the native string encoding of the Microsoft Windows API, Java, JavaScript (which uses UTF-16 code units for strings, including lone surrogates), the .NET Framework, Qt, and many other platforms and file formats. It is efficient for text dominated by BMP characters, such as most East Asian scripts, but less compact than UTF-8 for ASCII-heavy text, and it predominates less on the World Wide Web, where UTF-8 is dominant.
