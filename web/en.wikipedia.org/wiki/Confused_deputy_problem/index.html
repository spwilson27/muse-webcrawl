Confused deputy problem

In information security, a confused deputy is a computer program that is tricked by another program (or user) into misusing its authority on the third party's behalf. It is a specific type of privilege escalation. The term and the classic example were set out by Norm Hardy in 1988.

The classic example

Hardy described a compiler program on a timesharing system that also wrote billing statistics to a file it alone was authorized to access. Users could specify the name of an output file for debugging information; by naming the billing file, a user could trick the compiler — the "deputy" holding special privileges — into overwriting it. The compiler was "confused" because it could not distinguish its own authority from the authority the user asked it to exercise.

General pattern

The problem arises whenever a privileged program acts on designations (such as file names) supplied by a less privileged party without checking that the party has the corresponding rights. Familiar examples include cross-site request forgery on the web, setuid programs misled by arguments or environment, and cloud services that act on attacker-supplied resource identifiers.

Solutions

The capability-based security model addresses the problem by designating resources with unforgeable tokens that themselves convey authority, so designation and authorization cannot come apart. Other mitigations include careful separation of privileges and validating that the requester is authorized for each requested resource.
