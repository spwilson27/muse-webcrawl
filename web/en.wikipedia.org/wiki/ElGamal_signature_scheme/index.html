The ElGamal signature scheme is a digital signature scheme which is based on the difficulty of computing discrete logarithms. It was described by Taher Elgamal in 1985. The scheme is rarely used directly in practice, but its close variant, the Digital Signature Algorithm (DSA), was standardised by NIST and is widely deployed; the Schnorr signature scheme is also closely related.

Parameters and keys

System parameters consist of a large prime p, a generator g of the multiplicative group modulo p, and a cryptographic hash function H. The signer chooses a private key x with 1 < x < p − 1 and publishes the public key y = gx mod p.

Signing

To sign a message m, the signer chooses a random k coprime to p − 1, computes r = gk mod p, and then s = (H(m) − xr) k−1 mod (p − 1). The signature is the pair (r, s). The value k must be kept secret and never reused: reusing k for two signatures allows an attacker to solve for the private key x.

Verification

A verifier checks that 0 < r < p and 0 < s < p − 1, and confirms that gH(m) ≡ yr rs (mod p). If the congruence holds, the signature is accepted; correctness follows by substituting the definition of s.

Security

Forging an ElGamal signature requires either solving the discrete logarithm problem or finding hash collisions. The scheme is existentially forgeable in its raw form for certain parameter choices, which is one reason hashed, standardised descendants such as DSA are preferred. The requirement for a fresh, unpredictable k per signature is shared with DSA and ECDSA, where nonce failures have caused real-world key compromises.
