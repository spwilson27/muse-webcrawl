Object-oriented programming

From Wikipedia, the free encyclopedia
[Image: A class diagram with boxes for classes and arrows for inheritance]

Object-oriented programming (OOP) is a programming paradigm based on the concept of objects, which bundle data (fields/attributes) and code (methods/procedures) that operate on it. Programs are designed by making objects interact with one another, rather than by structuring code primarily around functions and logic.

The paradigm's core ideas are encapsulation (hiding internal state), inheritance (deriving new classes from existing ones), and polymorphism (objects of different types responding to the same interface). Alan Kay coined the term 'object-oriented' for Smalltalk in the 1970s; roots reach back to Simula 67 (Kristen Nygaard and Ole-Johan Dahl), the first object-oriented language.

History and languages

Smalltalk (Xerox PARC, 1970s) purified the model; C++ (Bjarne Stroustrup, 1985) brought OOP to systems programming and mass adoption; Java (1995) carried it to enterprise and education, followed by C#, Python, Ruby, and others — most modern mainstream languages are multi-paradigm with OOP support.

Design patterns (the 1994 'Gang of Four' book) codified reusable OOP solutions; UML diagrams standardised their depiction.

Criticism

OOP is criticised for inheritance hierarchies that tangle, over-engineered class structures, and statefulness complicating concurrency; functional programming and composition-over-inheritance are frequent alternatives, and modern languages blend the paradigms. Influential advocates (Kay himself) note mainstream OOP diverged from the original message-passing vision.
