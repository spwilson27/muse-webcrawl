Polynomial time

In computational complexity theory, polynomial time refers to an amount of time that is bounded by a polynomial expression in the size of the input for an algorithm. That is, the running time is O(nk) for some fixed constant k, where n is the input size. Problems solvable in polynomial time are generally regarded as tractable, and the complexity class of decision problems solvable in polynomial time by a deterministic Turing machine is denoted P.

Definition

An algorithm is said to run in polynomial time if its running time is upper bounded by a polynomial in the length of the input. Polynomial-time algorithms include basic arithmetic, sorting (O(n log n) or O(n²)), matrix multiplication, linear programming (via the ellipsoid and interior-point methods), and graph algorithms such as Dijkstra's shortest path algorithm. By contrast, algorithms with running times such as O(2n) are exponential time and rapidly become infeasible even for moderate input sizes.

Complexity classes

The class NP consists of decision problems whose "yes" instances have certificates verifiable in polynomial time. It is unknown whether P = NP — the most famous open problem in computer science and one of the Clay Mathematics Institute's Millennium Prize Problems. Polynomial time is closed under composition: running a polynomial-time subroutine a polynomial number of times yields another polynomial-time algorithm, a property essential to the theory of polynomial-time reductions used to prove NP-completeness.

Strong and weak polynomial time

An algorithm runs in strongly polynomial time if the number of arithmetic operations is polynomial in the number of input numbers (independent of their magnitude) and the space used is polynomial in the input size. Algorithms such as the simplex method for linear programming are polynomial in practice for many inputs but are not known to be strongly polynomial; the existence of a strongly polynomial algorithm for linear programming is a major open question (Smale's 9th problem). Pseudopolynomial algorithms, such as dynamic programming for the knapsack problem, run in time polynomial in the numeric values but exponential in their bit-length.

Related notions

Finer distinctions include linear time, quadratic time, and sublinear time; randomized and quantum analogues include BPP and BQP. Quasi-polynomial time, nO(log n), lies between polynomial and exponential time and arises for problems such as graph isomorphism.
