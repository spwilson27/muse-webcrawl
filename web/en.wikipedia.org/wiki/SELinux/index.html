SELinux

SELinux enforces mandatory access control in the Linux kernel

Security-Enhanced Linux (SELinux) is a Linux kernel security module that provides a mechanism for supporting access control security policies, including mandatory access controls (MAC). SELinux is a set of kernel modifications and user-space tools that can be added to various Linux distributions. Its architecture strives to separate enforcement of security decisions from the security policy itself, and streamlines the amount of software involved with security policy enforcement.

History

SELinux was originally developed by the United States National Security Agency (NSA), building on the Flask security architecture developed at the University of Utah and elsewhere. It was released to the open source community in December 2000 and integrated into the mainline Linux kernel in 2003 (kernel 2.6), using the Linux Security Modules (LSM) interface. Red Hat Enterprise Linux adopted it as a flagship feature, shipping it enabled by default from RHEL 4 in 2005. SELinux technology also underlies the SEAndroid enhancements used to confine applications in the Android operating system.

How it works

Under SELinux, every process and file is assigned a security context containing a user, role, type, and optionally a sensitivity level. Access decisions are made by comparing contexts against a compiled policy, principally using type enforcement: a process running in a given domain type may perform only the operations on object types that the policy explicitly permits. Unlike traditional discretionary access control based on users and permissions, the policy applies to all users including root, so a compromised service remains confined to the resources its policy allows. SELinux operates in enforcing, permissive (logging-only), or disabled modes, and distributions typically ship a targeted policy confining network-facing services, or a stricter multi-level security (MLS) policy.

Criticism

SELinux has been criticised for complexity: writing and debugging policies is difficult, and administrators have often disabled it rather than resolve denials, a practice widely advised against by distributions.
