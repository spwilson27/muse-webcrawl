Apache Maven is a build automation and project management tool used primarily for Java projects. Maven addresses two aspects of building software: how the software is built, and its dependencies. It uses an XML file called the Project Object Model (POM) to describe the project, its dependencies on external libraries, the build order, directories, and required plug-ins, following the principle of convention over configuration.

Maven standardizes builds around the Project Object Model (POM)

Concepts

A Maven project is built according to a standard directory layout (for example, source code in src/main/java and tests in src/test/java) and a fixed build lifecycle of phases—including validate, compile, test, package, verify, install, and deploy. Goals, provided by plug-ins, are bound to these phases. Projects are identified by coordinates (groupId, artifactId, and version), which also identify artifacts in repositories.

Dependency management

Maven automatically downloads dependencies, including transitive dependencies, from repositories such as Maven Central, caching them in a local repository. This removed the need for projects to bundle library JAR files in version control and made builds reproducible across machines. Dependency conflicts are resolved by a "nearest definition" rule, and scopes (such as compile, provided, runtime, and test) control where each dependency applies.

History

Maven began as part of the Jakarta Turbine project, created by Jason van Zyl to standardize the way Turbine was built, and was released in 2004. Maven 2 (2005) and Maven 3 (2010) substantially reworked its architecture while retaining POM compatibility. Maven's dependency-resolution model influenced later tools, and it remains one of the most widely used build tools in the Java ecosystem, alongside Gradle.
