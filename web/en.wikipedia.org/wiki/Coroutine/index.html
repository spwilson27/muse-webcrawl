Coroutine

Coroutines are computer program components that allow execution to be suspended and resumed, generalizing subroutines for non-preemptive multitasking. Unlike a subroutine, which begins at its start each time it is called and returns once, a coroutine can yield control at an arbitrary point and later resume exactly where it left off, retaining its local state between activations.

Comparison with subroutines and threads

A subroutine is a special case of a coroutine whose entry point is always the beginning and which exits only once, to its immediate caller. Coroutines, by contrast, may transfer control to any designated coroutine, not only the caller, and are typically scheduled cooperatively rather than preemptively, as with threads. Because switching is explicit, coroutines avoid much of the locking and race-condition complexity of threads, but cannot by themselves exploit multiple processor cores.

Uses

Coroutines are widely used to implement generators (iterators that produce a sequence of values on demand), asynchronous I/O and event-driven programming (the basis of async/await features in many languages), pipelines and simulations, and lightweight concurrency in game engines. The concept dates to Melvin Conway's 1958 work on compiler design and Donald Knuth's discussion of coroutines as a generalization of subroutines.

Language support

Coroutines appear natively in Lua, Kotlin, Python (via generators and asyncio), C# (yield and async methods), JavaScript (generator functions and promises), Ruby (fibers), Go (goroutines, a related but distinct construct), and since C++20 in the C++ standard library ecosystem.
