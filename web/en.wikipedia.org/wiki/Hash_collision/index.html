Hash collision

In computer science, a hash collision occurs when two distinct inputs to a hash function produce the same output (hash value). Because a hash function maps an effectively unlimited input space to a fixed number of possible outputs, collisions are mathematically inevitable by the pigeonhole principle; good hash functions make them rare, hard to find, or both, depending on the application.

Two different inputs producing the same hash value: a collision.

In hash tables

In a hash table, collisions are routine and are handled by resolution strategies such as separate chaining (each bucket holds a list of entries) or open addressing (entries are stored in alternative slots found by probing). Well-designed hash functions distribute keys uniformly so that collisions remain infrequent and operations stay close to constant time.

In cryptography

For cryptographic hash functions, collision resistance is a core security property: it should be computationally infeasible to find any two inputs with the same hash. The birthday paradox implies that an n-bit hash offers at most about 2n/2 security against collision search. Practical collision attacks have broken widely used functions — MD5 fell to collisions in 2004, and in 2017 the SHAttered attack produced two PDF files with the same SHA-1 hash — prompting migration to stronger functions such as the SHA-2 and SHA-3 families. Collision resistance matters for digital signatures, certificates, and content-addressed storage, where an attacker who can force a collision can substitute one document for another with the same fingerprint.
