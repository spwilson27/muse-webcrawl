Autosave

Autosave
"All changes saved" indicator in a cloud office suite.
TypeSoftware feature
PurposePrevent data loss from crashes or user error
TriggersTimer interval; on change; at checkpoints

Autosave is a feature of computer software that automatically saves changes to a document or progress in a game at regular intervals or in response to edits, protecting work against loss from crashes, power failure or accidental closure. It removes the need for the user to remember to invoke a manual save command, and is now a default behaviour in most productivity applications, web services and video games.

Implementation

Early implementations, such as the AutoSave add-in in Microsoft Word of the 1990s and the recovery files of text editors, periodically wrote a temporary recovery copy that could be offered after a crash. Modern cloud applications — including Google Docs (from 2006) and Microsoft 365 — save continuously as the user types, synchronising to remote storage and maintaining version histories that allow earlier states to be restored. Editors such as Vim and Emacs similarly write swap or backup files enabling crash recovery.

In video games

In games, autosave records progress automatically at checkpoints, level transitions or after significant events, complementing or replacing manual save slots and quicksave keys. Designs vary: generous autosaving reduces frustration at the cost of tension, while restrictive checkpointing — or a single autosave that overwrites itself — can lock a player into an unwinnable state, a recognised design pitfall. The rotating autosave (several slots cycled in turn) is a common compromise.

Criticism

Critics note that automatic saving can also automatically preserve mistakes: an accidental deletion or unwanted edit may be saved before the user can close without saving, making undo and version history essential companion features. In collaborative documents, continuous saving changes authorship practices, since drafts are visible to collaborators in real time.
