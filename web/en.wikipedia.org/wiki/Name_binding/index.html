Name binding

In programming languages, name binding is the association of entities (data and/or code) with identifiers. An identifier bound to an object is said to reference that object. Machine languages have no built-in notion of identifiers, but name-object bindings are implemented as a service and notation for the programmer. Binding is intimately connected with scoping, as scope determines which names bind to which objects — at which locations in the code (lexically) and in which one of the possible execution paths (temporally).

Binding time

Bindings may be created at various times: at language design time (e.g., keywords), at language implementation time (e.g., built-in types of a compiler), at compile time, at link time, at load time, or at run time. When a binding occurs determines how early errors can be detected and how much flexibility the program has.

Static and dynamic binding

Static binding (or early binding) resolves names before run time, as in statically typed languages where a variable's type is fixed at compile time. Dynamic binding (or late binding) postpones resolution until run time; it underlies dynamic dispatch in object-oriented programming, where the method invoked depends on the runtime class of the receiver object.

Rebinding and shadowing

A name may be rebound within a nested scope, shadowing the outer binding. Assignment typically rebinds a mutable variable to a new value, whereas in languages with immutable bindings (such as many functional languages) each binding is created once.
