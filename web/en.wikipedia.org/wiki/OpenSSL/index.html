OpenSSL is a software library for applications that provide secure communications over computer networks against eavesdropping, and to identify the party at the other end. It is widely used by Internet servers, including the majority of HTTPS websites. OpenSSL implements the Secure Sockets Layer (SSL) and Transport Layer Security (TLS) protocols, together with a full-strength general-purpose cryptographic library.

History

OpenSSL was forked in 1998 from SSLeay, a library developed by Eric A. Young and Tim J. Hudson. The project is managed by a worldwide community of volunteers and funded through support contracts and donations. Major versions include the 1.0 series, the long-lived 1.1.0 and 1.1.1 releases (1.1.1 was a Long Term Support release), and OpenSSL 3.0 (2021), which introduced a provider-based architecture and moved the project to the Apache License 2.0.

Features

The library provides implementations of TLS (up to TLS 1.3) and DTLS, a broad range of symmetric ciphers (AES, ChaCha20), public-key algorithms (RSA, Diffie–Hellman, elliptic-curve cryptography), cryptographic hash functions, and X.509 certificate handling. The accompanying openssl command-line tool can create and manage keys and certificates, act as a test client and server, and perform file encryption and hashing.

Heartbleed

In April 2014, a serious vulnerability in OpenSSL's implementation of the TLS heartbeat extension — dubbed Heartbleed — was publicly disclosed. The flaw allowed attackers to read arbitrary memory from affected servers, potentially exposing private keys and passwords, and affected a large fraction of the web. The incident spurred the creation of the Linux Foundation's Core Infrastructure Initiative to fund critical open-source projects, prompted fork projects such as LibreSSL (by the OpenBSD team) and BoringSSL (by Google), and led to major funding and audit improvements within OpenSSL itself.

FIPS validation

Certain OpenSSL releases and modules have been validated under the U.S. Federal Information Processing Standards (FIPS 140-2 and 140-3) programme, which is required for cryptographic software used by U.S. government agencies.
