JSON-RPC is a stateless, light-weight remote procedure call (RPC) protocol. Primarily this specification defines several data structures and the rules around their processing. It is transport agnostic in that the concepts can be used within the same process, over sockets, over HTTP, or in many various message passing environments. It uses JSON (RFC 4627) as data format.

History

JSON-RPC version 1.0 was published in 2005, inspired by earlier JSON messaging proposals. Version 2.0, published in 2010, added support for named parameters, notifications (requests without an id, to which no response is expected), and batch requests in which multiple calls are sent as a JSON array. The protocol is a close cousin of XML-RPC, differing mainly in its use of JSON rather than XML.

Conventions

A request object contains a jsonrpc field (always "2.0" in version 2.0), a method name, an optional params array or object, and an id. The response echoes the id and carries either a result or an error object with standard error codes such as -32700 (parse error) and -32601 (method not found).

{"jsonrpc": "2.0", "method": "subtract", "params": [42, 23], "id": 1}
{"jsonrpc": "2.0", "result": 19, "id": 1}

Usage

JSON-RPC is used in cryptocurrency node interfaces (Bitcoin Core and Ethereum clients expose JSON-RPC APIs), language server tooling, blockchain data services, and numerous internal microservice systems, where its simplicity is preferred to heavier protocols such as SOAP.
