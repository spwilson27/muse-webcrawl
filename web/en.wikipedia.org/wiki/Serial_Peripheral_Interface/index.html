Serial Peripheral Interface

The Serial Peripheral Interface (SPI) is a synchronous serial communication interface specification used for short-distance communication, primarily in embedded systems. The interface was developed by Motorola in the mid-1980s and has become a de facto standard.

Operation

SPI devices communicate in full duplex mode using a controller–peripheral architecture (historically termed master–slave). The controller generates the clock and selects individual peripheral devices using dedicated select lines. A typical SPI bus uses four logic signals:

SignalDescription
SCLKSerial clock, output from the controller
MOSIController out, peripheral in (data from controller)
MISOController in, peripheral out (data to controller)
CS / SSChip select, active-low signal from the controller to select a peripheral

During each clock cycle, the controller and each peripheral exchange one bit of data through shift registers. Data is usually shifted out with the most significant bit first. Because there is no formal standard, four clock polarity/phase combinations (modes 0–3, defined by CPOL and CPHA) are in common use, and devices must be configured to match.

Advantages and disadvantages

SPI offers high throughput, simple hardware interfacing and full-duplex operation, and peripherals require no unique addresses. Unlike I²C, however, it has no acknowledgment mechanism, no flow control, and requires a separate chip-select line for each peripheral, consuming more pins. It also has no error checking built into the basic protocol.

Applications

SPI is widely used to connect microcontrollers to sensors, analog-to-digital and digital-to-analog converters, flash memory (including SD cards in SPI mode), display controllers and radio transceivers.
