Model–view–controller

The MVC pattern divides an interactive application into three components

Model–view–controller (MVC) is a software architectural pattern commonly used for developing user interfaces. It divides an application into three interconnected elements: the model, which manages the data, logic and rules of the application; the view, which presents information to the user; and the controller, which accepts input and converts it into commands for the model or view.

History

MVC was formulated by Trygve Reenskaug while working on Smalltalk at Xerox PARC in the late 1970s, as part of the effort to give non-programmers control over information systems. It became a standard feature of Smalltalk-80 and influenced most later graphical user interface toolkits.

Components and interactions

The model holds the application's state and business rules, independent of the interface. Views observe the model and render its current state; a single model may have several views. The controller interprets user gestures — mouse clicks, keystrokes, HTTP requests — and updates the model or selects a view in response. Decoupling the three parts allows independent development, testing and reuse.

Use in web frameworks

MVC became the organising pattern of many web frameworks, including Ruby on Rails, Django (which uses a closely related model–template–view arrangement), Laravel, ASP.NET MVC and Spring MVC. Numerous variants — MVP, MVVM, HMVC — adapt the separation to different platforms.
