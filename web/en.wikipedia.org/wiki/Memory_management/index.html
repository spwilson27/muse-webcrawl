Memory management

Memory management is the act of managing computer memory at the system level. The essential requirement of memory management is to provide ways to dynamically allocate portions of memory to programs at their request, and free it for reuse when no longer needed. This is critical to any advanced computer system where more than a single process might be underway at any time.

Overview

Several methods have been devised that increase the effectiveness of memory management. Virtual memory systems separate the memory addresses used by a process from actual physical addresses, allowing separation of processes and increasing the effectively available amount of RAM using disk space. The quality of the virtual memory manager can have an extensive effect on overall system performance. The operating system kernel manages memory using page tables maintained with the help of the memory management unit (MMU).

Allocation strategies

  • Static allocation — memory assigned at compile time for the duration of the program.
  • Stack allocation — automatic storage for local variables, freed when a function returns.
  • Heap allocation — dynamic allocation of variable-sized blocks at run time, using allocators such as malloc in C.
  • Arena/region allocation — groups of objects freed together.

Manual vs automatic management

In manual memory management (C, C++), the programmer explicitly allocates and frees memory; errors include memory leaks, dangling pointers, and double frees. Automatic memory management, chiefly garbage collection (Java, C#, Python, Go), reclaims unreachable objects programmatically, trading some performance and predictability for safety. Intermediate approaches include reference counting (Swift, Python's primary mechanism), ownership and borrowing (Rust), and RAII-based smart pointers in C++.

Protection and fragmentation

Memory management also provides protection: each process's address space is isolated so one program cannot corrupt another's memory. Over time, allocation and deallocation can cause fragmentation — free memory split into small non-contiguous blocks — reducing the ability to satisfy large requests. Garbage collectors may compact the heap to mitigate this.
