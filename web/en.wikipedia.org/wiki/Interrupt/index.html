Interrupt


Devices signal the processor through interrupt requests.

In digital computers, an interrupt is a request for the processor to interrupt currently executing code (when permitted), so that the event can be processed in a timely manner. If the request is accepted, the processor suspends its current activities, saves its state, and executes a function called an interrupt handler (or interrupt service routine) to deal with the event.

Overview

Interrupts are commonly used by hardware devices to indicate electronic or physical state changes that require time-sensitive attention, such as a keypress, a completed disk transfer, or a timer tick. They allow the processor to avoid wasteful polling and to respond to asynchronous events with low latency. Hardware interrupts are signalled over dedicated lines, often routed through a programmable interrupt controller that prioritises and delivers them.

Types

Interrupts may be maskable, meaning they can be temporarily ignored by the software, or non-maskable, reserved for critical errors such as memory parity failures. Software interrupts, or traps, are generated by executing a special instruction and are used for system calls and exception handling. Processor exceptions such as divide-by-zero faults are a related mechanism.

Handling

When an interrupt is taken, the processor typically finishes the current instruction, pushes key registers, disables further interrupts of equal or lower priority, and vectors to the handler through an interrupt vector table. Handlers are expected to be short; longer work is often deferred to background processing.
