XML-RPC

XML-RPC is a remote procedure call (RPC) protocol which uses XML to encode its calls and HTTP as a transport mechanism. It was created in 1998 by Dave Winer of UserLand Software in collaboration with Microsoft, and is notable for its simplicity compared with later protocols such as SOAP, which evolved partly from it.

Protocol

An XML-RPC call is an HTTP POST request whose body is XML. The document names a method and lists parameters, each typed with tags such as <int>, <string>, <double>, <boolean>, <array> and <struct>. The response similarly carries a single return value, or a fault element describing an error. For example, a request might take the form:

<methodCall>
  <methodName>examples.getStateName</methodName>
  <params>
    <param><value><i4>41</i4></value></param>
  </params>
</methodCall>

History and use

Microsoft initially participated in the design but later moved toward SOAP, which added features such as extensible headers and namespaces. XML-RPC remained popular because it was easy to implement, with libraries in nearly every programming language. It powered early blogging APIs (Blogger, MetaWeblog), the pingback mechanism between weblogs, content management systems such as WordPress, and various web services. Its limitations — no standard support for 64-bit integers in the original specification, no null value, and verbose encoding — led to the development of JSON-RPC and later REST/JSON and gRPC approaches. Security concerns, particularly unauthenticated endpoints in some applications, have also curtailed its use.
