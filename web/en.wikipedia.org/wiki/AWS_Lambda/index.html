AWS Lambda

AWS Lambda is an event-driven, serverless computing platform provided by Amazon Web Services (AWS) since 2014. It runs code in response to events and automatically manages the underlying compute resources. Users upload functions and Lambda handles provisioning, scaling, patching and high availability, charging only for the compute time consumed, measured in millisecond increments.

History

Lambda was announced at AWS re:Invent in November 2014, initially supporting code written in Node.js, with Java added in 2015 and Python and C# (.NET) in 2016. Go and Ruby support followed, and in 2018 AWS announced custom runtimes and the open-source Firecracker microVM technology that underpins Lambda's isolation. In 2020, Lambda added support for container images as a packaging format and for billing granularity of one millisecond.

Features

Lambda functions are stateless and are triggered by events from AWS services such as Amazon S3, DynamoDB, API Gateway, SQS and EventBridge, or by direct invocation through the AWS API. Each function runs in an isolated execution environment based on Firecracker microVMs. Functions can be allocated between 128 MB and 10 GB of memory, with CPU scaled proportionally, and may run for up to 15 minutes per invocation.

Common use cases include web backends, data processing pipelines, stream processing, file transformation, scheduled tasks, and glue logic between managed services. The programming model encourages small, single-purpose functions composed into applications using services such as AWS Step Functions.

Limitations

Criticisms of Lambda have included cold-start latency for infrequently invoked functions, the 15-minute execution limit, debugging complexity in distributed systems, and the risk of vendor lock-in. Provisioned concurrency and SnapStart (for Java) were introduced to mitigate cold starts.
