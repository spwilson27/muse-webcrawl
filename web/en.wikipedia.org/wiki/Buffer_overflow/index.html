Buffer overflow

Data written past the end of a buffer overwrites adjacent memory

In programming and information security, a buffer overflow or buffer overrun is an anomaly whereby a program writes data to a buffer beyond the buffer's allocated memory, overwriting adjacent memory locations. Because buffers are contiguous blocks of memory, the excess data can corrupt other variables, control data such as return addresses and saved pointers, and ultimately the flow of execution of the program.

Technical description

A buffer overflow occurs when data written to a buffer exceeds its capacity because the program fails to perform adequate bounds checking. Languages such as C and C++, which give programmers direct control over memory and do not automatically check array bounds, are particularly susceptible; classic unsafe library functions such as strcpy() and gets() copy data without verifying that the destination is large enough. Overflows may occur on the stack, the heap, or in static data areas, each with different consequences and exploitation techniques.

char buffer[8];
strcpy(buffer, "this string is too long"); /* overflow */

Exploitation

Attackers exploit buffer overflows by supplying carefully crafted input that overwrites a saved return address on the stack, redirecting execution to attacker-supplied machine code ("shellcode") or to existing code fragments, as in return-oriented programming. Successful exploitation can give the attacker control of the vulnerable process, often with its full privileges. Buffer overflows have historically been one of the most common and severe classes of software vulnerability, and are catalogued as CWE-120 and related weaknesses.

Notable incidents

The 1988 Morris worm, one of the first computer worms distributed via the Internet, exploited a buffer overflow in the Unix fingerd program. The Code Red (2001) and Slammer (2003) worms exploited buffer overflows in Microsoft server software, and numerous high-profile vulnerabilities since have had the same root cause.

Countermeasures

Defences operate at several levels. Programmers can use memory-safe languages or bounds-checked library functions and validate input lengths. Compilers add stack canaries that detect overwrites of return addresses, and mark the stack non-executable. Operating systems deploy address space layout randomisation (ASLR) and data execution prevention (DEP/NX) to make exploitation unreliable. Static analysis, fuzz testing, and code review are used to find overflows before deployment, but the class of bug remains a major concern in legacy C and C++ codebases.
