Translation lookaside buffer

From Wikipedia, the free encyclopedia

A translation lookaside buffer (TLB) is a memory cache that stores the recent translations of virtual memory to physical memory. It is used to reduce the time taken to access a user memory location. The TLB stores the recent translations of virtual memory to physical memory and can be called an address-translation cache. It is a part of the chip's memory-management unit (MMU). A TLB may reside between the CPU and the CPU cache, between CPU cache and the main memory or between the different levels of the multi-level cache.

Overview

Modern processors use virtual memory: every memory access goes through address translation from a virtual address to a physical address. Without a TLB, each access would require walking the page table in memory — potentially several memory references per access. Because programs exhibit locality of reference, a small cache of recent translations serves the great majority of accesses. Typical TLBs hold from a few dozen to a few thousand entries and are implemented as content-addressable memory (CAM), allowing a virtual page number to be looked up in parallel across all entries in a single cycle.

TLB hits and misses

When the CPU generates a virtual address, the MMU checks the TLB. If a matching entry is present (a TLB hit), the physical frame number is obtained immediately. If not (a TLB miss), the hardware or operating system walks the page table to find the translation, installs it in the TLB, and retries the access. A miss where the page table entry itself is invalid — because the page is not resident — raises a page fault, handled by the operating system.

Address-space identifiers

Because each process has its own virtual address space, TLBs must handle context switches. Older designs flushed the entire TLB on every switch. Most modern processors tag entries with an address space identifier (ASID) — called a PCID (process-context identifier) on x86 — so entries from several processes can coexist and a switch need not flush the cache. Some entries may be marked global, shared by all processes, typically for kernel pages.

Multi-level TLBs

Like data caches, TLBs are often split into levels: a small, fast first-level TLB (sometimes separate instruction and data TLBs) backed by a larger, slower second-level TLB. Some architectures add page-walk caches that accelerate the page-table walk itself on a miss. TLB reach — the amount of memory mappable through cached entries — can be increased with large pages (huge pages), which map megabytes or gigabytes per entry.

Software-managed TLBs

Some architectures, notably classic MIPS and SPARC designs, leave TLB refill to software: on a miss, the CPU traps to a handler that computes the translation and writes the TLB entry. This gives the operating system freedom in page-table format at the cost of miss-handling overhead.
