Dangling pointer

A dangling pointer, in computer programming, is a pointer that does not point to a valid object of the appropriate type. Dangling pointers arise when memory is freed or goes out of scope while a pointer to it is retained; dereferencing such a pointer is undefined behaviour in languages such as C and C++ and is a classic source of crashes, data corruption and security vulnerabilities (use-after-free errors).

[Image: Diagram of a pointer still referencing memory after it has been freed]

Causes

The most common cause is freeing memory and then continuing to use the pointer:

char *p = malloc(16);
free(p);
/* p is now a dangling pointer */
*p = 'x';   /* undefined behaviour */

Other causes include returning the address of a local (stack) variable from a function, and retaining a pointer to an object that has been deleted through a different pointer (aliasing).

Prevention

Mitigations include setting pointers to NULL after freeing, using garbage-collected languages, reference counting and smart pointers (such as C++ unique_ptr and shared_ptr), borrowing/ownership systems as in Rust, and runtime tools such as AddressSanitizer and Valgrind that detect use-after-free errors.
