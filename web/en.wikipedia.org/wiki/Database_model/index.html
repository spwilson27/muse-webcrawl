Database model

Common database models and how data is structured in each

A database model is a type of data model that determines the logical structure of a database. It fundamentally determines in which manner data can be stored, organized and manipulated. The most popular example of a database model is the relational model, which uses a table-based format.

Common database models include the hierarchical model, the network model, the relational model, the entity–relationship model, the object-oriented model, the document model, and various NoSQL models. A database management system (DBMS) may support one or more models; the optimal structure depends on the natural organization of the application's data and on the application's requirements, which include transaction rate, reliability, maintainability, scalability, and cost.

Types of database models

Hierarchical model

In a hierarchical model, data is organized into a tree-like structure, implying a single parent for each record. A sort field keeps sibling records in a particular order. Hierarchical structures were widely used in early mainframe database systems, such as IBM's Information Management System (IMS). Records are connected through links and must be accessed through a single path. This model works well when the data naturally forms a hierarchy, but it handles many-to-many relationships poorly.

Network model

The network model generalizes the hierarchical model by allowing each record to have multiple parents and multiple children, forming a graph structure. It was standardized by the CODASYL Database Task Group in 1969. The network model is more flexible than the hierarchical model but is complex to design and maintain, and queries are typically navigational.

Relational model

The relational model, proposed by Edgar F. Codd in 1970, organizes data into relations (tables) composed of tuples (rows) and attributes (columns). Relationships between tables are represented by values in common columns, typically enforced through primary keys and foreign keys. Data is manipulated with relational algebra and queried most commonly with SQL. The relational model dominates general-purpose database systems because of its simplicity, mathematical foundation, and data independence.

Entity–relationship model

The entity–relationship model (ER model) describes things of interest in a domain as entities, their properties as attributes, and the associations between them as relationships. ER diagrams are widely used during conceptual database design, and an ER schema is usually mapped to a relational schema for implementation.

Object-oriented model

The object model treats data as objects, as used in object-oriented programming: objects encapsulate both data and behavior, support inheritance and polymorphism, and are identified by object identifiers rather than by value.

Document model

The document model stores data in documents, typically encoded in JSON, BSON, or XML, which can contain nested structures and varying fields. Document databases such as MongoDB and Couchbase are popular for applications with evolving schemas and hierarchical data.

NoSQL and other models

Other models include key–value stores, wide-column stores, and graph databases, each optimized for particular access patterns such as massive horizontal scaling or highly connected data. These are collectively grouped under the NoSQL movement, though many have since added SQL-like query capabilities.

Flat model

The simplest model of all is the flat model: a single table or file, such as a spreadsheet or a comma-separated values file, with all data in one place. Flat files lack any mechanism to enforce relationships or integrity constraints, but they remain useful for small, simple datasets and data exchange.
