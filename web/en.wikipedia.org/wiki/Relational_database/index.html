Relational database

From Wikipedia, the free encyclopedia
[Image: Two tables joined by a highlighted key column]

A relational database is a database based on the relational model of data, proposed by Edgar F. Codd in his 1970 paper 'A Relational Model of Data for Large Shared Data Banks' while at IBM. Data is organised into relations — tables of rows (tuples) and columns (attributes) — and relationships are expressed by matching values (keys) rather than by pointers.

Relational database management systems (RDBMS) answer queries in SQL using relational algebra and calculus under the hood, enforce integrity constraints, and (per Codd's later rules) guarantee data independence: applications are insulated from how data is physically stored.

Development

IBM's System R (1970s) proved the model implementable with a query optimiser; Oracle (1979) was the first commercial SQL product; Ingres/Postgres, DB2, Sybase/SQL Server, MySQL (1995) and PostgreSQL (1996, from POSTGRES) followed. Normalisation theory (Codd, Boyce, others) removes redundancy anomalies by decomposing tables into normal forms.

Despite periodic obituaries (object databases, then NoSQL), relational systems remain the default for transactional data, and absorbed rivals' features (objects, JSON, graphs) — 'relational' became a platform, not just a model.
