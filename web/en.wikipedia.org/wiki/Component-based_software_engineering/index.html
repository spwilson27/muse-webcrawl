Component-based software engineering

Component-based software engineering (CBSE), also called component-based development, is a branch of software engineering that emphasizes the separation of concerns with respect to the wide-ranging functionality available throughout a given software system. It is a reuse-based approach in which systems are built from loosely coupled, independently deployable components with well-defined interfaces.

Principles

Components should be composable, deployable, documented, independent, and standardized. Component models — such as COM, CORBA, JavaBeans/EJB, and later OSGi and microservice approaches — define how components are described, connected, and deployed.

History

The idea was articulated by Douglas McIlroy at the 1968 NATO Software Engineering Conference, which proposed mass-produced software components. Industrial component frameworks emerged in the 1990s.

Benefits and challenges

CBSE promises reuse, reduced development time, and easier maintenance, but faces challenges of component discovery, versioning, trust, and integration mismatch.
