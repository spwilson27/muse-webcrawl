Exokernel

Image placeholder: Exokernel structure diagram

An exokernel is a type of operating system kernel developed by the MIT Parallel and Distributed Operating Systems group, and also a class of similar operating systems. Operating systems generally present hardware resources to applications through high-level abstractions. By contrast, an exokernel removes as many of these abstractions as possible, securely exposing the hardware directly to applications so that each application can decide how best to use the resources.

Design

The exokernel philosophy is based on the end-to-end argument: operations should be implemented at the lowest level only when doing so is a performance win. The kernel's role is reduced to securely multiplexing physical resources — securely binding applications to hardware, revoking access, and protecting one application from another — while resource management policies, such as file systems, virtual memory, and network protocols, are moved into application-level library operating systems (libOSes).

Because abstractions are not fixed by the kernel, applications can choose the implementation best suited to their needs, or bypass library abstractions entirely. This can yield large performance improvements for specialised workloads but makes programming more demanding and writing secure bindings complex.

History

The exokernel concept was introduced by researchers at MIT in the mid-1990s, notably in work by Dawson Engler, M. Frans Kaashoek, and James O'Toole Jr. The prototype systems Xok and its library operating system ExOS demonstrated the approach. Related research systems include Nemesis from the University of Cambridge. Although no mainstream commercial operating system is a pure exokernel, the ideas influenced later work on library operating systems, unikernels, and virtualisation.
