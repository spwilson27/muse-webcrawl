SYN flood

A SYN flood is a form of denial-of-service attack in which an attacker rapidly initiates a large number of TCP connections to a target without completing the connection handshake. The attack exploits the state that a server allocates when it receives the initial SYN packet of the TCP three-way handshake.

Mechanism

Under normal operation, a server that receives a SYN responds with a SYN-ACK and reserves an entry in its connection backlog queue, waiting briefly for the client's final ACK. In a SYN flood, the attacker sends SYNs — often with spoofed source addresses that never reply — faster than the server can time the half-open connections out. The backlog fills, and legitimate connection requests are rejected or ignored, rendering the service unavailable. Because a single SYN packet is small, the attack can be highly asymmetric: little attacker bandwidth can deny service on a much better-provisioned target.

Countermeasures

  • SYN cookies: the server encodes connection state in the sequence number of its SYN-ACK and allocates no memory until the client returns a valid ACK, defeating spoofed floods.
  • Increasing the backlog and shortening half-open timeouts.
  • Filtering and scrubbing: firewalls, load balancers and upstream providers detect and drop anomalous SYN traffic or complete handshakes on the server's behalf (SYN proxying).
  • Micro-blocks and RST cookies, older techniques that reduce per-connection state.

SYN floods were first widely publicised in 1996, when attacks knocked the New York ISP Panix offline; they remain a common component of distributed denial-of-service campaigns.
