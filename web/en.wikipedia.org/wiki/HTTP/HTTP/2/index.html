HTTP/2

HTTP/2 (originally named HTTP/2.0) is a major revision of the HTTP network protocol used by the World Wide Web. It was published by the IETF in May 2015 as RFC 7540, with its header compression format HPACK specified in RFC 7541. HTTP/2 was derived from the SPDY protocol developed by Google and is supported by virtually all modern web browsers and servers.

Goals

HTTP/2 was designed to reduce perceived latency by enabling full request and response multiplexing over a single TCP connection, compressing request headers, and allowing servers to push resources to clients before they are requested. Unlike HTTP/1.1, which requires multiple connections or pipelining to fetch resources in parallel, HTTP/2 interleaves many streams within one connection.

Key features

  • Binary framing: messages are split into small binary frames tagged with stream identifiers.
  • Multiplexing: many requests and responses proceed concurrently on one connection without head-of-line blocking at the HTTP layer.
  • Header compression: HPACK compresses header fields using static and dynamic tables plus Huffman encoding.
  • Server push: a server may send resources it anticipates the client will need.
  • Stream prioritisation: clients can signal relative importance of streams.

Encryption

Although the specification allows HTTP/2 over cleartext (h2c), all major browsers implemented it only over TLS (h2), negotiated with the ALPN extension. A revised specification, RFC 9113, was published in June 2022, consolidating and obsoleting RFC 7540.
