HTTP/2 (originally named HTTP/2.0) is a major revision of the HTTP network protocol used by the World Wide Web. It was standardised by the Internet Engineering Task Force in 2015, derived from the experimental SPDY protocol developed by Google. HTTP/2 was designed to reduce latency and improve the perceived performance of web pages without changing the semantics of HTTP — methods, status codes, URIs and header fields remain the same.

Key features

Instead of HTTP/1.1's textual request-response format, HTTP/2 frames messages in a binary format and multiplexes many concurrent streams over a single TCP connection, removing the head-of-line blocking that forced browsers to open multiple connections. Headers are compressed using the HPACK algorithm to eliminate redundancy between requests. Servers can also "push" resources to the client in anticipation of need, though server push proved little used in practice and was later removed from some implementations.

Adoption

Although the standard does not require encryption, all major browsers support HTTP/2 only over TLS (negotiated via ALPN), so in practice web HTTP/2 is almost always encrypted. Within a few years of standardisation it carried a large share of web traffic, particularly at major platforms and content delivery networks. Its successor, HTTP/3, replaces TCP with QUIC over UDP to address remaining transport-level head-of-line blocking.
