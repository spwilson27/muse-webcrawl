HTTP/3

From Wikipedia, the free encyclopedia

HTTP/3 is the third major version of the Hypertext Transfer Protocol used to exchange information on the World Wide Web. Unlike HTTP/1.1 and HTTP/2, which run over TCP, HTTP/3 uses QUIC, a transport protocol built on top of UDP, as its transport. HTTP/3 was standardised by the Internet Engineering Task Force (IETF) in RFC 9114, published in June 2022.

Motivation

HTTP/2 introduced multiplexing, allowing many requests to share a single TCP connection, but because TCP delivers a single ordered byte stream, the loss of one packet stalls all streams on the connection — a problem known as head-of-line blocking at the transport layer. HTTP/3 addresses this by running over QUIC, in which each request stream is independent: packet loss affects only the stream whose data was lost. QUIC also integrates the TLS 1.3 handshake into the transport handshake, reducing connection setup latency, and supports connection migration across network changes, such as switching from Wi-Fi to a mobile network.

History

HTTP/3 grew out of Google's experimental QUIC protocol (originally "gQUIC"), deployed in Chrome and Google's servers from about 2013. The IETF QUIC working group reworked the protocol, separating the transport (standardised as RFC 9000 in May 2021) from the HTTP mapping. The HTTP semantics over QUIC — originally drafted under the name "HTTP over QUIC" and renamed HTTP/3 in 2018 — were finalised as RFC 9114 alongside QPACK header compression (RFC 9204).

Adoption

Major browsers — Chrome, Firefox, Safari and Edge — support HTTP/3, and large content delivery networks and web platforms enabled it through the early 2020s. Servers negotiate HTTP/3 via the Alt-Svc response header or DNS HTTPS records, since initial browser requests still begin over TCP-based HTTP/1.1 or HTTP/2.
