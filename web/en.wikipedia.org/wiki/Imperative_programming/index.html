Imperative programming

In computer science, imperative programming is a programming paradigm that uses statements that change a program's state. In much the same way that the imperative mood in natural languages expresses commands, an imperative program consists of commands for the computer to perform. Imperative programming focuses on describing how a program operates rather than describing what it should accomplish, in contrast to declarative programming.

Description

Imperative programs consist of sequences of statements executed in order. Statements typically include assignments that update the values stored in variables, conditional statements such as if/else, and loop constructs such as for and while, along with procedure calls. The state of the computation — the contents of memory at a given moment — is central to the paradigm, which closely mirrors the operation of the underlying von Neumann architecture: instructions and data stored in memory, with a processor fetching and executing instructions in sequence.

total := 0
for i := 1 to 10 do
    total := total + i
print total

History

The earliest imperative languages were the machine languages of the first computers, followed by assembly languages. High-level imperative languages became dominant from the 1950s with Fortran, COBOL and ALGOL, and continued with Pascal, C and many successors. Structured programming, promoted in the 1960s and 1970s, disciplined the paradigm by replacing unrestricted jumps (goto) with nested control structures. Procedural programming organised imperative code into procedures, and object-oriented programming extended it by bundling state with the operations that act on it.

Comparison with declarative programming

Declarative programming, which includes functional and logic programming, expresses the logic of a computation without describing its control flow. Many modern languages are multi-paradigm: languages such as Python, Java and C++ are primarily imperative but support declarative and functional features. Because imperative code mutates shared state, it can be harder to reason about and parallelise than pure declarative code, but it maps efficiently onto real hardware and remains the most widely used paradigm.
