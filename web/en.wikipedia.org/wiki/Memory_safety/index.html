Memory safety

Memory safety is the state of being protected from software bugs and security vulnerabilities that arise when a program accesses memory incorrectly — for example reading or writing outside the bounds of an allocated buffer, using memory after it has been freed, or dereferencing null or dangling pointers. It is a property of a program, and by extension of the programming language and runtime that enforce its rules.

Memory errors

In languages with manual memory management such as C and C++, common memory errors include buffer overflows, use-after-free, double-free, null-pointer dereference, uninitialised reads and data races. Such defects are a leading cause of exploitable security vulnerabilities: analyses by Microsoft and the Chromium project have each attributed roughly 70% of serious security bugs to memory-safety problems.

Approaches

Memory safety can be achieved by:

  • Garbage collection, as in Java, C#, Go and most scripting languages, which frees memory automatically when it becomes unreachable;
  • Borrow checking and ownership, as in Rust, which enforce safety statically at compile time without a garbage collector;
  • Bounds checking on array and pointer accesses;
  • Reference counting, as in Swift and Objective-C;
  • Formal verification, sanitizers and hardware features (such as ARM memory tagging) that detect or mitigate violations.

Policy interest

From the early 2020s, government agencies including the US NSA and the White House Office of the National Cyber Director publicly recommended adopting memory-safe languages for new development and progressively rewriting critical code, citing the disproportionate share of vulnerabilities caused by memory errors.
