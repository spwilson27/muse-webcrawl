Prototype-based programming

Prototype-based programming is a style of object-oriented programming in which behaviour reuse (known as inheritance) is performed via a process of reusing existing objects that serve as prototypes. This model can also be known as prototypal, prototype-oriented, classless, or instance-based programming.

Concepts

In prototype-based languages there is no explicit distinction between classes and instances. Instead, every object may have a link to a prototype object; when a property or method is not found on an object, lookup delegates to its prototype, forming a prototype chain. New objects are created by cloning prototypes or by constructing objects that delegate to them, and objects can be modified at runtime by adding or changing their own properties.

Languages

The style was pioneered by the Self language (developed at Xerox PARC and Stanford in the 1980s) and popularised enormously by JavaScript, in which every object has an internal prototype link and constructor functions set up delegation. Other examples include Lua (via metatables), Io, NewtonScript and Cecil. Some class-based languages have added prototype-like features, and modern JavaScript provides Object.create for direct prototypal creation.

Comparison with class-based programming

Advocates argue that prototypes are simpler and more flexible than classes because behaviour can be composed and changed dynamically, and because programmers work with concrete examples rather than abstract taxonomies. Critics note that heavy reliance on delegation can obscure program structure and complicate optimisation, although modern JavaScript engines largely mitigate the performance cost with hidden classes.
