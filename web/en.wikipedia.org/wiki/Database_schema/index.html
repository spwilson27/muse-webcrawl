Database schema

The database schema is the structure of a database described in a formal language supported by the database management system (DBMS). The term usually refers to the formal description of the organisation of data — tables, columns, data types, keys, constraints, views, and relationships — as opposed to the data itself.

Levels of schema

The ANSI/SPARC architecture distinguishes three levels. The external schema defines user views of the data; the conceptual schema describes the complete logical structure of the database independent of storage; and the internal (physical) schema describes how data is stored — files, indexes, and access paths. This separation provides logical and physical data independence: either the storage or the logical structure can change with limited impact on applications.

Creation and evolution

Schemas for relational databases are created and modified using the data definition language (DDL) subset of SQL, such as CREATE TABLE and ALTER TABLE statements. In production practice, schemas are versioned and evolved through migration scripts managed alongside application code. The term schema also has a second, narrower meaning in SQL: a named namespace within a database that groups tables and other objects under an owner.

Schema-less systems

Document-oriented and other NoSQL databases are often described as "schema-less" because records need not conform to a single fixed structure; in practice, an implicit schema still exists in the application code and in the expectations of readers, sometimes called "schema on read" as opposed to the relational "schema on write".
