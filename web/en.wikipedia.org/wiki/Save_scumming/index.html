Save scumming

Save scumming is a video game practice in which a player repeatedly saves and reloads a game in order to obtain a favourable outcome — for example, reloading until a random event succeeds, a rare item drops, or a mistake is undone. The term, with "scumming" implying dishonourable exploitation, originated in the roguelike community, where it originally referred to backing up save files to circumvent permanent death.

Usage and attitudes

The practice is most common in role-playing games, strategy games, and games with random number generation, such as reloading before opening a container in The Elder Scrolls, before a difficult shot in XCOM, or before a gamble in a casino minigame. Attitudes among players are divided: some regard save scumming as cheating that undermines a game's intended tension, while others view it as a legitimate way to respect one's time, learn mechanics, or enjoy a story without repetition. Because it occurs in single-player games, it is generally treated as a matter of personal preference rather than misconduct.

Design responses

Designers have responded to save scumming in various ways. Roguelikes traditionally delete the save file on death (permadeath); "ironman" modes in strategy games restrict the player to a single automatically overwritten save. Some games seed random outcomes in advance ("pre-rolled" results) so that reloading cannot change them, while others deliberately embrace the behaviour — for instance, allowing quicksave/quickload freely — or incorporate reloading into their fiction, as in games where the protagonist's ability to rewind time is part of the story. Autosaving after significant events is another common compromise.
