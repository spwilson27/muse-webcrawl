Intersection type

In type theory, an intersection type is a type that classifies terms which inhabit several given types at once. If a term M has type A ∩ B, then M can be used both where a value of type A is expected and where one of type B is expected. Intersection types are written A ∩ B, and the operation behaves like set-theoretic intersection: it is commutative, associative, and idempotent.

History

Intersection types were introduced in the late 1970s by Mario Coppo, Mariangiola Dezani-Ciancaglini, and collaborators, and independently developed by Henk Barendregt and others, as a refinement of the simply typed lambda calculus. They arose from attempts to characterise exactly the strongly normalising lambda terms: a term is strongly normalising if and only if it is typable in a certain intersection type system.

Properties

Because intersection types can express properties that simple types cannot, type checking and type inference for systems with intersections are generally undecidable, although restricted fragments are used in practice. Intersection types are closely related to the subtyping in some object-oriented languages, to gradual typing systems, and to the "and" types found in languages such as TypeScript and Flow, where a value of an intersection type must satisfy all constituent types.

Related notions

The dual notion is the union type, whose values belong to at least one of the constituent types. Together, intersection and union types give type systems a lattice structure reminiscent of set operations.
