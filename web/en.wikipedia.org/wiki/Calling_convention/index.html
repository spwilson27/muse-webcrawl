Calling convention

A typical stack frame laid out according to a calling convention.

In computer science, a calling convention is an implementation-level scheme for how subroutines or functions receive parameters from their caller and how they return a result. Calling conventions are usually part of a platform's application binary interface (ABI) and specify such details as which registers or stack locations hold arguments, which registers a callee must preserve, who is responsible for cleaning up the stack, and where return values are placed.

Elements of a calling convention

  • Argument passing: the order and location (registers, stack, or both) in which arguments are passed.
  • Return values: the register or memory location used for results.
  • Register preservation: the division of registers into caller-saved (volatile) and callee-saved (non-volatile) sets.
  • Stack maintenance: whether the caller or the callee removes arguments from the stack after the call, and how the stack is aligned.
  • Name decoration: how function names are mangled in object files to encode the convention.

Examples

x86 conventions

On 32-bit x86, several conventions coexist. In cdecl, arguments are pushed onto the stack right-to-left and the caller cleans the stack. In stdcall, used widely by the Windows API, the callee cleans the stack. fastcall passes the first arguments in registers (ECX and EDX). Microsoft's thiscall passes the this pointer in ECX for C++ member functions.

x86-64 conventions

The System V AMD64 ABI, used on Linux and most Unix-like systems, passes the first six integer or pointer arguments in RDI, RSI, RDX, RCX, R8 and R9. The Microsoft x64 convention instead uses RCX, RDX, R8 and R9, requires 32 bytes of "shadow space" on the stack, and designates different registers as non-volatile.

Other architectures

ARM's Procedure Call Standard passes the first arguments in registers R0–R3 (or X0–X7 on AArch64). RISC-V similarly uses registers a0–a7. Register-based conventions generally reduce memory traffic and improve performance compared with purely stack-based schemes.

Importance

Code compiled by different compilers, or written in different languages, can interoperate only if both sides agree on the calling convention. Mismatches cause crashes or silent stack corruption, so conventions are fixed by the platform ABI and documented for compiler writers.
