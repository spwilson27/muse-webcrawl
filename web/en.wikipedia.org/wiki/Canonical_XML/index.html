Canonical XML

Canonical XML is a W3C specification that defines a canonical form of an XML document — a normalized serialization such that any two documents with the same canonical form are logically equivalent for purposes such as digital signatures. Because superficially different XML serializations can represent the same content, canonicalization is essential to XML Signature, where a hash is computed over the document.

Normalizations applied

Canonicalization converts the document to UTF-8, normalizes line endings to the line-feed character, replaces character and parsed entity references with their referenced character data, removes the XML declaration and document type declaration, converts empty elements to start–end tag pairs, sorts attributes and namespace declarations lexicographically, and removes redundant namespace declarations. Attribute values are normalized as in a validating parser, and whitespace in the document prolog and epilog is stripped.

Variants

The specification defines inclusive canonicalization, which retains namespace declarations from ancestors, and Exclusive XML Canonicalization, which includes only the namespaces actually used in the document content — important when a signed fragment is moved into a different document context, as in SOAP messages. Version 1.1 revised the handling of the xml:id attribute and inherited attributes from the XML namespace.

Applications

Canonical XML underpins XML Signature (XMLDSig) and is used in SAML assertions, WS-Security, and other protocols where signed XML fragments are processed by intermediaries. Implementation subtleties in canonicalization have been a recurring source of signature-verification vulnerabilities, and a working group produced "Canonical XML 2.0" as a non-normative streamlining of the algorithm.
