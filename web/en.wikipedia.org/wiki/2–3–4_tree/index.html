2–3–4 tree

A 2–3–4 tree (also called a 2–4 tree) is a self-balancing data structure that is commonly used to implement dictionaries. The numbers mean that a tree node can have two, three, or four child links and one, two, or three data elements respectively. 2–3–4 trees are B-trees of order 4 — that is, every internal node can store up to three elements and point to up to four subtrees.

Properties

In a 2–3–4 tree:

  • Every node stores one, two or three keys in sorted order.
  • An internal node with k keys has k + 1 children, each covering the key range between successive stored keys.
  • All leaves are at the same depth, so the tree is perfectly balanced.
  • Nodes are classed by their occupancy: a 2-node has one key and two children, a 3-node has two keys and three children, and a 4-node has three keys and four children.

Operations

Searching a 2–3–4 tree proceeds as in any multiway search tree, comparing the target key against the keys stored in each node and descending into the appropriate child; this takes logarithmic time in the number of elements. Insertion maintains balance by splitting 4-nodes: when a full node is encountered on the way down (or on the way back up, depending on the variant), it is divided into two 2-nodes and its middle key is promoted into the parent. Splitting the root increases the height of the tree by one — the only way the tree grows — which keeps all leaves level. Deletion is more involved, using rotations and fusions of sibling nodes to guarantee that no node underflows.

Relation to red–black trees

2–3–4 trees are closely related to red–black trees: every 2–3–4 tree has an equivalent red–black representation in which 3-nodes and 4-nodes are encoded using red links. Red–black trees are often preferred in practice because they require less storage overhead and simpler splitting logic, but the 2–3–4 tree remains a standard pedagogical route into balanced search trees and into the B-trees used in databases and file systems.
