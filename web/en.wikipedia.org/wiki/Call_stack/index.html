In computer science, a call stack is a stack data structure that stores information about the active subroutines of a computer program. This type of stack is also known as an execution stack, program stack, control stack, run-time stack, or machine stack, and is often shortened to just "the stack". Although maintenance of the call stack is important for the proper functioning of most software, the details are normally hidden and automatic in high-level programming languages.

Function

When a subroutine is called, a stack frame (activation record) is pushed containing the return address, the caller's saved registers and frame pointer, the arguments and space for local variables. On return, the frame is popped and execution resumes in the caller. The call stack thereby keeps track of the point to which each active subroutine should return control when it finishes executing.

Uses and abuses

Debuggers display the call stack as a "stack trace" or backtrace to show the chain of calls leading to an error. Because the return address is stored in memory, corrupting it through a buffer overflow is a classic software vulnerability, exploited by techniques such as stack smashing and return-oriented programming. Deep recursion or unbounded call chains can exhaust the stack and cause a stack overflow crash.
