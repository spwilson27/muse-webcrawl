Apache HBase

Apache HBase is a free and open-source, distributed, scalable, non-relational (NoSQL) database modelled after Google's Bigtable and run on top of the Hadoop Distributed File System (HDFS). Developed as part of the Apache Software Foundation's Hadoop project, HBase provides random, real-time read/write access to very large datasets — billions of rows and millions of columns — on clusters of commodity hardware, with strong consistency and automatic sharding.

History

HBase began in 2006 as a contribution by the company Powerset to the Hadoop project, inspired by Google's 2006 Bigtable paper. It became a subproject of Hadoop and shipped its first usable release in 2008; in May 2010 it graduated to an Apache top-level project. Michael Stack was a long-serving project chair. Facebook famously adopted HBase in 2010 to store its Messages data, and it was widely deployed at companies including Yahoo, Adobe, and many others for large-scale storage.

Data model and architecture

HBase stores data in tables of rows identified by a row key. Columns are grouped into column families fixed at schema definition; individual cells are versioned by timestamp. Tables are automatically split into regions, each served by a RegionServer. Writes go first to a write-ahead log and an in-memory store (MemStore), which is periodically flushed to immutable files (HFiles) on HDFS; reads merge these sources, aided by Bloom filters and block caches. Coordination uses Apache ZooKeeper, while an HMaster assigns regions and handles schema changes. The design favours high write throughput and point lookups/scans by row key; it provides no built-in secondary indexes or SQL, though projects such as Apache Phoenix add a SQL layer.

Features

  • Linear, modular scalability across commodity servers
  • Strongly consistent reads and writes (unlike many eventually consistent stores)
  • Automatic failover and region splitting
  • Block cache and Bloom filters for read performance
  • Inter-cluster replication for backup and availability
  • Integration with MapReduce and other Hadoop ecosystem tools; Java API plus REST and Thrift gateways and a shell

Limitations

HBase is optimised for a particular access pattern — key-based reads and writes of sparse, wide tables. It is less suitable for complex queries, joins, or small datasets, and its dependence on HDFS and JVM tuning makes operations relatively demanding. Interest has declined somewhat as cloud-native wide-column services and other stores have matured, but HBase remains in production at very large scale.
