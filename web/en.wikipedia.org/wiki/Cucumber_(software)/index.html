Cucumber is a software tool that supports behavior-driven development (BDD). It allows the behavior of software to be specified in a plain-language, business-readable format which is then executed as automated acceptance tests, acting as both documentation and verification.

Gherkin

Specifications are written in Gherkin, a structured natural language using keywords such as Feature, Scenario, Given, When and Then:

Feature: Shopping cart
  Scenario: Adding an item
    Given I have an empty cart
    When I add a book costing $10
    Then the cart total should be $10

Each step is bound to code — a "step definition" — that performs the action or assertion. Because the text is readable by non-programmers, product owners, testers and developers can collaborate on the specifications, a practice sometimes called "the three amigos."

History and implementations

Cucumber was created by Aslak Hellesøy in 2008, growing out of the RSpec story runner in the Ruby community. Implementations now exist for Java, JavaScript, Python (via related tools), .NET (historically SpecFlow) and many other platforms, coordinated through the open-source Cucumber project and its common components.
