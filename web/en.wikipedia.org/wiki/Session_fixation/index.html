Session fixation

Session fixation is a class of web application security vulnerability in which an attacker is able to set ("fix") a user's session identifier before the user authenticates, and then use that known identifier to hijack the victim's session once the victim has logged in. It is closely related to session hijacking, but differs in that the attacker chooses the session ID in advance rather than stealing one that already exists.

How the attack works

A typical session fixation attack proceeds in three steps:

  1. The attacker obtains a valid session identifier from the target website, or causes the application to accept an attacker-chosen identifier (for example via a URL parameter, a cookie set from a vulnerable subdomain, or a hidden form field).
  2. The attacker tricks the victim into using that identifier — for instance by sending a link such as http://example.com/login?SID=attacker_chosen_id.
  3. The victim authenticates with the fixed identifier. Because many applications historically did not regenerate the session ID after login, the attacker, who already knows the ID, can now present it and be treated as the authenticated victim.

Countermeasures

The principal defence is for the application to generate a fresh, unpredictable session identifier whenever the privilege level of a session changes — most importantly at login — and to invalidate the old identifier. Other defences include:

  • Refusing session identifiers supplied by the client before authentication (e.g. in URLs or POST data).
  • Binding the session to additional attributes, while recognising this alone is not sufficient.
  • Setting cookies with the HttpOnly and Secure attributes to reduce related attacks such as cross-site scripting based theft.
  • Rejecting cookies set for a parent domain by less-trusted subdomains where possible.
