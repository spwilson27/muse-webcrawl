Deadlock

[Image: Resource allocation graph showing a circular wait between two processes]

In concurrent computing, deadlock is any situation in which no member of some group of entities can proceed because each waits for another member, including itself, to take action, such as sending a message or, more commonly, releasing a lock. The classic problem arises with processes or threads that acquire multiple resources in inconsistent order.

Conditions

The four Coffman conditions must all hold simultaneously for a deadlock to occur:

  1. Mutual exclusion: at least one resource is held in a non-shareable mode.
  2. Hold and wait: a process holds at least one resource while waiting for others.
  3. No preemption: resources can only be released voluntarily by the holder.
  4. Circular wait: a chain of processes exists, each waiting for a resource held by the next.

Handling strategies

Operating systems typically use one of three strategies. Prevention designs the system so that one of the four conditions can never hold, for example by imposing a global ordering on lock acquisition. Avoidance uses runtime information, such as the Banker's algorithm, to grant requests only if the resulting state remains safe. Detection and recovery periodically checks for cycles in the resource allocation graph and breaks deadlocks by aborting or rolling back a victim process. Many general-purpose systems take the "ostrich approach": ignore the problem and rely on rarity and reboots.

Related problems

Livelock is a situation in which processes continually change state in response to each other without making progress. Starvation occurs when a process is perpetually denied resources it needs, without necessarily being part of a cycle.
