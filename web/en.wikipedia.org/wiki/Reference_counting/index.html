Reference counting

In computer science, reference counting is a programming technique of storing the number of references, pointers, or handles to a resource, such as an object, a block of memory, disk space, or other resource. It is a form of garbage collection: when an object's reference count reaches zero, the object becomes unreachable and is destroyed, reclaiming its memory.

How it works

Each object carries a counter. Creating a new reference increments the count; when a reference is destroyed or reassigned, the count decrements. When the count falls to zero, the object is deallocated — possibly triggering decrements on objects it references, which may cascade. Implementations exist in CPython (the primary memory-management mechanism), Objective-C and Swift (Automatic Reference Counting, ARC), C++ smart pointers (std::shared_ptr), and COM.

Advantages

  • Objects are reclaimed promptly and deterministically, which also manages non-memory resources such as file handles.
  • Costs are distributed through program execution, avoiding long garbage-collection pauses.
  • It is simple to implement and needs no special compiler support in its basic form.

Disadvantages

  • Cycles: two objects referencing each other keep each other's counts above zero even when unreachable, leaking memory. Weak references or supplementary cycle detectors are used as remedies.
  • Overhead: every reference assignment costs increments/decrements, and in multithreaded programs these must be atomic, adding contention.
  • Deleting a large structure can cascade into a long, unbounded chain of frees.

Variants

Deferred and coalesced reference counting reduce update costs; weighted reference counting distributes the count among references for distributed systems. Many modern runtimes combine reference counting with a tracing collector for cycles.
