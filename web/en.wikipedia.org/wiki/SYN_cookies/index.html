SYN cookies

SYN cookies are a technique used to resist SYN flood attacks, a form of denial-of-service attack in which an attacker sends a large number of TCP SYN packets, often with forged source addresses, in order to exhaust the server's connection resources. The technique was invented by Daniel J. Bernstein in September 1996.

A server using SYN cookies encodes connection state in the SYN-ACK sequence number instead of storing it.

Background

In the normal TCP three-way handshake, a client sends a SYN packet, the server replies with SYN-ACK and allocates a data structure to remember the half-open connection, and the client completes the connection with an ACK. In a SYN flood, the attacker never sends the final ACK, so the server's backlog of half-open connections fills up and legitimate clients can no longer connect.

Operation

With SYN cookies enabled, the server does not allocate state when it receives a SYN. Instead, it computes a cookie: a carefully chosen initial sequence number for the SYN-ACK that encodes a hash of the client's IP address and port, the server's IP address and port, the timestamp, and a secret value known only to the server. If the client is legitimate, it replies with an ACK whose acknowledgement number is the cookie plus one. The server recomputes the hash and, if it matches, reconstructs the connection state from the acknowledgement number and establishes the connection at that point.

Limitations

Because the cookie has limited space, some TCP options cannot be fully negotiated under a SYN-cookie fallback; historically this meant the loss of features such as window scaling and SACK, although modern implementations encode a subset of options in the timestamp value. SYN cookies are therefore typically used only when the connection queue is under pressure, as a server-side defense of last resort rather than the normal path.

Implementations

SYN cookies are implemented in the Linux kernel (controlled by the tcp_syncookies sysctl), in FreeBSD, and in various other operating systems and network appliances. Bernstein also developed the related concept in the context of his work on high-performance network servers.
