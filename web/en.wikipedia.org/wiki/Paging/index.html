Paging

In computer operating systems, paging is a memory management scheme by which a computer stores and retrieves data from secondary storage for use in main memory. In this scheme, the operating system retrieves data from secondary storage in same-size blocks called pages. Paging is an important part of virtual memory implementations in modern operating systems, using secondary storage to let programs exceed the size of available physical memory.

For simplicity, main memory is called "RAM" and secondary storage is called "disk" in this article. The hardware implementation of this scheme is the memory management unit (MMU) between the CPU and the RAM, and the software implementation is part of the operating system.

History

In the 1960s, swapping was an early virtual memory technique. An entire program would be "swapped out" (or "rolled out") from RAM to disk, and another one would be swapped in to replace it. A swapped-out program would be current but its execution would be suspended while its RAM was in use by another program.

The Manchester Atlas, completed in 1962, is generally credited as the first system to implement paging. Its "one-level store" treated main memory and a magnetic drum as a single level of storage, dividing addresses into pages handled automatically by hardware. Other early systems implementing paging-like schemes included the Burroughs B5000 and later the IBM System/360 family with dynamic address translation.

An important aspect of early swapping is the possibility to swap one program in its entirety. This simplifies memory management somewhat, because each program uses the same amount of RAM, and the same contiguous region of it. With paging, a thrashing operating system is able to keep only the most frequently used parts of each program in RAM, swapping out the rest as needed.

Page faults

When a process tries to reference a page not currently present in RAM, the MMU interrupts the CPU and the operating system handles the resulting page fault. The operating system searches for the page in secondary storage, allocates a free page frame in RAM, loads the data, updates the page table, and resumes the interrupted instruction. If no frames are free, a page must first be evicted, and if it has been modified, its contents are written back to disk before reuse.

Page replacement algorithms

Demand paging, as opposed to anticipatory paging (also known as "prepaging"), loads pages into memory only when needed by the executing program. Page replacement algorithms decide which page to evict when a new page must be loaded. Common approaches include least recently used (LRU) approximation, the clock algorithm (a FIFO-based approximation of LRU), and various working-set strategies. Poor replacement choices can cause thrashing, where the system spends more time moving pages than executing useful instructions.

Page tables

Operating systems maintain a page table for each process, mapping virtual pages to physical page frames. To avoid walking the entire table on every memory access, processors cache recent translations in a translation lookaside buffer (TLB). Large address spaces typically require multi-level (hierarchical) page tables so that tables for unused address ranges need not be allocated.

Sharing and protection

Because page tables are maintained per process, the same physical frame can be mapped into several address spaces, enabling efficient sharing of libraries and inter-process communication through shared memory. Page table entries also carry permission bits (read, write, execute, user/supervisor), so the MMU can enforce memory protection on every access.
