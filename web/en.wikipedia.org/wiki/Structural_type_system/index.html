Structural type system

A structural type system (or property-based type system) is a major class of type system in which type compatibility and equivalence are determined by the type's actual structure or definition and not by other characteristics such as its name or place of declaration. Structural systems are used to determine if types are equivalent and whether a type is a subtype of another.

Structural type systems contrast with nominal type systems, where comparisons are based on explicit declarations or names of types. In a nominal system, two types are equivalent only if they are declared to be so (or share the same name), whereas in a structural system, two types are equivalent if they have the same structure — for example, if they expose the same set of fields or methods with compatible types.

Structural subtyping

In structural subtyping, one type is considered a subtype of another if it provides at least all of the members of the supertype. For example, a record type with fields x and y is a subtype of a record type with only field x, because any value of the wider type can be used wherever a value of the narrower type is expected. This is sometimes called width subtyping.

Languages

Languages that use structural typing, wholly or in part, include:

  • Go — interfaces are satisfied implicitly by any type implementing the required methods.
  • TypeScript — object types are compared structurally.
  • OCaml — object types and polymorphic variants are structural.
  • Haskell — type classes resemble structural interfaces, though they are resolved by instance declarations.
  • Elm and Flow also employ structural typing for records and objects.

Relation to duck typing

Structural typing is related to duck typing, in which compatibility is determined by the presence of methods and properties. The difference is that structural typing is checked statically, at compile time, while duck typing is typically a dynamic, runtime concept.
