SQL injection

SQL injection
TypeCode injection vulnerability
First discussedLate 1990s (Phrack, 1998)
AffectsWeb applications using SQL databases
Primary defenceParameterised queries / prepared statements
CWECWE-89

SQL injection is a code injection technique used to attack data-driven applications, in which malicious SQL statements are inserted into an entry field for execution. The vulnerability arises when user input is concatenated directly into SQL queries without proper validation or escaping, allowing an attacker to read, modify or delete database contents, bypass authentication, and in some configurations execute administrative commands or gain control of the underlying server.

Example

A classic vulnerable login query is built by string concatenation: SELECT * FROM users WHERE name = '" + userName + "'; If an attacker supplies the input ' OR '1'='1, the resulting condition is always true and the application may log the attacker in without a valid password. More advanced attacks use UNION-based queries to extract arbitrary tables, or blind techniques that infer data one bit at a time from application responses or timing.

History and impact

SQL injection was publicly documented in 1998 in Phrack magazine and quickly became one of the most common and damaging web vulnerabilities, figuring in many major data breaches. It has appeared near the top of the OWASP Top Ten list of web application risks for decades.

Prevention

The definitive defence is the use of parameterised queries (prepared statements), in which user input is sent to the database separately from the query structure so it can never be interpreted as SQL code. Input validation, least-privilege database accounts, escaping routines and web application firewalls can provide defence in depth but are not substitutes for parameterisation.
