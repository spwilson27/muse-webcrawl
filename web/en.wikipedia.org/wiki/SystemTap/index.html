SystemTap (stap) is a dynamic tracing and instrumentation tool for the Linux kernel and user-space applications. It lets administrators and developers observe a running system in detail — gathering performance and diagnostic data — without rebooting or recompiling, by executing probe scripts written in a simple C-like scripting language.

How it works

A SystemTap script associates handlers with probe points such as kernel function entries, timers, system calls, or user-space markers. The tool translates the script into C, compiles it into a kernel module (or uses a backend based on eBPF in newer versions), loads it, and runs the handlers when probes fire; results are printed to the console when the script exits.

Context

SystemTap was inspired by Sun's DTrace for Solaris and developed principally by Red Hat from 2005. Security restrictions (the "stapusr" and related groups) limit who may run scripts, since probe code executes with high privilege. Later Linux tracing tools such as perf, ftrace, and eBPF-based bpftrace cover overlapping ground.
