Goodput

Goodput is the application-level throughput of a communication network, i.e. the number of useful information bits delivered by the network to a certain destination per unit of time. The amount of data considered excludes protocol overhead bits as well as retransmitted data packets. This is related to the concept of throughput, but where throughput measures the gross rate of data transfer, goodput measures only the rate at which useful data reaches the application.

Definition

Goodput is distinguished from throughput in that throughput includes all data transferred across a link, including protocol headers, retransmissions, and control messages. Because overhead consumes bandwidth, the goodput of a connection is always less than or equal to its throughput. For example, a file transfer over a network with a high packet loss rate may require many retransmissions, substantially reducing goodput even if the raw link throughput remains high.

Factors affecting goodput

Goodput is affected by protocol overhead (such as TCP and IP headers), retransmissions caused by packet loss or errors, flow control behaviour, congestion control algorithms, and acknowledgment traffic. In wireless networks, contention for the shared medium and half-duplex operation can further reduce goodput.

Example

Consider a file transferred using FTP over an Ethernet link at 100 Mbit/s. After accounting for Ethernet framing, IP and TCP headers, and acknowledgments, the maximum achievable goodput is noticeably below 100 Mbit/s, typically around 94-95 Mbit/s under ideal conditions with maximum-size frames.
