Void pointer

A void pointer is a pointer that has no associated data type, written void * in the C and C++ programming languages. Because it lacks a type, a void pointer can hold the address of an object of any type, and it can be converted to and from pointers to other object types. It is known as a generic pointer, and it is the principal mechanism for generic programming in C.

Properties

A void pointer cannot be dereferenced directly, because the compiler does not know the size or type of the object it points to; it must first be cast to a typed pointer. For the same reason, pointer arithmetic on void pointers is not permitted by the ISO C standard (although some compilers, notably GCC, allow it as an extension, treating the pointed-to size as one byte). In C, conversions between void * and other object pointers are implicit; C++ requires explicit casts.

Usage

Void pointers underlie many standard library interfaces. Memory allocation functions such as malloc return void * because the block they allocate may hold any type:

int *p = malloc(10 * sizeof *p);  /* void * converted to int * */

Generic functions receive void pointers together with size information: qsort and bsearch operate on arrays of any element type by taking a void * base address, an element size and a comparison callback. Library and operating-system APIs use void pointers as opaque "handles" and to pass user data through callbacks — for example, the argument pointers of POSIX threads (pthread_create) and the data pointers of many event-driven frameworks.

Function pointers and limitations

Strictly, the C standard guarantees round-trip conversion between void * and pointers to object types only; function pointers may have a different representation, though POSIX guarantees their convertibility as well (as required by dlsym). Because void pointers discard type information, misuse can cause undefined behaviour, and in modern C++ they are largely supplanted by templates, std::any, std::variant and smart pointers, which provide type-safe genericity. They remain indispensable at C interfaces and ABI boundaries.
