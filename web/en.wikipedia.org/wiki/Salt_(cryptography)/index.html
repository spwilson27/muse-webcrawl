Salt (cryptography)

Salt
Field: Cryptography / password storage
Purpose: Defeat precomputation (rainbow table) attacks
Stored: Yes, alongside the password hash
Related: Pepper, nonce, key stretching

In cryptography, a salt is random data used as an additional input to a one-way function that hashes data, typically a password. A new salt is randomly generated for each password and stored alongside its hash, so that two users with the same password have different stored hashes.

Purpose

Salting makes precomputation attacks such as rainbow tables infeasible, because an attacker would have to recompute the table for every possible salt value, and it prevents identical passwords from being identified across accounts or systems. Salts need not be secret, but they must be unique and unpredictable; modern password-hashing schemes such as bcrypt, scrypt and Argon2 generate and embed salts automatically.

History

Salting was introduced in Unix password storage in the 1970s, where a 12-bit salt was combined with the DES-based crypt function, a design adopted after Robert Morris and Ken Thompson analysed password security for Unix.
