Memory leak

In computer science, a memory leak is a type of resource leak that occurs when a computer program incorrectly manages memory allocations in a way that memory which is no longer needed is not released. A memory leak may also happen when an object is stored in memory but cannot be accessed by the running code. Memory leaks can diminish the performance of the computer by reducing the amount of available memory, and in the worst case can cause a program or the whole system to crash or be terminated by the operating system's out-of-memory killer.

Causes

Leaks typically arise in languages with manual memory management, such as C and C++, when a programmer allocates memory with malloc or new but fails to call free or delete on every path, or when the last pointer to an allocation is overwritten. A classic example:

void f(void) {
    int *ptr = malloc(sizeof(int));
    /* do something */
    return; /* ptr is lost; the allocation can never be freed */
}

In garbage-collected languages, leaks still occur when programs unintentionally retain references to objects that are no longer needed — for example, objects accumulating in a cache or registered event listeners that are never removed — a situation sometimes called a "logical memory leak".

Consequences

A leaking program consumes ever more memory over time. In long-running processes such as servers, daemons and web browsers, even a small leak per operation eventually exhausts available RAM, forcing the system into swapping or triggering the out-of-memory (OOM) killer on Linux. A well-known example was memory leaks in early web browsers, which required periodic restarts during long sessions.

Detection and prevention

Tools for detecting leaks include Valgrind's Memcheck, AddressSanitizer and LeakSanitizer, and profiling utilities such as pmap and heap analyzers. Prevention strategies include disciplined ownership conventions, smart pointers and RAII in C++, garbage collection, reference counting, and static analysis.
