Geometric addition of points on a twisted Edwards curve

The Edwards-curve Digital Signature Algorithm (EdDSA) is a digital signature scheme using a variant of Schnorr signatures based on twisted Edwards curves. It is designed to be faster than existing digital signature schemes without sacrificing security, and includes design features — notably deterministic nonce generation — intended to make implementations robust against common failure modes. Its best-known instance is Ed25519; a larger instance, Ed448, offers a higher security level.

Algorithm

An EdDSA scheme is parameterised by a finite field, a twisted Edwards curve over that field, a base point B of prime order L, and a cryptographic hash function H with 2b-bit output. The key generation hashes a b-bit secret seed and clamps the first half to obtain the secret scalar a; the public key is the encoding of the point A = [a]B. To sign a message M, the signer deterministically derives r = H(second half of the hashed seed ‖ M), computes R = [r]B, and outputs S = (r + H(R ‖ A ‖ M)·a) mod L together with R. Verification reconstructs the equation [S]B = R + [H(R ‖ A ‖ M)]A. Because the nonce r is derived deterministically from the key and message, no random number generator is required when signing — avoiding the key-recovery disasters that afflicted ECDSA when its random nonces were biased or repeated.

Design choices

  • Twisted Edwards curves give a complete addition law (no special cases for the identity or inverses), enabling fast, constant-time arithmetic and reducing implementation errors.
  • Transparent parameters — curves are selected by a rigid "nothing up my sleeve" procedure from efficiency and security criteria.
  • Collision resistance — EdDSA retains security even if the hash function suffers collisions, a property distinguishing it from some other Schnorr variants.
  • Strong unforgeability — RFC 8032 verification uses the cofactored equation; debates over cofactorless strict verification ("ZIP-215" rules in Zcash) illustrate subtle differences among implementations.

History and standardisation

EdDSA generalises Ed25519, published in 2011 by Daniel J. Bernstein, Niels Duif, Tanja Lange, Peter Schwabe and Bo-Yin Yang. Ed448 followed in 2015, using the "Goldilocks" curve edwards448 and SHAKE256. The IETF published RFC 8032, Edwards-Curve Digital Signature Algorithm (EdDSA), in January 2017; NIST included Ed25519 and Ed448 in FIPS 186-5 in February 2023. EdDSA is used in TLS 1.3, SSH, DNSSEC experiments, cryptocurrencies, and messaging protocols.

Variants

Each instance has three modes: the "pure" mode signing the whole message, a pre-hashed mode (Ed25519ph, Ed448ph) for streaming data, and a context mode (Ed25519ctx) providing domain separation. Related derivatives include XEdDSA (used by the Signal protocol) and the Schnorrkel/Ristretto ecosystem in some blockchain systems.
