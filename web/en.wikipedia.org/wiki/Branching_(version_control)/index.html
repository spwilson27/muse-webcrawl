Branching (version control)

Branching
Field: Software configuration management
Related operation: Merging
A branch diverging from, and later merging into, the main line

In software engineering, branching is the duplication of an object under version control (such as a source file or directory tree) so that modifications can occur in parallel along multiple lines of development. The original line is often called the trunk, mainline or main branch, and each copy is a branch.

Purposes

Branches allow developers to work on new features, bug fixes or experiments in isolation without destabilising the main code base. A release branch may be created to stabilise a version for release while development continues on the trunk, and long-lived branches can support old versions with backported fixes. When work on a branch is complete, it is combined back into its parent through merging, which may require resolving conflicts where the same lines were changed in both.

Strategies

Teams adopt branching strategies ranging from trunk-based development — very short-lived branches merged frequently — to models such as Gitflow, with long-lived development and release branches. Distributed version control systems such as Git made branching cheap, because a branch is essentially a movable pointer to a commit, whereas in older centralised systems branching involved copying whole trees.
