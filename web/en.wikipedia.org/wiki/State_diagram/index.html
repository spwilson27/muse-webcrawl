State diagram

A state diagram is a type of diagram used in computer science and related fields to describe the behaviour of systems. State diagrams require that the system described is finite — composed of a finite number of states — and are sometimes used to model systems that can be thought of this way. In the Unified Modeling Language (UML), the notation is called a state machine diagram or statechart, a term originating with David Harel's statecharts of 1987, which extended traditional finite-state diagrams with hierarchy, concurrency and broadcast communication.

Elements

A classical finite-state diagram consists of states (drawn as circles or rounded rectangles), transitions (directed arrows), and labels giving the event or condition that triggers each transition and, in Mealy-style notation, the output produced. A special initial state (filled black circle), one or more final states (bullseye), and in UML also entry and exit points, pseudo-states such as choice and junction, and composite states containing nested sub-diagrams complete the notation.

Statecharts

David Harel introduced statecharts in 1987 to tame the "state explosion" of flat diagrams for complex reactive systems. Their key additions are hierarchy (a state may contain a whole sub-machine), orthogonal regions (concurrent sub-machines separated by dashed lines, together in an AND-state), and broadcast communication between regions. Statecharts underpin the UML state machine and tools such as IBM Rhapsody and the SCXML state-machine language used in some voice and embedded systems.

Semantics and uses

State diagrams model objects, protocols and devices whose behaviour depends on history: user-interface widgets, communication protocols, vending machines, embedded controllers and protocol stacks. Formal semantics matter — UML state machines differ in detail from Harel's originals and from Mealy/Moore machines — because diagrams are increasingly used not only for documentation but for code generation and model checking.
