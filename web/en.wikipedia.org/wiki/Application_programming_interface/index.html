Application programming interface

An application programming interface (API) is a way for two or more computer programs to communicate with each other. It is a type of software interface, offering a service to other pieces of software. A document or standard that describes how to build or use such a connection or interface is called an API specification. A computer system that meets this standard is said to implement or expose an API. The term API may refer either to the specification or to the implementation. Whereas a system's user interface dictates how its end-users interact with the system in question, an API dictates how to write code that interacts with the system in terms of functions, data structures and object classes, among other things.

Purpose

In building applications, an API simplifies programming by abstracting the underlying implementation and only exposing objects or actions the developer needs. While a graphical interface for an email client might provide a user with a button that performs all the steps for fetching and highlighting new emails, an API for file input/output might give the developer a function that copies a file from one location to another without requiring that the developer understand the file system operations occurring behind the scenes.

History

1940s and 1950s

The term "application program interface" (without an -ing) was first recorded in a paper by Maurice Wilkes and David Wheeler in 1951, The Preparation of Programs for an Electronic Digital Computer, which described a library of subroutines for the EDSAC computer. Joshua Bloch claims that Wilkes and Wheeler "latently invented" the API, because it is more of a concept that is discovered than invented.

1960s and 1970s

The term was introduced to the field of databases by C. J. Date in a 1974 paper. APIs became a part of the ANSI/SPARC framework for database management systems. This framework treated programming interfaces as separate from other interfaces, such as queries.

1990s

With the rise of the World Wide Web and distributed computing, APIs for remote procedure calls and web services became widespread. Remote APIs allow developers to manipulate remote resources through protocols; web APIs are the defined interfaces through which interactions happen between an enterprise and applications that use its assets.

Design

Modern APIs are designed to be consumed programmatically. Common design styles include representational state transfer (REST), GraphQL, gRPC, and SOAP. An API specification typically documents endpoints, request and response formats, authentication requirements, and error behaviour. API keys and OAuth tokens are commonly used to control access.

Release policies and versioning

APIs may be released as private (for internal use only), partner (shared with specific business partners), or public (available to any developer). Providers often version their APIs so that changes do not break existing client software, and they publish deprecation policies when older versions are retired.

Documentation

API documentation describes what services an API offers and how to use those services, aiming to cover everything a client would need to know for practical purposes. Reference documentation is conventionally generated from source code annotations, while tutorials and examples help new users get started.
