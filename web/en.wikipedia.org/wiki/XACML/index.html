XACML

XACML (eXtensible Access Control Markup Language) is a standard that defines a declarative fine-grained access control policy language implemented in XML, and a processing model describing how to evaluate access requests according to the rules defined in policies. It is an OASIS standard, first ratified in February 2003.

Architecture

XACML follows the classic policy-based access control reference architecture with four main components:

  • Policy Enforcement Point (PEP) — intercepts access requests and enforces decisions.
  • Policy Decision Point (PDP) — evaluates requests against policies and returns a decision.
  • Policy Administration Point (PAP) — where policies are written and stored.
  • Policy Information Point (PIP) — supplies attribute values about subjects, resources and the environment.

Policies

A policy is built from rules, each of which has a target (the subjects, resources and actions it applies to), a condition, and an effect of either Permit or Deny. Policies are combined into policy sets using combining algorithms such as deny-overrides and permit-overrides. Decisions returned by a PDP are Permit, Deny, Not Applicable or Indeterminate. XACML supports attribute-based access control (ABAC), in which decisions depend on attributes of the requester, the resource, the action and the context.

Versions

Version 2.0 was ratified in 2005, and version 3.0 in January 2013, adding features such as multiple decision requests, obligations and advice expressions, and improved support for delegation. Profiles have been published for use cases including SAML integration, multiple decision requests, and a JSON representation of the request format.

Use

XACML was widely adopted in enterprise and government systems in the 2000s, and several open-source and commercial implementations exist. Interest later shifted toward simpler policy engines and languages, though XACML remains in use in regulated industries requiring fine-grained, auditable authorisation.
