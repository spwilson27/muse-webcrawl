The MESI protocol is an invalidate-based cache coherence protocol used in multiprocessor computer systems to keep the data stored in separate processor caches consistent. It is one of the most common protocols supporting write-back caches, and it is sometimes known as the Illinois protocol, after its development at the University of Illinois.

States

Every cache line is in one of four states:

  • Modified (M) — the line is present only in this cache and has been changed; it differs from main memory and must be written back before another processor may use it.
  • Exclusive (E) — the line is present only in this cache but is unmodified, matching memory; it may transition to Modified on a write without bus traffic.
  • Shared (S) — the line may be present in several caches and is clean.
  • Invalid (I) — the line is not valid and must be fetched on access.

Operation

Caches snoop (monitor) transactions on the shared bus or interconnect. When a processor writes to a line, other copies are invalidated; when it reads a line held Modified by another cache, that cache supplies the data and both copies typically become Shared, or the line is written back to memory. The Exclusive state is the key optimisation over the simpler MSI protocol: a read miss that finds no other copy grants Exclusive status, so a subsequent write needs no invalidation broadcast.

Extensions

MESI has been extended by adding states, giving MOESI (used by AMD) and MESIF (used by Intel), which reduce traffic in large shared-memory and multi-socket systems.
