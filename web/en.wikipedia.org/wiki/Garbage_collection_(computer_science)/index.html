Garbage collection (GC) is a form of automatic memory management in which the runtime system reclaims memory occupied by objects that are no longer reachable — "garbage" — freeing the programmer from explicitly deallocating memory. It was invented around 1959 by John McCarthy for the Lisp programming language.

Strategies

Tracing garbage collectors periodically determine which objects are reachable from a set of roots (global variables, local variables, CPU registers) and free everything else. Variants include mark-and-sweep, copying (semi-space) collectors, and mark-compact collectors that also defragment the heap. Reference counting tracks the number of references to each object and frees it when the count reaches zero, but cannot by itself collect cyclic structures. Many modern systems use generational collection, exploiting the observation that most objects die young by collecting a small "nursery" heap frequently.

Advantages and disadvantages

Garbage collection prevents whole classes of bugs — use-after-free, double-free, and many memory leaks — and simplifies program design. Its costs include runtime overhead, unpredictable pauses ("stop-the-world" collection), and increased memory footprint. Modern collectors in the JVM, .NET, and Go runtimes use concurrent and incremental techniques to keep pauses very short.

Languages

Most high-level languages — Java, C#, Python, Ruby, JavaScript, Go, and functional languages such as Haskell — rely on garbage collection, while systems languages such as C and C++ traditionally use manual management, with Rust instead enforcing ownership at compile time.
