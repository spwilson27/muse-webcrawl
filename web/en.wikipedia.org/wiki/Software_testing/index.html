Software testing

Software testing is the act of checking whether software satisfies expectations and of detecting defects, carried out by executing the software, inspecting its artefacts, or both. It is a core part of software quality assurance and of the software development life cycle. Testing cannot prove the absence of defects; as Edsger Dijkstra famously observed, it can only show the presence of them. Testing consumes a substantial share of development effort, and its techniques range from informal manual exploration to fully automated verification pipelines.

History

Testing emerged as a distinct discipline in the 1950s, when "debugging" and testing were initially treated as the same activity. Glenford Myers's 1979 book The Art of Software Testing established the influential definition of testing as executing a program with the intent of finding errors. The 1980s brought standardised processes and professional organisations, and the 1990s and 2000s saw automated test tools, agile methods such as test-driven development (introduced with Extreme Programming), and continuous integration practices that run tests on every change.

Test levels

  • Unit testing verifies individual units of code, such as functions or classes, in isolation.
  • Integration testing checks that combined components interact correctly.
  • System testing evaluates the complete integrated system against its requirements.
  • Acceptance testing determines whether the system satisfies the customer or user, often including user acceptance testing (UAT).

Techniques and types

Black-box testing derives tests from specifications without knowledge of internal structure, using techniques such as equivalence partitioning and boundary-value analysis. White-box testing uses knowledge of the code to achieve structural coverage (statement, branch, path). Grey-box testing combines the two. Functional testing addresses what the system does; non-functional testing addresses qualities such as performance, security, usability, compatibility and reliability. Regression testing re-runs earlier tests to confirm that changes have not broken existing behaviour. Static testing, such as reviews and static analysis, examines artefacts without executing code.

Automation and process

Test automation executes tests via scripts and frameworks, enabling frequent regression runs in continuous integration and continuous delivery pipelines. Common models include the V-model, in which each development phase is paired with a test phase, and agile approaches in which testing is continuous. Notable approaches include test-driven development (write the test first), behaviour-driven development, exploratory testing, model-based testing, and mutation testing, which measures test quality by seeding faults. Metrics such as code coverage and defect density help gauge testing effectiveness, though coverage alone does not guarantee quality.
