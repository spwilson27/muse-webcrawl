Authenticated encryption


Image placeholder: AEAD operation diagram

Authenticated encryption (AE) is a form of encryption that simultaneously provides confidentiality, integrity and authenticity of data. An AE scheme combines an encryption algorithm with a message authentication code (MAC) so that a receiver can verify that the ciphertext has not been altered and was produced by a holder of the key.

AEAD

Authenticated encryption with associated data (AEAD) extends AE by allowing part of the message — such as a protocol header — to be authenticated but not encrypted. AEAD schemes are the standard building block of secure channel protocols. Widely used AEAD algorithms include AES-GCM (Galois/Counter Mode), ChaCha20-Poly1305, and AES-CCM. TLS 1.3 permits only AEAD cipher suites.

Composition approaches

Historically, AE was achieved by composing a cipher and a MAC in three generic ways: encrypt-then-MAC (the safest generic composition), MAC-then-encrypt (used by earlier TLS versions and vulnerable to padding oracle attacks when implemented carelessly), and encrypt-and-MAC (used by SSH). Dedicated AEAD modes avoid these pitfalls by design.

Security notions

Bellare and Namprempre (2000) formalised the security of generic compositions, and Rogaway introduced the AEAD notion. Modern schemes are expected to resist misuse — for example nonce reuse in AES-GCM catastrophically leaks authentication keys, motivating nonce-misuse-resistant designs such as AES-GCM-SIV and the CAESAR competition, which selected Ascon as a lightweight standard (standardised by NIST in 2023).
