Future (programming)

In computer science, future, promise, delay, and deferred refer to constructs used for synchronizing program execution in some concurrent programming languages. They describe an object that acts as a proxy for a result that is initially unknown, usually because the computation of its value is not yet complete.

Future
Type: Concurrency construct
First described: 1977 (Baker & Hewitt)
Related: Promise, async/await

History

The future concept was proposed in 1977 in a paper by Henry Baker and Carl Hewitt, and in the work of Daniel Friedman and David Wise on lazy evaluation. Languages such as MultiLisp and Alice ML implemented futures early.

Description

A future is a placeholder object for a value to be computed asynchronously. Reading the value blocks (or suspends) until the computation completes. The write-once nature of futures allows safe dataflow-style synchronization between concurrent tasks.

Examples

Java provides java.util.concurrent.Future; C++11 added std::future and std::promise; JavaScript Promises and async/await are widely used futures. Rust, Python (concurrent.futures, asyncio), and Scala also offer futures.
