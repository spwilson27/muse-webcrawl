Inter-process communication

In computer science, inter-process communication (IPC), also spelled interprocess communication, refers to the mechanisms an operating system provides to allow processes to exchange data and synchronize their actions. IPC is fundamental to building applications from cooperating processes, from simple pipelines to large distributed systems.

Approaches

The two broad models are shared memory, in which processes read and write a common region of memory (fast, but requiring semaphores or other synchronization to avoid race conditions), and message passing, in which data moves through explicit send and receive operations. Common mechanisms include:

  • Pipes and FIFOs — unidirectional byte streams, the basis of shell pipelines.
  • Sockets — endpoints that work between processes on the same machine or across a network.
  • Message queues — kernel-managed queues of discrete messages (POSIX and System V variants).
  • Signals — asynchronous notifications, limited to small amounts of information.
  • Memory-mapped files and shared memory segments.
  • Remote procedure call (RPC) and higher-level frameworks such as D-Bus, COM and gRPC, which give message passing the appearance of ordinary function calls.

Why it matters

IPC allows modular, isolated components to cooperate while retaining the fault isolation and security boundaries of separate processes — the design pattern behind web servers, database systems, microservice architectures and the client–server model generally. Its cost is overhead: context switches, copying and serialization, which is why high-performance systems often combine shared memory with message passing for control.
