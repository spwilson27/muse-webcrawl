Database index

Diagram of a B-tree, the most common index structure in relational databases

A database index is a data structure that improves the speed of data retrieval operations on a database table at the cost of additional writes and storage space to maintain the index data structure. Indexes are used to quickly locate data without having to search every row in a database table every time a database table is accessed. Indexes can be created using one or more columns of a database table, providing the basis for both rapid random lookups and efficient access of ordered records.

An index is a copy of selected columns of data, from a table, that is designed to enable very efficient search. An index normally includes a "key" or direct link to the original row of data from which it was copied, to allow the complete row to be retrieved efficiently. Some databases extend the power of indexing by letting developers create indexes on column values that have been transformed by functions or expressions. For example, an index could be created on upper(last_name), which would only store the upper-case versions of the last_name field in the index. Another option sometimes supported is the use of partial indexes, where index entries are created only for those records that satisfy some conditional expression. A further aspect of flexibility is to permit indexing on user-defined functions, as well as expressions formed from an assortment of built-in functions.

Index architecture and methods

Clustered and non-clustered indexes

A clustered index determines the physical order of data in a table. Because of this, a table can have only one clustered index. The leaf nodes of a clustered index contain the actual data pages. A non-clustered index, by contrast, is stored separately from the data rows; its leaf nodes contain pointers (row locators) to the data rows rather than the data itself. A table may have many non-clustered indexes.

B-tree indexes

The relational model implementations most commonly use the B-tree (and its variant, the B+ tree) as the underlying index structure. A B-tree is a balanced tree that keeps data sorted and allows searches, sequential access, insertions, and deletions in logarithmic time. The branching factor of a B-tree can be large, so the depth of the tree stays small even for very large tables.

Hash indexes

A hash index uses a hash function to map keys to locations. Hash indexes are efficient for equality comparisons but cannot be used for range queries or ordering, because the hash values do not preserve the sort order of the keys.

Bitmap indexes

A bitmap index uses bitmaps (bit arrays) to represent the rows in which a particular key value occurs. Bitmap indexes are especially efficient on columns with a low number of distinct values (low cardinality), such as gender or status flags, and are commonly used in data warehousing environments.

Spatial indexes

Spatial indexes, often based on R-trees, are used to index multidimensional information such as geographical coordinates, rectangles, and polygons.

Index types by column composition

A unique index guarantees that the index key contains no duplicate values and therefore that every row in the table is in some way unique. A composite index (also called a concatenated or multi-column index) is an index on more than one column; the order of the columns in the index definition matters for which queries can use it. A covering index contains all the columns needed to answer a query, so the database engine can satisfy the query entirely from the index without reading the table rows.

Advantages and disadvantages

Indexes speed up SELECT queries and WHERE clauses, but they slow down data input operations such as INSERT, UPDATE, and DELETE, because the index must be updated whenever the data changes. Indexes also consume additional storage space. Creating an index is therefore a trade-off that the database administrator or designer must weigh: indexes on columns frequently used in search conditions and joins usually pay for themselves, while indexes on rarely queried columns are a net cost.
