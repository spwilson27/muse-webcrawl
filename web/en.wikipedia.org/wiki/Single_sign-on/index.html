Single sign-on

Single sign-on (SSO) is an authentication scheme that allows a user to log in with a single ID to any of several related, yet independent, software systems. True single sign-on allows the user to log in once and access services without re-entering authentication factors. The reverse arrangement, in which signing out of one system signs the user out of all, is called single sign-off.

SSO is commonly enabled by a central identity provider (IdP) that applications trust. When a user requests a service, the service redirects them to the IdP; after authentication, the IdP issues a signed assertion or token that the service accepts in place of its own login.

Benefits and risks

Benefits include a better user experience, fewer passwords to remember and reset, centralised enforcement of security policy (including multi-factor authentication), and easier deprovisioning when an employee leaves. The principal risk is concentration: compromise of the single credential or of the IdP can grant access to every connected service, and an IdP outage can lock users out of everything at once.

Common protocols

  • SAML 2.0 — an XML-based standard widely used for enterprise federation.
  • OpenID Connect — an identity layer built on the OAuth 2.0 framework, dominant in modern web and mobile applications.
  • Kerberos — a ticket-based protocol underpinning single sign-on in Windows Active Directory domains.
  • LDAP and proprietary schemes used in legacy environments.

Consumer "social login" buttons — "Sign in with Google", "Continue with Apple" — are a form of SSO in which a large platform acts as the identity provider for third-party sites.
