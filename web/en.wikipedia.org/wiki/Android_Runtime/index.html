Android Runtime

Android Runtime (ART) is the managed runtime used by the Android operating system for executing applications. It replaced the earlier Dalvik virtual machine as Android's default runtime with the release of Android 5.0 "Lollipop" in 2014. ART compiles application bytecode into native machine code, originally using ahead-of-time (AOT) compilation at install time, and in later versions using a hybrid of interpretation, just-in-time (JIT) compilation and profile-guided AOT.

Background

Android applications are typically written in Java or Kotlin and compiled to DEX (Dalvik Executable) bytecode contained in APK files. Under Dalvik, bytecode was interpreted and compiled just-in-time by a virtual machine process per application. ART was introduced as an experimental option in Android 4.4 "KitKat" in 2013 and became the sole runtime in Android 5.0.

Compilation model

Originally, ART used the dex2oat tool to compile the entire application to a native ELF executable at installation time. This improved execution speed and battery life but increased install times and storage use. In Android 7.0 "Nougat", Google reintroduced a JIT compiler working alongside AOT: code is interpreted at first, frequently executed ("hot") methods are JIT-compiled, and during device idle and charging periods the collected profiles guide AOT compilation of hot code into a base profile compiled image. Android 9 added cloud-sourced profiles for faster first-run performance of popular apps.

Features

ART includes an improved garbage collector with fewer and shorter pauses, better allocation performance, enhanced debugging and profiling support (including a dedicated profiler), and support for 64-bit architectures. Since Android 12, ART is delivered as a Mainline module (APEX) that can be updated through the Google Play system updates independently of the device manufacturer.
