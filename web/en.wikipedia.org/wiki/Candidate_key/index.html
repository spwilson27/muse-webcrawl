Candidate key

In the relational model of databases, a candidate key of a relation is a minimal superkey — a set of attributes that uniquely identifies each tuple (row) in the relation and contains no redundant attribute that could be removed without losing uniqueness.

Definition

A set of attributes K is a candidate key if it satisfies two properties: uniqueness, meaning no two distinct tuples can have identical values for K; and irreducibility (or minimality), meaning no proper subset of K also has the uniqueness property. A relation always has at least one candidate key, because the set of all its attributes is a superkey and can be reduced to a minimal one.

Relation to other keys

One candidate key is chosen by the database designer as the primary key; the remaining candidate keys are called alternate keys. Candidate keys are distinct from foreign keys, which reference keys in other relations. When a candidate key consists of more than one attribute it is called a composite key. Natural keys drawn from the data, such as a national identification number, and artificial surrogate keys can both serve as candidate keys if they meet the criteria.

Example

In an employee table, an employee identification number and the combination of (name, date of birth, department) might both uniquely identify rows; if both are minimal, both are candidate keys, and the designer might select the employee number as the primary key for simplicity.
