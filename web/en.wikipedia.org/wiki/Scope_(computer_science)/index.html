Scope (computer science)

In computer programming, the scope of a name binding — an association of a name to an entity, such as a variable — is the part of a program where the name binding is valid; that is, where the name can be used to refer to the entity. In other parts of the program, the name may refer to a different entity (it may have a different binding), or to nothing at all (it may be unbound).

Lexical and dynamic scope

In lexical scope (or static scope), a name always refers to the binding in the most closely nested textual block of code. Lexical scoping was introduced in ALGOL and is used by most modern languages, including C, Java, Python and the Scheme and ML families. It allows the binding for any name to be determined by reading the program text.

In dynamic scope, a name refers to the binding most recently established at run time — the nearest binding in the chain of calling functions. Dynamic scoping appeared in early Lisp dialects and survives in a few languages and in shell scripting; it is generally considered harder to reason about because a function's free variables depend on how it was called.

Levels of scope

  • Global scope — names visible throughout a program or file, such as global variables and top-level functions.
  • Local scope — names visible only within a function or block; local variables are typically created on entry and discarded on exit.
  • Module or file scope — names visible within a single module or source file.
  • Class scope — names bound within a class in object-oriented languages.

Shadowing and lifetime

An inner declaration can shadow an outer one of the same name, so that within the inner scope the name refers to the inner entity. Scope (where a name is visible) should not be confused with lifetime (how long an entity exists): a variable can outlive the scope in which its name was declared, for example when captured by a closure or returned via a pointer.
