Representational state transfer

From Wikipedia, the free encyclopedia

Representational state transfer (REST) is a software architectural style for networked applications, defined by Roy Fielding in his 2000 doctoral dissertation. A system conforming to REST's constraints is described as RESTful. REST is the dominant design style for web APIs: clients interact with resources identified by URLs by exchanging representations of their state, typically JSON documents transferred over HTTP.

Defined byRoy Fielding (2000)
ArchitectureClient–server, stateless
Key constraintsUniform interface, statelessness, cacheability, layered system
Common formatsJSON, XML over HTTP

Architectural constraints

Fielding specified six constraints. The system is divided into client and server; communication is stateless, each request containing all information needed to process it; responses must declare themselves cacheable or not; there is a uniform interface between components, centred on resource identification and manipulation through representations; the system is layered, so intermediaries such as proxies and load balancers can be inserted transparently; and, optionally, servers may extend client functionality by transferring code on demand.

RESTful web APIs

In practice, RESTful APIs map HTTP methods to operations on resources: GET retrieves a representation, POST creates, PUT or PATCH updates, and DELETE removes. Fielding has emphasised that true REST also requires hypermedia controls (HATEOAS) — links within representations guiding the client — a constraint many production APIs omit. REST displaced SOAP-based services in the 2000s for its simplicity and remains the baseline against which alternatives such as GraphQL and gRPC are compared.
