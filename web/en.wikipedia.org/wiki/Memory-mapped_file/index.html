Memory-mapped file

A memory-mapped file links file contents to virtual memory pages

A memory-mapped file is a segment of virtual memory that has been assigned a direct byte-for-byte correlation with some portion of a file or file-like resource. This resource is typically a file that is physically present on disk, but can also be a device, shared memory object, or other resource that the operating system can reference through a file descriptor. Once present, this correlation between the file and the memory space permits applications to treat the mapped portion as if it were primary memory.

Benefits

The primary benefit of memory mapping a file is increasing I/O performance, especially when used on large files. Accessing memory mapped files is faster than using direct read and write operations for two reasons: a system call such as read or write is not needed to access data, and the file data need not be copied into a user-space buffer, because the operating system's page cache serves both purposes. Memory-mapped files also enable lazy loading — pages are read from disk only when accessed — and efficient inter-process communication when processes map the same file.

Implementation

On Unix-like systems, the mmap system call maps a file into a process's address space; on Windows, the equivalent is provided by CreateFileMapping and MapViewOfFile. When a program accesses a mapped page that is not yet in memory, a page fault occurs and the operating system loads the page from the file. Changes to mapped pages are written back to the file by the operating system, either on request (via msync) or when the pages are evicted.

Drawbacks

Memory mapping can be slower than conventional I/O for small files or purely sequential access because of page fault overhead, and errors such as disk-full conditions may be reported as signals rather than return codes. Files larger than the available address space cannot be mapped whole on 32-bit systems.
