Reflection (computer programming)

In computer science, reflection is the ability of a process to examine, introspect, and modify its own structure and behaviour. Programs in languages such as Java, C#, Python, Ruby and JavaScript can, at runtime, inspect the types, methods, fields and annotations of objects, construct instances of classes named in strings, and invoke methods whose names are only known dynamically.

Introspection and intercession

Introspection (observing structure) is more widely supported than intercession (modifying structure or behaviour, e.g. adding methods at runtime, found in prototype-based and Lisp-like systems). Reflective access typically works through metadata that the runtime maintains about compiled code.

Uses

  • Serialization and object–relational mapping frameworks that map objects to JSON, XML or database rows generically.
  • Dependency injection containers and unit-testing/mocking libraries.
  • Plug-in architectures, scripting interfaces, debuggers, and object browsers.
  • Calling methods by name in RPC and message-passing systems.

Costs and criticisms

Reflection is generally slower than direct code, defeats some compile-time type checking and refactoring tools, and can bypass access controls (e.g. reading private fields), raising security concerns. Many frameworks therefore generate code at build time instead (annotation processing, source generators) to obtain similar flexibility without runtime costs.

History

The concept grew out of work on metaobject protocols in Lisp systems such as 3-Lisp and CLOS in the 1980s, and entered mainstream practice with Java's java.lang.reflect package (1997).
