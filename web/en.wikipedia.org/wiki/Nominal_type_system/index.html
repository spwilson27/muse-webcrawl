Nominal type system

In computer science, a nominal or nominative type system (or name-based type system) is a type system in which compatibility and equivalence of data types are determined by explicit declarations and/or by the names of the types. Nominal systems are used to determine whether types are equivalent, and whether a type is a subtype of another.

Nominal typing stands in contrast to structural type systems, in which compatibility is based solely on the structure (the members and layout) of the types involved.

Nominal typing

Under nominal typing, two types are the same only if they are declared to be so, or if one is declared as an alias of the other. For example, in C, two struct types with identical members but different names are different, incompatible types. Likewise, in languages such as Java and C#, a class is a subtype of an interface only if it explicitly declares that it implements it; a class that merely happens to define the same methods is not a subtype.

Nominal subtyping

Nominal subtyping means that one type is a subtype of another only if it is explicitly declared to be. This is the dominant approach in mainstream object-oriented languages: Java, C++, C#, Scala, and Rust (for trait implementations) all use declared inheritance or implementation relationships to establish subtyping.

Comparison with structural typing

Nominal typing makes type relationships explicit and self-documenting, and prevents accidental compatibility between types that look alike but mean different things (for example, a Temperature and a Pressure class both wrapping a floating-point number). Structural typing, used in languages such as Go (for interfaces), OCaml, and TypeScript, is more flexible: a value automatically satisfies an interface if it has the required members, which can ease interoperability but risks unintentional conformance. TypeScript's system is largely structural, though it uses nominal behaviour in a few places (such as with private members).
