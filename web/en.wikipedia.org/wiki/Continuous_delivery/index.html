Continuous delivery

Continuous delivery (CD) is a software engineering approach in which teams produce software in short cycles, ensuring that the software can be reliably released to production at any time. Every change passes through an automated deployment pipeline of builds and tests, so that a deployable version is always available; the final release step may be triggered manually by a business decision. Continuous delivery extends continuous integration and is closely related to DevOps practices. When the release step is also automated, the practice is called continuous deployment.

FieldSoftware engineering, DevOps
Key textContinuous Delivery (Humble & Farley, 2010)
PracticesDeployment pipeline, infrastructure as code, feature toggles, trunk-based development

Principles

The approach, popularised by Jez Humble and David Farley's 2010 book, rests on making releases a low-risk, routine event: build quality in with automated testing, keep everything in version control, automate deployment, and have everyone share responsibility for the release process. Small, frequent releases reduce the risk of each change and shorten feedback loops from users.

Pipeline

A deployment pipeline typically includes a commit stage (compilation and unit tests), automated acceptance testing, user acceptance or staging environments, and production deployment, with each stage promoting the same built artefact. Supporting practices include infrastructure as code, database migration automation, canary releases and blue-green deployments, and feature toggles to decouple deployment from feature release.
