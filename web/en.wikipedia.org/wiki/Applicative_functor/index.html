Applicative functor

From Wikipedia, the free encyclopedia

In functional programming, an applicative functor, or simply an applicative, is a type class (or corresponding structure in other languages) that sits between functors and monads in expressive power. Applicative functors allow functions to be applied to values wrapped in a computational context, and allow several independent computations in that context to be combined, while not permitting the structure of later computations to depend on the results of earlier ones — the limitation that distinguishes them from monads. The concept was introduced by Conor McBride and Ross Paterson in their 2008 paper "Applicative programming with effects".

Definition

In Haskell, the Applicative type class is defined (in modern versions of the language, as a superclass of Monad and subclass of Functor) with two principal operations:

class Functor f => Applicative f where
    pure  :: a -> f a
    (<*>) :: f (a -> b) -> f a -> f b

pure embeds a plain value into the context, and the infix operator <*> (pronounced "ap") applies a function wrapped in a context to a value wrapped in a context. Applicatives must obey four laws: identity, composition, homomorphism, and interchange, which together guarantee that applicative expressions behave predictably regardless of how they are associated or reordered.

Examples and uses

With the Maybe applicative, a computation proceeds only if every step yields a value: pure (+) <*> Just 2 <*> Just 3 evaluates to Just 5, while any Nothing propagates to the result. With lists, applicative application forms all combinations of functions and arguments, making it useful for non-deterministic computations. The ZipList applicative instead combines lists element-wise. Applicative style is widely used in parser combinator libraries and in validation code: the Validation applicative can accumulate all errors from independent checks, something a monad (which must stop or branch at the first failure) cannot do, because monadic binding makes each step depend on the previous value.

Relation to monads and functors

Every monad gives rise to an applicative functor, and every applicative is a functor, so the classes form a hierarchy: Functor ⊃ Applicative ⊃ Monad. The key difference is dependency: in an applicative expression the set of effects is fixed statically by the structure of the expression, which permits analyses and optimisations impossible with monads — for example, running independent database queries or remote calls in parallel. This static character also means applicative computations can be freely reordered by a compiler or library when the laws hold.

History

McBride and Paterson introduced applicative functors in the context of the Epigram language, recognising that many idiomatic uses of monads did not exploit the full power of monadic binding. The class was added to Haskell's standard library in GHC 7.10 (2015) as part of the Functor–Applicative–Monad proposal, which made Applicative a superclass of Monad. Analogous abstractions now exist in many languages and libraries, including Scala, F#, OCaml, and Rust-adjacent designs.
