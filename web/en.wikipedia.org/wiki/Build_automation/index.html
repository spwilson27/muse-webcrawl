Build automation

Build automation underpins continuous integration and delivery pipelines.

Build automation is the practice of automating the creation of a software build and the associated processes, including compiling source code into binary code, packaging the binaries, resolving and fetching dependencies, and running automated tests. Historically driven by tools such as make and its makefiles, modern build automation is handled by systems including Apache Ant, Maven and Gradle for the Java ecosystem, CMake and MSBuild for native code, and language-specific tools such as Cargo, npm scripts and Bazel.

Types and benefits

Automation may be on-demand (a developer runs a build), scheduled (nightly builds) or triggered (every commit starts a build on a server). Build servers such as Jenkins, GitHub Actions, GitLab CI and TeamCity implement continuous integration: each change is compiled and tested automatically so integration errors are detected early. Benefits include reproducibility, faster feedback, reduced manual error and a reliable path from source code to deployable artefacts, extended by continuous delivery pipelines toward automated deployment.
