Content addressable network

The content addressable network (CAN) is a distributed, decentralised P2P infrastructure that provides hash table functionality on an Internet-like scale. CAN was one of the four original distributed hash table (DHT) proposals, introduced concurrently with Chord, Pastry and Tapestry, in a paper by Sylvia Ratnasamy, Paul Francis, Mark Handley, Richard Karp and Scott Shenker published in 2001.

Design

CAN is built around a virtual multi-dimensional Cartesian coordinate space — conceptually, a d-dimensional torus. This coordinate space is completely virtual and bears no relation to physical geography. The space is dynamically partitioned among all peers in the system, so that every peer "owns" a contiguous zone of the space. A key is hashed to a point in the space, and the value is stored at whichever peer owns the zone containing that point. To retrieve an entry, any peer can apply the same hash function to determine the point and then route a query across the coordinate space, using greedy forwarding to neighbouring zones, until it reaches the responsible peer. Routing takes on the order of d·n1/d hops for n peers, and each peer maintains only O(d) neighbours regardless of system size.

Joining, leaving and design parameters

A new peer joins by choosing a random point in the space, routing to the owner of that point, and splitting that peer's zone in half, taking over one half. Departures require a neighbour to take over the orphaned zone, sometimes after zone merging. The design allows several optimisations: multiple independent coordinate spaces ("realities"), multiple peers per zone for redundancy, overloading zones, and caching and replication of hot entries. CAN influenced subsequent DHT and peer-to-peer research, though in practice systems such as Kademlia became more widely deployed.
