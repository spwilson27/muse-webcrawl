Quirks mode

Quirks mode
Type:Browser compatibility technique
Triggered by:Missing or legacy DOCTYPE

In computing, quirks mode is a technique used by some web browsers for the sake of maintaining backward compatibility with web pages designed for old browsers, instead of strictly complying with W3C and IETF standards in standards mode.

The concept was introduced in Internet Explorer 5 for Macintosh and adopted by all major browsers thereafter: a page with no document type declaration (DOCTYPE), or an old one, is rendered with legacy behaviours, while a page with a modern DOCTYPE triggers standards mode (and, in Internet Explorer, various intermediate "almost standards" modes).

Behaviour differences

Quirks mode emulates the bugs and non-standard behaviour of late-1990s browsers, particularly Netscape Navigator 4 and Internet Explorer 5. Differences include:

  • The CSS box model follows the old Internet Explorer model, in which width includes padding and borders.
  • Some CSS properties, such as unitless length values, are accepted where standards mode would reject the declaration.
  • Fonts inside tables do not inherit sizes in the standard way; percentage-based heights and certain table layouts behave differently.
  • Parsing of HTML tolerates different errors, and certain JavaScript behaviours differ.

Triggering

Browsers choose the rendering mode by "DOCTYPE sniffing". The simplest trigger for standards mode is the HTML5 doctype, <!DOCTYPE html>; documents without a doctype are always rendered in quirks mode. Some older doctypes trigger quirks or limited-quirks ("almost standards") modes depending on their exact public and system identifiers.

Modern web development practice is to always include the HTML5 doctype so that pages render in standards mode.
