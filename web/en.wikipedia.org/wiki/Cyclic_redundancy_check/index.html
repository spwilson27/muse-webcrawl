Cyclic redundancy check

A cyclic redundancy check (CRC) is an error-detecting code commonly used in digital networks and storage devices to detect accidental changes to digital data. Blocks of data entering these systems get a short check value attached, based on the remainder of a polynomial division of their contents. On retrieval, the calculation is repeated and, if the check values do not match, corrective action can be taken.

Principle

CRC computation treats the data as a large binary polynomial and divides it by a fixed generator polynomial over GF(2), keeping the remainder as the check value. Because polynomial division has strong algebraic properties, a CRC detects all single-bit errors, all double-bit errors within its designed span, and all burst errors no longer than the check value. The mathematics was set out by W. Wesley Peterson in 1961.

Common variants

The most widely used variant is CRC-32 (the IEEE 802.3 polynomial), used in Ethernet, ZIP and PNG files, and many other formats. CRC-16 variants serve in protocols such as Modbus and USB, and CRC-64 in some storage systems. Each specification defines not only the polynomial but also the initial value, bit reflection, and final XOR, which is why implementations are catalogued in detailed "CRC revues".

Applications

CRCs are cheap to implement in hardware with a linear feedback shift register, making them ideal for link layers and storage media. They are error-detecting, not security, codes: anyone can recompute a CRC after deliberately modifying data, so cryptographic hash functions are used where tampering must be detected.
