Register allocation

In compiler optimisation, register allocation is the process of assigning a large number of target program variables onto a small number of CPU registers. Register allocation can happen over a basic block (local register allocation), over a whole function/procedure (global register allocation), or across function boundaries traversed via call-graph (interprocedural register allocation).

Problem

Most computer architectures have far fewer registers than a program has variables. Values that cannot be held in registers must be "spilled" to memory, which is much slower to access. The allocator must decide which values stay in registers at each point in the program, taking into account which values are live simultaneously and therefore cannot share a register.

Graph colouring

A classic approach models the problem as graph colouring: each variable is a node, edges connect variables that interfere (are live at the same time), and registers correspond to colours. The problem is NP-complete in general, so compilers use heuristics such as the Chaitin–Briggs algorithm. Alternatives include linear scan allocation, used in just-in-time compilers, and allocation via puzzle solving or integer programming.
