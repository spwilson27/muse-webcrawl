Assembler (computing)

An assembler translates mnemonics into machine code

An assembler is a computer program that translates assembly language — symbolic mnemonics for machine instructions, together with labels, directives and macros — into machine code object files that can be linked and executed. Each assembly-language statement typically corresponds to a single processor instruction or a small, predictable expansion of instructions.

How assemblers work

Most assemblers make two passes over the source. In the first pass they build a symbol table, recording the address assigned to each label as instructions are counted. In the second pass they generate the actual machine code, resolving symbolic references. Assembler directives (pseudo-operations) control data allocation, section placement and conditional assembly, while macro assemblers let programmers define reusable instruction sequences that are expanded before assembly.

Types

Assemblers are usually specific to one instruction-set architecture: examples include GAS (the GNU Assembler), NASM and MASM for x86, and the assemblers built into LLVM. A cross-assembler runs on one machine while producing code for another, common in embedded development. A disassembler performs the reverse operation, converting machine code back into assembly language for analysis.

History

The first assemblers appeared in the late 1940s and 1950s; Kathleen Booth is credited with an early assembly system for the ARC computer, and the SOAP assembler for the IBM 650 was widely used. Assembly programming dominated early computing and remains in use for boot code, device drivers, performance-critical routines and embedded systems, though most software is now written in high-level languages whose compilers may themselves emit assembly as an intermediate step.
