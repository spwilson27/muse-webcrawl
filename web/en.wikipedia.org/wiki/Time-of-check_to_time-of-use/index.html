Time-of-check to time-of-use


The gap between check and use is exploitable

Time-of-check to time-of-use (TOCTOU, pronounced "tock-too") is a class of software bugs in computer security caused by a race condition involving the checking of the state of a part of a system (such as a security credential) and the use of the results of that check. TOCTOU race conditions are most common in Unix file system operations, but can occur in other local and distributed systems.

Description

A classic example involves a program that checks whether a user has permission to access a file, and then opens the file. Between the check and the open, an attacker may replace the file with a symbolic link pointing to a protected file such as a password database. If the checking program runs with elevated privileges, the attacker thereby gains access it should not have. The vulnerability exists because the state verified at check time is not guaranteed to be the state acted on at use time.

Exploitation and mitigation

TOCTOU bugs are hard to eliminate because they require the attacker to win a race, often by slowing the victim process with many files or symlinks. Reliable mitigations bind the check and the use together: opening the file once and performing permission checks on the already-open file descriptor (for example with fstat), using system calls that operate on file descriptors rather than paths, or working in directories the attacker cannot write to. Transactions and atomic operations provide similar guarantees in databases and distributed systems.
