Rule of three (C++ programming)

FieldSoftware engineering / C++
RelatedRule of five, rule of zero
ConcernsDestructor, copy constructor, copy assignment operator

The rule of three is a rule of thumb in C++ programming: if a class defines any one of the following, it should probably explicitly define all three — the destructor, the copy constructor and the copy assignment operator.

Rationale

Needing to define one of these special member functions usually signals that the class manages a resource, such as a heap allocation, that the compiler-generated defaults handle incorrectly: default copying copies the pointer rather than the resource, leading to double deletion or dangling handles. Defining all three ensures the resource is released exactly once and copies are made safely.

Successors

With C++11's move semantics, the rule was extended to the rule of five, adding the move constructor and move assignment operator. Modern guidance prefers the rule of zero: classes should delegate resource management to dedicated members such as smart pointers and standard containers, avoiding user-declared special member functions altogether.
