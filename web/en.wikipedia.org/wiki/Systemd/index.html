systemd is a software suite that provides an array of system components for Linux operating systems. Its main aim is to unify service configuration and behaviour across Linux distributions; systemd's primary component is a "system and service manager" — an init system used to bootstrap user space and manage user processes. It also provides replacements for various daemons and utilities, including device management, login management, network connection management, and event logging.

The name systemd adheres to the Unix convention of making daemons' names end with the letter d. It also plays on the term "System D". The software is written by Lennart Poettering and many other contributors, and is published as free and open-source software under the terms of the GNU Lesser General Public License.

Design

systemd organises system resources into units, described by declarative unit files: service units, socket units, device units, mount units, timer units, targets (groups of units) and others. Dependencies between units are expressed declaratively, allowing extensive parallelisation of the boot process through socket-based and D-Bus-based activation. Processes are tracked using Linux cgroups. Components include journald for logging, logind for login sessions, networkd and resolved for networking, and udevd-derived device management.

Adoption

Following its release in 2010, systemd was adopted by Fedora in 2011 and subsequently became the default init system of most major Linux distributions, including Red Hat Enterprise Linux 7, Debian 8, Ubuntu 15.04, SUSE and Arch Linux. Its adoption was controversial: critics argued that its scope violated the Unix philosophy of small, single-purpose tools and that absorbing other system functions created excessive interdependence, while supporters praised its consistent management interface, fast parallel boot, and modern features. The controversy led to forks and alternatives such as Devuan (a Debian fork without systemd), OpenRC, runit and s6.
