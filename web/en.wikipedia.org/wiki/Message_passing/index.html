Message passing

From Wikipedia, the free encyclopedia

In computer science, message passing is a technique for invoking behaviour (for example, running a program, producing output, or updating state) on a computer through the sending of discrete messages to a system rather than by direct manipulation of shared memory. The implementing system selects, from its own store of procedures, the procedure whose name and arguments match the message, and runs it. Message passing differs from conventional programming where a process, subroutine, or function is directly invoked by name.

Message passing is a core abstraction in concurrent and distributed systems and in object-oriented programming, where objects communicate by sending messages to one another.

Overview

Message passing may be implemented by hardware primitives such as channels, by operating-system inter-process communication (pipes, sockets, signals), or by language-level constructs. It may be synchronous, where the sender blocks until the receiver is ready (as in CSP-style channel communication), or asynchronous, where messages are buffered and the sender continues immediately (as in the actor model).

Language and system support

  • Erlang and the actor model: processes share nothing and communicate only by asynchronous messages, supporting fault-tolerant distributed systems.
  • Go: goroutines communicate over typed channels, following the maxim "share memory by communicating".
  • MPI (Message Passing Interface): the standard for high-performance computing clusters, with send/receive primitives such as MPI_Send and MPI_Recv.
  • Smalltalk and Objective-C: method invocation itself is framed as sending messages to objects.
  • Microkernel operating systems such as Mach and QNX pass messages between servers implementing system services.

Comparison with shared memory

Message passing avoids the race conditions and locking hazards of shared-memory concurrency and maps naturally onto machines without common memory, including clusters and networks. The cost is copying and serialisation overhead and potentially more complex control flow. Modern frameworks often combine both models.
