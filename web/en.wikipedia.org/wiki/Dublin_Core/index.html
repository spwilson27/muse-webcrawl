The Dublin Core, also known as the Dublin Core Metadata Element Set (DCMES), is a set of fifteen "core" elements (properties) for describing resources such as documents, images, and web pages, designed to make them easier to discover and manage. It is one of the most widely used metadata schemas in libraries, archives, digital repositories, and web publishing.

History

Dublin Core originated at a March 1995 invitational workshop in Dublin, Ohio—hosted by OCLC and the National Center for Supercomputing Applications—where librarians, computer scientists, and text-encoding specialists sought a simple, common set of descriptive elements for networked resources; the name refers to the Ohio city, not the Irish capital (and echoes, coincidentally, "Dublin" as in OCLC's home). The resulting scheme was deliberately minimal and extensible so that non-specialists could create useful records.

The fifteen elements

The core elements are: Title, Creator, Subject, Description, Publisher, Contributor, Date, Type, Format, Identifier, Source, Language, Relation, Coverage, and Rights. All are optional and repeatable, and none has a prescribed order. "Simple" (unqualified) Dublin Core uses just these elements; "qualified" Dublin Core adds refinements and encoding schemes—for example, narrowing Date to created or modified, or specifying that an identifier is a URI. Since 2008 the vocabulary has been maintained as the DCMI Metadata Terms, expressed in RDF, and Dublin Core forms the basis of the metadata harvested by the Open Archives Initiative Protocol for Metadata Harvesting (OAI-PMH), which requires it as the lowest-common-denominator format.

Encodings and uses

Dublin Core records can be embedded in HTML/XHTML meta tags, expressed in XML, or serialized as RDF. It underpins digital-library platforms such as DSpace and Omeka (the latter built its item descriptions on Dublin Core), institutional repositories, and many government open-data portals. Its simplicity is both its strength—easy cross-domain interoperability—and its limitation, as richer domains often extend it or adopt more detailed schemas alongside it.
