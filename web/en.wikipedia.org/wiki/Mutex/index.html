Mutex

In concurrent programming, a mutex (short for mutual exclusion) is a synchronisation primitive that prevents state from being modified or accessed by multiple threads of execution at once. A mutex enforces a mutual exclusion policy: only one thread at a time may hold the lock, and thereby enter the critical section the mutex protects.

Operation

A thread acquires (locks) the mutex before entering a critical section and releases (unlocks) it on exit. If another thread attempts to acquire a mutex that is already held, it blocks — or spins — until the owner releases it. Mutexes are typically implemented with support from atomic hardware instructions such as compare-and-swap, and from the operating system scheduler, which can put waiting threads to sleep.

Variants

Common variants include the recursive mutex, which can be re-acquired by the thread that already owns it; the reader–writer lock, which permits many concurrent readers or a single writer; and the spinlock, which busy-waits and is suitable only for very short critical sections. The C++ and POSIX pthreads standards both provide mutex types, and most high-level languages expose them as lock objects.

Pitfalls

Incorrect use of mutexes leads to race conditions if critical sections are left unprotected, and to deadlock when threads acquire several locks in inconsistent orders and wait on each other forever. Priority inversion, in which a high-priority thread waits on a low-priority lock holder that is itself preempted, can be mitigated by priority inheritance protocols. A mutex differs from a semaphore in that it has an owner — the thread that locked it must be the one to unlock it — whereas a semaphore is a general signalling and counting mechanism.
