Collision attack

Collision attack
Field: Cryptanalysis
Target: Cryptographic hash functions
Related: Preimage attack, birthday attack

A collision attack on a cryptographic hash function is an attempt to find two distinct inputs that produce the same hash output, known as a collision. A secure hash function should make finding collisions computationally infeasible; a successful collision attack therefore breaks one of the function's core security properties.

Birthday bound

Because of the birthday paradox, a generic collision search against an n-bit hash requires only about 2^(n/2) evaluations, far fewer than the 2^n needed for a preimage attack. This birthday bound is why output sizes are chosen generously: a 256-bit hash offers roughly 128-bit collision resistance.

Real-world attacks

Differential cryptanalysis enabled practical collisions in MD5 by 2004, and MD5 collisions were later used to forge certificates and by the Flame malware. In 2017 the SHAttered attack produced the first public collision for SHA-1, and chosen-prefix SHA-1 collisions followed in 2020. These results accelerated migration to the SHA-2 and SHA-3 families.

Types

In a classic collision attack the attacker controls both inputs freely. In a chosen-prefix collision attack, the attacker is given two different prefixes and must find suffixes making the complete messages collide, a stronger and more dangerous result. A preimage attack, by contrast, targets a fixed output.

Consequences

Collisions undermine digital signatures and certificates, because a signature computed for one document can be transferred to a colliding, malicious document.
