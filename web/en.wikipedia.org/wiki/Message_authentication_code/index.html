Message authentication code

In cryptography, a message authentication code (MAC), sometimes known as an authentication tag, is a short piece of information used for authenticating and integrity-checking a message. In other words, it confirms that the message came from the stated sender (its authenticity) and has not been changed (its integrity). The MAC value protects a message's data integrity, as well as its authenticity, by allowing verifiers (who also possess the secret key) to detect any changes to the message content.

Security properties

A MAC algorithm is considered secure if it is computationally infeasible, without knowledge of the key, to produce a valid tag for a new message — a property called existential unforgeability under chosen-message attack. Unlike digital signatures, MACs are symmetric: the same secret key is used to generate and verify the tag, so a MAC cannot provide non-repudiation, since any verifier could also have created the tag.

Constructions

  • HMAC — a MAC built from a cryptographic hash function (e.g., HMAC-SHA256), standardized in FIPS 198 and RFC 2104.
  • CMAC — a block-cipher-based MAC derived from CBC-MAC, standardized by NIST (SP 800-38B).
  • GMAC — the authentication component of AES-GCM authenticated encryption.
  • Poly1305 — a one-time MAC used with ChaCha20 in the ChaCha20-Poly1305 AEAD construction.
  • KMAC — a MAC based on the Keccak (SHA-3) permutation, specified in NIST SP 800-185.

Applications

MACs are used in network protocols such as TLS and IPsec, in financial messaging (e.g., ISO 8583 and SWIFT), in protecting the integrity of cookies and API tokens, and in authenticated encryption schemes. MACs are also related to checksums and hash functions, but differ in using a secret key: an unkeyed hash can be recomputed by an attacker who modifies the message.
