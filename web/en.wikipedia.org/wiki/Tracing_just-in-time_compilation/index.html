Tracing just-in-time compilation

Tracing just-in-time compilation is a technique used by virtual machines to speed up the execution of programs, often those written in dynamically typed languages. Instead of compiling whole methods in advance, a tracing JIT observes the program as it runs in an interpreter, identifies frequently executed ("hot") sequences of instructions — typically loops — and records a linear trace of the actual instructions executed along one path through the code. The trace is then compiled to optimized native machine code, with guards that check assumptions made during recording; if a guard fails, execution exits back to the interpreter.

Overview

The approach contrasts with method-based JIT compilation, which compiles one method at a time. Because traces follow actual execution across method calls and branches, tracing JITs naturally inline across function boundaries and optimize the common path, deferring rarely taken branches to side exits. The linearization of control flow simplifies optimization, but the technique is less effective for code with many unpredictable branches or short-lived programs where compilation costs are not amortized.

History and implementations

Tracing compilation has roots in research systems of the 1990s and 2000s, including the Dynamo project for native code optimization and the Gal et al. work on tracing for dynamic languages. Well-known implementations include:

  • TraceMonkey — the tracing JIT added to Mozilla's SpiderMonkey JavaScript engine in Firefox 3.5 (2009)
  • LuaJIT — Mike Pall's high-performance just-in-time compiler for Lua, built around trace compilation
  • PyPy — a Python implementation whose meta-tracing JIT is generated from an interpreter written in RPython
  • GraalVM / Truffle — related partial-evaluation approaches in the same design space

Advantages and disadvantages

Traces capture type information and branch behaviour observed at run time, enabling aggressive specialization. However, tracing JITs can suffer from "trace explosion" on branchy code, high memory use for compiled traces, and difficulty with programs whose hot paths are not loop-shaped.
