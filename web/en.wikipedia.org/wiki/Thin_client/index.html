Thin client

Thin client
Definition: a lightweight computer that depends on a server for most processing and storage
Opposite: fat client (a fully capable standalone PC)
Related models: dumb terminal, network computer, zero client, desktop virtualisation (VDI)
Protocols: RDP, Citrix ICA/HDX, VMware Blast, PCoIP, X11

A thin client is a computer or computer program that runs primarily by connecting to a remote server, which performs the bulk of the computation and stores the data and applications. The thin client itself supplies essentially the user interface — display, keyboard, mouse, and basic networking — with minimal local processing power, storage, and software. The term was popularised in the 1990s as the "network computer" concept promoted by companies such as Oracle and Sun Microsystems challenged the dominant model of powerful desktop PCs.

Model and architecture

In a thin-client system, applications run on central servers — terminal servers, or virtual desktops delivered through virtual desktop infrastructure (VDI) — and only screen updates, keystrokes, and pointer movements travel over the network, using remote display protocols such as Microsoft's RDP, Citrix ICA/HDX, or VMware's Blast Extreme. A still more reduced variant, the zero client, contains no local operating system or storage at all, implementing the protocol in firmware or dedicated hardware.

Advantages

  • Centralised management: software is installed, patched, and backed up once, on the server.
  • Security: no sensitive data resides on endpoints; devices can be locked down and are unattractive to thieves.
  • Cost and longevity: endpoints are cheap, consume little power, have no moving parts, and last longer than full PCs.
  • Anywhere access: a user's session can follow them from terminal to terminal.

Disadvantages

Thin clients depend completely on network and server availability — a server or network failure idles every connected user. Performance can suffer over slow or high-latency connections, especially for graphics, video, and peripheral-rich work, and the server infrastructure needed to support many simultaneous desktops can be expensive and complex to scale. The pendulum of computing has swung repeatedly between centralised and local models: dumb terminals on mainframes, then PCs, then thin clients and VDI, and most recently browser-based and cloud applications, which are in effect a software form of the thin-client idea.

Uses

Thin clients are widely deployed in call centres, hospitals, schools, libraries, banks, retail points of sale, and government offices — environments with many similar workstations, standard applications, and strong requirements for control and data security.
