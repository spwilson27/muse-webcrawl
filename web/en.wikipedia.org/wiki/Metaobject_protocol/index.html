Metaobject protocol

In computer science, a metaobject protocol (MOP) is an interpreter of the semantics of a program that is open and extensible. Rather than treating the language's object system as a fixed black box, a metaobject protocol exposes the objects that implement the language itself — classes, methods, generic functions, and slots — as objects that the programmer can inspect and modify. This allows programmers to adjust the semantics of the language, for example to implement new kinds of inheritance, method combination, or persistence, without modifying the underlying implementation.

History

The term and the canonical design were presented in the 1991 book The Art of the Metaobject Protocol by Gregor Kiczales, Jim des Rivières, and Daniel G. Bobrow, which described the metaobject protocol of the Common Lisp Object System (CLOS). The CLOS MOP defines metaobjects such as standard-class, standard-method, and standard-generic-function, together with generic functions like compute-slots and slot-value-using-class that programmers can specialise.

Design principles

  • Open implementation — language designers expose selected implementation decisions as a protocol rather than hiding them.
  • Incremental extension — new behaviour is added by subclassing metaobjects and specialising protocol functions, keeping default behaviour intact.
  • Reflectivity — the system can be used to describe and modify itself.

Examples

Besides CLOS, metaobject protocols or related reflective facilities appear in Smalltalk (where classes are objects manipulated through the class library), Ruby, Python (metaclasses and descriptors), Objective-C's runtime, and various research languages. Java's reflection API is sometimes contrasted with a true MOP because it is largely read-only: it permits inspection but limited modification of program semantics.
