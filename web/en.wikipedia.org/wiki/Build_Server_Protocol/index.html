Build Server Protocol

An editor communicating with a build server over BSP

The Build Server Protocol (BSP) is an open protocol for communication between development tools — such as editors and IDEs — and build servers, analogous to the Language Server Protocol (LSP) for language intelligence. It was created by the Scala Center and first published in 2018.

Purpose

Build tools such as sbt, Bazel, Gradle and Mill already know how a project is structured: its targets, dependencies, source directories and compilation settings. Before BSP, every editor had to reimplement integration with each build tool, or duplicate its logic. BSP standardises the interface so that any editor can ask any build server for project structure, compile targets, run tests, and receive diagnostics and build events.

How it works

BSP is based on JSON-RPC, like LSP, and can run over standard input/output, sockets, or other transports. A client first sends an initialize request, then queries the server for build targets and their capabilities. The server reports compilation status, diagnostics, and task progress, and the client can request compilation, testing, and running of targets. BSP deliberately complements LSP: LSP handles editing features such as completion and hover, while BSP handles build concerns such as compilation and classpath.

Adoption

BSP is supported by sbt, Mill, Bazel (via rules and plugins), and build servers for Scala, Java, Kotlin and other JVM languages. Editors including IntelliJ IDEA, VS Code (via the Metals extension), Neovim and Emacs can connect to BSP servers, giving developers a consistent experience across build tools.
