Pattern matching

A value is tested against patterns in order; the first match selects its branch.

In computer science, pattern matching is the act of checking a given sequence of tokens for the presence of the constituents of some pattern. In contrast to pattern recognition, the match usually has to be exact: either it will or will not be a match. The patterns generally have the form of either sequences or tree structures.

In programming languages

Pattern matching is a core feature of functional programming languages such as ML, Haskell, Erlang, Elixir, Scala, Rust, and OCaml, where it serves both to test the shape of a data value and to destructure it, binding variables to its parts. A match expression lists patterns — literals, variables, wildcards, tuples, lists, and constructors of algebraic data types — each with a corresponding result expression:

describe []        = "empty"
describe [x]       = "singleton"
describe (x : xs)  = "headed by " ++ show x

Compilers for such languages typically check that matches are exhaustive (all possible cases are covered) and warn about redundant clauses. Pattern matching on strings is most commonly provided through regular expressions, while languages such as Snobol and early string-processing systems historically specialised in it.

Tree patterns

When data takes the form of trees — abstract syntax trees, XML documents, or term-rewriting systems — pattern matching generalises to tree patterns, which can include variables standing for whole subtrees. Term rewriting systems such as Mathematica's use patterns with named blanks to define symbolic transformations.
