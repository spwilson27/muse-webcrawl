Distributed database

A distributed database is a database in which data is stored across multiple computers located in different physical locations, connected by a network, while appearing to users as a single logical database. The software that manages it — a distributed database management system (DDBMS) — handles data fragmentation, replication, and transactions across sites.

Architecture

Data may be fragmented (partitioned) across nodes — horizontally by rows or vertically by columns — or replicated, with copies maintained at several sites for fault tolerance and read performance. Systems may be homogeneous (same DBMS software everywhere) or heterogeneous (different systems integrated behind a common interface).

Transparency and transactions

A DDBMS aims to provide location, fragmentation, and replication transparency: users issue queries as if the data were local. Distributed transactions must preserve the ACID properties across sites, classically using the two-phase commit protocol, though this can harm availability. The CAP theorem formalises the trade-off between consistency and availability during network partitions, and many modern systems (including many NoSQL stores) adopt eventual consistency instead.

Advantages and drawbacks

Advantages include improved reliability, scalability, modular growth, and performance for geographically dispersed users. Drawbacks include greater complexity in design, concurrency control, security, and failure handling. Widely used distributed systems include Google Spanner, Apache Cassandra, Amazon DynamoDB, and CockroachDB.
