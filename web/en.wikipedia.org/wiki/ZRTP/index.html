ZRTP

ZRTP is a cryptographic key-agreement protocol for negotiating the keys for encryption between two end points in a Voice over Internet Protocol (VoIP) phone telephony call, based on the Real-time Transport Protocol (RTP). It is described in RFC 6189. ZRTP uses Diffie–Hellman key exchange and the Secure Real-time Transport Protocol (SRTP) for encryption, and was designed so that no signalling-layer key exchange, public key infrastructure or prior shared secrets are required.

Design

ZRTP was developed by Phil Zimmermann, the creator of Pretty Good Privacy (PGP), together with Jon Callas and Alan Johnston, and was unveiled in 2006. The protocol runs in the media stream itself, in the same UDP path as the RTP voice data, rather than in the signalling channel. Endpoints discover each other's ZRTP capability through special hello packets, perform a Diffie–Hellman exchange, and then switch the call to SRTP encryption.

Authentication and the Short Authentication String

Because the Diffie–Hellman exchange is unauthenticated, ZRTP protects against man-in-the-middle attacks by deriving a Short Authentication String (SAS) — typically two words from the PGP word list — from the shared secret, which the two callers read aloud and compare over the voice channel, authenticating the exchange with the recognisability of the human voice. Key continuity is provided by retained shared secrets: each endpoint caches secrets from previous calls and mixes them into new sessions, so an attacker must be present on the very first call to remain undetected.

Implementations

ZRTP was first shipped in the Zfone software developed by Zimmermann's company. Open-source libraries such as GNU ZRTP (used in the GNU project and by applications such as Jitsi, Linphone and CSipSimple) and support in softphones and in the FreeSWITCH and Asterisk ecosystems have made it one of the best-known end-to-end VoIP encryption protocols, although built-in support by major consumer services remained limited.
