Windows Runtime (WinRT) is a platform-agnostic component application architecture first introduced in Windows 8 and Windows Server 2012. It is implemented in C++ and officially supports development in C++ (via C++/WinRT or C++/CX), managed languages such as C# and Visual Basic .NET, and JavaScript.

WinRT is not a runtime in the traditional sense, but rather a collection of APIs built on an enhanced Component Object Model (COM) that allows applications written in different languages to interoperate. It exposes APIs for building applications for the Universal Windows Platform (UWP), including the Windows Store app model introduced with Windows 8.

Windows Runtime architecture with language projections

Technology

WinRT components are described by metadata files with the .winmd extension, based on the ECMA-335 metadata format used by the .NET Framework. Language projections translate these metadata descriptions into idiomatic bindings for each supported language, so that developers in C#, JavaScript, or C++ see APIs that feel native to their language. The underlying application binary interface is COM-based, and all WinRT objects implement the IUnknown interface.

Services

The Windows Runtime provides services grouped into namespaces such as Windows.Foundation, Windows.UI, Windows.Storage, Windows.Networking, and Windows.Devices. These expose functionality for user interfaces, file access, networking, sensors, and media playback. Asynchronous operations are a first-class part of the design: any operation that may take longer than about 50 milliseconds is exposed as an asynchronous API.

History

WinRT was unveiled at Microsoft's Build conference in September 2011 and shipped with Windows 8 in October 2012. It was later extended to support the Universal Windows Platform in Windows 10, allowing a single application binary to run across PCs, phones, tablets, Xbox consoles, and HoloLens devices. The C++/WinRT projection, a standard C++17 implementation, largely superseded the earlier C++/CX language extension.
