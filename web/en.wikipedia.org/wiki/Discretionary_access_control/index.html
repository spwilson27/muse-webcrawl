Discretionary access control

In computer security, discretionary access control (DAC) is a type of access control defined by the Trusted Computer System Evaluation Criteria (TCSEC) as "a means of restricting access to objects based on the identity of subjects and/or groups to which they belong. The controls are discretionary in the sense that a subject with a certain access permission is capable of passing that permission (perhaps indirectly) on to any other subject (unless restrained by mandatory access control)."

Implementations

The term DAC is used in two subtly different senses in practice. In the classic TCSEC sense, DAC refers to the ability of object owners to decide who may access their objects. In a looser sense used by much of the industry, DAC describes any identity-based access control scheme as opposed to lattice-based mandatory access control (MAC) or role-based access control (RBAC).

The most familiar implementation of DAC is the file permission system of Unix and Unix-like operating systems, in which each file has an owner and a group, and read, write, and execute permissions can be set separately for the owner, the group, and others. POSIX access control lists (ACLs) extend this scheme by allowing permissions to be granted to additional named users and groups. Microsoft Windows NT and its successors implement DAC through discretionary access control lists (DACLs) attached to securable objects.

Comparison with mandatory access control

Whereas DAC allows users to control access to their own data, mandatory access control enforces system-wide security policies that users cannot override, typically based on security labels and clearances. Because a DAC system cannot prevent a user (or a Trojan horse program running with the user's privileges) from passing information to unauthorized parties, DAC alone is considered insufficient for high-assurance environments, and it is often combined with MAC in multi-level secure systems.
