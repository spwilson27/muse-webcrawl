Exception handling

Exception handling is the process of responding to the occurrence of exceptions — anomalous or exceptional conditions requiring special processing — during the execution of a program. In general, an exception breaks the normal flow of execution and executes a pre-registered exception handler; the details depend on whether the exception is defined at the hardware or software level and on the language implementation.

Mechanisms

Most modern languages provide constructs such as try, catch (or except), and finally: code that may raise an exception is placed in a try block, handlers catch particular exception types, and a finally block runs cleanup code regardless of outcome. Exceptions are raised explicitly with throw or raise, or implicitly by runtime errors such as division by zero or null dereferences. Languages including Java distinguish checked exceptions, which must be declared or caught, from unchecked ones.

History

Early mechanisms appeared in PL/I (ON conditions) and Lisp (condition systems). The try/catch model was popularized by C++ in the 1990s and adopted by Java, C#, Python, JavaScript, and many others. Alternatives include returning error codes or result types (as in Rust and Go), which avoid the control-flow complexity of exceptions.

Criticism

Exceptions are criticized for creating invisible exit points and for performance costs in some implementations; supporters value the separation of error handling from normal code.
