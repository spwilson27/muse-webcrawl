Berkeley sockets is an application programming interface (API) for Internet domain sockets and Unix domain sockets, used for inter-process communication (IPC). It originated with the 4.2BSD Unix operating system, released in 1983, and became the de facto standard abstraction for network programming; a version of the interface is implemented on essentially every modern operating system, including the Windows implementation known as Winsock.

Design

A socket is an endpoint of a communication channel, represented to the programmer by a file descriptor. The API provides functions including socket(), bind(), listen(), accept(), connect(), send()/recv() (and sendto()/recvfrom() for connectionless communication), and close(). The interface is protocol-agnostic: address structures (sockaddr) allow the same calls to serve TCP/IP, UDP, and local Unix-domain communication.

History and standardisation

The sockets interface was designed at Berkeley's Computer Systems Research Group as the user interface to the networking code in BSD Unix, funded under a DARPA contract. It was later standardised by POSIX as part of the networking APIs. The typical client–server usage pattern — a server binding, listening, and accepting connections while clients connect — remains the model taught in network programming today, though many higher-level frameworks now hide it.
