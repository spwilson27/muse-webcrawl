Extended Display Identification Data

Extended Display Identification Data (EDID) is a metadata format for display devices to describe their capabilities to a video source (for example, a graphics card or set-top box). The format is defined by a standard published by the Video Electronics Standards Association (VESA). EDID data includes the manufacturer's name and serial number, product type, phosphor or filter type (for older displays), timings supported by the display, display size, luminance data, and (for digital displays) pixel mapping data.

Transmission

The video source reads the EDID over the Display Data Channel (DDC), an I²C bus carried on VGA, DVI, HDMI, and DisplayPort connections. When a display is connected, the source retrieves the EDID block and uses it to select a video mode — resolution and refresh rate — that the display supports, enabling plug-and-play operation without manual configuration.

Structure

The base EDID block is 128 bytes long. It begins with the fixed header 00 FF FF FF FF FF FF 00, followed by manufacturer and product identifiers, serial number, date of manufacture, display parameters (size, gamma, supported features), chromaticity coordinates for the display's color primaries, established timing bitmaps, standard timing information, and up to four 18-byte detailed timing descriptors, one of which typically gives the native (preferred) resolution. A final byte is a checksum; the sum of all 128 bytes must equal zero modulo 256.

Extensions

An optional extension count byte indicates additional 128-byte extension blocks. The most common is the CTA-861 extension (formerly CEA-861), used with HDMI equipment to declare supported video formats (such as 720p, 1080p, and 4K modes), audio capabilities (formats, channel counts, speaker allocation), colorimetry, and HDR metadata support. Other extensions cover detailed timings and display transfer characteristics.

Versions and successors

EDID structure versions 1.0 through 1.4 refined the data fields over time. VESA's DisplayID standard was designed as a more flexible successor with variable-length, tagged data blocks, and is used in some modern displays and embedded DisplayPort (eDP) applications, while EDID remains near-universal in consumer equipment.

Problems and overrides

Incorrect or incomplete EDID data from a display can cause a source to select a suboptimal or unsupported resolution. Operating systems therefore provide "EDID overrides" that substitute corrected data. KVM switches and long cable runs can also interfere with the DDC connection, preventing EDID from being read at all.
