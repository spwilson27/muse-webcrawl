System programming language

A system programming language is a programming language used for system programming, that is, for writing system software such as operating systems, device drivers, compilers, embedded firmware and high-performance infrastructure. Such languages generally provide direct access to hardware, predictable performance, and fine control over memory, while application programming languages typically prioritize abstraction and safety over control.

Characteristics

System programming languages are distinguished by features such as manual memory management or explicit ownership models, minimal or optional runtime support, the ability to interface directly with machine instructions and operating-system calls, and compilation to efficient native code. Programs written in them must often run with limited resources and strict timing requirements.

Examples

Historically, system software was written in assembly language; the arrival of PL/S, BCPL and especially C — in which most of Unix was rewritten in 1973 — made portable system programming practical. Later languages in this category include C++, and more recent entrants designed to preserve C-like control while improving safety, such as Rust, Zig, D and Go (which occupies a borderline position). Domain-specific system languages include eBPF languages and shader languages for graphics hardware.
