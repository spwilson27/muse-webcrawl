Command-query separation
FieldSoftware design
Introduced byBertrand Meyer

Command-query separation (CQS) is a principle of imperative computer programming. It was devised by Bertrand Meyer as part of his work on the Eiffel programming language. It states that every method should either be a command that performs an action, or a query that returns data to the caller, but not both.

Principle

A query should not modify the observable state of the object, while a command should not return a value. Asking a question should not change the answer, in Meyer's formulation. The separation makes code easier to reason about and queries safe to call repeatedly.

Exceptions and related patterns

Some operations, such as popping an element from a stack, naturally both return data and mutate state and are commonly accepted violations. At the architectural level, the related CQRS pattern (command query responsibility segregation) separates read and write models of an entire system.
