Parametric polymorphism

In programming languages and type theory, parametric polymorphism allows a function or a data type to be written generically, so that it can handle values identically without depending on their type. Such functions and data types are called generic functions and generic definitions respectively, and form the basis of generic programming.

Definition

A function exhibits parametric polymorphism if its behaviour does not depend on the concrete types at which it is used. The canonical example is the identity function, which in Hindley–Milner notation has the type ∀a. a → a: for every type a, it maps a value of that type to a value of the same type. Similarly the type of lists can be written ∀a. [a]. Christopher Strachey distinguished parametric polymorphism from ad hoc polymorphism (overloading) in 1967, a classification still in use.

Parametricity

Because a parametrically polymorphic function cannot inspect the values of an abstract type, its behaviour is tightly constrained — a principle John C. Reynolds formalised as parametricity, and Philip Wadler popularised as "theorems for free": properties of generic functions can be deduced from their types alone. For example, any function of type ∀a. [a] → [a] can only rearrange, duplicate, or drop elements of its input list.

Implementations

Parametric polymorphism is a core feature of ML-family languages (ML, OCaml, Haskell), where it is inferred by the Hindley–Milner type system. Other languages provide it as generics: Java (via type erasure), C# (via reification), C++ (templates, checked at instantiation), and Rust (traits with monomorphisation). Bounded parametric polymorphism constrains type parameters with subtyping bounds or type-class constraints.

History

The concept was identified in logic by Gerhard Gentzen's work in the 1930s and developed for programming by Strachey, Reynolds (who introduced System F in 1974), and Jean-Yves Girard, who independently developed System F.
