Amortized analysis

In computer science, amortized analysis is a method for analysing an algorithm's time complexity by averaging the cost of operations over a sequence: even if a single operation occasionally takes much longer than the rest, amortized analysis bounds the cost per operation over the whole sequence. It differs from average-case analysis because it makes no probabilistic assumptions — the guarantee holds for the worst-case sequence. The technique was systematically developed by Robert Tarjan in 1985; the word "amortized" is borrowed from the accounting notion of spreading a cost over time.

Methods

Aggregate method

Show that any sequence of n operations takes total time T(n); the amortized cost per operation is then T(n)/n.

Accounting method

Assign each operation an artificial "charge"; inexpensive operations bank credit with the data structure, which expensive operations later spend. The charges must be set so the bank balance never goes negative.

Potential method

Define a potential function Φ on the data structure's state; the amortized cost of an operation is its actual cost plus the change in potential, Φ(after) − Φ(before). Expensive operations "pay for themselves" by reducing potential.

Example: dynamic arrays

A dynamic array (as in C++ vector or Java ArrayList) doubles its capacity when full: most appends cost O(1), but the append that triggers a resize costs O(n) to copy the elements. Over n appends the total copying cost is n + n/2 + n/4 + … < 2n, so append is O(1) amortized even though an individual append can be expensive. Amortized bounds of this kind underpin the analysis of splay trees, Fibonacci heaps (O(1) amortized decrease-key) and the union–find data structure (inverse-Ackermann amortized cost).
