DLL hell

DLL hell is a colloquial term for the problems caused by managing dynamic-link libraries (DLLs) on Microsoft Windows, most notoriously in the 1990s and early 2000s.

The problem

Applications shared DLLs installed in common system directories. Installing or upgrading one program could overwrite a shared library with an incompatible version, silently breaking other programs; uninstallers could likewise remove libraries still needed. Version conflicts were hard to diagnose and reproduce.

Remedies

Microsoft addressed DLL hell with Windows File Protection, side-by-side assemblies and the WinSxS store, private application-local DLLs, and later the .NET Framework with its strongly named assemblies in the Global Assembly Cache. Similar dependency problems appear on other platforms under names such as "dependency hell".
