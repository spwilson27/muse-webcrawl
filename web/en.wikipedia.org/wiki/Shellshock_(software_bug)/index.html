Shellshock (software bug)

CVE identifier(s)CVE-2014-6271 (original); CVE-2014-7169 and others
Date discoveredSeptember 2014 (reported 12 September; disclosed 24 September 2014)
Affected softwareGNU Bash through version 4.3
DiscovererStéphane Chazelas

Shellshock, also known as Bashdoor, is a family of security bugs in the Unix Bash shell, the first of which was disclosed on 24 September 2014. Shellshock could enable an attacker to gain unauthorised access to a computer system: versions of Bash up to 4.3 improperly executed trailing commands stored in environment variables, a feature intended to pass function definitions between shell processes. Because Bash is widely used to run programs on behalf of web servers, DHCP clients, SSH servers, and mail servers, the bug exposed a huge fraction of Internet-connected systems — comparable in scale to the Heartbleed bug disclosed earlier in 2014.

Testing a system for Shellshock with a crafted environment variable.

Background

The flaw was introduced into Bash around 1989 and reported by Unix specialist Stéphane Chazelas to the maintainer, Chet Ramey, on 12 September 2014. Because many programs pass attacker-influenced data (such as HTTP headers, User-Agent strings, or DHCP options) into a child process's environment and then invoke Bash indirectly — for example through CGI scripts executed via /bin/sh — the bug could be triggered remotely without any credentials.

Exploitation and response

A vulnerable shell could be detected with a test of the form:

env x='() { :;}; echo vulnerable' bash -c "echo test"

Exploitation in the wild began within hours of disclosure, including botnet-driven scanning and attempts to build DDoS armies. The first patch was incomplete, leading to a series of follow-on CVEs (7169, 6277, 6278, 7186, 7187) addressed over the following days. Vendors of Linux distributions, macOS, and embedded devices issued updates; the US National Vulnerability Database rated the original bug 10.0, the maximum severity.
