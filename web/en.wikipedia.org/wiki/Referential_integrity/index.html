Referential integrity

Referential integrity is a property of data stating that all its references are valid. In relational databases, it means that if a value of one attribute (column) of a relation (table) references a value of another attribute (either in the same or a different relation), then the referenced value must exist. It is enforced through foreign key constraints.

Formal definition

For referential integrity to hold in a relational database, any field in a table declared as a foreign key must contain only values from a parent table's primary key or a candidate key. Inserting a row with a foreign key value that has no matching parent row, or deleting a parent row still referenced by children, would violate the constraint.

Declarative enforcement in SQL

SQL lets designers declare referential actions that the database management system applies automatically when a referenced row is updated or deleted:

  • CASCADE — propagate the update/delete to referencing rows.
  • SET NULL / SET DEFAULT — replace the foreign key with null or a default value.
  • RESTRICT / NO ACTION — reject the operation if references exist.

Constraints may be checked immediately or deferred until the end of a transaction, which allows temporary inconsistencies within multi-step operations.

Importance

Referential integrity prevents "orphan" records — such as order lines pointing to a deleted customer — and is one of the integrity types in Codd's model of relational databases, alongside entity integrity and domain integrity.
