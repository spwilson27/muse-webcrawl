Referential transparency

Field: Programming language semantics, logic
Key figures: Willard Van Orman Quine, Christopher Strachey
Related: Pure functions, equational reasoning

Referential transparency is a property of a part of a program or expression: an expression is referentially transparent if it can be replaced by its value without changing the behaviour of the program. Conversely, an expression that cannot be so replaced is referentially opaque.

Definition

In a referentially transparent language, every expression denotes a value that depends only on the values of its subexpressions. Functions that always return the same result for the same arguments and produce no side effects are called pure functions; pure functional programming languages such as Haskell are referentially transparent by construction.

Origin of the term

The philosopher and logician Willard Van Orman Quine introduced the notion in discussing contexts in which substituting co-referential terms can change truth value — for example, in modal and propositional-attitude contexts. Christopher Strachey adopted the term in his influential 1967 lecture notes on fundamental concepts in programming languages.

Benefits

Referential transparency supports equational reasoning about programs, making them easier to understand, test and refactor. It also enables compiler optimisations such as common subexpression elimination, memoisation and safe parallelisation, because expressions can be evaluated in any order or reused without observable difference.
