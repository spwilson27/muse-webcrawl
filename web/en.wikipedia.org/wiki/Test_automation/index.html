Test automation

In software testing, test automation is the use of software separate from the software being tested to control the execution of tests and the comparison of actual outcomes with predicted outcomes. Test automation can automate repetitive but necessary tasks in a formalized testing process, or perform additional testing that would be difficult to do manually.

Approaches

Automated tests are commonly implemented at several levels, often described by the "test pyramid": numerous fast unit tests at the base, fewer integration or service tests, and a small number of end-to-end tests that exercise the graphical user interface. GUI testing frameworks such as Selenium, Playwright, and Cypress drive browsers and applications programmatically, while API-level tools test services directly.

Frameworks and practices

Common techniques include record-and-playback, data-driven testing, keyword-driven testing, and model-based testing. Automated suites are typically integrated into continuous integration pipelines so they run on every change, providing rapid regression feedback. Test automation code is itself software, and requires design and maintenance to avoid brittle, flaky tests.

Benefits and limitations

Automation improves repeatability, speed, and coverage of regression checks, but it cannot fully replace exploratory manual testing, and poorly chosen automation can impose high maintenance costs that outweigh its value.
