JSON Schema is a vocabulary that allows you to annotate and validate JSON documents. It describes the structure of JSON data — the types of values, required properties, formats, and constraints — enabling automated validation, documentation, and user-interface generation for data exchanged between systems. A JSON Schema is itself written in JSON.

Overview

A schema can specify, for example, that a value must be an object with a required string property name and an optional integer property age within a given range. Keywords such as type, properties, required, minimum, pattern, and format express constraints, while keywords like title and description provide documentation metadata. Schemas can be composed using references ($ref) and combinators such as allOf, anyOf, and oneOf.

History

JSON Schema originated around 2009–2010, with early drafts authored by Kris Zyp submitted to the IETF. Drafts 1 through 3 circulated informally; draft 4, published in 2013, became the long-standing de facto standard. Later versions moved versioning to date-based names: draft 2019-09 introduced vocabularies, and draft 2020-12 refined referencing with dynamic anchors. Although progress through the IETF standards track stalled, the specification is maintained by the JSON Schema organization and is extremely widely implemented.

Applications

JSON Schema is a core component of the OpenAPI specification for describing REST APIs, and is used for configuration-file validation, form generation, data-contract testing, and in tools such as IDEs that provide autocomplete and linting for JSON files. Validator libraries exist for virtually every programming language, including ajv for JavaScript and python-jsonschema.
