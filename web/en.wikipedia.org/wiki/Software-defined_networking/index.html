Software-defined networking

Software-defined networking (SDN) is an approach to network management that enables dynamic, programmatically efficient network configuration to improve network performance and monitoring. SDN is meant to improve the static architecture of traditional networks and can be employed to centralize network intelligence in one network component by disassociating the forwarding process of network packets (the data plane) from the routing process (the control plane). The control plane consists of one or more controllers, which are considered the brains of the SDN network, where the whole intelligence is incorporated.

Architecture

An SDN architecture has three layers:

  • Application layer — network applications (load balancing, security, monitoring) that communicate desired behaviour to the controller via northbound APIs.
  • Control layer — the logically centralized SDN controller, which maintains a global view of the network and translates application requirements into forwarding rules.
  • Infrastructure layer — the switches and routers that forward packets according to flow tables installed by the controller, communicating via southbound protocols such as OpenFlow.

History

SDN grew out of research at Stanford University in the mid-2000s, notably the Ethane project and the OpenFlow protocol (described in a 2008 paper by Nick McKeown and colleagues). The Open Networking Foundation was founded in 2011 by companies including Google, Microsoft, Facebook, Yahoo!, and Deutsche Telekom to standardize OpenFlow and promote SDN. Google's B4 wide-area network, publicly described in 2013, demonstrated SDN operating at global scale, driving links to near-full utilization. The approach has since been widely adopted in data centres, campus and enterprise networks, wide-area networks (SD-WAN), and 5G infrastructure.

Benefits and challenges

Advantages include centralized visibility and control, faster deployment of policies and services, vendor-neutral hardware ("white box" switches), and automation. Challenges include the controller as a potential single point of failure and attack target, scalability and consistency of distributed controllers, and the complexity of migrating legacy networks. Related technologies include network function virtualization (NFV) and intent-based networking.
