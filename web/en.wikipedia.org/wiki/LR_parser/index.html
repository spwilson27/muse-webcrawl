LR parser

An LR parser is a type of bottom-up parser for deterministic context-free languages, named for its method: it reads input from Left to right, and constructs a Rightmost derivation in reverse. LR parsers are driven by a finite-state control and a parse table, operate in linear time, and can detect a syntax error as soon as it is impossible for the input to continue into a valid sentence. They underlie parser generators such as yacc, Bison and many compiler front ends.

How it works

The parser maintains a stack of states and grammar symbols and an input buffer. At each step it consults the ACTION table for the current state and next input token: shift pushes the token and a new state onto the stack; reduce pops the symbols of the right-hand side of a production, pushes the left-hand-side nonterminal, and follows the GOTO table. Parsing succeeds when an accept action is reached for the end-of-input marker.

Variants

Variants differ in how much lookahead and context the table construction uses. LR(0) tables use no lookahead and handle only a small class of grammars. SLR (simple LR) improves on LR(0) using FOLLOW sets. LALR(1) merges LR(1) states with identical cores — this is the method yacc implements, balancing power with modest table size. Canonical LR(1), introduced in Donald Knuth's 1965 paper "On the translation of languages from left to right", is the most powerful and generates the largest tables; practical refinements include IELR and the GLR algorithm, which handles ambiguous grammars by forking the parse. The languages accepted by deterministic LR parsers (the DCFLs) properly include those handled by LL parsers, which is why LR methods dominate programming-language parsing where generated parsers are acceptable.
