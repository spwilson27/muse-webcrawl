Functional requirement

In requirements engineering, a functional requirement defines a function of a system or its component — what the system must do. A function is described as a specification of behaviour between outputs and inputs: given specified inputs or stimuli, the system must produce specified outputs or responses. Functional requirements form the core of a software requirements specification (SRS) and are typically captured as statements such as "the system shall allow a user to reset their password".

Characteristics

A typical functional requirement has a unique name or reference number, a brief summary, and a rationale, and describes behaviour in a way that can be verified by test, inspection, analysis or demonstration. Requirements are elicited from stakeholders during requirements analysis, often documented through use cases and user stories, and traced through design, implementation and testing. Good functional requirements are unambiguous, complete, consistent, and testable.

Contrast with non-functional requirements

Functional requirements state what the system does, whereas non-functional requirements state how well it must do it — qualities such as performance, security, reliability, scalability, and usability. Confusing the two categories is a common source of specification errors, since a missed functional requirement means missing behaviour, while a missed non-functional requirement may be discovered only when the system fails under real-world load or attack.
