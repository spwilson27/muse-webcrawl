Primary key

A table with a primary key uniquely identifying each row

In the relational model of databases, a primary key is a specific choice of a minimal set of attributes (columns) that uniquely specify a tuple (row) in a relation (table). Informally, a primary key is "which attributes identify a record," and in simple cases, a single attribute: for example, a student ID number.

Properties

More formally, a primary key is a choice of candidate key: a set of attributes that is (1) unique — no two distinct tuples may have the same values for the key attributes — and (2) irreducible — no proper subset of the attributes has the uniqueness property. In addition, a primary key may not contain null values. A table can have several candidate keys, of which one is designated the primary key; the others are called alternate keys.

Composite and surrogate keys

A primary key consisting of more than one attribute is a composite key. When a table lacks a satisfactory natural key, designers often introduce a surrogate key — an artificial attribute, such as an auto-incrementing integer or a UUID, which has no business meaning but serves purely as an identifier.

Role in relationships

Primary keys are the targets of foreign keys: a foreign key in another table references the primary key to establish relationships between records, and the database management system enforces referential integrity so that references cannot point to nonexistent rows. In SQL, a primary key is declared with the PRIMARY KEY constraint, either inline on a column or as a table-level constraint, and most database systems automatically create a unique index to support it.

Example

In a table Employees(EmployeeID, FirstName, LastName, DepartmentID), EmployeeID is a natural choice of primary key because each employee has a distinct ID, whereas names may repeat. Orders in another table can then store an EmployeeID foreign key to record which employee handled each order.
