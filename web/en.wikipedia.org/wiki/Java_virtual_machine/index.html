Java virtual machine

Diagram of the Java virtual machine architecture and class loading process

A Java virtual machine (JVM) is a virtual machine that enables a computer to run programs written in the Java programming language and other languages compiled to Java bytecode. The JVM interprets or compiles bytecode at runtime, providing platform independence summarized by the slogan "write once, run anywhere."

Overview

Java source code is compiled by a compiler such as javac into bytecode stored in .class files. At execution, the JVM's class loader loads and verifies the bytecode; the runtime then executes it through an interpreter and, for frequently executed ("hot") code, a just-in-time (JIT) compiler that translates bytecode into native machine instructions. The best-known implementation is HotSpot, distributed with OpenJDK and Oracle JDK; others include OpenJ9 and the ahead-of-time GraalVM.

Memory and garbage collection

The JVM manages memory automatically. Objects are allocated on the heap and reclaimed by a garbage collector, freeing programmers from manual memory management. Runtime data areas include the heap, method area, Java stacks, PC registers, and native method stacks. Collectors range from the throughput-oriented Parallel GC to low-latency collectors such as G1, ZGC, and Shenandoah.

Specification and languages

The JVM is defined by a formal specification, allowing many languages to target it, including Kotlin, Scala, Groovy, Clojure, and JRuby. Because the platform combines portability, a large library ecosystem, and mature tooling, the JVM remains widely used for enterprise servers, Android development (via the related Android Runtime), and big-data systems such as Hadoop and Spark.
