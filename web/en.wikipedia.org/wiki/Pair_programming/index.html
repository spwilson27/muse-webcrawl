Pair programming

Pair programming is an agile software development technique in which two programmers work together at one workstation. One, the driver, writes code while the other, the observer or navigator, reviews each line of code as it is typed in. The two programmers switch roles frequently.

While reviewing, the observer also considers the "big picture" direction of the work, coming up with ideas for improvements and likely future problems to address. This is intended to free the driver to focus all of their attention on the "tactical" aspects of completing the current task, using the observer as a safety net and guide.

History

Although pair programming has older informal antecedents, it was popularised as a core practice of Extreme Programming (XP) in the late 1990s, notably in Kent Beck's book Extreme Programming Explained (1999). It has since been adopted in various forms by agile teams, including remote pairing using screen-sharing and collaborative editors.

Benefits and costs

Studies and industry reports attribute to pair programming improved code quality and fewer defects, faster problem-solving on complex tasks, continuous knowledge transfer between team members, and better morale. Its costs include more person-hours per line of code in some measurements, though proponents argue that the reduction in defects and rework offset this, and that pairs often complete tasks faster in wall-clock time.

Variations

Common variations include ping-pong pairing, in which one partner writes a failing test and the other writes the code to pass it, and mob programming, which extends pairing to a whole team working on the same code at the same time.
