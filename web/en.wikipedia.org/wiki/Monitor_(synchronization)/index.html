Monitor (synchronization)

In concurrent programming, a monitor is a synchronization construct that prevents threads from concurrently accessing a shared resource, while allowing them to wait for changes in the state of the resource. A monitor consists of a mutex (lock) associated with a set of procedures and shared data, together with one or more condition variables on which threads can wait and be signalled. Only one thread may execute a monitor procedure at a time, guaranteeing mutual exclusion by construction.

History

The concept was developed in the early 1970s by Per Brinch Hansen and C. A. R. Hoare, drawing on earlier ideas by Edsger Dijkstra. Brinch Hansen implemented monitors in the Concurrent Pascal language, and Hoare's 1974 paper "Monitors: An Operating System Structuring Concept" gave the classic formal description. Hoare-style (signalling thread immediately hands over to the waiting thread) and Mesa-style (signal-and-continue) semantics differ in when a signalled thread resumes.

Condition variables

Condition variables support two operations:

  • wait — the calling thread releases the monitor lock and blocks until signalled; it must re-check its condition on waking, typically in a loop.
  • signal (notify) — wakes one waiting thread; broadcast (notifyAll) wakes all waiters.

Language support

Monitors are built into several languages: Java associates a monitor with every object and provides synchronized methods with wait/notify; C# offers lock and the Monitor class; POSIX threads and many other systems supply the equivalent primitives via mutexes and condition variables.
