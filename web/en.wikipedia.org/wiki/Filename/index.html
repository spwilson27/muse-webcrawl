A filename or file name is a name used to uniquely identify a computer file in a file system. Different file systems impose different restrictions on filename lengths and the characters allowed within filenames. A filename may include one or more of: the path (directory) in which the file resides, the base name, and an extension indicating the file's type or format.

Components and extensions

The filename extension, conventionally separated from the base name by a period (for example report.txt), historically indicated the file format. MS-DOS and early Windows used the 8.3 convention—eight characters plus a three-character extension. Modern systems allow long names with multiple periods; on Unix-like systems a leading dot marks hidden files, and extensions are a convention rather than a requirement.

Restrictions and portability

Windows forbids characters such as \ / : * ? " < > | and reserves device names like CON, AUX and NUL. Unix-like systems forbid only the slash and the null byte, and are case-sensitive, whereas Windows and classic Mac OS preserve but ignore case. Filenames may be encoded in Unicode, raising issues of normalisation that can affect portability between systems. Reserved-name and encoding mismatches are a frequent source of cross-platform file-transfer bugs.

History

Early operating systems restricted names severely—RT-11 and CP/M used short fixed formats—while timesharing systems such as Multics and Unix introduced hierarchical directories and increasingly permissive naming, culminating in today's 255-byte component limits on ext4, NTFS and APFS.
