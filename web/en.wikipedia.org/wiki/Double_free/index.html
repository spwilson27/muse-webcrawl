Double free

In computer programming, a double free is a memory corruption error that occurs when a program calls the memory deallocation function free() (or an equivalent) more than once on the same memory address. Double-freeing memory leads to undefined behaviour: it can corrupt the memory allocator's internal data structures, cause crashes, and create exploitable security vulnerabilities that allow an attacker to write arbitrary data to arbitrary memory locations.

Causes

Double frees commonly arise when two pointers alias the same heap allocation and both are freed, when an error-handling path frees memory that the caller also frees, or when memory is freed but the pointer is not cleared and is later reused. Setting pointers to NULL immediately after freeing them is a common defensive practice, since free(NULL) is defined to do nothing.

Exploitation

Modern heap allocators (such as glibc's ptmalloc) include consistency checks that detect many double frees and abort the program. Historically, however, double-free vulnerabilities were a reliable primitive for arbitrary code execution, and they remain classified among dangerous software weaknesses (CWE-415).

Prevention

Mitigations include clear ownership conventions for allocations, use of smart pointers and garbage collection, running code under memory error detectors such as AddressSanitizer or Valgrind, and static analysis tools that track allocation lifetimes.
