Composition over inheritance

Composition over inheritance (or composite reuse principle) is a principle in object-oriented programming that classes should achieve polymorphic behaviour and code reuse by containing instances of other classes that implement the desired functionality (composition) rather than by inheriting from a base or parent class.

Motivation

Deep inheritance hierarchies can become rigid and fragile: changes to a base class affect all subclasses (the fragile base class problem), and a subclass may be forced to inherit behaviour it does not need. Composition keeps components loosely coupled — an object delegates work to contained objects whose implementations can be swapped at runtime, for example through interface-based design and dependency injection.

History

The principle was popularised by the 1994 book Design Patterns by the "Gang of Four", whose introduction advises: "Favor object composition over class inheritance." It underlies many design patterns, such as Strategy, Decorator, and Adapter, and is reflected in the entity–component architectures used in game development.

Benefits and trade-offs

Benefits include greater flexibility, better encapsulation, and easier unit testing of individual components. Trade-offs include more boilerplate delegation code and a larger number of small classes; inheritance remains appropriate for stable "is-a" relationships within a controlled hierarchy.
