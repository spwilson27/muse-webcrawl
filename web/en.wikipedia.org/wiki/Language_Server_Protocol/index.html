Language Server Protocol

The Language Server Protocol (LSP) is an open, JSON-RPC-based protocol for use between a text editor or integrated development environment (IDE) and servers that provide "language intelligence" features: auto-completion, go-to-definition, find-all-references, hover information, diagnostics, renaming, formatting and similar functionality. It was designed and open-sourced by Microsoft and announced in June 2016, together with Red Hat and Codenvy.

Motivation

Before the LSP, each combination of a programming language and a development tool required a separate, bespoke integration: with M languages and N tools, up to M×N integrations were needed. The protocol replaces this with an M+N model: a language community maintains a single language server implementing the protocol, and each editor needs only a single generic LSP client.

Design

Communication between client and server uses JSON-RPC 2.0 messages, conventionally transported over stdio or a socket. After an initialize handshake in which the two sides exchange capabilities, the client sends notifications and requests as the user edits: for example textDocument/didOpen, textDocument/didChange, textDocument/completion, textDocument/hover and textDocument/definition. The server may publish diagnostics (errors and warnings) back to the client. Positions are given as zero-based line and character offsets in the document.

Adoption

The protocol originated in Visual Studio Code and was subsequently adopted by most major editors and IDEs, including Eclipse, Emacs, Vim and Neovim, Sublime Text, JetBrains IDEs, Atom and many others. Well-known language servers include TypeScript's tsserver-based implementations, the Eclipse JDT Language Server for Java, Microsoft's Pylance/Pyright for Python, rust-analyzer for Rust, clangd for C and C++, and gopls for Go. Extensions of the basic idea include the Debug Adapter Protocol (DAP), also pioneered by Microsoft, which standardizes debugger communication in the same style.
