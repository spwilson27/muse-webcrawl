Tail call

Tail call optimisation reuses the caller's stack frame for the final call

A tail call is a subroutine call performed as the final action of a procedure: the caller returns the result of the call directly, without any further computation. If the target of a tail call is the procedure itself, the call is a tail recursive call.

Tail call optimisation

Because nothing remains to be done after a tail call, the caller's stack frame need not be preserved. Tail call optimisation (also called tail call elimination) replaces the call with what amounts to a jump after moving the arguments, so that arbitrarily long chains of tail calls — including unbounded recursion — execute in constant stack space. In effect it turns recursion written in this style into iteration.

The Scheme programming language famously requires implementations to perform this optimisation ("proper tail recursion"), making tail calls a fundamental control structure in the language. Many functional languages, including Erlang, Elixir, and ML implementations, and compilers for languages such as C (as an optimisation opportunity) support it to varying degrees. The technique was analysed in influential papers by Guy L. Steele in the 1970s connecting procedure calls, jumps, and the treatment of functions as "the ultimate goto".
