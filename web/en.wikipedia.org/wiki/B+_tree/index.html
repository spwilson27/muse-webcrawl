A B+ tree is an n-ary tree with a variable but often large number of children per node. A B+ tree consists of a root, internal nodes and leaves. It is a self-balancing tree data structure that maintains sorted data and allows searches, sequential access, insertions, and deletions in logarithmic time. The B+ tree is a variant of the B-tree in which all data records are stored only in the leaf nodes, while internal nodes store only keys that guide the search.

Characteristics

In a B+ tree, internal nodes contain separator keys and pointers to child nodes, but no data. All records reside in the leaves, and the leaves are typically linked together in a linked list, which makes range queries and ordered sequential scans efficient. Because internal nodes hold only keys, more keys fit in each node, increasing the fan-out and reducing the height of the tree for a given number of records.

Uses

B+ trees are widely used for indexes in relational database systems — including MySQL's InnoDB storage engine, PostgreSQL, and Oracle — and in the metadata structures of many filesystems, such as NTFS, ext4 (for directory indexing), and XFS. Their shallow depth minimizes the number of disk accesses needed to locate a record, since each node can be sized to match a disk block.

Comparison with B-trees

Unlike a B-tree, in which every node may store data, the B+ tree stores data pointers only in leaves. This separation produces higher fan-out, uniform access paths (every search ends at a leaf), and efficient sequential traversal through the linked leaf level. The trade-off is that a search can never terminate early at an internal node.
