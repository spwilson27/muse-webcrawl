Software rot

Software rot (also software erosion, software decay, or bit rot in a looser sense) is the slow deterioration of software quality over time, or the growing mismatch between software and the environment in which it runs. Unlike physical objects, software does not wear out through use; instead it degrades through change — both changes made to it and changes in everything around it.

Active and dormant rot

Scholars distinguish two forms. Active rot occurs as software is repeatedly modified: each change, made under time pressure or by developers unfamiliar with the original design, erodes the architecture's integrity, accumulating technical debt. Dormant rot affects software that is left unchanged: operating systems, libraries, hardware, regulations, and user expectations evolve, so the untouched program gradually becomes obsolete, insecure, or incompatible — for example when an old application breaks on a new operating system release.

Causes

  • Accumulation of quick fixes and workarounds that violate the original design.
  • Loss of knowledge as original developers leave ("knowledge rot").
  • Outdated dependencies and unmaintained libraries with known vulnerabilities.
  • Documentation drifting out of sync with the code.
  • Environmental change: new platforms, protocols, security threats, and data volumes.

Mitigation

Common countermeasures include refactoring, automated regression tests, continuous integration, dependency updates, code review, and modular design with clear interfaces. Lehman's laws of software evolution state that a system must continually be adapted or it becomes progressively less satisfactory — a formal statement of the phenomenon software rot describes.
