Java Card

Java Card technology powers billions of SIM and payment cards

DeveloperSun Microsystems (now Oracle)
First released1996 (specification); late 1990s products
PlatformSmart cards and secure elements
LanguageA restricted subset of Java

Java Card is a software technology that allows Java-based applications (applets) to run securely on smart cards and other resource-constrained secure devices. Developed by Sun Microsystems and now maintained by Oracle, it is the dominant platform for programmable smart cards, used in SIM cards, bank cards, identity cards, passports and payment tokens; cumulative shipments number in the tens of billions.

Technology

A Java Card device contains a Java Card Runtime Environment (JCRE) implementing a subset of the Java language and virtual machine adapted to devices with very limited memory (historically a few kilobytes of RAM and tens of kilobytes of EEPROM/flash). Features unsupported on cards — such as dynamic class loading, threads, many primitive types (long, double, float), and garbage collection guarantees — are restricted or optional. Applications are compiled to bytecode, converted to the CAP (converted applet) format, verified off-card, and loaded onto the card, where an on-card bytecode verifier (in later versions) and a firewall between applet contexts enforce isolation so that multiple issuers' applications can co-reside securely.

Applications and communication

Cards communicate with terminals using APDU commands defined in ISO/IEC 7816, contactlessly via ISO/IEC 14443. Typical applications include GSM/UMTS SIM and USIM functions, EMV payment, logical and physical access control, digital signatures and e-government ID. The related GlobalPlatform specifications govern card content management and security domains.

Development

Developers write applets in Java using the Java Card Development Kit, test them in simulators, and deploy through card management systems. Java Card versions 2.x dominated the SIM market; version 3, in its "Connected" and later "Classic" editions, aligned the platform more closely with standard Java tooling while preserving the resource limits of secure elements.
