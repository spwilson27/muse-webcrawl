Call by name

FieldProgramming language semantics
CategoryEvaluation strategy / parameter passing
Notable languagesALGOL 60, Simula; related: Haskell (call by need)
Contrasts withCall by value, call by reference

In programming language theory, call by name is an evaluation strategy and parameter-passing mechanism in which an argument to a function is not evaluated before the function is called. Instead, the unevaluated argument expression is substituted directly into the function body (with care to avoid variable capture), so the expression is evaluated afresh every time the parameter is used inside the function — and not at all if the parameter is never used.

Implementation

Implementations traditionally pass each argument as a hidden parameterless procedure, a thunk, which is invoked whenever the formal parameter's value is needed. Because evaluation is repeated, an argument with side effects behaves differently under call by name than under call by value: it may execute its side effects zero, one, or many times.

Uses and consequences

Call by name allows functions to define new control structures: in ALGOL 60, where it was the default mechanism, programmers exploited it in tricks such as Jensen's device, where a parameter used both as a variable and within an index expression implements summation constructs. It also permits working with infinite data structures and avoids the cost of computing arguments that a branch never needs — an advantage akin to short-circuit evaluation. The disadvantages are unpredictable performance and confusing side effects, which led most later languages to prefer call by value or call by reference.

Call by need

A close relative is call by need (lazy evaluation), used in Haskell: arguments are still passed unevaluated, but the result of the first evaluation is memoised and shared, so each argument is computed at most once. Scala (by-name parameters) and various macro systems retain true call-by-name behaviour in restricted form.
