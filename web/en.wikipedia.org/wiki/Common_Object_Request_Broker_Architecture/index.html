Common Object Request Broker Architecture

The Common Object Request Broker Architecture (CORBA) is a standard defined by the Object Management Group (OMG) designed to facilitate the communication of systems that are deployed on diverse platforms. CORBA enables collaboration between systems on different operating systems, programming languages, and computing hardware, allowing software components written in multiple languages to work together as if they were a single application.

Overview

Objects in CORBA are described in the Interface Definition Language (IDL), from which language mappings generate client stubs and server skeletons. At runtime, an Object Request Broker (ORB) marshals method calls between clients and objects, locating implementations through naming and trading services. Inter-ORB communication uses the General Inter-ORB Protocol (GIOP), usually carried over TCP/IP as IIOP.

History

The first version of CORBA was released in 1991; CORBA 2.0 (1996) added interoperability between vendors' ORBs, and CORBA 3 added component models and quality-of-service features. CORBA saw wide use in the 1990s and early 2000s in telecommunications, finance, and defense systems, where its language neutrality and strong typing were valued.

Decline and legacy

CORBA was criticized for complexity, verbose APIs, firewall-unfriendly protocols, and slow, committee-driven standardization. From the 2000s it was largely displaced in new systems by web services, REST APIs, and later gRPC — though gRPC's IDL-based contracts and stubs owe a clear debt to CORBA's model. Large legacy CORBA installations remain in operation in telecom and enterprise systems.
