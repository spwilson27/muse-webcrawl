Priority inversion

Priority inversion is a scenario in scheduling in which a high-priority task is indirectly preempted by a lower-priority task, effectively inverting the relative priorities of the two tasks. It most commonly occurs when tasks share a resource protected by a lock or semaphore: a low-priority task holding the resource blocks a high-priority task that needs it, while medium-priority tasks that do not need the resource run ahead of both.

Example

Suppose task L (low priority) acquires a lock, then task H (high priority) preempts L and blocks trying to acquire the same lock. Task M (medium priority), which does not need the lock, then preempts L, so H waits not only for L but for all medium-priority work — an unbounded delay unless the scheduler or locking protocol intervenes.

Solutions

Common mitigations include priority inheritance, where the lock holder temporarily inherits the priority of the highest-priority waiter, and the priority ceiling protocol, where a lock is assigned a ceiling priority and a task holding it runs at that priority. Disabling preemption or interrupts while holding a lock is used in small kernels.

Mars Pathfinder

The best-known real-world incident occurred on the Mars Pathfinder mission in 1997. The spacecraft's information bus manager task was blocked by a low-priority meteorological task holding a mutual-exclusion lock, while medium-priority communications tasks ran; the resulting watchdog timeouts caused system resets. Engineers diagnosed the problem from Earth and enabled priority inheritance in the VxWorks mutex, fixing the resets.
