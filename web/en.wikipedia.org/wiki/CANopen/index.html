CANopen

Type: Higher-layer protocol for CAN
Standard: EN 50325-4 / CiA 301
Maintained by: CAN in Automation (CiA)
First released: 1995

CANopen is a communication protocol and device profile specification for embedded systems used in automation. In terms of the OSI model, CANopen implements the layers above and including the network layer. The CANopen standard consists of an addressing scheme, several small communication protocols and an application layer defined by device profiles. It is based on the Controller Area Network (CAN) bus and is standardized as EN 50325-4.

Overview

The basic CANopen device and communication profiles are given in the CiA 301 specification published by CAN in Automation (CiA). Profiles for specific classes of device — such as I/O modules, drives and motion controllers (CiA 402), encoders and hydraulic valves — build on this base. CANopen was developed from an internal project at Bosch and released to the market in 1995.

Communication model

CANopen devices exchange data as process data objects (PDOs), which carry time-critical real-time data, and service data objects (SDOs), which give access to the device's object dictionary — the structured list of all configurable parameters and process variables. Network management (NMT) services supervise device states (pre-operational, operational, stopped), while additional protocols provide synchronisation (SYNC), emergency notification (EMCY) and node monitoring via heartbeat messages.

Applications

CANopen is widely used in machine control, medical equipment (where the related CANopen-based profiles are common in patient tables and imaging systems), rail vehicles, maritime electronics, elevators and building automation. In the United States, a similar higher-layer protocol role is played by DeviceNet, while CANopen dominates in European markets.
