OpenMP

The fork–join model: a master thread spawns a team, then rejoins.
DeveloperOpenMP Architecture Review Board
Initial release1997 (Fortran), 1998 (C/C++)
TypeAPI for shared-memory parallel programming

OpenMP (Open Multi-Processing) is an application programming interface (API) that supports multi-platform shared-memory multiprocessing programming in C, C++ and Fortran, on most platforms and operating systems. It consists of compiler directives, library routines and environment variables that together implement a portable, scalable model for developing parallel applications, from laptops to supercomputers.

Model

OpenMP uses a fork–join model: a program begins as a single master thread, which forks a team of threads at parallel regions and joins them again afterwards. In C and C++, parallelism is requested through pragmas such as #pragma omp parallel for, which distributes the iterations of a loop among the team; clauses control data sharing (shared, private, reduction), scheduling and synchronisation. Because directives can be ignored by a non-OpenMP compiler, the same source remains a valid serial program.

History

The OpenMP Architecture Review Board (ARB) published the first specification, for Fortran, in October 1997; a C/C++ specification followed in 1998. Major milestones included tasking in version 3.0 (2008), SIMD and accelerator (device) offloading in 4.0 (2013), and metadirectives and improved device support in 5.x. Compilers supporting OpenMP include GCC, Clang/LLVM, Intel's compilers and Microsoft Visual C++.

Comparison

OpenMP targets shared-memory (including NUMA) machines and is frequently combined with MPI, which handles distributed-memory communication between nodes, in a hybrid model. For accelerators it competes and overlaps with OpenACC and with GPU-specific models such as CUDA.
