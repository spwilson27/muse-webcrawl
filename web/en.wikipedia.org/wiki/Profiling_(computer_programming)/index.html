Profiling (computer programming)

Flame graphs are a popular visualisation of profiling data.

In software engineering, profiling ("program profiling", "software profiling") is a form of dynamic program analysis that measures, for example, the space (memory) or time complexity of a program, the usage of particular instructions, or the frequency and duration of function calls. Most commonly, profiling information serves to aid program optimization, and more specifically, performance engineering.

Methods

Profiling is performed by tools called profilers (or code profilers), which use various techniques:

  • Instrumentation — the program is modified, by the compiler or at runtime, to add code that counts executions and times function calls. This gives precise counts but adds overhead.
  • Statistical sampling — the profiler periodically interrupts the program and records the call stack. Sampling has low overhead and gives an approximate picture of where time is spent.
  • Event-based tracing — events such as function entries, exits, cache misses or system calls are recorded, sometimes with the help of hardware performance counters.

Output

Profiler output traditionally includes a flat profile (how much time each function spends in itself and its descendants, as in the Unix tool gprof) and a call graph showing the relationships between callers and callees. Modern profilers commonly produce flame graphs, in which the width of each frame represents the proportion of samples in which a function appears.

Use

Profiling guides optimisation toward the parts of a program that actually dominate its running time or memory use — as the adage attributed to Donald Knuth warns, "premature optimization is the root of all evil." Profilers exist for nearly every platform and language, including perf on Linux, Instruments on macOS, and built-in profilers in runtimes such as the JVM, CPython and web browsers.
