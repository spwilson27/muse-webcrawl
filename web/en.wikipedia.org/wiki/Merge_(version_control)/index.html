Merge (version control)

In version control, merging (also called integration) is a fundamental operation that reconciles multiple changes made to a set of files under revision control. Merging is most often needed when files are modified on two or more independent branches and the changes must later be combined into a single revision.

Overview

A merge takes two (or more) sets of changes — often called the source and target branches — and produces a unified result. Version control systems such as Git, Mercurial, and Subversion attempt to perform merges automatically by comparing each branch against their common ancestor, a technique underlying the three-way merge.

Types of merge

  • Three-way merge: compares two modified versions against their common ancestor to determine which changes are unique to each side.
  • Two-way merge: compares two versions directly, without an ancestor; common in simple file-comparison tools.
  • Fast-forward merge: when the target branch has not diverged, the branch pointer is simply advanced.
  • Squash merge: combines all changes from a branch into a single commit.

Merge conflicts

A merge conflict occurs when the same part of a file is changed in incompatible ways on both branches, so the system cannot decide automatically which change to keep. The user must then resolve the conflict manually, editing the affected sections before completing the merge. Frequent, small merges and clear communication between developers reduce the likelihood of conflicts.
