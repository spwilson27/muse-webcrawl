Dimension (data warehouse)

In data warehousing, a dimension is a structure that categorizes facts and measures in order to enable users to answer business questions. Commonly used dimensions are people, products, places, and time (dates). In a data warehouse, dimensions provide structured labeling information to otherwise unordered numeric measures. A dimension is a dataset composed of individual, non-overlapping data elements.

Dimension tables

A dimension is implemented as a dimension table containing descriptive attributes (columns) in mostly textual form, referenced by a fact table through a foreign key. For example, a Date dimension may contain year, quarter, month, day-of-week and holiday flag attributes; a Product dimension may contain product name, brand, category, and department. Dimensional modelling, as popularised by Ralph Kimball, contrasts these wide, denormalised dimension tables with deep, numeric fact tables, typically arranged in a star schema.

Surrogate keys and slowly changing dimensions

Dimensions are usually keyed by a single-column surrogate key, an artificial integer unrelated to the operational source key, so that changes in source systems and in the dimension's own attributes can be handled. A slowly changing dimension describes how such changes are treated:

  • Type 1: overwrite the old value.
  • Type 2: add a new row with a new surrogate key, preserving history.
  • Type 3: add a column holding the previous value.

Common dimension types

  • Conformed dimensions shared consistently across multiple fact tables or data marts.
  • Degenerate dimensions whose key (e.g., an invoice number) lives in the fact table itself.
  • Role-playing dimensions used multiple times in one fact table (e.g., order date and ship date).
  • Junk dimensions grouping miscellaneous low-cardinality flags and indicators.
