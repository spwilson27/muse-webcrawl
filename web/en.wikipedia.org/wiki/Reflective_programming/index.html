Reflective programming

A reflective program examining and modifying its own structure at runtime

Reflective programming or reflection is the ability of a process to examine, introspect, and modify its own structure and behavior. In computer science, reflection is a foundational concept in many programming languages, allowing a program to treat its own code, types, and data structures as objects that can be inspected and manipulated at runtime.

History

The earliest example of reflection occurred in Lisp, where code and data share the same representation, and in the work of Brian Cantwell Smith, whose 1982 doctoral dissertation and the 3-Lisp language introduced the notion of reflective computational architectures. The concept was further developed in Smalltalk, where classes are themselves objects, and later in languages such as Java and C#, which provide dedicated reflection APIs.

Uses

Reflection enables introspection — observing the type or properties of an object at runtime — and intercession — altering the structure or behaviour of the program. Typical applications include serialization and deserialization, object-relational mapping, dependency injection frameworks, debuggers and profilers, generic pretty-printers, and the dynamic loading and invocation of methods whose names are only known at runtime.

Implementation

A language supports reflection to the degree that it maintains runtime metadata about its structures. Compiled languages such as Java and C# store type information in class files or assemblies, accessible through APIs such as java.lang.reflect. Interpreted and dynamic languages like Python and Ruby expose the interpreter's internal structures directly, making reflection pervasive. Reflection usually carries costs: it can defeat compiler optimizations, obscure program structure, and raise security concerns, since reflective access can bypass access-control mechanisms such as private members.
