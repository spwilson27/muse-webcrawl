Metaprogramming is a programming technique in which computer programs have the ability to treat other programs as their data. A metaprogram can read, generate, analyze, transform, or modify other programs — or itself — either at compile time or at run time. Metaprogramming underlies macros, templating systems, compilers, and much of modern framework design.

Approaches

Compile-time metaprogramming

Compile-time techniques include macro systems, from simple textual substitution in the C preprocessor to the hygienic macros of Scheme and the procedural macros of Rust; template metaprogramming in C++, where templates are Turing-complete and computations are carried out during compilation; and generic programming facilities in languages such as D and Nim that allow code to be generated from types and constant values.

Runtime metaprogramming

Dynamic languages often support reflection and introspection, letting programs inspect and modify their own objects, classes, and methods at runtime. Ruby's method_missing and open classes, Python's decorators and metaclasses, and JavaScript's Proxy objects are common examples. Lisp is historically notable for homoiconicity — code represented as ordinary data structures — which makes macro-based metaprogramming especially natural.

Benefits and drawbacks

Metaprogramming can eliminate boilerplate, build internal domain-specific languages, and shift work from run time to compile time, improving performance. Its costs are increased complexity, harder debugging and tooling, and the risk of code that is difficult for others to read or maintain.
