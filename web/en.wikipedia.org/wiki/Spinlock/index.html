Spinlock

In software engineering, a spinlock is a lock that causes a thread trying to acquire it to simply wait in a loop ("spin") while repeatedly checking whether the lock is available. Because the thread remains active but performs no useful work, spinlocks are a form of busy waiting. They avoid the overhead of operating-system process rescheduling, but waste processor time when the lock is held for long.

Implementation

A spinlock is typically implemented with an atomic test-and-set or compare-and-swap instruction: a thread atomically reads the lock's state, sets it to "held" if it was free, and retries in a tight loop otherwise. Naive implementations suffer under contention, because every spinning processor continually hammers the same memory location, generating bus or cache-coherence traffic. Optimisations include test-and-test-and-set (spin on a normal read until the lock looks free), exponential backoff, and ticket locks, which grant the lock in fair first-come-first-served order by having each waiter spin on its own ticket number.

Appropriate use

Spinlocks are efficient when threads are likely to be blocked for only short periods — shorter than the cost of a context switch — which is why they are common inside operating system kernels, especially on multiprocessors, where the holder may be running concurrently on another core. In user-space applications facing long or unpredictable waits, a mutex or semaphore that puts the waiter to sleep is usually preferred. On a single processor, a pure spinlock is dangerous: if the lock holder is preempted, the spinning thread can waste an entire scheduling quantum unless it yields, so uniprocessor kernels often simply disable preemption or interrupts instead. Priority inversion is another hazard if a low-priority holder is starved by spinning higher-priority waiters.
