Spaghetti code

TypeAnti-pattern / code smell
CharacteristicsUnstructured flow, heavy GOTO use, tangled dependencies
Related termsBig ball of mud, ravioli code, lasagna code

Spaghetti code is a pejorative phrase for unstructured and difficult-to-maintain source code. Such code has a complex, tangled control structure — resembling a bowl of spaghetti — typically resulting from undisciplined use of jumps such as GOTO statements, exceptions, threads, or other unstructured branching constructs.

History

The term appeared in computing literature by the 1970s. Edsger W. Dijkstra's 1968 letter "Go To Statement Considered Harmful" helped launch the structured programming movement that aimed to eliminate such tangles by restricting code to sequences, selection, and iteration. Languages with liberal GOTO facilities, such as early BASIC and Fortran, were especially prone to the style.

Causes and remedies

Spaghetti code commonly arises from deadline pressure, inexperienced developers, and repeated incremental changes to software without refactoring ("code rot"). Remedies include structured and modular design, code review, and refactoring into functions and modules. Related food metaphors include "ravioli code" (many small, loosely coupled objects) and "lasagna code" (excessive layering).
