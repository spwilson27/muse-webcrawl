JSON Web Token (JWT, often pronounced "jot") is a proposed Internet standard for creating data with optional signature and/or optional encryption whose payload holds JSON that asserts some number of claims. The tokens are signed either using a private secret or a public/private key pair. JWTs are an open, industry standard method (RFC 7519) for representing claims securely between two parties.

Structure

A JWT consists of three parts separated by dots: a header, a payload, and a signature. Each part is Base64URL-encoded. The header typically identifies the token type (JWT) and the signing algorithm (alg), such as HMAC SHA-256 (HS256) or RSA (RS256). The payload contains claims — statements about an entity (typically the user) and additional data — including registered claims such as iss (issuer), sub (subject), aud (audience), exp (expiration time), and iat (issued at). The signature is computed over the encoded header and payload using the specified algorithm and a secret or private key, allowing recipients to verify that the token was not altered.

Use cases

JWTs are widely used for authorization in web applications and APIs: after a user signs in, each subsequent request includes the JWT, allowing stateless authentication without server-side session storage. They are also used for secure information exchange, as the signature ensures the sender is who it claims to be and the content is intact. JWTs form part of the OAuth 2.0 and OpenID Connect ecosystems, where OpenID Connect ID tokens are JWTs.

Security considerations

Because tokens are typically only signed, not encrypted, sensitive data should not be placed in the payload, which anyone can decode. Implementations have suffered vulnerabilities from algorithm confusion (such as accepting alg: none or switching between asymmetric and symmetric verification), weak secrets, and failure to verify expiration. Best practice guidance is captured in RFC 8725, "JSON Web Token Best Current Practices."
