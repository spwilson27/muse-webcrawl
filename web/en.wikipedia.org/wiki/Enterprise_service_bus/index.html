Enterprise service bus

An enterprise service bus (ESB) implements a communication system between mutually interacting software applications in a service-oriented architecture (SOA). It is a software architecture for distributed computing, and is a special variant of the more general client–server model, wherein any application may behave as server or client. The ESB promotes agility and flexibility with regard to high-level protocol communication between applications, decoupling the applications from one another and from the details of message transport.

Function

The primary duties of an ESB are to:

  • Monitor and control routing of message exchange between services
  • Resolve contention between communicating service components
  • Control deployment and versioning of services
  • Marshal use of redundant services
  • Provide commodity services such as event handling, data transformation and mapping, message and event queuing and sequencing, security or exception handling, protocol conversion and enforcing proper quality of communication service

Rather than applications connecting point-to-point — which produces a brittle web of n×n interfaces as the number of systems grows — each application connects once to the bus. The bus performs content-based routing, transforms messages between the formats and protocols used by producers and consumers (for example between SOAP, REST, JMS and legacy formats), and applies mediation policies in transit.

History and criticism

The term was popularized in the early 2000s by analysts and middleware vendors, developing out of earlier message-oriented middleware and enterprise application integration (EAI) products. Commercial implementations included IBM WebSphere ESB, Oracle Service Bus, Microsoft BizTalk Server, Mule ESB and Apache ServiceMix. Critics have argued that the ESB can become a centralized bottleneck and an over-engineered "smart pipe" that embeds business logic in infrastructure; the rise of microservices architectures in the 2010s favoured lightweight API gateways and "smart endpoints and dumb pipes" instead. Nevertheless, ESB products remain widely deployed in large enterprises with complex legacy estates.
