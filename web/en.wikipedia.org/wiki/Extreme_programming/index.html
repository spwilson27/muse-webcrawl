Extreme programming

Extreme programming (XP) is a software development methodology intended to improve software quality and responsiveness to changing customer requirements. As a type of agile software development, it advocates frequent releases in short development cycles, intended to improve productivity and introduce checkpoints at which new customer requirements can be adopted.

Other elements of extreme programming include programming in pairs or doing extensive code review, unit testing of all code, not programming features until they are actually needed, a flat management structure, code simplicity and clarity, expecting changes in the customer's requirements as time passes and the problem is better understood, and frequent communication with the customer and among programmers. The methodology takes its name from the idea that the beneficial elements of traditional software engineering practices are taken to extreme levels.

History

Extreme programming was created by Kent Beck during his work on the Chrysler Comprehensive Compensation System (C3) payroll project. Beck became the C3 project leader in March 1996 and began refining the development methodology. In October 1999 he published Extreme Programming Explained. XP was one of several agile methodologies that influenced the Agile Manifesto of 2001, which Beck co-signed.

Practices

XP's core practices are commonly grouped into four areas: fine-scale feedback (pair programming, unit testing, test-driven development, the planning game), continuous process (continuous integration, small releases, refactoring, collective code ownership), shared understanding (coding standards, simple design, system metaphor), and programmer welfare (a sustainable, forty-hour pace). Its values are communication, simplicity, feedback, courage, and respect.

Criticism

Critics argue XP is difficult to scale, depends heavily on an on-site customer, can under-emphasize documentation and up-front design, and that some practices such as pair programming are costly. Nevertheless many XP practices, especially test-driven development and continuous integration, have been widely adopted independently.
