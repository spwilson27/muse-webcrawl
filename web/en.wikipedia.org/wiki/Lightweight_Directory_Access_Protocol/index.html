Lightweight Directory Access Protocol

LDAP
Port(s)389 (389/TCP/UDP), 636 (LDAPS)
StandardRFC 4510 series (LDAPv3)
First released1993

The Lightweight Directory Access Protocol (LDAP) is an open, vendor-neutral, industry-standard application protocol for accessing and maintaining distributed directory information services over an Internet Protocol (IP) network. It is commonly used for centralized authentication and for storing information about users, groups, and resources in organizations.

Overview

LDAP originated at the University of Michigan in the early 1990s as a lightweight front end to the X.500 directory access protocol, which required the heavy OSI protocol stack; LDAP instead runs directly over TCP/IP. The current version, LDAPv3, is specified in a series of RFCs beginning with RFC 4510.

An LDAP directory is organized as a tree of entries. Each entry is a collection of attributes and is identified by a distinguished name (DN), such as cn=John Doe,ou=People,dc=example,dc=com. The protocol defines operations to add, delete, modify, search, and compare entries, as well as to bind (authenticate) to the server. Searches use filters written in a prefix notation and can be scoped to a single entry, one level, or a whole subtree.

Security

LDAP sessions can be secured with Transport Layer Security (TLS), either through the StartTLS operation on the standard port 389 or through the separate LDAPS service on port 636. Authentication ranges from anonymous access and simple password binds to SASL mechanisms such as Kerberos (GSSAPI).

Implementations and use

Major implementations include OpenLDAP, Microsoft Active Directory, Red Hat Directory Server (389 Directory Server), and Apache Directory Server. LDAP is a standard building block of single sign-on and identity management systems, and many applications — email clients, VPNs, and web applications — consult LDAP directories for address books and login verification.
