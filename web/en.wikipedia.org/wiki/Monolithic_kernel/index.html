Monolithic kernel

A monolithic kernel is an operating system architecture where the entire operating system kernel runs in supervisor mode (kernel space) as a single program. Unlike a microkernel, in which core services are minimal and most functions run as user-space servers, a monolithic kernel provides the virtual machine abstractions — process management, memory management, device drivers, file systems, and networking — within the single kernel address space.

Advantages and disadvantages

Because services share one address space, communication between kernel subsystems is a simple and fast function call, avoiding the message-passing overhead of microkernel designs. The disadvantages are size and fault isolation: a bug in any driver can crash the whole system, and the kernel's large codebase can be harder to maintain and secure. Loadable kernel modules mitigate some of this by allowing functionality to be added or removed at runtime, leading to "modular monolithic" designs.

Examples

Classic Unix kernels, MS-DOS (with its TSRs and drivers), and the Linux kernel are prominent examples; Linux is monolithic but highly modular. The BSD kernels (FreeBSD, NetBSD, OpenBSD) are also broadly monolithic with modules. The design contrast between monolithic and microkernel architectures was the subject of the famous Tanenbaum–Torvalds debate of 1992, in which Andrew Tanenbaum argued Linux's monolithic design was a step backwards compared with MINIX's microkernel.
