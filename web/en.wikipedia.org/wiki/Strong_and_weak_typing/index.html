Strong and weak typing

Implicit conversions (weak typing) versus strict type enforcement (strong typing)

In computer programming, strong typing and weak typing are informal labels for how strictly a programming language enforces its type system. The terms have no universally agreed definition and are used in several overlapping ways; computer scientists often discourage them in favour of more precise properties, such as whether a language is type-safe, or whether it performs implicit conversions.

Meanings

A language is often called strongly typed if it prevents operations from being applied to values of the wrong type, and weakly typed if it freely converts between types. In JavaScript, for example, the expression "3" + 2 yields the string "32" by implicit conversion, a behaviour commonly cited as weak typing. In contrast, Python raises a TypeError when adding a string and an integer, and is usually described as strongly (but dynamically) typed.

Some authors instead equate "strong" with static typing and "weak" with dynamic typing, though these are separate axes: type checking may occur at compile time or run time regardless of strictness. Luca Cardelli's notion of type safety — that a language's abstract machine cannot perform an operation on data for which it is not intended — underlies many rigorous discussions.

Criticism of the terms

Because languages sit at many points along the spectrum — differing in implicit conversion, unchecked pointer arithmetic, unions, and coercion rules — many textbooks argue the strong/weak dichotomy is too vague to be useful, and recommend describing the specific behaviours instead.
