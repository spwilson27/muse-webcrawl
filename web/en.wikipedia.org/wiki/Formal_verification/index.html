Formal verification

In the context of hardware and software systems, formal verification is the act of proving or disproving the correctness of a system with respect to a certain formal specification or property, using formal methods of mathematics. Formal verification is a key incentive for formal specification of systems, and is at the core of building high-integrity systems, where correctness matters more than in consumer applications — for example in avionics, railway signalling, medical devices and cryptographic protocols.

The verification of a system involves constructing an abstract model of the system and a formal statement of the property to be checked, expressed in a logic such as temporal logic, then demonstrating mathematically that the model satisfies the property. Unlike testing, which samples only some behaviours, formal verification in principle covers all possible behaviours of the model — although it can only prove correctness relative to the model and specification, not to reality itself.

Approaches

  • Model checking: an algorithm automatically explores the state space of a finite-state model to check whether a temporal-logic property holds; if not, it produces a counterexample trace. Edmund Clarke, E. Allen Emerson and Joseph Sifakis received the 2007 Turing Award for this work.
  • Theorem proving: correctness is established with deductive proof, often assisted by interactive proof assistants such as Coq, Isabelle or Lean. This scales to infinite-state systems but requires human guidance.
  • Equivalence checking: used in hardware design to prove that two circuit descriptions (e.g. register-transfer level and gate level) behave identically.
  • Static analysis and abstract interpretation: over-approximate program behaviour to prove the absence of classes of runtime errors.

Notable verified systems

Landmark projects include the seL4 microkernel, whose functional correctness was machine-proved in Isabelle/HOL; the CompCert C compiler, verified in Coq; and floating-point hardware verification at Intel and AMD, spurred by the 1994 Pentium FDIV bug, which made model checking and equivalence checking standard in processor design flows.

Challenges

The main obstacles are state-space explosion, the effort of writing good specifications, and modelling gaps between the formal model and the implemented system. Industrial practice often applies formal verification selectively to the most critical components or properties.
