Modular programming

Modular programming
ParadigmSoftware design methodology
Key conceptsModules, interfaces, information hiding, separation of concerns
Influential worksParnas, "On the Criteria To Be Used in Decomposing Systems into Modules" (1972)

Modular programming is a software design technique that emphasizes separating the functionality of a program into independent, interchangeable modules, such that each contains everything necessary to execute only one aspect of the desired functionality. A module interface expresses the elements that are provided and required by the module; other modules can use its functionality without knowing its internal workings, a principle known as information hiding.

History

The idea of modularity in software emerged in the late 1960s as systems grew too large for monolithic designs. David Parnas's 1972 paper on decomposing systems into modules argued that modules should be defined around design decisions likely to change, rather than around steps of processing. Languages such as Modula and Modula-2 (designed by Niklaus Wirth), Ada, and later ML-family languages built module systems directly into the language, and the concept became a foundation of structured and object-oriented design.

Principles

Effective modular design seeks high cohesion within each module — its elements should serve a single purpose — and low coupling between modules, so that a change in one part of a system has limited impact elsewhere. Modules communicate through explicit, narrow interfaces, and their internal representations are hidden so implementations can be replaced without breaking clients. These properties make systems easier to understand, test, reuse and maintain, and allow teams to develop components in parallel.

Language support

Most modern programming languages provide some module mechanism: packages in Java and Go, modules in Python and JavaScript (ES modules), crates in Rust, assemblies in .NET, and header/source separation with libraries in C and C++. Operating-system-level modularity appears in dynamically linked libraries and in component and microservice architectures, which apply the same decomposition ideas at the scale of running services.
