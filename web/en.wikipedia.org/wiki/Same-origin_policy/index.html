Same-origin policy

In computing, the same-origin policy (SOP) is a fundamental security mechanism of the Web that restricts how a document or script loaded from one origin can interact with resources from another origin. A browser permits scripts contained in a first web page to access data in a second web page only if both pages have the same origin — defined as the combination of scheme (protocol), host (domain), and port of the URL. The policy prevents malicious scripts on one page from obtaining access to sensitive data on another page through that page's Document Object Model.

Under the same-origin policy, a script may freely access a same-origin document's DOM but is denied access to a cross-origin one.

History

The concept was introduced by Netscape Navigator 2.0 in 1995 alongside JavaScript, and was progressively extended to other browser features: XMLHttpRequest and fetch responses, cookies in some contexts, canvases, Web Storage, and more. The policy is specified today across the HTML and Fetch standards maintained by the WHATWG.

Definition of an origin

Two URLs are said to have the same origin if the protocol, port (defaulting by scheme), and host are the same for both. Thus http://example.com/page1 and http://example.com/page2 are same-origin, while https://example.com, http://sub.example.com, and http://example.com:8080 are all different origins from it. URLs with the file: scheme and opaque origins such as sandboxed iframes receive special treatment.

Relaxing the policy

Because legitimate applications often need controlled cross-origin communication, several standardized mechanisms relax the policy safely:

  • Cross-Origin Resource Sharing (CORS) — servers opt in via HTTP headers to allow cross-origin reads of responses.
  • window.postMessage — allows scripts from different origins to exchange messages explicitly.
  • JSONP — an older technique exploiting the fact that script tags may be loaded cross-origin (now largely superseded by CORS).
  • document.domain — a legacy mechanism allowing subdomains of a common parent domain to share an origin, now deprecated and disabled by default in modern browsers.

Security significance

The same-origin policy underpins much of web security: without it, a malicious site open in one tab could read a user's webmail or banking pages open in another. It is distinct from, but works together with, defenses against cross-site scripting (XSS) and cross-site request forgery (CSRF).
