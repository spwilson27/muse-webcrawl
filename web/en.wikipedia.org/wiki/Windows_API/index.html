Windows API

The Windows API, informally WinAPI, is the foundational application programming interface for Microsoft Windows operating systems. It allows user-written programs to interact with the operating system — creating windows and other user-interface elements, reading and writing files, using processes and threads, networking, and accessing devices — through a set of C-language functions implemented mainly in system dynamic-link libraries (DLLs) such as kernel32.dll, user32.dll and gdi32.dll.

History

The API began with the 16-bit Windows of the 1980s (retroactively called Win16), was expanded and modernised as Win32 with Windows NT and Windows 95, and grew a 64-bit variant with Windows XP Professional x64 Edition. A subset, Win32s, bridged 16-bit and 32-bit systems in the early 1990s. Later frameworks — MFC, .NET, and the Windows Runtime (WinRT) used by Universal Windows Platform apps — are built on top of, or alongside, the classic API rather than replacing it.

Organisation

The API is grouped by function: base services (files, processes, memory, registry), graphics device interface (GDI/GDI+) for drawing, user interface functions (windows, menus, controls, messages), common controls, the Windows shell, networking (Winsock, RPC), and security and identity APIs. Programs typically receive input through a message loop, dispatching window messages to a window procedure.

Compatibility and influence

Microsoft's emphasis on backward compatibility means that much of the Win32 API surface remains supported decades later, and the API has been reimplemented by open-source projects such as Wine and ReactOS to run Windows programs on other systems. Internally, user-mode API calls often map onto the undocumented Native API of the Windows NT kernel.
