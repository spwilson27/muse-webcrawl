Conceived byDouglas McIlroy; implemented by Ken Thompson (1973)

In Unix and Unix-like operating systems, a pipeline is a mechanism for inter-process communication in which the output (stdout) of one process is passed as the input (stdin) of the next, forming a chain of processes connected by pipes. In shell syntax, pipelines are written with the vertical bar character: ls -l | grep "key" | sort.

Concept

The pipeline is a central element of the Unix philosophy of writing small programs that do one thing well and work together through text streams. The idea was proposed by Douglas McIlroy in 1964 and implemented by Ken Thompson in 1973, who added the pipe system call and the shell's | notation to Unix. Data flows through the processes concurrently, with the kernel buffering a limited amount in each pipe.

Implementation

In POSIX systems, pipes are created with the pipe() system call, producing a pair of file descriptors. The shell forks each command in the pipeline and redirects its standard input and output accordingly, so all stages run in parallel. If a stage tries to write to a pipe whose reader has closed, it receives the SIGPIPE signal. Named pipes (FIFOs), created with mkfifo, allow unrelated processes to communicate through the file system.

Extensions

Shells provide related features such as process substitution, the tee command for splitting a stream, and capturing a pipeline's exit status. The pipeline concept influenced stream processing in many later systems and languages, including PowerShell's object pipelines and functional stream APIs.
