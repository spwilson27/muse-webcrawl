Type system

In computer programming, a type system is a logical system comprising a set of rules that assigns a property called a type (for example, integer, floating point, string) to every "term" — variables, expressions, functions and modules. Its main purpose is to reduce the possibility of bugs by defining interfaces between parts of a program and checking that the parts have been connected consistently; this checking can happen at compile time (static typing) or at run time (dynamic typing).

Overview

A type system formalises which operations may be performed on which values. When a program passes type checking it is said to be well-typed, and a language is type-safe if well-typed programs cannot "go wrong" in certain ways — Robin Milner's slogan was "well-typed programs cannot go wrong." Type systems range from the simple types of C to the sophisticated inference systems of ML and Haskell, which implement the Hindley–Milner algorithm and let programmers omit most type annotations.

Major dimensions

  • Static vs dynamic: whether checks occur at compile time or run time.
  • Strong vs weak: how strictly types are enforced versus implicitly converted (a spectrum with no universal definition).
  • Nominal vs structural: whether type compatibility is determined by declared names or by actual structure.
  • Inferred vs manifest: whether types are deduced automatically or must be written explicitly.
  • Advanced features: parametric polymorphism (generics), subtyping, dependent types, linear types and gradual typing.
