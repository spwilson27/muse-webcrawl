Fork (software development)

Fork
TypeSoftware development practice
Common inFree and open-source software
Related conceptsBranching, pull request, upstream

In software development, a fork occurs when developers take a copy of a project's source code and start independent development on it, creating a distinct and separate piece of software. The term most often implies not merely a technical branching, but a split in the developer community and in the direction of the project.

Forks in open-source software

Free and open-source software licences guarantee the right to fork, which acts as a check on project leadership: if contributors believe a project is mismanaged, they may take the code in a new direction. Well-known forks include LibreOffice, forked from OpenOffice.org in 2010; MariaDB, forked from MySQL; the illumos project from OpenSolaris; and numerous Linux distributions and BSD variants descended from common ancestors. Historical milestones of Unix itself, such as the BSD line, grew through what would now be called forks.

Forking on hosting platforms

On code-hosting services such as GitHub and GitLab, "fork" also has a narrower technical meaning: a personal server-side copy of a repository, from which a contributor can propose changes back to the original through a pull request. In this workflow, forking is routine and usually amicable, and most such forks never become independent projects.

Reasons and consequences

Forks arise from technical disagreements, licensing changes, governance disputes, commercial relicensing of previously open projects, or simple differences in goals. While forks can invigorate development and rescue abandoned software, they may also duplicate effort and fragment user communities; some forks later re-merge.
