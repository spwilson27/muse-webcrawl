Cross-site scripting

Cross-site scripting (XSS) is a type of security vulnerability that can be found in some web applications. XSS attacks enable attackers to inject client-side scripts into web pages viewed by other users. A cross-site scripting vulnerability may be used by attackers to bypass access controls such as the same-origin policy. XSS is among the most commonly reported web vulnerabilities and has figured in major incidents, including self-propagating worms on social networks.

Types

  • Stored (persistent) XSS — the malicious script is permanently stored on the target server, for example in a database or comment field, and delivered to victims who request the stored content.
  • Reflected (non-persistent) XSS — the script is reflected off the web server in an error message, search result or link, and executes when a victim follows a crafted URL.
  • DOM-based XSS — the vulnerability lies in client-side code that writes attacker-controlled data into the document object model.

Effects and prevention

Exploiting XSS, an attacker can steal session cookies, impersonate the victim, deface pages, redirect users or perform actions on the victim's behalf. Defences include validating and sanitising input, encoding output for the context in which it appears, using Content Security Policy headers, setting the HttpOnly flag on cookies, and employing framework-level auto-escaping.

Terminology

The term "cross-site scripting" was coined in the late 1990s; the abbreviation XSS (rather than CSS, which already meant Cascading Style Sheets) became standard in security writing.
