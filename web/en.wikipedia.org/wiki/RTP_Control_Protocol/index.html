RTP Control Protocol

The RTP Control Protocol (RTCP) is a binary-encoded out-of-band signaling protocol that functions alongside the Real-time Transport Protocol (RTP). Its basic functionality and packet structure is defined by RFC 3550. RTCP provides statistics and control information for an RTP session, periodically transmitting control packets to the participants in a streaming multimedia session.

Developer(s): IETF
Introduction: July 2003 (RFC 3550)
Supersedes: RFC 1889
OSI layer: Transport layer (via UDP)

Functions

The primary function of RTCP is to provide feedback on the quality of service (QoS) being provided by the distribution of data in a multimedia session. This feedback includes the number of packets lost, the highest sequence number received, round-trip delay estimates and interarrival jitter. Applications can use this information to adapt the encoding of the media being sent, for example by lowering the bit rate when packet loss increases.

RTCP also carries a persistent transport-level identifier for an RTP source called the canonical name (CNAME). Receivers use the CNAME to track participants across changes in the synchronization source (SSRC) identifier and to associate multiple data streams from a given participant in a set of related RTP sessions.

Packet types

RTCP defines several packet types, each identified by a packet type (PT) field:

  • Sender Report (SR), PT=200 — sent by participants that are actively sending data, containing transmission and reception statistics.
  • Receiver Report (RR), PT=201 — sent by participants that are not active senders, containing reception statistics.
  • Source Description (SDES), PT=202 — carries items such as the CNAME and optional name, email address, or location of participants.
  • Goodbye (BYE), PT=203 — indicates that one or more sources are no longer active.
  • Application-defined (APP), PT=204 — intended for experimental use as new applications and features are developed.

Bandwidth usage

The interval between RTCP packets is randomized and scaled so that RTCP typically consumes no more than five percent of the session bandwidth. This prevents control traffic from overwhelming the media traffic and allows sessions to scale to large numbers of participants.
