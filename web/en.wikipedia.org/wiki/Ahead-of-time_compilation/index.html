Ahead-of-time compilation

In computer science, ahead-of-time (AOT) compilation is the act of compiling a higher-level programming language, or an intermediate representation such as bytecode, into native machine code before the program is executed — typically at build time. AOT compilation contrasts with just-in-time (JIT) compilation, in which code is compiled during execution.

Advantages and trade-offs

AOT-compiled programs start faster, use less memory at runtime, and avoid the warm-up cost and unpredictability of a JIT compiler, which makes AOT attractive for embedded systems, mobile applications, and platforms that restrict runtime code generation. Because the compiler can spend more time optimising and can see the whole program, AOT can also apply aggressive whole-program optimisations. The disadvantages include losing runtime information that a JIT can exploit (such as actual profiling data and dynamic types), larger or platform-specific binaries, and reduced portability of the compiled artifact.

Examples

Traditional languages such as C and C++ are compiled ahead of time by design. Technologies that bring AOT to normally interpreted or bytecode-based environments include GraalVM Native Image for Java, .NET Native and NativeAOT for C#, and the Android Runtime (ART), which moved from JIT to AOT and later hybrid profiles. Angular's AOT compiler compiles HTML templates to TypeScript/JavaScript at build time.
