Sidecar (container pattern)

The sidecar pattern is a software design pattern used in containerised and microservice architectures, in which a helper component — the "sidecar" — is deployed alongside a primary application component, sharing its lifecycle, network namespace, and often its storage volumes. The name comes from a motorcycle sidecar, which is attached to and travels with the main vehicle.

Characteristics

A sidecar runs in its own process or container but is tightly coupled to the main application: it is created and destroyed with it and can communicate over localhost. Because the sidecar is separate from the application's code, it can be written in a different language and reused across services written in many languages.

Uses

Common sidecar functions include:

  • Service-mesh proxies (such as Envoy) handling networking, retries, and encryption
  • Logging and monitoring agents that collect and forward application output
  • Configuration synchronisation and secret fetching
  • Protocol translation and legacy integration

In Kubernetes, sidecar containers run within the same pod as the main container. The pattern is foundational to service mesh implementations such as Istio and Linkerd, where a proxy sidecar intercepts all traffic to and from the workload.
