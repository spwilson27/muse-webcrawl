Runtime system

In computer programming, a runtime system or runtime environment is a sub-system that exists both in the computer where a program is created and in the computer where it is intended to be run. The name comes from the compile time and runtime division in compiled languages, where "runtime" is a period when a program is running. A runtime system primarily implements portions of an execution model.

Most programming languages have some form of runtime system that provides an environment in which programs run. This environment may address a number of issues: application memory management, access to variables, mechanisms for passing parameters between procedures, interfacing with the operating system, and otherwise.

Overview

A runtime system creates an abstract layer that hides details of the processor and operating system on which a program runs. Features typically provided by a runtime system include loading application code into memory, executing instructions, allocating and managing memory (including garbage collection in managed languages), handling input/output, and providing a standard library of functions.

Every programming language has an associated runtime. In compiled languages such as C, the runtime is minimal—small startup code and a library. In interpreted and bytecode languages the runtime is much more substantial: the Java virtual machine and the .NET Common Language Runtime interpret or just-in-time compile bytecode, enforce type safety and sandboxing, and manage memory automatically.

Examples

  • The C runtime library (e.g. glibc, Microsoft's MSVCRT), providing startup code and functions such as malloc and printf.
  • The Java Runtime Environment (JRE), containing the Java virtual machine and class libraries.
  • The Common Language Runtime (CLR) of .NET Framework and modern .NET.
  • Node.js, which uses the V8 JavaScript engine plus libraries to provide a server-side JavaScript runtime.
  • The Erlang BEAM virtual machine, designed for fault-tolerant, concurrent telecom systems.
  • Web browsers, which act as runtimes for JavaScript, HTML and WebAssembly applications.

Features

Memory management

Many runtimes provide automatic memory management through garbage collection, relieving programmers of manual allocation errors, though at some cost in performance and predictability.

Exception handling and reflection

Richer runtimes support structured exception handling, reflection (the ability of a program to inspect and modify its own structure at runtime), dynamic loading of code, and concurrency primitives such as threads and event loops.
