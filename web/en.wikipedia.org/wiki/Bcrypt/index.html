DesignersNiels Provos, David Mazières
Published1999

Key featuresSalt, adaptive cost factor

bcrypt is a password-hashing function designed by Niels Provos and David Mazières, based on the Blowfish cipher, and presented at the USENIX Annual Technical Conference in 1999. Besides incorporating a salt to protect against rainbow table attacks, bcrypt is an adaptive function: over time, the iteration count can be increased to make it slower, so it remains resistant to brute-force search attacks even with increasing computation power.

Algorithm

bcrypt uses the EksBlowfish key setup, an expensive variant of the Blowfish key schedule that takes both a 128-bit salt and the password as inputs. The configured cost parameter determines how many iterations of the key expansion are performed (2 raised to the cost power). After the key schedule, the algorithm encrypts the 24-byte text "OrpheanBeholderScryDoubt" 64 times to produce the hash output. The standard output string encodes the cost, the salt and the hash in a custom base-64 alphabet in the form $2b$10$..., where the version identifier has evolved through $2a$, $2x$ and $2y$ variants.

Usage and limitations

bcrypt became the default password hash in OpenBSD and is widely available in libraries for most programming languages. It only uses the first 72 bytes of a password, a limitation that has led to workarounds and to the development of successor functions. Newer password hashing schemes such as scrypt and Argon2 were designed to be memory-hard as well as computationally expensive, offering greater resistance to GPU and ASIC attacks; nevertheless bcrypt remains widely deployed and accepted for password storage.
