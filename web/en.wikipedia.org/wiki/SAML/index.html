Security Assertion Markup Language (SAML, pronounced "SAM-el") is an open standard for exchanging authentication and authorization data between parties, in particular between an identity provider (IdP) and a service provider (SP). SAML is an XML-based markup language for security assertions — statements that service providers use to make access-control decisions. The standard is maintained by the Security Services Technical Committee of OASIS.

SAML's most important use case is web browser single sign-on (SSO), especially in enterprise and government environments, where a user authenticates once with an identity provider and then accesses many applications without re-entering credentials.

Overview

The SAML specification defines three roles. The principal (typically a user) requests a service; the service provider delivers it and relies on assertions; the identity provider authenticates the principal and issues assertions. Assertions are XML documents containing statements about authentication (when and how the subject authenticated), attributes (such as name, email, or group membership), and authorization decisions.

SAML separates the protocol machinery — request/response message formats and bindings to transport protocols such as HTTP Redirect and HTTP POST — from profiles, which combine assertions, protocols, and bindings to address specific use cases such as Web Browser SSO.

History

SAML 1.0 was adopted as an OASIS standard in November 2002, drawing on Netegrity's S2ML and Securant's AuthXML. SAML 1.1 followed in 2003. SAML 2.0, ratified in March 2005, merged SAML 1.1 with the Liberty Alliance's Identity Federation Framework (ID-FF) and the Shibboleth profile, adding features such as single logout, name identifier management, and pseudonymous identifiers. It remains widely deployed in enterprise federation, though newer systems often prefer the JSON- and OAuth-based OpenID Connect.

Security considerations

Assertions are typically digitally signed using XML Signature, and may be encrypted. Misconfigurations and implementation flaws — such as signature-wrapping attacks — have been the subject of significant security research, leading to hardened profiles and best-practice guidance.
