OpenAPI Specification

The OpenAPI Specification, previously known as the Swagger Specification, is a specification for a machine-readable interface description language for describing, producing, consuming, and visualising web services. It is a standard for describing HTTP-based APIs in JSON or YAML documents, allowing both humans and computers to discover and understand the capabilities of a service without access to its source code. The specification is maintained by the OpenAPI Initiative, a consortium under the Linux Foundation.

History

The specification began in 2010 as part of the Swagger framework developed by Tony Tam at Wordnik for describing its developer API. In 2015, SmartBear Software acquired the Swagger API project and, together with companies including Google, IBM, and Microsoft, formed the OpenAPI Initiative under the Linux Foundation; the specification was renamed from Swagger to OpenAPI. Version 3.0 was released in July 2017, adding support for callbacks, links, and richer request-body descriptions based on JSON Schema, and version 3.1 (2021) brought full alignment with JSON Schema 2020-12.

Structure

An OpenAPI document describes an API's paths and operations, parameters, request and response bodies, content types, security schemes, and reusable components such as schemas. Documents are commonly written in YAML:

openapi: 3.0.0
info:
  title: Example API
  version: 1.0.0
paths:
  /users:
    get:
      summary: List users
      responses:
        '200':
          description: OK

Tooling

A large ecosystem of tools consumes OpenAPI documents: Swagger UI renders interactive documentation in the browser; code generators produce client libraries and server stubs in many languages; and testing, mocking, and gateway products import definitions to validate requests and responses. Because the description is language-agnostic, it complements interface approaches such as GraphQL schemas and gRPC protocol buffers.
