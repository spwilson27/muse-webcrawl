Locality of reference

Locality of reference, also known as the principle of locality, is the tendency of a processor to access the same set of memory locations repetitively over a short period of time. There are two basic types of reference locality: temporal locality and spatial locality.

Programs tend to reuse data and instructions near those they have used recently.

Types

Temporal locality: if a memory location is referenced, it will tend to be referenced again soon. Examples include data in loops and subroutine calls. Spatial locality: if a memory location is referenced, nearby locations will tend to be referenced soon; this applies to sequential instruction execution and to traversing arrays. A third form, branch locality, arises because programs spend much of their time in a few core routines with many local branches.

Importance

Locality is one of the cornerstones of computer system design. It is the phenomenon that makes caching effective: a small, fast cache can serve most accesses because programs repeatedly touch a small working set. It also underlies virtual memory and the working-set model of Peter Denning, who introduced the concept in the 1960s, as well as disk prefetching, branch prediction, and the design of memory hierarchies generally.

Locality is closely related to pointer locality of reference, the phenomenon whereby processors tend to use memory addresses that are near one another, and to the observation that a small fraction of a program's code accounts for most of its execution time.

Exploiting locality

Programmers can improve performance by restructuring code and data layouts for better locality — for example, by using blocking (tiling) in matrix multiplication so that blocks of a matrix fit in cache, or by storing related data together. Poor locality, as in pointer-chasing through scattered linked structures, defeats caches and can dominate running time.
