Code review

Modern code review centres on the pull request

Discipline: Software engineering / quality assurance

Forms: Pull-request review, formal inspection, pair programming, over-the-shoulder

Code review (also referred to as peer code review) is the practice of systematically examining source code written by another developer, typically before it is merged into a shared codebase. It is one of the most widely used software quality practices, intended to find defects, improve readability and design, enforce standards, spread knowledge of the codebase across the team, and mentor less experienced developers.

History

The formal version of the practice, the software inspection, was described by Michael Fagan at IBM in the 1970s; Fagan inspections used planned meetings with defined roles (moderator, reader, recorder) and were shown to catch a high proportion of defects. With the spread of distributed version control and hosting platforms such as GitHub (founded 2008), a lighter-weight, asynchronous style of review built around the pull request became dominant: an author proposes changes, reviewers comment inline, automated checks (continuous integration) run, and the change is merged after approval.

Process and effectiveness

Research on modern code review indicates that reviewers find fewer defects than folklore suggests — many comments concern maintainability and design rather than outright bugs — but review also serves documentation, consensus-building and learning functions. Best practice generally includes keeping changes small, responding promptly, separating automated style checks (linters, formatters) from human judgement, and maintaining a constructive, non-adversarial tone. Related practices include pair programming, in which review is continuous, and static analysis tools, which automate the detection of certain defect classes.

Outcomes

Studies associate review coverage and participation with fewer post-release defects and better code quality. Poorly run review processes, conversely, can become bottlenecks that delay delivery, or rubber stamps that provide little value. Many organisations now also apply code review, sometimes with stricter rules, to security-sensitive changes and infrastructure-as-code.
