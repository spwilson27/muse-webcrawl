Debugger

[Image: Screenshot of a debugger paused at a breakpoint, showing source code and variable values]

A debugger is a computer program used to test and debug (find and fix errors in) other programs. A debugger runs the target program under controlled conditions, allowing the programmer to halt execution at chosen points (breakpoints), step through code line by line, and inspect or modify the values of variables, memory, and registers.

Features

Typical capabilities include setting breakpoints and watchpoints, single-stepping, viewing call stacks, evaluating expressions, examining core dumps after a crash, and reverse debugging (recording execution so it can be replayed backwards). Many debuggers are integrated into integrated development environments, while others, such as GDB (the GNU Debugger) and LLDB, are standalone tools often driven from the command line.

History

The term "bug" for a programming error predates electronic computers, and was popularised by the story of a moth found in a Harvard Mark II relay in 1947 by operators including Grace Hopper. Early debugging was done with print statements and dumps; interactive debuggers appeared with time-sharing systems in the 1960s and 1970s and became standard tooling with tools like dbx, Turbo Debugger, and the debuggers built into modern IDEs.

Anti-debugging

Malware and copy protection schemes often include anti-debugging techniques that detect an attached debugger and alter behaviour, because debuggers are also powerful tools for reverse engineering software.
