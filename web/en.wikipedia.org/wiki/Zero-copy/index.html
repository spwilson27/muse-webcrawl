Zero-copy

Zero-copy describes computer operations in which the CPU does not perform the task of copying data from one memory area to another, or in which unnecessary copies are avoided altogether. The term is most often used of input/output: when a program sends a file over a network, a naive implementation copies the data from the file buffer into kernel space, then into a user-space application buffer, then back into a kernel socket buffer. Zero-copy mechanisms eliminate the intermediate copies and context switches, reducing CPU usage and memory bandwidth and improving throughput — a decisive advantage for file servers, streaming systems and message brokers.

Techniques

Several mechanisms implement zero-copy transfer. Direct memory access (DMA) lets peripheral hardware read and write main memory without CPU involvement. Memory-mapped files (mmap) let the kernel and application share the same pages. On Linux, the sendfile() system call moves data from a file descriptor to a socket within the kernel; splice() and vmsplice() move data between pipes and sockets through page remapping, and copy_file_range() can offload copies to the filesystem or storage device. Some network interfaces support scatter-gather DMA, assembling packets from discontiguous buffers so headers can be prepended without copying the payload. RDMA (remote direct memory access) extends the idea across machines.

Software design

Beyond the operating system, zero-copy is a design principle in application code: passing references or views instead of duplicating buffers, using immutable data structures with shared storage, and laying out protocols so payloads need not be transformed. Message-queue systems such as Apache Kafka are built around the kernel page cache and sendfile, and Java's java.nio channels expose similar facilities.

Trade-offs

Zero-copy is not free: it can complicate buffer lifetime management, pin memory so it cannot be paged, interact awkwardly with data transformation (such as TLS encryption, though kernel TLS and NIC offload mitigate this), and yield little benefit for small transfers. Where the CPU must touch every byte anyway — compression, checksumming, encryption — copies may be unavoidable.
