Observer pattern

The observer pattern is a software design pattern in which an object, named the subject, maintains a list of its dependents, called observers, and notifies them automatically of any state changes, usually by calling one of their methods. It is one of the twenty-three classic patterns described by the "Gang of Four" in Design Patterns (1994), classified as a behavioral pattern.

Structure

The subject provides an interface for attaching and detaching observers. Each observer implements an update method which the subject calls when its state changes. The pattern promotes loose coupling: the subject knows only that observers implement a common interface. It is the basis of the publish–subscribe pattern, event listeners in graphical user interfaces, and the model–view–controller architecture, where views observe the model.

Considerations

Because notifications are typically issued in an unspecified order and observers may update the subject in turn, careless use can cause unexpected update cascades, memory leaks from observers that are never deregistered ("lapsed listener" problem), and difficulty in reasoning about program flow.
