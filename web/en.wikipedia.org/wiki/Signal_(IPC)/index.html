Signal (IPC)

A signal is a form of inter-process communication (IPC) in Unix and Unix-like operating systems: a limited, asynchronous notification sent to a process or thread to inform it of an event. Signals have been part of Unix since the 1970s and are standardised by POSIX.

Common signals

  • SIGHUP (1) — terminal hangup
  • SIGINT (2) — interrupt, typically Ctrl+C
  • SIGQUIT (3) — quit, typically Ctrl+\
  • SIGKILL (9) — forced termination; cannot be caught or ignored
  • SIGSEGV (11) — invalid memory reference (segmentation fault)
  • SIGTERM (15) — polite termination request; the default of the kill command
  • SIGSTOP / SIGCONT — suspend and resume a process

Handling

A process may set a signal handler, block signals, or accept the default action (termination, core dump, stop, or ignore). Sending a signal is done with the kill() system call or the kill command. Because handlers run asynchronously, only a restricted set of async-signal-safe functions may be called within them. Real-time signals (SIGRTMIN–SIGRTMAX) extend the standard set with queueing and user data.
