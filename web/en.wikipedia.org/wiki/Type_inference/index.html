Type inference

Type inference, sometimes called type reconstruction, is the ability of a compiler or interpreter to automatically deduce the type of an expression from its context, partly or fully, rather than requiring the programmer to annotate every declaration explicitly. It is a defining feature of the ML family of languages and is central to languages such as Haskell, OCaml, F#, Rust, and Scala, as well as appearing in more limited forms in C++ (auto), C# (var), Swift, and Kotlin.

Constraints gathered from how values are used are solved to assign types to every expression.

Hindley–Milner type system

The classic and most studied form of type inference is that of the Hindley–Milner (HM) type system, developed from work by J. Roger Hindley (1969) and Robin Milner (1978). HM supports parametric polymorphism: a function such as the identity can be given the type scheme ∀a. a → a, usable at any type. Milner's Algorithm W showed that a program's principal type — its most general type — can be computed by generating equations between type variables and solving them by unification, with the let-generalisation rule allowing polymorphic use of locally defined values. Luis Damas completed the formalisation in his 1982 thesis.

Because inference in HM is complete, programmers can omit nearly all annotations; typical code declares few or no types yet remains statically and strongly typed. However, unification errors can point to locations far from the actual mistake, and extensions such as subtyping, type classes with overlapping instances, higher-rank polymorphism, and mutable references complicate or restrict inference (the value restriction in ML is one famous compromise). Type inference for richer systems, such as full System F, is undecidable.

Local inference in mainstream languages

Many languages adopt only local inference: the type of a variable is deduced from its initialiser (var x = 5; in C#, auto in C++), while function parameters and return types must still be declared. Languages with global inference engines, by contrast, propagate constraints across function boundaries, letting entire programs be written without annotations.
