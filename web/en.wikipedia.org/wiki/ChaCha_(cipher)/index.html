ChaCha (cipher)

ChaCha is a family of stream ciphers designed by Daniel J. Bernstein and published in 2008. It is a refinement of Bernstein's earlier Salsa20 cipher, using the same basic principles but with a modified round function intended to increase diffusion per round and improve performance. The most widely used variant, ChaCha20, is specified in RFC 8439 and is used together with the Poly1305 message authentication code (ChaCha20-Poly1305) as an authenticated encryption scheme in protocols such as TLS 1.3 and WireGuard.

Design

ChaCha operates on a 512-bit state arranged as a 4×4 matrix of 32-bit words. The state consists of eight words of key material (for the 256-bit-key variant), four constant words derived from the ASCII string "expand 32-byte k", and words holding a block counter and a nonce.

The core operation is the quarter round, which updates four words of the state using only additions, XORs, and fixed rotations by 16, 12, 8, and 7 bits — operations collectively known as ARX. In each full round, quarter rounds are applied first to the columns of the matrix and then to its diagonals; this diagonal arrangement, which differs from Salsa20, improves diffusion. One "round" in ChaCha terminology consists of a column step and a diagonal step, so ChaCha20 performs 10 double rounds, or 20 quarter-round steps in total.

After all rounds, the original input state is added word-by-word to the final state, and the result is serialised as a 64-byte keystream block, which is XORed with the plaintext.

Variants

  • ChaCha20 — 20 rounds; the standardised and most widely deployed variant.
  • ChaCha12 and ChaCha8 — reduced-round variants offering higher speed with a smaller security margin.
  • XChaCha — a variant using a 192-bit nonce, constructed by hashing the key and part of the nonce with HChaCha to derive a subkey for ordinary ChaCha.

Adoption

ChaCha20-Poly1305 was standardised for TLS in RFC 7905 and is one of only three cipher suites permitted in TLS 1.3. Google adopted it for HTTPS connections from Chrome on Android devices, where AES hardware acceleration was commonly unavailable, because ChaCha runs efficiently in pure software. It is also the sole encryption primitive of the WireGuard VPN protocol, is used in OpenSSH (chacha20-poly1305@openssh.com), and serves as the basis of the arc4random family of random number functions in several operating systems. The BLAKE2 and BLAKE3 hash functions use a compression function modelled on the ChaCha round function.

Cryptanalysis

No practical attack against ChaCha20 is known. The best published attacks, using differential cryptanalysis techniques, reach only reduced-round versions (around 7 of the 20 rounds), leaving a large security margin.
