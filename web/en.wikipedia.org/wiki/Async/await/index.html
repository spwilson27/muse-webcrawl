Async/await

In computer programming, the async/await pattern is a syntactic feature of many programming languages that allows an asynchronous, non-blocking function to be structured in a way similar to an ordinary synchronous function. It is semantically related to the concept of a coroutine: async marks a function as able to pause, and await suspends its execution until an asynchronous operation completes, without blocking the calling thread.

History

Microsoft's F# pioneered asynchronous workflows, and the async/await keywords themselves were introduced in C# 5.0 with Visual Studio 2012, as an evolution of the Task-based Asynchronous Pattern. The feature was subsequently adopted by Python (3.5, 2015), JavaScript (ECMAScript 2017), TypeScript, Rust (stabilised in 2019), Swift (5.5, structured concurrency), Kotlin (coroutines library) and C++ (coroutines in C++20, with co_await).

How it works

A function declared with async returns a "future-like" object when called: a Task<T> in C#, a Promise in JavaScript, or a Future in Rust. Inside such a function, await applied to another future-like value checks whether the operation has finished: if it has, execution continues synchronously; if not, the function saves its state, returns control to the caller, and is resumed later by a state machine generated by the compiler once the awaited operation completes.

async function fetchUser(id) {
  const response = await fetch(`/users/${id}`);
  const data = await response.json();
  return data;
}

This allows asynchronous code — network requests, file I/O, timers — to be written in a direct, sequential style instead of nested callbacks (sometimes called "callback hell") or explicit promise chains.

Advantages and criticism

Advocates emphasise readability, natural exception handling with try/catch, and stack-friendly debugging. Critics note the "function colouring" problem: async functions can only be awaited from other async contexts, so the pattern tends to spread through a codebase; others point to hidden context-switching and the risk of deadlocks when blocking calls are mixed with awaits in environments with synchronisation contexts.
