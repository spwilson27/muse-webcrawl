Base64 is a group of binary-to-text encoding schemes that transforms binary data into a sequence of printable characters, limited to a set of 64 common characters. More specifically, the source binary data is taken 6 bits at a time, and each group is mapped to one of 64 characters from an alphabet consisting of the uppercase and lowercase Latin letters, the digits, and two additional symbols — typically + and /. Base64 is widely used to embed binary data, such as images and attachments, in text-based formats such as email, XML and JSON.

Encoding

The encoder processes the input in groups of three bytes (24 bits), producing four 6-bit values and hence four output characters — an expansion of about 33 percent. If the final group contains only one or two bytes, the output is completed with two or one = padding characters respectively. For example, the ASCII text "Man" encodes to TWFu, "Ma" to TWE=, and "M" to TQ==.

History and variants

Base64 originated in the Privacy-Enhanced Mail (PEM) standard and was adopted by MIME for encoding email attachments so that binary data could pass through mail systems designed for 7-bit ASCII text. RFC 4648 (2006) codified the scheme and its variants, including a URL- and filename-safe alphabet that replaces + and / with - and _. Other variants appear in Unix password files, UTF-7, and the "data:" URL scheme, which lets small files be embedded directly in web pages.

Applications

Base64 is used in email attachments, embedded images in HTML and CSS, basic access authentication headers, JSON Web Tokens, cryptographic certificates and keys distributed in PEM format, and countless APIs that move binary content through text channels. It is an encoding, not encryption: anyone can decode Base64 data, a point often misunderstood in security contexts.
