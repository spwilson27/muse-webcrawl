Return value optimization

Return value optimization (RVO) is a compiler optimization that involves eliminating the temporary object created to hold a function's return value. In C++, it is particularly notable for being allowed to change the observable behaviour of the resulting program — copy elision is one of the few optimizations permitted to produce side-effect differences (for example, skipping calls to copy constructors and destructors) even in strict standard-conforming mode.

Named return value optimization

Named return value optimization (NRVO) extends the idea to a named local variable that is returned by value: the compiler allocates the variable directly in the caller's storage for the return value, eliminating both the copy from the local to the return slot and the destruction of the local. RVO for unnamed temporaries has been effectively mandatory in many cases since C++17's guaranteed copy elision rules for prvalues; NRVO remains an optional (though widely implemented) optimization because it depends on all return paths returning the same named object.

std::string build() {
    std::string result = "data";  // NRVO: constructed in place
    return result;                // no copy or move needed
}

Interaction with move semantics

When neither RVO nor NRVO applies, returning a local variable is still treated as an implicit move in modern C++, falling back to the move constructor rather than the (potentially far more expensive) copy constructor.
