Stack frame

A stack frame (also called an activation record) is a region of the call stack that stores the data associated with a single invocation of a subroutine: its parameters, local variables, saved registers, the return address, and often a pointer to the caller's frame. Stack frames are created when a function is called and destroyed when it returns, which makes the call stack a natural structure for nested and recursive calls.

Structure

A typical frame, as on x86 with the cdecl calling convention, contains (from high to low addresses, since the stack usually grows downward): the arguments pushed by the caller, the return address pushed by the call instruction, the saved value of the caller's frame pointer (base pointer, EBP/RBP), and space for local variables and saved callee-saved registers. The stack pointer (ESP/RSP) marks the current top of the stack, while the frame pointer provides a stable base from which arguments and locals are reached at fixed offsets during the function's execution.

Function prologue and epilogue

On entry, a compiled function executes a prologue: it pushes the old frame pointer, copies the stack pointer into the frame pointer, and subtracts from the stack pointer to reserve space for locals. Variants such as the "leaf" functions may skip the frame pointer entirely, using the stack pointer directly. The epilogue reverses the process, restoring registers and the caller's frame before returning. Debuggers and stack traces walk the chain of linked frames (sometimes using separate unwind metadata when frame pointers are omitted, as in optimized 64-bit code) to reconstruct the sequence of calls.

Overhead and security

Frames make recursion and reentrancy straightforward but cost memory per call, so very deep recursion can overflow the stack. Because frames place control data (return addresses, saved frame pointers) adjacent to writable buffers, they are the classic target of stack buffer overflow exploits; mitigations include stack canaries, non-executable stacks, and address-space layout randomization.
