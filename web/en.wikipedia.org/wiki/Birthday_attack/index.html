Birthday attack

TypeCryptographic attack
ExploitsBirthday paradox (probability of collisions)
TargetHash functions, digital signatures
ComplexityRoughly 2n/2 for an n-bit hash

A birthday attack is a type of cryptographic attack that exploits the mathematics behind the birthday paradox in probability theory. The attack depends on the high likelihood of collisions found between random attack attempts and a fixed degree of permutations, as described by the pigeonhole principle.

Given a hash function f with n bits of output, an attacker would naively expect to try about 2n different inputs before finding two that produce the same output (a collision). The birthday paradox shows that only about 2n/2 inputs are needed before a collision becomes likely — the same reasoning by which only 23 randomly chosen people are needed for a better-than-even chance that two share a birthday, out of 365 possible days.

Mathematics

If a function produces H equally likely outputs, then after about 1.25√H distinct inputs there is roughly a 50% probability that two inputs produced the same output. For an n-bit hash, H = 2n, so the birthday bound is approximately 2n/2. Consequently, a hash function with 128 bits of output offers only about 64 bits of security against collision attacks.

Applications

Birthday attacks are used to find collisions in hash functions, which can undermine digital signatures: an attacker prepares many harmless and many malicious variants of a document, finds a pair with equal hashes, and gets the harmless one signed, after which the signature also validates the malicious version. The practical collision attacks against MD5 and later SHA-1 were extensions of this idea. The attack also applies to problems such as finding collisions in MACs and to the "birthday" bounds used in the design of block ciphers and protocols.

Countermeasures

The principal defence is to use output lengths large enough that 2n/2 work is infeasible: modern standards recommend hash functions with at least 256 bits of output where collision resistance matters. Salting, randomization of signed documents, and switching away from broken hash functions (such as MD5 and SHA-1) also mitigate the risk.
