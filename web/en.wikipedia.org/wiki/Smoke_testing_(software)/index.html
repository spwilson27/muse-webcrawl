Smoke testing (software)

Smoke tests as an early gate in a build pipeline

Smoke testing, also called build verification testing or confidence testing, is a type of software testing that comprises a small, non-exhaustive set of tests run on a new software build to determine whether its most crucial functions work before further, more detailed testing is performed. Its purpose is to reject a badly broken build quickly — the software analogue of powering up a hardware device and checking that it does not start smoking.

Overview

A smoke test checks the build's stability: does the application start, can users log in, do core flows such as saving a file or loading the main screen succeed? If a smoke test fails, the build is sent back to development without deeper QA effort. Smoke tests are typically run on every build, ideally automated as part of a continuous integration pipeline.

Origin of the term

The phrase comes from hardware testing, where a new device is turned on and checked for smoke; similar usage existed in plumbing (pumping smoke through pipes to find leaks). Microsoft popularised the term in software development in the 1990s and discussed it in works such as Lessons Learned in Software Testing.

Relation to sanity testing

Smoke testing is often contrasted with sanity testing: smoke tests are broad and shallow, checking that the build is stable enough to test at all; sanity tests are narrower and deeper, verifying that specific functionality works after a small change. Practice varies between organizations, and the terms are sometimes used interchangeably.
