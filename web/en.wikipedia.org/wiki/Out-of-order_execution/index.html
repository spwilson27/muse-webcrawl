Out-of-order execution

Instructions may complete in a different order than issued, but retire in order

In computer engineering, out-of-order execution (or dynamic execution) is a paradigm used in most high-performance central processing units to make use of instruction cycles that would otherwise be wasted. In this paradigm, a processor executes instructions in an order determined by the availability of input data and execution units, rather than by their original order in a program. In doing so, the processor can avoid being idle while waiting for preceding instructions to complete and can, in the meantime, process next instructions that are able to run immediately and independently.

History

Out-of-order execution was pioneered in the CDC 6600 (1964), which used a scoreboard to resolve conflicts, and in IBM's System/360 Model 91 (1967), which introduced Tomasulo's algorithm and register renaming. The technique became widespread in personal computing with processors such as the Intel Pentium Pro (1995).

Basic concept

An out-of-order processor typically divides instruction processing into issue and dispatch, execution, and in-order retirement (commit) through a reorder buffer, which preserves the illusion of sequential execution and supports precise exceptions. Register renaming eliminates false (write-after-read and write-after-write) dependencies so that only true data dependencies constrain scheduling. Reservation stations hold instructions until their operands and an execution unit are ready.

The added complexity comes with costs: more silicon area, higher power consumption, and — as shown by the Spectre vulnerabilities disclosed in 2018 — speculative and out-of-order execution can leak information through microarchitectural side channels.
