In computability theory and computational complexity theory, an undecidable problem is a decision problem for which it is proved to be impossible to construct an algorithm that always leads to a correct yes-or-no answer. The term was introduced in response to David Hilbert's Entscheidungsproblem ("decision problem").

The halting problem

The classic example is the halting problem: given a description of an arbitrary computer program and an input, determine whether the program will finish running or continue to run forever. In 1936 Alan Turing proved that no general algorithm can solve the halting problem for all program–input pairs, using a diagonal argument: any supposed halting decider can be turned against itself by a program that does the opposite of whatever the decider predicts.

Other undecidable problems

Many other problems have been shown undecidable, often by reduction from the halting problem: determining whether a program computes a given non-trivial property (Rice's theorem), the word problem for groups, Hilbert's tenth problem on Diophantine equations (resolved negatively in 1970), the Post correspondence problem, and whether a set of Wang tiles can tile the plane. A problem's undecidability does not mean every instance is unanswerable — it means no single algorithm answers all instances correctly.
