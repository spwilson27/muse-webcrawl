Dynamic linker

In computing, a dynamic linker is the part of an operating system that loads and links the shared libraries needed by an executable when it is executed (at "run-time"), by copying the content of libraries from persistent storage into RAM, filling jump tables and relocating pointers. It contrasts with a static linker, which performs linking at compile time.

Operation

When a dynamically linked program is started, the operating system loads the dynamic linker (specified, for example, in the ELF interpreter field, PT_INTERP, commonly ld.so on Unix-like systems). The linker then finds the required shared objects, maps them into memory, resolves symbol references, performs relocations, and runs library initializers before transferring control to the program.

Lazy binding, in which function addresses are resolved on first call through the Procedure Linkage Table (PLT) and Global Offset Table (GOT), reduces start-up time. Environment variables such as LD_LIBRARY_PATH and LD_PRELOAD influence library search paths and preloading on many systems, with security implications for setuid programs.

On Microsoft Windows, the equivalent functionality is provided by the loader in ntdll.dll resolving DLL imports at load time.
