Spiral model

The spiral model is a risk-driven software development process model that combines elements of iterative development with the systematic, controlled aspects of the waterfall model. It was described by Barry Boehm in his 1988 paper "A Spiral Model of Software Development and Enhancement". The model is represented as a spiral: each loop of the spiral represents a phase of the project, and the project cycles outward through the loops with increasing cost and scope.

Phases

Each circuit of the spiral passes through four quadrants:

  1. Determine objectives — identify the objectives, alternatives, and constraints for this iteration.
  2. Evaluate alternatives and resolve risks — analyse risks and reduce them, often by building prototypes.
  3. Develop and test — develop the product for this iteration using whatever specific model (waterfall, incremental, etc.) best fits the risk profile.
  4. Plan the next iteration — review the results with stakeholders and plan the next loop.

Characteristics

The defining feature of the spiral model is its explicit emphasis on risk analysis: risk assessment determines how much planning and prototyping each loop receives, so the model adapts its own rigour to the project's needs. An "anchor point milestone", such as a lifecycle objectives or lifecycle architecture review, closes each loop. The spiral model is best suited to large, complex, expensive projects where requirements cannot be fully specified in advance. Its flexibility has influenced later iterative and agile approaches, though critics note that it provides little concrete guidance on when a project should terminate its spirals.
