Treap

From Wikipedia, the free encyclopedia

A treap is a data structure that combines a binary search tree and a binary heap — the name is a portmanteau of tree and heap. It was introduced by Raimund Seidel and Cecilia R. Aragon in 1989. Each node stores a key and is assigned a random priority. The tree is ordered by key as in a binary search tree (an inorder traversal yields the keys in sorted order) and simultaneously heap-ordered by priority (each parent has higher priority — conventionally a smaller value — than its children).

Properties

For a given set of keys and priorities, the treap's shape is uniquely determined: it is exactly the tree obtained by inserting the keys one by one in decreasing order of priority into an ordinary binary search tree. Because the priorities are random, the expected height is O(log n), so searches, insertions, and deletions run in expected logarithmic time, without the explicit rebalancing machinery of AVL or red–black trees. A treap is also the same structure as a Cartesian tree built on the sequence of (key, priority) pairs.

Operations

Search proceeds as in any binary search tree. Insertion adds the new node as a leaf in search-tree position and then rotates it upward until heap order is restored. Deletion rotates the node downward — always toward its higher-priority child — until it becomes a leaf, then removes it. Two operations unique to treaps make many algorithms elegant:

  • Split: divide a treap into two treaps containing the keys less than and greater than a given key.
  • Merge (join): combine two treaps in which all keys of one precede all keys of the other.

Split and merge are each expected O(log n), and together they implement insert and delete, as well as set operations such as union, intersection, and difference in O(m log (n/m)) time.

Variants and applications

An implicit treap uses a node's position (index) as its key, maintained via subtree sizes, giving a sequence structure supporting splits and merges by position — insertions, deletions, and reversals of array segments in expected logarithmic time. Treaps are used in randomized algorithms courses as the simplest balanced-tree structure, in some standard libraries and databases, and as a basis for persistent (functional) balanced trees, since updates create only O(log n) new nodes along the modified path. A related structure, the randomized binary search tree of Martínez and Roura, has the same distribution of shapes.
