Wild pointer

Field: Computer programming

Related: Dangling pointer, use after free

A wild pointer is a pointer that has not been initialised prior to its first use. Such a pointer does not point to a valid object of the appropriate type; its value is whatever arbitrary bits happened to occupy its storage. Dereferencing a wild pointer produces undefined behavior and is a common source of crashes and security vulnerabilities in languages such as C and C++.

The term is closely related to the dangling pointer, which is a pointer that initially pointed to valid memory but whose target has since been deallocated. Both classes of bug arise from manual memory management without automatic checks.

Causes

int *p;   /* uninitialised: p is a wild pointer */
*p = 42;  /* undefined behavior */

Wild pointers typically arise when a pointer variable is declared but never assigned a value before use, when a function returns a pointer to a local variable, or when pointer arithmetic moves a pointer outside the bounds of any valid object.

Prevention

Mitigations include initialising pointers to null, setting pointers to null after freeing their targets, using smart pointers and references in C++, static analysis tools, and memory-safe languages such as Rust, which eliminate the class of error by construction.
