Formal methods

Formal methods
FieldComputer science, software engineering
TechniquesFormal specification, model checking, theorem proving, formal verification
Notable languagesZ, VDM, TLA+, Alloy, Dafny

In computer science, formal methods are mathematically rigorous techniques for the specification, development, analysis and verification of software and hardware systems. The approach uses formal specification languages to describe a system's desired properties precisely, and automated or semi-automated reasoning tools — model checkers and theorem provers — to prove that a design or implementation satisfies its specification.

Approaches

Formal specification notations include model-based languages such as Z and VDM, algebraic and process-algebraic notations, and temporal-logic-based languages such as TLA+. Verification techniques range from exhaustive model checking of finite-state models, through interactive theorem proving in assistants such as Coq and Isabelle, to static analysis and abstract interpretation, which are sometimes called "lightweight" formal methods.

Use in industry

Formal methods are applied where failure is costly or dangerous: avionics and railway signalling (for example the driverless Paris Métro Line 14, developed with the B method), microprocessor design (notably after the Pentium FDIV bug), smart-card security, cryptographic protocols, and compiler verification such as the CompCert C compiler and the seL4 microkernel, both fully verified. Organisations including NASA, Amazon Web Services and major chip manufacturers use formal tools for selected critical components, though full verification of large systems remains expensive and labour-intensive.

Criticism and limitations

Critics note the cost, specialist expertise required, and the risk that a proof validates a specification rather than real-world intent. Proponents respond that targeted, lightweight use of formal methods finds deep design errors that testing alone rarely exposes.
