Elliptic-curve Diffie–Hellman

From Wikipedia, the free encyclopedia

Elliptic-curve Diffie–Hellman (ECDH) is a key agreement protocol that allows two parties, each having an elliptic-curve public–private key pair, to establish a shared secret over an insecure channel. It is a variant of the Diffie–Hellman protocol using elliptic-curve cryptography.

Key establishment protocol

The parties agree on a domain parameter set for an elliptic curve (such as Curve25519 or the NIST P-256 curve). Each party generates a private scalar d and a public key point Q = dG, where G is the curve's base point. After exchanging public keys, each party computes the point dAQB = dBQA; the x-coordinate of this shared point is typically hashed to derive a symmetric session key, for example for use with AES.

Security

The security of ECDH rests on the elliptic-curve discrete logarithm problem: given G and Q = dG, recovering d is computationally infeasible for properly chosen curves. Because elliptic curves offer equivalent security to RSA or finite-field Diffie–Hellman at much smaller key sizes — a 256-bit elliptic-curve key is roughly comparable to a 3072-bit RSA key — ECDH is widely used in protocols such as TLS 1.3, Signal and WireGuard.

Ephemeral and static variants

When both parties generate fresh key pairs for each session, the scheme is called ephemeral ECDH (ECDHE) and provides forward secrecy: compromise of long-term keys does not reveal past session keys. TLS 1.3 mandates ephemeral key exchange. Static ECDH, in which one or both keys are long-term, lacks this property.

Attacks and validation

Implementations must validate received public keys to prevent invalid-curve attacks, in which an attacker supplies a point on a weak curve to leak information about the victim's private key. Protocols such as X25519 are designed to make such validation checks largely unnecessary.
