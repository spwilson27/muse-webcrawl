Cluster manager

From Wikipedia, the free encyclopedia

A cluster manager coordinates workloads and resources across a group of machines.

A cluster manager is software that manages a computer cluster—a set of linked computers that work together so that, in many respects, they can be viewed as a single system. Cluster managers allocate workloads to nodes, monitor node health, restart or migrate failed work, and present the pool of machines as a coherent resource to users and applications.

Functions

  • Scheduling: deciding which node runs each job or service, subject to CPU, memory, and placement constraints.
  • Resource management: tracking capacity, enforcing quotas, and balancing load.
  • Health monitoring and failover: detecting node or process failure (often via heartbeats) and rescheduling work elsewhere.
  • Service discovery and configuration: keeping track of where services run and how to reach them.
  • Scaling: adding or removing replicas to match demand.

Examples

In high-performance computing, batch-oriented cluster managers and job schedulers such as Slurm, PBS, and HTCondor dominate. For containerized workloads, Kubernetes, Apache Mesos, and Docker Swarm act as cluster managers for containers. High-availability clusters use managers such as Pacemaker and Corosync to keep services running through hardware failures, while cluster file systems and databases use their own coordination layers (for example ZooKeeper or etcd) for consensus.

Design issues

Cluster managers must solve hard distributed-systems problems: reaching consensus about cluster state, avoiding split-brain scenarios in which partitioned nodes act independently, fencing failed nodes so they cannot corrupt shared state, and making scheduling decisions quickly at scale. Many designs separate a control plane (decision-making) from a data plane (the workloads themselves).
