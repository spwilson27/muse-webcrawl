Control-flow graph

A control-flow graph (CFG) is a representation, using graph notation, of all paths that might be traversed through a program during its execution. The control-flow graph was discovered by Frances E. Allen, who noted that Reese T. Prosser used boolean connectivity matrices for flow analysis before. The CFG is essential to many compiler optimizations and static-analysis tools.

Definition

In a control-flow graph each node represents a basic block — a straight-line sequence of code with a single entry point and a single exit point, containing no jumps into or out of its interior. Directed edges represent jumps in control flow: conditional branches produce two outgoing edges, unconditional jumps one, and calls and returns connect blocks to and from subroutines. Special blocks, the entry block and exit block, anchor the graph.

Applications

Compilers build CFGs to perform data-flow analysis, which underpins optimizations such as constant propagation, dead-code elimination, common subexpression elimination and register allocation. Dominator trees derived from the CFG are used to construct static single assignment (SSA) form. Software testing uses CFGs to measure structural coverage, and security researchers use them to analyse program behaviour and detect malware.

Related representations include the call graph, which connects procedures rather than blocks, and the program dependence graph, which adds data-dependence edges.
