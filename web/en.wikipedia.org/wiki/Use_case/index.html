Use case

A use case is a list of actions or event steps typically defining the interactions between a role (known in the Unified Modeling Language as an actor) and a system to achieve a goal. The actor can be a human or another external system. In systems engineering and software engineering, use cases are a central technique for capturing functional requirements.

History

In 1986, Ivar Jacobson first formulated the concept of use cases while working at Ericsson; the idea was incorporated into the Objectory method and later into UML. Alistair Cockburn's book Writing Effective Use Cases (2000) popularised a structured textual template and popular usage. The Unified Process made use cases the primary artefact driving analysis, design, implementation and testing — an approach known as use case driven development.

Structure

A fully dressed use case typically contains:

  • Title and goal — the objective the primary actor wants to achieve.
  • Primary actor and other stakeholders with their interests.
  • Preconditions and postconditions (success guarantees).
  • Main success scenario — the step-by-step "happy path" of interactions.
  • Extensions — alternative flows and exception handling for each step.

Cockburn distinguished levels of detail, from brief one-paragraph summaries to casual and fully dressed forms, and goal levels ("sea level" user goals versus sub-function and summary goals).

Use case diagrams

In UML, a use case diagram shows actors as stick figures outside a system boundary, use cases as ellipses inside it, and relationships including include, extend and generalisation. Diagrams give an overview, but the essential content is generally considered to be the textual flows.

Relationship to user stories

In agile software development, the lighter-weight user story often serves a similar purpose. Use cases describe interactions in more detail and are frequently used where documentation of system behaviour, rather than conversational planning, is the priority.
