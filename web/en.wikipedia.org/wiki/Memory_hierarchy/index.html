Memory hierarchy

In computer architecture, the memory hierarchy is the organisation of storage in a computer system into levels with different speeds, costs and capacities. Because fast memory is expensive per bit and slow memory is cheap, systems use small amounts of fast memory close to the processor (cache) backed by progressively larger, slower levels — main memory (RAM) and secondary storage (SSDs and hard disks). Programs perform well on this hierarchy because of locality of reference: recently used and nearby data are likely to be needed again.

Memory hierarchy

The memory hierarchy pyramid

Levels: registers → cache → RAM → SSD/HDD → archival
Principle: locality of reference

Levels

  • Registers — inside the CPU; a few dozen to a few hundred words; access in a fraction of a cycle.
  • Cache (L1, L2, L3) — SRAM; kilobytes to tens of megabytes; access in ~1–40 cycles. L1 is split into instruction and data caches.
  • Main memory — DRAM; gigabytes; access in ~100 cycles (~100 ns).
  • Secondary storage — SSDs (microseconds) and magnetic disks (milliseconds); hundreds of gigabytes to terabytes.
  • Tertiary/offline storage — tape and optical archives for rarely accessed data.

Why it works

Cache performance depends on hit rates, which are high in practice because programs exhibit temporal locality (reusing data soon) and spatial locality (using nearby addresses). Hardware prefetching and compiler optimisations exploit these patterns. The growing gap between processor speed and memory speed — the "memory wall" — has made cache behaviour one of the dominant concerns in software performance engineering.
