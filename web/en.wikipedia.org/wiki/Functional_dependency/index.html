Functional dependency

In relational database theory, a functional dependency is a constraint between two sets of attributes in a relation. If attribute set X determines attribute set Y — meaning that whenever two tuples agree on X they must also agree on Y — we write X → Y and say Y is functionally dependent on X.

Concepts

Functional dependencies generalize the notion of a key: if X is a candidate key, then X functionally determines every attribute of the relation. A dependency is trivial if Y is a subset of X. Armstrong's axioms (reflexivity, augmentation and transitivity) provide a sound and complete system for deriving all dependencies implied by a given set, and the closure of an attribute set under a set of dependencies can be computed algorithmically.

Role in normalization

Functional dependencies are the basis of database normalization: normal forms such as second, third and Boyce–Codd normal form are defined by ruling out undesirable dependency patterns that cause redundancy and update anomalies. Dependencies arising from the real-world meaning of the data are specified by the database designer, not discovered from sample data alone.
