Inverted index

From Wikipedia, the free encyclopedia


An inverted index maps terms to the documents containing them

An inverted index (also referred to as a postings file or inverted file) is a database index storing a mapping from content — such as words or numbers — to its locations in a set of documents. It is the core data structure of full-text search engines and information retrieval systems: whereas a forward index lists, for each document, the words it contains, an inverted index lists, for each word, the documents (and often the positions) in which it occurs.

Structure

The index consists of a dictionary (or lexicon) of terms and, for each term, a postings list of document identifiers, usually stored in increasing order so that set operations needed to answer Boolean queries — intersection and union — can be performed efficiently by merging lists. Postings may also record term frequency and the positions of the term within each document, enabling phrase and proximity queries. Indexes are typically compressed (for example with variable-byte or frame-of-reference encodings) because they can be comparable in size to the text itself.

Construction and use

Documents are tokenised, normalised (case folding, stop-word removal, stemming) and each term occurrence is recorded; the resulting postings are sorted and merged. Block-based and distributed algorithms allow indexes of web scale to be built across clusters. At query time the engine retrieves the postings for the query terms, scores candidate documents — commonly with TF–IDF or BM25 weighting — and returns the top-ranked results; early-termination and caching techniques keep latency low.

Inverted indexes are implemented in systems such as Apache Lucene (and the Elasticsearch and Solr platforms built on it), and historically underpinned early web search engines. Variants include the inverted lists used by database systems for full-text columns and indexes over structured fields such as dates or categories.
