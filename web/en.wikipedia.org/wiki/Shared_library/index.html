Shared library

In computing, a shared library (or shared object) is a file containing machine code that can be loaded and used by multiple programs at run time, rather than being copied into each program at compile time as with a static library. Shared libraries are the foundation of dynamic linking on modern operating systems.

How it works

A shared library is compiled as position-independent code and stored in a standard file — .so files on Linux and other Unix-like systems, .dll (dynamic-link library) files on Windows, and .dylib files on macOS. When a program starts, the operating system's dynamic loader maps the library into the process's address space and resolves its symbols. Because the code pages are shared between processes, memory usage is reduced and a library can be updated once to benefit all its users.

Advantages and drawbacks

Shared libraries save disk space and RAM, allow security fixes to be deployed centrally, and let programs use common system services uniformly. Their drawbacks include dependency management problems — famously "DLL hell" on Windows — version incompatibilities when an updated library breaks older programs, and a small run-time overhead for dynamic symbol resolution and position-independent code. Techniques such as symbol versioning, the soname convention on Linux, and prelinking mitigate these issues.
