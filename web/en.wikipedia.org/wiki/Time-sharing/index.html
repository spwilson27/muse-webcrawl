Time-sharing

Time-sharing

In computing, time-sharing is the concurrent sharing of a single computer's resources among many users by means of multiprogramming and multitasking. Because the computer switches rapidly between users' jobs, each user, working at an interactive terminal, has the illusion of having the machine to themselves. Time-sharing evolved in the late 1950s and 1960s as a way to make efficient use of extremely expensive mainframe computers and to allow interactive, rather than batch, computing.

History

The idea was championed by Christopher Strachey and by John McCarthy, whose 1959 memorandum at MIT set out the concept. One of the first working systems was MIT's CTSS (Compatible Time-Sharing System), demonstrated in 1961. Other landmark systems followed: the Dartmouth Time-Sharing System (DTSS), which brought BASIC to undergraduates, and Multics, the ambitious MIT/GE/Bell Labs project whose ideas — hierarchical file systems, dynamic linking, security rings — profoundly influenced Unix.

How it works

A time-sharing operating system allocates each active job short slices of processor time in rotation, switching so quickly that interactive response appears continuous. Memory protection keeps users' programs from interfering with one another, and virtual memory lets the machine serve more users than could fit in physical memory at once. Users connect through terminals — originally teletypes and later video displays — over local lines or telephone networks.

Impact

Time-sharing transformed computing from a priesthood of batch job submission into an interactive activity, enabling early computer networks, electronic mail, and online communities. Commercial time-sharing bureaus sold access by the hour in the 1960s and 1970s. The personal computer revolution of the 1980s made shared mainframes seem obsolete, but the model returned in force with client–server computing and, later, cloud computing, which is in essence time-sharing on a planetary scale.
