NX bit

The NX bit (no-execute bit) is a technology used in CPUs to segregate areas of memory for use by either storage of processor instructions (code) or storage of data. Memory pages marked with the NX attribute cannot be executed as code, so an attempt to run instructions stored in such a page causes a fault. The feature is a key defence against buffer overflow attacks, in which an attacker injects malicious code into a program's data and tricks the processor into executing it.

Terminology

AMD introduced the bit as "NX" (Enhanced Virus Protection) with its Athlon 64 and Opteron processors in 2003. Intel markets the equivalent feature as the "XD bit" (execute disable), and ARM architecture implements it as "XN" (execute never). Microsoft Windows refers to the software policy built on the hardware feature as Data Execution Prevention (DEP).

Implementation

In the x86-64 architecture the NX bit is bit 63 of each page-table entry, available when the processor operates in PAE or long mode. Operating systems set the bit on stacks, heaps, and other data pages. Software support arrived in Linux 2.6.8 (2004), Windows XP Service Pack 2 (2004), and later versions of macOS. Where hardware lacks the feature, some systems emulate it in software — OpenBSD's W^X policy and the PaX project's PAGEEXEC are notable examples.

Limitations

NX prevents executing injected data but does not stop attacks that reuse existing code, such as return-to-libc and return-oriented programming (ROP), which is why it is typically combined with address space layout randomisation (ASLR) and stack canaries.
