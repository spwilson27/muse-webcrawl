Software design

Software design translates requirements into a plan for building a system.

Software design is the process by which an agent creates a specification of a software artifact intended to accomplish goals, using a set of primitive components and subject to constraints. It sits between requirements analysis and coding within the software development process: given what a system must do, design determines how it will be structured and built. In the standard view (e.g. SWEBOK), software design encompasses software architecture — the high-level structure of components and their relationships — and detailed design of modules, interfaces, algorithms, and data structures.

Considerations

Good design is judged by qualities such as modularity, cohesion, coupling, abstraction, separation of concerns, information hiding, and suitability for the system's quality attributes (security, performance, modifiability, testability). Designers must balance competing requirements and constraints; design decisions made early can be costly to reverse, so design involves anticipation of change and trade-off analysis. Both functional requirements and non-functional ("-ility") requirements constrain the solution.

Approaches and notations

Historically, structured design (top-down decomposition with data-flow diagrams) was followed by object-oriented design, popularized by works such as Design Patterns (1994) by the "Gang of Four," which catalogued reusable solutions to common problems. Model-driven approaches and the Unified Modeling Language (UML) provide graphical notations for structure and behaviour. Agile methods favour emergent design and refactoring over extensive up-front specification, while domain-driven design aligns system structure with a model of the problem domain. Software design documents (SDDs), architecture decision records, prototyping, and design reviews are common practices for recording and validating design choices.
