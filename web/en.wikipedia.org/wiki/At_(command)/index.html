at (command)

In computing, at is a command in Unix-like operating systems that schedules commands or scripts to be run automatically at a specified time in the future, once only. It is the one-shot counterpart of cron, which runs jobs on a recurring schedule. Windows has a similar command, also called at, which was deprecated in favour of schtasks.

Usage

at reads a list of commands from standard input or from a file given with the -f option, and executes them at the requested time via the atd daemon. Times can be given in many formats, including clock times, dates, and relative expressions:

$ echo "shutdown -h now" | at 22:00
$ at now + 1 hour
$ atq        # list pending jobs
$ atrm 3     # remove job 3

The related command batch works like at but runs the job as soon as the system load average drops below a threshold. atq lists the user's pending jobs, and atrm removes jobs from the queue. When a job finishes, any output it produced is mailed to the user.

Access control

Access to at is controlled by the files /etc/at.allow and /etc/at.deny. Jobs are stored in a spool directory (for example /var/spool/at or /var/spool/cron/atjobs), together with the environment in which they were submitted, so that each job runs with the environment the user had when scheduling it.

Design

The command dates to early Unix and was standardised by POSIX. On Linux, a widely used implementation was written by Thomas Koenig. Because many modern systems use systemd, the same task can also be achieved with transient timers (systemd-run --on-calendar), but at remains simpler for one-off jobs.
