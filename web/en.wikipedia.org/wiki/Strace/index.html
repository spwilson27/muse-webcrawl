Strace

strace output tracing a program's system calls

strace is a diagnostic, debugging and instructional userspace utility for Linux. It is used to monitor and tamper with interactions between processes and the Linux kernel, which include system calls, signal deliveries, and changes of process state. The operation of strace is made possible by the kernel feature known as ptrace.

Usage

strace can be used to attach to a running process or to launch a program and trace it from the start. A typical invocation is:

strace [options] <command> [arguments]
strace -p <PID>

The output lists each system call with its arguments and return value, for example:

execve("/bin/ls", ["ls"], 0x7ffd...) = 0
openat(AT_FDCWD, "/etc/ld.so.cache", O_RDONLY|O_CLOEXEC) = 3
read(3, "\177ELF...", 832) = 832

Common options include -e trace=... to filter by system call class or name, -f to follow child processes created by fork or clone, -c to print a summary of time and call counts, -o file to write output to a file, and -s to control the maximum length of printed strings.

Applications

Because strace reveals exactly which files a program opens, which network connections it attempts, and where it fails, it is widely used for troubleshooting missing configuration files, permission errors, unexpected behaviour, and performance problems. Software developers use it to understand the behaviour of programs for which source code is unavailable.

History and related tools

strace was originally written for SunOS in 1991–1992 by Paul Kranenburg, based on a utility called "trace" by Mark Kleynerman for System V, and was later ported to Linux. Related tools include ltrace, which traces library calls, and truss on Solaris and other System V systems.
