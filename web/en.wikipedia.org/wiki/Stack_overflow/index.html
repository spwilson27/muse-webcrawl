Stack overflow

In software, a stack overflow occurs when the call stack pointer exceeds the stack bound. The call stack is a fixed-size region of memory that stores information about active subroutines — return addresses, local variables, and saved registers. If a program uses more stack space than is available, it overflows, typically crashing the program or corrupting adjacent memory.

Causes

The most common cause of stack overflow is recursion that is too deep or that never terminates: each recursive call pushes a new stack frame, and if the base case is missing, incorrect, or reached only after an enormous number of calls, the frames accumulate until the stack is exhausted. Other causes include allocating very large objects as local variables (for example, a megabyte-sized array declared inside a function) and deeply nested mutual recursion between functions.

Consequences

On modern operating systems, the stack is usually guarded by an inaccessible page; growth into the guard page triggers a segmentation fault or a dedicated exception (such as STATUS_STACK_OVERFLOW on Windows, or StackOverflowError in Java). In embedded and kernel contexts without such protection, an overflow can silently overwrite other data and produce arbitrary misbehavior.

Historically, stack overflows have also been a security concern: classic buffer-overflow exploits overwrite the saved return address on the stack to redirect execution, though the phrase "stack overflow" more properly refers to exhaustion of stack space rather than the buffer overrun itself.

Prevention

Common mitigations include converting recursion to iteration, increasing the configured stack size, moving large allocations to the heap, adding explicit depth counters to recursive algorithms, and using tail-call optimization where the language provides it, which reuses the caller's frame for a call in tail position.
