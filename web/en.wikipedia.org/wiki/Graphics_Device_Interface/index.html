Graphics Device Interface

GDI gives Windows applications a device-independent way to draw graphics and text.

The Graphics Device Interface (GDI) is a legacy component of Microsoft Windows responsible for representing graphical objects and transmitting them to output devices such as monitors and printers. Introduced with Windows 1.0 in 1985, GDI allows programmers to draw lines, shapes, text and bitmap images without knowledge of the specific hardware.

Concepts

Applications draw through a device context (DC), an object representing a device surface together with its current drawing attributes. Objects — pens, brushes, fonts, bitmaps, regions and palettes — are selected into the DC, and functions such as LineTo, Rectangle, TextOut and BitBlt perform drawing. GDI insulates programs from hardware differences by using driver software for each device.

GDI+ and successors

GDI+, shipped with Windows XP (2001), added anti-aliased 2D drawing, gradient fills, alpha blending, and support for more image formats through a C++ class-based API built on top of GDI. From Windows Vista onward, the Desktop Window Manager composes windows using DirectX, and Microsoft has promoted Direct2D and the Windows UI frameworks as the modern successors for high-performance graphics, though GDI remains deeply embedded in the operating system and countless applications.

Limitations

GDI is largely CPU-based and historically limited in the number of objects per process (a default quota of 10,000 GDI handles per process in modern Windows). Rendering is not hardware-accelerated to the extent of DirectX, which motivated the newer APIs.
