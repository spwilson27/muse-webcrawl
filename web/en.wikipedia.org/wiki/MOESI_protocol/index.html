The MOESI protocol is a cache coherence protocol used in multiprocessor computer systems. It is a full extension of the MESI protocol that adds an Owned state, allowing a cache line that has been modified in one cache to be shared with other caches without first being written back to main memory.

States

Each cache line can be in one of five states:

  • Modified — the line is present only in this cache and is dirty; its value differs from main memory.
  • Owned — the line is dirty and may be present in other caches in the Shared state; this cache is responsible for supplying the current value and eventually writing it back.
  • Exclusive — the line is present only in this cache and is clean, matching memory.
  • Shared — the line may be present in several caches; it is clean unless held as Owned elsewhere.
  • Invalid — the line is not valid in this cache.

Advantage of the Owned state

In plain MESI, when a modified line is read by another processor it must be written back to memory (or the state changed and data forwarded with extra traffic). MOESI's Owned state lets the modifying cache keep responsibility for the dirty data while supplying it directly to other caches, reducing memory bandwidth and latency in workloads where dirty data is shared. The protocol is associated with AMD's multiprocessor designs, including the Opteron family.
