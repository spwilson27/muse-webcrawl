Object-capability model

The object-capability model is a computer security model based on the capability-based security approach. A capability describes a transferable right to perform one (or more) operations on a given object; in the object-capability model, access to an object is obtained by holding a reference to it, so that designation and authority are combined in a single unforgeable token.

Principles

In an object-capability system, programs interact only through references they possess. Three rules govern authority: a computation can exercise only the capabilities it holds; capabilities can be acquired only initially, from a parent computation, or by receiving them over an existing capability; and objects can be created to encapsulate and attenuate authority. Because there is no ambient authority — no global namespaces or identity-based access checks — the model naturally supports the principle of least authority and helps avoid the confused deputy problem.

Implementations

Languages and systems designed around the model include the E programming language, Joe-E (a subset of Java), the seL4-based and KeyKOS operating system traditions, and modern frameworks such as Cap'n Proto RPC. Object-capability discipline can also be followed within ordinary object-oriented languages by restricting language features that grant ambient authority.
