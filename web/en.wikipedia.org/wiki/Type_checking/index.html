Type checking

Image placeholder: type checking

In computer programming, type checking is the process of verifying and enforcing the constraints of types on values. A compiler or interpreter performs type checking to ensure that operations in a program are applied to values of appropriate types — for example, that an integer is not passed where a string is required. Programs that pass the check are type-safe with respect to that class of errors: the slogan "well-typed programs cannot go wrong" is associated with Robin Milner's work on type theory.

Static and dynamic checking

Static type checking is performed at compile time, as in Java, C++, Rust and Haskell. It catches errors before the program runs and enables optimisations, but rejects some programs that would in fact run correctly. Dynamic type checking is performed at run time, as in Python, JavaScript and Lisp, where values carry type tags and operations check them as they execute. It offers greater flexibility, at the cost of detecting errors only when the offending code executes and of some runtime overhead.

Type systems and safety

A type system is a set of rules assigning types to program constructs, together with rules for how types may be combined and converted. Type checking relies on these rules, often expressed as formal typing judgements in type theory, and may be supported by type inference, which deduces types automatically (as in ML and Haskell, using Hindley–Milner inference). A language is called strongly typed — an informal term — when it permits few implicit conversions that could subvert its types, and weakly typed when it permits many.

Gradual typing

Gradual typing combines the two approaches, allowing typed and untyped code to interoperate and types to be added incrementally, as in TypeScript, Python's optional type hints, and Typed Racket. Type checkers in such systems are separate tools that verify annotations while the underlying language remains dynamically typed.
