The Logical Volume Manager (LVM) is a device mapper target in the Linux kernel that provides logical volume management, allowing system administrators to allocate storage space more flexibly than with conventional disk partitioning. LVM creates an abstraction layer in which physical storage devices are pooled and then carved into virtual partitions — logical volumes — that can be created, resized, moved and snapshotted while the system is running.

Architecture

  • Physical volumes (PV) — disks or disk partitions initialised for LVM use
  • Volume groups (VG) — pools combining one or more physical volumes; storage is allocated from a VG in units called physical extents
  • Logical volumes (LV) — the virtual block devices carved out of a VG, on which filesystems are created; each LV is composed of logical extents mapped to physical extents

The kernel's device-mapper framework implements the mapping, and the LVM2 userspace tools (commands such as pvcreate, vgcreate, lvcreate, lvextend and lvreduce) manage the on-disk metadata.

Features

  • Online resizing of volumes and filesystems (growing; shrinking where the filesystem supports it)
  • Snapshots — point-in-time, copy-on-write copies of a logical volume, widely used for consistent backups
  • Striping and mirroring of volumes across physical devices
  • Thin provisioning (thin pools), caching (dm-cache integration via cache volumes), and RAID levels implemented through device mapper
  • pvmove — live migration of data off a failing or retiring disk

History and adoption

LVM for Linux was written by Heinz Mauelshagen beginning in 1997, inspired by the volume manager of HP-UX, and merged into the Linux 2.4 kernel series. LVM2, using the device-mapper, superseded it in the 2.6 kernel (2003). Most major Linux distributions offer or default to LVM-based layouts in server installs, and LVM underlies many virtualisation and cloud image setups because of its snapshot and resizing flexibility. Criticisms focus on added complexity and recovery difficulty compared with plain partitions, and newer filesystems such as Btrfs and ZFS integrate similar volume-management functions directly.
