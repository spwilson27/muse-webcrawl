In object-oriented programming, a class is an extensible program-code template for creating objects, providing initial values for state (member variables) and implementations of behavior (member functions or methods). In many languages, the class name is used as the name for the class, the name for the default constructor of the class, and as the type of objects generated by instantiating the class.

When an object is created by a constructor of the class, the resulting object is called an instance of the class, and the member variables specific to the object are called instance variables, to contrast with the class variables shared across the class.

History

The concept of classes was introduced by the Simula language in the 1960s, developed by Ole-Johan Dahl and Kristen Nygaard in Norway. Smalltalk, developed at Xerox PARC in the 1970s, popularized the idea that "everything is an object" belonging to a class. Classes became a central feature of mainstream programming with C++ and later Java, C#, and Python.

Structure

A class typically defines:

  • Fields (attributes or properties) — the data an object holds;
  • Methods — functions that define the object's behavior;
  • Constructors — special methods invoked when an object is created;
  • A destructor or finalizer in some languages, invoked when an object is destroyed.
// Java example
public class Dog {
    String breed;
    void bark() { System.out.println("Woof!"); }
}

Inheritance and polymorphism

Classes can inherit state and behavior from other classes, forming hierarchies in which a subclass extends or specializes a superclass. This enables polymorphism, where objects of different classes can be treated through a common interface. Access modifiers such as public, private, and protected control encapsulation — the hiding of internal state.

Class-based vs. prototype-based

In class-based languages (Java, C++, C#, Ruby, Python), objects are created from classes. In prototype-based languages such as JavaScript (before ES6 class syntax, which is syntactic sugar over prototypes), objects inherit directly from other objects. The two models differ mainly in how inheritance chains are defined and when they can be modified.
