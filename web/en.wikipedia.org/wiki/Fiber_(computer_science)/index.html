Fiber (computer science)

Fiber
CategoryConcurrency primitive
SchedulingCooperative (manual yield)
Related conceptsThread, coroutine, green thread, process

In computer science, a fiber is a particularly lightweight thread of execution. Like threads, fibers share the same address space within a process. Unlike threads, however, fibers use cooperative multitasking: a running fiber must explicitly "yield" to allow another fiber to execute, rather than being preempted by the operating system scheduler.

Description

A fiber is typically implemented entirely in userspace library code. Each fiber maintains its own stack and saved register context, but because switching is cooperative and deterministic, fibers do not need the synchronisation primitives required when preemptive threads share data. A scheduler library decides which fiber to run when the current one yields or blocks.

Comparison with threads and coroutines

Fibers occupy a middle ground between operating-system threads and coroutines. They resemble coroutines in that control transfer is explicit, but differ in that any fiber can yield to any other fiber, whereas coroutines transfer control only back to their caller. Microsoft Windows provides a fibers API (CreateFiber, SwitchToFiber), and several programming-language runtimes—including Ruby (since 1.9) and Win32-based event frameworks—use fibers to implement efficient asynchronous I/O and "green thread" models.

Advantages and disadvantages

Because fiber switches avoid kernel transitions and are deterministic, fibers can be far cheaper than threads and simplify reasoning about shared state. However, a fiber that fails to yield blocks every other fiber in its thread, and fibers cannot by themselves exploit multiple processor cores unless combined with multiple OS threads.
