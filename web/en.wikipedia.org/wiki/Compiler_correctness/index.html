Compiler correctness

In computer science, compiler correctness is the discipline concerned with proving that a compiler correctly implements the semantics of the language it compiles: informally, that the compiled program behaves as prescribed by the source program. Because compilers are complex pieces of software, miscompilation bugs can silently introduce errors or security vulnerabilities into otherwise correct programs, so establishing correctness is a significant goal of formal verification research.

Approaches

Formal verification of a compiler

The most rigorous approach is to construct the compiler itself together with a machine-checked proof of its correctness, typically using a proof assistant such as Coq. The best-known example is CompCert, a formally verified optimizing compiler for a large subset of the C programming language, developed by Xavier Leroy and collaborators at Inria. CompCert's correctness theorem states that the observable behaviour of the generated assembly code is one of the behaviours allowed by the source program's semantics. Evaluations have found that CompCert's generated code performs comparably to GCC at moderate optimization levels, and controlled experiments (such as the Csmith random-testing study of Yang et al., 2011) found no miscompilation bugs in CompCert's verified components, unlike the many found in mainstream compilers.

Translation validation

Translation validation checks, for each individual compilation run, that the output program refines the input program. Rather than verifying the compiler once and for all, a separate validator — itself much simpler than the compiler — verifies the equivalence or refinement of each translation, so any existing, unverified compiler can be used.

Testing

In practice, most compiler correctness assurance comes from extensive testing: conformance suites, regression tests, differential testing between compilers, and randomized program generation with fuzzers such as Csmith, which generates random C programs and compares the outputs of different compilers to find discrepancies revealing bugs.

Challenges

Correctness proofs require formal semantics for both the source language and the target architecture; memory models, undefined behaviour, and floating-point semantics are especially subtle. Verified compilation has also been extended to verified compilation toolchains that include assemblers and linkers, as in the CakeML project for a dialect of ML.
