A cryptographic hash function (CHF) is a mathematical algorithm that maps data of arbitrary size to a fixed-size bit string (a hash, digest, or fingerprint) and is designed to be a one-way function — infeasible to invert. Unlike ordinary hash functions used in data structures, cryptographic hash functions must resist deliberate attack.

Properties

  • Preimage resistance: given a hash, it is infeasible to find any input producing it.
  • Second-preimage resistance: given an input, it is infeasible to find a different input with the same hash.
  • Collision resistance: it is infeasible to find any two distinct inputs with the same hash.
  • Avalanche effect: flipping one input bit changes about half the output bits unpredictably.

Constructions and history

Most classic designs (MD5, the SHA family) use the Merkle–Damgård construction, processing message blocks through a compression function; SHA-3 (standardised 2015, from the Keccak design) uses a sponge construction instead. MD5 collisions were demonstrated in 2004 and exploited by the Flame malware in 2012; Google and CWI announced the first practical SHA-1 collision ("SHAttered") in 2017, driving migration to SHA-256 and SHA-3.

Applications

Hash functions underpin digital signatures (signing the hash of a message), message authentication (HMAC), password storage (with slow, salted password hashing functions such as bcrypt, scrypt, and Argon2), file integrity verification, content addressing in version control (Git) and peer-to-peer systems, and proof-of-work in cryptocurrencies such as Bitcoin, which uses double SHA-256.
