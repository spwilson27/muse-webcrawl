Legacy code

Legacy code is source code that relates to a no-longer supported or manufactured operating system or other computer technology, or more generally any codebase that a team has inherited and must continue to maintain. In software engineering the term often carries the implication that the code is difficult to understand, test, or change safely.

Definitions

In his book Working Effectively with Legacy Code (2004), Michael Feathers offered an influential pragmatic definition: "legacy code is simply code without tests." Because there is no automated safety net, developers cannot verify that a change has not broken existing behaviour, so even small modifications become risky.

Working with legacy code

Common techniques for taming legacy systems include writing characterization tests that pin down current behaviour before changing it, refactoring in small steps, and wrapping old components behind modern interfaces. The strangler fig pattern replaces parts of a legacy system incrementally until the old code can be retired entirely.

Causes and consequences

Code becomes "legacy" through staff turnover and lost knowledge, obsolete platforms, accumulating technical debt, and sheer age — some banking and government systems still run COBOL written decades ago. Despite the negative connotation, legacy code is often valuable: it embodies years of bug fixes and business rules that would be costly to reproduce.
