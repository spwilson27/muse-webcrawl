Zachman Framework

The Zachman Framework is an enterprise ontology and a fundamental structure for enterprise architecture which provides a formal and structured way of viewing and defining an enterprise. It was developed by John Zachman, who first published the concept in the IBM Systems Journal in 1987 in the paper "A framework for information systems architecture".

Structure

The ontology is a two-dimensional classification schema presented as a 6×6 matrix. The rows represent six perspectives or viewpoints of different stakeholders:

  • Planner (contextual) — the scope and purpose of the enterprise
  • Owner (conceptual) — the business model
  • Designer (logical) — the system model
  • Builder (physical) — the technology model
  • Programmer/Subcontractor (detailed representations) — component specifications
  • User (functioning enterprise) — the operational system

The columns represent six interrogatives or primitive questions: What (data), How (function), Where (network), Who (people), When (time) and Why (motivation). Each cell of the matrix addresses one perspective's answer to one question, giving 36 cells in total.

Principles

Zachman insisted the framework is a taxonomy or ontology rather than a methodology: it classifies architectural artefacts but does not prescribe a process for creating them. Its rules require that each cell be distinct, that each column have a simple generic model, and that no artefact be repeated across rows at the same level of detail. The framework influenced later enterprise architecture approaches such as TOGAF and FEAF.

Criticism

Practitioners have criticised the framework for being difficult to implement completely, since filling all 36 cells is a large undertaking, and for providing little guidance on sequencing or governance. Zachman responded that the framework was never intended as an implementation method.
