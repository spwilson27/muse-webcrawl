Software reengineering

Software reengineering is the examination and alteration of a software system to reconstitute it in a new form and the subsequent implementation of that new form. It typically combines reverse engineering — analysing an existing system to recover its design and specifications — with forward engineering, rebuilding the system with improved qualities such as maintainability, performance, or portability to a new platform.

Reengineering is undertaken when a legacy system remains valuable to a business but has become costly or risky to maintain, for example because it is written in an obsolete language, its developers have left, or its documentation is missing. Unlike ordinary software maintenance, reengineering aims at a substantial renewal of the system rather than incremental fixes.

Process

A typical reengineering project includes inventory analysis of candidate systems, reverse engineering to abstract a higher-level representation, restructuring of code and data, and forward engineering to produce the replacement system. The "horseshoe model" describes the flow from source code up through abstraction levels and back down to new code. Partial approaches include code translation (translating source language automatically), program restructuring, and data reengineering (migrating and normalising databases).

Risks and benefits

Reengineering can extend a system's useful life and reduce long-term maintenance cost, but it carries risks: recovered abstractions may be incomplete, subtle business rules embedded in code may be lost, and the cost may approach that of redevelopment. Automated tool support and incremental ("chicken little") migration strategies, in which old and new systems run in parallel during transition, are used to manage these risks.
