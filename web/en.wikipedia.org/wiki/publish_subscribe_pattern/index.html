Publish–subscribe pattern

TypeMessaging / software design pattern
ComponentsPublishers, subscribers, broker or event bus
ExamplesMQTT, Kafka, Redis Pub/Sub

In software architecture, publish–subscribe is a messaging pattern where publishers categorize messages into classes without knowledge of subscribers, and subscribers express interest in classes and receive only matching messages.

Design

Publishers and subscribers are decoupled in space, time, and synchronization. A message broker (or event bus) often sits between them, filtering by topic or by message content. This loose coupling aids scalability but can complicate debugging and delivery guarantees.

Filtering

Topic-based systems route messages by named channels; content-based systems evaluate predicates over message attributes, which is more expressive but more computationally expensive.

Applications

The pattern underlies news feeds, IoT telemetry (MQTT), streaming platforms (Apache Kafka), and event-driven microservices.
