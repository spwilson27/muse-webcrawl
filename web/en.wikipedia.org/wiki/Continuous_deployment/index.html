Continuous deployment

From Wikipedia, the free encyclopedia

Continuous deployment (CD) is a software engineering practice in which code changes that pass an automated build, test, and staging pipeline are released to production automatically, without explicit manual approval. It extends continuous delivery — in which software is always kept in a deployable state and can be released at the push of a button — by removing the human release decision, so that every validated change reaches users as quickly as possible, sometimes many times per day.

Practice

Continuous deployment depends on a mature automated pipeline: continuous integration, comprehensive automated tests (unit, integration, and acceptance), infrastructure as code, and automated deployment strategies such as blue–green deployments, canary releases, and feature flags, which decouple deployment from release and permit rapid rollback. Production monitoring and alerting close the loop, allowing teams to detect and revert bad changes quickly; because each change set is small, faults are easier to localise. Organisations known for deploying very frequently include Amazon, Google, Facebook, Netflix, and Etsy, and industry research (such as the DORA "State of DevOps" reports and the book Accelerate) associates deployment frequency with elite software delivery performance.

Benefits and challenges

Advantages include faster feedback from users, reduced release risk per change, and improved developer productivity. Constraints include the need for very high test confidence, regulatory or contractual approval requirements in some industries, safety-critical domains where automatic release is inappropriate, and the organisational change required for teams to take end-to-end ownership of software in production.
