Unique key

In relational database management systems, a unique key is a set of one or more attributes (columns) whose combined values are guaranteed to be unique for each row (tuple) in a table. A table may have multiple unique keys, unlike a primary key, of which there can be only one per table.

Unique constraints

A unique key is typically enforced by a unique constraint and a unique index. If the columns of a unique key are not declared NOT NULL, most systems allow rows in which some or all of those columns are NULL, and the handling of multiple NULLs varies by vendor: standard SQL treats NULLs as distinct, so many rows with NULL keys may be permitted.

Unique vs primary keys

Both primary keys and unique keys identify rows uniquely and both are candidate keys in relational theory. The differences are that a table has exactly one primary key, primary key columns cannot be NULL, and a primary key is often chosen as the table's clustered key or the default target of foreign key references.
