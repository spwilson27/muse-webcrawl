Component Object Model

From Wikipedia, the free encyclopedia

A COM object and its interfaces, identified by GUIDs

Component Object Model (COM) is a binary-interface standard for software components introduced by Microsoft in 1993. It is used to enable inter-process communication and dynamic object creation in a large range of programming languages. COM is the basis for several other Microsoft technologies and frameworks, including OLE, OLE Automation, ActiveX, COM+, and DCOM, and it underlies much of the Windows API surface (including the Windows Runtime).

Overview

COM specifies an object model and programming requirements that enable COM objects to interact with other objects. A COM object is a chunk of compiled code — usually in a DLL or executable — that exposes its functionality through one or more interfaces: groups of related methods addressed through a table of function pointers (a vtable). Every interface and class is identified by a globally unique identifier (GUID): interfaces by IIDs and coclasses by CLSIDs.

All COM interfaces derive from IUnknown, which provides reference counting (AddRef and Release) and the ability to query an object for its other interfaces (QueryInterface). Because the standard is binary, components written in different languages — C++, Visual Basic, Delphi, and many others — can interoperate without recompilation.

Related technologies

  • OLE (Object Linking and Embedding) — built on COM for compound documents.
  • OLE Automation and the IDispatch interface — late-bound, scriptable components.
  • ActiveX — COM components usable in applications and (historically) web pages.
  • DCOM (Distributed COM) — extends COM across machine boundaries.
  • COM+ — adds services such as transactions and object pooling for enterprise applications.
  • Windows Runtime (WinRT) — a modern descendant of COM used by Universal Windows Platform apps.

History

Microsoft introduced COM with Windows NT 3.1 and Windows 95 in the early 1990s, evolving it from the earlier OLE 1.0 and the work of engineers including Tony Williams and Craig Wittenberg. COM was a central part of Microsoft's component strategy during the 1990s, competing with standards such as CORBA. Although newer .NET technologies have displaced COM for much application development, COM remains pervasive in Windows itself and in enterprise and industrial software, and most modern Windows APIs continue to be COM-based.
