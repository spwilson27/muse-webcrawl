Tracing (software)

In software engineering, tracing involves a specialized use of logging to record information about a program's execution. Tracing is used by programmers for debugging and by systems administrators and observability platforms for monitoring running systems, especially distributed systems. Unlike ordinary event logging, tracing typically follows the flow of a single request or transaction as it propagates through components, recording a sequence of timed operations.

Tracing versus logging

Logging records discrete events; tracing records causally related spans of work. In distributed tracing, a request crossing many services carries a trace identifier, and each service records spans — units of work with start times, durations and metadata — which are assembled into a trace showing latency and dependencies across the whole system. Open standards such as OpenTelemetry, and earlier projects like Google's Dapper (which inspired Zipkin and Jaeger), define how trace data is propagated and collected.

Implementation

Tracing can be implemented by:

  • Instrumentation in source code — explicit trace statements or tracing libraries and macros
  • Kernel and system tracers — such as Linux's ftrace, perf, eBPF-based tools, LTTng, and Sun's DTrace, which trace system calls, function entry and exit and scheduler events
  • Hardware tracing — processor features such as Intel Processor Trace and ARM CoreSight
  • Program tracing utilities — e.g. strace and ltrace, which intercept system calls and library calls of a running program

Uses

Tracing is used for performance analysis and optimization (locating bottlenecks at function granularity), debugging intermittent faults that cannot be reproduced, reverse engineering of program behaviour, and production observability — where sampled traces complement metrics and logs. Because tracing generates large volumes of data, production systems commonly sample traces or enable detailed tracing only conditionally.
