Register (computer)

From Wikipedia, the free encyclopedia
Registers form the fastest level of the memory hierarchy, inside the CPU itself

In computer engineering, a register is a small amount of very fast storage available as part of a central processing unit (CPU). Registers hold the data, addresses and intermediate results that instructions operate on directly, and are the fastest form of storage a computer possesses — typically accessible in a single clock cycle. The collection of registers in a processor is called a register file.

Types of registers

Architectures define several classes of register. General-purpose registers hold operands and pointers and can be used freely by instructions. Special-purpose registers include the program counter (instruction pointer), which holds the address of the next instruction; the stack pointer; the instruction register, holding the instruction being executed; and status/flags registers recording outcomes of comparisons and arithmetic. Floating-point and vector (SIMD) registers form separate register sets in many designs, as do memory-mapped control registers used to configure peripherals.

Registers in architectures

The number and width of registers is a defining feature of an instruction set architecture. The x86 architecture originally had only a handful of 16-bit registers (AX, BX, CX, DX, SI, DI, BP, SP), expanded to 32-bit in the 80386 and to sixteen 64-bit general registers in x86-64. RISC designs such as ARM and RISC-V typically provide 31–32 general-purpose registers, encouraging a load–store architecture in which arithmetic operates only between registers. Register renaming in out-of-order processors maps the architectural registers onto a larger pool of physical registers to eliminate false dependencies.

Register allocation

Compilers must assign a program's many variables to the limited set of hardware registers. Register allocation — often modelled as graph colouring — keeps frequently used values in registers and "spills" the remainder to the stack. Good allocation is critical to performance, because a register access is orders of magnitude faster than a main-memory access.
