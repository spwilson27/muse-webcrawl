Microcode

Microcode is a computer hardware technique that interposes a layer of low-level machine-specific instructions between the higher-level machine code instructions of a computer architecture and the underlying electronics. The microcode resides in a dedicated high-speed memory called the control store, and each machine instruction is implemented as a short sequence of microinstructions (a microprogram) that generate the control signals for the datapath.

History

The concept was developed by Maurice Wilkes in 1951 as a systematic way to design a control unit, and was first widely used in IBM's System/360 family (1964), which allowed different models — from small to large — to share one architecture while differing in hardware, the slower models interpreting complex instructions with microcode on simple datapaths. Microprogramming dominated mainframe and minicomputer design through the 1970s; the RISC movement of the 1980s favored hardwired control for simple instruction sets, but modern high-performance x86 processors still decode complex instructions into micro-operations, some of them microcoded.

Vertical and horizontal microcode

In horizontal microcode, each microinstruction word is wide and directly encodes many control signals, allowing parallel control of hardware resources. In vertical microcode, words are narrower and more like conventional instructions, requiring more cycles but less storage. Many designs compromise between the two, a style sometimes called diagonal.

Updates

Because microcode in modern processors is stored in patchable RAM loaded at startup, vendors can issue microcode updates through firmware or the operating system to fix errata. Notable examples include updates mitigating the Pentium FDIV bug's aftermath in later designs and the Spectre and Meltdown vulnerabilities, where microcode changes assisted software mitigations.
