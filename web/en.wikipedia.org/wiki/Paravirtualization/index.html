Paravirtualization

From Wikipedia, the free encyclopedia

In computing, paravirtualization or para-virtualization is a virtualization technique that presents a software interface to the virtual machines which is similar, yet not identical, to the underlying hardware–software interface.

The intent of the modified interface is to reduce the portion of the guest's execution time spent performing operations which are substantially more difficult to run in a virtual environment compared to a non-virtualized environment. The paravirtualization provides specially defined "hooks" to allow the guest(s) and host to request and acknowledge these tasks, which would otherwise be executed in the virtual domain (where execution performance is worse). A successful paravirtualized platform may allow the virtual machine monitor (VMM) to be simpler (by relocating execution of critical tasks from the virtual domain to the host domain), and/or reduce the overall performance degradation of machine execution inside the virtual guest.

Paravirtualization requires the guest operating system to be explicitly ported for the para-API; a conventional OS distribution that is not paravirtualization-aware cannot be run on top of a paravirtualizing VMM. However, even in cases where the operating system cannot be modified, components may be available that enable many of the significant performance advantages of paravirtualization. For example, the Windows paravirtualization drivers in Xen and virtio drivers for KVM provide high-performance paravirtual I/O.

History

The term "paravirtualization" was first used in the research literature in association with the Denali virtual machine monitor. The concept has older roots: IBM's VM operating system provided a "DIAGNOSE" hypercall facility from the 1970s. The Xen hypervisor, described in a 2003 paper, popularised paravirtualization on x86 hardware, which lacked efficient hardware support for full virtualization at the time.

Hypercalls and interfaces

Instead of executing privileged instructions that must be trapped and emulated, a paravirtual guest issues hypercalls — analogous to system calls — directly to the hypervisor. Paravirtual interfaces have also been defined for device I/O: the virtio standard defines paravirtual network, block and other devices used by KVM and other hypervisors, while Xen uses split device drivers with front-end drivers in the guest and back-end drivers in a privileged domain.

Relation to full virtualization

With the spread of hardware virtualization extensions (Intel VT-x and AMD-V, and later nested paging), full virtualization became more efficient, reducing the advantage of paravirtual CPUs; paravirtual I/O interfaces nevertheless remain widely used because emulated hardware devices are slow. Linux's paravirt ops infrastructure allows a single kernel to run either natively, fully virtualized, or paravirtualized.

Examples

  • Xen (paravirtual guests, "PV" and later "PVH" modes)
  • Linux paravirt ops and virtio
  • VMware paravirtual SCSI and VMXNET adapters
  • Hyper-V enlightenments for guest operating systems
