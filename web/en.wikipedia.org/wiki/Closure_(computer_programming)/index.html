Closure (computer programming)

In programming languages, a closure is a technique for implementing lexically scoped name binding in a language with first-class functions: a function, together with references to the variables of the environment in which it was defined. When the closure is invoked, it can access those captured variables even after the enclosing scope has finished executing.

[Image: Diagram of a closure capturing a variable from its enclosing scope]

History

The concept originated in the lambda calculus and was implemented in Lisp and Scheme in the 1960s–70s; Peter Landin coined the term. Closures spread to mainstream programming through languages such as Smalltalk, JavaScript, Python, Ruby, and later C++ (lambda expressions, C++11), Java (lambdas, Java 8), and C#.

Behaviour

Languages differ on whether a closure captures variables themselves or their values at the moment of creation. A classic consequence is the "loop variable" pitfall, in which closures created in a loop all share one mutable variable unless the language binds a fresh copy per iteration. Because captured variables can outlive their defining stack frame, implementations typically allocate them on the heap, and closures thereby provide a lightweight mechanism for encapsulation, callbacks, event handlers, currying, and partial application.

Example

In JavaScript, a counter factory returns a closure over a private variable: function makeCounter(){ let n=0; return () => ++n; } — each returned function remembers and mutates its own n, demonstrating how closures serve as the basis for module patterns and private state.
