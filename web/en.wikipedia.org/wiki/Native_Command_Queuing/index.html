Native Command Queuing

Native Command Queuing
StandardSerial ATA (from SATA 2.0 / AHCI)
Queue depthUp to 32 commands
PurposeReordering of read/write commands to improve disk performance

Native Command Queuing (NCQ) is a technology designed to increase the performance of SATA hard disk drives by allowing the drive to internally optimise the order in which received read and write commands are executed. It was introduced with the Serial ATA II specification and requires a host controller operating in AHCI or RAID mode.

Operation

With NCQ, the host can issue up to 32 commands to the drive at once, tagging each one. The drive's firmware then reorders those commands — for example, by sorting them by logical block address to minimise rotational latency and head movement — and signals completion as each finishes rather than in strict order.

Benefits and use

Reordering is most beneficial under random, multi-threaded workloads such as servers and busy desktops, where it can substantially raise throughput and reduce latency. NCQ also incorporates features such as DMA setup and interrupt aggregation to reduce CPU overhead. For solid-state drives, queuing concepts carried over into the NVMe protocol, which supports vastly deeper queues across many cores.

History

NCQ superseded the simpler Tagged Command Queuing used in SCSI and Parallel ATA. Early implementations occasionally caused problems with certain operating systems and drive firmware, but the technology became a standard, transparent feature of modern storage stacks.
