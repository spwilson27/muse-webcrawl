Unix time is a date and time representation system widely used in computing. It measures time by the number of seconds that have elapsed since 00:00:00 UTC on 1 January 1970, the Unix epoch, without counting leap seconds. It is used extensively in Unix-like and other operating systems and file formats as a simple, monotonic integer timestamp.

Definition

Unix time is defined as the duration in seconds from the epoch, excluding leap seconds. Because leap seconds are ignored, Unix time is not a linear representation of true elapsed time: each day is treated as having exactly 86,400 seconds. A Unix timestamp can be converted to a UTC calendar date by arithmetic alone, which makes it convenient for storage, sorting and comparison.

History

The epoch of 1 January 1970 was chosen by the early Unix developers at Bell Labs as a convenient round date close to the system's development. Early editions of Unix counted in sixtieths of a second, later settling on whole seconds. The value is conventionally stored in a signed 32-bit integer on older systems and in a 64-bit integer on modern ones.

Year 2038 problem

Systems storing Unix time in a signed 32-bit integer will overflow at 03:14:07 UTC on 19 January 2038, when the count reaches 2,147,483,647 and wraps to a negative value representing a date in 1901. This is known as the Year 2038 problem. Most modern 64-bit systems use 64-bit timestamps, for which overflow will not occur for roughly 292 billion years.

Milestones

Notable Unix time values have been celebrated by programmers: the counter reached 1,000,000,000 seconds on 9 September 2001, and 1,234,567,890 on 13 February 2009.
