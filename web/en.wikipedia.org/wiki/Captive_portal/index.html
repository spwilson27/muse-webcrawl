Captive portal

TypeNetwork access control
Used byWi-Fi hotspots, hotels, airports, cafés
StandardRFC 8910, RFC 8908 (captive portal architecture/API)

A captive portal is a web page accessed with a web browser that is displayed to newly connected users of a Wi-Fi or wired network before they are granted broader access to network resources. Captive portals are commonly used to present a login page requiring authentication, payment, acceptance of an acceptable use policy, or survey completion before a user is allowed to access the Internet.

How it works

When a client joins the network, the access point or gateway intercepts its traffic. DNS queries may be answered with the portal's address, and HTTP requests redirected to the portal page, until the user completes the required steps. Modern operating systems detect captive portals by requesting a known probe URL and expecting a specific response; if the response differs, the system opens a restricted browser window ("captive portal assistant") to display the login page. After authorisation, the gateway whitelists the device, typically by MAC address, for a period of time.

Limitations and criticisms

Captive portals break end-to-end connectivity, interfere with VPNs and with apps that do not use a browser, and historically relied on insecure interception techniques that fail with HTTPS and HSTS. In response, the IETF standardised a captive portal architecture (RFC 8952), a signalling protocol (RFC 8910), and a captive portal API (RFC 8908) so that devices can discover portal information securely instead of relying on interception.

Uses

Beyond access control, portals are used for marketing data collection, bandwidth management, and legal compliance (for example, displaying terms that allocate liability for user activity on the host's connection).
