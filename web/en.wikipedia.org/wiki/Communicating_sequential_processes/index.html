Communicating sequential processes

From Wikipedia, the free encyclopedia

Communicating sequential processes (CSP) is a formal language for describing patterns of interaction in concurrent systems. It was introduced by the computer scientist Tony Hoare in a 1978 paper and developed in his 1985 book of the same name. CSP describes a system as a set of independent sequential processes that communicate only by synchronous message passing along named channels; a communication can occur only when both the sending and the receiving process are ready, so the exchange is an event in which both participate.

Formal model

CSP processes are built from primitive events using prefix (a → P), deterministic and nondeterministic choice, and parallel composition, in which processes run concurrently and synchronise on shared events. The theory gives CSP a family of formal semantics — traces, failures, and failures–divergences models — which support machine-checked refinement: verifying that one process implements another. The model checker FDR (Failures–Divergences Refinement) automates such verification and has been applied to security protocols and distributed algorithms.

Influence on programming languages

CSP directly inspired the occam programming language for the transputer and has strongly influenced the concurrency designs of Go (goroutines and channels), Erlang's actor model comparisons notwithstanding, Limbo, and Rust's channel libraries; Hoare's dictum "don't communicate by sharing memory; share memory by communicating" is often quoted in this tradition. Practical systems influenced by CSP-style reasoning include the verification of cache-coherence and security properties in industry.

Related approaches

CSP is one of the two classical process calculi, the other being Robin Milner's Calculus of Communicating Systems (CCS) and its successor the π-calculus, which adds channel mobility. The actor model differs in using asynchronous, buffered message delivery rather than synchronisation.
