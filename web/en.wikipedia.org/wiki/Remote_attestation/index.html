Remote attestation

From Wikipedia, the free encyclopedia


A verifier checks a remote platform's state

Remote attestation is a method by which a host (the attestor or prover) authenticates its hardware and software configuration to a remote host (the verifier or challenger) in a way that the verifier can trust. Unlike simple authentication, which establishes who the remote party is, attestation seeks to establish what software is running on the remote machine — that is, its integrity state.

Remote attestation is typically a core function in trusted computing. A common implementation uses a Trusted Platform Module (TPM), which records measurements (cryptographic hashes) of the boot firmware and software into Platform Configuration Registers (PCRs). The prover can then produce a signed quote of these registers, which the verifier compares against a list of known-good values.

Process

A typical attestation exchange proceeds as follows: the verifier sends a challenge (usually a fresh nonce) to the prover; the prover's TPM signs the PCR values together with the nonce using an attestation identity key (AIK) whose credential chains back to the TPM manufacturer; the prover also supplies the measurement log of events that produced those PCR values; and the verifier validates the signature, replays the log to confirm it matches the quoted values, and appraises each measurement against reference values.

Applications

Remote attestation underlies measured boot and features such as Windows Device Health Attestation, Android key attestation, and the WebAuthn/Play Integrity ecosystems in which servers verify that requests come from genuine, unmodified devices. It is also used in cloud computing so that customers can verify the integrity of confidential-computing enclaves, such as Intel SGX enclaves, before provisioning secrets to them.

Limitations

Attestation proves what was loaded, not that the software is free of vulnerabilities; a machine can attest to known-good but exploitable code. Time-of-check to time-of-use (TOCTOU) gaps can also allow an attacker to modify software after attestation. Privacy is a concern because detailed measurements can fingerprint a device.
