Apache Avro is a row-oriented remote procedure call and data serialization framework developed within the Apache Hadoop ecosystem. Avro provides a compact binary data format, a container file format for persistent data, and rich data structures described by schemas written in JSON. It is widely used in big-data pipelines, including with Apache Kafka, for exchanging and storing large volumes of structured data efficiently.

Avro data is always accompanied by its JSON schema

Features

Avro's central design principle is that data is always read using a schema: when Avro data is written, its schema is stored with it (in the file header for container files), and readers interpret the bytes accordingly. This enables schema evolution: readers and writers may use different but compatible versions of a schema, with rules for resolving differences such as added or removed fields with defaults. Supported types include primitive types (null, boolean, int, long, float, double, bytes, string) and complex types (records, enums, arrays, maps, unions, and fixed).

Comparison with other systems

Avro is frequently compared with Apache Thrift and Protocol Buffers. Unlike those systems, Avro does not require code generation for basic use, supports dynamic typing, and was designed around schemas stored in JSON rather than an interface definition language. Its tight integration with Hadoop made it a common storage format alongside columnar formats such as Parquet and ORC.

History

Avro was created in 2009, principally by Doug Cutting and the Hadoop community, initially to provide a serialization format for Hadoop's data storage and communication needs. It became a top-level project of the Apache Software Foundation in 2010 and has library implementations in many languages, including Java, C, C++, C#, Python, Ruby, and PHP.
