Syntactic sugar

In computer science, syntactic sugar is syntax within a programming language that is designed to make things easier to read or express. It makes the language "sweeter" for human use: concepts can be expressed more clearly or concisely, or in an alternative style some may prefer, without adding any new expressive power — the sugared form can always be rewritten in the plainer "core" syntax.

Origin

The term was coined by Peter Landin in 1964 in connection with his work on the lambda calculus and the ISWIM language. It has a playful counterpart, "syntactic salt," for features that make it harder to write bad code, and the rarer "syntactic saccharin" and "syntactic syrup" for gratuitous or excessively decorative syntax.

Examples

Augmented assignment (x += 1) in C-like languages is sugar for x = x + 1. Infix notation itself can be viewed as sugar in languages like Lisp, where (+ 1 2) is fundamental. Array indexing, string interpolation, list comprehensions, and the foreach loop are other commonly cited examples. Designers debate sugar because while it aids readability, excessive sugar can fragment a language's idiom.
