Role-based access control

In computer systems security, role-based access control (RBAC) or role-based security is an approach to restricting system access to authorized users, and to implementing mandatory access control (MAC) or discretionary access control (DAC). Rather than assigning permissions directly to users, administrators assign users to roles, and roles to permissions, which greatly simplifies managing access in large organisations.

Model

The NIST RBAC model, standardised in 2004 as ANSI/INCITS 359, defines core RBAC (users, roles, permissions, sessions), hierarchical RBAC (senior roles inherit the permissions of junior roles), and constrained RBAC (separation-of-duty rules that prevent a single user from holding conflicting roles).

Advantages

RBAC supports the principle of least privilege, eases administration when employees change jobs, and helps demonstrate compliance with regulations requiring controlled access to sensitive data. It is implemented in most operating systems, database systems, and enterprise applications.

Comparison

RBAC contrasts with attribute-based access control (ABAC), in which decisions are made by evaluating attributes of the user, resource, and environment, offering finer-grained but more complex policies.
