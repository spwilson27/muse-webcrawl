Resource acquisition is initialization

Resource acquisition is initialization (RAII) is a programming idiom used in several object-oriented, statically typed languages, most prominently C++, in which the life cycle of a resource — memory, a file handle, a database connection, a lock — is bound to the lifetime of an object. The resource is acquired in the object's constructor and released in its destructor, so that release is guaranteed to occur when the object goes out of scope, including when an exception is thrown.

Origin and name

The idiom was developed by Bjarne Stroustrup, the creator of C++, during the 1980s. The name, which emphasises acquisition rather than release, is often remarked on as unintuitive; Stroustrup has noted that "resource release is destruction" would describe the mechanism more directly.

Examples and uses

Standard C++ library facilities embody RAII: std::unique_ptr and std::shared_ptr manage dynamically allocated memory, std::lock_guard releases a mutex at the end of a scope, and file stream objects close their files on destruction. Analogous deterministic-cleanup mechanisms exist in other languages — Rust's ownership system generalises the pattern, while languages with garbage collection typically add constructs such as Java's try-with-resources or Python's with statement for non-memory resources.

Benefits

RAII prevents resource leaks and double-release errors, makes code exception-safe, and localises resource management in the class that owns the resource rather than scattering cleanup code across clients.
