Borg (cluster manager)

Borg
DeveloperGoogle
TypeCluster management / orchestration
SuccessorKubernetes (inspired by Borg)

Borg is a cluster manager developed and used internally by Google. It orchestrates the execution of hundreds of thousands of jobs, from thousands of different applications, across clusters each of tens of thousands of machines. Borg is the system that runs most Google services, and its design — described publicly in a 2015 paper — was the direct inspiration for the open-source Kubernetes project.

[ Image: Diagram of a Borg cell: a Borgmaster coordinating Borglet agents on worker machines ]

Architecture

Machines in a Borg deployment are grouped into cells. Each cell is run by a logically centralised controller, the Borgmaster, replicated for fault tolerance and elected via Paxos. A scheduler assigns tasks to machines according to resource requirements, priorities and quotas. On each machine an agent, the Borglet, starts and supervises tasks, restarting them if they fail. Work is submitted as jobs composed of tasks, described in a declarative configuration language.

Features

Borg packs tasks densely onto machines to achieve high utilisation, shares machine resources between production jobs and lower-priority batch work (with pre-emption), isolates tasks using Linux containers based on cgroups, and provides naming and monitoring services. Production jobs reserve resources and receive priority; quota and admission control prevent overcommitment.

Influence

Google engineers drew on Borg and its successor concepts (Omega) when designing Kubernetes, which generalises Borg's ideas — pods, labels, services — into an open, portable API. Other descendants and analogues include Apache Mesos and Docker Swarm.
