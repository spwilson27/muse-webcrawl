Data redundancy

Redundant copies allow data to survive the failure of individual components.

Data redundancy occurs when the same piece of data is stored in two or more separate places, or when extra data is stored beyond what is strictly necessary to represent the information. Whether redundancy is beneficial or wasteful depends on the purpose: deliberately engineered redundancy protects against data loss and corruption, while uncontrolled redundancy in databases can cause inconsistency and wasted storage.

Redundancy for reliability

Deliberate redundancy is a cornerstone of reliable systems. Error-correcting codes, checksums and parity bits add redundant information that allows errors in transmission or storage to be detected and corrected. Storage systems replicate data across disks (as in RAID arrays), across servers, and across geographic locations, so that the failure of a component does not destroy the data. Backups are a form of temporal redundancy, preserving earlier states of data.

Redundancy in databases

In database design, uncontrolled redundancy is usually undesirable: storing the same fact in several tables risks update anomalies, in which one copy is changed and others are not, leaving the database inconsistent. Database normalization is the process of restructuring tables to eliminate such accidental redundancy while preserving the information content. Controlled redundancy is sometimes reintroduced deliberately (denormalization) to improve query performance.
