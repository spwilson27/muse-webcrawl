Thread (computing)

TypeUnit of execution within a process
ContextOperating systems, concurrent programming
Related conceptsProcess, multitasking, scheduler, mutex

In computer science, a thread of execution is the smallest sequence of programmed instructions that can be managed independently by a scheduler, which is typically a part of the operating system. In many cases, a thread is a component of a process. The multiple threads of a given process may be executed concurrently (via multithreading capabilities), sharing resources such as memory, while different processes do not share these resources. In particular, the threads of a process share its executable code and the values of its dynamically allocated variables and non-thread-local global variables at any given moment.

Threads versus processes

A process is an instance of a program in execution with its own address space. Threads exist within a process: each process has at least one (the "main") thread, and all of its threads share the process's memory, open files and other resources, while each thread has its own stack, registers and program counter. Creating and switching between threads is therefore typically cheaper than creating or switching between processes, but sharing imposes costs: threads must coordinate access to shared data with synchronisation primitives such as mutexes, semaphores and condition variables, and programming errors can produce race conditions, deadlocks and other concurrency bugs.

Models and implementations

Threads may be implemented in the kernel (kernel-level threads scheduled by the operating system), in user space (user-level or "green" threads managed by a runtime library), or by hybrid (M:N) models mapping many user threads onto fewer kernel threads. Standard programming interfaces include POSIX Threads (pthreads) on Unix-like systems, the Windows API thread functions, Java threads in the JVM, and higher-level constructs such as thread pools, futures and async/await. On multicore processors threads can run truly in parallel; on a single core they are interleaved by time-slicing. Simultaneous multithreading (Intel's Hyper-Threading) exposes multiple logical processors per physical core.

Single-threaded and multithreaded programs

Threading is used to keep user interfaces responsive while work proceeds in the background, to overlap computation with input/output, and to exploit parallel hardware — in servers handling many clients, in games, and in scientific computing. Languages and frameworks increasingly offer safer concurrency models — actors, message passing, software transactional memory, and structured concurrency — to tame the difficulty of shared-memory multithreading.
