Copy elision


Image placeholder: Copy elision

Copy elision, also known as copy omission, is a compiler optimization technique used in the C++ programming language that allows the compiler to eliminate the copying of objects in certain situations, even if the copy would have visible side effects such as printing to standard output. It is one of the few exceptions to the "as-if" rule that permits a compiler to change program behaviour from the abstract machine semantics.

Return value optimization

The most common form of copy elision is return value optimization (RVO), where a function that returns an object by value constructs the returned object directly in the storage location where the caller expects the result, rather than constructing a temporary and copying or moving it. A related optimization, named return value optimization (NRVO), applies when a named local variable is returned.

History and standardization

Copy elision was permitted by the C++ standard since C++98 in specific cases, but compilers were free to choose whether to apply it. In C++17, certain forms of elision — notably for temporaries used to initialize an object of the same type (so-called "guaranteed copy elision") — became mandatory, changing the semantics so that no copy or move constructor need even exist in those cases.
