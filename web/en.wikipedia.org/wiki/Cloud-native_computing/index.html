Cloud-native computing

From Wikipedia, the free encyclopedia

Cloud-native applications are built from loosely coupled microservices packaged in containers.

Cloud-native computing is an approach in software development that utilizes cloud computing to build and run scalable applications in modern, dynamic environments such as public, private, and hybrid clouds. Containers, service meshes, microservices, immutable infrastructure, and declarative APIs exemplify this approach.

The Cloud Native Computing Foundation (CNCF), founded in 2015 under the Linux Foundation, defines cloud-native technologies as empowering organizations to build and run scalable applications in modern, dynamic environments. Cloud-native systems are designed to be resilient, manageable, and observable, and to tolerate rapid change through automation.

Key elements

  • Containers — applications and their dependencies packaged into portable units, popularized by Docker.
  • Orchestration — automated deployment, scaling, and management of containers, dominated by Kubernetes, originally developed at Google.
  • Microservices — applications decomposed into small, independently deployable services communicating over APIs.
  • DevOps and CI/CD — automation of building, testing, and releasing software in small, frequent increments.
  • Declarative configuration and infrastructure as code — desired state described in files rather than applied by manual commands.
  • Observability — metrics, logs, and traces (projects such as Prometheus and OpenTelemetry).

Cloud Native Computing Foundation

The CNCF hosts many of the ecosystem's central open-source projects, graded as sandbox, incubating, or graduated. Graduated projects include Kubernetes, Prometheus, Envoy, containerd, Helm, etcd, and Fluentd. The foundation also maintains the Cloud Native Landscape, a widely referenced map of the ecosystem, and runs the KubeCon + CloudNativeCon conferences.

Twelve-factor methodology

Cloud-native design overlaps with the twelve-factor app methodology published by Heroku engineers in 2011, which prescribes practices such as storing configuration in the environment, treating backing services as attached resources, keeping processes stateless, and separating build, release, and run stages.

Criticism and evolution

Critics note that cloud-native stacks can introduce significant operational complexity, and that container orchestration may be excessive for simple workloads. More recent developments include serverless computing, WebAssembly-based components, and platform engineering, in which internal developer platforms hide cloud-native machinery behind simpler interfaces.
