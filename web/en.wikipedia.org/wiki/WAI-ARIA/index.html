Web Accessibility Initiative – Accessible Rich Internet Applications (WAI-ARIA) is a technical specification published by the World Wide Web Consortium (W3C) that specifies how to increase the accessibility of web pages, in particular, dynamic content and user interface components developed with HTML, JavaScript, and related technologies.

In the 18 September 2018 draft of the Accessible Rich Internet Applications Working Group, WAI-ARIA has been split into multiple new documents: Accessible Rich Internet Applications (WAI-ARIA) 1.1, Core Accessibility API Mappings 1.1, Digital Publishing WAI-ARIA Module 1.0, and Digital Publishing Accessibility API Mappings 1.0.

Scope

Web developers use many on-page widgets that are difficult or impossible to re-create using native HTML semantics alone: sliders, tree views, tab panels, modal dialogs, and progress bars among them. ARIA provides semantics in the form of roles, states, and properties that can be added to HTML elements to convey the purpose and behavior of such widgets to assistive technologies such as screen readers. For example, a generic <div> styled as a button can be given role="button" so that assistive technology announces it as a button rather than as plain text.

Rules of use

The W3C's guidance documents, such as Using ARIA and the ARIA Authoring Practices Guide, emphasize that native HTML semantics should be preferred where available — often summarized as "the first rule of ARIA is: don't use ARIA" — because built-in elements carry correct semantics, focus behavior, and keyboard interaction by default. Where ARIA is used, authors are responsible for implementing the expected keyboard interaction and state management in script.
