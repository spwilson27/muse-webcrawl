Content Security Policy

CSP lets a site declare which sources of content the browser may load.

Content Security Policy (CSP) is a computer security standard introduced to prevent cross-site scripting (XSS), clickjacking and other code injection attacks resulting from execution of malicious content in the trusted web page context. It is a Candidate Recommendation of the W3C working group on Web Application Security, widely supported by modern web browsers.

Mechanism

A website administrator specifies a policy in an HTTP response header, Content-Security-Policy, or in a <meta> element. The policy consists of directives such as default-src, script-src, style-src, img-src and connect-src, each listing the origins or schemes from which that type of resource may be loaded. By, for example, disallowing inline scripts and scripts from untrusted origins, CSP makes it much harder for an attacker who has injected markup into a page to execute arbitrary code.

Reporting

CSP supports a report-only mode, delivered with the Content-Security-Policy-Report-Only header, in which violations are reported to a specified endpoint but not enforced. Reporting directives allow administrators to test policies and to detect attacks in progress before deploying enforcement.

History

The concept originated at Mozilla; an early version was implemented in Firefox 4 in 2011 under the header X-Content-Security-Policy. The W3C published CSP Level 1 as a Candidate Recommendation in 2012, followed by Level 2 in 2016, with Level 3 adding further directives and refinements. CSP is now considered a core defence-in-depth measure for web applications, complementing output encoding and other XSS mitigations.
