Object Linking and Embedding

Developer: Microsoft

Initial release: 1992 (OLE 1.0 with Windows 3.1)

Operating system: Microsoft Windows, macOS

Type: Component technology

Object Linking and Embedding (OLE) is a proprietary technology developed by Microsoft that allows embedding and linking to documents and other objects. It was developed as a way to create compound documents — for example, a word processor document containing a spreadsheet chart — and to let the embedded content be edited with the application that created it, a feature called in-place activation.

History

OLE 1.0 was released in 1992 with Windows 3.1, building on the earlier Dynamic Data Exchange (DDE) protocol. OLE 2.0 followed in 1993, introducing automation, drag-and-drop integration, and a foundation based on the new Component Object Model (COM). Over time the name OLE came to be applied to a wider family of COM-based technologies: OLE Automation, ActiveX controls, and OLE DB for data access. Microsoft later de-emphasized the OLE brand, but the underlying technologies remain part of Windows.

Linking versus embedding

When an object is embedded, a copy of its data is stored inside the container document. When it is linked, the container stores only a reference (a moniker) to the object's source, so that changes to the source are reflected in every document that links to it. Embedded objects can be double-clicked to edit in place, with the container application's menus and toolbars temporarily merging with those of the server application.

Related technologies

OLE's chief historical competitor was Apple's and IBM's OpenDoc, which was discontinued in the late 1990s. OLE concepts underlie the clipboard transfer formats and drag-and-drop behavior of Windows, and OLE DB served as Microsoft's data-access layer above ODBC before the rise of ADO and ADO.NET.
