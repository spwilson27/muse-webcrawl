Google File System

Google File System (GFS or GoogleFS, not to be confused with the GFS Linux file system) is a proprietary distributed file system developed by Google to provide efficient, reliable access to data using large clusters of commodity hardware. It was designed to meet Google's escalating data processing needs in the early 2000s and was described in a 2003 paper by Sanjay Ghemawat, Howard Gobioff and Shun-Tak Leung.

Design

Files are divided into fixed-size 64-megabyte chunks, each replicated at least three times across chunkservers. A single master maintains all metadata and coordinates operations such as leasing chunks for mutation. GFS assumes component failures are routine rather than exceptional, optimises for large streaming reads and appends rather than small random writes, and relaxes consistency in favour of throughput. It underpinned services such as Bigtable and MapReduce workloads.

Legacy

GFS strongly influenced open-source systems: the Hadoop Distributed File System (HDFS) was modelled on the published GFS design. Google later replaced it internally with a successor system known as Colossus, which distributes the master role and supports far greater scale.
