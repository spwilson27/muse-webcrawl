Tacit programming

In tacit programming, functions are composed without naming their arguments

Tacit programming, also called point-free style, is a programming paradigm in which function definitions do not explicitly mention the arguments (or "points") they operate on. Instead, functions are defined by composing other functions, using combinators and function composition.

Example

An explicit definition of the average of a list in Haskell might be:

avg xs = sum xs / fromIntegral (length xs)

In point-free style, the argument disappears:

avg = (/) <*> sum <*> fromIntegral . length

The style is idiomatic in array languages such as APL, J, and K, where trains of verbs operate on data without variable references, and is also common in concatenative languages such as Forth and Factor, where programs are sequences of functions applied to an implicit stack.

Advantages and criticism

Supporters argue that tacit definitions can be concise, emphasise the algebra of functions, and make equational reasoning and refactoring easier. Critics note that dense point-free code can become hard to read — sometimes jokingly called "pointless style" — especially when carried to extremes. The name "point-free" is borrowed from topology, where point-free methods describe spaces without referring to their points; the term was popularised in computing through the work of John Backus on function-level programming.
