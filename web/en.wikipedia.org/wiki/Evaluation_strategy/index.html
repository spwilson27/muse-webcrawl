Evaluation strategy

Evaluation strategy
FieldProgramming language semantics
Main variantsCall by value, call by name, call by reference, call by sharing, call by need

An evaluation strategy is a set of rules for the semantics of a programming language: specifically, for evaluating the arguments of a function call and for determining when the expressions passed as arguments are evaluated and what values they may be bound to. Evaluation strategies are divided into strict strategies, in which arguments are always evaluated before the function is applied, and non-strict strategies, in which arguments are not evaluated unless their values are actually needed.

Strict evaluation

In call by value, the argument expression is evaluated and the resulting value is bound to the corresponding parameter; this is the most common strategy, used by languages such as C, Java, and Scheme. In call by reference, the function receives a reference to the argument variable, so assignments to the parameter modify the caller's variable. Call by sharing, used for objects in languages such as Python and Java, passes a reference by value: the callee can mutate a shared object but cannot rebind the caller's variable.

Non-strict evaluation

In call by name, the argument expression is substituted into the function body and re-evaluated each time the parameter is used; it was used in Algol 60 and can be simulated with macros or thunks. Call by need is an optimised version in which the result of evaluating an argument is memoised and shared between uses; it is the strategy used by lazy languages such as Haskell. Non-strict evaluation permits working with infinite data structures and can avoid wasted computation, but makes reasoning about time, space, and side effects more difficult.

Other strategies

Other strategies include call by copy-restore (used historically in Fortran and Ada), call by result, and nondeterministic or futures-based evaluation in concurrent languages, in which an argument is evaluated in parallel with the rest of the program and its value is demanded only when needed.
