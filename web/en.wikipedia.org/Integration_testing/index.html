Integration testing

Integration testing is a level of software testing in which individual program units or components are combined and tested as a group, in order to expose faults in the interaction between integrated units and to verify that the interfaces between them work as designed. It follows unit testing, in which modules are verified in isolation, and precedes system testing, in which the complete integrated system is evaluated against its requirements.

Approaches

Big-bang integration combines all components at once; it is simple but makes fault localisation difficult, because a failure may originate anywhere. Incremental integration adds components one at a time, using stubs (which simulate called modules) and drivers (which simulate calling modules) for components not yet available. In top-down integration, high-level control modules are tested first, with stubs for subordinates; in bottom-up integration, low-level components are combined into clusters and tested with drivers, needing no stubs. Sandwich (hybrid) integration combines the two strategies, integrating top layers top-down and bottom layers bottom-up toward a middle target layer.

What it checks

Integration tests concentrate on interface defects: inconsistent parameter passing and data formats, incorrect assumptions about units and ranges, error-handling mismatches, unexpected side effects, and timing or concurrency issues that appear only when components interact. In modern practice, contract testing and continuous integration pipelines automate much of this: every code change is built and subjected to automated unit and integration tests, with services under development tested against mocks or test doubles of their dependencies.

Related concepts

Integration testing also applies outside software: in electronics and systems engineering, subsystems are progressively integrated and verified before full system validation. The V-model of development maps integration testing to the corresponding integration and design phases. Its scope is narrower than end-to-end or acceptance testing, which exercise the finished product from the user's perspective.
