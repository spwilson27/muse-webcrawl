Database normalization is a systematic approach to designing a relational database so as to reduce data redundancy and improve data integrity. Proposed by Edgar F. Codd as part of his relational model, normalization organises tables according to a series of normal forms, each imposing rules based on functional dependencies between attributes.

Objectives

An unnormalised design stores the same fact in many places, so updates may leave copies inconsistent (update anomalies) and make some facts impossible to record without others (insertion and deletion anomalies). Normalization decomposes tables so that each fact is stored once, and dependencies are enforced by keys.

Normal forms

First normal form (1NF) requires atomic values and no repeating groups. Second normal form (2NF) removes partial dependencies on part of a composite key. Third normal form (3NF) removes transitive dependencies: every non-key attribute must depend on "the key, the whole key, and nothing but the key". Boyce–Codd normal form (BCNF) is a slightly stronger version of 3NF. Higher forms (4NF, 5NF) address multi-valued and join dependencies.

Practice

Most production designs target 3NF or BCNF. Deliberate denormalization — reintroducing redundancy — is sometimes used to improve read performance, at the cost of more complex updates.
