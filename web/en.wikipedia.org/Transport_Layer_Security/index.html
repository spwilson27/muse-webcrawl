Transport Layer Security (TLS) is a cryptographic protocol designed to provide communications security over a computer network. It aims primarily to provide confidentiality, integrity and authenticity between two communicating applications, most commonly between a web browser and a server in HTTPS connections. TLS evolved from the Secure Sockets Layer (SSL) protocol developed by Netscape in the 1990s; despite the name change, older versions are still widely referred to as SSL.

History

Netscape released SSL 2.0 in 1995 and SSL 3.0 in 1996. When the Internet Engineering Task Force took over standardisation, the protocol was renamed TLS: version 1.0 appeared as RFC 2246 in 1999, followed by TLS 1.1 (2006) and TLS 1.2 (RFC 5246, 2008). Serious attacks against the older versions — including POODLE against SSL 3.0 and BEAST, CRIME and Heartbleed-era vulnerabilities affecting implementations — led browsers and standards bodies to deprecate SSL and early TLS versions; by 2021 TLS 1.0 and 1.1 were formally deprecated. TLS 1.3, standardised in RFC 8446 in August 2018, removed legacy algorithms, made forward secrecy mandatory, and cut the handshake to a single round trip.

How it works

A TLS session begins with a handshake in which the client and server agree on a protocol version and cipher suite, exchange random values, and use asymmetric cryptography — typically an ephemeral Diffie–Hellman key exchange such as ECDHE — to establish shared session keys without transmitting them. The server (and optionally the client) authenticates itself with an X.509 digital certificate issued by a certificate authority. After the handshake, application data is protected with fast symmetric authenticated encryption algorithms such as AES-GCM or ChaCha20-Poly1305. TLS 1.3 also offers a 0-RTT resumption mode, in which data can be sent with the first flight of messages, at some cost to replay protection.

Applications

TLS secures web browsing (HTTPS), email transport (SMTP, IMAP and POP3, including STARTTLS), instant messaging, voice over IP, and virtual private networks. It underlies services such as FTPS and is a component of the QUIC transport protocol, which integrates TLS 1.3 directly. The widespread deployment of free, automated certificates from authorities such as Let's Encrypt, founded in 2015, drove HTTPS adoption from a minority of web traffic to the overwhelming majority by the early 2020s.

Security and attacks

Known attacks on TLS have mostly targeted obsolete versions, optional features, or implementation flaws: padding-oracle attacks such as POODLE and Lucky Thirteen, compression side channels (CRIME), export-grade cryptography downgrade attacks (FREAK and Logjam), and the Heartbleed bug in the OpenSSL library (2014), which exposed server memory rather than breaking the protocol itself. Mis-issued certificates and compromised certificate authorities led to the development of Certificate Transparency logs, which make the issuance of publicly trusted certificates auditable. Datagram TLS (DTLS) adapts the protocol for unreliable transports such as UDP.
