Software as a service

Software as a service (SaaS) is a software licensing and delivery model in which software is licensed on a subscription basis and is centrally hosted. It is sometimes referred to as "on-demand software". SaaS applications are typically accessed by users using a thin client, e.g. via a web browser, and are a common delivery model for many business applications, including office software, messaging software, payroll processing software, database management system (DBMS) software, management software, and customer relationship management (CRM) software.

Characteristics

SaaS removes the need for organisations to install and run applications on their own computers or in their own data centres. This eliminates the expense of hardware acquisition, provisioning and maintenance, as well as software licensing, installation and support. Other benefits of the SaaS model include flexible payments, scalable usage, automatic updates, and accessibility from any internet-connected device.

However, SaaS customers have less control over customisation than with on-premises software, and concerns persist around data security, vendor lock-in, and limited control over versioning — a provider could update the software in ways that change workflows without customer consent.

History

The concept descends from the application service provider (ASP) model of the 1990s and from time-sharing systems of the 1960s. Salesforce, founded in 1999, was an early and influential pure-SaaS company, popularising the delivery of CRM software over the web. The proliferation of broadband internet and cloud computing in the 2000s made SaaS the default model for much new business software, with examples including Google Workspace, Microsoft 365, Dropbox and Zoom.

Architecture

Most SaaS applications use a multi-tenant architecture, in which a single version of the application, with a single configuration, is used for all customers. To support scalability, the application is installed on multiple machines, and data for multiple customers may be stored in the same database with logical separation. Some larger providers use multi-instance architectures, running separate instances per customer.
