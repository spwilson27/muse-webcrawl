Concurrent computing

Multiple computations interleaved in time.

Concurrent computing is a form of computing in which several computations are executed concurrently—during overlapping time periods—instead of sequentially, with one completing before the next starts. Concurrent computations may be executed on a single core through interleaved time-slicing, on multiple cores in a shared-memory machine, or across networked machines in a distributed system. Concurrency is a structuring technique: a concurrent program is decomposed into independently executing tasks even when they are not literally running in parallel.

Concepts

Concurrent tasks must often coordinate access to shared resources. Uncontrolled sharing produces race conditions, in which the outcome depends on the relative timing of tasks. Programmers use synchronization primitives such as mutexes, semaphores, monitors, and message passing to enforce correct interleavings, and must guard against hazards including deadlock, livelock, and starvation. Formal models, notably the actor model and Hoare's Communicating Sequential Processes (CSP), provide foundations for reasoning about concurrent systems.

Programming support

Most modern languages provide concurrency facilities: threads and locks in Java and C++, goroutines and channels in Go, processes and message passing in Erlang, and async/await task models in languages such as C#, Rust, and JavaScript. Deterministic scheduling, software transactional memory, and data-parallel frameworks attempt to reduce the difficulty of writing correct concurrent software, which remains one of the most error-prone areas of programming.

Applications

Concurrency is fundamental to operating systems, web servers handling many simultaneous requests, graphical user interfaces that must stay responsive, real-time and embedded control systems, and simulations. It is distinct from, though related to, parallel computing, which aims primarily at speeding up computation by using multiple processors simultaneously.
