Page fault

Page fault
TypeHardware exception / trap
Occurs inPaged virtual memory systems
Handled byOperating system kernel

A page fault is a type of exception raised by computer hardware when a running program accesses a memory page that is not currently mapped into the process's virtual address space. Despite the name, a page fault is not necessarily an error: it is the normal mechanism by which demand paging loads data into memory only when needed.

Types

A minor (soft) page fault occurs when the page is already in physical memory — for example in the page cache or another process's address space — and only the page table entry needs updating; these are inexpensive. A major (hard) page fault requires reading the page from disk or another backing store, which is orders of magnitude slower. An invalid page fault arises when the address is not part of the process's address space at all; on Unix-like systems the kernel typically responds with a segmentation fault (SIGSEGV), and Microsoft Windows reports an access violation.

Handling

When a page fault occurs, control passes to the operating system's page fault handler, which validates the access, locates the page on disk or in the swap area, finds a free frame (evicting another page via a page replacement algorithm if necessary), schedules the transfer, updates the page tables, and restarts the faulting instruction. If faults happen excessively because the working set exceeds available RAM, the system is said to thrash, and performance collapses.
