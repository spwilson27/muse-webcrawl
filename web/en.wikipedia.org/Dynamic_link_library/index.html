Dynamic-link library
Filename extension.dll
TypeShared library (executable code)
PlatformsMicrosoft Windows, OS/2

A dynamic-link library (DLL) is a library of executable code in Microsoft Windows and OS/2 that is loaded and linked at run time rather than being copied into each program at compile time. Programs call functions stored in DLLs, allowing many applications to share the same code, reducing memory use and disk space, and letting components be updated without recompiling every dependent program.

How it works

A DLL is a Portable Executable (PE) file, like an .exe, but marked as a library. It exports functions and data by name or ordinal; importing programs record the DLLs they need in an import table, and the Windows loader maps the libraries into the process address space when the program starts (load-time linking) or on demand via LoadLibrary (run-time linking). Symbols are resolved through the import address table.

Advantages

Shared libraries promote modular software, enable language-independent components, support plug-in architectures, and let the operating system itself be organized as a set of services (such as kernel32.dll and user32.dll) used by all applications.

"DLL hell"

Version conflicts — where installing one application overwrote a shared DLL with an incompatible version needed by another — became notorious in the 1990s and were dubbed "DLL hell". Microsoft addressed the problem with side-by-side assemblies, manifests, the Windows file protection system, and private (application-local) DLL deployment.
