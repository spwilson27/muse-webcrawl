RPM Package Manager

The rpm command-line tool managing packages on an RPM-based Linux system.

The RPM Package Manager (RPM; originally Red Hat Package Manager) is a powerful command-line package management system capable of installing, uninstalling, verifying, querying, and updating computer software packages. Each software package consists of an archive of files along with information about the package like its version, a description, and a list of dependencies.

RPM was created in 1995 by Erik Troan, Marc Ewing and the Red Hat community for use in Red Hat Linux. It is now the package management system used by the Linux Standard Base and by distributions including Fedora, Red Hat Enterprise Linux, CentOS, SUSE Linux and openSUSE.

Features

For a system administrator performing software installation, using package managers rather than building from source provides several advantages: packages are easy to install, upgrade and remove; file conflicts and dependencies can be tracked in a central database; and packages can be cryptographically verified using GnuPG signatures. RPM files carry the .rpm extension and consist of a header containing metadata and a compressed archive of files, nowadays typically compressed with xz or zstd.

Front ends

While rpm itself resolves no dependencies automatically, higher-level tools have been built on top of it. YUM and its successor DNF manage software repositories and dependency resolution on Fedora- and RHEL-based systems, while ZYpp (with its zypper front end) performs the same role on SUSE systems. Graphical front ends such as GNOME Software use these libraries through PackageKit.

Package building

Packages are built from a human-readable recipe called a spec file, which describes how source code is compiled, which files are installed, and what scripts run at install and removal time. The rpmbuild tool turns a spec file plus sources into binary and source RPMs (SRPMs). Build environments such as mock are used to produce packages in clean chroots.
