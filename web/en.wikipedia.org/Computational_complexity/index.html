Computational complexity

Relationships between common complexity classes

In theoretical computer science and mathematics, computational complexity theory focuses on classifying computational problems according to their resource usage, and relating these classes to each other. A computational problem is a task solved by a computer; complexity measures how the resources required — typically time and memory — scale with the input size.

Complexity classes

Problems are grouped into complexity classes such as P (solvable in polynomial time), NP (verifiable in polynomial time), NP-complete problems (the hardest problems in NP, to which all NP problems reduce), PSPACE, and EXPTIME. The question of whether P = NP is one of the Millennium Prize Problems; most complexity theorists believe the classes differ, but no proof is known.

Models and measures

Complexity is analyzed relative to a model of computation, usually the Turing machine, and expressed using asymptotic notation such as Big O. Key concepts include reductions between problems, completeness, time and space hierarchy theorems, and the study of approximation and randomized algorithms (classes such as BPP).

History

The field took shape in the 1960s and 1970s with work by Juris Hartmanis and Richard Stearns on time complexity, Stephen Cook's 1971 theorem on the NP-completeness of Boolean satisfiability, and Richard Karp's 1972 list of 21 NP-complete problems. Complexity results have practical weight in cryptography, which relies on problems believed to be hard, and in algorithm design, where NP-completeness signals that heuristic or approximation methods are needed.
