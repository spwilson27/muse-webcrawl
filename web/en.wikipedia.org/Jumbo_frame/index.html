Jumbo frame

Jumbo frame
Standard Ethernet payload: 1,500 bytes
Typical jumbo payload: 9,000 bytes
Used in: Data centers, storage networks, high-performance computing

In computer networking, a jumbo frame is an Ethernet frame with a payload larger than the standard maximum transmission unit (MTU) of 1,500 bytes. Jumbo frames commonly carry up to 9,000 bytes of payload, although there is no single universally standardized size; sizes up to about 9,216 bytes are typical of vendor implementations.

Rationale

Every frame carries fixed per-packet overhead — headers, inter-frame gaps, and host processing for interrupts and protocol handling. Increasing the payload size amortizes that overhead over more data, improving throughput and reducing CPU utilization, particularly for bulk transfers such as backups, storage traffic, and virtual-machine migration. The trade-off is slightly higher latency per frame and a greater cost when a corrupted frame must be retransmitted.

Deployment

Because jumbo frames are not part of the original IEEE 802.3 standard, all devices on a network segment — hosts, switches, and routers — must be configured consistently; a mismatch causes frames to be dropped or fragmented. For this reason jumbo frames are usually confined to controlled environments such as data-center fabrics, iSCSI and Fibre Channel over Ethernet storage networks, and supercomputing clusters, rather than the public Internet, where the path MTU is generally 1,500 bytes or less.

Related concepts

Even larger "super jumbo frames" exceeding 9,000 bytes have been proposed for specialized links. Alternative approaches to the same overhead problem include TCP segmentation offload and large receive offload, which let host operating systems handle large buffers while the network itself keeps standard frame sizes.
