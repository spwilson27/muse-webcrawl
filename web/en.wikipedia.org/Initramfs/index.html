initramfs (initial RAM file system) is a scheme for loading a temporary root file system into memory in the early stages of the Linux boot process. It provides a minimal environment, including an init program and necessary kernel modules and tools, so that the real root file system can be prepared and mounted.

Purpose

The real root file system may reside on an encrypted volume, a logical volume (LVM), a RAID array, or a network share, none of which the kernel can necessarily access on its own. The initramfs contains the drivers and utilities needed to unlock, assemble, and mount that file system. Once the real root is mounted, control passes to it via switch_root, and the normal init system (such as systemd) starts.

Construction

An initramfs image is a (usually compressed) cpio archive. Distributions generate it with tools such as dracut or mkinitcpio, and update it whenever the kernel is updated. The boot loader (such as GRUB) loads both the kernel and the initramfs image into memory.

Comparison with initrd

The older initrd (initial ramdisk) treated the image as a block device formatted with a conventional file system, which had to be copied and mounted. initramfs instead unpacks the archive directly into the kernel's rootfs, a special instance of a RAM-based file system, which is simpler and more efficient.
