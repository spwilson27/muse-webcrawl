GitOps


A Git-centric deployment pipeline.

GitOps is a set of practices for managing infrastructure and application configurations using Git as a single source of truth. It applies the version control, collaboration, compliance and continuous integration practices long used in software development to infrastructure automation.

Principles

The term was coined by Alexis Richardson of Weaveworks in 2017. The canonical GitOps principles are:

  • Declarative: A system managed by GitOps must have its desired state expressed declaratively, for example in YAML manifests.
  • Versioned and immutable: The desired state is stored in Git, giving a full history and an easy rollback mechanism.
  • Pulled automatically: Software agents automatically pull the desired state declarations from the source.
  • Continuously reconciled: Agents constantly observe the actual system state and attempt to apply the desired state, correcting drift.

Tools

Popular GitOps tools include Argo CD and Flux, both graduated projects of the Cloud Native Computing Foundation, which continuously sync Kubernetes clusters with configurations stored in Git repositories. Changes are made through pull requests rather than by pushing changes directly to the cluster, which makes the process auditable and reversible.

Benefits

Advocates cite increased deployment speed, improved reliability through easy rollbacks, a complete audit trail of every change, and self-healing systems in which manual configuration drift is automatically reverted to the declared state.
