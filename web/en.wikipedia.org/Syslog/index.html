Syslog

In computing, syslog (short for "system log") is a standard for message logging that allows separation of the software that generates messages, the system that stores them, and the software that reports and analyses them. Each message is tagged with a facility code identifying the type of program generating it and assigned a severity level.

History

Syslog originated in the 1980s as part of the Sendmail project, written by Eric Allman, and became the de facto logging standard on Unix and Unix-like systems through the syslogd daemon, before being documented by the IETF in RFC 3164 (2001, the "BSD syslog" protocol) and standardised in RFC 5424 (2009).

Mechanism

Programs send short log messages, traditionally under 1 KB, to a local syslog daemon, which may write them to files (commonly under /var/log), display them on a console, or forward them over a network to a central log host, typically on UDP port 514. Messages carry a priority value encoding one of 24 facilities (such as kern, user, mail, daemon, auth, and local0–local7) and one of eight severity levels, from Emergency (0) down to Debug (7).

Successors and related tools

Modern implementations such as rsyslog and syslog-ng add reliable transport over TCP, TLS encryption, filtering, and structured output. On Linux systems using systemd, the journal (journald) largely supersedes syslog for local logging while retaining compatibility interfaces.
