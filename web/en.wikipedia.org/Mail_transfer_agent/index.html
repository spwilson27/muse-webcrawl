Message transfer agent

AbbreviationsMTA; also mail transfer agent, mail server
FunctionTransfers email between computers using SMTP
Well-known softwareSendmail, Postfix, Exim, qmail, Microsoft Exchange
Default portTCP 25 (server-to-server)

A message transfer agent (MTA), or mail transfer agent, is software that transfers electronic mail messages from one computer to another using the Simple Mail Transfer Protocol (SMTP). Within Internet mail architecture, MTAs form the relay backbone: a sender's mail submission agent hands the message to an MTA, which looks up the recipient domain's MX records in the Domain Name System, and relays the message from MTA to MTA until it reaches the destination mail delivery agent (MDA).

Operation

An MTA accepts messages from local users, other MTAs, or submission services; determines routing by parsing recipient addresses; queues messages when a destination is temporarily unreachable, retrying with backoff; and generates delivery status notifications (bounces) for undeliverable mail. MTAs prepend "Received:" header fields, which create an auditable hop-by-hop trace of a message's path.

History and implementations

Sendmail, written by Eric Allman at the University of California, Berkeley in the early 1980s, dominated Internet mail routing for decades and remains in use. Later MTAs emphasized modularity and security: qmail (1995) by Daniel J. Bernstein, Exim (1995) from the University of Cambridge, and Postfix (1998) by Wietse Venema, the default on many Linux distributions. Microsoft Exchange Server combines MTA functions with mailbox and calendaring services.

Spam and abuse control

Early MTAs acted as "open relays," forwarding mail for anyone, a practice shut down in the late 1990s as spammers exploited it. Modern MTAs implement authentication (SMTP AUTH), encryption (STARTTLS), sender frameworks and scoring (SPF, DKIM, DMARC), rate limiting, and blocklist checks to control abuse.
