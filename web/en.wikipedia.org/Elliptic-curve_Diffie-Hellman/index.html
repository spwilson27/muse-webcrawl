Elliptic-curve Diffie–Hellman

Elliptic-curve Diffie–Hellman (ECDH) is a key agreement protocol that allows two parties, each having an elliptic-curve public–private key pair, to establish a shared secret over an insecure channel. It is a variant of the Diffie–Hellman protocol using elliptic-curve cryptography, and the shared secret can be used directly or fed into a key derivation function to produce symmetric keys.

The protocol

The parties agree on public domain parameters: an elliptic curve over a finite field and a base point G of large prime order. Alice chooses a private scalar a and publishes A = aG; Bob chooses b and publishes B = bG. Alice computes aB = abG and Bob computes bA = abG; both arrive at the same point, whose x-coordinate is typically used as the shared secret. An eavesdropper who sees A and B must solve the elliptic-curve discrete logarithm problem to recover it.

Ephemeral and static keys

In ephemeral ECDH (ECDHE), fresh key pairs are generated for each session, providing forward secrecy; this mode is widely used in TLS 1.2 and is the only key-exchange mode of its kind in TLS 1.3. Static ECDH, in which long-term keys are reused, lacks forward secrecy. Authentication of the public keys, by certificates or signatures, is required to prevent man-in-the-middle attacks.

Security and curves

Commonly used curves include the NIST curves P-256 and P-384 and Daniel J. Bernstein's Curve25519, whose X25519 function is popular in modern protocols such as WireGuard and Signal. Correct implementation must validate received points to avoid invalid-curve attacks.
