Model–view–viewmodel

Model–view–viewmodel (MVVM) is a software architectural pattern that facilitates the separation of the development of a graphical user interface (the view) from the development of the business logic or back-end logic (the model) so that the view is not dependent upon any specific model platform.

The viewmodel of MVVM is a value converter, meaning it exposes data objects from the model in a form the view can easily manage and binds the view's display to the model's data, typically through declarative data binding. In this way, the viewmodel acts as an abstraction of the view that contains a model's data and commands tailored for presentation.

History

MVVM was invented by Microsoft architects Ken Cooper and Ted Peters specifically to simplify event-driven programming of user interfaces, and was publicly described by John Gossman in 2005 in connection with Windows Presentation Foundation (WPF) and Microsoft Silverlight. It is a variation of Martin Fowler's Presentation Model pattern, adapted to take advantage of WPF's data-binding and command infrastructure.

Components

  • Model — the domain model or data-access layer, as in classic MVC.
  • View — the structure, layout, and appearance of what the user sees on screen (typically declarative markup such as XAML); it is "active", containing behaviours, events, and data binding rather than being manipulated directly by a controller.
  • View model — an abstraction of the view exposing public properties and commands; it serves as a data binder/converter between model data and view requirements.
  • Binder — the declarative binding technology (e.g., WPF's binding engine) that synchronizes the view and viewmodel, freeing the developer from writing boiler-plate synchronization logic.

Use

MVVM is the standard pattern for WPF and Xamarin/.NET MAUI applications, and similar ideas underpin JavaScript frameworks and libraries such as KnockoutJS, as well as data-binding approaches in Vue and other front-end frameworks.
