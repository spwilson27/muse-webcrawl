Relational model

The relational model (RM) is an approach to managing data using a structure and language consistent with first-order predicate logic, first described in 1969 by English computer scientist Edgar F. Codd, where all data is represented in terms of tuples, grouped into relations. A database organized in terms of the relational model is a relational database.

Basic concepts

A relation is a set of tuples, each consisting of attribute values drawn from domains. In database terminology, relations are visualised as tables with rows (tuples) and columns (attributes). Integrity is enforced by keys: a primary key uniquely identifies each tuple, and foreign keys express relationships between relations. The model avoids pointers and record ordering, so queries specify what data is wanted rather than how to navigate to it — an idea known as data independence.

Relational algebra and SQL

Codd defined a relational algebra with operations such as selection, projection, join, union, and set difference, and an equivalent relational calculus. These inspired the query language SQL, standardized in the 1980s, which dominates relational database management systems such as Oracle, MySQL, PostgreSQL, and Microsoft SQL Server. Normalization theory, developed by Codd and others, gives rules for decomposing relations to eliminate redundancy and update anomalies.

History and influence

Codd introduced the model in his 1970 paper "A Relational Model of Data for Large Shared Data Banks" while at IBM. Prototype systems System R (IBM) and Ingres (Berkeley) demonstrated feasibility in the 1970s. The relational model displaced hierarchical and network databases and remains the dominant paradigm, though object-relational extensions and NoSQL systems have broadened the landscape.
