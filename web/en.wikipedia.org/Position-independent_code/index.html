Position-independent code

Position-independent code (PIC) or position-independent executable (PIE) is a body of machine code that executes properly regardless of its memory address. PIC is commonly used for shared libraries, so that the same library code can be loaded in a location in each program address space where it does not overlap with other memory used by that program.

Mechanism

Position-independent code avoids absolute addresses by referring to data and code through offsets relative to the current instruction pointer, or through indirection tables such as the Global Offset Table (GOT) and Procedure Linkage Table (PLT) used in ELF-based systems. Because the code itself never needs modification at load time, a single copy of a shared library's text segment can be shared between processes.

Uses

PIC enables address space layout randomization (ASLR), a security technique that randomizes the locations of executables and libraries to make exploitation harder. It is also essential for shared libraries on most Unix-like systems and for code stored in ROM. Writing PIC traditionally carried a small performance cost on some architectures, notably 32-bit x86, due to the reservation of a register for the GOT pointer; modern architectures such as x86-64 support instruction-pointer-relative addressing that largely removes this cost.
