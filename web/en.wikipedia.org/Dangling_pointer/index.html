Dangling pointer

A dangling pointer indicates memory that has been deallocated

Dangling pointers and wild pointers in computer programming are pointers that do not point to a valid object of the appropriate type. These are special cases of memory safety violations. A dangling pointer arises when an object is deleted or deallocated without modifying the value of pointers that referenced it, so the pointer still refers to the memory location even though it may have been reused for other purposes.

Causes

The classic cause in languages such as C and C++ is freeing heap memory while pointers to it remain:

char *p = malloc(10);
free(p);
/* p is now a dangling pointer; using it is undefined behaviour */

Dangling pointers also arise when a function returns the address of a local variable, when a scope exits while references to its variables persist elsewhere, and in manual reference systems when an object is destroyed while other objects still hold pointers to it. Wild pointers, by contrast, are pointers that have never been initialised to a valid address.

Consequences

Dereferencing a dangling pointer is undefined behaviour in C and C++: the program may crash, read corrupted data, or appear to work while silently corrupting memory. Such use-after-free errors are also a major source of exploitable security vulnerabilities, since an attacker who can control the reused memory may hijack the stale pointer.

Avoidance

Common defences include setting pointers to NULL after freeing, using smart pointers and ownership models (such as C++ RAII and Rust's borrow checker), garbage collection, and static and dynamic analysis tools such as AddressSanitizer and Valgrind.
