Proxy ARP

From Wikipedia, the free encyclopedia

Proxy ARP
StandardRFC 925 (1984); described in RFC 1027 (1987)
LayerLink layer / network layer boundary
ProtocolAddress Resolution Protocol (ARP)

Proxy ARP is a technique by which a device on a network, typically a router, answers Address Resolution Protocol (ARP) requests intended for another device that is not on the same physical network segment. When a host broadcasts an ARP request for an IP address that lies elsewhere, the proxy device replies with its own hardware (MAC) address, and then forwards the traffic it receives to the true destination.

Uses

Proxy ARP was first described in RFC 925 (1984) for use with transparent subnet gateways, letting a network be subnetted without reconfiguring hosts. It remains useful for connecting devices that cannot be configured with a default gateway, for some dial-up and VPN configurations in which remote clients appear to be on the local subnet, and for certain firewall and redundancy arrangements.

Disadvantages and security

The technique hides the real topology of a network, increases ARP traffic and cache sizes, can fail confusingly when misconfigured, and complicates fault-finding. Because it depends on hosts trusting unauthenticated ARP replies, it interacts badly with network security: gratuitous and spoofed ARP responses can be used for ARP spoofing attacks and man-in-the-middle interception, and proxy ARP can inadvertently extend such vulnerabilities across segments. Modern network design generally prefers explicit routing or DHCP configuration over proxy ARP.
