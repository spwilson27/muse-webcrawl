Infrastructure as code

Practice areaDevOps, cloud computing, systems administration
ApproachesDeclarative, imperative
Notable toolsTerraform, AWS CloudFormation, Ansible, Puppet, Chef, Pulumi

Infrastructure as code (IaC) is the process of managing and provisioning computer data centres and cloud resources through machine-readable definition files, rather than through manual configuration or interactive tools. The infrastructure definitions are treated like software source code: they are versioned, reviewed, tested, and applied by automation.

Approaches

IaC tools are commonly divided into declarative (functional) approaches, in which the user describes the desired end state and the tool works out how to reach it — as in Terraform and CloudFormation — and imperative (procedural) approaches that specify the sequence of commands to run. Configuration-management tools such as Ansible, Puppet, and Chef configure software inside servers, while provisioning tools create the servers and networks themselves. A related goal is immutable infrastructure, in which servers are replaced rather than modified in place.

Benefits and practices

Storing infrastructure in code makes environments reproducible, eliminates configuration drift, enables code review and automated testing of infrastructure changes, and supports disaster recovery by redeploying from definitions. IaC is a core enabling practice of DevOps and of cloud-native computing, and it underpins techniques such as GitOps, in which the state of a system is continuously reconciled against definitions held in a Git repository.

History

The idea evolved from configuration-management tools of the 1990s and 2000s (CFEngine, Puppet, Chef) and became mainstream with the rise of cloud computing APIs, which made it possible to create entire data centres by calling web services. HashiCorp's Terraform (2014) popularised cloud-agnostic, declarative provisioning.
