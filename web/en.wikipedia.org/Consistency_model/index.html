Consistency model

A consistency model is a contract between a distributed (or shared-memory) system and the programs that use it, specifying which histories of reads and writes are allowed — in particular, what value a read may return given the writes that preceded it. Consistency models are a central topic in distributed computing and computer architecture, where data may be replicated across many nodes or cached in many processors.

Strong and weak models

The strongest familiar model is linearizability (strict consistency), in which every operation appears to take effect instantaneously at some point between its invocation and completion, so all processes observe a single global order. Sequential consistency, defined by Leslie Lamport in 1979, requires only that operations appear in a single order consistent with each process's program order. Weaker models relax ordering further for performance: causal consistency preserves the order of causally related operations; processor consistency, release consistency, and eventual consistency allow still more reordering or delay.

Trade-offs

Weaker models permit higher availability, lower latency, and better scalability, but are harder to program against. The CAP theorem formalizes part of this tension: in the presence of a network partition, a system must choose between consistency and availability. Real systems — from multiprocessor memory hierarchies to cloud databases — expose tunable consistency, advertising models such as strong, bounded-staleness, session, consistent-prefix, and eventual consistency. The related concept in databases is captured by transaction isolation levels and the ACID properties.
