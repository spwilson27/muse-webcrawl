Stream cipher

A stream cipher is a symmetric key cipher in which plaintext digits are combined with a pseudorandom cipher digit stream (the keystream), typically by XOR, one bit or byte at a time. Unlike block ciphers, which encrypt fixed-size blocks, stream ciphers can encrypt data of arbitrary length and are well suited to continuous streams of data.

Operation

The keystream is generated from a secret key and usually an initialisation vector (IV) or nonce by a keystream generator — often built from linear-feedback shift registers, nonlinear feedback registers, or a block cipher or hash function in a streaming mode. Encryption and decryption are identical: the same keystream is regenerated and XORed with the ciphertext to recover the plaintext. A keystream must never be reused with the same key and nonce; doing so exposes the XOR of the two plaintexts.

Examples

  • RC4 — once ubiquitous in TLS and WEP; now deprecated because of statistical biases.
  • A5/1 and A5/2 — used in GSM mobile telephony; both broken.
  • Salsa20 and ChaCha — modern designs; ChaCha20 is standardised for use in TLS as part of ChaCha20-Poly1305.
  • Trivium, Grain and Mickey — hardware-oriented finalists of the eSTREAM project.
  • Block ciphers in counter (CTR) or output feedback (OFB) mode behave as stream ciphers.

Properties

Stream ciphers generally offer high speed, low hardware complexity and no error propagation — a corrupted ciphertext bit affects only the corresponding plaintext bit. They provide no integrity protection by themselves and are usually combined with a message authentication code in authenticated encryption constructions.
