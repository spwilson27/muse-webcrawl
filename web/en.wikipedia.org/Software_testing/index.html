Software testing

Software testing is the act of checking whether software satisfies expectations. Software testing can provide objective, independent information about the quality of software and the risk of its failure to a user or sponsor. It typically involves executing a program or application with the intent of verifying behavior, finding defects (bugs), and ensuring the product is fit for use.

Levels and types

Testing is commonly organized into levels: unit testing of individual components, integration testing of combined components, system testing of the complete product, and acceptance testing against user requirements. Functional testing verifies what the system does, while non-functional testing examines performance, security, usability and reliability. Regression testing checks that changes have not broken existing behavior.

Approaches

Tests may be static (reviews and static analysis, without executing code) or dynamic. "Black-box" testing designs cases from specifications without knowledge of internal structure; "white-box" testing uses knowledge of the code to target paths and conditions. Test automation executes tests by script or framework, and practices such as continuous integration and test-driven development integrate testing throughout the development lifecycle. A well-known limitation, articulated by Edsger Dijkstra, is that testing can show the presence of defects but never their absence.
