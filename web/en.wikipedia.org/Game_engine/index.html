A game engine is a software framework primarily designed for the development of video games, providing the core functionality — a rendering engine for 2D or 3D graphics, a physics engine, sound, scripting, animation, artificial intelligence, networking, and a level editor — so that developers can build games without recreating these systems for each title. Engines are commonly licensed to third-party studios and are increasingly used in film, architecture, and simulation.

History

The term emerged in the mid-1990s as id Software separated the reusable core of Doom (1993) and Quake (1996) from game-specific assets and licensed it to other developers, a model Epic Games extended with Unreal Engine (1998) and its visual scripting. In the 2000s, Unity (2005) broadened access with low-cost licensing for independent developers; in 2014 the open-source Godot engine was released. Modern engines support real-time global illumination, physically based rendering, and deployment to consoles, PC, mobile, and web from a single project.

Components

A typical engine includes a renderer (rasterisation and, increasingly, ray tracing), physics and collision detection (often via libraries such as Havok or PhysX), an entity/component system or scene graph, audio mixing, asset pipelines, and editors for levels, materials, and animation. Scripting is exposed in languages such as C#, C++, GDScript, or visual node graphs; Unreal's Blueprints made node-based scripting mainstream.

Market and criticism

Unity and Unreal dominate licensed development, with Godot growing rapidly after changes to Unity's pricing in 2023 prompted many indie studios to migrate. Critics note that reliance on a small number of engines can homogenise game feel and aesthetics, while engine licensing terms can create business risks — topics of recurring industry debate.
