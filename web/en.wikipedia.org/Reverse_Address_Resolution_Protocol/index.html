The Reverse Address Resolution Protocol (RARP) is an obsolete computer networking protocol used by a client computer to request its Internet Protocol (IPv4) address from a computer network, when all it has is its link layer or hardware address, such as a MAC address. The client broadcasts its hardware address and asks for its IP address to be assigned; a RARP server on the local network, which holds a static table of MAC-to-IP mappings, replies with the address. RARP was defined in RFC 903 in 1984.

RARP is the converse of the Address Resolution Protocol (ARP), which maps a known IP address to a hardware address. Both use the same packet format; RARP uses distinct operation codes (3 for request, 4 for reply) and EtherType 0x8035.

A diskless client broadcasts its MAC address; the RARP server replies with the client's assigned IP address.

Use case

RARP served diskless workstations, which powered on with no stored configuration: the machine knew its network interface's burned-in hardware address but nothing else. A RARP reply gave it an IP address, after which it typically downloaded a boot image with TFTP. Because RARP works by broadcast, a server had to be present on every subnet.

Limitations and obsolescence

RARP could deliver only an IP address — no subnet mask, default gateway, or other configuration. It required a server on each physical network and manual maintenance of its mapping table. These limits led to its replacement by BOOTP (1985) and then the Dynamic Host Configuration Protocol (DHCP), which provides complete, dynamically leased configuration over UDP/IP. RARP is no longer in practical use.
