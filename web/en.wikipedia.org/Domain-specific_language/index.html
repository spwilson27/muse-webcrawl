Domain-specific language

A domain-specific language (DSL) is a computer language specialised to a particular application domain. This is in contrast to a general-purpose language (GPL), which is broadly applicable across domains. There are a wide variety of DSLs, ranging from widely used languages for common domains, such as HTML for web pages, down to languages used by only one or a few pieces of software, such as MUSH soft code.

Kinds of DSLs

Domain-specific languages are sometimes divided into domain-specific markup languages, domain-specific modelling languages (specification languages), and domain-specific programming languages. Well-known examples include SQL for database queries, regular expressions for text matching, CSS for styling web pages, the dot language for graphs in Graphviz, LaTeX for typesetting documents, makefiles for build automation, and shell scripts' specialised utilities such as sed and awk. A DSL may be an external language with its own parser, or an internal (embedded) DSL built within a host general-purpose language, as in Ruby on Rails conventions or Lisp macros.

Advantages and disadvantages

DSLs can express solutions in the idiom and at the level of abstraction of the problem domain, allowing domain experts to understand, validate and sometimes write programs themselves. They allow solutions to be expressed more concisely and to be checked for domain-specific errors. Against this, designing, implementing and maintaining a new language is costly, there is a risk of over-specialisation, and users must learn a new syntax. The boundary between a DSL and a scripting language or library is often blurred.

Design and implementation

By designing a language around the concepts of a domain, DSL designers aim to raise the level of abstraction and hide implementation detail. DSLs are implemented with tools such as parser generators, language workbenches, and compiler frameworks, or by interpretation within a host language.
