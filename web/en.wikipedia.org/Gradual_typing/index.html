Gradual typing

IntroducedTerm coined by Jeremy Siek and Walid Taha (2006)
Key mechanismDynamic type ("?"), consistency relation, runtime casts
ExamplesTypeScript, Hack, Typed Racket, mypy's Python, Reticulated Python
FieldProgramming language theory

Gradual typing is a type system in which some variables and expressions may be given types while others are left untyped, allowing a program to mix static and dynamic typing and to be migrated incrementally from one style to the other. The idea grew out of work on integrating static typing into dynamically typed languages, notably Jeremy Siek and Walid Taha's 2006 paper, which introduced a special dynamic type (written ?) and a symmetric "consistency" relation replacing equality of types.

How it works

Where typed and untyped code meet — at "boundaries" such as function calls — a gradual type system inserts runtime casts or contracts that check values as they cross. If a value fails to conform, the cast fails and blame is assigned to one side of the boundary. In sound designs ("sound gradual typing"), annotated code receives the usual guarantee that well-typed programs cannot commit certain errors; in unsound or "optional typing" designs (such as TypeScript's), annotations are erased and used only for tooling and error detection during development.

Implementations

Typed Racket (developed by Sam Tobin-Hochstadt and Matthias Felleisen) was one of the first full implementations, letting programmers add types module by module to Racket programs. Other prominent examples include TypeScript and Flow for JavaScript, Hack for PHP, Sorbet for Ruby, and type checkers such as mypy for Python. Research continues on the performance cost of boundary checks ("the gradual guarantee" versus soundness) and on blame assignment for higher-order contracts.

Debates

A widely discussed 2016 paper, "Is Sound Gradual Typing Dead?", reported severe performance overheads in some sound implementations, prompting work on more efficient cast representations, transient checks, and erasure semantics. The debate clarified the design space: languages trade off stronger guarantees against speed and simplicity.
