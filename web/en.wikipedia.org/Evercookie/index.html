Evercookie

An evercookie stores copies of an identifier in many browser storage mechanisms so it can respawn itself if any copy is deleted.

Evercookie is a JavaScript application programming interface (API) created by Samy Kamkar in 2010 that produces extremely persistent cookies in a web browser. Its goal is to identify a client even after the user has deleted standard HTTP cookies: the tracking identifier is simultaneously stored in numerous places — HTTP cookies, Flash Local Shared Objects, HTML5 Local Storage, session storage, web history features, ETags, web cache, window.name, and even PNG image data read back through an HTML5 canvas — so that if the user deletes any one copy, the script can detect the missing copy and regenerate ("respawn") it from the survivors.

Reception and response

Kamkar released evercookie as open source to draw attention to the limits of user control over tracking; he described it as a demonstration rather than a product. The technique attracted criticism from privacy advocates and was cited in regulatory and industry debates about "supercookies". Modern browsers have responded with storage partitioning, automatic expiry of script-writable storage, and clearing site data across all mechanisms at once, which greatly reduce (though do not always entirely eliminate) respawning techniques.

Related concepts

Evercookies are often classed with zombie cookies and supercookies. Verizon's use of an undeletable tracking header ("UIDH") led to a 2016 settlement with the US Federal Communications Commission. The existence of such techniques motivated "Do Not Track" proposals and later comprehensive privacy regulation, and illustrates why privacy tools advise clearing all site data rather than cookies alone.
