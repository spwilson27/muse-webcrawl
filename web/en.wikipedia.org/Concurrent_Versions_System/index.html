Concurrent Versions System

The Concurrent Versions System (CVS), also known as the Concurrent Versioning System, is a client–server revision control system for software development. Originally developed in the 1980s by Dick Grune as a set of shell scripts built on the Revision Control System (RCS), it was rewritten in C by Brian Berliner in 1989 and became the dominant version control system for open-source projects through the 1990s and early 2000s.

Design

Unlike earlier systems such as RCS and SCCS, which locked files during editing, CVS lets multiple developers work on the same files simultaneously — hence "concurrent". A central repository holds the full revision history of each file (stored in RCS format), and developers check out working copies, edit them, and commit changes; conflicts between overlapping edits are flagged and merged manually. CVS supports branching and tagging, keyword expansion, and client–server access over the network, which made it suitable for geographically distributed free-software development; it powered early collaboration sites such as SourceForge.

Limitations and succession

CVS lacks atomic commits, does not track renames or directory changes, stores binary files inefficiently, and has weak support for merging. These shortcomings prompted the development of Subversion (begun in 2000 explicitly as a "CVS done right") and later distributed systems such as Git and Mercurial, which displaced CVS in most projects. Development of CVS itself effectively ceased after version 1.11.23 in 2008, though the protocol and the CVSNT fork remained in use in legacy environments.
