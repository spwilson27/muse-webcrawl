Stack overflow

TypeRuntime error / software bug
CauseExcessive call-stack usage
Common triggerUnbounded recursion
Typical outcomeProgram crash (segmentation fault)

In software, a stack overflow occurs when a program uses more memory than is available on the call stack. The result is usually a program crash, and in some runtimes the condition is raised as a catchable error or exception.

Causes

The most common cause is excessive or infinite recursion: each nested function call pushes a new stack frame, and if recursion has no reachable base case — or a base case that requires too deep a call chain — the stack grows until it exceeds its limit. Very deep but finite recursion, large local variables declared on the stack, and unbounded mutual recursion can produce the same failure.

Behaviour by platform

In C and similar languages the overflow typically manifests as a segmentation fault when the stack grows into an unmapped guard page. Managed runtimes make the condition explicit: the Java Virtual Machine throws a StackOverflowError, and .NET raises a StackOverflowException which, in modern versions, cannot be caught and terminates the process.

Mitigations

Programmers avoid stack overflows by converting recursion to iteration, using explicit heap-allocated stacks, adding depth limits, or relying on tail-call optimisation where the language guarantees it. The stack overflow should not be confused with the buffer overflow, a different vulnerability in which a program writes beyond the bounds of a buffer; a stack buffer overflow is a specific security-relevant subtype.
