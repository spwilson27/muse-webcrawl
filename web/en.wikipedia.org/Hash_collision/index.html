Hash collision

In computer science, a hash collision (or clash) occurs when two distinct inputs to a hash function produce the same output value, or hash. Because hash functions map inputs of arbitrary size to fixed-size outputs, collisions are mathematically inevitable by the pigeonhole principle; good hash functions are designed to make them hard to find or unlikely to occur in practice.

Hash collision
Field: Computer science, cryptography
Cause: Many-to-one mapping of hash functions
Key risk: Attacks on digital signatures and data integrity

In hash tables

In hash table data structures, collisions occur when different keys hash to the same bucket. Common resolution strategies include separate chaining, in which each bucket holds a list of entries, and open addressing, in which the table probes for the next free slot. Collision handling is central to the average-case performance of hash tables.

In cryptography

For cryptographic hash functions, collision resistance — the infeasibility of finding any two inputs with the same hash — is a core security property. By the birthday paradox, a generic attack needs only about 2^(n/2) evaluations for an n-bit hash. Practical collision attacks have broken MD5 and SHA-1, leading to their deprecation for security uses.
