Memory management

Memory management is the act of managing computer memory at the system level. It involves allocating portions of memory to programs at their request and freeing the memory for reuse when it is no longer needed. Essential functions include allocation and deallocation, tracking which parts of memory are in use, protection between processes, and — in systems with virtual memory — mapping virtual addresses to physical locations.

Manual memory management

In languages such as C, the programmer explicitly allocates memory (e.g. with malloc) and frees it (with free) when done. This gives fine control and low overhead, but errors produce bugs such as memory leaks, double frees and use-after-free, which can cause crashes and security vulnerabilities.

Automatic memory management

Most modern languages automate management with garbage collection, in which the runtime identifies and reclaims memory that is no longer reachable. Alternatives include reference counting (used in Objective-C/Swift ARC, Python and COM) and region-based or ownership-based schemes, as in Rust, where the compiler enforces that each value has a single owner whose scope determines deallocation.

Operating system techniques

Operating systems manage physical memory through paging: memory is divided into fixed-size pages, and per-process page tables translate virtual addresses. Demand paging loads pages from disk only when accessed; page replacement algorithms such as least-recently-used decide which pages to evict when physical memory is exhausted. Kernel allocators use techniques such as buddy allocation and slab allocation to limit fragmentation.

Fragmentation

Repeated allocation and deallocation can fragment memory into unusable small gaps (external fragmentation), or waste space inside allocated blocks (internal fragmentation). Compaction, pooling and size-class allocators are used to mitigate these effects.
