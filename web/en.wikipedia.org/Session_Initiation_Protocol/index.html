Session Initiation Protocol

A basic SIP call flow between two endpoints.

The Session Initiation Protocol (SIP) is an application-layer signalling protocol used for initiating, maintaining and terminating communication sessions that include voice, video and messaging applications. It is the dominant protocol for Voice over IP (VoIP) telephony and is also used in IP multimedia subsystems and unified communications.

Overview

SIP was developed within the IETF and standardised in RFC 3261 in 2002, revising the original RFC 2543. It is a text-based protocol modelled on HTTP and SMTP: messages consist of a start line, headers and an optional body, most often carrying a session description in SDP. SIP handles signalling only — locating users, negotiating media capabilities and setting up sessions — while the actual voice and video data travel via other protocols such as RTP, typically secured with SRTP, and SIP itself is often protected by TLS.

Operation

Users are identified by SIP URIs resembling email addresses. Endpoints (user agents) register their current location with registrars, and proxy servers route requests such as INVITE, which starts a session, followed by responses like 180 Ringing and 200 OK, confirmed with ACK; BYE terminates the session. Other methods include REGISTER, OPTIONS, CANCEL, SUBSCRIBE and REFER. Response codes mirror HTTP conventions, from provisional 1xx messages to 6xx global failures.

Use

SIP underpins most modern VoIP services, IP PBX systems, video-conferencing platforms and the IMS architecture used for voice over LTE and 5G. Its extensibility and similarity to web protocols contributed to its adoption over the earlier H.323 suite, though interoperability between vendors' extensions remains a practical concern addressed by interoperability testing and profiles such as SIPconnect.
