FreeBSD jail

The FreeBSD jail mechanism is an implementation of operating-system-level virtualisation that allows system administrators to partition a FreeBSD-based computer system into several independent, mini-systems called jails, all sharing the same kernel. It was introduced in FreeBSD version 4.0 (released in 2000) and is commonly credited to Poul-Henning Kamp, building on earlier work with the chroot mechanism.

Overview

A jail extends the traditional chroot environment by virtualising access to the file system, the set of users, and networking. A jailed process cannot access resources outside its jail: it sees only its own directory tree, has its own hostname and IP addresses, and cannot view or signal processes in other jails or on the host. System administrators can confine services such as web or mail servers so that a compromise of one service does not compromise the whole machine.

Features

Jails are managed with the jail utility and jexec, and configured through jail.conf. Over time the mechanism gained support for resource limits (via rctl), virtual network stacks (VNET), CPU pinning, and nested configurations. Unlike full virtual machines, jails impose very little overhead because all jails run on the host kernel. The concept influenced similar technologies elsewhere, including Solaris Containers/Zones.

Use cases

Common uses include service isolation, virtual hosting, building packages in clean environments, and testing software. Management frameworks such as iocage, Bastille, and ezjail simplify jail creation and maintenance.
