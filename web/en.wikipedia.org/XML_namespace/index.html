XML namespace

Defined byW3C Recommendation, 1999
Declaration syntaxxmlns, xmlns:prefix
PurposeDisambiguating element and attribute names

An XML namespace is a collection of names, identified by a Uniform Resource Identifier (URI) reference, that is used in XML documents as element types and attribute names. Namespaces allow documents to combine markup from multiple vocabularies without naming collisions, because two elements with the same local name can be distinguished by the namespaces they belong to.

Namespace declaration

A namespace is declared with the reserved xmlns attribute. Declaring xmlns="http://example.org" makes that URI the default namespace for elements in scope, while xmlns:pfx="http://example.org" binds the prefix pfx, so names may be written in qualified form such as pfx:table. The namespace name is an identifier only; it need not point to a retrievable document.

Motivation

Namespaces became essential as XML was used to mix vocabularies — for example, embedding XHTML inside a document of another type, or combining metadata formats. Before the Namespaces in XML recommendation of January 1999, such combinations risked ambiguity whenever two vocabularies used the same element name for different purposes.

Namespaces and schemas

XML Schema documents associate definitions with a target namespace, so that validation processors can match elements to the vocabulary the schema describes. Attribute names without a prefix belong to no namespace, a rule that often surprises newcomers.
