The Invisible Internet Project (I2P) is an anonymous network layer (implemented as a mixnet) that allows for censorship-resistant, peer-to-peer communication. Anonymous connections are achieved by encrypting the user's traffic (by using end-to-end encryption), and sending it through a volunteer-run network of roughly 55,000 computers distributed around the world. Given the high number of possible paths the traffic can transit, a third party watching a full connection is unlikely to be able to trace its origin or destination.

Design

I2P uses garlic routing, a variant of onion routing in which multiple messages can be bundled into a single "garlic clove" and each peer both routes traffic and runs its own applications. Traffic passes through unidirectional inbound and outbound tunnels, typically three hops each, which are rebuilt frequently. Network information is stored in a distributed hash table called the netDb, maintained using the Kademlia algorithm with floodfill routers.

Unlike Tor, which was designed primarily for accessing the regular internet anonymously through exit nodes, I2P is designed mainly for internal services: hidden websites called "eepsites", anonymous email (I2P-Bote and the bundled mail service), IRC, file sharing and blogging. Outproxies to the clearnet exist but are not the network's focus.

History

I2P began in 2003 as a fork of the Freenet-related Invisible IRC Project. The reference implementation is written in Java and is bundled as a router with applications for web browsing within the network, email and BitTorrent (I2PSnark). A lightweight C++ implementation, i2pd ("Purple I2P"), was developed independently. The software is free and open-source, published under multiple licences.

Terminology

  • Router — the I2P software that routes encrypted packets for the user.
  • Eepsite — a website hosted anonymously within the I2P network, reachable by a .i2p pseudo-top-level domain or a long base-32/base-64 "destination" address.
  • Tunnels — unidirectional paths through a sequence of peers, used separately for inbound and outbound traffic.
  • netDb — the distributed database of router information and destination lease sets.
