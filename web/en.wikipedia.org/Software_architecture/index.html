Software architecture

The software architecture of a system is the set of structures needed to reason about the system, comprising software elements, relations among them, and properties of both. It represents the fundamental design decisions about how a system is organised and how its components communicate, made early because they are costly to change later.

Common styles and patterns

Widely used architectural styles include layered architecture, client–server, pipes and filters, event-driven architecture, microkernel (plug-in) architecture, service-oriented architecture, and microservices. Patterns such as Model–View–Controller address recurring design problems within these styles.

Quality attributes

Architects evaluate designs against quality attributes (also called non-functional requirements) such as performance, scalability, availability, security, modifiability, and testability. Trade-offs are inevitable: improving one attribute often harms another, and architecture documentation and evaluation methods (such as ATAM) exist to make these trade-offs explicit.

History

The discipline emerged in the late 1960s and crystallised in the 1990s with works by Perry and Wolf, Shaw and Garlan, and the "4+1" view model of Philippe Kruchten.
