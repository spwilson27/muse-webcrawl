Ad hoc polymorphism

In programming languages, ad hoc polymorphism is a kind of polymorphism in which polymorphic functions can be applied to arguments of different types, because a polymorphic function can denote a number of distinct and potentially heterogeneous implementations depending on the type of argument(s) to which it is applied. This contrasts with parametric polymorphism, in which a single implementation works uniformly for all types.

In programming languages

The term was coined by Christopher Strachey in his 1967 lectures on fundamental concepts in programming languages, where he distinguished parametric from ad hoc polymorphism. The most familiar mechanisms are function overloading — where the compiler or interpreter selects among implementations by argument types, as with the "+" operator in many languages — and operator overloading. In Haskell, type classes provide a structured and type-safe form of ad hoc polymorphism: a function constrained by a class such as Num dispatches to the implementation defined for each instance type.

Comparison

Where parametric polymorphism (see generic programming) gives the same code for all types, ad hoc polymorphism gives a separate implementation for each type, making it flexible but harder to reason about uniformly. Late binding in object-oriented languages, where method selection occurs at runtime, is sometimes classified separately as inclusion polymorphism.
