Functional dependency

Constraint in relational database theory

In relational database theory, a functional dependency is a constraint between two sets of attributes in a relation (table). A set of attributes X functionally determines a set Y — written X → Y — if, whenever two tuples agree on all the attributes of X, they must also agree on all the attributes of Y. For example, in an employee table, an employee ID functionally determines the employee's name, because each ID belongs to exactly one person.

Properties

A functional dependency is trivial if the determined attributes are a subset of the determining ones. A dependency is full if no proper subset of the determinant suffices. William W. Armstrong showed in 1974 that dependencies can be reasoned about with three inference rules — reflexivity, augmentation and transitivity — which are sound and complete; derived rules include union, decomposition and pseudotransitivity. From a set of dependencies one can compute the closure of a set of attributes, which identifies candidate keys: a set whose closure is the entire relation.

Role in normalisation

Functional dependencies are the basis of database normalisation. Edgar F. Codd's normal forms are defined in terms of them: second normal form forbids partial dependencies on part of a composite key, third normal form and Boyce–Codd normal form progressively eliminate transitive and anomalous dependencies, so that each fact is stored once and update anomalies are avoided. Multivalued dependencies generalise the concept and underlie fourth normal form.
