WebSocket

StandardRFC 6455 (protocol); W3C/WHATWG API
Published2011
URI schemesws: and wss: (secure)
Default ports80 and 443
TransportTCP, single long-lived connection

WebSocket is a computer communications protocol providing full-duplex communication channels over a single TCP connection. It was standardized by the IETF as RFC 6455 in 2011; the companion WebSocket API for web pages is maintained by the WHATWG. WebSocket is distinct from HTTP, but is designed to work over HTTP ports 80 and 443 and to be compatible with existing web infrastructure such as proxies.

How it works

A WebSocket connection begins with an HTTP "upgrade" handshake: the client sends a request with an Upgrade: websocket header, and if the server agrees it replies with status 101 Switching Protocols. Thereafter both parties exchange small framed messages — text or binary — at any time, in either direction, until the connection is closed. Because the connection persists, data can be pushed from server to client instantly, with per-message overhead of as little as two bytes, instead of the heavy request headers of HTTP polling.

Motivation and uses

Before WebSocket, real-time web applications relied on workarounds such as long polling and the Comet techniques, which wasted bandwidth and added latency. WebSocket enables live chat, multiplayer games, collaborative editing, financial tickers, sports updates and live notifications. Higher-level libraries and protocols, such as Socket.IO and MQTT over WebSocket, add reconnection, rooms and messaging patterns on top.

Security

The wss: scheme encrypts traffic with TLS. The protocol includes origin-based safeguards and masking of client frames to protect against cache-poisoning attacks on intermediaries.
