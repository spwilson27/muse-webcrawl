Protocol (object-oriented programming)

Protocols let unrelated classes guarantee a common set of methods.

In object-oriented programming, a protocol is a named set of methods (and sometimes properties) that a class, structure or enumeration can adopt, promising to provide implementations of them. The concept is known by different names in different languages: protocols in Objective-C and Swift, interfaces in Java and C#, traits in Rust (with somewhat broader powers), and type classes in Haskell.

Purpose

Protocols define a contract independently of any class hierarchy. Where inheritance ties a subclass to one particular superclass, protocol conformance lets unrelated types be used interchangeably wherever the protocol's behaviour is required — a form of polymorphism sometimes described as duck typing made explicit and checkable by the compiler. In Swift, for example, the standard library protocols Equatable, Comparable and Codable let generic algorithms work over any conforming type.

Features

Objective-C protocols may declare methods optional as well as required, and objects can be asked at runtime whether they conform. Swift protocols can carry associated types and, through protocol extensions, provide default implementations, enabling "protocol-oriented programming" as an alternative to deep class hierarchies. Java interfaces historically allowed only abstract methods but have since gained default and static methods, narrowing the gap.

Comparison with abstract classes

Unlike an abstract class, a protocol supplies no storage and (in its pure form) no implementation, and a type may conform to many protocols while inheriting from only one class. The trade-off is that protocols cannot capture shared state or guarantee the invariants an abstract base class can.
