API

An API (application programming interface) is a connection between computers or between computer programs. It is a type of software interface, offering a service to other pieces of software. A document or standard that describes how to build such a connection or interface is called an API specification. A computer system that meets this standard is said to implement or expose an API. The term API may refer either to the specification or to the implementation.

In contrast to a user interface, which connects a computer to a person, an application programming interface connects computers or pieces of software to each other. It is not intended to be used directly by a person (the end user) other than a computer programmer who is incorporating it into software. An API is often made up of different parts which act as tools or services that are available to the programmer. A program or a programmer that uses one of these parts is said to call that portion of the API. The calls that make up the API are also known as subroutines, methods, requests, or endpoints. An API specification defines these calls, meaning that it explains how to use or implement them.

Purpose

One purpose of APIs is to hide the internal details of how a system works, exposing only those parts a programmer will find useful and keeping them consistent even if the internal details later change. An API may be custom-built for a particular pair of systems, or it may be a shared standard allowing interoperability among many systems.

There are APIs for programming languages, software libraries, computer operating systems, and computer hardware. APIs originated in the 1940s, though the term did not emerge until the 1960s and 1970s. Contemporary usage of the term API often refers to web APIs, which allow the communication between computers that are joined by the internet. Recent developments in APIs have led to the rise in popularity of microservices, which are loosely coupled services accessed through public APIs.

Web APIs

Web APIs are the defined interfaces through which interactions happen between an enterprise and applications that use its assets. A web API allows interaction between two systems using HTTP protocol, and data is usually exchanged in formats such as JSON or XML. The most common architectural style for web APIs is REST (representational state transfer), which uses standard HTTP methods such as GET, POST, PUT, and DELETE. Other approaches include SOAP, GraphQL, and remote procedure call frameworks.

API documentation and design

Documentation is crucial for the development and maintenance of applications that use APIs. Common specification formats include OpenAPI (formerly Swagger), which allows both humans and computers to understand the capabilities of a service. Well-designed APIs typically offer consistency in naming, predictable error handling, versioning, and appropriate authentication and rate limiting.

Release policies and versioning

APIs may be private (internal to a company), partner-facing, or public. Public APIs are often versioned so that changes do not break existing consumers; breaking changes are usually introduced in a new major version, while old versions are deprecated over a defined schedule.
