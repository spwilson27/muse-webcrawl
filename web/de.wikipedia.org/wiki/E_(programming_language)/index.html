E (Programmiersprache)

Paradigmaobjektorientiert, ereignisgesteuert
Erscheinungsjahr1997
EntwicklerMark S. Miller u. a.
PlattformJava Virtual Machine

E ist eine objektorientierte Programmiersprache für sicheres, verteiltes Rechnen. Sie wurde 1997 von Mark S. Miller und weiteren Entwicklern bei Electric Communities entworfen und baut auf Ideen der Sprachen Joule und Original-E auf. E verbindet ein auf Fähigkeiten (Capabilities) beruhendes Sicherheitsmodell mit einem ereignisgesteuerten Programmiermodell, das Nebenläufigkeit ohne Threads und Sperren ermöglichen soll.

Entwurf

Zentrales Konzept von E sind sogenannte Promises („Versprechen“): Platzhalter für Ergebnisse noch nicht abgeschlossener Berechnungen. Nachrichten an entfernte Objekte werden asynchron versendet; statt zu blockieren, liefert der Aufruf sofort eine Promise zurück. Dadurch lassen sich verteilte Anwendungen schreiben, die nicht an der klassischen Problematik von Deadlocks und blockierenden Aufrufen leiden.

Das Sicherheitsmodell folgt dem Prinzip der objektbasierten Fähigkeiten: Ein Objekt kann nur auf jene Objekte zugreifen, auf die es eine Referenz besitzt. Es gibt keine globalen Namensräume und keine Umgebungsautorität; Zugriffsrechte werden ausschließlich durch das Weitergeben von Referenzen gewährt.

Syntax

Die Syntax von E lehnt sich an Java und Python an. Ein einfaches Beispiel:

def add(x, y) { return x + y }

Objekte werden mit def und Methoden mit to definiert. Die Sprache läuft auf der Java Virtual Machine und kann mit Java-Bibliotheken zusammenarbeiten.

Einfluss

Die Ideen von E beeinflussten unter anderem die Entwicklung sicherer verteilter Systeme sowie spätere Sprachentwürfe und Bibliotheken für asynchrone Programmierung. Das von E geprägte Konzept des „Promise Pipelining“ reduzierte in verteilten Anwendungen die Zahl der nötigen Kommunikationsrunden.
