REST

REST (englisch Representational State Transfer) ist ein Architekturstil für verteilte Systeme, insbesondere für Webdienste. Er wurde im Jahr 2000 von Roy Fielding in seiner Dissertation beschrieben, in der er die Architektur des World Wide Web analysierte. REST-konforme Schnittstellen werden als RESTful bezeichnet und bilden die Grundlage vieler moderner Web-APIs.

Prinzipien

REST beruht auf mehreren Randbedingungen: einer Client-Server-Architektur, Zustandslosigkeit der Kommunikation (jede Anfrage enthält alle nötigen Informationen), einer einheitlichen Schnittstelle, Cachebarkeit von Antworten sowie der Möglichkeit geschichteter Systeme. Im Web werden Ressourcen über URIs identifiziert und mithilfe der HTTP-Methoden angesprochen: GET zum Abrufen, POST zum Erstellen, PUT zum Ersetzen, PATCH zum Ändern und DELETE zum Löschen. Repräsentationen der Ressourcen werden typischerweise als JSON oder XML übertragen.

Reifegrad

Das Richardson Maturity Model beschreibt vier Stufen der REST-Umsetzung, von der Nutzung von HTTP als reines Transportmittel bis hin zu Hypermedia-Steuerung (HATEOAS), bei der Antworten Verknüpfungen zu möglichen Folgeaktionen enthalten.

Abgrenzung

REST ist kein Protokoll und kein Standard, sondern ein Architekturstil. In der Praxis wird der Begriff häufig weiter gefasst und für beliebige HTTP-basierte JSON-Schnittstellen verwendet. Von REST abzugrenzen sind andere Ansätze wie SOAP, GraphQL und gRPC.
