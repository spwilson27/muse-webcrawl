Dynamische Programmanalyse

Symbolbild: Ablaufverfolgung eines Programms

Die dynamische Programmanalyse (englisch dynamic program analysis) ist ein Verfahren der Softwaretechnik, bei dem Eigenschaften eines Computerprogramms untersucht werden, während das Programm tatsächlich ausgeführt wird. Sie steht im Gegensatz zur statischen Programmanalyse, die den Quelltext analysiert, ohne ihn auszuführen.

Verfahren

Da die dynamische Analyse auf realen Ausführungen beruht, liefert sie präzise Informationen über das tatsächliche Laufzeitverhalten, etwa über belegte Speicherbereiche, tatsächlich durchlaufene Ausführungspfade oder konkrete Werte von Variablen. Typische Techniken sind:

  • Profiling: Messung von Laufzeiten und Häufigkeiten von Funktionsaufrufen, etwa mit Werkzeugen wie gprof oder Valgrind.
  • Speicherfehleranalyse: Aufdecken von Speicherlecks, Pufferüberläufen und Zugriffen auf nicht initialisierten Speicher, beispielsweise mit AddressSanitizer.
  • Code Coverage: Bestimmung, welche Teile des Codes durch Tests ausgeführt wurden.
  • Taint-Analyse: Verfolgung des Datenflusses von Benutzereingaben durch das Programm, um Sicherheitslücken zu finden.
  • Instrumentierung: Einfügen zusätzlicher Mess- oder Prüflogik in das Programm, entweder im Quelltext, im Bytecode oder zur Laufzeit.

Vor- und Nachteile

Der Hauptvorteil der dynamischen Analyse liegt in ihrer Genauigkeit: Da sie reale Daten verarbeitet, sind die Ergebnisse frei von vielen Fehlalarmen, die bei statischen Verfahren durch Überapproximation entstehen. Ihr Hauptnachteil ist, dass sie nur Aussagen über die tatsächlich ausgeführten Pfade treffen kann; nicht ausgeführter Code bleibt ununtersucht. Zudem verursacht die Instrumentierung meist einen erheblichen Laufzeit-Overhead.

Anwendungsgebiete

Dynamische Analyse wird in der Qualitätssicherung, im Debugging, in der Leistungsoptimierung und in der IT-Sicherheit eingesetzt. Fuzzing kombiniert dynamische Analyse häufig mit automatisierter Eingabegenerierung, um Absturzursachen systematisch aufzudecken.
