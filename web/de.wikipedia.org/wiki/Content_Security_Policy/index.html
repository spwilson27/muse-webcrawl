Content Security Policy

Die Content Security Policy (CSP) ist ein Sicherheitskonzept für Webanwendungen, das vom World Wide Web Consortium (W3C) standardisiert wurde. Sie wird über den HTTP-Header Content-Security-Policy (früher auch X-Content-Security-Policy) vom Server an den Browser übermittelt und legt fest, aus welchen Quellen eine Webseite Inhalte wie Skripte, Stylesheets, Bilder oder Schriftarten laden darf. Ziel ist es vor allem, Cross-Site-Scripting (XSS) und das Einschleusen fremder Inhalte zu erschweren.

Funktionsweise

Die Policy besteht aus einer Liste von Direktiven, die jeweils durch Semikolons getrennt werden. Zu den wichtigsten Direktiven zählen:

  • default-src – Fallback für alle nicht näher bestimmten Ressourcenarten
  • script-src – erlaubte Quellen für JavaScript
  • style-src – erlaubte Quellen für CSS
  • img-src – erlaubte Quellen für Bilder
  • connect-src – erlaubte Ziele für Fetch- und XHR-Anfragen
  • frame-ancestors – legt fest, welche Seiten die Seite in einem Frame einbetten dürfen

Als Werte können unter anderem 'self' (nur die eigene Herkunft), 'none' (gar keine Quelle), Hostnamen, Schemata wie https: sowie Nonces und Hashes angegeben werden. Mit 'unsafe-inline' werden Inline-Skripte erlaubt, was den Schutz jedoch deutlich schwächt.

Berichtsmodus

Über den Header Content-Security-Policy-Report-Only kann eine Policy zunächst nur überwacht werden: Verstöße werden nicht blockiert, sondern an eine per report-uri bzw. report-to angegebene Adresse gemeldet. So lässt sich eine Policy testen, bevor sie scharf geschaltet wird.

Geschichte

Das Konzept geht auf einen Vorschlag von Robert Hansen aus dem Jahr 2004 zurück. Die erste Implementierung erschien 2010 in Mozilla Firefox 4. Das W3C veröffentlichte die Spezifikation in mehreren Stufen (CSP Level 1, 2 und 3); alle gängigen Browser unterstützen CSP heute.
