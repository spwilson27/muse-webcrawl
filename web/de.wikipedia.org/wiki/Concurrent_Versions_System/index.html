Concurrent Versions System

Das Concurrent Versions System (CVS) ist ein zentrales Versionsverwaltungssystem für Dateien, das vor allem in der Softwareentwicklung eingesetzt wurde. Es erlaubte mehreren Entwicklern, gleichzeitig an denselben Dateien zu arbeiten, und verwaltete die vollständige Änderungsgeschichte. CVS war über Jahre das dominierende System in der Open-Source-Entwicklung, wurde aber ab den 2000er-Jahren weitgehend durch Subversion und später durch verteilte Systeme wie Git abgelöst.

Geschichte

CVS entstand 1986 als Aufsatz (Frontend) auf dem Revision Control System (RCS) von Dick Grune an der Vrije Universiteit Amsterdam; die verbreitetste Implementierung stammte wesentlich von Brian Berliner (1989). Plattformen wie SourceForge machten CVS in den 1990er-Jahren zum Standard für freie Softwareprojekte.

Funktionsweise

CVS verwaltet die Dateien zentral in einem Repository auf einem Server. Entwickler holen sich eine Arbeitskopie (checkout), ändern Dateien lokal und spielen die Änderungen zurück (commit). Änderungen an verschiedenen Zeilen derselben Datei führt CVS automatisch zusammen; bei Konflikten muss der Entwickler manuell eingreifen. Markierungen (tags) kennzeichnen Versionsstände, Entwicklungszweige (branches) erlauben parallele Entwicklungslinien. Als Grundlage dient das Kopieren-Ändern-Zusammenführen-Modell statt exklusiver Dateisperren, was dem System seinen Namen gab.

Schwächen und Nachfolger

Zu den bekannten Schwächen zählen fehlende atomare Commits, Probleme beim Umbenennen und Verschieben von Dateien, fehlende Versionsverwaltung von Verzeichnissen und umständliche Binärdateien. Subversion wurde ausdrücklich als CVS-Nachfolger mit Behebung dieser Mängel entwickelt; später setzte sich in vielen Projekten Git durch. CVS wird heute nur noch selten und überwiegend in Altsystemen verwendet.
