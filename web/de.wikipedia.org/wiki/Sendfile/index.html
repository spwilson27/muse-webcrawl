sendfile

sendfile ist ein Systemaufruf in Unix-ähnlichen Betriebssystemen, mit dem Daten direkt zwischen zwei Dateideskriptoren – typischerweise einer Datei und einem Socket – übertragen werden können, ohne sie durch den Userspace zu kopieren. Dadurch werden Kontextwechsel und Kopien vermieden, was insbesondere Webserver und Dateiserver deutlich beschleunigt (sogenanntes Zero-Copy-Verfahren).

Funktionsweise

Bei der klassischen Übertragung liest ein Serverprozess die Datei mit read() in einen Puffer im Benutzerspeicher und schreibt ihn anschließend mit write() auf den Socket. Die Daten werden dabei mehrfach zwischen Kernel- und User-Speicher kopiert. Mit sendfile() entfällt der Umweg: Der Kernel kopiert die Daten intern vom Page Cache direkt an den Socket (beziehungsweise veranlasst DMA-Transfers der Hardware), und der Prozess erhält lediglich die Kontrolle über die übertragene Bytezahl.

Syntax unter Linux

#include <sys/sendfile.h>

ssize_t sendfile(int out_fd, int in_fd, off_t *offset, size_t count);

Der Parameter in_fd muss eine Datei bezeichnen, die mit mmap() abbildbar ist (in der Praxis eine reguläre Datei), während out_fd üblicherweise ein Socket ist. Seit Linux 2.6.33 können beide Deskriptoren allgemeiner gehalten sein. Ein einzelner Aufruf überträgt höchstens 0x7ffff000 Bytes (rund 2 GB), sodass Server die Übertragung in einer Schleife aufrufen.

Verfügbarkeit und Verwendung

sendfile wurde erstmals in Linux 2.2 eingeführt. Ähnliche Schnittstellen existieren in FreeBSD, Solaris und anderen Systemen; unter Windows entspricht dem die Funktion TransmitFile. Bekannte Serverprogramme wie Apache HTTP Server und nginx nutzen sendfile standardmäßig für die Auslieferung statischer Dateien. In höheren Sprachen ist der Mechanismus unter anderem über Java NIO (FileChannel.transferTo) zugänglich.

Grenzen

Da die Daten den Userspace nie durchlaufen, kann der Prozess sie unterwegs nicht verändern – Verschlüsselung (TLS) oder Kompression lassen sich daher nicht ohne Weiteres mit sendfile kombinieren. Moderne Ansätze wie Kernel-TLS (kTLS) oder die neueren Schnittstellen copy_file_range und splice erweitern das Zero-Copy-Konzept.
