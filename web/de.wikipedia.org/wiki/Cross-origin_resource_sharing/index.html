Cross-Origin Resource Sharing

Cross-Origin Resource Sharing (kurz CORS) ist ein Mechanismus des Webs, der auf HTTP-Headern beruht und es einem Server erlaubt anzugeben, welche fremden Ursprünge (Origins) über einen Browser auf seine Ressourcen zugreifen dürfen. CORS lockert damit gezielt die Same-Origin-Policy, die Webseiten den Zugriff auf Antworten fremder Herkunft grundsätzlich untersagt.

Hintergrund

Aus Sicherheitsgründen darf ein Skript, das von einer Herkunft geladen wurde, zwar Anfragen an andere Server senden, deren Antworten jedoch nur lesen, wenn der Zielserver dies erlaubt. Ein „Ursprung“ (Origin) setzt sich aus Schema (etwa https), Host und Port zusammen. Ohne CORS wäre die Nutzung vieler Web-APIs von anderen Domains aus – etwa von Single-Page-Anwendungen – nicht möglich.

Ablauf

Bei einfachen Anfragen (z. B. GET ohne besondere Header) sendet der Browser die Anfrage mit einem Origin-Header; der Server antwortet mit Access-Control-Allow-Origin und nennt die zugelassenen Ursprünge oder „*“. Erhält der Browser keine passende Freigabe, blockiert er den Zugriff des Skripts auf die Antwort.

Bei nicht einfachen Anfragen – etwa mit Methoden wie PUT oder DELETE oder eigenen Headern – sendet der Browser zunächst eine Voranfrage (Preflight) mit der Methode OPTIONS, in der er Methode und Header des eigentlichen Requests ankündigt. Der Server erklärt per Antwort-Headern (z. B. Access-Control-Allow-Methods, Access-Control-Allow-Headers), ob die Anfrage zulässig ist. Für Anfragen mit Cookies oder Zugangsdaten muss der Server die konkrete Herkunft nennen und Access-Control-Allow-Credentials: true senden; „*“ genügt dann nicht.

Sicherheit

CORS ist ein reiner Browser-Mechanismus und schützt den Server nicht vor Zugriffen durch andere Programme. Eine zu großzügige Konfiguration – etwa das Spiegeln beliebiger Origins zusammen mit Credentials – kann Daten ungewollt für fremde Webseiten lesbar machen. CORS verhindert zudem kein Cross-Site Request Forgery; dafür sind eigene Maßnahmen nötig.
