Distributed Component Object Model


Kommunikation zwischen verteilten Komponenten

Das Distributed Component Object Model (DCOM) ist eine von Microsoft entwickelte Technologie für die Kommunikation zwischen Softwarekomponenten auf verschiedenen Rechnern in einem Netzwerk. DCOM erweitert das lokale Component Object Model (COM), sodass Objekte auf entfernten Rechnern so angesprochen werden können, als befänden sie sich lokal.

Technik

DCOM baut auf einer RPC-Implementierung (Remote Procedure Call) auf und nutzt zur Identifikation von Objekten und Schnittstellen GUIDs. Die Kommunikation erfolgt standardmäßig über dynamisch zugewiesene TCP-Ports, was den Einsatz durch Firewalls hindurch erschwert. Konfiguration und Sicherheitseinstellungen werden unter Windows über das Werkzeug dcomcnfg verwaltet; Authentifizierung und Zugriffssteuerung übernimmt das Windows-Sicherheitsmodell.

Geschichte und Verbreitung

Microsoft stellte DCOM 1996 mit Windows NT 4.0 vor. Es wurde vor allem in Unternehmenssoftware, in der Industrieautomatisierung und im SCADA-Bereich eingesetzt; die OPC-Spezifikationen (OLE for Process Control) basierten lange auf DCOM, bevor mit OPC UA ein plattformunabhängiger Nachfolger entstand. Als Konkurrenztechnologien gelten CORBA und Java RMI.

Kritik und Nachfolge

DCOM gilt als komplex zu konfigurieren und schwer durch Firewalls zu betreiben. Historisch sorgte der Blaster-Wurm 2003 für Aufmerksamkeit, der eine Schwachstelle im DCOM-RPC-Dienst ausnutzte. Moderne Anwendungen setzen für verteilte Kommunikation überwiegend auf Webservices, REST, gRPC oder Nachrichtenwarteschlangen; DCOM wird in .NET durch Windows Communication Foundation und spätere Technologien abgelöst.
