Leser-Schreiber-Problem

Das Leser-Schreiber-Problem (englisch readers–writer problem) ist ein klassisches Synchronisationsproblem der Informatik. Eine Leser-Schreiber-Sperre (readers–writer lock, RW-Lock) ist ein Synchronisationsmechanismus, der den gemeinsamen Zugriff mehrerer Threads oder Prozesse auf eine Ressource so steuert, dass beliebig viele Leser gleichzeitig lesen dürfen, während ein Schreiber die Ressource ausschließlich belegt.

Regeln

  • Mehrere Leser dürfen gleichzeitig auf die Daten zugreifen, solange kein Schreiber aktiv ist.
  • Ein Schreiber benötigt exklusiven Zugriff: Während er schreibt, darf weder ein weiterer Schreiber noch ein Leser zugreifen, da sonst inkonsistente Zustände gelesen würden.

Gegenüber einem einfachen Mutex kann die Leser-Schreiber-Sperre bei leseintensiven Arbeitslasten eine deutlich höhere Parallelität ermöglichen.

Fairnessvarianten

  • Leserpräferenz: Leser werden bevorzugt; bei ständig nachrückenden Lesern kann ein Schreiber unbegrenzt lange warten („verhungern").
  • Schreiberpräferenz: Ein wartender Schreiber blockiert neue Leser, sodass wartende Leser verzögert werden.
  • Faire Varianten: Zugriffe werden in Ankunftsreihenfolge (FIFO) gewährt.

Implementierungen

Leser-Schreiber-Sperren sind in vielen Laufzeitumgebungen vorhanden, beispielsweise als pthread_rwlock in POSIX, als std::shared_mutex in C++17, als ReentrantReadWriteLock in Java oder als RwLock in Rust. Anwendungsbeispiele sind Caches, Konfigurationsdaten und Indexstrukturen von Datenbanken, bei denen Lesezugriffe die Schreibzugriffe deutlich überwiegen.
