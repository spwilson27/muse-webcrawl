Command Query Responsibility Segregation

Command Query Responsibility Segregation (CQRS) ist ein Architekturmuster der Softwareentwicklung, bei dem das Datenmodell zum Ändern von Daten (Befehle, commands) strikt vom Datenmodell zum Lesen von Daten (Abfragen, queries) getrennt wird. Das Muster geht auf Überlegungen von Greg Young zurück und erweitert das Prinzip der Command-Query Separation von der Methodenebene auf die Ebene der Systemarchitektur.

Beschreibung

In einer CQRS-Architektur werden Schreiboperationen über ein Befehlsmodell verarbeitet, das die Geschäftslogik und die Konsistenzregeln enthält. Leseoperationen greifen dagegen auf ein separates, für Abfragen optimiertes Lesemodell zu, das etwa als denormalisierte Sicht oder eigene Datenbank vorliegen kann. Die Synchronisation zwischen beiden Modellen erfolgt häufig asynchron über Ereignisse; CQRS wird daher oft mit Event Sourcing kombiniert, bei dem nicht der aktuelle Zustand, sondern die Folge aller Zustandsänderungen gespeichert wird.

Vor- und Nachteile

Zu den Vorteilen zählen die unabhängige Skalierbarkeit von Lese- und Schreibzugriffen, optimierte Datenmodelle für beide Aufgaben und eine klare Abbildung der Fachlogik. Dem stehen eine erheblich höhere Komplexität, der Aufwand für die Synchronisation der Modelle und eine eventuell nur eventuelle Konsistenz der Lesedaten gegenüber. CQRS gilt daher als Muster für komplexe Fachdomänen und Systeme mit sehr unterschiedlichen Lese- und Schreibanforderungen, nicht als Standardlösung für einfache Anwendungen.
