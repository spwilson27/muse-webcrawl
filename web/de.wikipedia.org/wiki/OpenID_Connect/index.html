OpenID Connect

Erstveröffentlichung2014
OrganisationOpenID Foundation
BasisOAuth 2.0
ArtAuthentifizierungsprotokoll

OpenID Connect (OIDC) ist ein Authentifizierungsprotokoll, das auf dem Autorisierungsframework OAuth 2.0 aufbaut. Es wurde von der OpenID Foundation entwickelt und im Februar 2014 als Standard verabschiedet. OpenID Connect ermöglicht es Clients, die Identität eines Endbenutzers anhand einer Authentifizierung durch einen Autorisierungsserver zu überprüfen und grundlegende Profilinformationen über den Benutzer auf interoperable, REST-ähnliche Weise zu erhalten.

Grundlagen

Während OAuth 2.0 lediglich ein Framework zur Autorisierung darstellt, fügt OpenID Connect eine Identitätsschicht hinzu. Zentrales Element ist das ID Token, ein JSON Web Token (JWT), das Informationen (sogenannte Claims) über den authentifizierten Benutzer enthält, darunter eine eindeutige Kennung (sub), den Aussteller (iss) und die Zielgruppe (aud). Das ID Token ist digital signiert, sodass der Client seine Echtheit prüfen kann.

Die Beteiligten werden als OpenID Provider (OP, der Identitätsanbieter), Relying Party (RP, die Anwendung) und der Endbenutzer bezeichnet. Ergänzend zum ID Token bietet der UserInfo-Endpunkt standardisierte Profilangaben wie Name, E-Mail-Adresse und Profilbild.

Abläufe

OpenID Connect definiert mehrere Abläufe (Flows):

  • Authorization Code Flow – der Client erhält zunächst einen Autorisierungscode und tauscht diesen serverseitig gegen Token ein; dieser Ablauf gilt als der sicherste.
  • Implicit Flow – Token werden direkt über den Browser zurückgegeben; er wird heute aus Sicherheitsgründen nicht mehr empfohlen.
  • Hybrid Flow – eine Kombination aus beiden Verfahren.

Über den Discovery-Mechanismus (/.well-known/openid-configuration) kann ein Client die Endpunkte und Fähigkeiten eines OpenID Providers automatisch ermitteln.

Verbreitung

OpenID Connect hat das ältere OpenID 2.0 weitgehend abgelöst und wird von zahlreichen großen Identitätsanbietern wie Google, Microsoft und Apple sowie von Unternehmenslösungen und Open-Source-Projekten wie Keycloak unterstützt. Es bildet die Grundlage vieler Single-Sign-on-Umsetzungen im Web und in mobilen Anwendungen.
