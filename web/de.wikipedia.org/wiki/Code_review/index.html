Code Review

Ein Code Review (deutsch etwa „Quelltextprüfung“) ist ein Verfahren der Qualitätssicherung in der Softwareentwicklung, bei dem Quelltext von einem oder mehreren Entwicklern gelesen und beurteilt wird, die nicht (allein) dessen Autoren sind. Ziel ist es, Fehler früh zu finden, die Verständlichkeit des Codes zu sichern und Wissen im Team zu verteilen.

Formen

Klassische Formen sind die formale Inspektion nach Michael Fagan aus den 1970er-Jahren, der weniger formelle Walkthrough sowie das Pair Programming, bei dem der Review laufend während des Schreibens erfolgt. Heute dominieren werkzeuggestützte, asynchrone Verfahren: Änderungen werden als Pull- oder Merge-Request in Systemen wie GitHub oder GitLab eingereicht, von Kollegen kommentiert und erst nach Freigabe in den Hauptzweig übernommen.

Ziele und Wirkung

Studien und Praxisberichte nennen als wesentliche Effekte die Fehlerfindung – Reviews entdecken viele Defekte, die Tests entgehen –, die Einhaltung von Programmierrichtlinien, den Wissenstransfer und ein gemeinsames Verantwortungsgefühl für den Code („collective code ownership“). Gleichzeitig sind Reviews zeitaufwendig; zu große Änderungspakete und unfreundliche Kommentarkultur gelten als typische Fallstricke.
