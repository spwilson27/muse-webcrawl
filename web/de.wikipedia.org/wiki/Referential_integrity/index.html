Referentielle Integrität

Referentielle Integrität ist eine Eigenschaft relationaler Datenbanken, die sicherstellt, dass Verweise zwischen Tabellen konsistent sind: Jeder Fremdschlüssel in einer Tabelle muss entweder auf einen tatsächlich existierenden Primärschlüssel in der referenzierten Tabelle verweisen oder den Nullwert annehmen. Dadurch werden „verwaiste“ Datensätze verhindert.

Regeln bei Änderungen

Was beim Löschen oder Ändern eines referenzierten Datensatzes geschehen soll, wird über referentielle Aktionen festgelegt:

  • RESTRICT / NO ACTION: Die Operation wird abgelehnt, solange noch Verweise bestehen.
  • CASCADE: Die Änderung wird auf die verweisenden Datensätze fortgepflanzt – beim Löschen werden auch die abhängigen Sätze gelöscht, beim Ändern des Schlüssels mitgeführt.
  • SET NULL: Die Fremdschlüssel der verweisenden Datensätze werden auf NULL gesetzt.
  • SET DEFAULT: Die Fremdschlüssel werden auf einen vorgegebenen Standardwert gesetzt.

Beispiel

Enthält eine Tabelle „Bestellungen“ eine Spalte kunden_id, die als Fremdschlüssel auf die Tabelle „Kunden“ verweist, so verhindert die referentielle Integrität, dass eine Bestellung für einen nicht existierenden Kunden angelegt oder ein Kunde gelöscht wird, dessen Bestellungen noch vorhanden sind (sofern keine Kaskade definiert ist).

Umsetzung

In SQL werden Fremdschlüssel mit dem FOREIGN-KEY-Constraint deklariert; das Datenbankmanagementsystem überwacht die Einhaltung bei jeder INSERT-, UPDATE- und DELETE-Operation. Neben der referentiellen Integrität zählen die Entitätsintegrität (Eindeutigkeit und Nicht-Nullheit des Primärschlüssels) und die Domänenintegrität zu den grundlegenden Integritätsbedingungen des relationalen Modells, das Edgar F. Codd ab 1970 entwickelte.
