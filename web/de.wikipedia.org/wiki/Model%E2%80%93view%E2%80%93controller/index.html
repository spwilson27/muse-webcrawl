Model View Controller

Model View Controller (MVC) ist ein Architekturmuster der Softwareentwicklung, das eine Anwendung in drei miteinander verbundene Komponenten aufteilt: das Datenmodell (Model), die Darstellung (View) und die Steuerung (Controller). Ziel ist eine klare Trennung von Datenhaltung, Geschäftslogik und Präsentation, um Wartbarkeit, Wiederverwendbarkeit und Testbarkeit zu verbessern.

Komponenten

  • Model (Modell): verwaltet die Daten und die Geschäftsregeln der Anwendung; es kennt weder View noch Controller.
  • View (Ansicht): stellt die Daten des Modells für den Benutzer dar, etwa als Fenster, Webseite oder Bericht; eine View liest Daten aus dem Modell.
  • Controller (Steuerung): nimmt Eingaben des Benutzers entgegen, verarbeitet sie und veranlasst Änderungen am Modell oder die Auswahl einer View.

Änderungen am Modell können über ein Beobachter-Muster (Observer) an die Views gemeldet werden, die sich daraufhin aktualisieren.

Geschichte

MVC wurde 1978/79 von Trygve Reenskaug am Xerox Palo Alto Research Center (PARC) im Rahmen der Entwicklung von Smalltalk beschrieben und in Smalltalk-80 als Grundgerüst grafischer Benutzeroberflächen umgesetzt. Später wurde das Muster zum prägenden Paradigma vieler Frameworks.

Verbreitung

MVC ist vor allem durch Webframeworks weit verbreitet, darunter Ruby on Rails, Django (dort als „Model-Template-View“ variiert), Laravel, ASP.NET MVC und Spring MVC. Auch Desktop-Frameworks wie Apples Cocoa greifen auf MVC zurück. Verwandte Muster sind Model-View-Presenter (MVP) und Model-View-ViewModel (MVVM), die insbesondere die Zuständigkeiten von View und Controller anders verteilen.
