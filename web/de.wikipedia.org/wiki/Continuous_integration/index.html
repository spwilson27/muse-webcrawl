Continuous Integration

Continuous Integration (CI, deutsch „kontinuierliche Integration“) ist eine Praxis der Softwareentwicklung, bei der alle Entwickler ihre Änderungen häufig – idealerweise mehrmals täglich – in einen gemeinsamen Hauptzweig der Versionsverwaltung integrieren. Jede Integration wird durch einen automatisierten Build und automatisierte Tests verifiziert, damit Fehler frühzeitig erkannt werden.

Geschichte und Prinzipien

Der Begriff stammt aus dem Extreme Programming der späten 1990er Jahre und wurde durch Martin Fowler und andere Autoren verbreitet. Zu den Kernpraktiken zählen ein einziges Code-Repository, automatisierte Builds und Tests, kurze Build-Zeiten, das Testen in einer produktionsähnlichen Umgebung und die Verpflichtung, einen fehlerhaften Build vorrangig zu reparieren.

Werkzeuge

CI wird durch spezialisierte Server unterstützt, die jeden Commit überwachen und den Build-Prozess auslösen. Bekannte Systeme sind Jenkins, GitLab CI, GitHub Actions, Travis CI und CircleCI. Continuous Integration ist die Grundlage für die weitergehenden Verfahren Continuous Delivery und Continuous Deployment, bei denen getestete Änderungen auch laufend ausgeliefert beziehungsweise bereitgestellt werden.
