Return-to-libc-Angriff

Ein Return-to-libc-Angriff ist eine Angriffstechnik auf Computerprogramme, bei der ein Pufferüberlauf ausgenutzt wird, um die Rücksprungadresse auf dem Stack so zu verändern, dass statt in eingeschleusten Code in eine Funktion der Standard-C-Bibliothek (libc) gesprungen wird – typischerweise system(). Die Technik umgeht Schutzmechanismen, die den Stack als nicht ausführbar markieren (NX-Bit, DEP).

Funktionsweise

Der Angreifer überschreibt die gespeicherte Rücksprungadresse mit der Adresse einer libc-Funktion und legt deren Argumente – etwa einen Zeiger auf die Zeichenkette /bin/sh – auf dem Stack bereit. Kehrt die verwundbare Funktion zurück, wird stattdessen die Bibliotheksfunktion mit den präparierten Argumenten ausgeführt und startet beispielsweise eine Shell mit den Rechten des angegriffenen Prozesses.

Geschichte und Weiterentwicklung

Die Technik wurde Ende der 1990er Jahre beschrieben, als nicht-ausführbare Stacks als Gegenmaßnahme gegen klassische Shellcode-Angriffe eingeführt wurden. Eine Verallgemeinerung ist das Return-Oriented Programming (ROP), bei dem kurze vorhandene Codefragmente („Gadgets") zu einer Kette verbunden werden.

Gegenmaßnahmen

  • Address Space Layout Randomization (ASLR) erschwert das Auffinden der libc-Adressen.
  • Stack-Canaries erkennen das Überschreiben der Rücksprungadresse.
  • Sichere Programmierpraktiken und Bounds-Checking verhindern den Pufferüberlauf selbst.
