Remote Procedure Call

Ein Remote Procedure Call (RPC, deutsch „entfernter Prozeduraufruf") ist ein Kommunikationsparadigma in verteilten Systemen, bei dem ein Programm eine Prozedur oder Funktion auf einem anderen Rechner aufrufen kann, so als wäre sie lokal. Die Übermittlung der Parameter und Rückgabewerte über das Netzwerk wird dabei weitgehend vor dem Programmierer verborgen.

Funktionsweise

Die Schnittstelle eines Dienstes wird üblicherweise in einer Interface-Beschreibungssprache definiert. Daraus werden Client- und Server-Stubs generiert, die das Serialisieren der Aufrufdaten (Marshalling), den Transport und das Entpacken auf der Gegenseite übernehmen. Der Server führt die angeforderte Prozedur aus und sendet das Ergebnis zurück.

Implementierungen und Kritik

Bekannte RPC-Systeme sind ONC RPC (Sun RPC), DCE/RPC, CORBA, Java RMI, XML-RPC, SOAP sowie das moderne gRPC von Google, das auf HTTP/2 und Protocol Buffers setzt. Kritisch wird angemerkt, dass Fernaufrufe sich in Latenz, Ausfallverhalten und Sicherheit grundlegend von lokalen Aufrufen unterscheiden und eine vollständige Abstraktion dieser Unterschiede („Verteiltheitstransparenz") in der Praxis problematisch sein kann.
