Code Smell

Ein Code Smell (deutsch etwa „Code-Geruch“) ist ein Hinweis im Quelltext eines Programms, der auf ein tieferliegendes Problem des Entwurfs hindeuten kann, ohne dass das Programm notwendigerweise fehlerhaft ist. Der Begriff wurde durch Kent Beck geprägt und durch Martin Fowlers Buch Refactoring (1999) verbreitet.

Typische Code Smells

  • Doppelter Code (duplicated code): dieselbe Logik kommt an mehreren Stellen vor
  • Lange Methode (long method): eine Funktion umfasst sehr viele Zeilen und Verantwortlichkeiten
  • Große Klasse (large class / god class): eine Klasse bündelt zu viele Aufgaben
  • Lange Parameterliste (long parameter list): Methoden mit übermäßig vielen Argumenten
  • Neid (feature envy): eine Methode greift stärker auf fremde Daten zu als auf eigene
  • Schrotflinten-Chirurgie (shotgun surgery): eine einzige Änderung erfordert Eingriffe an vielen Stellen
  • Spekulative Allgemeinheit: vorsorglich gebaute, nie genutzte Abstraktionen

Umgang

Code Smells sind keine Fehler, sondern Diagnosehinweise. Die übliche Reaktion ist Refactoring: Der Code wird in kleinen Schritten umgebaut, bis der Smell verschwindet. Analyseprogramme (Linter und Werkzeuge zur statischen Codeanalyse) können viele Smells automatisch aufspüren und werden heute routinemäßig in der Qualitätssicherung eingesetzt.
