Branch (Versionsverwaltung)

Ein Branch (englisch für „Zweig“) ist in der Versionsverwaltung ein Entwicklungszweig, der parallel zur Hauptlinie (häufig main oder früher master genannt) verläuft. Branches erlauben es, neue Funktionen, Fehlerkorrekturen oder Experimente isoliert zu entwickeln, ohne die stabile Version zu beeinträchtigen.

Arbeitsweise

Beim Erstellen eines Branches zweigt die Versionsgeschichte von einem bestimmten Commit ab. Änderungen im Branch wirken sich nicht auf andere Zweige aus, bis sie durch einen Merge (Zusammenführen) übernommen werden. Dabei können Konflikte auftreten, wenn dieselben Stellen in beiden Zweigen unterschiedlich verändert wurden. Verteilte Systeme wie Git machen Branches besonders billig: Sie sind dort nur Zeiger auf Commits, während ältere zentrale Systeme wie CVS oder Subversion Verzeichnis-Kopien anlegten.

Strategien

Bekannte Arbeitsmodelle sind Git Flow mit langlebigen Entwicklungs- und Release-Zweigen, GitHub Flow mit kurzlebigen Feature-Branches und Pull Requests sowie trunkbasierte Entwicklung, bei der fast ohne Zweige gearbeitet wird.
