Defensive Programmierung

Aus Wikipedia, der freien Enzyklopädie

Defensive Programmierung (englisch defensive programming) ist eine Vorgehensweise in der Softwareentwicklung, bei der Programme so geschrieben werden, dass sie auch bei unvorhergesehenen Eingaben, fehlerhaften Daten und unerwarteten Zuständen kontrolliert und sicher reagieren, statt abzustürzen oder Schaden anzurichten.

Techniken

  • Eingaben an Systemgrenzen konsequent validieren (statt „Garbage in, garbage out").
  • Annahmen durch Zusicherungen (Assertions) prüfen.
  • Fehlerbehandlung mit sinnvollen Standardwerten und klar definierten Ausnahmen.
  • Unveränderlichkeit (Immutability) und defensive Kopien, damit fremder Code interne Zustände nicht unerwartet verändert.
  • Ressourcen in allen Pfaden freigeben (etwa try-finally).

Abgrenzung

Defensive Programmierung unterscheidet sich von übermäßiger Absicherung jeder einzelnen Zeile: Prüfungen gehören vor allem an Schnittstellen und Vertrauensgrenzen. Zu viel Vorsicht kann Code unübersichtlich machen; zu wenig führt zu Sicherheitslücken wie Pufferüberläufen oder Injection-Angriffen.
