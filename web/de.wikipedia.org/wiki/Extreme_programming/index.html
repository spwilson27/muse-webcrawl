Extreme Programming

Extreme Programming (XP)

KernpraktikenPair Programming, TDD, Continuous Integration, Refactoring

Extreme Programming (XP) ist eine Methode der agilen Softwareentwicklung, die bewährte Praktiken des Programmierens „extrem" konsequent und kontinuierlich anwendet. Sie wurde maßgeblich von Kent Beck entwickelt und 1999 in seinem Buch Extreme Programming Explained beschrieben. XP zählt zu den einflussreichsten Ansätzen der agilen Bewegung und prägte das Agile Manifest von 2001 mit.

Werte und Praktiken

XP beruht auf den Werten Kommunikation, Einfachheit, Feedback, Mut und Respekt. Zu den zwölf Praktiken der ursprünglichen Fassung gehören unter anderem:

  • Pair Programming – zwei Entwickler arbeiten an einem Arbeitsplatz.
  • Testgetriebene Entwicklung (TDD) – Tests werden vor dem Code geschrieben.
  • Kontinuierliche Integration – Änderungen werden mehrmals täglich integriert.
  • Refactoring – laufende Verbesserung der Code-Struktur ohne Verhaltensänderung.
  • Kleine Releases und ein Kunde vor Ort (On-Site Customer).
  • Einfaches Design, gemeinsame Code-Verantwortung und ein nachhaltiges Arbeitstempo (40-Stunden-Woche).

Ablauf

Die Entwicklung verläuft in kurzen Iterationen von ein bis drei Wochen. Anforderungen werden als User Stories auf Karten festgehalten; im Planungsspiel (Planning Game) schätzen Entwickler den Aufwand, und der Kunde priorisiert. Qualitätsprobleme sollen durch das dichte Feedback der Praktiken früh sichtbar werden.

Verbreitung und Kritik

Viele XP-Praktiken wie TDD, Pair Programming und Continuous Integration sind heute Standard in der professionellen Softwareentwicklung, auch außerhalb ausgewiesener XP-Teams. Kritiker wenden ein, dass die Methode stark von disziplinierten Teams und einem verfügbaren Kunden abhänge und in verteilten oder sicherheitskritischen Projekten nur eingeschränkt anwendbar sei.
