Duck-Typing

Duck-Typing (englisch duck typing) ist ein Konzept der objektorientierten Programmierung, bei dem der Typ eines Objekts nicht durch seine Klasse oder eine deklarierte Schnittstelle bestimmt wird, sondern durch die Menge der Methoden und Attribute, die das Objekt zur Laufzeit tatsächlich bereitstellt. Der Name geht auf den sogenannten „Ententest" zurück: „Wenn es wie eine Ente aussieht, wie eine Ente schwimmt und wie eine Ente schnattert, dann ist es wahrscheinlich eine Ente."

Prinzip

Beim Duck-Typing wird ein Objekt in einem bestimmten Kontext verwendet, ohne dass seine Klasse vorab festgelegt sein muss. Entscheidend ist allein, ob das Objekt die im jeweiligen Programmteil aufgerufenen Methoden unterstützt. Dadurch entfällt die Notwendigkeit expliziter Schnittstellendeklarationen oder Vererbungshierarchien.

class Ente:
    def schnattern(self):
        return "Quak!"

class Hund:
    def schnattern(self):
        return "Quak?"

def lasse_schnattern(tier):
    return tier.schnattern()

Beide Objekte können an die Funktion übergeben werden, weil sie die Methode schnattern besitzen – unabhängig von ihrer Klasse.

Verbreitung

Duck-Typing ist ein zentrales Merkmal dynamisch typisierter Programmiersprachen wie Python, Ruby, JavaScript und Smalltalk. In statisch typisierten Sprachen wird ein ähnliches Verhalten über strukturelle Typisierung (englisch structural typing) erreicht, etwa in Go, TypeScript oder über Templates in C++.

Vor- und Nachteile

Zu den Vorteilen zählen hohe Flexibilität, geringer Boilerplate-Code und eine lose Kopplung zwischen Komponenten. Als Nachteile gelten, dass Typfehler häufig erst zur Laufzeit auftreten und die Lesbarkeit sowie Werkzeugunterstützung (etwa Autovervollständigung) erschwert werden können.
