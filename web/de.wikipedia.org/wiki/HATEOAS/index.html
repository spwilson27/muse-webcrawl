HATEOAS

HATEOAS
AusgeschriebenHypermedia as the Engine of Application State
KontextREST-Architekturstil (Roy Fielding, 2000)
ZielVerknüpfungen in Antworten treiben die Navigation einer API

HATEOAS (Akronym für Hypermedia as the Engine of Application State) ist ein Grundprinzip der REST-Architektur für verteilte Systeme. Es besagt, dass ein Client mit einer REST-Anwendung ausschließlich über Hypermedia interagieren soll, die der Server dynamisch in seinen Antworten bereitstellt – ähnlich wie ein Mensch eine Website bedient, indem er den dort angebotenen Links und Formularen folgt, ohne deren Adressen vorab zu kennen.

Prinzip

Bei einer HATEOAS-konformen API enthält jede Antwort neben den Nutzdaten auch Verknüpfungen (Links) zu den Aktionen, die auf der Ressource im aktuellen Zustand möglich sind – zum Beispiel „bezahlen“, „stornieren“ oder „zur nächsten Seite“. Der Client muss daher keine URL-Schemata auswendig kennen und sich nicht auf eine fest verdrahtete Dokumentation verlassen; er folgt den übermittelten Links mit ihren Relationen (rel-Attributen) und Medientypen. Dadurch lässt sich der Server weiterentwickeln, ohne dass Clients angepasst werden müssen, und der aktuelle Anwendungszustand ergibt sich aus dem durchlaufenen Linkgraphen.

Umsetzung und Kritik

In der Praxis wird HATEOAS häufig mit dem Format HAL (Hypertext Application Language) oder JSON:API umgesetzt; auch die HTML-Schnittstelle des World Wide Web selbst ist das ursprüngliche Vorbild. Viele reale „REST-APIs“ verzichten auf HATEOAS und begnügen sich mit statischer URL-Dokumentation (Stufe 2 im Reifegradmodell nach Leonard Richardson), weil Hypermedia-Steuerung als aufwendig gilt und die Vorteile erst bei langlebigen, föderierten Systemen voll zum Tragen kommen.
