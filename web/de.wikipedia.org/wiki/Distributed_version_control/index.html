Verteilte Versionsverwaltung

Eine verteilte Versionsverwaltung (englisch distributed version control system, DVCS) ist ein System zur Versionsverwaltung von Dateien – meist Quellcode –, bei dem jeder Entwickler eine vollständige Kopie des Repositorys einschließlich der gesamten Änderungshistorie besitzt. Im Gegensatz zu zentralen Systemen gibt es keinen zwingend erforderlichen zentralen Server.

Funktionsweise

Jede Arbeitskopie ist ein vollwertiges Repository. Änderungen werden zunächst lokal committet und können anschließend mit beliebigen anderen Repositorys ausgetauscht werden (per Push und Pull). Zusammenführungen (Merges) fremder Entwicklungszweige erfolgen ebenfalls lokal. In der Praxis wird häufig ein Repository als Referenz vereinbart – etwa auf Plattformen wie GitHub oder GitLab –, dies ist jedoch eine organisatorische, keine technische Notwendigkeit.

Vorteile

  • Offline-Arbeit mit voller Historie möglich
  • Hohe Geschwindigkeit lokaler Operationen
  • Keine einzelne Fehlerquelle; jede Kopie ist ein vollständiges Backup
  • Erleichtertes Verzweigen (Branching) und Zusammenführen

Bekannte Systeme

Das verbreitetste System ist Git, das 2005 von Linus Torvalds für die Entwicklung des Linux-Kernels geschaffen wurde. Weitere verteilte Systeme sind Mercurial, Darcs, Fossil und das ältere GNU Arch. Verteilte Versionsverwaltung hat zentrale Systeme wie Subversion oder CVS in der Softwareentwicklung weitgehend verdrängt.
