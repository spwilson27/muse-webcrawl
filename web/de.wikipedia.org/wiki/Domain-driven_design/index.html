Domain-Driven Design

Domain-Driven Design (DDD) ist eine Herangehensweise an die Softwareentwicklung, bei der die fachliche Domäne — also der Problemraum der Anwendung — im Mittelpunkt von Modellierung und Architektur steht. Der Begriff geht auf das gleichnamige Buch von Eric Evans aus dem Jahr 2003 zurück.

Kernkonzepte

Zentrales Element ist eine ubiquitäre Sprache (Ubiquitous Language): Fachleute und Entwickler verwenden dieselben Begriffe, die sich direkt im Code wiederfinden. Das System wird in begrenzte Kontexte (Bounded Contexts) zerlegt, in denen je ein eigenes Domänenmodell gilt. Das strategische Design beschreibt die Beziehungen zwischen diesen Kontexten, während das taktische Design Bausteine wie Entitäten, Wertobjekte, Aggregate, Repositories und Domänendienste definiert.

Bedeutung

DDD wird vor allem bei komplexen, langlebigen Fachsystemen angewandt und beeinflusst moderne Architekturstile wie Microservices, bei deren Zuschnitt die Bounded Contexts eine wichtige Rolle spielen.
