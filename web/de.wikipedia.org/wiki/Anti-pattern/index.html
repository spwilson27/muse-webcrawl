Antipattern

Ein Antipattern (englisch anti-pattern) ist in der Softwareentwicklung ein verbreitetes, aber ineffizientes oder kontraproduktives Vorgehensmuster zur Lösung eines wiederkehrenden Problems. Der Begriff wurde in Anlehnung an die Entwurfsmuster (Design Patterns) der „Gang of Four“ geprägt und 1995 von Andrew Koenig eingeführt; systematisch dargestellt wurde er 1998 im Buch AntiPatterns von William Brown und anderen.

Beschreibung

Antipatterns werden üblicherweise durch ihre Symptome, ihre Ursachen und eine verbesserte Lösung (Refactored Solution) beschrieben. Sie treten nicht nur im Code auf, sondern auch in Architektur, Projektmanagement und Organisation. Ihre Kenntnis soll helfen, typische Fehler früh zu erkennen und zu vermeiden.

Bekannte Antipatterns

  • God Object (Gottobjekt): eine Klasse, die zu viele Aufgaben übernimmt.
  • Spaghetti-Code: unstrukturierter, schwer nachvollziehbarer Programmfluss.
  • Golden Hammer: ein vertrautes Werkzeug wird auf alle Probleme angewendet.
  • Cargo-Kult-Programmierung: Rituale und Code werden ohne Verständnis ihres Zwecks übernommen.
  • Lava Flow: toter, unverstandener Code bleibt aus Angst vor Änderungen im System.
  • Reinventing the Wheel: Eigenentwicklung statt Nutzung vorhandener Lösungen.
  • Not-Invented-Here-Syndrom: Ablehnung fremder Lösungen allein wegen ihrer Herkunft.
