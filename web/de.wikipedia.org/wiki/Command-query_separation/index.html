Command-Query Separation

Command-Query Separation (CQS), deutsch etwa „Trennung von Befehl und Abfrage“, ist ein Prinzip des Softwareentwurfs, das von Bertrand Meyer im Zusammenhang mit der Programmiersprache Eiffel formuliert wurde. Es besagt, dass jede Methode eines Objekts entweder ein Befehl (command) oder eine Abfrage (query) sein soll, aber nicht beides.

Das Prinzip

Eine Abfrage liefert ein Ergebnis und verändert den beobachtbaren Zustand des Objekts nicht; sie ist frei von Seiteneffekten und kann beliebig oft wiederholt werden. Ein Befehl dagegen verändert den Zustand, liefert aber keinen Rückgabewert. Durch diese Trennung wird der Programmcode leichter nachvollziehbar, testbar und gegen Fehler robust: Wer einen Wert abfragt, muss keine unerwarteten Zustandsänderungen befürchten.

Ausnahmen und Diskussion

In der Praxis gibt es gebräuchliche Ausnahmen, etwa das Entfernen eines Elements aus einer Datenstruktur, das zugleich das entfernte Element zurückgibt (wie die Operation pop bei einem Stack). Solche Operationen sind bequem, verletzen aber das Prinzip. Das verwandte, aber weitergehende Architekturmuster Command Query Responsibility Segregation (CQRS) greift die Idee auf Systemebene auf und trennt Lese- und Schreibmodelle vollständig.
