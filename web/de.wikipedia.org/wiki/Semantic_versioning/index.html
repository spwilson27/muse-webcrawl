Semantic Versioning

Semantic Versioning (kurz SemVer, deutsch „semantische Versionierung") ist ein Vergebungsschema für Versionsnummern von Software, das die Art der Änderung an der öffentlichen Schnittstelle (API) eines Programms aus der Versionsnummer ablesbar macht. Die Spezifikation wurde von Tom Preston-Werner, dem Mitgründer von GitHub, formuliert und wird auf der Website semver.org gepflegt.

Schema

Eine semantische Versionsnummer besteht aus drei durch Punkte getrennten Zahlen: MAJOR.MINOR.PATCH, etwa 2.4.1:

  • MAJOR wird erhöht, wenn Änderungen vorgenommen werden, die inkompatibel zur bisherigen API sind (Breaking Changes),
  • MINOR wird erhöht, wenn neue Funktionalität abwärtskompatibel hinzugefügt wird,
  • PATCH wird erhöht, wenn nur abwärtskompatible Fehlerbehebungen erfolgen.

Ergänzend sind Vorschaukennzeichnungen (Pre-release, z. B. 1.0.0-alpha) und Build-Metadaten (z. B. 1.0.0+20130313) vorgesehen. Versionen vor 1.0.0 gelten als Entwicklungsversionen, bei denen sich die API noch beliebig ändern darf.

Bedeutung

Semantic Versioning ist in vielen Paketverwaltungen (u. a. npm, Cargo, Composer) der De-facto-Standard, weil Abhängigkeitsmanager wie npm zulässige Aktualisierungsbereiche (z. B. „^1.2.3") aus den Nummern ableiten können. Es soll das sogenannte „Dependency Hell", die Unübersichtlichkeit inkompatibler Abhängigkeiten, vermeiden helfen.
