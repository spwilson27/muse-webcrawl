Page Cache

Der Page Cache ist ein Cache des Betriebssystemkerns, in dem Seiten (pages) von Dateien und Blockgeräten im Arbeitsspeicher gehalten werden, um Zugriffe auf langsame Massenspeicher zu vermeiden. Unter Linux und anderen Unix-artigen Systemen ist er der zentrale Dateisystem-Cache; auch Windows nutzt mit dem System-Cache ein vergleichbares Konzept.

Funktionsweise

Beim Lesen einer Datei prüft der Kernel zunächst, ob sich die benötigten Seiten bereits im Page Cache befinden. Ist dies der Fall (cache hit), werden die Daten direkt aus dem RAM kopiert. Andernfalls (cache miss) liest der Kernel die Daten vom Datenträger und legt sie zugleich im Cache ab, sodass spätere Zugriffe schneller sind.

Beim Schreiben werden die Daten zunächst nur in den Cache übernommen und als „dirty“ (verändert) markiert. Ein Zurückschreiben auf den Datenträger erfolgt verzögert – spätestens bei einem Aufruf von sync beziehungsweise beim Aushängen des Dateisystems. Dadurch wirken Schreiboperationen für Anwendungen schnell, allerdings können noch nicht geschriebene Daten bei einem Systemabsturz verloren gehen. Programme können mit fsync ein sofortiges Schreiben erzwingen.

Verwaltung

Der Page Cache nutzt den ansonsten freien Arbeitsspeicher nahezu vollständig aus. Wird Speicher für Anwendungen benötigt, gibt der Kernel Cache-Seiten frei; Seiten, auf die lange nicht zugegriffen wurde, werden bevorzugt verdrängt (annähernd nach dem LRU-Prinzip über Aktiv/Inaktiv-Listen). Unter Linux zeigt etwa der Befehl free die Cache-Belegung getrennt aus; sie ist nicht als „verbraucht“ im eigentlichen Sinn zu verstehen.

Abgrenzung

Zu unterscheiden ist der Page Cache vom Buffer Cache, der traditionell Blöcke des Datenträgers zwischenspeicherte. In modernen Linux-Kerneln sind beide zusammengelegt: Der Page Cache ist die primäre Struktur, Puffer dienen nur noch Sonderfällen wie dem Zugriff auf Blockgeräte-Metadaten.
