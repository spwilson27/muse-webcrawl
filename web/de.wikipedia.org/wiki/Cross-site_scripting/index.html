Cross-Site Scripting

Cross-Site Scripting (XSS) ist eine Sicherheitslücke in Webanwendungen, die entsteht, wenn nicht vertrauenswürdige Daten – meist Benutzereingaben – ohne ausreichende Prüfung und Kodierung in eine Webseite eingebettet werden. Ein Angreifer kann dadurch eigenen JavaScript-Code in Seiten einschleusen, der anschließend im Browser anderer Benutzer im Kontext der betroffenen Website ausgeführt wird. Die Abkürzung XSS wurde gewählt, um Verwechslungen mit der Abkürzung CSS für Cascading Style Sheets zu vermeiden.

Varianten

Beim gespeicherten XSS (stored XSS) wird der Schadcode dauerhaft auf dem Server abgelegt, etwa in einem Gästebuch, Kommentar oder Profil, und an jeden Besucher ausgeliefert. Beim reflektierten XSS (reflected XSS) ist der Code Teil einer manipulierten URL und wird vom Server unmittelbar in die Antwort „reflektiert“; das Opfer muss auf den präparierten Link klicken. Beim DOM-basierten XSS schließlich entsteht die Lücke ausschließlich im clientseitigen Code, der Eingaben unsicher in das Document Object Model schreibt, etwa über innerHTML.

Auswirkungen

Mit XSS lassen sich Sitzungs-Cookies auslesen (sofern sie nicht durch das Attribut HttpOnly geschützt sind), Aktionen im Namen des Opfers ausführen, Inhalte der Seite verändern, Tastatureingaben protokollieren oder Phishing-Inhalte einblenden. Ein spektakulärer Fall war der Wurm Samy, der sich 2005 innerhalb weniger Stunden auf über eine Million Profile des Netzwerks MySpace verbreitete. XSS gehört seit Jahren zu den am häufigsten gemeldeten Schwachstellenkategorien und wird unter anderem in den OWASP Top 10 geführt.

Abwehrmaßnahmen

Die wichtigste Gegenmaßnahme ist die kontextgerechte Ausgabekodierung aller dynamischen Daten, ergänzt durch Eingabevalidierung und moderne Frameworks, die Ausgaben standardmäßig escapen. Zusätzlich kann eine Content Security Policy (CSP) die Ausführung eingeschleuster Skripte erschweren, und Cookies sollten mit den Attributen HttpOnly und SameSite versehen werden.
