Linux Security Modules

Linux Security Modules (LSM) ist eine Rahmenarchitektur (Framework) im Linux-Kernel, die es erlaubt, verschiedene Sicherheitsmodelle zur Zugriffskontrolle einheitlich in den Kernel zu integrieren, ohne dessen übrige Struktur zu verändern. LSM wurde mit der Kernelversion 2.6 eingeführt.

Hintergrund

Die klassische Unix-Zugriffskontrolle (Discretionary Access Control, DAC) über Dateirechte galt für sicherheitskritische Anwendungen als unzureichend. Verschiedene Projekte wie SELinux, entwickelt von der US-amerikanischen National Security Agency (NSA), wollten eine verbindliche Zugriffskontrolle (Mandatory Access Control, MAC) in Linux verankern. Um zu verhindern, dass sich ein einzelnes Sicherheitsmodell im Kernel festsetzt, setzte Linus Torvalds 2001 auf dem Linux Kernel Summit eine modulare Lösung durch: LSM stellt sogenannte Hooks an sicherheitsrelevanten Stellen des Kernels bereit, an denen registrierte Sicherheitsmodule ihre Prüfungen ausführen können.

Bekannte Module

  • SELinux – sehr fein granulierbares, regelbasiertes MAC-System; Standard in Red Hat Enterprise Linux und Fedora.
  • AppArmor – pfadbasierte Zugriffskontrolle; Standard in Ubuntu und SUSE.
  • Smack – vereinfachtes, labelbasiertes System, unter anderem in Tizen eingesetzt.
  • TOMOYO Linux – pfadbasiertes Lernsystem, besonders in Japan verbreitet.
  • Yama – kleinere Härtungsfunktionen, etwa zur Einschränkung von ptrace.

Arbeitsweise

Der Kernel führt zunächst die üblichen Berechtigungsprüfungen durch und ruft anschließend die LSM-Hooks auf. Das aktive Sicherheitsmodul kann die Operation aufgrund seiner Richtlinien zusätzlich erlauben oder verweigern. Seit Kernel 5.1 können mehrere Module in begrenztem Umfang gestapelt (stacking) werden, sodass beispielsweise ein großes MAC-Modul mit kleineren Modulen kombiniert werden kann.
