Legacy Code

Legacy Code (deutsch etwa „Altcode“ oder „Code aus Altlasten“) bezeichnet Quellcode, der weiterhin betrieben wird, aber nur schwer zu verstehen, zu testen oder sicher zu verändern ist. Der Begriff ist nicht auf besonders alte Software beschränkt: Entscheidend sind fehlende automatisierte Tests, unklare Verantwortlichkeiten, veraltete Abhängigkeiten und Wissen, das nicht mehr dokumentiert oder im Team vorhanden ist.

Merkmale

Typische Merkmale sind große, stark verflochtene Module, fehlende oder veraltete Dokumentation, manuelle Testverfahren, nicht mehr unterstützte Bibliotheken und Angst vor Änderungen, weil Nebenwirkungen schwer vorherzusagen sind. Legacy Code kann geschäftlich sehr wertvoll sein, weil er über Jahre erprobte Regeln und Sonderfälle enthält.

Umgang

Der Softwareentwickler Michael Feathers prägte eine pragmatische Definition: Legacy Code sei im Kern Code ohne Tests. Beim Ändern werden zunächst Charakterisierungstests erstellt, die das vorhandene Verhalten festhalten. Anschließend können Abhängigkeiten gelöst, kleine Refactorings durchgeführt und neue Funktionen an klaren Nähten eingefügt werden.

Strategien

Zu den Strategien gehören schrittweises Refactoring, das Einführen von Schnittstellen zu externen Systemen, das Kapseln problematischer Module und das Ersetzen einzelner Teile durch neue Dienste. Ein vollständiges Neuschreiben ist riskant, weil versteckte Anforderungen und Fehlerkorrekturen des Altsystems verloren gehen können.

Abgrenzung

Ein Legacy-System ist die betriebene Gesamtlösung aus Code, Daten, Infrastruktur und Prozessen. Legacy Code ist der problematische Quellcode innerhalb eines solchen Systems, kann aber auch in einem ansonsten modernen System auftreten.
