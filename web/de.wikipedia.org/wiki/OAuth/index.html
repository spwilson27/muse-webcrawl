OAuth

OAuth ist ein offenes Protokoll für die delegierte Autorisierung im Internet. Es ermöglicht einer Anwendung (Client), im Auftrag eines Benutzers auf Ressourcen eines anderen Dienstes (Resource Server) zuzugreifen, ohne dass der Benutzer sein Passwort an die Anwendung weitergeben muss. Stattdessen erteilt er der Anwendung ein zeitlich begrenztes Zugriffstoken mit eingeschränktem Umfang (Scope).

Geschichte

OAuth 1.0 entstand 2007 aus Vorarbeiten von Entwicklern bei Twitter und anderen Webdiensten und wurde 2010 als RFC 5849 veröffentlicht. Die grundlegend überarbeitete Version OAuth 2.0 erschien im Oktober 2012 als RFC 6749 (Framework) und RFC 6750 (Bearer Token). Sie verzichtet auf kryptografische Signaturen jeder Anfrage und setzt stattdessen auf TLS-geschützte Verbindungen.

Ablauf

Die vier Rollen des Protokolls sind Ressourceneigentümer (Benutzer), Client, Autorisierungsserver und Ressourcenserver. Im verbreitetsten Verfahren, dem Authorization Code Flow, leitet der Client den Benutzer zum Autorisierungsserver um. Nach erfolgreicher Anmeldung und Zustimmung wird der Client mit einem Autorisierungscode beliefert, den er serverseitig gegen ein Access Token (und optional ein Refresh Token) eintauscht. OpenID Connect erweitert OAuth 2.0 um eine Identitätsschicht mit ID-Tokens.

Sicherheit

Da Access Tokens wie Bargeld funktionieren („Bearer“), sind sichere Speicherung und kurze Laufzeiten wichtig. Für öffentliche Clients wird die PKCE-Erweiterung (Proof Key for Code Exchange) empfohlen; der früher für native Apps und Skripte gebräuchliche Implicit Flow gilt als veraltet. Die Autorisierungsdetails werden im RFC 9700 (OAuth 2.0 Security Best Current Practice) zusammengefasst.
