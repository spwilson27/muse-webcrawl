Compilerkorrektheit

Compilerkorrektheit bezeichnet die Eigenschaft eines Compilers, dass das von ihm erzeugte Zielprogramm dieselbe Bedeutung (Semantik) hat wie das Quellprogramm. Da Fehler in Compilern besonders tückisch sind – sie führen dazu, dass korrekte Programme sich falsch verhalten –, ist die Korrektheit von Übersetzern ein zentrales Thema der Programmverifikation.

Formale Verifikation

Beim formal verifizierten Compiler wird maschinell bewiesen, dass die Übersetzung die Semantik erhält. Das bekannteste Projekt ist CompCert, ein optimierender C-Compiler, dessen Korrektheit im Beweisassistenten Coq bewiesen wurde; er wird unter anderem in sicherheitskritischer Software, etwa in der Luftfahrt, eingesetzt. Weitere Projekte sind CakeML (ein verifizierter ML-Compiler) und CertiCoq.

Testen von Compilern

Da vollständige Verifikation aufwendig ist, werden Compiler meist intensiv getestet:

  • Differentielles Testen: Dasselbe Programm wird von mehreren Compilern oder mit verschiedenen Optimierungsstufen übersetzt; abweichendes Verhalten weist auf Fehler hin.
  • Zufallsgenerierung: Werkzeuge wie Csmith erzeugen zufällige, wohldefinierte C-Programme und fanden damit Hunderte Fehler in GCC und LLVM.
  • Übersetzungsvalidierung (translation validation): Statt den Compiler selbst wird jede einzelne Übersetzung nachträglich geprüft.

Bedeutung

Ken Thompson wies in seiner Turing-Award-Rede „Reflections on Trusting Trust“ (1984) darauf hin, dass ein manipulierter Compiler Hintertüren selbst in scheinbar sauberen Quelltext einschleusen kann – ein grundlegendes Vertrauensproblem, das durch Verfahren wie Diverse Double-Compiling adressiert wird.
