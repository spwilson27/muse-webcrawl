Application Binary Interface

AbkürzungABI
ArtSchnittstelle auf Binärebene
Regelt u. a.Aufrufkonventionen, Datenlayout, Objektdateiformate

Ein Application Binary Interface (ABI, deutsch etwa „binäre Anwendungsschnittstelle“) ist die Schnittstelle zwischen zwei Programmmodulen auf der Ebene des Maschinencodes. Es legt fest, wie kompilierte Programme miteinander und mit dem Betriebssystem zusammenwirken, ohne dass der Quelltext bekannt sein muss.

Bestandteile

Ein ABI beschreibt unter anderem die Größe und Ausrichtung von Datentypen, die Aufrufkonventionen (wie Funktionsargumente und Rückgabewerte in Registern oder auf dem Stack übergeben werden), das Format von Objektdateien und ausführbaren Dateien (etwa ELF unter Linux oder PE unter Windows), die Namensgebung von Symbolen (Name Mangling) sowie die Nummern und Konventionen von Systemaufrufen.

Abgrenzung zum API

Während eine Programmierschnittstelle (API, siehe Application Programming Interface) auf Quelltextebene definiert ist, operiert das ABI auf Binärebene. Code, der gegen ein API geschrieben wurde, muss neu kompiliert werden, wenn sich das API ändert; gegen ein ABI kompilierte Programme bleiben dagegen nur lauffähig, solange das ABI stabil bleibt.

Beispiele

Bekannte ABIs sind das System V ABI für Unix-Systeme, die ABIs der ARM-Architektur (AAPCS) sowie die Windows-ABIs für x86 und x64. Die Kompatibilität von Emulatoren wie Rosetta 2 beruht wesentlich darauf, fremde ABIs zur Laufzeit zu übersetzen.
