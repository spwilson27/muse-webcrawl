Language Server Protocol

Das Language Server Protocol (LSP) ist ein offenes, von Microsoft entwickeltes Protokoll, das die Kommunikation zwischen Entwicklungsumgebungen beziehungsweise Texteditoren (Clients) und sogenannten Sprachservern regelt. Sprachserver stellen Funktionen wie Autovervollständigung, Fehlerdiagnose, «Gehe zur Definition» und Umbenennen für eine bestimmte Programmiersprache bereit. Das LSP wurde 2016 zusammen mit Visual Studio Code und den Sprachservern von Red Hat und Codenvy vorgestellt.

Motivation

Vor dem LSP musste jede Entwicklungsumgebung die Unterstützung für jede Sprache gesondert implementieren; bei M Editoren und N Sprachen entstand ein Aufwand von M×N Integrationen. Mit dem Protokoll reicht es, pro Sprache einen Sprachserver zu schreiben und pro Editor einen LSP-Client: Der Aufwand sinkt auf M+N. Das LSP entwickelte sich dadurch schnell zum De-facto-Standard der Werkzeuglandschaft.

Technik

Die Kommunikation erfolgt über JSON-RPC 2.0. Nachrichten bestehen aus einem Header-Teil (ähnlich HTTP, mit Content-Length-Angabe) und einem JSON-Inhalt. Der Client sendet Anfragen (requests) wie textDocument/completion oder textDocument/definition und Mitteilungen (notifications) über geöffnete, geänderte und geschlossene Dokumente; der Server antwortet mit Ergebnissen beziehungsweise veröffentlicht Diagnosen (Fehler und Warnungen). Beim Start handeln Client und Server über die Initialisierungsnachricht ihre Fähigkeiten (capabilities) aus. Der Transport kann über Standardströme, Sockets oder andere Kanäle erfolgen.

Verbreitung

Bekannte Sprachserver sind etwa der TypeScript-Server, Eclipse JDT Language Server (Java), Pyright und Pylance (Python), rust-analyzer (Rust) und gopls (Go). Nahezu alle gängigen Editoren und IDEs – darunter Visual Studio Code, Neovim, Emacs, IntelliJ-basierte Umgebungen und Eclipse – unterstützen das Protokoll. Als Ergänzung entstanden verwandte Protokolle wie das Debug Adapter Protocol für Debugger.
