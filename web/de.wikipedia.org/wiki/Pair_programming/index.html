Zwei Programmierer an einem Arbeitsplatz

Paarprogrammierung

Die Paarprogrammierung (englisch pair programming) ist eine Arbeitstechnik in der agilen Softwareentwicklung, bei der zwei Programmierer gemeinsam an einem Arbeitsplatz an derselben Aufgabe arbeiten. Sie ist ein zentrales Praktikum des Extreme Programming (XP).

Rollen

Einer der beiden, der Driver (Fahrer), schreibt den Code und konzentriert sich auf die konkrete Umsetzung. Der andere, der Navigator (Beobachter), überprüft laufend den entstehenden Code, denkt an Tests, Randfälle und das übergeordnete Design und hält die strategische Richtung im Blick. Die Rollen werden in regelmäßigen Abständen getauscht.

Varianten

Neben der klassischen Form gibt es Varianten wie das Ping-Pong-Verfahren (einer schreibt einen fehlschlagenden Test, der andere die Implementierung), das Strong-Style Pairing und das zeitlich begrenzte Arbeiten wechselnder Teams an einer Aufgabe (Mob Programming mit mehr als zwei Personen).

Vor- und Nachteile

Vorteile sind höhere Codequalität durch kontinuierliche Review, gegenseitige Wissensvermittlung, geringere Fehlerzahlen und weniger Ablenkung. Als Nachteil gilt der scheinbar doppelte Personaleinsatz; Studien zeigen jedoch, dass der Mehraufwand durch weniger Fehler und schnelleren Wissenstransfer teilweise ausgeglichen wird. Die Technik erfordert gute Zusammenarbeit und funktioniert am besten mit regelmäßigem Partnerwechsel.
