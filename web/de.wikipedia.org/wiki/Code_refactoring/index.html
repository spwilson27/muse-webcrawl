Refactoring

Refactoring (deutsch auch Refaktorisierung oder Restrukturierung) bezeichnet in der Softwareentwicklung die manuelle oder automatisierte Umstrukturierung des Quelltextes eines Programms, ohne dessen beobachtbares Verhalten zu verändern. Ziel ist es, Lesbarkeit, Wartbarkeit und Erweiterbarkeit des Codes zu verbessern und technische Schulden abzubauen.

Vorgehen

Refactoring erfolgt in kleinen, verhaltensneutralen Schritten, die einzeln überprüfbar sind. Typische Operationen sind das Umbenennen von Variablen und Methoden, das Extrahieren einer Methode aus einem langen Codeabschnitt, das Verschieben von Verantwortlichkeiten zwischen Klassen oder das Ersetzen verschachtelter Bedingungen durch Polymorphie. Viele dieser Schritte sind in Martin Fowlers Buch Refactoring (1999) katalogisiert, das den Begriff nachhaltig prägte.

Voraussetzung für sicheres Refactoring ist eine gute Testabdeckung durch automatisierte Tests, die nach jedem Schritt nachweisen, dass sich das Verhalten nicht geändert hat. Moderne Entwicklungsumgebungen unterstützen zahlreiche Refactorings automatisiert und fehlerarm.

Abgrenzung und Anlässe

Im Unterschied zum Neuschreiben (Rewrite) bleibt die Funktionalität beim Refactoring unangetastet. Anlässe sind häufig sogenannte Code Smells – Anzeichen wie überlange Methoden, doppelt vorhandener Code oder übermäßige Kopplung. Refactoring ist ein Kernbestandteil agiler Methoden wie Extreme Programming und wird dort mit dem Prinzip der kontinuierlichen Designverbesserung verbunden.
